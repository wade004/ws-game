游戏技术基础架构 图解

一套不属于任何具体游戏、专门用来"打地基"的技术骨架——它决定的是"世界怎么跑起来、内容怎么加进去"，不决定"这是一款什么样的游戏"。

第一章 · 一分钟看懂：这套架构是什么、不是什么

打个比方： 这套架构像一栋"毛坯楼房加装修标准"，而不是某一套具体的家具。承重墙、水电走线、层高这些"结构性的东西"一旦定下就不轻易改；至于客厅摆沙发还是摆书架、卧室刷什么颜色，这些"装修风格"留给每一款具体游戏自己决定，随时可以换。

目标（5 条）

  • 一套骨架能装下后续所有游戏：做新游戏＝选好承重方式（引擎）＋装修（数据与资源），不用重新盖楼。
  • 逻辑的世界和看到的画面彻底分家：世界怎么运转不需要知道自己长什么样，画面只负责"照着世界的样子画出来"。
  • 可以随时换承重结构（引擎）：只要接口不变，把承重方式从钢筋换成木结构，房间里的家具不用挪。
  • 结果可以重复验证：同样的操作，反复重放要得到一模一样的结果，才能放心测试与排错。
  • 每个房间能整体搬走复用：厨房、卫生间这些"模块"设计成能拆下来装到别的房子里继续用。

非目标（明确不做）

联网多人 服务器权威校验 防作弊 玩家对玩家对战 公会 / 邮件 / 拍卖行 跨服 开放给玩家的插件接口 载具与飞行 独立的宠物对战玩法 账号登录体系

这栋楼从设计之初就没打算通网线——它是给单机、单人游戏盖的地基，上面这些能力不是"以后再加"，而是从设计上就不考虑。

四个"可以随时反悔"的选择 与 三个"定死的根基"

图 A骨架与可插拔件示意图
要点
  • 架构本身不是一款游戏，它不回答"这个游戏有几个技能""能不能跳跃"这类问题，只提供能装下这些答案的容器。
  • "根基"和"口味"是两类完全不同的东西：根基改动代价极高，需要走严格的审批流程；口味改动只是填一份配置表。
  • 画面是 2D 还是 3D，只影响"最后怎么画出来"，不影响世界内部怎么计算距离和碰撞——这是"逻辑与画面分家"（见第四章）能够成立的前提。
  • 即时战斗与回合制战斗共用同一套战斗规则，区别只在于"下一步是按时间自动推进，还是等每个人依次行动"。
  • 这套架构的设计参照系是一款知名的大型多人在线游戏在系统设计上的做法，但把"多人在线"相关的部分整体拿掉，只留下"内容怎么组织、规则怎么跑"的骨架。
