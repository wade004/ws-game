## 你方的核实结论对，但检索词差了一层

你方检索 `tile|terrain|ground|layer|tilemap|backdrop|background|scenery|zonelayout` 命中 0 处地面
图层**数据契约**——这个结论是对的，框架确实没有"按格/按区域引用地面纹理资源 id 的图层表"。

漏掉的是另一条已经存在的线：**[ADR-0053](../adr/0053-地图分层图路径约定纳入公开契约.md)** 已经把
"每张地图四张分层图"纳入公开契约，`import_assets.py` 的 `map` 子命令一直能产出它们，
`check_cmd.py` 一直在做存在性校验。四层语义早就定死了：

| 文件 | 层 | 必需 | 语义 |
| --- | --- | --- | --- |
| `maps/<map>/ground.png` | 地面层 | 必需 | 2D 地面图 |
| `maps/<map>/overlay.png` | 前景遮挡层 | 必需 | 遮挡单位的近景建筑、树冠等 |
| `maps/<map>/decal.png` | 装饰层 | 可选 | 不遮挡单位的贴花、痕迹 |
| `maps/<map>/nav_hint.png` | 导航标注参考图 | 可选 | 作者手绘导航数据时参考，**不是可见内容** |

配套的 `world.map.image_transform`（可选字段，`pixels_per_unit` / `origin_px` / `image_size_px`）
也早就在了——那是 2026 年更早一批反馈（ADR-0036）加的。

**真正的缺口是：这些图产出后就是孤儿资产。** `RenderLayers` 里 `Ground=0`/`Decoration=1`/
`Foreground=3` 三个层号常量，除定义处外全仓零引用；`ResourceKind.Scene` 加载出的文本零消费方，
样例内容本身就是占位。坑位预留着，没有任何东西填得进去。这一刀把它填上了。

## 做了什么

- `ground` / `decal` / `overlay` 三层在场景加载完成时被真正建出来并渲染，分别落到
  `RenderLayers.Ground` / `Decoration` / `Foreground`。`nav_hint` **不渲染**。
- **摆放位置唯一由 `world.map.image_transform` 决定**：世界矩形 = 图片像素尺寸 ÷
  `pixels_per_unit`，原点按 `origin_px` 换算。**你方手算的坐标、旋转、平铺比例，一行都不用写了。**
- 切图/卸载时销毁，不泄漏（切走再切回，总层数与首次一致，有实测）。
- **契约扩展全是纯加法**：`ResourceKind` 追加一项（按 `world.map` 行 id 整套加载）；`IRenderer2D`
  新增一对建层/销毁层的**默认接口方法**，默认实现不绘制、返回无效句柄——你方若自带
  `IRenderer2D` 实现，不改一行仍然编译通过、行为不变。
- **不新增任何 `world.map` schema 字段，不新增资源引用类别前缀。** 关联靠 ADR-0053 已有的 id 约定
  （地图名 = `world.map` 行 id 去掉类别前缀），不发明第二套命名空间。

**降级行为（都有实测）**：可选层缺失（样例地图就没有 `decal.png`）只少建一层、记诊断、不报错、
不画占位；地图行没有 `image_transform` 时一层都不建、记诊断、不抛异常。

## 你方怎么接

1. 把 S00 那四块地面纹理（枯草地/土路/焦土/泥土空地）在美术侧按地图布局合成**一张**
   `ground.png`；近景遮挡物出一张 `overlay.png`；贴花/痕迹（可选）出 `decal.png`。
2. 跑 `import_assets.py map <src> --id world.<地图名> --pixels-per-unit <值>`，它会把图规范化落到
   `maps/<地图名>/` 并把 `image_transform`（含从 `ground.png` 的 PNG 头直接读出的 `image_size_px`）
   写进 `world.map` 行。
3. **`SetupGroundAndCamera` 里那套 `CreatePrimitive(Quad)` + 手算坐标/旋转/平铺比例可以整段拆掉。**
   框架会在场景加载完成时自己摆好。

## 明确不做（ADR 里逐条记了，免得你方等）

- **不做按格 tilemap、不做平铺重复、不做逐区域拼贴、不做旋转。** ADR-0053 的模型就是"一张地图一套
  分层图"，这一刀只把它接上。
- **不加任何地形语义**——可通行性、移动消耗、地表类型一概不进这套契约。可通行性归 `nav_ref` 与
  导航，加第二个真相源必然打架。分层图纯粹是可见内容。
- 不动 `scene_ref`（引擎场景资源）这条既有逃生通道。

## 这套做法的代价，如实说

你方原本想要的是"按格/按区域引用**可平铺**纹理 id"，得到的是"一张合成大图"。区别在于：

- **好处**：零手算、零样板代码、美术布局所见即所得，且不需要新契约、不需要你方学一套新数据格式。
- **代价**：`ground.png` 是整张地图一张位图。单张图的地图完全没问题；地图变大或数量变多时，
  它的体积与内存占用会线性涨，而可平铺小纹理不会。

**如果你方后续真的进到多图/大地图，这件事从"能接受"变成"拦路"，请单独反馈一次并标为阻塞项**——
按格图块图层是另一套子系统（要拍板分块、剔除、作者工具），届时另开 ADR 单独做，不会因为现在这一刀
就不做了。
