## 观察（消费方反馈原文摘要）

`move` 效果原语现有三种子类型（`charge`/`leap`/`knockback`）均由 `EffectDispatcher.ApplyMove`
直接 `SetPosition` 到算出的终点，一次性完成，没有连续路径采样、没有碰撞/导航裁决、没有暂停/取消
的观测点。已复现最小场景：合法墙前目标 `(1,0)` 使用 static leap `(3,0)`，墙区间 `x=1.5..2`，终点
发生一次位置跳变且 `walkable=true`——`walkable=true` 只说明落点本身可行走，不代表从起点到落点这条
路径没有穿墙。消费方建议合同：增加可选连续模式，保持现有瞬移模式兼容；合同明确路径采样、碰撞/
导航裁决、阻挡后的停止或回退、暂停与取消事件；验证条件是同一输入分别走瞬移与连续模式，逐 tick
比较位置、事件与最终状态，现有三种模式结果保持兼容。

## 契约决定

按消费方建议方向拍板，写为 [ADR-0026《技能位移的连续模式》](../adr/0026-技能位移的连续模式.md)：

1. **`move` 效果新增正交参数 `motion`**（`instant`，缺省，现行三种子类型的既有语义原样不变；
   `continuous`）。判断记录：不复用既有 `mode` 字段（`charge|leap|knockback`）表达这一维度——
   两者正交，复用会与既有取值集合冲突。`motion: continuous` 时追加：`speed`（每秒位移距离）或
   `duration`（总耗时，二选一，`speed` 存在时优先，否则按 `|target-origin|/duration` 换算）、
   `blocking`（`stop`/`revert`，缺省 `stop`）、`sample_step`（路径采样步长，未声明或非正值时取
   L3 `MovementOptions.DefaultDisplacementSampleStep` 兜底，默认 0.5）。五个新字段登记进
   `SkillSchemas.cs` 的 `move` 变体（扁平超集，同既有登记风格），`speed`/`duration`/`sample_step`
   若声明必须 `> 0`。
2. **实现落在 L3 `core/carriers/unit`，通过依赖倒置接口接入**：新增
   `Core.Rules.Common.IControlledDisplacementSink`/`ControlledDisplacementRequest`（惯例同既有
   `IProjectileSpawner`）；`MovementHost` 直接实现该接口，新增公开入口
   `BeginControlledDisplacement(ControlledDisplacementRequest)`。真正逐 tick 推进由
   `MovementTickHandler` 在既有 `TickPhase.MovementAndNavigation` 完成——每步按不超过
   `sample_step` 的增量推进，每段用 `INavigation2D.Raycast` 做判定（与既有目标/方向移动"射线与
   路径段同源判定"完全一致）；受阻按 `blocking` 停在阻挡前最后可通行采样点或回到起点；到达/
   受阻/控制打断（`MovementState.MovementLocked`/`IAuraQuery.GetControlFlags.NoMove`）/施法者
   死亡（`Unit.Alive`）/显式 `MovementHost.Stop` 均结束受控位移，触发既有 `OnMoveStopped`
   （`MoveStopReason` 新增四个 `Displacement*` 枚举成员，显式 `Stop` 复用既有 `Requested`）；
   时间模型暂停（本次推进 `dt<=0`）不推进、不产生事件；受控位移期间该单位的普通移动意图被拒绝
   （落地位置与既有"控制期间禁止移动"同一处）。离散（回合制）模式下一次性完成整段位移，不按
   每回合移动预算拆分（判断记录见 ADR-0026 决策 4）。
3. **可观测性复用既有事件，不新增事件类型**：位移开始经既有 `unit.state_changed`
   （`MovementState.Mode` 切到既有 `Forced`）；逐 tick 位置变化经既有 `unit.moved`；全部终止
   路径经既有 `MovementHost.OnMoveStopped`（新增四个 `Displacement*` 原因值）。`MovementState`
   新增只读属性 `IsControlledDisplacementActive`。
4. **兼容性**：`motion` 缺省 `instant`，`EffectDispatcher.ApplyMove` 原有三分支 `switch`
   （`charge`/`leap`/`knockback`）代码逐字节未改动，新分支在其之前短路返回；既有数据、既有测试
   全部不受影响。无阻挡时连续模式与瞬移模式对同一输入的终点公式相同（两段代码各自独立实现、不
   共享状态），由测试锁定最终落点一致。

## ABI 安全（公开 API 只新增）

`EffectDispatcher`/`SkillHost`/`RulesAssembly`/`CarriersAssembly` 均**未改动任何既有构造函数的
物理签名**：

- `EffectDispatcher`/`SkillHost` 各新增一个可写属性 `DisplacementSink`（`IControlledDisplacementSink?`）
  ——纯 getter/setter，不经过构造函数注入；`Core.Carriers.Assembly.CarriersAssembly` 在
  `Movement`/`Rules` 均构造完成后一行赋值 `Rules.Skill.DisplacementSink = Movement;` 接线。

## 对消费方的提示

1. **`motion` 与 `mode` 是两个正交字段**：`mode`（`charge|leap|knockback`）决定"位移到哪个点"，
   语义与升级前完全一致；`motion`（`instant|continuous`）决定"怎么位移过去"，缺省 `instant` 即
   升级前唯一行为，不改变任何既有内容数据的解读。若要为某条技能开启连续位移，只需在其 `move`
   效果 `params` 里追加 `motion: "continuous"` 与 `speed`（或 `duration`）等参数，不需要改动
   `mode`/`point`/`distance`/`stop_distance` 等既有字段。
2. **阻挡裁决与既有移动系统同一套判定**：连续位移复用 `INavigation2D.Raycast`/
   `IsWalkable`（02 第 1.8 节"可通行统一规则"，边界/角点相切不算受阻），与玩家/AI 的目标/方向
   移动、投射物飞行共用同一套导航裁决口径，不会出现"技能位移一套规则、玩家移动另一套规则"的
   不一致。
3. **受控位移与普通移动互斥**：位移进行中，该单位提交的普通 `MoveRequest` 会被拒绝（不排队、不
   报错，静默忽略），需要"位移结束后自动恢复被打断的移动"的游戏层逻辑，请订阅
   `MovementHost.OnMoveStopped`（`MoveStopReason` 为 `DisplacementArrived`/`DisplacementBlocked`/
   `DisplacementControlled`/`DisplacementCasterDead`/`Requested` 之一，可据此区分具体终止原因）
   后自行重新提交移动请求；框架本身不提供排队缓存（简单确定性优先，与既有移动系统的既定取舍
   一致）。
4. **离散（回合制）模式下一次性完成**：连续位移在离散模式下不按每回合移动预算拆分，一次
   `castSkill` 触发的位移会在同一步内推进到"到达/受阻/其它终止条件"之一，不会跨多个回合继续
   进行——若游戏是回合制且希望某个技能位移"分几个回合走完"，需要在游戏层把它拆成多个技能效果
   分别触发（比如用光环周期效果按回合调用多次 `move`），框架不在 `move` 原语本身提供跨回合拆分。
5. **公开 API 只新增，未删改**：本次改动全部落在 `EffectDispatcher`/`SkillHost`/`MovementHost`/
   `MovementState`/`MovementOptions`/`MoveStopReason` 新增成员，加上两个全新契约类型
   （`IControlledDisplacementSink`/`ControlledDisplacementRequest`），未改动任何既有构造函数/
   方法/属性的物理签名——不需要做任何升级前的兼容性核对，`toolchain/abi_probe.ps1`（基线
   1.12.0）已核实 `breaks=0`。
