**结论先行**：**已处理并验证。** `IDialogHost`/`IQuestHost` 现有方法均是有状态运行期契约（要求
单位已处于对话会话/持有运行期状态），无法在不持有单位/会话的前提下"模拟走一遍"剧情树/任务前置链——
编辑器"试走"面板类诉求此前只能手工读原始数据表核对。新增两个独立只读无状态入口：
`Core.Gameplay.Dialog.DialogStoryPreview.Preview` 与 `Core.Gameplay.Quest.QuestPrerequisitePreview
.Preview`，均不改动 `IDialogHost`/`IQuestHost` 既有成员、不引入任何运行时状态、不发布任何事件、
不要求任何会话。

## 现象

原文见 `ws-game-editor` 仓库 `docs/上游反馈.md` 第 55 条"`IDialogHost`/`IQuestHost` 无无状态
'模拟走一遍'入口"：`IDialogHost` 的只读方法（`GetGossipView`/`GetStoryView`）要求单位"当前已处于
一个已打开的会话中"；`IQuestHost.GetState` 要求给定具体单位，按其运行期上下文（世界状态/其它任务
进度）实时求值 `prerequisite`。两者都不支持"给定任意剧情树/任务 id，脱离任何单位/会话，分析结构"
这一预演场景——编辑器"剧情/任务链试走"面板此前只能手工读 `dialog.story_tree`/`quest.def` 原始 JSON
核对分支/前置关系，容易出错且效率低。

## 根因

`IDialogHost`/`IQuestHost` 从任务书拍板时起就是围绕"单位的运行期会话/状态机"设计的有状态契约，
从未规划过"脱离单位、纯读结构"这一使用场景——不是遗漏，是两种不同的使用场景（"驱动一次真实交互"
与"预演/分析内容"）此前只覆盖了前者。

## 处理

### 设计口径拍板（勘察报告标注的"需要先回设计层"的两点）

1. **对话预演是路径枚举还是单一路径**：拍板为"两者都要"——默认（不传条件回调）只给纯结构信息
   （节点/出边/起点/终止节点）；传入可选的条件判定回调时，额外给出可达节点集合与**全部**路径枚举
   （深度优先，`maxPaths`/`maxDepth` 双上限防御，遇环/悬空引用/命中上限均安全截断并显式标记）。
2. **任务链预演是否涉及 objective 语义**：拍板为"不涉及"——只分析 `prerequisite` 表达式里
   `quest.*` 引用构成的任务依赖图（直接前置/传递闭包/成环/拓扑序/可接性），不碰 `QuestObjective`。

### 1. `DialogStoryPreview`——对话/剧情树预演

`Core.Gameplay.Dialog.DialogStoryPreview.Preview(StoryTreeDefinition tree, Func<string, bool?>?
evaluateCondition = null, int maxPaths = 200, int maxDepth = 64): DialogStoryPreviewResult`：

- **纯结构信息**（恒返回）：`Nodes`（每个节点的 id/文本键/说话者引用 + 每条分支的下标/文本键/
  条件规范化文本/目标节点 id）、`StartNodeId`（直接读 `StoryTreeDefinition.FirstNode`，与
  `DialogHost.StartStory` 共用同一段取值逻辑，不复制一份）、`TerminalNodeIds`（该节点全部分支
  `next_node_id` 均为空，或零分支）。
- **条件文本**：`ConditionText` 是 `StoryBranchDef.Condition`（`ExprNode`）的 `ToString()` 规范化
  文本，不是原始逐字符文本——语法树本身不保留原始字符串，规范化文本语义等价，与
  `ExprNode.ToString()` 既有承诺一致。
- **可选可达性/路径枚举**：提供 `evaluateCondition` 回调（入参为分支条件的规范化文本，返回
  `true`/`false`/`null`；`null`=未知按"可能"处理）时，额外给出 `ReachableNodeIds`（从起点出发，
  沿"可能可见"分支能到达的全部节点）与 `Paths`（全部路径枚举，每条是节点 id 序列）；命中
  `maxPaths`/`maxDepth`、或遇到环（当前路径已访问过目标节点——不假设输入已通过
  `story_tree_cycle` 校验，预演入口面向任意/编辑中数据必须自行防御）、或悬空 `next_node_id`
  （引用了不存在的节点，另见第 56 条校验缺口），均安全终止该路径并把 `PathsTruncated` 置真。
- **不执行**：不调用任何 `PerformanceHookRef`、不推进任务/世界状态、不发布任何事件、不自己求值
  `condition`——是否可见完全由调用方回调决定。

### 2. `QuestPrerequisitePreview`——任务前置链预演

`Core.Gameplay.Quest.QuestPrerequisitePreview.Preview(Id questId, IEnumerable<QuestDefinition>
definitions, IReadOnlyCollection<Id>? completedQuestIds = null, int maxNodes = 10000):
QuestPrerequisitePreviewResult`：

- **前置引用提取复用框架已公开的 `Core.Foundation.Expr.ExprReferenceCollector`**（不复制/不改动
  `QuestContentValidationRule.CollectQuestIdLiteralArgs`——该私有方法与其所在文件由第 54/56/57 条
  同批的另一并行任务改动，本次改动为避免文件冲突、也为了不把"预演"逻辑与"校验规则"逻辑耦合，改用
  框架已有的通用引用遍历入口：直接读取 `QuestDefinition.Prerequisite` 已解析好的 `ExprNode`，用
  `ExprReferenceCollector.Collect` 收集全部引用节点，过滤 `Group == quest` 并取 Id 字面量参数——
  遍历口径与 `CollectQuestIdLiteralArgs` 一致，只是不共享同一份代码）。
- **图结构分析**：`DirectPrerequisiteQuestIds`（`questId` 直接引用的任务 id，按表达式出现顺序
  去重）、`TransitiveClosureQuestIds`（广度优先可达的全部已知任务 id）、`UnknownReferencedQuestIds`
  （引用了不在给定定义集合内的任务 id——数据缺陷的显式标记，不静默丢弃）、`HasCycle`/`CyclePath`
  （子图内是否成环，成环时给出首尾重复的环路径）、`TopologicalOrder`（前置排在被依赖任务之前的
  合法顺序；`HasCycle` 为真时恒为空——不是"无前置"的误导性空值）。图算法（BFS 闭包、Kahn 拓扑序、
  三色标记找环）独立实现，不依赖字典枚举顺序或哈希顺序，保证确定性。
- **可选可接性判定**：提供 `completedQuestIds` 时，额外给出 `IsAvailableByReferencedQuests`/
  `BlockingQuestIds`（`DirectPrerequisiteQuestIds` 中不在已完成集合内的子集，含未知引用——未知
  引用恒视为"未满足"）。
- **语义边界（重要限制）**：只看 `prerequisite` 里引用了哪些任务，不看 `and`/`or`/`not` 组合方式
  （与既有 `quest_prerequisite_cycle`/`quest_prerequisite_unknown` 校验构图同一套口径），也不涉及
  `QuestObjective` 语义。`IsAvailableByReferencedQuests` 因此是"假设 `prerequisite` 只由这些
  `quest.*` 引用以合取方式组成"这一简化视角下的可接性，不是 `IQuestHost.GetState` 的等价物——
  `prerequisite` 里若还混有世界标志/玩家属性等其它条件，或用 `or` 组合，真正可接性仍须调用
  `GetState`。面板应如实向用户说明这一范围，不能把预演结果当作最终可接性结论展示。
- **防御上限**：`maxNodes`（默认 10000）防止极端数据下子图扩展失控，命中时 `ClosureTruncated`
  置真；真实内容规模不预期触发。

### 为何不改 `IDialogHost`/`IQuestHost`

预演是与运行期会话/状态机正交的无状态查询，加进两个接口（哪怕用默认接口成员）会把"预演"这一新概念
混进"运行期契约"，且未来预演能力的演进（如接入更丰富的条件求值上下文）不应该受两个接口的兼容性
约束牵连。拆成独立静态类是本仓库既有惯例（同 `ExprReferenceCollector`"只读遍历入口"）。

## 对编辑器的使用建议

1. `DialogStoryPreview` 适合"作者写完一棵剧情树后，编辑器给出结构预览/试走"这类场景：默认调用
   （不传回调）即可拿到节点/分支/起点/终止节点的静态结构；若面板想模拟"某个具体玩家状态下能走到
   哪些节点"，自行提供 `evaluateCondition` 回调（用编辑器自己的表达式求值能力，或简单地按字符串
   规则模拟）。
2. `QuestPrerequisitePreview` 适合"任务链关系图"类可视化面板：`TopologicalOrder` 可直接用作"建议
   的任务设计/测试顺序"；**务必在面板上如实标注"可接性判定只覆盖任务引用类前置，不含世界标志等
   其它条件"**，避免用户把预演结果误当作运行期真实判定。
3. 两个入口均为纯新增独立类型，不影响任何既有 `IDialogHost`/`IQuestHost` 调用方，不需要迁移既有
   代码。
