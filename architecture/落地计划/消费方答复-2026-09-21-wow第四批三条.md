## 反馈 1：普通攻击状态

`HudViewModel` 新增两个只读属性，类型是枚举 `Core.Rules.Combat.AutoAttackState`
（`Off` / `NoTarget` / `Attacking`），不是字符串：

- `AutoAttackState`——玩家自身；
- `TargetAutoAttackState`——当前目标（同样是非空枚举；**无目标时为 `Off`**，不是 `null`。要区分
  "没有目标"与"目标未开普攻"，请先看 `TargetId` / `TargetAlive` 是否为 `null`）。

对应路径 `player.auto_attack.state` / `target.auto_attack.state`，路径层取值是固定小写文本
`off` / `no_target` / `attacking`；如果你方直接走路径查询而不经 `HudViewModel`，用新增的
`Core.Rules.Combat.AutoAttackStateNames.Parse` / `TryParse` 转回枚举，`ToText` 做反向转换。

取值来源是 `AutoAttackHost.GetState(unitId)` 的原样转发，表现层不做任何推断。如果你方自己装配时
走的是 Provider 旧构造重载（没有接入 `AutoAttackHost`），两个属性恒为 `Off`。

**已知口径：目标死亡后有一拍延迟**。目标死亡的那一拍，`AutoAttackState` 仍可能是 `Attacking`，
下一拍 `AutoAttackHost.Update` 清掉已死目标后才变为 `NoTarget`。这是规则层"每拍更新时清理死亡
目标"的既有时序，表现层照实转发。如果你方的 HUD 要在目标死亡的同一拍就不再显示"攻击中"，请
结合下文的 `TargetAlive` 判断，不要单靠 `AutoAttackState`。

## 反馈 2：单位存活状态

`HudViewModel` 新增两个只读属性：

- `PlayerAlive`（`bool`）——玩家自身；
- `TargetAlive`（`bool?`）——当前目标；**无目标时为 `null`，不是 `false`**，与既有
  `TargetId` / `TargetName` / `TargetFaction` 的判空口径一致：先判空，非空再读值。

对应路径 `player.alive` / `target.alive`（布尔值；无目标时 `target.alive` 为"无"）。

**取值来源**：`IUnitAccess.Exists(unitId) && IUnitAccess.IsAlive(unitId)`。`IsAlive` 是规则层在
结算致死伤害时写入的权威死亡标志，也是 `AutoAttackHost` 判断目标是否已死用的同一个查询。**请不要
改用"生命值是否 ≤ 0"自行判断**：生命值归零与 `IsAlive` 置 `false` 不保证同一拍同步，另起一套阈值
判断会与框架的死亡语义产生偏差窗口，而且框架本身不规定哪个资源池代表生命值。

## 反馈 3：`HudViewModel.Auras` 极性和图标恒为缺省值（框架缺陷，已修）

**根因**：`HudViewModel.RefreshAuras` 在读完 `player.auras[i].*` 各子路径后，用 1.52.0 时的旧构造
（五个参数）重建 `AuraSnapshot`，从未查询 1.53.0 新增的 `player.auras[i].polarity` /
`player.auras[i].icon_ref` 两个子路径，于是极性恒为 `AuraPolarity.Undeclared`、图标引用恒为
`null`。规则层 `AuraSnapshot` 与路径层两个子路径本身都是对的——1.53.0 的验收只测到这两层，没有
测到 `HudViewModel` 这一层，所以漏过。

**修复**：`RefreshAuras` 改为同时查询这两个子路径，用 1.53.0 的七参数构造
`AuraSnapshot(Id, int, double?, double?, Id?, AuraPolarity, Id?)` 重建。新增的验收测试经生产装配
入口 `PresentationAssembly` 一路走到 `HudViewModel.Auras` 读值断言（修复前该测试失败：期望
`Beneficial`，实得 `Undeclared`），同类"字段穿线"的新增今后都按这个深度验收。

**你方需要做的**：升到 1.55.0 即可，`HudViewModel.Auras[i].Polarity` / `IconRef` 的读法与 1.53.0
答复里写的一致，不需要改接线。如果你方为绕过这个缺陷在游戏层自己查过 `player.auras[i].polarity`
/ `icon_ref` 路径，升级后可以删掉，改回直接读 `HudViewModel.Auras`。
