## 1. 总体结论

**六条 ADR 在代码侧基本零落地。** 全仓库对 `derived_from`、`stat.weight`、`level_diff`、`use_condition`、`budget_rule`、`budget_share`、`value_curve`、`gold_base`、`xp_multiplier`、`item_level_offset`、`tryCharge`、`currency_overflow`、`sim.scenario`、`sim.anchor`、`core/sim` 的引用数全部为零。文档侧（04/06/07/08/10/11/13）已按 2026-09-14 修订完毕，代码停留在修订之前的形态。

**但底子有五处比预想好，落地时可以直接复用：**

| 已具备 | 位置 | 对哪条设计有用 |
|---|---|---|
| 周期效果每跳活读属性，已是动态计算 | `core/rules/skill/core/AuraHost.cs:451-479` → `EffectDispatcher.ApplyDamageOrHeal` | ADR-0031 决策 4，只差"来源缺失冻结" |
| 公共冷却默认关闭，`respects_gcd` 字段已在 | `core/rules/skill/contracts/SkillOptions.cs:39` | ADR-0031 决策 10，节拍锁只需改判定分支 |
| `max_targets` 已有，截断已实现 | `core/rules/targeting/core/TargetHost.cs:351-359` | ADR-0031 决策 6，只差超出策略 |
| 物品实例不存算出的属性值，读档经真实 `Equip` 重算 | `core/carriers/item/core/ItemPersistable.cs:71-78` | ADR-0032 决策 8 已符合精神，只差品质/词缀两个身份字段 |
| 跨表校验、图环检测、Analyzer 契约面、Perf 基线比对四种先例都有 | `ItemBudgetValidationRule`、`ArchTalentTreeCycleValidationRule`、`LootTableAnalyzer`、`PerfBaselineTests` | 新增校验与仿真骨架可照抄结构 |

**三条横切前置决定了整体顺序**（第 2 节）：通用曲线契约、校验规则的级别与报告、数值最小数据集。六条 ADR 一共要新增八张曲线表、七条阻断级和六条警告级校验，没有前两项就会把同一份插值和同一种"单调有限"规则写八遍；没有第三项，样例数据的 3 级满级、全 1 级怪、全 1 级物品跑不出任何有意义的仿真。

## 2. 横切前置

### 2.1 通用曲线契约

**现状。** 四张同构的分段线性曲线表各写一份插值与校验：

| 表 | schema | 断点形状 | 插值 |
|---|---|---|---|
| `item.budget_curve` | `core/carriers/item/contracts/ItemSchemas.cs:209-232` | `{item_level, budget}` | `ItemBudgetCurve.Interpolate`（`core/carriers/item/core/ItemBudgetCurve.cs:365-401`），线性、越界夹取 |
| `combat.resist_curve` | `core/rules/combat/schema/CombatSchemas.cs:85-127` | `kind: saturation\|table` + `{value, reduction}` + `k`、`max_reduction` | `ResistCurve.ComputeReduction`/`InterpolateTable`（`core/rules/combat/core/ResistCurve.cs:93-145`） |
| `prog.level_curve` | `core/numbers/progression/contracts/ProgSchemas.cs:16-45` | 逐级密集枚举 `{level, xp_to_next, growth}`，不插值 | 逐级查表 |
| `stat.rating_conversion` | `core/numbers/stat_block/core/StatSchemas.cs:46-69` | `{level, points_per_percent}` | `StatHost.ConvertRating`（`StatHost.cs:536-579`） |

`FieldKind` 十二种里没有曲线种类（`core/foundation/data_registry/contracts/FieldKind.cs`）；单调性校验只有 `combat.resist_curve` 一家（`CombatValidationRules.cs:117`），有限性检查 `field_finite` 只覆盖单个 `Number`（`DataRegistry.cs:1237-1249`）。

**改动点。**

| # | 改动 | 类型 | 落点 |
|---|---|---|---|
| C1 | 定义框架级曲线形态：统一 `entries: [{x, y}]` 子结构登记（ADR-0019 形态），横轴语义由字段登记声明（等级 / 物品等级 / 数值） | schema | `core/foundation/data_registry/contracts/`（新增 `CurveSchema` 或 `FieldSchema.WithCurve`） |
| C2 | 公共插值工具：线性插值、越界夹取、空表语义、按 x 排序，一处实现 | 运行时 | `core/foundation/common/`（新增 `PiecewiseCurve`），上提 `ItemBudgetCurve.ParseEntries/Interpolate` |
| C3 | 通用"曲线单调递增且逐值有限"阻断规则，对所有登记为曲线形态的字段生效 | 校验 | `core/foundation/data_registry/core/`（新增 `CurveMonotonicFiniteRule`），检查名建议 `curve_monotonic_finite` |
| C4 | 既有四表接入：`item.budget_curve`、`stat.rating_conversion` 改为引用通用形态（字段名迁移走 ADR-0029 迁移链，`currentSchemaVersion` 递增）；`combat.resist_curve` 的 `table` 分支复用插值；`prog.level_curve` 保持密集枚举但接入单调校验 | schema/迁移 | 四个模块的 schema 与 `data/_sample`、`games/_template` 存量数据 |
| C5 | 八张新曲线表全部按 C1 形态登记：`stat.weight`（非曲线，见 3）、`combat.level_diff_table`（三曲线一界线）、`item.armor_curve`、`item.weapon_dps_curve`、`item.req_level_curve`、`econ.value_curve`、`econ.gold_base_curve`、击杀基数曲线（ADR-0033 `base_curve_ref` 的目标表，表名待定，见第 10 节） | schema | 各归属模块 |

## 10. 需要拍板的实现层问题

盘点中发现的、ADR 没有写到实现粒度的决策点。**2026-09-14 用户逐项拍板，结果如下表；原建议保留在表后供追溯。**

| # | 问题 | 拍板结果 | 落点 |
|---|---|---|---|
| 1 | `group` 与 `category` | `category` 取代 `group`，抗性归 `defense`；`group` 保留一个版本周期标废弃；抗性维度开关改为独立策略项 | A1、A2、`StatHostOptions.EnableResistanceGroup` |
| 2 | `clamp` 与平级 `min`/`max` | 嵌套 `clamp` 为准，`min`/`max` 迁入，夹取发生在第二轮聚合之后 | A1、A2、C4 迁移链 |
| 3 | `prog.level_curve` 形态 | 保持密集枚举，只接 `xp_to_next` 单调有限阻断校验 | X2、X9 |
| 4 | `prog.xp_source` 旧字段 | 废弃 `base_xp`/`weight`；过渡期并存，`base_curve_ref` 存在时优先，一个周期后删除 | X2 |
| 5 | 击杀基数曲线 | 表名 `prog.xp_base_curve`，归 L1 progression | C5、X2 |
| 6 | 武器伤害范围 | 保留 `damage_min`/`damage_max` 手填，新增"偏离秒伤曲线"警告；一拍常数与浮动比例为数据项 | E8、E14 |
| 7 | 超出策略分配信息 | `ITargetHost.Resolve` 新增重载，返回带分配系数的结果；旧签名保留（MINOR） | S10 |
| 8 | 两条新经济事件 | 不另起 ADR，并入 ADR-0034 修订记录一行并登记事件表 | M7、ADR-0034 修订记录 |
| 9 | 进战下马策略项归属 | `CombatOptions`，战斗模块在进战时摘除坐骑类光环；需要坐骑类光环的识别方式（标签或叠加类别） | M8 |
| 10 | 仿真数据集归属 | 嵌入 `core/sim/tests`；`data/_sample` 只补 schema 覆盖用最小示例；`games/_template` 给空壳表 | D1、D2、D3、N8 |
| 11 | `derived_from[].coefficient` 负数 | 允许，只要求有限；不登记下界 | A1 |
| 12 | 命中改写后的回放基线 | 与命中公式改写同一提交按 Replay README 五步更新并注明；掉落三次掷骰那次再更新一次 | A8、E11 |

原建议（拍板前）：

1. **`stat.definition.group` 与新 `category` 的关系。** 现有四值枚举 `primary|secondary|derived|resistance` 里 `resistance` 承担"抗性维度开关"（`EnableResistanceGroup`）。建议：`category` 取代 `group`，抗性归 `defense` 类别，开关改为"是否启用抗性维度"的策略项，`group` 保留一个周期标废弃。
2. **`clamp` 与既有平级 `min`/`max`。** 建议 `clamp` 嵌套为准，`min`/`max` 迁移进去。
3. **`prog.level_curve` 密集枚举还是稀疏断点。** 密集枚举与"曲线单调有限"规则兼容，但 `growth` 是每级映射不适合插值。建议保持密集枚举，只接单调校验。
4. **`prog.xp_source` 的 `base_xp`/`weight` 去留。** 与当量写法冲突。建议废弃，过渡期允许并存且 `base_curve_ref` 优先。
5. **击杀基数曲线的表名与归属。** ADR-0033 只说 `base_curve_ref`。建议 `prog.xp_base_curve`，归 L1 progression。
6. **武器伤害范围手填还是推导。** ADR-0032 决策 4 给了推导公式但 `damage_min/max` 是既有必填字段。建议：保留手填，新增"手填偏离秒伤曲线"警告；一拍常数与浮动比例放 `skill.budget_rule` 与 `item.weapon_dps_curve` 旁。
7. **`overflow_policy` 的 `split`/`cap` 分配信息怎么从目标解析传到效果落地。** 现有 `ITargetHost.Resolve` 只返回 id 列表。建议返回值增带分配系数的重载。
8. **两条新经济事件是否走 12 第 2 节新事件审批。** 建议并入 ADR-0034 修订记录一行，不另起 ADR。
9. **"进入战斗时移除坐骑光环"策略项归属。** 建议 `CombatOptions`（进战事件在战斗模块发出）。
10. **仿真数据集归属。** ADR-0035 决策 4 说数归游戏。建议：仿真自测用嵌入式数据集在 `core/sim/tests`，`data/_sample` 只补 schema 覆盖用最小示例，`games/_template` 给空壳表。
11. **`derived_from[].coefficient` 是否允许负数。** 影响 `WithRange` 登记。建议允许（反向派生是合法设计），只要求有限。
12. **命中公式改写后的回放基线更新时机。** 建议与 A8 同一提交更新，并在提交信息按 Replay README 注明。

## 11. 工作包与顺序

依赖关系决定顺序：曲线与校验框架先行，属性是装备与技能的地基，仿真最后且依赖反解与独立求值组件。

| 包 | 内容 | 依赖 | 验收 |
|---|---|---|---|
| W0 横切 | C1～C4、V1～V3、D2/D3 骨架 | 无 | 四张既有曲线表跑在通用插值上，回放与 Perf 基线不变；报告能列规则清单与分组 |
| W1 属性 | A1～A12、C5 中的 `stat.weight`/`combat.level_diff_table` | W0 | 两轮聚合、换算三形态、来源类别、命中 Δ 双向的单测通过；回放基线按流程更新一次 |
| W2 装备与掉落 | E1～E16、C5 中三条 item 曲线 | W1（权重表、换算折点） | 预算消耗公式与反解可逆；三次掷骰确定性；读档后词缀重算一致；`item_budget_exceeded` 覆盖新公式 |
| W3 技能 | S1～S17 | W1（缩放属性、派生）、W2（秒伤查询） | 使用条件、节拍锁、冻结、瘟疫、超出策略单测；预算 Analyzer 三档判定；独立求值组件可驱动玩家单位 |
| W4 经验与经济 | X1～X11、M1～M11、C5 中两条 econ 曲线与击杀基数曲线 | W1（Δ 表）、W2（价格倍率、货币掉落类型） | 三种来源当量、货币掉落与溢出、`tryCharge`、复活不阻断；样例任务与商人改当量 |
| W5 校验全集 | 十三条数值规则收口、`--json` 报告分组、编辑器契约面文档 | W1～W4 | 04 第 5 节分级表逐条有实现类与测试；`toolchain/validator` 报告可按已确认/待确认分组 |
| W6 仿真 | N1～N10、D1 | W2（反解）、W3（独立求值）、W5 | 对账等式在嵌入数据集上可算；越级矩阵形状正确；基线差异报告可产出；11 第 6 节测试类型落地 |

**规模判断。** 六个包里 W0、W1、W6 是结构性改动（新契约、算法拆轮、新模块），W2～W5 主要是字段、公式与规则的铺开。确定性敏感点只有两处：命中公式改写（A8）与掉落三次掷骰（E11），两者都会改变 RNG 消耗序列，回放基线各更新一次。ABI 层面按第 9 节的手法全部可以控制在 MINOR，除非选择删除废弃字段。
