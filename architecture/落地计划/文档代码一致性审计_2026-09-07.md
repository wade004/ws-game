## 2. 设计层拍板（`scratchpad/audit2/DECISIONS.md` 全文纳入）

> 以下为设计层汇总裁决原文（2026-09-06 深夜，基于 A1～A4 与 A5 的五份子审计），逐条对应第 3 节

### 总体结论

00～05、08、10、11～14 与代码一致性高；真实缺口集中在：09 §4 动画/纸娃娃驱动层（`AnimState`、
`CharacterRig`、`FrameAnimPlayer`、程序动画原语 8 缺 7、命中帧 sprite 侧）、离散模式的若干接线
（`action_cost`→行动点、`Charges` 维度、GCD 离散关闭、`time.*` Expr、AI 多行动测试）、存档必填段
缺失（`player.progression`/`player.archetype`）、死亡复活三策略无执行逻辑、`race.passive_auras`
未应用、离散回放门生产未启用、商店 UI 单元、地图资产导入子命令、若干过期注释/README/登记表字段。

### 拍板（需设计层裁决的项）

1. GameObject 门/箱/杆/采集点内置行为绕过技能管线：**判定为 ADR-0001 的合理例外**（"kind 内置
   行为"= 载体层直接结算；陷阱等 `on_use` 效果仍经 Skill）。处理：07 §物件 与 ADR-0001 各补一句
   勘误说明，不改代码。
2. AI 离散模式"连续行动直到预算耗尽"：**只在 `initiative_policy=action_points` 下成立**；其余
   策略每回合一个行动是预期语义。处理：06 勘误一句 + 补集成测试（AP 策略多行动、非 AP 策略单行动）。
3. 死亡复活三策略执行主体：**落在 L4 新模块 `core/gameplay/death`**（`DeathPolicyHost`：订阅
   `unit.died`（玩家）→ `respawn_point`：置于当前地图 `spawn_points[0]`、恢复生命并发
   `unit.respawned`；`reload_save`：经 `SaveRequester`/`ISaveSystem` 读最近自动存档；
   `permadeath`：删除当前槽并请求 `AppState`→`MainMenu`）。策略来自
   `CombatOptions.DeathPolicy`/`GameOptions.DeathPolicy`。08 勘误补该模块一行。
4. 离散模式 GCD 恒关闭：`CastPipeline` 增加 `Func<bool> isDiscreteStep` 注入，离散步跳过 GCD；
   `GameplayAssembly` 接线。
5. 离散回放门：`FeedbackOptions.QueueMode` 经 `PresentationAssemblyOptions` 暴露，且当
   `TimeModelSwitch` 处于离散模式时由 `PresentationAssembly` 自动切 `Sequential`（连续模式
   `Immediate`）；Unity 引导不再靠"零事件兜底"短路。
6. 09 §4 动画层：**本轮落地 sprite 型全套**：`AnimState` 七态状态机（引擎无关，`presentation/render`：
   由事件与只读运动状态驱动）、`CharacterRig` 类型（归并 `SpriteViewBase` 的层/锚点/动画职责，
   sprite 型实现；model 型留接口）、`IFrameAnimPlayer` 契约 + Unity 实现（复用 `EffectSequencePlayer`
   思路做角色序列帧）、程序动画原语 8 个（`move`/`rotate`/`scale`/`flash`/`trail`/`stagger`/
   `topple`/`fade`）作为 `IProceduralAnim` 原语清单在 `presentation/render` 定义并在 Unity 视图
   实现（占位资产可视化验证）、命中帧同步 sprite 侧 `hit_frame` 标记（`display.anim_set` 或
   `weapon_style` 字段，按 09 §4.3 定，缺则 09 勘误补字段）。
7. 商店 UI：补 `ShopViewModel`（vendor 库存/价格/买卖意图）+ Unity `ShopPanel` + PlayMode 用例；
   `UiPanel` 枚举扩为 11 值（09 §7.1 本就列了商店，属恢复文档承诺，不是新增原语）；09 §7.1 补
   changelog 说明技能书/角色属性/存档槽/暂停菜单为实现级单元。
8. `IPresentationClock`：若 09 有对应概念则实现（`ViewBinder` 插值 alpha 来源），否则删除悬空
   契约——由 W3a 核对后执行。**执行结果**：09 无对应概念（插值 alpha 来源已是
   `GameplayAssembly.InterpolationAlpha`），判定为零实现零调用点的悬空契约，已删除
   `presentation/common/contracts/IPresentationClock.cs`（见第 3 节 W3a 行）。
9. 14 §1.2 文件命名：**以实现为准**（嵌套目录 `<set>/<方向>/<层>.png`），14 勘误改写模板并保留
   扁平命名作为"打包后可选形态"说明；不改工具。
10. 地图资产：给导入工具补最小 `map` 子命令（复制 `ground`/`overlay`/`nav_hint` 分层图到交付目录、
    生成/校验 `world.map` 的 `scene_ref`/`nav_ref` 引用），占位包补 `music/` 目录一个循环占位音频；
    `check` 子命令补 `mirror_pairs` 独立重校验与缺锚点清单校验；`import_assets.py check` 接入
    模板 `validate.ps1` 与 `check.ps1`（对 `data/_sample` 可容忍缺真实资产则用占位包数据集）。
11. 字体命名：文档统一改为"Noto Sans CJK SC（思源黑体同源）"。`com.unity.2d.animation` 包：从
    manifest 移除（代码零引用）。manifest URP 声明同步锁定版本。
12. 表现层异常隔离：补显式兜底——`OnFrameTick` 内各表现步骤 try/catch 记诊断，不影响固定步。
13. 存档段顺序：把 5 个自定义段加入 `SaveSections.KnownOrder`，与 10 §3 文字顺序一致。
14. 其余全部按各报告"文档待勘误 / S 级代码修正 / 测试补齐"逐条落地。

## 4. 仍保留项（本轮明确不处理，记录理由）

- **model 型 3D 渲染路径**：`ModelCharacterRig`/`IRenderer3D` 挂点/槽位应用只留接口与
  `NotSupportedException` 说明，真正的 3D 渲染管线留给接入真实模型资产的具体游戏在其阶段落地
  （09"基础架构提供/游戏层提供"表既有拍板，本轮未扩大范围）。
- **`combat.cast_school`/`time.day_cycle` 占位**：Expr 分组内两个 key 仍是占位实现，非本轮五路
  审计发现的缺口（未被列入 A1～A5 任何一条），不在本轮处理范围。
- **`jump` 状态由游戏层触发**：`AnimState.Jump` 只是状态机可扩展集合的一员，具体触发时机/物理
  语义由具体游戏决定（05/09 既有拍板），框架不代为实现。
- **`InterpolationAlpha` 按固定步更新，非逐渲染帧连续增长**：`GameplayAssembly.InterpolationAlpha`

  的既有行为，本轮未调整（见该类型判断记录"已知局限"）。
- **`data/_sample` 的 `display`/`vfx`/`sfx` 三域真实资产接入**：本轮变基整合的远端并行提交
  （PR #2，`toolchain/import_sample_assets.py`）已经补齐，`world` 域此前是唯一接入项，见本文档
  变基说明（第 5 节）。
