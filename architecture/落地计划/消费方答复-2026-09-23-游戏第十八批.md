## 反馈 1：sprite 型 `equip_visual` 的层资源改为走方向档位换算（ADR-0071）

**做法：沿用身体层已有的那套推导，不给 `mesh_ref` 加三向子结构。**

`mesh_ref` 仍然是单个 `Id?`，04 的字段结构不动。改的是它在 sprite 型下的**语义**：不再是"该层的最终
资源 Id"，而是"该装备层的资源集引用"，站在与身体层 `sprite_set_id` 同一个位置上。解析公式：

```
装备覆盖层资源 Id = layer.<mesh_ref 去类别前缀、点号换下划线>__<方向档位>__<层名>
```

与身体层的 `layer.<sprite_set>__<dir>__<layer>` 逐字对应：方向档位段同样经 `DirectionSlots.StripPrefix`
还原，`flipX` 同样不编码进资源 Id（镜像档位沿用 `_r` 原图 + flipX，与身体层同一口径）。

**为什么不选你方提的第二个方向（把 `mesh_ref` 扩成三向资源引用集合）**：一件装备要三向图，需要的是
"和身体层同一套方向规则"，不是"给这一张表单开一套子结构"。加子结构等于让同一件事在框架里有两种表达
方式（身体层按命名推导、装备层按字段枚举），将来加第四个方向档位或加一个档位维度时要改两处。

**新的可覆写点**：`SpriteViewBase` 新增 `protected virtual Id ResolveEquipLayerResourceId(SpriteLayerPlacement placement, Id equipLayerSetRef)`，
默认实现就是上面的公式。既有的 `ResolveLayerResourceId` 签名一字未动（你方若已覆写，不受影响），两者
的公共推导在框架内共用一份，身体层与装备层永远同一套规则。

**顺带修掉一个真实缺陷（同一条线上）**：朝向变化时走的层合成路径此前完全不看当前生效的装备覆盖——
人物一转身，装备层会退化成身体层资源、装备新增的额外层被整个丢掉，直到下一次装备事件才恢复。实测
（只经真实 `SyncPose` 切朝向，不手工重派装备事件）：切到 `front` 后装备层资源的加载进度为 0，被请求的
反而是身体层的同名层资源；额外层资源全程为 0。现已把装备感知的合成抽成一份，朝向变化与装备事件两条
重建路径共用，`SetPaperdollLayers` 的签名与可见性不变，没有装备覆盖时结果与升级前逐字一致。

## 反馈 2：纸娃娃层逐层播放剪辑（ADR-0072）

**做法同上：不改 schema，`clips.<state>.resource_ref` 在"带纸娃娃层的 sprite 外形"下改读作剪辑集。**

逐层资源按这个顺序探测：

1. `sprite_anim.<resource_ref 去前缀>__<方向档位>__<层名>`（按方向 + 按层）
2. `sprite_anim.<resource_ref 去前缀>__<层名>`（按层，不分方向）
3. 两级都探不到 → **该层保持它当前的静态层图，可见、不换帧**

第 3 档是框架拍板的默认行为（你方问"由框架决定"）：播放中途把装备藏起来比让它不动更难看。

**整身兜底与逐层播放的分界**：

- **一层都没探测到逐层剪辑** → 行为与升级前**完全一致**：整身 `AnimRoot` 帧序列，排序仍钉在全部纸娃娃
  层之上。你方现有的整身烤甲精灵不会因为升级而变样。
- **只要有一层探测到** → 走逐层播放，**此时整身 `AnimRoot` 渲染器隐藏**，不再盖住纸娃娃层。

各层共用同一条时间轴与同一份帧索引（你方明确要求的"同一帧表时序"）。逐层帧必须经既有的层列表路径
应用，所以 flash/fade、flipX、height 偏移、阴影对装备层继续生效。

## 验收

经真实生产装配 + 真实 Unity PlayMode：

- **三朝向**：同一件装备在三个方向档位下解析出三个不同的 `layer.*` 资源 Id（修复前恒为同一个
  `mesh_ref` 值）；
- **真实转身**：只经 `SyncPose` 连续切 `front`/`back`/`side_r`，装备层与装备新增的额外层均正确跟随
  （修复前装备层加载进度实得 0.0，退化成身体层资源）；
- **逐层播放**：声明了逐层剪辑的状态下，两个命中层的贴图随共享时间轴推进变化，`AnimRoot` 渲染对象
  `enabled=false`；未命中的层保持静态可见；
- **兜底不变**：没有任何层命中的状态仍走整身动画，`AnimRoot` 可见；
- **不回归**：flash 过曝对逐层动画的层仍生效；镜像档位下命中层的 flipX 仍为 true；无纸娃娃层的 sprite
  外形与 model 型外形行为不变。

## 升级影响（两条都是数据语义的破坏性变更，请一并处理）

1. **sprite 型 `display.equip_visual` 的 `mesh_ref`**：升级后它被当作资源集，旧的"直接指向一张最终层图"
   的写法会解析到不存在的资源（表现为该装备层加载不到）。需要把该装备的层图按
   `<mesh_ref 去前缀>__<方向档位>__<层名>` 的命名重新组织（与身体层图完全相同的组织方式）。
2. **`display.anim_set.clips.<state>.resource_ref`**：只有当你方按上述命名额外提供了逐层资源时才会
   切换到逐层播放；**不提供就什么都不变**。所以这一条对现存数据是安全的，是"想用才配"。

框架自己的样例数据与占位资产已按新语义重做，可作为命名参考。

版本号取 1.64.0（MINOR）而不是 MAJOR：没有任何公开签名变化、没有数据表字段的增删改，ABI 比对 1.63.0
破坏 0 处；变的是两个字段值的解读方式，且按你方反馈你们尚未接入装备外观，实际影响面只在框架自己的
样例数据上。
