## 第十一批：遭遇开始幂等化（行为变更，[ADR-0068](../adr/0068-遭遇开始幂等化.md)）

**新行为**：`EncounterHost.Start(encounterId, mapId, playerUnitId)` 的签名不变。**同一地图上同一遭遇定义
已有进行中实例时，不再新建**：不刷初始单位，不发 `EncounterStartedEvent`，直接返回已在进行中的那个
实例 id。
- "进行中"沿用 `IsActive` 口径；
- 实例已结束（胜利、失败、中止）后可以正常重开；
- 不同地图上的同一遭遇定义互不影响。

**新增入口**：想区分这两种情况，用新增的 `IEncounterHost.TryStart(encounterId, mapId, playerUnitId, out Id instanceId)`，
返回 `EncounterStartResult.Started` 或 `EncounterStartResult.AlreadyActive`。`Start` 和 `TryStart` 走同一份判定。
"已在进行中"属于正常情况，**不写诊断**。

**因此 `encounter_start` 触发 + `one_shot:false` 的组合现在是安全的**：玩家在战斗中来回穿越触发圈，
不会再重复开始遭遇。区域触发的默认 `EncounterStartRequested` 委托不用改，自动生效。

**验收**：经真实 `GameplayAssembly` 装配、真实 `encounter_start` / `one_shot:false` 区域与真实遭遇定义：
- 进圈：只有 1 个实例，开始事件发 1 次；
- 多次出圈再进圈：仍是同一个实例，初始单位没有重复刷，开始事件仍只发过 1 次；
- 遭遇中止后再进圈：新实例正常开始。

**你方需要做的**：删掉你方对 `EncounterStartRequested` 的整体覆写（"遭遇仍在进行中就吞掉本次触发"那段门控），回到框架默认委托。

**升级影响**：如果你方有逻辑依赖"同一遭遇连续 `Start` 会得到不同实例 id"，升级后行为会变。框架内唯一
依赖旧行为的是一条单测，已按新契约改写。

## 第十二批：非生物单位死亡不再写掉落告警（缺陷修复）

`CreatureDeathLootListener.OnUnitDied` 现在先判断死亡单位的来源类别（`IUnitAccess.GetSourceKind`，
按实体类别返回）。**不是生物就直接跳过，不写任何诊断**：玩家单位死亡属于这种情况，玩家不在本监听器的
职责范围内。"确实是生物、但 `creature.template` 里查不到模板"这一真正的内容缺口仍会告警，文案不变。

**验收**：经真实 `GameplayAssembly` 装配，玩家单位经真实死亡结算致死，Loot 诊断计数前后不变；生物死亡
照常掉落；生物模板缺失时照常告警。

**你方需要做的**：删掉你方端到端冒烟"全程零告警"步骤里按 `unitId=` 片段排除的那一条，恢复严格的
"全程零告警"。

## 第十三批：默认物件生成路径应用模板锁（缺陷修复）

**新增便捷入口**（纯新增）：

```csharp
Id GameObjectFactory.SpawnFromTemplate(IDataRegistryView registry, Id templateId, Id mapId,
                                       Vec2 position, double facing, Id? originKey = null);
```

它按模板读取 `gobj.template`，把 `lock_id` 一并带上生成。以下三处都改为调用它：
- `GameplayAssembly` 默认的 `SpawnOptions.GobjSpawner`（所以经 `spawn.table` 刷出的物件现在会带上
  模板锁）；
- 框架示例 `GameFoundationBootstrap` 的样例箱子；
- 测试辅助代码。

`GameObjectFactory.Spawn` 本身"是否照抄模板锁由调用方决定"的语义没有改：手工放置的物件仍可以用它覆盖
模板默认锁。

**验收**：经真实 `GameplayAssembly` 装配、真实 `spawn.table` 和带 `lock_id` 的模板：
- 刷出物件的 `LockId` 等于模板的锁；
- 锁的条件不满足时交互返回 `Locked`，满足后可以解锁；
- 模板没有锁的物件仍然没有锁。

**你方需要做的**：删掉你方启动代码里补读 `lock_id` 的自定义 `GobjSpawner`，回到框架默认委托。
如果你方还有别处要按模板生成物件，也可以直接调 `SpawnFromTemplate`。
