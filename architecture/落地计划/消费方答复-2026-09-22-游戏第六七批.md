## 第六批：任务名、目标描述的文本键

### 宿主契约

`Core.Gameplay.Quest.IQuestHost` 新增两个只读成员，都带默认实现：

```csharp
Id? GetQuestTitleKey(Id questId);                              // 转发 QuestDefinition.TitleKey
Id? GetObjectiveDescriptionKey(Id questId, int objectiveIndex); // 转发 QuestObjective.DescriptionKey
```

以下情况都返回 `null`：任务 id 未知、目标下标越界、数据里没填该字段。生产实现 `QuestHost` 显式实现了
这两个成员，按接口调用即可。既有 `QuestProgress` 和 `GetActiveObjectives` 的元组没有改。

### 视图模型

`QuestLogViewModel` 新增两个同名的只读转发方法：`GetQuestTitleKey(questId)`、
`GetObjectiveDescriptionKey(questId, objectiveIndex)`。`Log` / `ActiveObjectives` 的既有类型没有改。
推荐用法：遍历 `Log` 或 `ActiveObjectives` 拿到任务 id 和目标下标，再调这两个方法取文本键，经本地化
解析后显示。

验收经真实 `PresentationAssembly` 装配、真实 `quest.def` 数据：接任务后，读到的标题键、目标描述键和
数据定义一致；没填描述的目标读到 `null`。

### 路径层

- `player.quest.<questId>.title_key`
- `player.quest.<questId>.objective_description_key[i]`

既有的 `player.quest.<questId>.state` 和 `.objective[i]` 行为不变。

### 框架参考面板

参考面板 `QuestLogPanel` 新增一个带本地化宿主的 `Construct` 重载：有标题键时显示本地化后的任务名，
没有本地化宿主时显示键本身，完全没有标题键时仍回退显示任务 id。既有的两参数 `Construct` 签名和行为
不变。如果你方直接用这块参考面板，改调新重载就能看到任务名。

## 第七批：死亡生物不再是"最近可交互目标"的候选（缺陷修复）

**根因**：`InteractionTargetRegistry` 的候选判定只按实体类别筛选，不看生物是否存活。框架在单位死亡时
不会自动 `Despawn`，尸体会留在世界里，而掉落物就生成在死亡位置。尸体和它自己的战利品同坐标、等距时，
按实体 id 序数取小，`creature.*` 恒小于 `loot.*`，所以每次击杀后按交互键都会打在尸体上。

**修复**：生物类候选只有**存活时**才成立，判定口径是 `IUnitAccess.Exists && IsAlive`，和
`player.alive` / `target.alive` 同一口径，不看生命值。物件和掉落物没有"存活"概念，不受影响。
`CarriersAssembly.InteractionTargets.TryFindNearest` 和表现层 `interact.nearest.*` 用的是同一个
注册表，一起生效。**没有新增公开签名，你方的接线不用改**。

**验收**：经真实装配走完整条链路：普通攻击致死，真实掉落，然后查询，发 `interact` 意图，物品进背包。
**全程不调用 `Despawn`**。结果如下：

- 查询返回掉落物；
- 表现层 `interact.nearest.kind == "loot"`；
- 拾取成功；
- 尸体比活着的 NPC 更近时，查询返回活着的 NPC；
- 活着的生物仍然是候选。

**你方需要做的**：升级后把冒烟里为规避本缺陷临时加的 `Despawn` 尸体清理删掉。对应检查点应在"尸体
仍在场"的条件下通过。

**附带说明（本版本未改）**：核实时发现，生物的原生 `interact` 分流本身**不检查目标是否存活**。也就是说，
如果你方绕过最近目标查询，直接对一具尸体发 `interact` 意图，框架仍会受理。走最近目标查询的正常流程
不会碰到这种情况，所以这次没有改它。改分流的行为属于另一项决定：将来如果要做尸体交互（剥皮之类），
那会是一个新的交互类别。你方如果需要"对尸体发交互一律拒绝"，请另提反馈。
