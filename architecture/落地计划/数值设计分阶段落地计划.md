# 第一部分 前提与规则

## 1. 估算前提

- 人力模型、周期口径（首版基准，±30%）、"验收标准未达成不得推进"三条沿用既有计划第 9 节，不重复。
- 阶段间全部是硬依赖（见各阶段"依赖"），本专项内没有并行阶段；阶段内的小任务按"依赖"列串行或有限并行，并行的小任务各自过小任务门禁后才算完成。
- 每个阶段结束发布一个 MINOR 版本（1.30.0 起），版本号只增不跳；阶段内不发布。第 9 节 ABI 判定要求每个阶段的对外契约变化都能控制在 MINOR，做不到的任务必须在派发前回到设计层重新拆分，不允许在执行中升 MAJOR。
- 数值总纲的边界不变：本专项只交付表结构、公式、契约、校验、仿真骨架与最小数据集；任何具体系数、锚点数值、带宽阈值只出现在测试数据与样例里，不进框架默认值。

## 2. 六条工作线在本专项的分工

| 线 | 本专项产出 | 验收方式 |
|---|---|---|
| ① 核心逻辑 | `core/foundation`（曲线契约、校验级别）、`core/numbers`、`core/rules`、`core/carriers`、`core/gameplay`、新模块 `core/sim` | 受影响测试工程全绿 + 小任务门禁 |
| ② 适配层与表现 | 只涉及无头侧：`adapters/stub` 若需补桩；`presentation/assembly` 的校验装配入口与 schema 导出跟改 | 契约一致性测试 + 元数据门禁 |
| ③ 工具链 | `toolchain/validator` 报告分组与规则清单、`validate_data.py` 透传、`--update-baseline` 入口、`check.ps1` 新步骤 | 工具链 pytest + 门禁脚本自检 |
| ④ 美术管线与资产 | 无 | — |
| ⑤ 内容数据 | `data/_framework`、`data/_sample` 新字段与新表、`games/_template` 空壳表、`core/sim/tests` 嵌入数据集 | 数据校验全量通过 + schema 覆盖测试 |
| ⑥ 测试与验收 | 每个小任务的单测、每阶段的集成/回放/仿真基线、验收记录 | 对照各阶段"验收标准"逐项打勾 |

## 3. 执行规范（沿用）

每个派发任务必须自包含五项：目标、涉及文件、契约引用、验收标准（可执行命令）、禁止事项；设计层收到完成汇报后必须独立复核（重跑验收命令、抽查文件、对照契约），复核通过才计入完成；契约不清或发现架构缺口时如实上报，不允许执行层自行发明契约。全文见既有计划第 8 节。本专项的契约引用一律指向 `architecture/数值设计/`、ADR-0030～0035 与 04/06/07/08/10/11/13 的修订段，改动点清单的编号（A1、S3、E11…）只作定位，不替代契约。

## 4. 小任务门禁与阶段门禁

**小任务门禁**（每个 T 编号完成的定义，五条全过才能领下一个 T）：

| # | 门禁项 | 命令或核对方式 |
|---|---|---|
| G1 | 受影响测试工程全绿，且本任务新增的测试用例数 ≥ 任务表"验收标准"列出的用例数 | `dotnet test Core.sln -c Release --filter "FullyQualifiedName~<受影响命名空间>"`，再跑一遍不带 filter 的全量 |
| G2 | 快速门禁全绿 | `powershell -File check.ps1 -Quick`（构建、六工程测试、两道数据校验、事件常量一致性、两道禁用词扫描、版本一致性） |
| G3 | ABI 不破坏 | 涉及公开契约的任务额外跑 `toolchain/abi_probe.ps1`；新增成员只能是新重载、默认接口方法、枚举新成员；被标废弃的字段/成员本任务内不得删除 |
| G4 | 文档与实现同步 | 模块 `README.md`/`schema/README.md` 补判断记录；schema 版本递增的表补迁移函数并登记 `found.migration` 链；对外契约变化在 `CHANGELOG.md` 的"未发布"段记一行（编辑器相关契约同时进"编辑器相关契约"小节） |
| G5 | 设计层复核 | 重跑 G1 的验收命令，抽查任务表"涉及文件"列的每个文件至少一处关键实现，核对契约引用的章节；不通过打回，不计完成 |

确定性敏感任务（本计划标记 ★）在 G1 之外加 G1★：跑 `dotnet test Core.sln --filter "FullyQualifiedName~Replay"`，基线变化必须按 `core/gameplay/tests/Replay/README.md` 五步更新，并在提交信息注明原因；基线变化与代码变化同一提交。

# 第二部分 分阶段计划

## 6. 阶段 N0：横切前置

**周期**：1.5 周

**目标**：建立通用曲线契约、校验规则级别与报告、数值最小数据集骨架三项前置，使后续六张新曲线表与十三条数值校验规则不再各写一份实现。本阶段结束时既有四张曲线表跑在通用插值上，回放与 Perf 基线不变。

**任务清单（按六条线）**：

| 线 | 任务 |
|---|---|
| ① 核心逻辑 | 通用曲线子结构登记形态与公共插值工具；`IValidationRule` 规则元数据（规则 id、默认级别、不可提升标记）与注册去重；`ValidationIssue` 增 `group`/`note`；通用"曲线单调有限"阻断规则；既有四表接入 |
| ② 适配层与表现 | `presentation/assembly` 的 schema 导出与校验装配入口跟改：`--list-tables --json` 导出曲线形态与规则清单 |
| ③ 工具链 | `toolchain/validator` 文本与 JSON 报告增加规则清单、命中统计、分组；`validate_data.py` 透传 |
| ⑤ 内容数据 | `item.budget_curve`、`stat.rating_conversion` 存量数据迁移；`games/_template/data/game` 补空壳表清单 |
| ⑥ 测试与验收 | 插值工具单测（线性、越界、空表、乱序输入）；单调有限规则单测（正例、负例、NaN、无穷）；报告分组的 pytest；回放/Perf 基线不变的回归 |

**产出**：`core/foundation` 新增曲线契约与规则元数据；四张既有曲线表迁移完成；`toolchain/validator` 报告新格式；1.30.0。

**验收标准（可执行）**：
1. `dotnet test Core.sln --filter "FullyQualifiedName~Curve"`：插值工具 ≥ 6 组用例（两点线性、三点分段、左越界夹取、右越界夹取、空表返回 0、乱序输入自动排序）全绿。
2. 通用单调有限规则对故意构造的非单调、含 NaN、含无穷的曲线各报一条 Error，对合法曲线零告警（≥ 4 组用例）。
3. `item.budget_curve` 与 `stat.rating_conversion` 的 `currentSchemaVersion` 递增，迁移函数把旧字段名映射到统一形态；`validate_data.py --strict` 对迁移后的 `data/_sample` 与 `games/_template` 零错误。
4. `toolchain/validator --json` 输出包含 `rules[]`（规则 id、级别、命中数）与 `issues[].group`/`note`；`python -m pytest toolchain/tests -q` 全绿。
5. 一条注册为"警告且不可提升"的规则在 `Strictness=WarningsBlock` 下仍不阻断（单测）。
6. `dotnet test Core.sln --filter "FullyQualifiedName~Replay|FullyQualifiedName~Perf"` 基线未变。

**依赖**：无（起点）。

**风险**：`item.budget_curve` 字段改名波及 `ItemBudgetCurve.ParseEntries` 的全部调用点与 `item` 模块测试；`combat.resist_curve` 的 `saturation` 分支横轴语义与等级索引曲线不同，通用契约需支持"二元输入"或拆两种形态，在 T-N0-1 里定死。

## 7. 阶段 N1：属性

**周期**：2 周

**目标**：落地 ADR-0030 全部决策——属性类别与派生两轮聚合、换算层始终启用、来源类别进结算上下文、等级差规则表、属性权重表、职业派生系数覆盖——并按拍板 12 与命中公式改写同一提交更新回放基线。

**任务清单（按六条线）**：

| 线 | 任务 |
|---|---|
| ① 核心逻辑 | `stat.definition` 新字段与迁移；`StatHost` 两轮拓扑序与失效传播；换算层无条件启用、三种曲线形态；`arch.class.derivation_overrides`；`stat.weight` 表；`EffectContext.sourceKind` 与 `IUnitAccess` 载体类型查询；目标乘区按作用域遍历与被暴击减免；`combat.level_diff_table` 与 `DetermineHit` 加减式公式；策略项"有效等级是否计入装备等级偏移"、"是否启用抗性维度" |
| ② 适配层与表现 | 无 |
| ③ 工具链 | 无新增，复用 N0 的规则元数据 |
| ⑤ 内容数据 | `stat.definition` 按推荐分类补齐样例；`stat.weight`、`combat.level_diff_table`、`arch.class.derivation_overrides` 样例；`combat.hit_table_config` 的 miss 分支接上命中属性；`arch.power_type` 样例 health 上限改回固定值 |
| ⑥ 测试与验收 | 两轮聚合、失效传播、换算三形态、作用域目标乘区、命中公式与 Δ 双向、读档后派生重算、派生无环校验、属性无消费者警告；回放基线更新一次 |

**产出**：`Core.Numbers`/`Core.Rules` 属性与命中改动；`stat.weight`、`combat.level_diff_table` 两张新表；1.31.0。

**验收标准（可执行）**：
1. 两轮聚合：≥ 6 组用例（主属性三段式；派生属性由两条来源各带系数；职业系数覆盖生效；负系数；`clamp` 在第二轮之后夹取；来源属性变化后派生属性缓存失效）结果与手算一致。
2. 换算层：恒等、按等级除数、饱和三种曲线各 ≥ 2 组用例；`EnableRatingConversion` 已删除，不存在任何"关闭换算层"的路径（编译期断言）。
3. 来源类别：`scope: from_player` 的减免属性在 `sourceKind=creature` 时不生效、`sourceKind=player` 时生效；被暴击减免介入暴击率（≥ 3 组用例）。
4. 命中：`未命中率 = 基础 − 攻击者命中 + 目标闪避 + Δ 加成`、`暴击率 = 攻击者暴击 − Δ 压制`，Δ 为 −5～+5 的矩阵用例证明双向生效与两段斜率；`有效等级是否计入装备等级偏移` 关闭时装备不影响 Δ。
5. 校验：派生成环报 Error；`derived_from` 出现在非 `derived` 类别报 Error；无消费者属性报 Warning 且不阻断。
6. 迁移：`stat.definition` v1 数据（含 `group`/`is_rating`/`rating_conversion_ref`/`min`/`max`）经迁移链加载后行为与迁移前一致的回归用例 ≥ 1。
7. 回放基线：命中改写提交内按五步更新，`Replay` 测试全绿；Perf 基线不变。

**依赖**：N0 全部验收达成。

**风险**：`EffectContext` 构造点分散（`EffectDispatcher`、`AuraHost.FirePeriodic`、投射物、测试夹具），漏一处 `sourceKind` 默认值会让作用域属性静默失效——T-N1-6 要求 grep 全部构造点并逐一列入涉及文件。
