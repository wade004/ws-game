# 消费方答复：游戏接入方第四十批已交付（2026-09-26）

## 结论

阻塞解除（1.74.0 返工），落在 **1.77.0**（标签 `v1.77.0`，发布提交 `db451b82`，功能提交 `5ccc73fe+c39b228a+cdeb3722`）。ADR-0095；ADR-0091 决策 5"逐帧动画共用同一条解码路径"一句是错的，已勘误——`sprite_anim.*` 走特效解码路径，1.74.0 确实没有覆盖。

## 修法（零数据改动即可生效）

- 加载器契约新增默认接口重载 `IResourceLoader.LoadAsync(id, kind, ResourceLoadHints{ SpriteSetId }, callback)`（旧签名原样保留）；视图工厂加载剪辑的三处调用点（整身默认剪辑、逐层剪辑、武器/技能覆盖剪辑）都把该显示行 `display.map.sprite_set_id` 作为提示传入。
- 特效解码收到提示时，对每帧按 ADR-0091 同一公式取枢轴 `(root.x/帧宽, 1-root.y/帧高)`、ppu 取该精灵集 `anchors.json` 的 `pixels_per_unit`（同一读盘缓存）；方向取资源 id `__<dir>__` 段，无方向按 ADR-0091 决策 2 兜底；帧尺寸与画布不一致以帧为准并 Warn。
- `frames.json` 新增可选顶层 `root:[x,y]` 与 `pixels_per_unit`，声明了优先于精灵集提示。
- 无提示（vfx 特效图集）/ anchors 缺失 / 无 root → 仍 (0.5,0.5) + 全局 ppu，逐字节不变。帧切换与排序公式未动。
- 已知限制：同一 `sprite_anim` 资源先后带不同精灵集提示加载，复用首次解码结果并记一条去重 Warn，不重解码（需卸载资源或重建加载器才按新提示解码）。

## 凭据

- 复现（PlayMode，真实加载器）：仿 48×48、root [24,44]、ppu 32 的精灵集 + 逐帧动画夹具，带提示加载后每帧 pivot ≈ (0.5, 0.0833)、ppu = 32；修复前实测 pivot.y = 0.5。用例 `LoadAsync_Effect_WithSpriteSetHint_PivotAndPixelsPerUnitComeFromAnchorsRoot`（含三处工厂调用点传提示的形状核对）。
- 不变量：无提示走默认；`frames.json` 声明 `root:[5,5]`/`pixels_per_unit:8` 时得 (0.25,0.75)/8；同资源冲突提示复用 + 恰好一条 Warn。用例 `LoadAsync_Effect_Invariants_NoHintExplicitOverrideAndConflictReuse`。
- `Tests.Foundation` 1347/1347（`EffectFramesDocument` 新增 5 例）；`abi_probe` breaks=0；发布门禁见发布提交。
