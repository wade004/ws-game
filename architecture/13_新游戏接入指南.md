## 1. 立项步骤总览

```
1. 选引擎并实现适配层（L-1）       —— 见第 2 节
2. 组装模块与策略配置              —— 见第 3 节
3. 确定口味配置项清单              —— 见第 4 节
4. 定资产规格并接通导入工具        —— 见第 6 节
5. 填数据                          —— 见第 5 节
6. 配表现                          —— 见第 6 节
7. 跑验收                          —— 见第 7 节
```

七步之间允许有限并行（例如数据填充与表现资源制作可与适配层开发并行，定资产规格也可以与填数据并行推进），但"跑验收"必须在其余六步基本完成后进行，且验收标准以本文档集各章末尾的「验收标准」为准。

在跑通以上七步之前，需要先完成一步前置动作：按目标版本号引用框架的一份发布产物快照（而不是直接引用框架的开发目录），并核对随该快照一并提供的锁文件（记录快照版本号与各核心程序集的完整性校验值），确认引用到的内容与目标版本号一致、未被篡改或损坏。除发布产物快照外，也支持经私有包仓库按版本号依赖，两条通道并存、内容一致，选哪条不改变后续步骤。后续升级所引用的框架版本时，同样先重新引用新版本号的快照或私有包仓库条目，再走一遍第 7 节"跑验收"确认升级未破坏既有内容。具体的版本号格式、锁文件字段与完整的升级步骤见 [落地计划/落地方案与分阶段计划.md](落地计划/落地方案与分阶段计划.md) 第 3.5 节"新游戏如何消费本框架"。

前置动作之后还有一步可选项，不强制在立项当天完成：若该游戏需要内容编辑器，复制编辑器项目提供的编辑器模板到游戏仓库（如 `<game>/editor/`）并改名，与游戏工程共用同一份框架锁文件、另锁定编辑器项目自己的版本。编辑器基础套件与编辑器模板不在本框架仓库内，框架只对编辑器承诺契约与两项交付物（无头适配层、校验装配入口），具体决策与承诺边界见 [ADR-0018](adr/0018-编辑器随游戏走与框架为此提供的交付物.md) 与 `editor/docs/编辑器产品文档.md` 第 7 章"游戏项目：编辑器接入指南"。

## 2. 选引擎并实现适配层

按 [02_引擎适配层.md](02_引擎适配层.md) 的评估框架（渲染能力、Y 排序与分层、粒子与着色器、导航、UI、脚本语言与静态类型、headless 测试能力、Windows 导出、许可证与成本、社区与工具链、美术管线兼容、3D 骨骼动画与换装、模型与动画导入格式、2D/3D 混合渲染与排序、固定镜头投影可控性）对候选引擎打分，选定后（若本游戏只使用 `sprite` 型外形，与 3D 相关的四项维度可按低权重或不适用处理）：

1. 逐一实现 L-1 全部接口（窗口与生命周期、帧回调与时间、二维渲染、三维渲染与固定镜头、音频、输入设备、文件系统、资源加载、二维导航与空间查询、UI 承载面、平台服务）。
2. 同时实现一套桩适配层（Stub Adapter，见 [11_工程规范与测试.md](11_工程规范与测试.md) 测试分层）用于 CI 与模块单测，两套实现共享同一组 L-1 接口签名。
3. 若后续需要更换引擎，按 [02_引擎适配层.md](02_引擎适配层.md) 的"迁移引擎步骤"执行，`core/` 各层与游戏层代码理论上不改动。

## 3. 组装模块与策略配置

游戏层（见 [01_分层与依赖.md](01_分层与依赖.md) 游戏层边界）的首要工作是"组装"而非"编写"：

1. 从 L0~L4 的模块清单中选择本游戏需要启用的模块（例如不需要 Economy 的游戏可以不组装该模块）。
2. 为每个启用模块注入其策略配置项（见第 4 节）与自定义策略实现（如自定义目标选择链的具体规则、自定义 AI 行为状态的组合，注意：全新的目标选择"原语"需走 [12_扩展与变更流程.md](12_扩展与变更流程.md) 审批，仅是"新的一种配置组合"不需要）。
3. 注册游戏专属的钩子（HookRegistry，见 [03_运行时骨架.md](03_运行时骨架.md)），用于剧情演出、过场触发等游戏特有但不构成"新原语"的胶水逻辑。
4. 按需接入 owner/day/vendor 三个下层已具备、但装配层默认不接线的回调（12 第 5 节勘误：本条按当前实现补充说明，不改变已定稿结论）：
   - `owner`（任务/掉落等场景下的"归属者"解析）与 `vendor`（商人开店请求）默认不执行——需要时经装配层扩展点（`GameplayAssemblyOptions` 或等价可选参数）显式提供实现，再由本游戏的装配入口（`GameBootstrap` 等）注入；未接入时行为与不使用该能力完全一致。
   - `day`（日夜/天数推进）默认恒返回 `0`，不是任何"游戏内时钟"的替代实现——不要把 Gobj 侧的 `SimTime` 或时间模型的 `time.sim_time`（见 04 第 6.2 节 Expr `time` 分组）误当作等价物，两者用途不同；需要真正的天数推进时，同样经装配层扩展点接入具体游戏自己的日夜循环实现。
   - 三者均属"下层机制已具备、装配层尚未默认接线"的边界情况，不是缺失的原语，接入时不需要走 12 第 2 节新原语审批流程，只需按装配层扩展点的接口签名提供实现。

## 4. 口味配置项清单

以下清单汇总全架构中明确标记为"游戏口味、必须可配置"的项目，是新游戏立项时必须过一遍并显式决策的清单（未列出的口味项以对应章节文档为准）。

| 配置项 | 默认值（建议） | 可选值 |
|---|---|---|
| 主动技能槽数 | 4 | 任意正整数，取决于动作条 UI 设计 |
| 公共冷却开关 | 关闭 | 开启（并可配置公共冷却时长） |
| 目标链（Targeting） | 单体最近敌对目标 | 锁定目标优先、鼠标指向优先、自定义优先级链 |
| 消耗品开关 | 关闭 | 开启（背包内允许消耗类物品） |
| 跳跃 | 关闭 | 开启（影响碰撞与导航的高度语义，见 05） |
| 命中表项（招架/偏斜/格挡） | 全部关闭，仅保留命中/闪避/暴击 | 按需开启招架、偏斜、格挡等附加分支 |
| 资源类型数量与种类 | 单一资源池（如统一的"能量"） | 多资源池（如法力+怒气并存） |
| 控制递减 | 不启用（改用 Boss 免疫标志替代，见 06） | 若确有需要可作为游戏层自定义策略实现，不建议作为通用原语 |
| 方向档位数（仅 sprite 型外形） | 8 | 4、8 或更多，取决于美术资源投入 |
| 外形类型 | 单位与物件均为 sprite | 可选 model（单个逻辑对象二选一，同一游戏可混用，如仅单位用 model、物件仍用 sprite） |
| 场景做法 | 2D 地面图 + 2D 精灵 | 可选 2D 地面图 + 3D 角色、全 3D 场景 |
| 镜头俯角与缩放范围 | 待定 | 具体角度与缩放上下限经 `camera_profile` 数据表（见 04 总索引、[09_表现层.md](09_表现层.md) 第 3.5 节）落地为具体档位，经 `ICamera.configure` 设定，不是一个游戏层需要另开框架配置字段的口味项；游戏层模板（`games/_template`）在口味配置容器里只保留一个衍生开关——场景切换完成后是否重置镜头跟随——作为这条口味项在配置容器层唯一能挂的接入点 |
| 装备外观方式 | 纸娃娃分层加外观分档（大件独立部位独立层、小件按外观分档） | 可选槽位网格替换（`model` 型外形下，见 04 第 7.1.2 节 `display.equip_visual`） |
| 影子方式 | blob（贴地简化影子） | none（不渲染）、projected（投影阴影） |
| 死亡策略 | 传送回复活点 | 读档回退、场景重置、游戏层自定义流程 |
| 自动存档点 | 存档点开启、地图切换关闭、任务完成开启 | 见 [10_存档与持久化.md](10_存档与持久化.md) 第 6 节 |
| 画布分辨率与拉伸策略 | 见 [09_表现层.md](09_表现层.md) 3.6 节，具体数值待定 | 参考分辨率 + 信箱/拉伸/裁剪三选一 |
| 反馈合并窗口 | 见 09 第 6.3 节 | 具体时长与展示形式 |
| 光环多来源分别计时 | 关闭（同来源同光环刷新持续时间，见 06 第 3.8 节） | 开启（同一光环允许多个来源分别独立计时） |
| 单位间移动阻挡（`unit_block`） | 关闭（允许单位重叠，见 05 第 3.6 节，经 `MovementOptions.UnitBlocking` 接线，默认 false） | 开启（单位间互相阻挡移动，`MovementOptions.UnitBlocking = true`） |
| 地面掉落物是否随存档持久化 | 开启（见 05 第 1.6 节） | 关闭（读档后地面掉落物不保留） |
| 探索时间模型 | continuous | discrete（见 03、04 `found.time_model`、ADR-0013） |
| 战斗时间模型 | continuous | discrete |
| 先攻策略 | initiative_stat | action_points、fixed_order（`atb` 为预留扩展位） |
| 每回合秒数换算 `seconds_per_turn` | 6 | 任意正数，仅 `combat_time_model: discrete` 时生效 |
| 移动预算规则 | 距离 | 行动点（`action_points`），见 06 第 6.1 节 |
| 网格吸附 | 关 | 开（声明格子尺寸，范围形状按格子中心采样） |
| 节奏策略 | 按时间模型（连续默认 `immediate`，离散默认 `wait_for_playback`） | 手动指定为 `immediate` 或 `wait_for_playback`，见 03 第 3.2 节、09 第 6.4 节 |
| 开发期数据热重载 | 开启（编辑数据表保存后自动重读，见 `games/_template` README"开发期数据热重载"一节；只在开发/编辑期构建形态生效，发布构建下自动零开销） | 关闭（发布构建也可保留开启，本身已自动零开销；开发期若不需要该行为可显式关闭） |

（建议）新游戏立项文档应把本表逐行填写为该游戏的最终选定值，作为该游戏的"口味配置基线"记录，便于后续内容制作时对齐预期。

## 5. 填数据

1. 按 [04_数据与内容管线.md](04_数据与内容管线.md) 的全表清单，逐表建立本游戏的数据文件，遵循 id 规范（`<domain>.<name>`）。框架级数据表（行由框架代码引用或生成，如事件词汇登记表、输入动作声明）位于分发包 `data/_framework/`，游戏数据目录与之并列加载，不需要、也不应该重复提供这些表。
2. 优先填最小可玩闭环所需的最少数据（一个职业、若干技能、若干生物、一张地图、一条主线任务链），跑通端到端流程后再横向扩充内容量。
3. 全程使用 [12_扩展与变更流程.md](12_扩展与变更流程.md) 第 1 节的按类型 checklist 逐项核对"改哪些表、加哪些资源"，避免遗漏引用字段。

## 6. 配表现

配表现拆成三小步（顺序固定，验收分离原则见 [ADR-0014](adr/0014-资产契约导入工具与UI套件是框架交付物.md)）：

1. **定资产规格**：按框架级资产规格书模板（[14_资产规格书模板.md](14_资产规格书模板.md)，归属见 [11_工程规范与测试.md](11_工程规范与测试.md) 第 2.1 节）填出本游戏的具体值，落到该游戏的接入记录，至少覆盖以下必填项清单：
   - 每类资产的尺寸
   - 锚点约定
   - 方向数与镜像
   - 纸娃娃层清单与叠放顺序
   - 序列帧图集切法
   - 特效贴图格式
   - 图标尺寸与构图规则
   - 音效格式与响度
   - 命名规则
   - UI 与文本所需字体（含中文字体选择）
2. **用占位资产包先跑通**：套用 `assets/_placeholder/` 通用占位资产包与通用 UI 套件默认朴素皮肤，组装 UI 框架实例（HUD、动作条等），配置反馈绑定规则（FeedbackBinder），至少覆盖命中、暴击、死亡、任务完成等高频事件的基础反馈；此步只用占位资产验证逻辑、事件、契约是否正确，不追求手感与观感。
3. **导入工具批量替换真资产**：为已填的逻辑数据逐一配齐 DisplayInfo 映射（生物外形、物品外形、技能 vfx/sfx、武器表现档案；若选用 `model` 型外形，另配齐 `display.anim_set` 动画集与 `display.equip_visual` 装备外观，见 04 第 7.1.1、7.1.2 节），参照 [09_表现层.md](09_表现层.md) 第 7、10 节的对照表，经资产导入工具批量导入并生成外形表行，替换第 2 步的占位资产，替换过程不改任何运行时代码；UI 框架接入本游戏的美术主题与本地化文案。

   **选用 `model` 型外形时的接入步骤**（见 [ADR-0017](adr/0017-模型型外形默认路线补齐与命中帧同步.md)——model 型外形的默认落地路线是框架职责，游戏层只需按以下顺序接数据/口味配置项，不需要另外实现"把逻辑单位画成可动角色"这一段）：
   1. 三维模型资源、骨骼动画剪辑资源均按具体引擎适配层约定的资源路径规则命名（见该引擎适配层的接入文档；框架层不规定磁盘路径，只规定资源引用 id 的写法——`<资源类别前缀>.<名字>`）。
   2. 模型的挂点（供武器/特效等子模型挂接）与可换装槽位（供网格替换）在美术资产内的命名，必须与 `display.map.sockets`/`display.map.slots` 登记的 id 逐字一致（含类别前缀，不做任何裁剪/转换）——引擎适配层按这个精确名字在美术资产内查找对应挂点/槽位。
   3. 填 `display.map` 一行：`kind: "model"`，`model_ref` 指向模型资源，`anim_set_ref` 指向下一步的动画集行，按需登记 `sockets`/`slots`/`default_slot_meshes`/`material_params`。
   4. 填 `display.anim_set` 一行：`clips` 逐条给出状态名（`idle`/`move`/`attack`/`cast`/`hit`/`death`）到具体动画剪辑资源引用的映射；需要关键帧事件（命中帧等）时在对应剪辑的 `events` 数组按 `{name, time_pct}` 声明——`name: "hit_frame"` 是框架固定识别的命中帧标记，命中帧到达时机由引擎适配层经该资源的关键帧事件系统真实触发，不是逻辑层估算。
   5. 需要装备外观随槽位/挂点变化时，按 04 第 7.1.2 节填 `display.equip_visual`；需要武器切换驱动不同攻击/施法动作时，填 `display.weapon_style`（`auto_attack_anim`/`cast_anim_override`），并通过 `item.template.display_ref → display.map.logical_id → display.map.weapon_style_ref` 这条既有关联链路挂上——不需要在 `item.template` 新增字段。
   6. 命中帧同步（09 第 4.3 节 `anim_keyframe_driven` 策略）与武器风格两项都是可选口味配置项，默认关闭/未接线（框架提供机制、游戏层按需接线，见 02 第 1.2 节"策略配置项默认值不代表架构拍板具体数值"同一惯例）；需要启用时按具体引擎适配层的接入文档给出的接线步骤操作。

## 7. 跑验收

按顺序跑通以下验收关卡，每关对应本文档集相应章节的「验收标准」：

1. **数据校验通过**（对应 [04_数据与内容管线.md](04_数据与内容管线.md)）：全部数据表引用完整、schema 版本一致。
2. **模块单测与集成测试通过**（对应 [11_工程规范与测试.md](11_工程规范与测试.md)）：脱离引擎的核心逻辑测试全绿。
3. **确定性验证**（对应 [10_存档与持久化.md](10_存档与持久化.md)）：同种子同输入两次运行战斗日志事件流一致。
4. **表现层铁律核查**（对应 [09_表现层.md](09_表现层.md)、[01_分层与依赖.md](01_分层与依赖.md) 第 6 节禁止事项第 2 条）：人工/工具核查表现层查询只读、只订阅事件——改变状态一律经窄意图命令入口（如 `SubmitIntent`）提交、业务裁决下沉到接收方所在层，不存在表现层代码直接改变逻辑数据（绕开意图入口的写回）的路径。
5. **存档读写与迁移验证**（对应 [10_存档与持久化.md](10_存档与持久化.md)）：新建存档、读档、损坏存档兜底流程均可用。
6. **端到端可玩性验收**：从新游戏开始，经过至少一条完整的技能释放、一次战斗、一个任务完成、一次存档读档，无阻断性问题。
7. **资产管线验收**（对应 [11_工程规范与测试.md](11_工程规范与测试.md) 第 2.1 节、[ADR-0014](adr/0014-资产契约导入工具与UI套件是框架交付物.md)）：一件新资产从出图到进游戏零代码、耗时可量化。

消费方演练脚本（对应 [11_工程规范与测试.md](11_工程规范与测试.md) 第 6.1 节）是第 7 项验收关卡的自动化形式：从零搭建一个独立于框架源码树的最小消费方工程、只以分发产物为输入，机械化验证以上第 1、2 项，以及第 6 项里"新游戏开始、进图、移动、存档、读档"这一段基础设施链路，能否在"从未接触过框架源码"的前提下真正跑通；不依赖人工照着本章节步骤操作一遍。脚本用的是模板自带的最小闭环数据集，不含任何技能释放、战斗、任务内容——第 6 项要求的"至少一条完整的技能释放、一次战斗、一个任务完成"仍需游戏接入自己的内容后另行验收，不在本脚本覆盖范围内（见 games/_template/README.md"已知限制"一节、toolchain/consumer_smoke.ps1 头注释"覆盖范围"）。
