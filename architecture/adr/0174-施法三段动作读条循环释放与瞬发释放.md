# ADR-0174 施法三段动作：读条循环、释放、瞬发释放

状态：已拍板 2026-10-09（来源：`docs/消费方反馈/消费方反馈-2026-10-09-样板游戏B-受击自动选中施法动作技能详情.md` 第 B 节；纯加法，不声明 `release_anim_override` 的技能行为逐位不变，唯一的行为修正见决策 4）

## 背景

读条技能的施法姿势此前只在读条剪辑自身时长内播放一遍：读条剪辑比读条时间短时，姿势提前结束、角色在读条后半段站回待机；读条完成立刻回落运动态，没有"释放"那一下出手动作；瞬发技能一律用普攻剪辑，没有按技能区分的释放动作；读条途中被受击姿势顶掉后，受击结束回到运动态，剩下的读条时间里角色没有任何施法姿势。玩家看到的就是"施法时没有施法动作"。

## 决策

1. **`display.weapon_style` 新增可选映射 `release_anim_override`**（`{技能 id: 动作剪辑}`，格式与 `cast_anim_override` 相同，类别前缀限定 `anim`/`sprite_anim`）。声明了释放动作的技能获得三段动作：
   - **读条技能**（读条时间大于 0）：读条期间 `cast_anim_override` 的剪辑**循环**播放；读条正常完成（`skill.cast_success`）播一遍释放剪辑再回落；被打断/失败直接回落，不播释放。
   - **瞬发技能**：施放时直接播释放剪辑（取代普攻剪辑）；普通攻击与未声明的技能照旧用 `auto_attack_anim`。
2. **动画状态机**：新增可选查询 `ReleaseAnimProbe`（`(施法者, 技能) → 是否声明了释放动作`，装配时由剪辑解析方按武器风格接入；缺省为空 = 行为不变）。读条正常完成且查询为真时，状态从 Cast 切到 Attack 并携带技能 id 去播释放剪辑，播完由播放器完成回调回落（沿用 N19 的收尾口径）。
3. **剪辑解析**：Attack 状态按触发技能 id 先查 `release_anim_override`，查不到用 `auto_attack_anim`；Cast 状态的读条剪辑在该技能声明了释放动作时循环播放，否则播一遍（与既有一致）。
4. **行为修正（对所有游戏生效）**：读条途中被受击姿势（优先级更高）顶掉后，受击结束时若读条仍在继续，状态回到 Cast（携带技能 id，重新播读条剪辑）而不是运动态；读条已收尾（成功/失败/打断）后的受击结束仍回运动态。此前这种情形下读条剩余时间里角色站着不动，属缺陷。
5. 工具链资源存在性检查（`display_anim` 域）覆盖 `release_anim_override` 的值。
6. **武器风格剪辑预热（适配层，行为修正）**：不在动画集默认状态里的武器风格剪辑（`auto_attack_anim`、`cast_anim_override`/`release_anim_override` 的全部取值），此前在第一次被用到时才异步加载，加载完成前该状态呈现一张 1x1 白色占位帧（实测约 2 秒），玩家第一次施法看到的是白点而不是施法姿势。视图挂接动画播放器时与装备武器变更后，适配层对该实体当前武器风格的这些剪辑提前发起加载（带该实体的精灵集提示，保持 ADR-0095 的提示一致），首次使用时已在缓存里直接登记真实剪辑。只发加载请求，不改变登记与升级逻辑；没有武器风格来源、非精灵形态的视图不受影响。
7. **读条期间别的施法请求被拒，不收读条姿势（行为修正，对所有游戏生效）**：`skill.cast_failed` 说的可能是读条期间另一个新请求被拒（读条占用 `Busy`、冷却、没有目标……；敌人的 AI 每个决策间隔都会再请求一次，玩家读条时按别的技能键同理），此前一律当作读条收尾，读条姿势被提前收回待机（实测咒术师读条 1.8 秒，约 0.3 秒后站回待机）。动画状态机记录读条的实例 id（`skill.cast_start` 的 `CastInstanceId`），失败事件的实例 id 与之不同（含校验阶段失败、没有实例 id 的新请求）就忽略；实例 id 相同（读条本身失败），或没有可比较的实例 id（旧事件构造）仍按收尾处理，与改动前一致。

## 后果

- 新增 `WeaponStyleDef.ReleaseAnimOverride`（新构造重载，旧五参构造保持原签名）、`AnimStateMachine.ReleaseAnimProbe`、`display.weapon_style.release_anim_override` 数据字段，均为纯加法。
- 读条剪辑循环对美术的要求：循环剪辑应当是可首尾相接的"持杖蓄力"姿势片段，释放剪辑是出手到收招的片段；一份既含蓄力又含出手的整段读条剪辑不适合直接循环。

## 限制（已知）

1. 受击姿势顶掉施法姿势后回到 Cast 是从读条剪辑第一帧重播（不记录播放进度）。
2. 引导技能（`channel_time` > 0）沿用同一规则：引导期间循环读条剪辑，引导结束播释放。
3. 反应驱动受击模式下受击本就不打断动作态，不受决策 4 影响。

## 备选方案与为什么不选

- **按读条时长拉伸整段剪辑。** 读条 0.5 秒与 3 秒的同一剪辑速度差六倍，前几帧与待机几乎相同的姿势依然看不出施法；循环 + 释放两段才能让任意读条时长都有清楚的动作。
- **在动画集里用 `cast.loop`/`cast.release` 之类的通用键。** 一个角色所有技能共用同一对剪辑，无法按技能区分（火球与治疗的出手动作不同）；按技能的映射与既有 `cast_anim_override` 同一形状。
