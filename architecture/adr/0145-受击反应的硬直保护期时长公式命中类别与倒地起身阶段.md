# ADR-0145 受击反应的硬直保护期、时长公式、命中类别与倒地起身阶段

状态：已拍板 2026-10-04（落实 [手感设计/03](../手感设计/03_攻击受击与命中.md) 第 4 节；取代 [ADR-0117](0117-局部顿帧作为判定型手感.md) 决策 6 中"落地为内部控制光环、受控制递减约束"的表述，其余决策不变）

## 背景

手感落地后对照设计评审，受击反应一侧有八处缺口或矛盾：

- 03 写"硬直落地为内部控制光环，受控制递减约束"，实现里硬直从来是裁决宿主自己的硬直窗口，没有光环、也没有递减；于是"被高频攻击无限硬直锁"没有任何防线（窗口每次被更长的新反应刷新）。
- 武器对硬直时长没有任何贡献（`hit_stun_ms` 只在受击方）；05 第 9 节"硬直 150/230 ms"没有落点。
- 击退时长只有一个游戏级常量，重击与轻击一样快。
- 暴击、格挡、偏斜、弹反的顿帧与反应与普通命中完全相同；格挡 / 弹反 / 偏斜没有裁决语义。
- 倒地只有"硬直 + 倒地"，没有起身段、起身无敌与阶段事件；反应 → 姿势键没有契约，表现层无从驱动。
- 实验室没有击退距离、倒地时长度量。

## 决策

1. **删除"硬直 = 内部控制光环 + 控制递减"**。硬直是裁决宿主登记的硬直窗口；防"无限硬直锁"的机制改为受击方可选字段 `stagger_grace_ms`（硬直保护期）：从硬直登记起到硬直（含倒地与起身）结束后再过这么久，期间新的硬直类反应截到 `stagger_grace_cap`（缺省 `flinch`），击杀不受影响。理由：光环机制从未接入且语义（免疫、递减按类别）与受击反应不同，补上它比用一个窗口字段复杂得多。
2. **硬直时长公式**：受击方 `hit_stun_ms` × 攻击方 `hit_stun_scale`（武器为主，缺省 1）× 游戏级"反应类型倍率表"（缺省空表即全 1）。倒地段与起身段不乘。05 第 9 节"硬直 150/230 ms"明确为受击方基础值的参考取值，武器差异用 `hit_stun_scale` 表达；`inflicted_hit_stun_ms` 保持为不参与解析的参考数据。理由：武器贡献落在攻击方一侧，受击方基础值保持单一来源。
3. **击退时长**：攻击方可选字段 `knockback_duration_ms`，缺省取游戏级选项（再缺省取运动层缺省），与此前逐位一致。
4. **命中类别**：`Crit`/`Block`/`GlancingBlow`/`Parry` 各自可独立声明冲击等级与顿帧倍率（暴击读攻击方，其余读受击方），格挡另有 `block_reaction_cap` 与 `block_attacker_reaction`，弹反有 `parry_attacker_reaction`；未声明的类别逐位等价普通命中。
5. **格挡裁决**：新增防御裁决接口（命中表之前问一次）与防御状态查询接口 `IGuardStateQuery`（防御方的动作层 / 输入层实现，缺省没有实现时回退到动作实例的时间线标记 `guard_start`/`guard_end`）。语义：起身无敌 → `Invulnerable`；格挡中且攻击来向在 `guard_arc_deg`（缺省 180）内：格挡开始后 `guard_parry_window_ms` 内 `Parry`，否则 `Block` 且伤害乘 `guard_damage_scale`；只对会掷命中表的非周期伤害生效（起身无敌对全部非周期伤害生效）。理由：属性随机的 Block/Parry 无法表达"举盾期间正面被挡"。
6. **倒地 → 起身**：`knockdown` = 硬直段 → 倒地段（`downed_ms`）→ 起身段（`getup_ms`，缺省 0）；起身段开头 `getup_invuln_ms`（缺省 0）内命中判 `Invulnerable`。新事件 `unit.knocked_down`/`unit.getup_started`/`unit.getup_finished`；`combat.reaction_applied` 追加 `stunTicks`/`downedTicks`/`getupTicks`；`combat.hit_confirmed` 追加 `reactionDetail`/`attackerReaction`（均为加法）。
7. **反应 → 姿势键映射表**写入 03 第 4.5 节（`hit.light/heavy/knockback/knockdown/getup/block`；`stunned` 不属于受击反应）；姿势由表现层按事件驱动，规则层不选姿势。
8. **实验室**：三个脚本与独立数据根、独立条件度量组 `reactionext`（击退距离峰值、倒地 / 起身时长、起身无敌结局、被连击锁住、格挡结局），既有脚本基线不变。

## 后果

### 正面

- 受击反应的每个新机制都是可选字段，缺省与此前逐位一致（既有实验室基线、数据集内容均不变）。
- 无限硬直锁有了数据层的防线，且玩家侧与怪物侧同一套。
- 倒地 / 起身有阶段事件，表现层与实验室可直接度量。

### 负面

- 保护期字段声明后，硬直进行中被打到的那一击也截到 `stagger_grace_cap`（想允许追击升级成击倒需把它设为 `knockdown`）。
- 同一 tick 内裁决的两次命中在任一方登记硬直之前各自读到"无保护"，两击都得到完整反应。
- 每次击倒都发阶段事件，倒地期间被刷新则事件重发。
- 格挡 / 弹反窗口读不到防御状态实现时依赖动作时间线标记；输入层的格挡状态由后续切片接入查询接口。

## 备选方案与为什么不选

- **接入控制光环与递减**：需要给受击反应单独定义控制类别、免疫与递减曲线，且玩家与怪物的硬直都得走光环；否决，用一个窗口字段解决同一问题。
- **把 `inflicted_hit_stun_ms` 改成武器层分层字段**：改变现有数据与解析语义；否决，新增 `hit_stun_scale` 承载武器贡献。
- **起身无敌写成游戏级常量**：不同角色起身动作不同；否决，做受击方字段。
- **暴击 / 格挡类别的差异只由反馈包体现**：判定型手感（顿帧、反应）无法区分；否决。
