# ADR-0182 鼠标按钮规范名（MouseButtons）

状态：已拍板 2026-10-11（来源：样板游戏 C 真机试玩——鼠标左键攻击、中键锁定都不触发；缺陷修复，契约补全）

## 背景

输入映射的绑定字符串写作 `mouse:left`、`mouse:middle`，设备事件的按钮名原样与绑定里的名字做序数比较。适配层契约只说“设备侧名字由各引擎适配层约定”，没有规定鼠标按钮叫什么。结果是两侧各取了一套：数据、文档、全部测试用 `left`/`right`/`middle`，而引擎适配层发出的事件键名和按住查询用的是 `MouseLeft`/`MouseRight`/`MouseMiddle`。两边没有任何一处会报错，所以真机上**所有** `mouse:*` 绑定静默失效，只有用桩适配层按绑定写法喂事件的用例是绿的——用例测的是真机上不存在的路径。

## 决策

1. **契约词汇表 `MouseButtons`**（引擎适配层契约）：规范名只有 `left`、`right`、`middle`，小写、区分大小写、序数比较。它是三处共用的**唯一一份**名字：适配层发出的鼠标按钮事件（按下/抬起）的键名、`IInput.IsKeyDown` 查询鼠标按钮时传入的名字、绑定字符串 `mouse:<button>` 里的 `<button>`。
2. **选绑定侧的写法作为规范名**：绑定字符串是写进数据、被设计与美术直接编辑的公开语法，已有数据与文档都用 `left`/`right`/`middle`；改它会破坏所有已写的数据，而适配层是代码、一处翻译即可。按钮名与键盘键名（小写控件名）、手柄按钮名的写法也一致。
3. **适配层负责翻译，不接受别名**：引擎自己的鼠标按钮命名只存在于适配层内部，边界处统一翻译成规范名。绑定解析器对 `mouse:` 只放行规范名，其余名字在解析时抛 `ArgumentException`（报错信息列出规范名集合）；桩适配层的鼠标按下/松开测试驱动同样只接受规范名。**不做两边都认的别名兼容**——别名会让下一次不一致继续静默。
4. **运行时不静默**：输入映射宿主收到非规范的鼠标按钮事件名时，对每个不同的名字发一次诊断警告（该事件仍然匹配不上任何绑定）。
5. **不变量用例**：(a) 桩层与输入映射：规范名集合里每个名字都能触发对应 `mouse:` 动作，且只触发自己那一条；(b) 引擎适配层：用真实设备（虚拟的鼠标设备，走引擎自己的设备与动作路径）逐个按下物理按钮，适配层发出的每个鼠标按钮名都在规范名集合里、能被绑定解析器解析，反过来规范名集合里的每个名字都有物理按钮会发出它。

## 后果

- 引擎适配层发出的鼠标按钮事件键名与按住查询的名字**变了**（由旧的带前缀大写名改为规范名）；绑定数据不用改，此前写 `mouse:left` 的数据此版本起在真机上生效。直接读旧名字的游戏代码（鼠标按住查询、手写的事件匹配、脚本化输入测试替身）需要改用 `MouseButtons` 常量。
- 数据里写了规范名之外的 `mouse:` 绑定（此前解析成功但在任何适配层上都不会触发）从此在载入/解析时报错，而不是静默无效。
- 前进/后退侧键目前没有适配层事件，也不在规范名里；需要时作为新增规范名走本词汇表扩充（纯加法）。

## 限制（已知）

1. 规范名集合是封闭的：游戏不能自造鼠标按钮名。
2. 适配层对侧键、更多按键的鼠标不发事件。
3. 按住查询 `IsKeyDown` 与键盘键名共用同一个参数空间；规范名（`left` 等）与键盘键名不重叠（键盘左右方向键叫 `leftArrow`/`rightArrow`），但这是约定而非类型保证。
