# ADR-0136 可注入帧时间源

状态：已拍板 2026-10-03（对 [ADR-0120](0120-手感实验室为框架交付物.md) 决定 4"引擎宿主录制"与 [ADR-0134](0134-实验室引擎宿主.md) 决定 6"模拟时间驱动表现"的契约补充；手感落地 M4-W4 引入）

## 背景

引擎适配层的帧动画播放器与特效序列播放器此前每帧取引擎的帧间隔推进自己的时间轴。实验室引擎宿主要在同一个表现帧里同步跑完整段模拟，并要求结果可复现，所以必须由宿主按模拟时间推进这些播放器。M4-H 当时的做法是适配器里留一个内部推进入口，再用内部可见性开给宿主程序集——这是适配器与宿主之间的内部耦合：入口不属于公开契约，别的需要确定性驱动的使用方（回放、截图测试、自写工具）用不了，也不知道它的存在。

## 决策

1. **契约**：新增帧时间源接口，只回答一个问题——"这一步多长（秒）"。同时提供手动设置步长的实现（负数与非数当 0）。

2. **播放器暴露可选的时间源与公开的单步入口**：帧动画播放器、特效序列播放器暴露公开的可选时间源属性与公开的单步入口；二维渲染适配器对其已有与此后新建的全部序列帧特效提供同样的时间源属性与单步入口。**不设置时间源则每帧取引擎的帧间隔，行为与引入之前逐位一致。**

3. **时间源不决定"何时推进"**：引擎播放循环仍只在真实帧上调用更新；需要在一次调用里同步跑完整段模拟的驱动方，逐步调用单步入口，每步的长度由其注入的时间源给出。

4. **删除内部推进入口**：原来的内部推进入口删除或改为私有，内部可见性中不再需要的项一并删除。仍保留的内部可见性只服务于必须由引擎宿主驱动的内部推进（资源加载器、音频、镜头与模型的逐步更新），按设计这些只应由引擎宿主驱动，不另开公开入口。

## 后果

### 正面

- 确定性驱动（实验室引擎宿主、回放、截图测试、自写工具）通过公开契约获得可复现的推进，不再依赖内部可见性。
- 全部是加法：不注入时间源的游戏行为不变。
- 时间源只回答步长、不接管循环，播放器的更新入口语义不变。

### 负面

- 多一个注入点：驱动方要自己保证"调用单步的次数与模拟步一致"，错了就会让表现与模拟错位。
- 资源加载器、音频、镜头、模型的逐步更新仍不在公开契约内，确定性驱动它们的使用方仍局限于引擎宿主。

## 备选方案与为什么不选

- **保留内部推进入口，继续用内部可见性**：入口不属于公开契约，耦合持续存在；否决。
- **全局时间缩放**：影响全部播放器与无关的引擎子系统，且无法表达"按模拟步逐步推进"；否决。
- **把时间源做成播放器的必选构造参数**：违反"契约只加不改"，既有构造调用方全要改；否决，可选属性。
- **时间源直接驱动循环（取代引擎帧回调）**：要接管引擎播放循环，侵入过深；否决。

## 魔兽世界的对应做法

无直接对应：魔兽客户端的动画与特效按客户端帧时间推进，没有"由外部驱动方按模拟步注入时间"的需求。
