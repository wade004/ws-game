# ADR-0030 属性系统：派生两轮聚合、换算层始终启用、来源类别作用域、等级差规则表

状态：已拍板 2026-09-14

## 背景

2026-09-13～14 的数值设计讨论（属性、技能、装备、经验、金钱五块，方法见 [数值总纲](../数值设计/00_数值总纲.md)）发现 06 第 1 节的属性系统缺少让"数值有依据"的几层结构：

1. `stat.definition` 只登记属性 id、显示名文本键、聚合分组，属性之间没有任何关系。主属性（力量、敏捷等）与派生属性（攻击强度、生命上限等）在框架眼里是互不相关的两个数，"同一件加力量的装备对不同职业价值不同"无法表达。
2. 评级换算（`stat.rating_conversion`）是"默认关闭的可选策略"，等于框架替所有游戏决定了百分比属性直给。但数值尺度是游戏口味：保守版直给加硬上限，标准版按等级贬值，变态版点数堆到上亿仍要收敛，三者只是换算曲线形态不同。
3. 00 取舍表"PvP 全部直接去掉、无替代"没有为后续联机对战留口子。魔兽韧性的本质只是"目标乘区按伤害来源类别多读一条属性"，不是新系统。
4. 命中判定（06 第 4.2 节）没有等级差修正。"跨等级打不中、装备落后打不中"是用户明确要求保留的手感，且怪物经验的等级差衰减、目标名字的灰绿黄橙红五色与它共用同一条界线。
5. 属性权重（每条属性折算成"一点主属性当量"）没有登记处，而装备预算消耗、技能预算、装备评分、自动配装都要用它。

## 决策

1. **属性定义增加类别、派生规则、取值区间、换算曲线引用、作用域。** `stat.definition` 新增字段：`category`（`primary|derived|percent|defense|misc`）、`derived_from`（`List<{stat, coefficient}>`，可选，仅 `derived` 类别）、`clamp`（可选 `{min, max}`）、`conversion_ref`（可选，指向换算曲线，仅 `percent` 类别）、`scope`（`any|from_player|from_creature`，默认 `any`）。
2. **聚合改为两轮拓扑序。** 第一轮：无派生来源的属性完成三段式聚合。第二轮：派生属性的基础值 = Σ（来源属性最终值 × 派生系数），再走自己的三段式。派生关系必须无环，校验器新增"派生无环"阻断项。职业模板可覆盖派生系数（`arch.class.derivation_overrides`，可选）。
3. **换算层始终存在，恒等曲线为默认。** `stat.rating_conversion` 的语义由"评级换算策略开启时才用"放宽为"换算层始终启用；`percent` 类别属性未引用曲线时按恒等处理"。换算曲线契约固定为"输入点数与单位等级，输出百分比"，与 `combat.resist_curve` 同形态。00 第 3 节"属性评级换算 大幅简化"一行的结论相应修订。
4. **数值表示与值域。** 框架明确数值为 64 位浮点，有效数字约十五位；超出量级的游戏需在游戏层选型分段单位或大数表示。框架不写任何绝对上限，值域校验沿 ADR-0021 由游戏层登记。变态版尺度下百分比段膨胀的处理是用既有独立乘区分组拆开相乘，不改聚合算法。
5. **来源类别进结算上下文，属性作用域字段承接韧性口子。** 结算管线输入新增"来源类别"（施法者是玩家单位还是生物单位，由载体类型给出，联机时可细化）；"目标乘区"步骤按来源类别读取 `scope` 匹配的减免属性。单机下 `from_player` 作用域的属性永远读不到，零成本。00 取舍表"PvP 全部"一行修订为"去掉 PvP 系统本身，属性与结算保留来源类别维度作为扩展口"。控制递减仍留在光环叠加规则的策略钩子上，不进属性层。联机对战的确定性前提沿 ADR-0003 预留的定点数学 ADR 另行处理。
6. **命中保留，等级差规则表。** 新增 `combat.level_diff_table`：以"目标有效等级 − 攻击者有效等级"为横轴的三条曲线加一条界线——未命中加成、暴击压制、经验系数、灰名界线（随攻击者等级放宽）。命中判定 = 攻击者命中属性 − 目标闪避属性 − 未命中加成(Δ)；双向生效（怪物打高等级玩家同样吃惩罚）。有效等级默认等于角色等级；"有效等级是否计入装备等级偏移"为策略配置项，默认关闭（装备落后导致打不中走自然路径：命中属性本身来自装备）。目标名字五色由灰名界线与固定分档决定。
7. **属性权重表。** 新增 `stat.weight`：属性 id → 权重（一点主属性当量），可按职业覆盖。消费者：装备预算消耗（ADR-0032）、技能控制/增益价值（ADR-0031）、装备评分与自动配装。
8. **资源上限固定、回复速率派生（与 ADR-0031 决策 3 配套）。** 推荐默认：资源池上限走"固定值"来源，不随等级成长；派生属性列表中"资源上限"改为"资源回复速率"。上限来源字段本身仍支持引用属性，某个游戏要成长上限是数据选择。
9. **单机属性推荐分类（游戏层默认值，非框架硬编码）：** 主属性四个（力量、敏捷、智力、体质）；派生属性（攻击强度、法术强度、护甲、资源回复速率，见"修订记录"2026-09-14 一条）；战斗百分比属性小集合（暴击率、暴击伤害、急速、闪避、命中）；防御（护甲走减免曲线，元素抗性可选维度）；资源池；杂项（移动速度、仇恨系数、先攻、幸运）。韧性、精通、精准、穿透、防御等级不做通用属性。

## 后果

### 正面

- 主属性→派生的职业差异化、百分比属性的尺度无关、联机口子、等级差手感四件事各用一个字段或一张表解决，没有新增原语。
- 换算层总是存在意味着保守版与变态版共用同一套聚合代码，只换数据。
- 等级差表把命中、暴击、经验、目标颜色四个消费者绑到同一条界线，避免四处各自维护"灰名"定义。

### 负面

- 属性聚合从一轮变两轮，`StatHost` 需要按拓扑序缓存派生关系；派生系数变化（职业模板覆盖、光环临时改系数）需要触发重算。
- `stat.definition` 字段从三个增至八个，内容作者需要理解类别与派生的关系；编辑器需要展示派生图。
- 来源类别进入结算上下文是契约扩展，所有结算调用方要补这一入参（默认由载体类型自动填充，调用方通常无感）。

## 备选方案与为什么不选

- **保持属性无关系，主属性直接当攻击力用**：否决——职业差异只能靠每个职业各写一套装备，内容量翻倍。
- **评级换算继续作为默认关闭的可选项**：否决——框架不能替游戏决定数值尺度；恒等曲线作为默认值与"关闭"在保守版下行为相同，但变态版不必改代码。
- **韧性作为独立的 PvP 属性系统**：否决——它只是目标乘区多读一条属性，作用域字段足够；独立系统会把 00 已裁剪的 PvP 机制整个带回来。
- **命中去掉，闪避放怪物侧**：否决——用户明确要求"跨等级刷怪就是打不中，需要玩家自己提升"。
- **等级缩放（怪物等级跟随玩家）替代等级差表**：否决——见 ADR-0033 决策 8，单机以固定区域等级带为默认。

## 魔兽世界的对应做法

魔兽 3.3.5：五主属性按职业系数换算为攻击强度/法术暴击/生命/法力/回复；副属性以"评级"写在装备上，按单位等级换算成百分比，同样点数在高等级换出更少百分比；韧性为"受到玩家来源伤害与暴击时的额外减免"；命中/暴击受攻防双方"技能值"（等级×5）之差影响，差距两级内每点加得少、超过两级陡增；怪物经验按等级差递减到灰名归零。本 ADR 保留主属性换算与等级差两段斜率的思想，把评级换算泛化为"换算层 + 任意曲线"，把韧性缩为作用域字段，去掉精通/精准/穿透/防御等级等阈值型或微调型属性（对应暴雪熊猫人到德拉诺期间的删减）。
