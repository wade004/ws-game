# ADR-0012 表现形态：双外形类型（2D 精灵默认、3D 模型可选）加固定镜头，逻辑保持二维平面

状态：已拍板 2026-09-04

## 背景

装备驱动外观在纯 2D 纸娃娃下，出图量按"方向数 × 动作数 × 部件数 × 角色数"增长，是美术成本的上限之一；固定镜头下用三维模型承载角色与装备，换装可以变成挂点与网格槽位替换，外观数量不再直接受该组合数约束。为了让架构对不同项目的美术预算与团队管线保持中立，架构在保留 2D 精灵路线为默认的同时，新增三维模型作为可选的外形路线，场景仍以 2D 地面图为主以控制成本。

## 决策

1. 逻辑层不变：世界坐标仍是二维平面 `Vec2`，`layerDepth` 仍是逻辑深度键，`heightOffset` 仍是表现参数，范围形状、导航、视线全部保持平面定义。
2. 表现形态由游戏层在两种外形类型中选择，架构同时支持：`sprite`（2D 精灵，含方向量化与镜像、纸娃娃分层）与 `model`（三维模型，骨骼动画、挂点、槽位换装）。同一游戏可混用（例如单位用 model，物件与掉落物用 sprite）。**默认路线是 `sprite`**；`model` 是新游戏立项时可显式选择的可选路线，不强制采用。
3. 场景做法默认是"2D 地面图 + 2D 精灵"；游戏层可选择升级为"2D 地面图 + 前景遮挡层 + 3D 角色"的混合渲染，或进一步选择全三维场景。后两者都是可选路线，不作为默认路线，也不在本 ADR 中强制展开全三维场景的落地细节。
4. 镜头固定俯角与朝向，只做跟随与有限缩放，无论游戏层选择哪种外形路线都统一适用；世界平面到屏幕的投影、屏幕到世界平面的反投影由引擎适配层提供。
5. 引擎适配层新增 `IRenderer3D` 与 `ICamera` 接口；`IRenderer2D` 保留用于地面层、前景层、2D 粒子、飘字。`IRenderer3D` 仅当游戏层为至少一类外形选择 `model` 型时必需，只用 `sprite` 型的游戏可以不实现它。2D 层与三维模型（若启用）在同一深度排序空间内按 `sortY` 合成，由适配层保证。

## 后果

### 正面
- 默认的 2D 精灵路线维持不变，已有的纸娃娃管线与成本模型不受影响。
- 需要更高装备外观自由度的游戏可以按需选择 `model` 型外形，换装从"重绘纸娃娃层"变为"替换槽位网格或挂接挂点模型"，突破"方向数 × 动作数 × 部件数 × 角色数"的组合约束。
- 固定镜头在两种外形路线下统一适用，游戏层切换外形路线时镜头与投影相关的表现代码不需要重写。

### 负面
- 架构本身需要多维护一套接口（`IRenderer3D`）与相关数据表（`display.anim_set`、`display.equip_visual`），即使某个具体游戏从不使用 `model` 型外形，这部分定义仍是架构文档与引擎评估框架的常驻内容。
- 若某个游戏选择使用 `model` 型外形，其目标引擎必须具备三维骨骼动画、槽位换装与 2D/3D 混合排序能力，纯二维引擎不适用于该游戏；仅使用 `sprite` 型外形的游戏不受此约束。
- 二维层与三维模型混合排序、固定镜头的投影/反投影需要引擎适配层承担更多职责，一旦某游戏启用 `model` 型外形，其实现复杂度高于纯二维渲染。

## 备选方案与为什么不选

- **只保留纯 2D 纸娃娃，不提供 model 型选项**：维护面最小，但会让个别希望用三维模型换装换取更高外观自由度的项目完全没有架构内的路径可走，只能自行在架构外拼装，不采纳。
- **三维预渲染成精灵**：用三维模型预渲染出各方向序列帧，兼顾三维建模效率与二维渲染管线，但需要维护"三维制作 + 预渲染烘焙 + 二维播放"两套并行管线，长期维护成本高于直接提供 `IRenderer3D` 接口，不采纳。
- **把 model 型设为默认路线**：直接以三维模型为默认表现形态，画面表现力上限更高，但收窄了默认可用的引擎范围、抬高了默认美术管线门槛，与"架构默认路线应尽量降低起步成本"的取向冲突，不采纳；作为可选路线保留。

## 魔兽世界的对应做法

魔兽世界本身是三维模型加 `CreatureDisplayInfo` / `ItemDisplayInfo` 换装（几何组与贴图替换）的体系，本决策里 `model` 型外形的"槽位网格替换"是它的直接对应；固定镜头的做法则来自 MOBA 与俯视 ARPG 类游戏，与魔兽世界本身的自由镜头不同，是本架构在裁剪定位下额外引入的表现约束，且与外形路线的选择（`sprite`/`model`）相互独立。
