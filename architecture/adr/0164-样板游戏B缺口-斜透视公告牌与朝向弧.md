# ADR-0164 样板游戏 B 缺口：斜透视公告牌渲染、技能朝向弧与内容起步包预算规则

状态：已拍板 2026-10-08（来源：第 5 阶段样板游戏 B「2.5D 目标选择式 RPG」暴露的框架缺口；全部为纯加法，既有行为在不使用新能力时完全不变）

## 背景

样板游戏 B 用斜透视相机观察平面精灵世界：相机可以绕竖轴转、可以缩放，角色与场景物件是"立起来"的公告牌精灵，技能走目标选择式（点选/切目标、自动攻击、读条、技能栏冷却、公共冷却）。做的过程中发现几处只能绕行的缺口：

1. **生产渲染链路不支持相机偏航后的 2.5D 呈现。** 相机契约早已支持偏航/俯仰/透视，但：(a) 排序键与朝向换算没有把相机偏航算进去，相机一转，遮挡关系与角色朝向都错；(b) 引擎适配层的精灵实例把"高度"直接写成本地 Y，是平放在世界平面里的，相机倾斜后精灵是躺着的；特效序列播放器同理。此前只有实验室场景里有一份私有实现，生产路径没有。
2. **技能没有"朝向弧"检查。** 显式目标施法只走链条过滤，不检查施法者面向；目标选择式游戏常见的"目标在身后不能施放"只能由游戏在施法前自己算，且拿不到统一的失败原因。

3. **内容起步包的稀有/史诗品质让预算规则互相矛盾。** 起步包的稀有、史诗品质带可抽词缀（预留份额 0.3），"模板自身消耗 + 预留 <= 上限"要求自身消耗至多占 70%，而装备预算利用率警告要求至少 70%，窗口宽度为零；任何不带词缀的稀有装备要么报错要么报警。

## 决策

1. **渲染选项新增相机偏航提供器。** `RenderOptions.CameraYawRadiansProvider`（可空委托，约定同相机朝向契约的偏航：相机右方向为 (cos yaw, sin yaw)）。提供时：排序键沿屏幕上方向投影（`-x·sin(yaw) + y·cos(yaw) + 偏移`），朝向换算减去偏航，使"屏幕上更靠下的先画"与"角色朝向跟随相机"在相机旋转后依然成立。不提供时两处计算与此前逐位一致。
2. **引擎适配层的精灵渲染器新增公告牌相机。** 引擎适配层精灵渲染器的 `BillboardCamera`（可空）：设置后，精灵层根节点旋转到与相机平行、高度沿相机上方向抬升（而不是世界 Y），影子仍贴地；公开 `ApplyBillboards()` 供相机每帧转动后重新摆放；设回空还原为平放。特效定义新增布尔字段 `upright`（默认假）：为真的序列帧特效同样转到与相机平行。
3. **技能新增 `facing_arc`（度，可选）。** 声明后，施法起手（只在起手检查一次，不在读条途中复查）时，对每个解析出的非自身目标：施法者面向与"指向目标的方向"夹角（折到 [-π, π]）超过 `facing_arc/2` 则拒绝，失败原因为新增枚举值 `CastFailureReason.NotFacing`（追加在枚举末尾，不挪动既有值）。与目标重合的目标视为在弧内。校验规则：`facing_arc` 须在 (0, 360]；与 `timeline` 技能互斥（时间轴技能不走起手检查步骤）。
4. **相机转动、公告牌与排序键的游戏侧接线** 见游戏自己的装配（框架只提供提供器与公开方法，不替游戏决定相机怎么转）。
5. **装备预算利用率警告扣除词缀预留份额。** 利用率分母由"预算上限"改为"预算上限 ×（1 − 可抽词缀最大预留份额）"（预留份额的口径与词缀份额规则共用同一段逻辑，按品质池、模板词缀白名单与 `affix_count` 计算；不带词缀的品质预留为 0，行为不变）。警告消息写明已扣除的预留份额。
6. **资产导入工具的特效子命令新增 `--upright`**，写出 `vfx.def.upright`（重导入不丢字段）。

## 后果

- 样板游戏 B 的相机、朝向、排序、公告牌绕行可以删掉；其它游戏不用改。
- 枚举 `CastFailureReason` 新增值在末尾，公开面兼容探针 0 破坏。装备预算利用率警告的分母变化只影响带词缀品质（起步包稀有/史诗）上原先必然误报的模板。技能数据新增可选字段，旧数据不受影响。
- 公告牌的俯仰倾斜让精灵平行于相机而不是平行于世界地面：贴地的光环类特效应保持 `upright` 为假。

## 限制（已知，随各模块判断记录登记）

1. 朝向弧只在起手检查，读条途中目标绕到身后不会打断（决策 3）。
2. 朝向弧只对"显式解析出的目标"生效；无目标施法（地面点、自身）不检查（决策 3）。
3. 公告牌只处理旋转与高度抬升，不做"随相机距离缩放"的补偿（决策 2）。
4. 同一模板白名单与品质 `affix_count` 之外的词缀抽取规则（如按等级过滤）不在预留份额口径内（决策 5）。
