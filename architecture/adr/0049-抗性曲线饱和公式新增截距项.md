# ADR-0049 抗性曲线饱和公式新增截距项

状态：已拍板 2026-09-20

## 背景

`combat.resist_curve` 表的 `kind=saturation` 分支把护甲/抗性属性值换算成减免百分比，公式固定为：

```
reduction = value / (value + k × attackerLevel)
```

其中 `value` 是护甲/抗性属性当前值，`attackerLevel` 是攻击者等级，`k` 是数据配置的系数（见
06 第 4.3 节"输入护甲/抗性值、输出 0~1 减免百分比"这一契约；架构只固定契约，不固定具体数学式，
系数由数据配置）。消费方反馈第 7 条指出这条公式表达力受限，具体成因：

1. **分母只能是 `attackerLevel` 的纯比例项**（一条过原点的直线，斜率 `k`）。减免因此只能写成
   "护甲/抗性与等级比值"的函数——两条内容只要 `value / attackerLevel` 的比值相同，换算出的减免就
   完全相同，无法表达"存在一个不随等级缩放的基础量"这类更常见的曲线诉求。
2. **低等级段的退化**：`attackerLevel` 很小时（例如等级 0/1 的入门内容），`k × attackerLevel`
   趋近于 0，分母趋近于 `value` 本身，`reduction` 趋近于 1——只要护甲/抗性属性值大于 0，换算结果
   就已经在夹到 `max_reduction` 之前逼近饱和上限。低等级内容里，曲线在这一段完全没有实际调参
   空间：无论把护甲数值设成多少，结果都是同一个封顶值。

以上两点是同一个根因的两个表现：公式的分母是"经过原点"的一次函数，游戏层没有任何数据字段能把
这条直线整体平移，只能靠调 `k`（斜率）间接、并不精确地缓解退化区间。

## 决策

1. **饱和公式新增截距项 `k0`，分母改为一般仿射函数**：

   ```
   reduction = value / (value + k × attackerLevel + k0)
   ```

   `k0` 与既有系数 `k` 同属一条记录的两个平级数值字段，含义是"分母上不随等级缩放的常数偏移"——
   `k0` 越大，同样的护甲/抗性值换算出的减免越低（曲线整体收紧），且这个效果不随等级变化，恰好
   补上背景第 2 点"低等级段无调参空间"的缺口；`k0` 也允许取负值，效果相反（曲线整体放宽），
   由具体数值设计按需选择正负，架构本身不限制符号。分段插值分支（`kind=table`）不涉及本次改动，
   继续按已登记的采样点插值。

2. **`k0` 是加性可选字段，缺省 0**：未登记 `k0` 的既有记录，公式退化为
   `reduction = value / (value + k × attackerLevel + 0)`，与改动前的公式在数值上恒等（对分母
   加 0 不改变其值），**逐位兼容既有数据，不需要任何数据迁移**。这一结论不是靠推理认定的，而是
   对仓库随附的全部 `combat.resist_curve` 数据集（默认示例数据根、`<game>` 模板数据根、内置数值
   仿真测试数据根三处）里 `kind=saturation` 的每一条既有记录，构造新旧两版公式的对比测试逐条验证
   通过（新旧公式在相同护甲值/攻击者等级输入下产出完全相同的输出，不带容差）。
3. **字段登记加性追加，登记版本号不变**：`k0` 登记为 `Number` 种类、可选、无默认值声明（求值层
   落地默认值 0，登记层只声明"可选"），不改变该表已登记版本号——这条表的字段登记此前已有"新增
   可选字段、未登记时行为不变"的先例（数值范围约束一类的加性登记），版本号只在结构性变更（如
   字段改名、必填性收紧）时才递增，本次不属于这一类。
4. **不新增业务校验规则**：`k0` 本身没有"必须为正/非负"这类业务约束（正负都对应有效曲线形态），
   分母非正时的兜底处理沿用既有实现（换算结果按 0 处理），不需要在数据校验阶段额外拦截。

## 后果

### 正面

- 消费方反馈第 7 条的具体场景（表达"存在一个不随等级缩放的基础门槛"、修正低等级段退化）有了
  直接对应的数据字段，不再需要靠曲线形态之外的手段（如另设一条分段插值曲线）绕路表达。
- 缺省 0、逐位兼容，已发布内容不需要任何迁移动作即可继续在新版本上运行，新增能力是纯粹的
  "有需要再用"，不是强制改动。

### 负面

- 又一个可调参数意味着数值设计需要多理解一层公式形态；`k` 与 `k0` 两者组合出的曲线族比此前更
  丰富，也意味着更容易配出不符合直觉的曲线（例如 `k0` 取值过大导致任意护甲值都换算出接近 0 的
  减免），需要具体数值设计自行验证曲线形态，架构本身不做曲线合理性判断。

## 备选方案与为什么不选

- **只调整既有系数 `k` 的取值范围/推荐值，不新增字段**：无法真正解决背景第 2 点——`k` 是分母里
  唯一与 `attackerLevel` 相乘的量，调 `k` 只能整体缩放"等级的影响力"，做不到"给分母加一个不随
  等级变化的常数"，两者是曲线形态里两个独立自由度，不能相互替代。
- **换一种全新的曲线形态（如改成分段插值）表达同样的诉求**：分段插值（`kind=table`）已经存在，
  能表达任意形态，但消费方反馈明确诉求是"给现有的饱和曲线补一个自由度"，不是要放弃这条曲线形态
  本身——饱和曲线相对分段插值的优势（连续、单调、只需两三个数就能描述整条曲线的整体形状）在很多
  场景仍然是更合适的选择，不应该因为一个自由度不够就整体换形态。
- **把截距做成对 `value` 的偏移（`value + k0` 而不是分母加 `k0`）**：改的是分子而不是分母，含义
  变成"给护甲/抗性属性值本身加一个虚拟基础值"，这会影响 `value=0` 时的边界行为（`reduction` 不再
  恒为 0），与"没有护甲/抗性时减免为 0"这一各方均认可的直觉不符，因此选择只调整分母。
