# ADR-0161 自由第三人称镜头：俯仰范围声明、焦点高度、地面避让，与脚本携带控制空间声明

状态：已拍板 2026-10-06（承接 [ADR-0135](0135-相机相对控制空间与可选相机俯仰透视.md) 的相机俯仰与相机相对控制空间、[ADR-0159](0159-手感演示场景3D版鼠标环绕镜头与相机相对移动.md) 的环绕镜头；全部是加法，缺省行为逐位不变）。

## 背景

3D 演示场景的环绕镜头（ADR-0159）能转一整圈，却抬不了头：玩家看不到天空，也就没有"第三人称自由镜头"（偏航任意、俯角从近乎正俯视一直到仰视天空）的手感。卡点有两处，一处在游戏侧、一处在框架侧：

- 游戏侧：演示场景自己把环绕镜头的绝对俯角夹在 12～66 度。
- 框架侧：相机适配器把俯仰范围写死在 [0, 89]（0 = 正俯视，89 = 留出余量避免视线与世界平面平行），任何游戏都不可能把视线抬过水平。

另有 ADR-0159 登记的第二个缺口：录下的环绕会话在脚本里只有 `camera_yaw` 呈现标记，没有控制空间声明，所以偏航不为 0 的会话在无头命令行里按格子数据的 `world` 解释，逻辑不能逐位复现。

## 决策

1. **俯仰角约定（沿用，不改）**：0 = 视线垂直向下（正俯视），90 = 视线水平，大于 90 = 视线抬过地平线、看向天空，180 = 垂直向上。偏航仍是绕垂直轴的逆时针角度，姿态由"先俯仰、再偏航"显式合成。
2. **俯仰范围是游戏声明的可选能力**：相机适配器新增 `DeclarePitchRange(min, max)`（与 `ResetPitchRange`）。不声明时范围仍是 [0, 89]，行为与引入前逐位一致（`Configure` 的俯仰仍夹进该范围）。声明范围须满足 0 ≤ min ≤ max ≤ 179（180 = 垂直向上，留出余量避免偏航退化）；有限数检查、越界、下限大于上限都在声明期直接抛参数错误，不静默夹紧，也不改动已声明的范围。声明后已配置的俯仰按新范围重新夹紧。
3. **越过水平的数学：不翻转、不倒挂，相机相对仍只依赖偏航**。姿态是显式合成而不是"看向目标"的朝向求解，所以两极没有翻转；设俯仰 p、偏航 y：
   - 相机右轴恒为 (cos y, sin y)，且恒在世界平面上；
   - 视线的水平分量恒为 sin p · (−sin y, cos y)，p 在 (0, 180) 内 sin p 恒为正，所以**相机水平视线方向只由偏航决定**；
   - 上轴的"世界向上"分量恒为 sin p ≥ 0，相机从不倒挂；
   - 变的只有"屏幕上轴"在世界平面上的投影：它含 cos p 因子，**p 越过 90 度后符号翻转**（指向背离水平视线的一侧）。
   因此 ADR-0135 决策 5"相机相对只依赖偏航"在整个范围内仍成立，但它的措辞精化为：**摇杆向上 = 朝相机水平视线方向走**（p < 90 时与"屏幕上方"重合，缺省范围内含义不变）；输入映射不需要知道俯仰，轴值换算公式不变。回归用例用真实相机在 0～179 度俯仰、多个偏航下逐项证明（相机适配器的越过水平系列用例与实验室引擎宿主的相机相对用例）。
4. **焦点高度（可选，缺省 0 = 绕地面上的焦点转，逐位不变）**：`FocusHeight` 把环绕焦点抬到离地面一个高度（第三人称取角色头部）。仰视时相机因此落在焦点下方而仍可以高于地面；"缩放 = 焦点处地面可视半高"的换算与相机到焦点的名义距离不变。
5. **地面避让（可选，缺省关）**：`GroundAvoidance` 打开后，相机若会落到地面（含余量 `GroundAvoidanceMargin`，缺省 0.3 个世界单位）以下，就沿视线向焦点靠近到刚好离地余量处，而不是穿进地面——第三人称相机常见的"贴地拉近"。实际余量取 min(余量, 焦点高度)；保证是离地高度不低于实际余量（焦点自己不高于余量时无处可退，相机最近退到离焦点 0.01 个世界单位处）。纯表现，不回流逻辑层。
6. **屏幕点到地面点的换算**：仰视时视线与地面不相交，`ScreenToWorld` 原本就返回"没有交点"；本决定另补一条——相机位于地面平面上或之下时（仰视且没开地面避让才会出现）只会从背面穿过地面，不是玩家看到的地面点，同样返回"没有交点"。缺省范围内相机恒在地面之上，不受影响。
7. **脚本携带控制空间声明与偏航流**：脚本 meta 新增可选字段 `controlSpace`（`world` 或 `camera_relative`，空 = 不声明）。声明 `camera_relative` 的脚本自带偏航流——`camera_yaw` 标记（`Value.X` = 偏航度，逆时针为正，开局偏航 0）在其所在固定步的意图采集之前生效；实验室内核据此给输入映射配一个脚本驱动的相机朝向查询，**任何宿主（含无头宿主、没有相机的宿主）按同一串标记得到同一串偏航**，录下的相机相对会话逐位复现。控制空间的优先级：宿主扩展的显式覆盖 > 脚本声明 > 格子声明；没声明的脚本里 `camera_yaw` 仍是纯呈现标记、逻辑不读。声明按"格式版本 6"写出，只有声明了才写，其余脚本的序列化文本逐字不变，更老的内核读到会拒绝而不是悄悄按 `world` 重放。试玩宿主录会话时，在宿主声明相机相对控制空间的场景里写进该声明；引擎宿主重放声明了 `camera_relative` 的脚本时（没有环绕镜头驱动画面），舞台相机跟着偏航流转，真实相机的右轴与水平视线方向和输入映射用的偏航仍是同一个量。
8. **试玩宿主的接线**：引擎宿主选项与试玩宿主新增同名的相机声明——俯仰范围、焦点高度、地面避让与余量，缺省都不声明。环绕镜头的绝对俯角区间必须落在相机声明的范围之内，否则装配期报声明错误（相机会悄悄夹紧、控制器报的俯角与画面不一致，所以不静默）。相机相对的三向检验把"摇杆向上"取为相机水平视线方向：俯仰小于 90 度取上轴投影，越过 90 度取其反向，正好水平取视线的水平分量；回到屏幕的检验按俯仰余弦的符号折算，正好水平时屏幕纵向没有信息，只比横向。
9. **桩相机不跟进**：这些是适配层的可选选项（与固定俯仰、透视同类），共享的相机契约与朝向查询接口没有变化，桩相机本来就不建模俯仰、透视，所以没有需要对齐的共享成员。

## 已知限制

- 地面避让只处理水平的地面平面，不处理地形起伏与障碍物遮挡（没有相机碰撞）。
- 脚本的偏航流从 0 开始，不携带开局偏航：声明了 `camera_relative` 的脚本回放时，舞台选项里的固定偏航（`CameraYawDegrees`）不应非 0。
- 俯角偏移与缩放仍是纯呈现，不录入脚本（沿 ADR-0159）：回放只复现偏航（移动方向）。
- 越过水平后画面顶端是天空而不是地面：场景要自己铺天空与远景，并让地面覆盖到不再被视线射到的远处；这是游戏（演示场景）的呈现工作，框架不替游戏铺。

## 不做的事

- 不改缺省：不声明任何新能力时，相机、输入映射与脚本序列化逐位不变。
- 不加相机碰撞（障碍物遮挡）、跟随平滑、镜头锁定目标等游戏性镜头功能。
- 不改相机与输入映射的既有契约（只新增成员）。

## 后果

### 正面

- 任何游戏都能声明"偏航任意、俯角从正俯视到仰视天空"的自由镜头，焦点高度 + 地面避让给出贴地时的常见拉近行为；相机相对移动在整个俯仰范围内继续只读偏航。
- 录下的相机相对会话在任何宿主里逐位复现，补上 ADR-0159 的跨宿主回放缺口。

### 负面

- "屏幕上方"与"摇杆向上"在越过水平后不再重合，需要把文档里"屏幕上轴投影恒为 (−sin y, cos y)"的说法理解为俯仰小于 90 度时的特例（ADR-0135 的结论按本决定精化）。
- 脚本多一个格式版本；声明相机相对的脚本不能被更老的内核读取。
