# ADR-0113 手感体系纳入框架：判定型与呈现型两半拆分

状态：已拍板 2026-10-01

## 背景

用户提出：手感是游戏最难的部分，希望走路、移动、打怪、各角色、各武器、各姿势的手感做进框架，新游戏直接用或改模板，不再每次重新开发调试。现状：框架已有反馈绑定（顿帧/震屏/闪白/后仰）、命中帧同步、程序动画原语、输入绑定与重绑定、移动系统、镜头接口，但缺输入缓冲、动作分相与取消、加减速、局部顿帧、统一打击档案、姿势维度、调参与验收工具；这些散在四层，没有一个统一的边界说明"什么能进框架、进哪里、怎么验"。

## 决策

1. **手感是框架的一等交付物**，但不新建"手感层"：它是横切关注点，由一个解析器、若干判定型消费者、若干呈现型消费者与一组开发期工具构成，各自落在既有层与模块内（手感设计/00 第 3 节）。
2. **按"是否改变模拟结果"切成两半**：判定型（缓冲、宽限、分相与取消、连招、加减速、运动仲裁、击退、无敌窗口、局部顿帧、硬直裁决）放 L0/L1/L2，确定性、可回放；呈现型（姿势、打击反馈包、镜头、音效层、飘字、拖尾）放 L5，遵守表现层铁律 P2/P3。每个字段登记时声明半属；判定型字段不放表现域表，呈现型字段不被规则层读取，静态检查保证。
3. **三个时钟**：真实时钟（只做诊断与延迟测量）、模拟时钟（玩法权威）、新增行动者动作时钟（动作时间线、取消/连招/无敌窗口、缓冲过期；被局部顿帧暂停）。判定型一律以 tick 计，毫秒在解析时换算。
4. **归一化单位与标定**：档案数值用相对量（毫秒、身高倍数、单位移动速度属性的倍数、剪辑比例、画面高度比例、强度档），每款游戏一张标定表换算为绝对值，使原型库跨游戏迁移。
5. **"直接用"的口径**：机制、档案结构、分层解析、原型库、姿势规格、实验室零开发，验证过的预设在兼容条件下复用；不承诺免微调，不以复用百分比作承诺或验收指标。
6. **范围边界**：离散模式下判定型整体不生效；缺省世界没有竖直轴，跳跃、击飞、落地、空中控制与单向平台作为缺省关闭的可选能力包提供（[ADR-0130](0130-竖直轴能力包.md)），平台跳跃里的土狼时间对应输入宽限窗口（[ADR-0115](0115-输入缓冲与动作时间线.md)、[ADR-0133](0133-宽限窗口的施法瞄点.md)）；缺省固定俯角镜头，相机俯仰与透视仅在声明时启用（[ADR-0135](0135-相机相对控制空间与可选相机俯仰透视.md)）；不做联网预测。
7. 目录 `architecture/手感设计/` 为唯一设计出处，本 ADR 与 0114～0120 为其拍板记录。

## 后果

### 正面

- 新游戏的手感工作从"重新开发几周"压缩为"选预设、填标定、实验室校准"。
- 两半拆分使既有铁律不被破坏：反馈永远不判定伤害，判定永远不依赖表现。
- 判定型逐字节确定性让手感回归可以像逻辑回归一样精确。

### 负面

- 涉及输入映射、技能、移动、战斗、表现五处扩展，是框架近期最大的横切变更；分阶段落地时必须保证每一步缺省行为与既有实现逐位一致（各专题文档都要求缺省值等价既有行为）。
- 行动者动作时钟是新概念，所有读"动作进度"的代码必须改读它而不是模拟时钟。

## 备选方案与为什么不选

- **把手感做成独立的"手感层"**：会与输入映射、技能、移动系统各自的权威重叠，出现平行的位置/动作状态；否决。
- **只做呈现型（反馈包、镜头、姿势）**：走路、连招、取消、打击的分量大半来自判定型，只做呈现型达不到"现代单机动作游戏"的手感；否决。
- **把顿帧/慢动作全放表现层**：受击者在冻结期间逻辑继续走位会导致视图跳变、取消窗口无法定义；否决（见 ADR-0117）。
- **数值用绝对单位**：预设无法跨美术尺度、镜头高度迁移；否决。

## 魔兽世界的对应做法

魔兽是目标选择式 MMO：手感来自公共冷却节奏、法术队列窗口与命中帧上的音画反馈，没有顿帧、缓冲取消或空间判定。本架构保留这一整套作为 `rpg_classic` 预设与 `instant` 结算模式，在其上加一层动作式手感（ADR-0114）。
