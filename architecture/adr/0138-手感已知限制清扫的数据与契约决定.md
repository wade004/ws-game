# ADR-0138 手感已知限制清扫的数据与契约决定

状态：已拍板 2026-10-03（对 [ADR-0115](0115-输入缓冲与动作时间线.md)、[ADR-0128](0128-单位间体积阻挡.md)、[ADR-0130](0130-竖直轴能力包.md) 等手感体系决定的收口；手感落地 M4 最终清扫引入）

## 背景

手感体系在 M1～M3 的每个版本里都登记了若干"已知限制"：有的是真能力缺口（蓄力没有效果值倍率、目标没有体积、永远接不了的缓冲记录挡住后面的候选、冷加载的特效发射位置与热路径不一致、镜头阻尼按固定步长算），有的是合理的边界（单位体积阻挡要显式开启、挥空窗口按动作实例而不按段）。把它们长期挂在"已知限制"里有两个坏处：真缺口一直不修，合理边界又被读成待办。

M4 的收口原则是两类各有去处：缺口一律实现并带复现用例与不变量，默认行为逐位不变；合理边界一律改写成"设计决定"（决定 + 理由），不再叫限制。本 ADR 登记其中需要拍板的数据与契约取舍；纯实现层面的修复（冷加载发射位置、光环霸体的用例补齐、取消进入的朝向对齐）不在此重复，见各模块的判断记录。

## 决策

1. **蓄力效果值倍率用声明式字段 `charge.value_scale{min, max}`，取代"把蓄力比例暴露给表达式"的原设计**：倍率 = `min + (max − min) × 蓄力比例`（蓄力比例夹到 0～1）。理由：效果值契约里没有可求值的表达式点，声明式字段只动数据、不动契约；它可校验（两端均不小于 0）、可由规则算出期望值，不依赖运行期求值。倍率只缩放伤害与治疗类效果值，不缩放持续时间、范围等其它参数；不声明则不缩放。
2. **蓄力相是动作开始之前的按住阶段，不是动作相位**：它由输入缓冲里的 `hold_pending` 记录存续的那段表示，动作在抬起或到上限时才开始，所以蓄力期间没有动作实例、不发 `charge` 相位事件（枚举成员保留以满足契约只增不改）。表现层经输入缓冲的只读快照读按住时长来画蓄力。理由：位置与相位权威各只有一处，把蓄力再建模成一个动作相位会让缓冲与时间线各持一份"正在蓄力"的状态。
3. **缓冲意图出口新增"能否处理"默认成员，缺省为真**：只有出口声明"永远接不了"（例如输入动作没有映射到任何技能）的记录才被剔出候选，剔出的记录不被消费也不被丢弃，留在缓冲里直到自己的窗口过期；"此刻不能接受"（冷却、动作锁）仍按优先级等待、不让位。缺省为真，所以既有出口的行为逐位不变；输入缓冲的查询侧同步新增带跳过谓词的窥视与消费重载，默认实现忽略谓词。
4. **目标命中半径在目标选择里缺省关闭**：选项由游戏供给每个单位的命中半径与一个广相位上界，缺省不配置时一切只按目标中心判定。开启后，形状查询先把形状按最大半径外扩取候选，再对每个候选做"形状到目标中心的最近点距离不超过该目标半径"的精确重判；中心已在形状内的结果保持不变，新增命中的单位按 Id 序追加在其后，保证确定性。半径来源由游戏给，框架不替游戏选；上界必须不小于实际最大半径，否则大半径单位在广相位被漏掉。
5. **单位体积阻挡保持"声明才开启"**：位移扑击穿过靶子不再作为限制登记；需要的游戏在自己的预设里声明单位体积半径即可开启，缺省不改。理由：缺省开启会改变所有未声明体积的既有预设与基线，而"缺省不变"是手感体系的总约束。
6. **挥空窗口按动作实例计，不按段拆**：同一动作内多个命中标记、同一动作发射的多发弹合成一个窗口，窗口内任何一次接触（含被回避）都不算挥空。理由：挥空回答的是"这一挥是否完全打空"，按段拆会让命中了前两段的连击在第三段落空时报"打空"，与该定义不符。
7. **命中确认只计伤害类效果**：纯治疗与光环类技能不产生命中确认，无敌的友军照常被治疗。理由：命中确认的语义是"这一击打中了"，不是"这个技能作用到了"；动作是否带攻击由内容推断，可用 `is_attack` 显式覆盖（对友方的治疗类投射物写 `false`）。
8. **配置热加载依赖宿主发布的"数据加载完成"事件**：框架不轮询文件、不替宿主重载数据表；重载入口属于数据层，由重载它的宿主在成功后补发完成事件，手感解析器与宽限条件订阅这一个事件即可。理由：开发期热加载在全仓是同一套约定，手感模块不另起一套。
9. **动作步长只在选项里声明一次**：启用手感时，动作时间线的步长由装配根写成与手感、时钟同一个数；经装配入口显式给了不同值直接报错。理由：时间线按步计时，两处各存一份步长会静默错位，单一来源是最小办法。
10. **镜头更新取真实（不受时间缩放影响的）帧间隔，阻尼因此与帧率无关**：镜头是表现层，应与顿帧、慢动作期间的画面一致，而不是跟随逻辑步长。三个生产引导改用带帧间隔的更新入口；只带插值系数的旧入口原样保留并按固定 60 赫兹推进，对固定步长的宿主这就是准确值，直接调用它的外部宿主应改用带帧间隔的入口。

## 后果

### 正面

- 已知限制清零：真缺口有数据字段、契约成员与复现用例，合理边界都有"决定 + 理由"，读文档的人不再把边界当待办。
- 全部是加法：新增的是默认接口成员、可选属性、重载与可选数据字段；不声明时行为与改动前逐位一致（手感实验室既有基线未改）。
- 蓄力倍率、命中半径都可由规则算出期望值，测试不写死裸数。

### 负面

- 蓄力倍率是一个新的数据字段，旧的"暴露给表达式"写法不再被设计承认，需要读过早期设计文稿的人转到新字段。
- 缓冲出口的"能否处理"改变了一种边角行为：声明了动作却没有技能映射的记录，此前会挡住后面的候选，现在不挡；依赖旧行为的第三方出口需覆盖该成员并保持旧结果。
- 命中半径的上界是一个必须由游戏保证的约束，填小了会静默漏判，只能靠文档与用例提醒。

## 备选方案与为什么不选

- **蓄力比例暴露给表达式**：效果值没有表达式求值点，要加就得改效果契约；否决，声明式倍率只动数据。
- **把蓄力建模成动作的第一个相位**：缓冲与时间线重复持有"正在蓄力"；否决。
- **永远接不了的记录从缓冲里丢弃**：游戏自己的消费者可能要取用它们；否决，只从候选里剔除。
- **缺省开启目标命中半径或单位体积阻挡**：改变既有预设与基线；否决，声明才开启。
- **挥空按段拆分**：与"本攻击实例命中数为零"的定义冲突；否决。
- **镜头仍按固定步长，只在文档里标"近似"**：变帧率宿主上收敛速度随帧率变化，与顿帧期间的画面不一致；否决，接真实帧间隔。

## 魔兽世界的对应做法

无直接对应：魔兽的蓄力、体积与镜头平滑由客户端与服务端各自的内部实现决定，不向数据层暴露可声明的倍率与半径字段；本 ADR 的取舍面向"数据驱动、缺省行为不变"的框架约束。
