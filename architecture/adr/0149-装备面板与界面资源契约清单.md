# ADR-0149 装备面板与界面资源契约清单：皮肤包运行期消费、机器可读清单与具名诊断

状态：已拍板 2026-10-04（落实 [手感设计/08](../手感设计/08_装备与UI资产契约.md) 第 3、4、5、7 节与 [手感设计/06](../手感设计/06_手感实验室与验收.md) 第 3.6 节换装场景；增补 [ADR-0123](0123-装备资产包与界面皮肤包契约.md)；schema 变更遵守 [ADR-0039](0039-内容数据schema破坏性变更政策.md) 的只加不改）

## 背景

装备资产包与界面皮肤包在 ADR-0123 里只落到了"目录布局 + 静态校验"：皮肤包没有任何运行期消费方（界面上画的仍是写死的朴素外观），装备面板没有独立的面板与视图模型（落在角色面板里），实验室换装场景在引擎侧只有无头记录，没有屏幕上的装备面板、预览区、方向 × 姿势键轮播与拼图。同时，一款游戏接入真实素材时，界面资源的问题（缺文件、尺寸不对、九宫格边框不合法、状态图缺失、透明度不对、图层帧数与身体对不上）只有在接入后才会暴露，因为规则散落在校验代码、生成器与文档三处，没有一份可以同时交给出图工具和校验工具的契约。

## 决策

1. **皮肤包有运行期消费方，缺省皮肤逐位不变。** 引擎侧界面按同一份文件约定读皮肤包：槽位框、槽位框状态、品质框、纸娃娃预览区背景、面板九宫格底图、按钮九宫格状态图、主题颜色与字体。`skin.default` 不安装任何皮肤覆盖——面板底图、按钮、字体、配色保持框架原有默认值；非缺省皮肤才把主题与可选元素映射成覆盖。回落链为本包 → 占位皮肤同名 → 占位 `_default` → 程序生成的框，每次回落留记录；可选元素缺失不算回落，沿用框架默认外观。理由：缺省逐位不变是总约束，而"只换资源文件"要求新增能力全部是可选的加法。

2. **装备面板是独立面板与独立视图模型。** `ui_layout_definition.panel` 增加枚举值 `equipment`（加法），视图模型取装备槽位清单、已装备物品（图标、品质）与纸娃娃图层，数量全部由数据与真实装备状态算出；布局字段（锚点、列数、格子边长、预览缩放、预览身体层精灵集、预览初始方向）放行的 `fields`，行可选、缺省取内置布局，所以框架数据不必为它新增行。背包面板在给了皮肤与资源的重载里每行多一个物品格（槽位框、图标、品质框、数量），既有签名与行为不变。理由：装备面板的数据与交互（点击卸下、预览方向切换）与角色面板不同，混在一起无法按布局行定位；不改既有数据文件，避免引起数据集指纹变化。

3. **皮肤包、图标、纸娃娃图层的全部规则收成一份机器可读的契约清单。** 清单包含皮肤元素模板（路径、必备/可选/仅占位皮肤必备、尺寸与比例、同尺寸组、透明度规则、九宫格边框令牌、状态变体及其依赖）、主题令牌、图标类别与规格、纸娃娃静态层/逐层剪辑/身体剪辑路径与帧对齐规则、具名诊断全集。导入校验、占位皮肤生成器、人读清单生成器、引擎侧完整性用例读同一份；规则只改清单。占位皮肤只生成"必备 + 占位必备"元素，保证入库的占位皮肤逐位不变；另有一个全元素的确定性参照皮肤生成器，供用例当合格基线。理由：真实素材接入时不应有任何界面资源问题第一次在接入处暴露；规则只存一处，出图工具与校验工具才不会漂移。

4. **清单里每条规则对应一个具名诊断，每个诊断有一个反例。** 新增：状态变体缺失（必备状态缺、或给了依赖项缺它依赖的状态）、主题缺颜色令牌、颜色格式不对、图片读不出、尺寸/比例不合规、同尺寸组边长不一致、九宫格边框过大、透明度不合规（皮肤图）；图标透明度/贴边从尺寸诊断里拆出独立诊断；纸娃娃静态层图像素不合规、逐层剪辑与身体剪辑帧数不同、帧宽高不同、帧矩形超出图集。级别：缺文件是警告（有回落）；已存在文件的内容缺陷是错误（文件会被原样使用，不会回落）。理由：可回落的缺失不阻断，不可回落的缺陷必须在导入时拦下。

5. **引擎侧完整性用例逐元素核对换皮肤。** 用例用确定性程序生成的替换皮肤（每个元素一个由路径散列算出的唯一颜色），遍历清单的每个展开元素，读回精灵像素确认来自新包；面板实际使用的类型化取用与清单路径逐元素一致（清单新增元素而取用没跟上会失败）；真实面板、九宫格多尺寸、状态变体随交互切换、可选元素缺失回落、缺省皮肤不安装覆盖各一条。理由：换皮肤"没有默认皮肤残留"只能靠逐元素读回像素证明。

6. **换装场景在引擎宿主上有屏幕形态与本地产物。** 场景含装备面板、预览区、方向 × 姿势键轮播与"逐件穿戴"；"跑完整报告"在引擎宿主上跑同一份数据生成的衣橱脚本，核对图标、每个方向档静态层图、每个方向档 × 姿势键的层剪辑与身体剪辑，写本地报告与拼图。衣橱不新增度量组、不进指纹。理由：屏幕上的步骤与报告里的步骤读同一份数据清单、走同一条穿脱路径，所见即所得。

## 后果

### 正面

- 游戏选定默认手感模板后，界面换装只换资源文件；任何界面资源缺陷在导入时被具名诊断拦下，不会第一次出现在接入处。
- 出图工具与校验工具读同一份清单，人读清单由它生成，规则不漂移。
- 缺省皮肤与既有数据逐位不变。

### 代价与限制

- 皮肤图的内容检查要读图（皮肤包只有几十张小图，秒级）；纸娃娃逐层剪辑要读帧索引与图集头，导入校验时间略增。
- 提示框、拖拽态在运行期暂无内置消费面板（框架不提供提示框与拖拽面板），清单与导入校验已覆盖它们，皮肤画廊逐元素渲染它们供观察与完整性用例核对；游戏做提示框与拖拽时按同一取用接口读。
- 穿脱音效 `equip_sfx_ref` 的运行期播放、占位装备集的副手与挂点型外观夹具不在本 ADR 范围，仍是遗留项。
