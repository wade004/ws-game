# ADR-0014 资产契约、导入工具与 UI 套件是框架交付物

状态：已拍板 2026-09-04

## 背景

框架规则层本身不依赖美术资源即可跑通（数据校验、模块单测、桩适配层集成测试均只需要逻辑数据）。但美术资源要被框架识别为可用的表现，必须先经过一层契约：外形表、动画集、装备外观表、渲染约定（见 `04_数据与内容管线.md` 的 `DisplayInfo` 映射与 `09_表现层.md` 的表现层铁律）。若这层契约、把出图产物转成契约行的导入工具、以及承载契约的界面实现（UI 套件）都留给每款游戏各自完成，会带来两个后果：

1. 框架在 `12_扩展与变更流程.md` 与 `13_新游戏接入指南.md` 里对新增内容做出的两条承诺——"新增外观只加一行映射""UI 数据绑定契约可跨游戏复用"——会在实践中落空，因为每款游戏都要重新发明一遍"出图产物怎么变成一行外形表"和"界面单元怎么绑数据"。
2. 框架级的模块单测、集成测试、验收关卡（见 `11_工程规范与测试.md` 第 6 节测试分层）如果必须等真实美术资源到位才能跑，框架的进度会被具体某款游戏的美术产能卡住，违背"框架与任何具体游戏解耦"的定位（见 `00_架构总则.md` 第 1 节）。

## 决策

以下三样连同资产契约本身，一并列为框架级交付物，随核心逻辑一起排进落地计划，不属于某一款游戏的专属工作：

1. **资产规格书**：框架级模板，每款游戏在其上填具体值，不是每款游戏各写一份互不相关的规格文档。模板覆盖每类资产的尺寸、锚点约定、方向数与镜像、纸娃娃层清单与叠放顺序、序列帧图集切法、特效贴图格式、图标尺寸与构图规则、音效格式与响度、命名规则；规格书随文档版本规则（见 `12_扩展与变更流程.md` 第 4 节）版本化。
2. **资产导入工具**：把出图产物（原始美术素材）做抠图、切片、图集、锚点写入，落到本架构目录约定的资产目录（见 `11_工程规范与测试.md` 第 1 节），并**自动生成外形表行**，同时校验缺锚点、尺寸不符、引用不存在的文件等问题。工具拆成两部分：`toolchain/` 下与引擎无关的处理逻辑，以及引擎适配层里与具体引擎资源格式相关的部分。
3. **通用 UI 套件与占位资产包**：UI 套件拆成 `presentation/` 下引擎无关的数据绑定与界面单元定义，以及引擎适配层里带默认朴素皮肤的界面实现；占位资产包是一套色块角色、方块怪、简易特效、占位音效与一款开源可商用字体，任何新游戏立项第一天即可用占位资产跑起来。
4. **验收分离**：框架级验收允许且应当只用占位资产，验证的是逻辑、事件、契约是否正确；游戏级验收才使用真实资产，验证的是手感与观感。顺序固定为：先定资产规格 → 用占位资产跑通框架 → 按规格批量出真资产替换，替换过程不改任何运行时代码。

## 后果

### 正面
- "新增外观只加一行映射"这条承诺有了实际落地路径：导入工具自动生成外形表行，避免手填造成的规格漂移与遗漏字段。
- 框架级验收不再被具体游戏的美术产能卡住：占位资产包让"逻辑先跑通、美术后补齐"成为可执行的默认顺序，而不是口号。
- UI 套件的数据绑定契约跨游戏复用有了具体载体，后续新游戏立项不必重新设计界面单元与数据绑定方式。

### 负面
- 框架侧需要多维护一套导入工具与占位资产包，即使某款游戏的美术管线与默认假设（尺寸、锚点约定等）出入较大，也需要先适配规格书或走变更流程，不能绕过。
- 资产规格书本身需要跟随美术管线的实际能力迭代，一旦规格书改动涉及既有资产的锚点或切法约定，需要评估对已导入资产的影响范围。
- 验收分离要求团队自律：如果游戏级验收提前使用真实资产掩盖了框架级逻辑缺陷，或框架级验收长期只用占位资产而从不切换真资产复核，这条分离原则本身不能自动防止两种误用，需要在提交门槛里显式核对（见 `11_工程规范与测试.md` 第 8 节）。

## 备选方案与为什么不选

- **每款游戏自理美术接入**：起步最灵活，但会让"新增外观只加一行映射"的承诺在每款新游戏里都要重新验证一遍是否成立，且没有统一的占位资产包时框架级验收必须等美术资源到位，直接违反"框架进度不被美术进度卡住"的诉求，不采纳。
- **把美术资源本身也纳入框架**（即具体的角色贴图、动画剪辑作为框架交付物的一部分）：这与"架构和任何具体游戏解耦，不承载任何一款游戏的专属设定"（见 `00_架构总则.md` 强制约束）直接冲突——具体美术资源天然是某一款游戏的专属内容，框架只应该交付资产契约、处理契约的工具与承载契约的界面壳子，不应该交付具体资产本身（占位资产包例外，因为占位资产本身就是通用的、不承载任何游戏专属设定），不采纳。

## 魔兽世界的对应做法

魔兽世界用 `DisplayInfo` 体系（`CreatureDisplayInfo`/`ItemDisplayInfo` 等）把逻辑对象与具体模型、贴图、几何组解耦，客户端资源打包管线负责把美术产物转成运行时可加载的格式，这正是"资产契约 + 导入工具"分离的原型。它的 UI 由数据驱动的插件框架承载，界面定义与数据绑定跨越不同插件复用，对应本决策里"UI 套件的数据绑定契约与界面单元定义跨游戏复用"这一取向。
