# ADR-0170 单向平台、移动平台、下穿与俯冲

状态：已拍板 2026-10-08（来源：`docs/消费方反馈/消费方反馈-2026-10-08-样板游戏D-缺口.md`；全部为纯加法，不声明平台时既有行为逐位不变）

## 背景

样板游戏 D（横版动作，侧视投影）要做的关卡有三类典型结构：只能从下面跳上去、从上面可以走过或下穿的"单向平台"，沿固定路线来回运动并带着乘客走的"移动平台"，以及空中向下劈的"下劈"。竖直轴（[ADR-0130](0130-竖直轴能力包.md)）已经有重力、跳跃、落地、边缘下落与单值地形高度，但：

1. **地形是单值的。** 地形高度接口对每个平面点只回答"一个"地面高度。表达不了"同一个平面点上，地面在 0，头顶 3 的高度悬着一块平台"：用高台（`terrain` 区域）表达，下方的单位被挡住也跳不穿；用地面高度表达，站在下面的单位会被抬到平台上。
2. **没有随时间移动的表面。** 地形高度是静态数据，移动平台只能由游戏每帧改地形再手动搬乘客，乘客与平台不同步（平台动、乘客不动），且存档要自己记整套状态。
3. **没有主动下穿与下劈的竖直操作。** 现有竖直操作只有起跳、击飞、`LaunchToApex`、`CutAscent`；站在单向平台上向下穿过它、空中把竖直速度换成向下的俯冲，都得游戏绕开竖直轴自己改高度。

## 决策

1. **可选能力接口 `ITerrainPlatforms2D`**（引擎适配层契约，`VerticalAxisOptions.Platforms`，缺省 null = 没有平台）。平台是**单向**的：只有"这一步脚下起点不低于平台顶面（容差内）、终点不高于它"的下落步会落在平台上，多块满足取最高的一块；上升中、平台下方、与平台齐平以下的横向走动完全不受影响。声明平台必须同时声明地形（平台叠在地形之上，平地关卡用 `FlatTerrainHeight2D.Instance`），否则装配期抛参数异常，不静默忽略。
2. **平台的数据实现 `MapPlatforms`**（读 `world.map` 的可选字段 `platforms`：`{id, min, max, height, motion?}`，`motion` = `{offset, lift, travel, pause, phase}`）。范围是轴对齐矩形，id 在同一地图内唯一，校验由 `WorldMapTerrainValidationRule` 承担（检查名 `world_map_platform`、`required_field`，消息带 `platforms[i].…` 路径）。
3. **移动平台的位姿是平台时钟的解析函数**，不是累加位移：来回运动（匀速、两端各停 `pause` 秒、周期 `2·(travel+pause)`）按平台时钟 + 相位算位姿，帧长不均匀时没有积分漂移。平台时钟由竖直运动服务按步累加 `dt`，存档只需记平台时钟，读回时 `SetTime` 复原。
4. **竖直运动服务带乘客。** 每步先推进平台时钟，再把每块在动的平台的位移（平面位移 + 高度位移）加到站在它上面的单位上（经新属性 `VerticalMotionHost.UnitAccess` 写位置，空间索引同步更新），然后才推进飞行与贴地。站在平台上的单位走出平台范围，起一段零速飞行（边缘下落，同悬崖可土狼起跳）；刚被放到平台上的单位在首次观察时认出支撑（顶面与脚下齐平，或与移动平台上一步的顶面齐平）。
5. **`IVerticalMotion` 新增三个默认接口成员**（缺省行为是"不支持"）：`DropThrough(id)`——站在平台上的单位向下穿过它（初速 0 的下落，这次飞行里不再被那块平台接住，不是边缘下落，不可土狼起跳）；`Plunge(id, downSpeed)`——空中的单位把竖直速度换成向下的 `downSpeed`，继续抛体，保持空中跳跃次数与空中时间（下劈用）；`StandingPlatform(id)`——单位当前站着的平台 id。
6. **输入侧的"下 + 跳"、技能侧"下劈起手时俯冲"由游戏用钩子决定**：框架只提供竖直操作，不规定哪个按键组合触发（按键映射属于游戏）。

## 后果

- 新增公开面均为纯加法（新类型、`VerticalAxisOptions` 新属性、`IVerticalMotion` 默认成员、数据字段 `platforms`），公开面兼容探针 0 破坏。不声明 `Platforms` 时贴地、飞行、落地路径逐位不变。
- 存档：平台时钟是游戏需要保存的一个数（`ITerrainPlatforms2D.TimeSeconds`），框架不自动入档；游戏存档时记、读档时 `SetTime`。

## 限制（已知，随各模块判断记录登记）

1. 平台范围只有轴对齐矩形，没有斜面与曲线平台（决策 2）。
2. 移动平台之间不互相携带：站在平台 A 上的另一块平台 B 不会被 A 带走（平台只携带单位）。
3. 乘客被平台带走时不做碰撞检测：平台水平移动把乘客推进墙里不会被拦截（关卡设计保证路线上没有墙）。
4. 单位从下方被上升的移动平台"顶到"不会被抬起，也不受伤：平台只在单位下落穿过顶面时才与单位相互作用。
5. 平台时钟是整个世界一个（所有地图共用），不能让不同地图的平台各走各的时间。
6. `Plunge` 是新开的一段飞行，会清除边缘下落标记与下穿忽略的平台：下穿后立刻俯冲、下方又是同一块平台时会被它接住；边缘下落中俯冲后不能再土狼起跳。

## 备选方案与为什么不选

- **把平台做成多层地形**（同一点多个地面高度的列表）。要改地形接口的返回形状，且所有既有实现（物理射线版、数据版、测试桩）都得跟改；平台是少数特殊表面，独立的可选接口更小、对不用它的游戏零成本。
- **移动平台由游戏每帧改地形并手动搬乘客。** 平台和乘客的先后顺序是游戏自己的约定，容易差一帧；存档要游戏自己记整套状态。把平台时钟与带乘客收进竖直运动服务，顺序固定、可测。
- **累加位移的移动平台**（每帧 `+= v·dt`）：帧长不均匀时有漂移，存档需要记位置，读档后与时钟对不上。解析函数没有这些问题。
- **下穿用"临时关闭平台"实现。** 全局状态，会影响别的单位；按单位、按飞行记录"忽略哪块平台"边界清楚。
