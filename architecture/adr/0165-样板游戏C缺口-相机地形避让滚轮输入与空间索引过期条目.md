# ADR-0165 样板游戏 C 缺口：相机地形避让、滚轮输入与空间索引过期条目

状态：已拍板 2026-10-08（来源：`docs/消费方反馈/消费方反馈-2026-10-08-样板游戏C-缺口.md`；三条都是纯加法或缺陷修复，既有行为在不使用新能力时逐位不变）

## 背景

样板游戏 C（3D 动作）用自由第三人称镜头（[ADR-0161](0161-自由第三人称镜头俯仰范围声明焦点高度地面避让与脚本携带控制空间.md)）在有高差的室外区域和台地上玩，撞到三处框架缺口：

1. **地面避让只认世界平面 Z = 0。** 台地高 3.2、坡道上行时，镜头绕"脚下地形 + 头高"的焦点仰视，镜头落在台地侧面或台地之下（离地高度算出来是正的，因为只和 Z = 0 比），画面穿进地形。
2. **输入接口没有滚轮。** `IInput` 只有按键、鼠标位置与手柄轴；游戏要缩放镜头只能自己去读设备的滚轮，真实设备走一条绕开框架输入接口的通道，脚本化输入源与测试要另开一条注入口，同一份代码在两条通道上行为不同。
3. **空间索引过期条目让目标辅助抛异常。** 实体在某个固定步里被销毁、"实体已销毁"事件尚未分发的窗口内，空间索引里仍有它的 id；玩家的动作技能在这个窗口内起手做目标辅助，`nearest_in_shape` 对该 id 取位置，单位访问的"必须存在"断言抛出异常，整个固定步中断（样板的机器人全流程通关在第二队小怪里必现）。

## 决策

1. **相机增加可选的地面高度提供者。** 相机实现新增"地面高度提供者"（可选的委托：世界平面 (x, y) → 该处地面高度，与焦点高度、离地高度同一基准）。缺省 null = 地面恒为 Z = 0，逐位不变；设置后地面避让沿"焦点到名义相机位置"整条视线等分取样、找到第一个低于余量的点后二分，把相机拉近到刚好离地余量处，起伏地形、台地、坡上仰视都不穿地。余量取 `min(余量, 焦点离其下地面的高度)`。纯表现，不回流逻辑层；高度源由游戏提供（地形数据，或地形高度接口的适配），框架不规定地形格式。
2. **输入接口增加滚轮格数。** 输入接口新增 `ConsumeScrollNotches()`（默认接口成员，缺省 0）：取走并清零自上次调用以来累积的格数，一格 = 1.0，向前推为正；实现负责把硬件单位换算成格数。滚轮是连续累积量，不进离散事件列表。引擎侧输入实现把设备滚轮累积进去（像素单位按 120 一格换算），桩输入提供测试用的滚轮方法。
3. **目标解析丢弃过期空间条目。** 目标选择的所有空间查询出口（`nearest_in_shape`/`all_in_shape`、命中半径外扩、格子吸附路径）丢掉已不是世界里单位的 id（`IUnitAccess.Exists`），与 AI 宿主对候选的处理一致；窗口过后条目由事件正常注销，行为不变。没有改"事件分发之前空间索引仍有条目"本身的时序（那是事件总线的整体约定）。

## 后果

- 所有新增公开面为纯加法（新属性、接口默认成员、新测试方法），公开面兼容探针 0 破坏。
- 决策 3 是缺陷修复：此前在窗口内会抛异常的调用现在返回不含过期 id 的结果。

## 限制（已知，随各模块判断记录登记）

1. 地形版避让取样 32 段：地形起伏尺度小于名义相机距离的 1/32 时可能漏过一个很窄的隆起（决策 1）。
2. 地面高度提供者只约束相机，不约束渲染物（blob 阴影等仍贴 Z = 0 的实现由游戏自己按地形放置）。
3. 滚轮只有垂直方向的格数，没有水平滚轮与按设备区分（决策 2）。

## 备选方案与为什么不选

- **相机直接依赖地形高度接口。** 它要地图 id，而相机不知道当前地图；用委托让游戏决定怎么取高度，不给相机加地图依赖。
- **滚轮作为离散输入事件。** 精细滚动设备给出的是小数连续量，进事件列表要么丢精度要么刷屏；累积取走更贴合缩放、列表滚动的用法。
- **在空间索引注销时机上做文章（销毁时同步注销）。** 要改事件总线与世界销毁的耦合，影响面远大于这一处缺陷；在消费出口过滤与 AI 宿主的既有做法一致，改动小且可测。
