# ADR-0122 手感实验室场景矩阵与跨场景不变量

状态：已拍板 2026-10-01（用户要求实验室区分 2D/2.5D/3D × 目标选择式/动作式六种场景）

## 背景

ADR-0120 把手感实验室定为框架交付物，但只描述了一个竞技场场景。用户要求实验室必须区分 2D、2.5D、3D 三种空间与呈现组合各自配目标选择式与动作式战斗，共六种场景。同时"手感核心跨维度可复用"需要机器证据，而不是设计上的声明。

## 决策

1. **场景矩阵为数据**：新增 `lab.scenario` 表，六个格子各一行：`{2d, 2_5d, 3d} × {targeted, action}`。每行声明空间模型、外形类型、镜头模式、控制空间、朝向模式、命中形状维度、默认预设、默认武器集、靶子集、脚本子集、所需适配能力。三种组合共用同一张竞技场地图与靶子，只换镜头档案、外形类型与朝向模式；结算模式由数据集（技能是否有 `timeline` 块）与预设切换。
2. **三种组合的定义**建立在既有契约上：2D = 平面世界 + `sprite` + 正交俯视（俯角 90）+ 翻转/量化朝向；2.5D = 平面世界 + `sprite`/`model` + 固定俯角透视（ADR-0012 缺省）；3D = 平面世界 + `model` + 固定俯角透视，第三人称跟随为可选镜头模式（适配能力 `supportsFreeYaw`），体积扫掠为可选能力 `supportsVolumeSweep`。
3. **边界**：空间模型目前只有平面世界。体积空间（斜坡、台阶、重力、空中控制、自由视角）与横版二维（侧视 + 重力轴）是预留能力包：`lab.scenario.space` 预留取值 `volume`、组合预留 `2d_side`，标 `reserved`，启用需导航/空间查询契约扩展与独立 ADR。本 ADR 不承诺这两类可运行。
4. **跨场景不变量**（第 4 层与第 5 层测试各跑一次）：同一输入脚本、同一预设在平面空间的各组合之间逻辑组指纹逐字节一致；同一组合内移除全部 `timeline` 块并换预设后，动作式格子的指纹等于目标选择式格子；表现组指纹按格子各自基线，只有声明为投影无关的指标跨格子比较。
5. **可运行状态显式化**：每个格子在每个适配层组合上有"可运行 / 不可运行（缺能力 X）"状态，写进实验室能力报告，不静默跳过。预设的 `validated` 标签按格子记录。
6. 三种组合各有脚本子集增补：2D 加方向量化档位边界脚本；3D 第三人称格子加镜头相对输入脚本；`camera_relative` 控制空间下轴到世界方向的换算是被测对象。

## 后果

### 正面

- "呈现不改判定"从原则变为每次提交都跑的断言。
- 用户关心的六种场景各有独立基线与成熟度记录，预设不会在某个组合上"想当然地可用"。
- 六个格子共用地图、靶子与脚本骨架，维护成本是一个场景加三套镜头/外形配置。

### 负面

- 3D 格子在第三人称与体积扫掠能力落地前只覆盖固定俯角，用户期望的"3D 动作游戏"完整体验要等能力包。
- 指纹基线数量乘六，基线更新时要逐格确认。

## 备选方案与为什么不选

- **一个场景加运行时开关**：无法为每个格子分别记录成熟度与基线，也无法表达"缺能力不可运行"；否决。
- **六个独立场景各自地图与靶子**：重复维护且格子间不可比；否决。
- **把体积空间一起承诺进本 ADR**：导航与空间查询契约都要扩展，超出手感设计范围；预留字段、另开 ADR。

## 魔兽世界的对应做法

无直接对应（魔兽只有一种空间与呈现组合）。
