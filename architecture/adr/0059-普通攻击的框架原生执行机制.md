# ADR-0059 普通攻击（武器驱动的自动重复攻击）的框架原生执行机制

状态：已拍板 2026-09-21

## 背景

消费方反馈第三批第 5 条（`<game>` 接入方，基于冻结发布提交核实）指出：普通攻击（不需要玩家/AI
每次显式下达指令、按武器攻速持续自动重复的近战/远程基础攻击）目前完全没有框架原生的执行路径——
框架只提供"技能施放"（`CastPipeline`）与"结算管线"（06 第 4.1 节九步固定顺序）两层能力，两者
均要求调用方自己驱动"这一次攻击什么时候发生"；接入方若要实现普通攻击，只能在游戏层自建一套计时
器，绕开框架已有的命中/减免/事件发布能力，或者反过来把普通攻击伪装成一条"无消耗、无读条、无
冷却"的技能定义，硬套 `CastPipeline` 的全局冷却/法术队列语义。两条路都不是"框架原生支持"，且
后一条会把一个不该出现在任何职业技能书/AI 优先级表里的内容污染进 `skill.book`/`ai.rotation`
登记。

约束：本层对外公开的契约（接口、构造签名、事件契约）只允许新增，不允许修改既有公开签名的参数
列表；不得引入新的伤害结算公式，必须复用 `weapon_damage_pct` 效果原语与既有结算管线
（`Resolver.Resolve`）。

## 决策

1. **普通攻击是框架原生的一等执行路径，独立于技能施放管线，不是"技能"的特殊形态**：新增
   `Core.Rules.Combat.AutoAttackHost`，按"挥击计时驱动"（不是每 tick/每帧无条件结算一次）维护
   每个施法者的"开关"×"当前目标"两个正交可观测状态（见决策 4），到点时直接构造一份
   `EffectContext`（`EffectKind.WeaponDamagePct`）调用既有 `IEffectSink.ApplyEffect`——复用
   `EffectDispatcher.ApplyDamageOrHeal` → `ICombatHost.ResolveEffect` → `Resolver.Resolve` 这条
   现成的结算链路（命中/暴击/减免/免疫/落地九步固定顺序、事件发布，见 06 第 4.1 节），不新写任何
   伤害计算公式。`EffectContext.SkillId` 固定填一个不对应任何真实注册 `skill.def` 的保留 id
   （`skill.native_auto_attack`，仅供表现层/日志识别"这次结算来自普通攻击"）——结算管线九步本就
   独立于"这次结算是被哪种施法方式触发的"，`weapon_damage_pct` 分支的数值组装只读
   `EffectContext.Params`/`BaseValue`，不反查 `SkillDefCache`，不要求 `SkillId` 指向真实技能。
   判断记录（为什么不强行包一层真实 `skill.def` 走完整施法管线）：普通攻击的"周期"由武器攻速/
   生物模板驱动，不是任何 `skill.def.cast_time`/`cooldown`；若硬套一条真实技能定义，要么迁就
   "瞬发无冷却"技能既有的全局冷却/法术队列语义（与普通攻击"独立于全局冷却"的既定认知冲突），
   要么污染 `skill.book`/`ai.rotation` 内容登记（普通攻击不该出现在任何职业的技能书里）。

2. **挥击周期的数据来源与优先级：已装备武器的攻速优先，否则回退到生物模板声明的固定间隔，
   两者都缺失时不产生任何攻击（不静默降级为某个默认周期）**：
   - 新增 `IWeaponDamageQuery.GetWeaponAttackIntervalSeconds(Id unitId)`（默认接口成员，缺省返回
     `null`）与 `IWeaponDamageQuery.GetWeaponSchool(Id unitId)`（默认接口成员，缺省返回
     `null`）——两者均为纯新增的默认接口成员，不改变该接口任何既有方法的签名；已装备武器时取
     `item.template.weapon_profile.speed`/`weapon_school`（与既有 `GetWeaponDps` 取武器槽位的
     惯例一致：多个武器槽时取按槽位 id 序数最先的一个），未装备任何武器槽（或该槽没有
     `weapon_profile`）时返回 `null`——用 `null` 而不是 `0`，因为 `0` 秒的挥击间隔没有安全的
     "计时器"语义（对应"不会停"，不是"没有周期"），`null` 才能准确表达"这个数据源没有可用值"。
   - 新增 `IAttackIntervalFallbackProvider`（`core/rules/common/contracts`，L2 依赖倒置接口，
     惯例同既有 `IStaticImmunityProvider`）与 `creature.template` 新增可选字段
     `attack_interval`（`FieldKind.Number`，非必填，`min` 严格大于 0，纯新增字段，不提升
     `creature.template` 的 `currentSchemaVersion`，不需要迁移函数）——供未装备武器的生物（框架
     不给生物提供武器槽装备机制）声明一个固定挥击间隔；`core/carriers/creature.
     CreatureAttackIntervalProvider` 是该接口的 L3 实现，经
     `Core.Rules.Assembly.DeferredAttackIntervalProvider`（延迟绑定代理，惯例同既有
     `DeferredWeaponDamageQuery`——`CreatureFactory`/`ICreatureTemplateQuery` 的真实实现要等
     `CarriersAssembly` 组装完成之后才存在，`RulesAssembly` 构造期只能先塞一份代理）在
     `CarriersAssembly` 构造完成后换上真实实现。
   - 两处数据源都取不到值（武器接口返回 `null` 且回退接口也返回 `null`，或回退接口返回的间隔
     `<= 0`）时，本次 tick 不会发生任何攻击，计时器不推进——按 AGENTS.md §3"运行时不静默降级"，
     经既有 `ICombatDiagnostics` 出口告警（同一原因持续存在期间只警告一次，避免刷屏；此前若数据
     变得可用过、之后再次缺失会重新警告一次），不是悄悄按某个默认周期继续攻击，也不是直接抛异常
     中断整个仿真。

3. **落地事件与技能击杀完全同构，既有 XP/掉落/光环触发监听者不需要为普通攻击写任何特判**：因为
   决策 1 复用的是 `Resolver.Resolve` 本身（既有战斗结算的唯一出口），普通攻击命中/致死时发布的
   `combat.damage_dealt`（`CombatDamageDealtEvent`）与 `unit.died`（`UnitDiedEvent`）与技能击杀
   逐字段同构；`Core.Gameplay.ProgressionBridge.CreatureDeathXpListener`/`Core.Gameplay.Loot
   .CreatureDeathLootListener` 各自独立订阅同一个 `unit.died`，天然对普通攻击击杀与技能击杀一视
   同仁，不需要新增任何订阅、不需要在监听器内部区分"死因"。这正是选择"直接复用结算管线的公开
   出口"而不是"另起一条并行的伤害/事件通路"的核心动机——同构不是事后补的兼容测试，而是复用同一
   段代码的自然结果。

4. **可观测状态：一个施法者的"开关"（是否启用普通攻击）与"当前目标"是两个正交状态，合并成
   三值快照 `AutoAttackState { Off, NoTarget, Attacking }`**（`Off` = 未启用；`NoTarget` = 已
   启用但当前没有合法目标，即任务原文"未攻击"；`Attacking` = 已启用且有合法目标）。目标消失
   （`IUnitAccess.Exists` 为假）或目标死亡（`IUnitAccess.IsAlive` 为假）时，当前目标被清空、
   状态回落到 `NoTarget`（与 `CastPipeline`"目标已死亡的技能施放请求"既有惯例一致），不诊断
   （这是正常游戏进程中的状态迁移，不是配置错误）；`Enabled` 本身不受影响，消费方后续
   `SetTarget` 一个新目标即可继续攻击，不需要重新 `SetEnabled`。超出可配置的
   `AutoAttackOptions.Range`（默认 0 = 无限制，惯例同 `SkillDef.Range`）时，本次挥击被跳过（不
   结算、不诊断，同"距离是瞬时可变的战斗状态，不是配置缺陷"口径），计时器清零重新计时，目标本身
   不被清空。`ControlFlags.NoAttack` 单独识别为普通攻击自己的门控，不要求叠加
   `NoCast`/`NoMove`——`CastPipeline.TryStartCast` 的"完全失能"总闸要求三位同时命中才拒绝技能
   施放（服务于"技能施放"这一更宽的判定面），普通攻击有自己独立的门控语义，一个只打
   `no_attack` 的"缴械"类控制光环即可正确拦截普通攻击。命中该门控的这一拍视为被拦截、消耗掉，
   计时器照常清零重新计时，不会在控制解除的瞬间补发一次"攒下来的"攻击（同一口径也用于射程
   判定）。

5. **驱动方式：新增 `TickPhase.CombatResolution` 阶段处理器 `AutoAttackTickHandler`，只在
   `SimStep.Kind == Continuous` 时驱动**（与既有 `CombatTickHandler` 完全一致的既定分工，见
   ADR-0013）；离散（回合制）模式本版明确不驱动普通攻击——离散模式下"自动、按秒间隔重复"这件事
   本身与"每个回合由调度器显式产生一步"的既定时间模型冲突，留给需要它的游戏在离散模式下自行决定
   如何呈现"普通攻击"这一概念（如按回合固定触发一次），不在本决策范围内。

## 后果

### 正面

- 普通攻击第一次成为框架原生可用的能力：接入方不需要再自建计时器绕开结算管线，也不需要把它伪装
  成一条污染技能书/优先级表的假技能。
- 复用既有的武器攻速/生物模板数据、`weapon_damage_pct` 结算公式、`combat.damage_dealt`/
  `unit.died` 事件——维护面几乎不增加：普通攻击的行为随既有武器/生物数据/伤害管线的后续演进自动
  演进，不需要在两处（技能结算与普通攻击结算）重复维护同一份数值逻辑。
- 既有 XP/掉落/光环触发监听者对普通攻击击杀天然生效，不需要因为这次改动补任何特判分支。

### 负面

- 新增的两个 `IWeaponDamageQuery` 默认接口成员要求全部实现者（`EquipmentHost`/
  `DeferredWeaponDamageQuery`）显式转发（`InterfaceDefaultMemberForwardingTests` 门禁要求），
  给这条既有接口再添两个方法的维护面；`creature.template` 多一个可选字段，内容作者需要知道它的
  存在才会去为需要"无武器普通攻击"的生物（如野兽类近战生物）配置它。
- 离散（回合制）模式暂不支持普通攻击，选择离散时间模型的游戏仍需自行决定"普通攻击"概念如何落地
  （或干脆不需要这个概念）。

## 备选方案与为什么不选

- **把普通攻击定义成一条真实的、无消耗无读条无冷却的 `skill.def`，复用整条 `CastPipeline`**：
  能省去新增 `AutoAttackHost`/`AutoAttackTickHandler` 这两个类型，但会把普通攻击强行纳入全局
  冷却/法术队列/技能书/AI 优先级表这些为"玩家/AI 主动选择要不要现在释放"设计的既有语义，普通攻击
  恰恰不属于这一类（它是"持续、被动、不需要每次显式决策"的），两种语义硬凑在一起只会让
  `CastPipeline` 的既有行为变得难以推理。故不选。
- **游戏层自建计时器，框架只暴露"造成一次武器伤害"的原子方法**：框架已经有
  `IEffectSink.ApplyEffect` 这个原子入口，理论上游戏层确实能自己拼出一套计时器；但这正是消费方
  反馈指出的现状缺口本身——每个接入方各自实现一遍"武器攻速换算成挥击周期""目标消失/死亡如何处理"
  这类与具体游戏设计无关、纯属战斗基础设施的逻辑，重复造轮子且容易出现"目标死亡后计时器状态未
  清理"一类边角错误。故不选，改为框架原生提供。
- **挥击间隔缺失时按一个内置默认值（如 2 秒）静默降级**：与 AGENTS.md §3"运行时不静默降级"直接
  冲突——一个没有武器也没有声明间隔的单位理论上不该被开启普通攻击，静默给一个默认周期只会掩盖
  "这个单位的数据没配对"这一真实问题，且这个默认值本身无法找到任何设计依据（06/07 均未给出"徒手
  普通攻击"的间隔口径）。故不选，改为诊断 + 不攻击。

## 魔兽世界的对应做法

近战/远程普通攻击由客户端按武器攻速本地计时、命中判定与伤害结算走服务端战斗公式，是与技能施法
（法术）并列的独立系统，不占用全局冷却，也不出现在任何天赋/法术书条目里——本决策"普通攻击是
独立于技能施放管线的一等执行路径，不占用技能书/优先级表登记"的取舍与其一致；本框架的具体实现
（挥击计时驱动、复用 `weapon_damage_pct` 结算原语）是框架自身战斗层已有能力的组合，不是对该游戏
内部实现细节的对照。
