# ADR-0137 姿势切换交叉淡入时长数据化：每对键 > 逐键 > 缺省 0.15 秒

状态：已拍板 2026-10-03（对 [ADR-0119](0119-姿势维度模型与标准姿势库.md) 姿势集数据行的加法字段决定；手感落地 M4-D 引入）

## 背景

骨骼剪辑型外形在切换剪辑时，引擎适配层此前固定做 0.15 秒的交叉淡入。固定值对不同的状态切换并不合适：受击要几乎立刻切（过长的淡入会吃掉受击的打击感），落地接待机、起身接待机要更柔和，格挡要稍长。而姿势集数据里没有任何地方能表达"这次切换用多长"，调整只能改适配器代码，不同游戏的取舍也无法随数据走。

需要给过渡时长一个数据通道，同时不能改变任何既有数据行的行为（既有姿势集没有声明过渡时长）。

## 决策

1. **加法字段，不升 schema 版本**：姿势集数据行的每个剪辑条目新增可选字段 `blend_ms`（切入本剪辑的交叉淡入毫秒，0..2000）；行级新增可选字段 `blends`，每项 `{from, to, blend_ms}`，声明"从键 `from` 切到键 `to`"这一对的时长。`from`、`to` 是本行合并后剪辑表里的剪辑**键**，不是资源引用。

2. **优先级：每对键 > 目标剪辑逐键 > 调用方缺省**。两者都没有声明则返回"未声明"，由调用方用自己的缺省（骨骼角色外壳取 **0.15 秒**）。**显式 0 表示硬切**，与"未声明"可区分（声明 0 返回"已声明、值为 0"）。

3. **缺省保持 0.15 秒，而不是 0**：适配层此前一直固定 0.15 秒，把缺省改成 0 会让所有未声明的既有数据行行为变化，所以缺省保持 0.15 秒，要硬切必须显式写 0。

4. **继承合并**：姿势集有 `extends` 时沿继承链合并——子集覆盖同名键而没有写 `blend_ms` 则沿用被覆盖键的值；`blends` 沿链合并，子集声明的同一对键覆盖父集。体量组等派生行因此不必重复声明。单条记录不带登记表解析时只取自己这一行。

5. **键到资源引用的换算在姿势集内部完成**：运行期播放器只认资源引用，所以姿势集按合并后的剪辑表把键换成引用再查；体量组继承主集的 `blends` 时自然换算成组内自己的引用。

6. **只对骨骼剪辑型外形生效**：骨骼角色外壳在切换剪辑时按"上一个剪辑 → 本剪辑"取值；序列帧型外形的播放器不做交叉淡入，字段对它无效。没有挂姿势集时外壳取自己的缺省，与此前逐位一致。

7. **校验**：`blends` 引用了合并后剪辑表里不存在的键，或同一对重复，报**警告**（悬空的对在运行期被忽略，回落到逐键值或缺省，不影响播放）；值的范围与类型错误由字段登记报**错误**。形状错误（`blends` 不是对象数组、缺字段、非数值）在解析时抛数据错误，不静默丢弃。

8. **过渡时长不进动画控制器**：控制器的状态之间没有过渡连线、不含任何时长，过渡由运行期按数据取值后交叉淡入；因此控制器与资源标识不变，生成仍是确定性的、重复生成逐字节一致。框架的标准假人姿势集按状态给出逐键值（例如待机 120、移动 100、受击 30、格挡 80 毫秒）与若干每对键值（例如落地到待机 160、起身到待机 180 毫秒）。

## 后果

### 正面

- 过渡手感随数据走，游戏改数据而不是改适配器代码；每对键的粒度能表达"受击要快、落地接待机要慢"。
- 全部是加法，缺省行为逐位不变；没声明的既有姿势集与第三方数据行不受影响。
- 控制器资产不变，不增加资产体积，也不破坏生成的确定性。

### 负面

- 过渡时长只在骨骼剪辑型外形生效，序列帧型游戏声明了也没有效果（字段对它无意义，不报错）。
- 缺省 0.15 秒与"缺省 0 即硬切"的直觉不同，写数据的人需要知道硬切必须显式写 0。
- 键与引用的换算依赖合并后的剪辑表，悬空的对只给警告，拼错键名会静默落回缺省值。

## 备选方案与为什么不选

- **缺省改成 0（未声明即硬切）**：所有既有姿势集行为改变；否决，缺省 0.15 秒。
- **把过渡时长写进动画控制器的过渡连线**：要改资产、体积增加，且无法表达"每对键"的粒度并随继承合并；否决。
- **只提供全局单值**：不能区分受击与落地；否决。
- **另开一张过渡时长数据表**：与剪辑条目分离，继承合并要两处同步；否决，字段放在姿势集行内。
- **悬空的对报错**：它们在运行期无害，报错会让体量组等派生行因父集改键而无谓失败；否决，警告。

## 魔兽世界的对应做法

无直接对应：魔兽的动画过渡由客户端动画系统内部决定，不向数据层暴露每对动画的混合时长。
