# ADR-0158 手感演示场景 3D 版：真实骨骼模型、模型包装配与直立站姿

状态：已拍板 2026-10-05（承接 [ADR-0154](0154-手感演示场景真实美术表现层导演与框架界面皮肤.md) 的演示场景与导演；与 2.5D 版并行推进。编号说明：并行会话占用 0156（发布提速）与 0157（演示场景 2.5D 版），本条取 0158，合并时若索引已被占用按先到先得顺延；表现层只读逻辑事件，不改任何逻辑与数据行为）

## 背景

演示场景 2D 版（ADR-0154）证明了"同一手感运行时、换一套真实美术"。三维格子（3d_action）的试玩场景仍是白灰色方块人偶，看不出受击姿势、出手预备、倒地起身这些属于动画的那一半打击感，也没有走过框架的三维模型表现管线（模型视图工厂、骨骼动画控制器、命中帧事件对齐）的真实资产。需要一个 3D 演示场景：同一逻辑会话，真实骨骼角色经框架自己的模型管线渲染，由数据行驱动，不开实验室专用旁路。

## 决策

1. **场景是同一试玩宿主的一个选项。** `LabShowcase_3d_action` 是薄场景（格子 `3d_action`，演示开关打开），逻辑装配、固定步、输入、录制、F1 面板全部沿用；3D 追加的数据根 `data/_showcase_3d`（只含显示行：`display.anim_set` 与 `display.weapon_style`）由宿主按格子名并入。用例对同一段脚本输入比较它与 `LabPlayground_3d_action` 的逻辑指纹，逐字节相等；原 3D 试玩场景保持白灰方块、无导演无 HUD，用例守护。

2. **走框架既有模型管线，不开旁路。** 展示信息是 `DisplayInfo(kind=Model, ModelInfo(modelRef, animSetRef))`，`model.<名>` 解析为运行期资源 `GameFoundation/models/<名>` 的模型预制体，`anim.<名>` 为 `GameFoundation/anim_clips/<名>`；动画控制器的状态名就是剪辑 id；`display.anim_set` 行带事件（`hit_frame` 驱动命中帧对齐与挥砍拖影）。演示显示注册表在 2D 版的合成注册表上增加"模型型"出口：按单位类别给出模型与动画集，缺行时回落由用例判红而不静默显示占位。

3. **美术：Quaternius「RPG Character Pack」（CC0）四个互不相同的角色。** 英雄 = 战士，杂兵 = 盗贼，精英 = 牧师，木桩 = 武僧；只保留实际使用的 4 个骨骼模型文件与 7 张贴图加许可与来源说明，约 13 MB（`assets/_showcase/models/`，原包其余角色不入库）。地面复用 2D 演示的石砖贴图（贴图平面），道具与特效复用 2D 演示的道具图与特效图（广告牌）。

4. **模型包由编辑器工具确定性装配，装配结果不入库。** 规格由 `assets/_showcase/_source/build_data_3d.py` 单一来源生成（`showcase3d_models.json` 与展示行同源，`--check` 校验提交的文件没被手改）。构建脚本把 `assets/_showcase/models` 镜像到被忽略的导入根 `Assets/Showcase3dArt/Source`（镜像保留 `.meta`，新增参数 `-PreserveExtensions`）；包内编辑器工具 `ModelPackBuilder`（`Editor/ModelPack`）在编辑器加载时（或批处理入口）按规格生成材质、独立 `.anim`、动画控制器与预制体，写进 编辑器侧运行期资源目录。运行期用例的"缺同步必须红"断言覆盖：模型或贴图缺失时，用例失败而不是画占位。

5. **状态到剪辑的映射写在数据行里。** 每个角色一行 `display.anim_set.show3d_<角色>`：待机、战斗待机、行走、奔跑、冲刺、普攻与各段连招、施法、受击（轻/重/击退/击倒/起身）、死亡、闪避；技能到施法剪辑的映射放武器样式行的 `cast_anim_override`（含闪避技能）。包里缺的状态取最接近的剪辑并登记限制（见"已知限制"），限制清单随规格入库并有用例守护非空。

6. **直立站姿：`ModelGroundUpright`。** 框架约定模型锚点在 (x,y,0)、沿 +Y 站立，而 2D 宿主的地面是世界 XY 平面、相机在 -Z 侧俯视；这种约定下模型会"躺"在地面上。演示预制体在锚点下挂一个直立枢轴，由 `ModelGroundUpright` 每帧把朝向从锚点偏航读出来，重算为"头朝 -Z、脚踩 XY 平面"的姿态；模型子节点带 +90° 偏航偏移（包内模型原生朝 +Z）与按头高归一化的缩放。这是 `Runtime/EngineAdapter` 里一个小组件，只在带它的预制体上起作用，其他模型行为不变。

7. **投影收口：`ShowcaseProjection` 增加"物理上方"模式。** 2.5D 版引入的 `ShowcaseProjection` 在此扩一个构造参数：3D 时"向上"取世界 -Z，头顶、飘字、血条按物理上方抬高；道具与特效仍是与相机平行的广告牌，特效摆点沿视线向相机拉近（避免被有厚度的网格写深度挡掉一半）；朝向换算在 3D 下不加半圈偏移（那是精灵方向槽位的约定）。2D 与 2.5D 的行为不变。

8. **渲染：二维渲染器管线下的自写模型着色器。** 项目用可编程渲染管线的 2D 渲染器，没有 3D 光照；自写着色器 `GameFoundation/Showcase/ModelLit`（两个通道，写死世界空间太阳方向做半兰伯特，带闪白强度），模型闪白走它；脚下阴影沿用框架的假阴影，贴一张柔边圆形遮罩贴图。

9. **导演规则沿用。** 非玩家单位面向玩家、刚被打的单位 3 秒内面向最近攻击者（只改引擎侧视图朝向，逻辑朝向与指纹不变）、每个实体恰好一个可见模型、飘字分道、连击计数、冷却扫光，全部是 2D 版的同一份代码；挥砍拖影由命中帧事件触发（模型平面的命中帧回调接到导演）。

10. **F1 面板与原 3D 试玩场景功能一致**：武器 F3、体型 F4、手感模板 `tpl_*`、场景控制与调参、时间轴、轨迹、评分页；用例对比两个场景的面板页集合。

## 已知限制

- 包里没有击退专用剪辑：hit.knockback 取重受击（hero/grunt：RecieveHit_2；brute/dummy：RecieveHit_Attacking）。
- 包里没有击倒与起身剪辑：hit.knockdown 取死亡倒地剪辑（Death，不循环，停在倒地姿势），hit.getup 取同一份死亡剪辑的确定性倒放（编辑器侧派生，不改包内文件）。
- 包里没有闪避剪辑：dodge 取翻滚（Roll）。木桩（Monk）不声明闪避。
- 包里只有两种挥剑（Sword_AttackFast / Sword_Attack）：连招第三段与重击、蓄力取 Sword_Attack，三个技能各有独立剪辑 id 但画面相同。
- 冲刺（move.sprint）与奔跑共用同一份跑步剪辑；包里没有受伤姿态与持械变体，idle.combat 取各角色自带的战斗待机。
- 模型没有专门的击杀倒地后淡出：死亡剪辑停在最后一帧，尸体由逻辑清场移除。
- 带 `ModelGroundUpright` 的预制体不响应视图倾斜（`SetLean`）；这是演示预制体的取舍，其他模型不受影响。
- 部分剪辑身体扭转幅度大（包内动画本身的设计），从背后看英雄连击时肩背朝向会摆动，不是朝向换算错误。

## 不做的事

- 不为 3D 演示场景新增逻辑数据行或改任何基线；全部基线与数据集哈希零差异。
- 不把参考皮肤资源并进本场景（沿用 ADR-0154 决策 4）。
- 不用云端或实验室专用旁路生成/渲染；模型资产是下载的 CC0 现成资产，没有生成式美术。
- 不做 2.5D 版（另一分支，ADR-0157）。

## 后果

### 正面

- 3D 手感可以在真实骨骼动画下评：受击、击退、倒地起身、挥砍命中帧对齐，与手感数据同时可见；逻辑不变有指纹相等用例。
- 模型管线首次有"数据行驱动的真实资产"端到端用例（加载、动画切换、事件、闪白、站姿、朝向）。

### 负面

- 导入根 `Assets/Showcase3dArt` 与 编辑器侧运行期资源目录 的装配结果不入库，首次打开项目需要一次装配（自动触发，约十几秒）。
- 缺的动画状态靠近似剪辑顶替，评击倒/起身/闪避手感时要参考上面的限制清单。
