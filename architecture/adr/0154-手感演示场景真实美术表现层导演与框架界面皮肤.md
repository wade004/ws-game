# ADR-0154 手感演示场景：真实美术、表现层导演与框架界面皮肤

状态：已拍板 2026-10-04（承接 [ADR-0141](0141-手感实验室人手试玩宿主.md) 与 [ADR-0150](0150-实验室调参面板与时间轴轨迹评分.md) 的试玩宿主；表现层只读逻辑事件，不改任何逻辑与数据行为；落地 [手感设计/06](../手感设计/06_手感实验室与验收.md) 第 1 节试玩宿主）

## 背景

试玩宿主的占位精灵（色块与几何体）把"手感"和"画面"绑在一起评：占位图没有出手预备、没有受击姿势，打击感里属于动画的那一半（受击动作、击退姿势、挥砍拖影、命中火花、伤害数字、技能条冷却扫光）都看不出来。需要一个与试玩场景**同一套手感运行时**、但画面是真实美术的演示场景，让设计者在真画面里调参、评分，同时证明"换一套美术不改逻辑"。同时发现试玩面板里按钮与条目文字缺失（见决策 6）。

## 决策

1. **演示场景是试玩宿主的一个选项，不是另一套宿主。** 选项只改"表现装配"：数据根多一个演示数据根（只含显示表行，不含逻辑表）、显示注册表换成合成的演示注册表、舞台挂一个导演与一个界面。逻辑的装配、固定步、输入、录制、面板与调参路径完全沿用，原试玩场景（无该选项）的逻辑逐位不变（决策 8 例外：受击剪辑的选择与生产对齐，只影响表现）。格子只支持 2D 动作。理由：同一运行时才能保证"在演示场景里调出来的手感"就是真手感；不分叉才不会两套宿主互相漂移。

2. **表现层导演只订阅逻辑事件，不写回逻辑。** 命中确认、动作开始、单位死亡三类事件驱动：挥砍拖影（取动作的拖影时段）、命中火花（按冲击等级与暴击缩放）、倒地尘土与冲击环（只对击退/击倒/击杀/重冲击）、目标闪白（受"闪白"开关约束，沿用既有反馈开关）、伤害飘字与敌人头顶血条的数据。镜头震动与顿帧仍由手感运行时给出，导演不重复实现。**证据**：同一输入串在演示场景与原试玩场景各跑一遍，逻辑指纹逐字节相等（指纹排除数据集哈希，所以多一个只含显示行的数据根不影响比较）。

3. **美术是数据资源，不进代码，也不改既有表。** 英雄、小兵与精英共三套角色，每套含待机、跑、攻击、受击、击退、击倒、起身、死亡等剪辑，三个朝向（正、侧、背），斜向由展示端镜像对复用（右斜取侧向、左斜取侧向水平翻转）；场景地面与道具以静态图提供，特效（挥砍拖影、火花、尘土、冲击环）与技能图标为独立资源。显示信息（动画集、武器样式、地图行）放在演示数据根，用前缀唯一决定路径空间的既有约定（[ADR-0038](0038-资源引用类别前缀唯一决定路径空间.md)），不引入新前缀。美术原图与中间产物只留本地，不入库；入库的只有经确定性后处理（抠底色、锚点对齐、缩放到固定画布、降色保真）后的成品，总量控制在数十 MB。

4. **界面走框架界面库与皮肤契约。** 玩家生命与体力条、敌人头顶血条、伤害数字、技能条（含冷却扫光）、连击计数都用框架界面控件搭建；皮肤引用缺省指向参考皮肤，该皮肤资源不在场时回落到占位皮肤，不报错。皮肤资源本身属于它自己的分支，**不拷进本场景的资源**。界面只读导演的模型，不碰逻辑。

5. **调试面板缺省收起，一个键展开。** 演示场景进入时只有游戏界面；展开键显示原试玩面板（预设、模板、调参、时间轴、轨迹、评分页全部可用），叠加在演示画面上。理由：设计者调参时需要面板，演示、录屏、截图时需要干净画面。

6. **文字缺失缺陷：根因是面板内容宽度远大于面板，布局把超出部分裁掉。** 按钮与条目被排成一行，总宽远超面板宽，窗口外的文字不绘制。修法是把横向排列的开关项按面板宽度折行（纯函数规划，输入各项宽度与行宽，输出每行内容），所有页的开关排列统一走它。**复现**：纯函数用例（宽条目折行后每行不超过行宽，修复前红）；窗口模式下用真实布局探针量出每页内容宽度，断言不超过面板宽（批处理模式不分发界面事件，该用例仅在窗口模式运行）。

7. **舞台相机不被宿主相机盖掉。** 宿主相机（引擎宿主创建，剔除全部层、深度 0）原先会在舞台相机之后创建并覆盖其画面，导致画面缩半、不跟随。修法：先确保宿主相机存在，再从所有其他相机的剔除掩码里去掉舞台层；交互模式下舞台相机深度高于宿主相机。用例断言舞台层被所有其他相机排除。

8. **试玩舞台的动画状态机与生产一样进入受击反应驱动模式。** 生产装配会把只读的受击反应查询交给视图工厂；试玩舞台自己建视图工厂，原先漏了这一步，受击动画只会播基础受击剪辑，击退、击倒、起身的剪辑永远不会播，反应为无或霸体时也照样播受击动画。实验室舞台与生产表现不一致是舞台自己的缺陷，所以**所有舞台**（原试玩场景与演示场景）在建好视图工厂后都交付这个只读查询，口径与表现装配相同（手感受击裁决已装配且处于活动状态才交付）。逻辑指纹不变；引擎侧表现类度量若因此变化，只允许变化来自受击剪辑的选择，逐项核对后重录并在实验室 README 判断记录 73 写明。用例：同一重击脚本下，试玩场景与演示场景都选到击退/击倒类剪辑。

9. **头顶名字与飘字布局。** 敌人头顶名字取生物模板的名字键经本地化表解析，缺名才回落出场标签；同一目标连续命中的飘字按出字时的在场数字个数分道，左右轮换并逐道抬高，起点高过名字与血条，避免叠在一处。

## 不做的事

- **不做 2.5D / 3D 演示场景。** 本次只做 2D 动作格。
- **不为演示场景新增逻辑数据行或改任何基线。** 全部基线与数据集哈希零差异。
- **不把参考皮肤资源并进本场景。** 缺省回落占位皮肤。
- **小兵的"击倒/起身"剪辑不由视频模型生成。** 视频模型对"摔出去"一律画成多出的第二个主体；改用同一角色的死亡倒地过程与它的倒放确定性派生，见实验室 README 判断记录 73。

## 后果

### 正面

- 设计者在真实画面里调参，受击动作、拖影、火花、飘字、冷却扫光与手感数据同时可见；逻辑不变有可执行证据（指纹相等用例）。
- 文字缺失缺陷有红转绿的复现用例；相机覆盖问题有断言守护。

### 负面

- 美术成品入库约 32 MB，仓库体积增加；原图不入库，重出图需要本地生成环境与对应脚本。
- 演示场景的显示注册表是合成的（按单位类别映射到演示角色），新增单位类别要补映射。
