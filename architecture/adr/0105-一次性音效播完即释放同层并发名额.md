# ADR-0105 一次性音效播完即释放同层并发名额

状态：已拍板 2026-09-27（同日修订：主路径改为引擎回报，保留时长降为回退）

## 背景

消费方第五十四批反馈（在 1.84.0 冻结提交上黑盒排查）：同一次普通攻击内先后发布"挥出普通攻击"与
"造成伤害"两个事件（相差约 2 毫秒），分别驱动两条 `play_sfx` 规则，两个音效同属一个分层音效轨道，
挥击音效优先级低于命中音效。命中音效稳定可闻，挥击音效始终观测不到；事件发布、条件求值、资源加载、
单调累计播放诊断（ADR-0083）均正常，`PlayRequestedCount == PlayStartedCount`、`PlayDroppedCount == 0`。

框架内部复现（生产装配 + 真实表现绑定 + 真实音效播放器 + 桩音频后端）定位根因：音效播放器按层维护
"当前在播实例"记账，用于执行同层并发上限与按优先级抢占；但引擎适配层的音频契约没有"某个播放句柄
是否已经播完"的查询，记账只在显式停止或被抢占时释放。已经自然播完的一次性音效永久占着名额，一个层
累计播放满上限次之后就"永远满员"，此后每一次播放都要抢占一个名额——同层里优先级最低的新音效（挥击）
会被几毫秒后到来的更高优先级音效（命中）选为被抢占者，当场停止。抢占停止一个已经开始的播放不属于
"丢弃"，所以播放诊断计数完全正常；"最近一次播放"记录在同一帧内被命中音效覆盖，逐帧轮询也永远看不到
挥击音效。层内是否恰好还残留更早的、同为最低优先级的陈旧记账（例如其它单位的挥击音效），决定这一次
被停掉的是陈旧记账还是刚开始的挥击音效——这解释了消费方观测到的"间歇性"。

## 决策

1. **音频契约新增"句柄是否仍在播"查询**（默认接口成员，纯加法）：回报 `true` 仍在播、`false` 已结束
   （自然播完、已停止、句柄已回收或从未分配）、`null` 表示实现方不支持回报；默认体恒返回 `null`，
   既有实现方零改动。
2. **一次性音效的层记账以引擎真实回报为主释放**：音效播放器在逐帧维护入口与"判断层是否满员"之前，
   对每条非循环记账询问该查询——回报 `false` 立即释放；回报 `true` 保留（即便已超过下一条的保留
   时长，真实回报优先于推定）；回报 `null` 才退回下一条。两处共用同一个释放出口。释放只摘记账，
   不发停止指令。
3. **回退：保留时长推定**：音效播放器的可配置项新增"一次性音效层名额保留时长"（可选属性，默认 2 秒，
   ≤ 0 表示回退路径不释放）。仅当后端对该句柄回报 `null` 时生效：从真正开始播放（含首次冷加载完成
   后的补播放，取补播放那一刻）起，占满该时长后推定已播完、释放记账。计时用表现层逐帧维护入口传入
   的时间增量累加，不读系统时间。
4. **循环音效不释放**：显式停止前一直占名额，照原规则参与抢占。
5. **上限与抢占规则本身不变**：层内真正在播的实例超过上限时，停掉层内优先级最低者，同优先级停最早者。
6. **引擎适配层落地**：具体引擎的音频实现覆写该查询——句柄仍占播放槽位、该槽位有可播放的音频内容且
   引擎回报正在播放，才回报 `true`；其余回报 `false`。测试桩提供可控的"已播完"标记与"不回报"开关。

## 后果

### 正面

- 同层"低优先级音效后紧跟高优先级音效"的常见组合（挥击后命中、施法后命中）不再在长时间运行后
  把低优先级音效当场掐掉；并发上限回到它本来的含义——限制"真正在播"的实例数。
- 支持回报的后端下名额释放精确到引擎实际状态，不依赖任何推定。
- 纯新增契约成员与可配置项，公开签名不变；单调累计播放诊断（ADR-0083）的三个计数语义不变（释放
  与抢占停止都不计入丢弃）。

### 负面（已知限制）

- 仅当音频后端对句柄回报 `null`（不支持回报）时，才按保留时长推定，存在推定误差：比保留时长长的
  一次性音效尾段不再计数（上限在尾段变松，但不会被提前停止），比它短的音效播完后到期前仍占名额；
  且该回退依赖逐帧维护入口被驱动，不驱动时不会到期。

## 备选方案与为什么不选

- **只按保留时长推定，不新增查询**：启发式，推定误差在所有后端上都存在，不选（本决策初版曾如此，
  同日修订为以引擎回报为主）。
- **同优先级不抢占仍在起音的实例 / 新开始的实例一律免于被抢占**：本案两个音效优先级不同，前者无效；
  后者会让刚开始的低优先级一次性音效反过来挤掉仍在播的高优先级循环音效，破坏优先级语义，不选。
- **按系统时间计时回退**：不确定、测试需真实等待，且与表现层已有的逐帧维护入口重复，不选。
