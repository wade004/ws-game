# ADR-0120 手感实验室为框架交付物

状态：已拍板 2026-10-01（用户确认实验室必做）

## 背景

手感是迭代出来的。没有一个固定的、可重复的场景与工具，每个游戏都得在自己的关卡里"改一个数、重新构建、跑到怪面前挥一下"，而且调好的东西无法固化为回归。手感回归也没有载体：改了动画帧数或标定，手感变了没人发现。用户明确要求实验室必做。

## 决策

1. **一个内核、两个宿主、一份数据集**：引擎无关的实验室内核（场景控制、输入脚本驱动、录制器、指标提取、覆盖存储、溯源、A/B、导出为测试）；无头宿主（无头运行器 + 桩适配层，跑日常回归、出指纹）；引擎宿主（与模板游戏并列的独立包，基于长驻运行入口，人玩、调参、里程碑冒烟）；框架级数据集 `_lab`（竞技场、玩家模板、四类靶子、首期武器、假人姿势集、预设）。两个宿主吃同一份输入脚本、出同一种指纹。
2. **数据根可替换**：实验室场景固定，数据根可指向任何游戏自己的数据集；新游戏用自己的角色、武器、美术进同一个实验室。
3. **输入脚本是通用货币**：逐 tick 的动作事件序列加元数据，可手写可录制，经桩输入按 tick 注入；标准脚本集随框架发布，验收场景每个一份脚本入库当夹具。
4. **录制三条时间线**（逻辑、表现、真实时间），全部只读订阅；引擎宿主录制时同时产出输入脚本，人玩的一局可在无头宿主逐 tick 重放。
5. **指纹回归**：从录制算出响应/移动/攻击/顿帧/受击/群体/性能七组指标；指纹以（脚本、数据根版本、预设、标定、姿势集版本、适配组合）为键，基线作为夹具入库；逻辑组逐字节一致，表现组按容差（标定表只可收紧）；30/60/120 帧率上限各跑一遍逻辑组必须一致；基线全部在假人姿势集上采集。真实屏幕延迟只提供角落闪块供外测。
6. **覆盖与溯源**：调参走解析器第 8 层，与正式配置同一套校验，在安全动作边界生效；两个 A/B 槽位；写回数据表产生差异走正常提交；面板关闭零开销。
7. **导出为测试**：录制 + 指纹一键写成夹具；回归失败的用例可在引擎宿主加载重放慢放。
8. **五层测试**：解析器单元、判定型模拟、呈现型模拟、端到端指纹（前四层无引擎，每次提交）、引擎内实验室（里程碑与升级引擎，采指纹比差 + 主观评分）。
9. **验收表与硬门槛**：客观检查对应前四层，试玩检查对应评分表；"必须通过"八条（每攻击实例按规则命中、取消无残留、顿帧句柄释放、无冻结泄漏、低帧率不漏、能力可诊断、双跑逐字节一致、离散模式一致）。`experimental → validated` 需客观全绿 + 评分达标记录 + 绑定版本与设备。
10. **生成物规则**：录制、指纹输出、评分、截图、拼图全部本地；只有输入脚本与指纹基线入库；基线更新必须是显式提交，不允许静默通过。
11. 实验室是开发期运行时诊断工具，属框架（不是随游戏走的内容编辑器，ADR-0018 的编辑器边界不变）；面板视图模型在表现层，引擎侧只绘制。

## 后果

### 正面

- 调参循环从"分钟到小时"压到秒级；调好的手感一键变回归；回归红了能在引擎里原样重现。
- 原型库与姿势集有了验收场，成熟度标签有据可查。
- 新游戏接入手感的全部步骤都在实验室里完成，不写机制代码。

### 负面

- 实验室本身是需要维护的框架包（数据集、脚本集、面板）；姿势清单或字段登记变化要同步。
- 引擎宿主的第五层测试依赖真实引擎与设备，只能里程碑跑。

## 备选方案与为什么不选

- **只做引擎内调参面板**：调出来的东西不能进无头回归，指纹无从谈起；否决。
- **只做无头测试不做引擎场景**：主观手感无处试玩，预设无法升 `validated`；否决。
- **实验室放进每个游戏自己写**：正是要消除的重复；否决。
- **指纹用容差比较逻辑组**：固定步长本就确定，容差只会掩盖回归；否决。
