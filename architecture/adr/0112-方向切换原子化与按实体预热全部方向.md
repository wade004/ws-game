# ADR-0112 方向切换原子化与按实体预热全部方向

状态：已拍板 2026-09-30

## 背景

消费方第六十三批反馈（阻塞，两条）。精灵单位第一次转到某个方向档位（冷转向）时，新方向的静态层图和逐层
剪辑还在加载：

- 静态层在期望方向变化的**当帧**就按新方向重合成（资源未到时先是占位图）；
- 逐层剪辑的内容要等新方向探测异步完成才被换掉，其间逐层映射为空，整身兜底渲染器被打开，继续播放
  **旧方向**的整身内容，且排序压在纸娃娃层之上；
- 结果是 0.1～0.3 秒里旧方向身体与新方向装备同屏，开头一两帧还有占位图；同一方向第二次转过去（热转向）没有
  这个窗口。

第二条：没有"按实体（外形）预热全部方向"的入口，游戏侧要避免首次转向发硬只能自己按命名规则拼资源 id 去
预热，等于复制一份框架的探测候选规则。

## 决策

### A. 方向切换原子化

1. **期望方向与已显示方向分离**。视图同时持有两者；模拟朝向（逻辑层/锚点之外的一切）不受影响。新方向准备好
   之前，全部视觉内容——静态层、装备层、逐层剪辑帧、整身与覆盖剪辑、随方向变化的锚点——都停在已显示方向。
2. **"准备完成"的定义 = 当前显示所需**：每一项都有结论。项 = ① 新方向下当前合成层集合每一层的静态图；② 运动态
   两个状态键（`idle`、`move`，含该外形声明的对应战斗变体键）以及实体**此刻所处状态**的状态键，这三类状态键的
   逐层剪辑（逐层全部耗尽时再加整身方向变体）；实体此刻正在播放的覆盖剪辑（有的话）同样计入。结论 = 已加载，
   或确认缺失（探测档位耗尽 / 加载失败）。缺美术算结论，**从不无限等待**。其余状态键（attack / cast / hit /
   death / jump 及其变体）与其余覆盖剪辑**不阻塞提交**：提交时才在后台发起探测，进缓存后由既有补切路径接上。
   预热（B）不受此收窄影响，一个档位有结论仍按全部状态键与覆盖剪辑计。
3. **准备期间只加载、不改显示**：合成"某方向下的层集合"是纯计算（与应用路径共用同一份实现），不写渲染器、
   不触发既有的重探测/重登记。
4. **单帧提交**：全部有结论的当帧，把结果写入既有的按方向缓存，再走原有的换向路径——全部命中缓存的同步分支——
   在同一帧内换掉静态层与剪辑内容。播放时间轴沿用既有换向规则（保留进度）。
5. **仅镜像变化（同档位、翻转不同）与热转向当帧提交**（0 帧保持）。
6. **准备期间期望方向再变**：放弃旧目标（其在途加载自然完成进缓存，不取消、不报错），转为准备最新目标；
   显示始终停在最后一次提交的方向。期望方向变回已显示方向即取消待切换。
7. **并行探测**：新方向的全部加载同时发起；每条探测链保持既有的分档回落语义（带方向档位 → 无方向档位 →
   保持静态）。
8. **整身兜底渲染器方向不变量**：兜底渲染器可见时，它上面登记的剪辑内容的方向必须等于已显示方向（内容与方向
   无关的除外）；不满足就保持隐藏、显示静态层。实现为给登记到播放器的剪辑内容打"内容方向"标签（带方向档位的
   命中记方向名，无方向档位/单帧占位记空）。只对有纸娃娃层的外形生效（没有纸娃娃层的外形整身渲染器是唯一的
   视觉内容，隐藏它只会让实体消失）。
9. **提交后进入尚未就绪的状态**：该状态在已显示方向下的逐层剪辑没就绪的层，显示已显示方向的静态层图；整身兜底
   渲染器只有内容方向等于已显示方向时才可见（决策 8 的不变量兜底）；绝不显示其它方向的内容。剪辑加载完成后按
   既有补切路径接上（此时仍在该状态则换成剪辑帧）。
10. **首次显示与换装不要求原子**（现状见下"已知限制"）；准备期间换装则重新计算完成条件，提交时不混。
11. **默认开启、没有开关**。`DirectionSlotChanged` / `OnDirectionSlotChanged` 语义变更为**提交时**触发（此前是
    期望方向变化的当帧）；新增只读查询：期望方向、已显示方向、是否有待切换。

附带调整：合成层身份（用于判断"装备变了要不要整体重探测"）由"(层名, 合成后的层资源 id)"改为
"(层名, 装备资源集引用)"。此前资源 id 含方向档位段，纯方向变化的重合成也被判成装备变化，触发一次清空全部按
方向缓存的完整重探测。锚点查询在有已显示方向时改用已显示方向。

### B. 按实体预热全部方向

1. **入口**：视图工厂上按实体的预热调用（镜像对去重后的每个方向档位各跑一次与转向相同的准备），带完成回调；
   只读进度查询给出"已就绪档位数 / 总档位数"。
2. **逐档位顺序执行**（一个档位有结论后再发起下一个，控制在途加载量与内存峰值）；**让路**：只要有实体正处于
   真实转向的准备中，预热在档位之间暂停，转向提交后继续（已开始的档位内的加载不暂停）。
3. **粘性**：预热过的实体换装后对新增层补预热一轮（进度回落，已加载的同步命中）；实体销毁/工厂清理时取消并
   清理，未完成的回调以 `false` 触发一次。
4. **选项枚举** `None`（默认）/ `OnAttach`（视图挂接完成后自动预热）。默认不多发任何加载。
5. **使用加载器既有的分帧预算**，不新增第二套预算（ADR-0109）。
6. **已知代价**：预热把该外形全部方向的贴图常驻内存。实测（真实美术，一个 16 方向外形 = 9 个不同档位，五个
   状态键，身体 + 一件装备层）：预热总耗时约 3.6 s（加载器主线程预算 4 ms，216 帧，60 Hz 配速）/ 2.3 s（预算 8 ms，138 帧），期间显示与帧率不受影响（无占位帧）；纹理显存增量约 1.4 GB（9 个档位 × 五个状态键 × 身体与装备两层的全部序列帧图集，两种预算下一致；贴图数 +544），预热完成后常驻。因此默认 `None`，只建议对确实需要"首次转向也不发硬"的少数外形（如玩家单位）预热。

## 后果

### 正面

- 冷转向期间整个实体保持旧方向的完整外观，提交后同一帧整体切到新方向；不再有新旧混搭、占位图。
- 需要首次转向也不发硬的外形可预热（或选 `OnAttach`），之后转到任一方向当帧完成。
- 契约面纯加法：新增只读查询、预热调用、选项枚举；没有给任何既有签名追加可选参数。
- 去掉了纯方向变化时的整体重探测，换向路径全部走缓存命中。

### 负面 / 已知限制

- 冷转向的保持时间 = 新方向"当前显示所需"资源（静态层图 + 运动态与当前状态的剪辑）里最慢的一项加载完成的时间；
  没有超时，加载失败按"缺失"算结论。同一真实外形（16 方向、五个声明的状态键、身体 + 装备层）实测：预算 4 ms
  时冷转向保持 14～21 帧（240～350 ms），预算 8 ms 时 9～14 帧（155～240 ms），保持期间没有占位帧、没有混合帧；
  要消除等待用预热。热转向 0 帧，预热后首次转向 0 帧。
- 提交后首次进入尚未就绪的非运动态状态（如冷转向后马上攻击）时，该状态的逐层剪辑在后台加载期间，各层显示新方向
  静态图（不是动画），加载完成后接上；要避免这一段静态显示，用预热。
- **首次显示与换装不是原子的**：首次显示与换装那一刻，层图先以占位图出现，同一真实外形实测 1～3 帧（约 17～100 ms，60 Hz，随加载器预算与磁盘缓存冷热浮动）后被真图替换；此后的方向准备/预热不受影响。
- 被放弃的目标方向的在途加载不取消（占用一部分加载带宽，结果进缓存供之后使用）。
- 预热的让路只发生在档位之间；一个档位内已发起的加载不会因转向而暂停。
- 整身兜底渲染器方向不变量只对有纸娃娃层的外形生效。
- 初始方向的整身方向变体美术（`<剪辑>__<方向>`）不在挂接时探测，首次换向之后才会被探测——这是本 ADR 之前
  就有的行为，本 ADR 没有改变，仅在调查中确认。
- `DirectionSlotChanged` 触发时机变化：订阅方若依赖"期望方向一变就通知"需要改用只读的期望方向查询。
