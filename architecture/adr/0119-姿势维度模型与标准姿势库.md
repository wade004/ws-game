# ADR-0119 姿势维度模型与标准姿势库

状态：已拍板 2026-10-01

## 背景

用户要求走路、跑步、战斗、各武器的姿势区分开，并由框架准备多种姿势供游戏直接用或在模板上改。现状：动画状态机七个状态键加两个补丁（`combat_` 前缀表示战斗姿态，ADR-0111；武器表现档案覆盖攻击/施法剪辑），走路与跑步不区分，再叠补丁会失控；框架不能出具体游戏画风的最终美术，但可以出模型、规格与中性资产。

## 决策

1. **姿势维度模型**：状态（既有七个，不增减）× 步态（walk/run/sprint，仅 move）× 姿态（peace/combat）× 武器族（`feel.weapon.family` 自由集合）× 变体（游戏层扩展）。性别与体型不是维度，是整套姿势集的选择。
2. **剪辑键语法与回落链**：`<state>[.<gait>][.<stance>][.<family>][.<variant>]` 固定顺序；找不到时按"去变体 → 去武器族 → 去姿态 → 去步态 → 基础键"回落；`combat_<state>` 恒等于 `<state>.combat`（单处别名，旧数据不改）；武器表现档案与技能覆盖剪辑优先级仍最高。`hit` 按裁决结果加后缀回落到 `hit`。解析时机与就绪规则沿 ADR-0111 同一出口。
3. **步态由表现层派生**：逻辑层无步态；按速度比例与滞回派生；播放速率按剪辑每循环位移匹配地面速度。
4. **标准姿势清单**分必备/推荐/可选三级：必备缺项校验错误不能发布；推荐缺项警告进完整性报告并按回落链兜底；可选静默回落。启停过渡为过渡剪辑，不是状态。
5. **动作规格**随 14 资产规格书模板发布：循环、关键姿势、参考时长与帧数、每循环位移、时间标记、方向档、锚点、元数据；是美术验收标准与手感相对量的依据。
6. **时间标记唯一权威**：判定类标记以 `skill.def.timeline.source` 决定作者态权威并在数据构建阶段抄写，运行期规则层只读 `timeline`、表现层只读剪辑；表现类标记（脚步、拖尾、特效挂点、受击冲击帧）只在剪辑；速率变化两边用同一系数，跨帧标记按区间遍历不重不漏。
7. **标准资产为框架资产**：`model` 型出标准人形骨骼定义与全清单剪辑库（按体量分组）；`sprite` 型出中性像素密度的假人姿势集（全键、全方向档、标记齐全）；姿势集 id 以 `display.anim_set.std_` 开头随版本发布。预渲染管线（标准骨骼加蒙皮生成序列帧）列为后续项。
8. **姿势集继承**：`display.anim_set.extends` 只覆盖要换的键，链无环；性别/种族在游戏层映射为"选哪套姿势集 + 选哪个体型原型"。
9. **导入校验与完整性报告**：必备键、标记齐全、循环一致、标记与 `timeline` 一致（错误/警告按权威来源）、位移与时长容差、`model`/`sprite` 各自的几何检查；报告不入库。
10. **姿势与手感对齐测试**作为发版门槛：剪辑长度 × 分相比例落在原型范围内、`hit` 在判定相内、脚步间隔与步幅一致、回落链枚举、继承等价。

## 后果

### 正面

- 走/跑/战斗/各武器的姿势差异有一个解析规则而不是一堆补丁；老数据零改动。
- 新游戏用假人第一天就能调手感、跑测试，美术按规格逐键替换；标准骨骼游戏换蒙皮即得全部姿势。
- 指纹基线与美术无关。

### 负面

- 标准骨骼剪辑库与假人集是持续维护的美术资产，随姿势清单变化要同步。
- 序列帧游戏仍要自己画全部帧（规格约束了帧数与标记，但不减少绘制量），预渲染管线做出来之前这是主要成本。

## 备选方案与为什么不选

- **继续加前缀补丁**（`run_`、`2h_`…）：组合爆炸且无回落规则；否决。
- **步态作为新 `AnimState`**：波及全部按状态遍历的调用点，且逻辑层不该知道步态；否决。
- **性别作为键维度**：把游戏层标签带进框架；否决，改为姿势集选择。
- **不出资产只出规格**：新游戏仍要先做美术才能调手感，达不到"直接用"；否决。

## 魔兽世界的对应做法

魔兽的动画集按"状态 + 武器持握类型（单手/双手/远程/法杖…）+ 战斗待机"命名，行走与奔跑分开剪辑并按速度切换。本架构的维度模型与之对应，多出步态派生、回落链与继承机制。
