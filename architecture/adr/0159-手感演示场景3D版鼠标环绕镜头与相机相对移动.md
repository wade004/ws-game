# ADR-0159 手感演示场景 3D 版：鼠标环绕镜头与相机相对移动

状态：已拍板 2026-10-06（承接 [ADR-0158](0158-手感演示场景3D版真实模型与模型包装配.md) 的 3D 演示场景与 [ADR-0135](0135-相机相对控制空间与可选相机俯仰透视.md) 的相机相对控制空间；框架契约无变化，改动全部在试玩宿主一侧）。

## 背景

3D 演示场景的镜头是固定俯角、固定偏航：真实骨骼模型只能从一个方向看，评手感时看不到背面与侧面，也没有第三人称游戏里"转镜头、移动跟着镜头走"的体验。框架早已提供相机朝向查询接口（`ICameraOrientation`）与输入映射的 `camera_relative` 控制空间（ADR-0135），但还没有一个游戏式的宿主把它们真正连起来用。试玩宿主在这里扮演"游戏"：要不要让玩家转镜头、转多少，是游戏自己的事，不是框架默认。

## 决策

1. **操作**：右键按住水平拖动 = 偏航（无上下限，可以转任意圈）；垂直拖动 = 俯角偏移，夹在默认俯角上下一个区间内，绝对俯角再夹进一个安全区间；滚轮 = 缩放，夹在最近与最远之间。鼠标在展开的调试面板上时，滚轮与右键拖动归面板，不转镜头。区间与灵敏度是 `OrbitCameraOptions` 的缺省，宿主可改。
2. **平滑且确定**：鼠标只改控制器的目标值，当前值按真实帧间隔指数逼近目标（时间常数 0.06 秒），只依赖帧间隔与输入序列，不依赖墙钟。画面上的相机每个控制器帧跟着转；逻辑侧不读画面。
3. **偏航与模拟步对齐（不新开旁路）**：输入映射每次更新都读相机朝向查询的偏航，所以同一个固定步内偏航必须不变。控制器偏航变化时，宿主向会话注入一个脚本标记 `camera_yaw`（`Value.X` = 偏航度），舞台在固定步边界上应用它，把偏航"提交"给相机；相机在打开"提交取样"后，`YawRadians` 只报最近一次提交的值，画面偏航可以逐帧平滑转。偏航因此进了会话脚本，同一局可按步复现同样的移动方向。
4. **框架接口的接线（无实验室专用旁路）**：舞台上那台真实相机实现 `ICameraOrientation`，宿主构造输入映射时把它作为相机朝向查询交出，与生产装配（`PresentationAssembly` 在移动动作声明 `camera_relative` 且相机实现了该接口时的做法）同一路径。宿主只做只读的三向检验（相机右/上轴、偏航公式、回到屏幕），不自己换算。
5. **声明走演示场景自己的选项，不改框架缺省，也不改格子数据**：宿主选项 `ControlSpaceOverride = camera_relative`，只在 3D 演示场景里设；`3d_action` 格子数据与框架缺省仍是 `world`。声明 `camera_relative` 而没有偏航来源仍在声明期报错（沿用 ADR-0135 决策 4），有回归用例。
6. **F1 面板开关"镜头：固定 / 鼠标环绕"**：3D 演示场景缺省"鼠标环绕"。"固定"= 此前的行为：姿态逐位复位到缺省、鼠标与滚轮被忽略、偏航恒 0（相机相对换算是恒等变换，ADR-0135 决策 3），逻辑指纹与原 3D 试玩场景逐字节一致；切回"固定"时位置、旋转、视场、缩放逐位还原。面板另有"复位镜头"按钮（平滑回到缺省）与一行操作提示（右键拖动转镜头、滚轮缩放）。
7. **旋转下的画面一致性**：①直立道具、命中火花、挥砍拖影、尘土都是广告牌，每帧按相机当前姿态重新定向与摆点（挥砍拖影的屏幕角由地面朝向按当前相机重算）；②遮挡次序不再按世界 Y 排，而是按"沿相机屏幕上方向在地面上的深度"排（细分档），墙面贴花恒低于广告牌；固定镜头仍用原公式；③血条、名字、飘字用相机投影定位，点转到相机背后时隐藏，不画镜像位置；④地面砖在环绕可用时铺得更大，保证俯角上限与最大拉远下视口四角都落在地面上；⑤模型站姿不受影响（头顶恒朝世界 -Z）。
8. **只改呈现与宿主输入，不改逻辑**：不新增数据行、不改任何基线。固定模式、偏航 0 的环绕模式的逻辑指纹与原 3D 试玩场景逐字节一致，有用例。

## 已知限制

- 偏航进了会话脚本，但俯角偏移与缩放是纯呈现，不录入脚本：回放只复现偏航（移动方向），不复现俯角与缩放。
- 控制空间是宿主在运行时的声明，脚本本身只带 `camera_yaw` 展示标记：已存成本地脚本的环绕会话，在无头命令行或不带环绕镜头的宿主里按脚本重放时，移动轴按格子数据的 `world` 解释，偏航不为 0 的会话在那里不能逐位复现逻辑。需要跨宿主复现，要让脚本带控制空间声明，属于后续实验室内核的工作，本决策不做。（已由 [ADR-0161](0161-自由第三人称镜头俯仰范围声明焦点高度地面避让与脚本携带控制空间.md) 补上：脚本 meta 携带 `controlSpace` 声明，偏航流进脚本，任何宿主逐位复现。）
- 非 3D 演示场景（原 3D 试玩场景、2D、2.5D）不装环绕镜头。

## 不做的事

- 不改框架契约（`ICameraOrientation`、输入映射、控制空间枚举均不动），不改框架缺省。
- 不加相机碰撞、跟随平滑、镜头锁定目标等游戏性镜头功能。
- 不为演示场景新增数据行或基线。

## 后果

### 正面

- 3D 手感可以从任意方向看，评击退、倒地、挥砍的背面与侧面表现；框架的相机相对控制空间首次在一个完整的游戏式宿主里端到端跑通（鼠标 → 偏航 → 输入映射 → 世界移动方向 → 屏幕上方）。
- 偏航按固定步提交并进脚本，移动方向可复现、可测。

### 负面

- 环绕可用时地面砖更大（约 11 倍面积），首次进入场景多一点网格构建时间。
- 已知限制中的跨宿主回放缺口要等脚本携带控制空间声明才能补上。
