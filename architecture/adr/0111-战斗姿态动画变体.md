# ADR-0111 战斗姿态动画变体（战斗待机）

状态：已拍板 2026-09-30

## 背景

消费方第六十一批反馈：单位进入战斗后应切换到"战斗待机"动画，脱战后切回普通待机；装备层要跟着身体走
（纸娃娃逐层剪辑机制，ADR-0072/0100）。此前表现层的动画状态机不认识战斗：`combat.entered`/`combat.left`
事件没有任何表现层订阅者，剪辑解析只查七个固定状态键，进战后身体层与装备层都停在普通待机那一套。
消费方明确不要在游戏侧自建"监听战斗事件再手动换剪辑"的旁路（会绕开逐层剪辑的探测、换向重探测、换装重探测
这些既有机制，装备层必然对不上）。

## 决策

1. **不新增 `AnimState` 成员**：战斗姿态是与 `AnimState` 正交的布尔维度。新增状态会波及全部按状态
   遍历的调用点、优先级表与既有数据；正交维度只影响"同一个状态选哪条剪辑"。
2. **剪辑键变体约定**：战斗姿态下状态 `<key>` 的默认剪辑先查 `combat_<key>`，没有就回落 `<key>`。
   适用全部七个状态键。前缀 `combat_` 只在一处定义（`AnimSetDef.CombatClipKeyPrefix`，`CombatClipKey`
   拼键）。优先级：武器风格/技能覆盖剪辑 > 变体键 > 基础键。循环与否跟随基础状态（`DefaultLoop`）。
   数据侧不新增 schema 字段：`display.anim_set.clips` 本就是自由键表，没有键白名单，声明了 `combat_*`
   键即生效，没声明的外形逐字节保持 1.89.0 行为。
3. **状态机记账**（`AnimStateMachine`，只维护姿态、不选剪辑）：订阅 `combat.entered`/`combat.left`
   （逻辑层每单位在真实迁移时各入队一次，读档不重发、销毁不发）；只读查询 `IsInCombatStance`；变化事件
   `CombatStanceChanged`（姿态没变不触发）；构造新增重载接受初始姿态探针 `Func<Id,bool>`，首次跟踪
   某实体时调用一次（生产装配接只读的 `ICombatHost.IsInCombat`），旧构造保留、初始恒非战斗；
   `Track` 显式登记；`Forget` 清除。由战斗事件首次创建记录的实体不问探针（迁移前姿态已知为事件值的反面，
   用探针当基线会把这次迁移误判为没变而吞掉）。
4. **切换时机**：Idle/Move 状态下，新姿态解析出的剪辑与最近实际播放的不同就立即切换并从头播；相同什么都不
   做（不重播、不打断时间轴）；从未播放过任何剪辑时基线取"不考虑变体的基础键剪辑"，因此没有变体键的外形
   永远不会被额外播放。Attack/Cast/Hit/Jump 期间姿态变化**不打断**，回落到运动态时按当时姿态解析；
   Death 终态不受影响。战斗中移动只查 `combat_move`，没有就回落 `move`，停下回到 `combat_idle`。
5. **冷加载与热路径同一结果**：变体剪辑内容（序列帧真实内容 + 逐层探测都结束）没到位时不切，维持当前
   显示；内容到位或探测结束时经同一个 `Refresh` 出口补切；期间已脱战则不切。已经在播的变体不因重探测期间
   就绪探针暂时为假而被踢回基础键（不闪）。变体内容永远不到位则一直维持当前显示（已知限制）。
6. **适配层接线点全部走同一张键表**（`AnimStateKeysFor`：基础键 + 外形实际声明的变体键）：默认剪辑登记、
   逐层探测、换向重探测、换装/合成层变化重探测、逐层缓存重登记；视图创建/重生时 `Track` + `Refresh`
   （创建时单位已在战中，初始即战斗待机）；销毁/重生/全量清理时清姿态与最近播放记账。model 型的默认剪辑表
   本就是 `anim_set` 全部键，变体键天然在表内，无需额外登记，就绪恒真。
7. **契约面纯加法**：状态机新增构造重载与成员；解析器新增构造重载（旧五参构造转调）与公开成员
   `Refresh`/`Forget`/`CombatStateKey`；`AnimSetDef` 新增常量与静态方法；视图工厂新增 `CombatProbe` 属性。
   没有给任何既有签名追加可选参数。

## 后果

### 正面

- 进战/脱战/移动/攻击/换向/换装/读档后视图创建这些路径都由同一个解析出口处理，装备层经逐层剪辑机制自然跟随。
- 没有 `combat_*` 键的外形零行为变化、零额外重播。
- 没有新 schema 字段、没有新事件、没有新 `AnimState`。

### 负面 / 已知限制

- 声明了变体键却没有对应美术时永远维持当前显示，没有超时回落，也没有专门诊断。
- 武器风格/技能覆盖剪辑不感知姿态（优先级更高，原样播放）；要区分战斗/非战斗请用 `combat_attack`/
  `combat_cast` 变体键。
- `jump` 不在默认登记的六个状态键里（既有行为），`combat_jump` 仅在外形声明且外部登记了剪辑时才可能生效。
- 生产装配入口需要把 `CombatProbe` 接到 `ICombatHost.IsInCombat`：框架自带的三个装配入口（引导、常驻宿主、
  游戏模板）已接；游戏自己写装配入口的需要照抄这一行，否则读档/重生/进入视野时已在战中的单位初始姿态为
  非战斗，直到下一次事件才对齐。

## 验证

适配层复现用例（生产装配级：真实事件总线 + 视图工厂 + 渲染器 + 加载器，纸娃娃身体层 + 武器装备层，
自造夹具）与不变量用例（六个分支 + 解析层）、状态机记账三条用例。复现用例在 1.89.0 上红：进战后身体层
应用的仍是普通待机那一套。
