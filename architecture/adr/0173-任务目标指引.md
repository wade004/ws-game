# ADR-0173 任务目标指引（引导步骤、目标位置与跨地图寻路）

状态：已拍板 2026-10-09（来源：样板游戏 A 试玩反馈——接了主线任务后玩家不知道该清哪个房间、楼梯在哪、是否已开启；纯加法，不声明 `guide` 时行为逐位不变）

## 背景

08 第 2.3 节早已要求逻辑层"只暴露当前激活目标的位置查询接口"，但一直没有实现：任务只有"目标进度"，没有"下一步去哪里"。多地图、分阶段的任务（先清若干房间、再下楼、再打首领、最后回去交任务）里，玩家拿不到任何方向信息，游戏层想自己做就得把"每个阶段指向哪里"硬编码进游戏代码，各游戏各写一套。

## 决策

1. **`quest.def` 新增可选字段 `guide`（步骤数组）与 `guide_priority`（整数，缺省 0）**。不声明 `guide` 的任务不参与指引，行为逐位不变；没有任何任务声明时 `QuestGuideHost.HasAnyGuide` 为假、`Evaluate` 恒返回空——缺省关闭靠数据决定，不设全局开关。
2. **步骤 `guide[]`**：`map_id`（可选：只在玩家当前处于该地图时适用，用来写随所在地图变化的文案）、`when`（Expr，缺省恒真）、`text_key`（文案键，文案可含 `{done}`/`{total}` 占位符）、`targets[]`（目标，可空：只显示文案）、`progress_flags[]`（世界标志 id 列表：已成立个数/总数即进度）。
3. **目标 `targets[]`** 三种写法恰好选一种：`area_ref`（`area.trigger_def`，取形状中心）、`spawn_ref`（`spawn.table`，取刷新点位置）、`map_id` + `position`（字面坐标）；另有可选 `visible_if`（Expr，为假则本次不参与候选，例如"尚未清理的房间"）。校验检查名 `quest_guide_target_form`；引用目标走通用引用完整性检查。
4. **求值口径**：`QuestGuideHost.Evaluate(unitId, mapId, position)` 现算、无状态、不订阅事件。任务按 `guide_priority` 降序（同值保持定义顺序），步骤按数组顺序，取第一条"`map_id`（若声明）等于玩家当前地图、`when` 为真且（没有目标，或至少一个目标可见且可达）"的步骤。同一步骤多个目标取"跳数最少，再取离玩家最近"。
5. **跨地图寻路**：目标不在玩家当前地图时，沿数据里 `trigger_type = map_transition` 且当前开着（`condition` 求值为真）的触发区做广度优先搜索，箭头指向路径上第一条通道的形状中心（`QuestGuideTarget.ViaTransitionId` 记录是哪条）。搜不到路径视为不可达，该步骤被跳过——通道关着时指引自然落到下一步。这不是导航网格寻路：同地图内只给直线方向。
6. **契约面**：`QuestGuideHost`（`Core.Gameplay.Quest`）、`IQuestGuideLocator`（把数据行引用解析成落点，组装层默认实现 `RegistryQuestGuideLocator` 读数据注册表）、`QuestGuideInfo`（命中的任务/步骤/文案键/进度/目标，`FormatText` 代入占位符）。`GameplayAssembly` 新增只读属性 `QuestGuide` 与 `QuestGuideLocator`。`QuestHost` 新增只读属性 `Definitions`；**不修改 `IQuestHost`**（接口加成员会破坏既有假实现），`QuestDefinition` 以新增构造重载承载新字段，既有构造签名不变。
7. **表现层**：引擎适配层提供可复用的屏幕边缘引导箭头控件（纯数学部分与控件分离、可单测），游戏层每帧把 `Evaluate` 的结果交给它；不接入的游戏不会出现任何箭头。

## 后果

- 新增数据字段与只读查询，纯加法；老数据、老接口、老存档不受影响（指引不持有运行期状态，无需存档）。
- 游戏作者把"分阶段做什么、指向哪里"写进数据，HUD 文案与箭头目标都由数据决定，不再硬编码进代码。

## 限制（已知）

1. 同地图内不做寻路，只给直线方向；墙体绕行由玩家自己判断。
2. 引导步骤的 `when` 只读任务与世界状态等既有 Expr 分组，不引入新分组。
3. 通道关闭条件只认 `area.trigger_def.condition`；由脚本或事件临时封路的通道不被识别。

## 备选方案与为什么不选

- **在任务目标（`objectives[]`）上直接挂位置。** 目标是"杀什么/收集什么"的进度判据，一个目标会对应多个房间、阶段又不止由目标进度决定（清房间由世界标志驱动），语义对不上。
- **游戏层自己写阶段到位置的映射。** 即现状，各游戏重复且无法用数据校验引用完整性。
