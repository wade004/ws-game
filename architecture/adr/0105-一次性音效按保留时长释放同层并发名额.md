# ADR-0105 一次性音效按保留时长释放同层并发名额

状态：已拍板 2026-09-27

## 背景

消费方第五十四批反馈（在 1.84.0 冻结提交上黑盒排查）：同一次普通攻击内先后发布"挥出普通攻击"与
"造成伤害"两个事件（相差约 2 毫秒），分别驱动两条 `play_sfx` 规则，两个音效同属一个分层音效轨道，
挥击音效优先级低于命中音效。命中音效稳定可闻，挥击音效始终观测不到；事件发布、条件求值、资源加载、
单调累计播放诊断（ADR-0083）均正常，`PlayRequestedCount == PlayStartedCount`、`PlayDroppedCount == 0`。

框架内部复现（生产装配 + 真实表现绑定 + 真实音效播放器 + 桩音频后端）定位根因：音效播放器按层维护
"当前在播实例"记账，用于执行同层并发上限与按优先级抢占；但引擎适配层的音频契约没有"某个播放句柄
是否已经播完"的查询，记账只在显式停止或被抢占时释放。已经自然播完的一次性音效永久占着名额，一个层
累计播放满上限次之后就"永远满员"，此后每一次播放都要抢占一个名额——同层里优先级最低的新音效（挥击）
会被几毫秒后到来的更高优先级音效（命中）选为被抢占者，当场停止。抢占停止一个已经开始的播放不属于
"丢弃"，所以播放诊断计数完全正常；"最近一次播放"记录在同一帧内被命中音效覆盖，逐帧轮询也永远看不到
挥击音效。层内是否恰好还残留更早的、同为最低优先级的陈旧记账（例如其它单位的挥击音效），决定这一次
被停掉的是陈旧记账还是刚开始的挥击音效——这解释了消费方观测到的"间歇性"。

## 决策

1. **一次性音效只在保留时长内占用层名额**：音效播放器的可配置项新增"一次性音效层名额保留时长"
   （可选属性，默认 2 秒）。非循环音效从真正开始播放（含首次冷加载完成后的补播放，取补播放那一刻）
   起，占满该时长后视为已自然播完，从层记账中释放，不再参与并发上限计数与抢占候选。
2. **释放只摘记账，不发停止指令**：到期只是"推定已播完"；若实际仍在播（比保留时长更长的一次性
   音效），不会被掐断。之后对该句柄的显式停止照常转发到引擎适配层。
3. **计时用表现层逐帧维护入口传入的时间增量累加**：生产装配已经逐帧驱动音效播放器的维护入口，
   播放器自行累加时间增量作为表现时钟，不读系统时间，保持确定性；从未驱动维护入口时不会到期，
   行为与本决策之前一致。
4. **循环音效不受影响**：显式停止前一直占名额，照原规则参与抢占。
5. **保留时长内真正并发的超限播放仍按原规则抢占**：层满时停掉层内优先级最低者，同优先级停最早者，
   规则本身不变；取值 ≤ 0 表示不按时长释放（回到本决策之前的行为）。

## 后果

### 正面

- 同层"低优先级音效后紧跟高优先级音效"的常见组合（挥击后命中、施法后命中）不再在长时间运行后
  把低优先级音效当场掐掉；并发上限回到它本来的含义——限制"真正可能同时在播"的实例数。
- 纯新增可配置项，公开签名不变；单调累计播放诊断（ADR-0083）的三个计数语义不变（到期释放与抢占
  停止都不计入丢弃）。

### 负面（已知限制）

- 保留时长是"推定已播完"，不是引擎回报的真实播完时刻：比保留时长更长的一次性音效在尾段不再计数，
  该层上限在尾段变松（可能多出若干条重叠播放，但不会提前停止任何音效）；比保留时长短得多的音效在
  播完之后、到期之前仍占名额，高密度同层播放下仍可能触发抢占（这是上限本身的正常语义，可调大上限
  或调小保留时长）。
- 依赖逐帧维护入口被驱动；不驱动时名额不会按时间释放，退回原行为。

## 备选方案与为什么不选

- **给音频契约新增"句柄是否仍在播"查询，由引擎适配层回报真实播完**：最精确，但需要每个引擎适配层
  同步实现；默认实现只能回答"未知"，未跟改的适配层等于没修。可作为后续增强与本决策并存（有真实
  回报时优先用真实回报），本轮不做。
- **同优先级不抢占仍在起音的实例 / 新开始的实例一律免于被抢占**：本案两个音效优先级不同，前者无效；
  后者会让刚开始的低优先级一次性音效反过来挤掉仍在播的高优先级循环音效，破坏优先级语义，不选。
- **按系统时间计时**：不确定、测试需真实等待，且与表现层已有的逐帧维护入口重复，不选。
