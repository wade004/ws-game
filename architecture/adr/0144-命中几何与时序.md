# ADR-0144 命中几何与时序

状态：已拍板 2026-10-04（对 [ADR-0114](0114-技能结算新增时间线模式.md)、[ADR-0117](0117-局部顿帧作为判定型手感.md)、[ADR-0128](0128-单位间体积阻挡.md)、[ADR-0130](0130-竖直轴能力包.md) 的补充；手感设计/03 第 2 节与 05 第 3 节落地后审计发现的命中几何与时序缺口）

## 背景

时间线空间命中落地之后，下面几处缺口在审计里被点名：

1. 命中把目标当一个点：形状只要没盖住目标中心就算没打中，身体很大的目标被擦到却"打空"，接触点也落在目标体内。目标选择宿主早有可选的"目标半径来源"，但生产装配没有接上，档案里的单位体积半径也没有进入命中。
2. 无敌窗口的前置检查只在时间线与时间线投射物两条路径里各写了一份；目标选择式、范围效果、非时间线投射物对无敌目标照常结算，同一个无敌窗口在不同命中路径上效果不一致。文档第 2.2 节还写着"额外排除无敌目标"，与第 2.3 节"判为回避并发事件"互相矛盾。
3. 法术等没有动作时间线的技能没有地方声明手感引用：`impact_class` 只能取武器，文档第 5 节写着"由技能的 `feel_ref` 覆盖"，数据里却没有这个字段。
4. 多段与蓄力没有各自的手感：多段技能所有段共用动作开始快照，最后一击不能更重；蓄力只缩放效果值，不缩放顿帧与击退。
5. 声明了 `ground_target` 的技能被地面坐标施法请求施放时，`timeline` 被静默忽略（只给一条警告），落点技能没法用动作时间线与空间命中。
6. 文档整理：扫掠接口、采样步长、命中路径选择、空战相关字段在 03 里没有交代，文档写的"适配层声明扫掠能力时用扫掠查询"与实现（一律子采样）不符。

## 决策

1. **目标的受击半径 = 单位体积半径 × `hurt_radius_scale`**。`hurt_radius_scale` 是受击组的可选判定型字段（范围 0～4，缺省无值即 1，只允许 `set`）；单位体积半径沿用 [ADR-0128](0128-单位间体积阻挡.md) 的 `unit_body_radius`（标定后的世界单位），没有声明体积半径的单位受击半径恒为 0，仍按点判定。命中形状与该圆相交即命中，接触点取目标圆面上朝向形状的点（目标中心已在形状内时朝向攻击方），接触法线随之改为从目标中心指向该点，不再落在体内。理由：体积半径已经是档案里的"这个单位有多大"，另起一套命中半径会让同一个单位有两个大小；倍数字段让体型相同的单位可以有"好打/难打"的差别而不动体积阻挡。
2. **受击半径来源的生产接线做成装配选项，缺省关闭**（`HitRadiusFromFeel`）。理由：打开会让擦边的目标从没打中变成打中，既有命中结果因此改变；缺省不变是手感体系的总约束，由游戏在装配根显式打开。广相位上界不再是装配时的静态常数，而由目标选择宿主每次查询时从提供者读取最大受击半径——半径来自档案，换装与光环会改变它，静态上界会漏判。
3. **无敌窗口前置检查上移为结算管线第 0 步**，所有命中路径共享，伤害类结算在无敌窗口内判为回避（`Invulnerable`），发布回避事件，不进命中表、不落地、不进战。不拦治疗、周期性结算、光环来源结算与自伤；技能行可声明 `ignores_invulnerability` 豁免（环境伤害、斩杀等）。时间线路径在构造批次时的前置过滤保留，使整批效果对无敌目标都不执行、确认事件与同批其它目标同时到达；第 0 步是它之后的第二道门。无敌窗口只有时间线动作才会产生，没有这类动作的数据里第 0 步恒为假，既有结算与实验室全部既有基线逐位不变。理由：同一个无敌窗口在所有命中路径上应当同一个结果；检查放在管线里一处，而不是每条路径各抄一份。文档 2.2 节"额外排除无敌目标"更正为"无敌目标留在命中集合里、由第 0 步判回避"，消除与 2.3 节的矛盾。
4. **技能行可声明 `feel_ref`（手感行引用），优先级 技能 > 武器 > 角色**。落点就是 05 的第 6 层"当前动作"，它本来就高于武器层（4）与角色层（5），按字段逐个覆盖——不新增解析层。时间线技能与 `timeline.feel_ref` 等价（同时声明且不同是加载期错误）；非时间线技能命中时由受击裁决据此以该行为动作层重算攻击方视图。未声明时逐位等于现状（按武器）。理由：法术的冲击等级与顿帧本来就该由法术自己定，不该借武器；落在已有的层里，解析器、溯源、热加载都不用改。
5. **多段与蓄力各自的手感**：`hit`/`release` 标记可带 `args.feel_ref`，在动作层之上再叠一行覆盖该段命中的攻击方视图（命中那一刻重算；落地阶段的击退、击飞也读它）；蓄力动作可声明 `charge.feel_scale`，按蓄力比例对攻击方顿帧、受击方顿帧、击退距离、击飞高度各自线性缩放（顿帧缩放在换算 tick 与上限限幅之前乘）。理由：多段技能的收尾一击更重、蓄满更猛是动作手感的基本需求，拆成多个技能会破坏取消、连招与攻击实例语义。
6. **落点技能可声明 `timeline.hit_anchor`**（`caster`｜`ground_point`），声明后经地面坐标施法请求施放时进入时间线，命中形状以攻击方位姿或落点（朝向取施放时刻攻击方指向落点的方向）为锚点；不声明保持既有行为——`timeline` 被忽略并给警告。理由：落点技能（陨落、地面法阵）也是"站位与朝向决定命中"的动作，缺了锚点语义只能退回读条结算。
7. **扫掠接口不设，`continuous` 一律子采样**（记录既有设计决定）：采样密度已保证相邻采样间位移不超过形状最窄尺寸的一半，上限只在单 tick 位移超过形状尺寸 128 倍时才咬合，那已是瞬移；为这种极端情形让所有适配层实现解析扫掠查询得不偿失。

## 后果

### 正面

- 命中几何有了"体积"：大个子被擦到会被打中，接触点与法线落在圆面上，反馈的击中位置与方向更贴近画面。
- 无敌窗口在所有命中路径上一个口径；技能声明 `ignores_invulnerability` 即可绕开。
- 法术、多段、蓄力有了各自的手感落点，全部可选、未声明逐位不变，没有新增解析层。
- 落点技能能使用动作时间线与空间命中。
- 全部是加法：新增可选字段（受击组一项、技能行两项、时间线与标记各一项）、新增重载与默认接口成员、新增装配选项；schema 版本不动（[ADR-0039](0039-内容数据schema破坏性变更政策.md) 的加法政策）。

### 负面

- 默认接口成员的缺省实现退回旧口径：自带的判定型来源或目标选择宿主替身若没有实现新成员，新声明会被静默忽略（框架内全部生产实现都已实现）。
- 打开 `HitRadiusFromFeel` 后每次目标选择查询对全部单位取一遍受击半径，单位很多时有成本；它是可选开启的，上界提供者的结果没有缓存。
- 调试覆盖层（第 8 层）高于第 6 层：对某字段写了全局调试覆盖时，技能行与分段行对该字段的声明同样被盖住，调参时容易误判成声明没生效。
- 分段覆盖视图在命中时刻重算，不是动作开始快照：它会反映动作开始之后才发生的光环与临时状态变化（只影响声明了分段覆盖的段）。
- 分段行叠加在动作层之上，行内与行间按"先 `set`、再 `multiply`、再 `add`"的层内顺序合成，所以分段行的 `set` 之后动作行的 `multiply` 仍会乘上去；想要"完全替换"需要在分段行里连同倍率一起写。
- 投射物的碰撞半径与目标受击半径是两条各自的路径，本决定不统一它们。
- 不经命中表的效果（光环施加、位移、召唤等）不受第 0 步约束。

## 备选方案与为什么不选

- **另设 `hit_radius` 字段**：同一个单位两个大小，且与体积阻挡脱节；否决，复用体积半径加倍数。
- **缺省就开受击半径**：改变既有命中结果；否决，装配选项缺省关闭。
- **每条命中路径各自检查无敌**：已经是现状，出现了不一致；否决，管线里一处。
- **无敌检查放进目标选择链的过滤**：回避事件与确认事件需要知道"本来会命中"，过滤掉了就没有可发的事件；否决。
- **给技能行单设一层"技能层"**：第 6 层已经高于武器与角色；新增层要改解析器、溯源与热加载；否决。
- **蓄力缩放写进手感档案**：蓄力比例是动作实例的运行期量，档案是静态配置；否决，写在蓄力声明里。
- **落点技能缺省进入时间线**：改变既有 `ground_target` 技能的行为；否决，声明 `hit_anchor` 才进入。
- **加扫掠能力接口**：见决策 7；否决。

## 魔兽世界的对应做法

魔兽的近战判定是"目标在攻击者前方扇形与距离内"，距离按双方战斗触及半径之和算，等价于"命中形状与目标的体积圆相交"；法术的触发效果与武器攻击分开取各自的数据行。本框架保留数据驱动的形状与档案的分层覆盖，把"目标有多大"收回到档案的单位体积半径上。
