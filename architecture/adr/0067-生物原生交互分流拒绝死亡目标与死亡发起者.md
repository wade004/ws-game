# ADR-0067 生物原生交互分流拒绝死亡目标与死亡发起者

状态：已拍板 2026-09-22

## 背景

消费方反馈（游戏接入方第十批第 1 条）：ADR-0065 已经让"最近可交互目标"查询排除死亡生物，但生物
原生交互本身（生物交互宿主的 `Interact`，以及经 `interact` 意图走的生物交互分流处理器）不核对
目标是否存活。接入方有一条真实生产路径不经"最近可交互目标"查询：鼠标点选生物后按交互键，直接把
已知的生物实例 id 交给生物交互宿主发起交互——只要该生物运行期实体还留在世界模拟中（死亡不销毁
实体，见 ADR-0065 背景），这条路径就会受理，点中尸体也能打开对话。友方 `<game>` 内容里存在
"敌对守卫能把友方生物打死"这类场景，是真实玩法路径，不是测试环境的偶发问题。

ADR-0065"备选方案"倒数第二条曾记录：生物原生交互分流对死亡目标的现状行为"没有失败用例支撑"，
按当时任务边界不处理，留作已知现状记录。本次反馈提供了失败用例——上述直连生产路径——使该现状
从"未证实的遗留行为"变为已确认的缺陷，因此本决策在该分流上补齐存活核对；ADR-0065 该段记录已随本
决策改写为最终口径（见"影响既有文档"）。

交互发起者若已死亡（例如两个单位互相打死、或发起交互请求的单位在请求处理前的同一批结算中死亡）
同样不应该成功发起交互——死人不能和 NPC 对话，属于同一批需要补齐的存活核对。

## 决策

1. **生物交互宿主 `Interact` 对已死亡的目标生物拒绝**：存活判定用单位状态门面的"是否存在"×
   "是否存活"两个只读查询的合取，与 ADR-0061/0065 同一权威口径——不看生命值资源池是否 `<= 0`，
   理由同 ADR-0065 决策 1：资源池归零与规则层真正判定死亡（写入存活状态那一刻）不保证同一拍
   同步，另起一套阈值判断会制造与规则层结果不一致的时序窗口。

2. **交互发起者已死亡同样拒绝**：判定口径与决策 1 完全相同（同一个只读契约、同一对方法），不
   为发起者另设一套判定。

3. **判定所需的存活信息，走本层已经持有的依赖，不新增契约**：生物交互宿主构造时已经接收单位
   状态门面作为依赖（原本就需要它解析交互发起者的存在性与位置），本次改动直接复用同一个字段，
   不新增构造参数、不新增依赖注入点、不产生新的公开签名——与 ADR-0065 决策 3 同一处理方式。生产
   装配根构造生物交互宿主时已经把该依赖接了进去，不需要额外接线。

4. **`interact` 意图分流与直连调用共用同一判定**：`interact` 意图处理器本身就是把意图参数解析
   出目标 id 之后转调生物交互宿主的 `Interact`，两条路径天然走同一份判定代码，不需要、也不允许
   各写一份。

5. **失败原因新增两个取值，不复用"未知/无法识别"**：交互结果的失败原因枚举只追加成员——新增
   "目标已死亡""发起者已死亡"两个取值，与既有"未知/无法识别的实例或类型"取值区分开，调用方能
   分辨"目标 id 压根没登记"与"目标 id 有效但当前已死亡"这两种不同的失败原因。

6. **死亡判定不写诊断**：诊断出口是否记录取决于该失败原因是否属于正常游玩中随时会发生的瞬时
   状态。距离过远不写诊断的既有口径已经确立了这一判断标准——生物交互宿主对"超出交互距离"的既有
   处理正是"这是正常游玩中随时会发生的瞬时状态，不应该逐帧刷诊断"。玩家击杀一个生物后按交互键
   打在尸体上、或鼠标点选一个恰好在请求处理前死亡的目标，是同样正常的游玩操作，不是内容配置
   错误（内容错误的既有例子是"生物模板未配置对话菜单"，那种情况确实需要留诊断线索让内容制作方
   发现），因此按同一标准不写诊断。

## 后果

### 正面

- 接入方按键交互一个已死亡的生物不再意外打开对话——直连生产路径与经"最近可交互目标"查询两条
  路径现在对死亡生物的行为完全一致，不再有一条路径绕过另一条路径已经加固的存活核对。
- 死亡单位不能发起交互，与"死人不能和 NPC 对话"这一基本预期一致。
- 改动落在生物交互宿主内部已有的依赖范围之内，不新增契约、不新增可选参数、不产生新的公开签名
  变化（枚举只追加成员，不影响已有取值的数值），没有旧调用方需要跟着改。

### 负面

- 这是一次行为变更：本决策落地前，直连生物交互宿主对一个已知的死亡生物 id 发起交互会被受理
  （无对话配置判定为"无可交互内容"、有对话配置则打开对话）；落地后统一拒绝并返回"目标已死亡"。
  框架内经排查没有依赖"允许与死亡生物交互"这一行为的既有测试或流程（见"影响既有文档"排查
  结论）。
- 死亡生物、死亡发起者的交互能力从这条分流里完全消失，如果后续需要支持"对尸体做点什么"（拾荒、
  检查尸体一类），需要另起一条新的交互类别，不能通过放宽本次收窄的判定来实现——与 ADR-0065
  决策 2 同一取舍：候选/分流的既有含义不应该为极少数场景开洞，破坏默认安全的行为。

## 备选方案与为什么不选

- **只加固"最近可交互目标"查询，不改分流本身**：这正是 ADR-0065 当时的选择，理由是彼时没有
  失败用例支撑。本次反馈提供了绕过查询、直连分流的真实生产路径，前提条件已经不成立，故不再
  适用，改为在分流上补齐。
- **给分流的交互方法加一个"是否允许死亡目标"的可选参数**：与 ADR-0065 备选方案第一条同一取舍
  ——把判断转嫁给每个调用点，默认值若不安全则每个新接入方都要重新踩坑；默认值若安全（默认拒绝）
  则这个参数形同虚设，不如没有。故不选。
- **失败原因复用既有"未知/无法识别"取值，不新增枚举成员**：能省一次枚举扩容，但会让调用方无法
  区分"目标 id 根本没登记"（提示排查内容配置或调用方传参）与"目标 id 有效、只是当前死了"（提示
  这是正常游玩瞬时状态，重试或提示玩家）——这两类失败对调用方的后续处理路径完全不同，合并成
  一个取值是把区分度让给了调用方自己再猜一遍。故不选。

## 魔兽世界的对应做法

无直接对应（这是本框架生物原生交互分流与生物死亡后运行期实体保留机制两者组合出的一处结构性
缺口修复，与 ADR-0065 属于同一根因的两处不同表现，不对应魔兽世界任何具体游戏系统设计）。
