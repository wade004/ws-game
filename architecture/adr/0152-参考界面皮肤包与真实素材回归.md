# ADR-0152 参考界面皮肤包与真实素材回归：真实美术走一遍皮肤、图标、纸娃娃链路

状态：已拍板 2026-10-04（落实 [手感设计/08](../手感设计/08_装备与UI资产契约.md) 第 3、4 节，续 [ADR-0149](0149-装备面板与界面资源契约清单.md)；只加不改；2026-10-04 第二轮追加决策 7～11，决策 5 的遗留由决策 8 拍板）

## 背景

ADR-0149 的皮肤契约清单、导入校验、引擎侧完整性用例此前只在"程序生成的占位皮肤"与"纯色替换皮肤"上验证过。程序生成的素材总是规整的：同尺寸、对称、alpha 干净、令牌与像素天然一致。真实美术（出图工具产出再后处理）才会带来脏 alpha 底噪、横竖边粗细不一、状态图轮廓错位、令牌与边框像素不符等问题，这些问题如果等到具体游戏接入时才第一次出现，代价最高。

## 决策

1. **新增一套独立的参考皮肤包（通用奇幻风）**，放在 `assets/_reference_fantasy/`：皮肤包 `ui/skin/reference_fantasy/`（清单全部元素，含全部可选项：8 个槽位框 + 兜底 + 五态、五档品质框、拖拽三态、提示框三件、预览区背景、面板九宫格、按钮五态、主题）、样例装备的图标与纸娃娃静态层图。它是样例包：不替换占位皮肤，不进缺省行为，不进任何内容同步或发布打包，既有基线与数据集哈希不动。
2. **素材只用本地出图流程生成，生成过程可复现**：提示词、种子、后处理脚本（缩放在预乘 alpha 空间做、去紫边、脏 alpha 清零、四向与对角对称化、九宫格由确定性装配保证边框像素等于主题令牌、状态图由同一底图派生以保证轮廓逐像素对齐）入库在 `assets/_reference_fantasy/_source/`；原始大图与中间产物只留本地，不入库；门禁不跑这些脚本，只守产物。
3. **回归用例守住"真实美术过链路"**：导入校验对参考包零错误零警告、可选缺失为空，且包内文件恰好是清单展开的全集（含 8 槽位 × 5 品质的扩展口径）；真实美术才有的不变量（脏 alpha、格子组同尺寸、九宫格边框与令牌、边带沿拉伸方向恒定、按钮五态轮廓对齐）与各自的反例；真实形态的负例（非正方形、品质框盖住图标、中心区 alpha 底噪、不透明化的槽位框、令牌过大、缺状态、截断的图、非 2 的幂/无 alpha/贴边/全透明图标、不透明的静态层）逐个只破坏一处并断言命中对应的具名诊断。引擎侧用例换成参考包：逐元素读回像素与包内文件一致、0 回落、主题颜色读回、真实装备面板/背包面板/衣橱场景/拼图零异常。
4. **走这条链路发现的框架缺陷在本切片内修复并带复现用例**：
   - 图标没有透明像素（不透明底、无 alpha 通道）被报成"主体贴边"，误导修图方向；现在单独说明"没有任何透明像素"，贴边的报告给出包围盒与图像尺寸。
   - 品质框中心区"不是全透明"只给结论；出图模型常在透明处留肉眼不可见的 alpha 1~9 底噪，现在报最大 alpha 与首个像素位置。
   - 布局的 `cell_size` 为 0 按契约取皮肤包槽位框原生宽度，装备面板照办，背包面板却当成缺省 32 px；两个面板现在共用同一处解析。
   - 背包面板的物品格不认 `cell_size`：竖直列表不控制行高、横向布局不控宽，格子按矩形缺省 100 x 100 画出，面板放不下三行；带皮肤的重载现在显式设定行高与格子尺寸（无皮肤的文字行保持原样）。
   - 实验室换装场景写死占位皮肤，装备面板与衣橱在实验室里看不到真皮肤包；场景新增可选的皮肤引用（缺省仍是占位皮肤，行为不变）。
5. **纸娃娃静态层的对位**：预览区把装备静态层与身体静态层按画布中心叠放，框架不读锚点对位，契约也没有规定两者的画布关系；占位层图是 144 画布里脚底对齐的动画帧几何，叠到 64 x 96 的身体上整体偏下（占位美术自己的预览就是偏的）。参考包的层图按身体几何摆放（躯干中心、手锚点）使预览成立，并在回归里守住；"静态层与身体层画布关系/对位规则"属于契约设计，本轮不改，列为遗留——**已由决策 8 拍板：预览读锚点，不规定画布一致**。
6. **导入校验不新增"九宫格美术与令牌是否一致"的检查**：边框像素是否等于令牌取决于美术意图（对称与否、边带是否恒定都可以是有意的设计），无法在不误报的前提下机器判定；这类检查留给样例包的专用 lint 与出图工具自己的装配保证（见决策 2、3）。理由：一条会误报的检查比没有检查更糟。

7. **逐方向层序（装备层在背面方向画在身体之后）**：此前装备层一律追加在身体层之后（画在身体前面），背面方向手持武器盖在身体上，与"武器在身体后面"的视觉相反。现状核对：`IRenderConventionHost.ComposeSpriteLayers` 的层序就是列表序（09 §3.3.1），契约没有逐方向层序。新增**可选**字段 `display.equip_visual.behind_directions`（方向槽位 id 列表，如 `dir.back`、`dir.back_side_r`；缺省空）：命中当前方向的装备层排到层列表最前（身体之后的最底层），其余层相对顺序不变；镜像方向（如 `back_side_l`）按它镜像自的已制作档位判定。运行期合成（`SpriteViewBase`）与预览区（`PaperdollPreview`）读同一份声明。纯新增可选字段，不升 schema 版本（ADR-0039 的加字段政策），缺省行为逐位不变；装备完整性校验核对每一项都在该游戏声明的方向档里（`equip_behind_direction_invalid`）。参考包的五把武器声明了 `back_side_r`、`back`（`toolchain/std_equip_set` 是共享数据来源，占位美术的武器在这两个方向也画在身体后面）。
8. **静态层锚点对齐（决策 5 的遗留，已拍板）**：规定"层图画布与身体画布关系"会把每个游戏的美术约束成同一套画布，代价高于收益，所以**不规定画布一致，由预览读锚点**。层精灵集的 `sprites/<集>/anchors.json` 可选声明 `directions.<方向>.grip`（层图自己的像素坐标，原点左上）；预览区在层与身体该方向的同名挂接点（身体集 anchors.json 里与层名同名的锚点，如 `hand_main`）都存在时，把层的 `grip` 对到身体的挂接点上；任一缺失按画布居中叠放（未声明时逐位不变）。导入校验：`grip` 必须是两个数字且落在层图画布内，越界报 `equip_anchor_out_of_bounds`、格式不对报 `equip_anchor_invalid`（负例各一）。参考包的武器按"身体 hand_main + 画布偏移"声明了 `grip`（层图制作时已摆在那里，所以对齐结果与居中一致，用例核对位移为零，同时守住"声明了就走锚点路径"）。**限制**：运行期合成（`UnityRenderer2D`）仍按各层画布居中叠放，锚点只驱动预览区；参考层图已预先摆好位置所以两者一致，换一套"层图不预摆位置"的美术时运行期需要另行接锚点（未做）。
9. **背包面板：尺寸随内容、物品名、图标可见度**：
   - 面板宽高 = max(缺省 260 x 260, 内边距 + 内容)：行高、"使用"按钮宽、名称标签宽度（取最长文本）都显式设定，格子再大、物品名再长，所有子控件都落在面板矩形内；内容放得下缺省尺寸时与此前的 260 x 260 逐位一致；没有滚动（物品多到超出屏幕时面板跟着变高）。不带皮肤的三参数重载此前行高与按钮宽都是矩形缺省 100，同样修复。
   - 物品名：行标签显示 `item.template.name_key` 的本地化文案（`UiVisuals.ItemName`，宿主装配 `L10n`）；没有本地化宿主或取不到文案时退回 id 短名。样例数据里 `l10n.item.<名>.name` 一直存在，此前面板没有读它。
   - 图标可见度：参考包的弓图标几乎透明（图像模型把弓画得很细，后处理按比例缩小后主体只剩细线）。重出弓图标（更粗的描述与新种子，入库的提示词与选定种子同步更新）；导入校验新增**警告**"不透明像素占比过低"（`equip_opaque_coverage_low`，图标阈值 alpha ≥ 128 的像素占比 ≥ 6%，纸娃娃静态层 ≥ 0.2%，阈值写在 `skin_manifest.json`，只在硬规则全部通过后才算，负例各一）。它是警告不是错误：细长的合法美术（长杖）是有意的设计，只提醒作者确认。
10. **运行期切换皮肤的缓存失效**：此前换皮肤（实验室衣橱场景换 `skin_ref`）要手工 `Unload` 缓存的图标才能看到新皮肤的图：加载器按资源 id 缓存精灵、按精灵集目录缓存 `anchors.json` 解析结果（像素密度与枢轴），两者都不随皮肤变。新增 `UiVisuals.SwitchSkin(skinRef, contentRoot)`：本入口发起过的图标/层图全部作废（已加载的 `Unload`；在途的在完成回调里卸掉，期间同 id 不发新请求，免得并入旧在途请求拿到旧根的图）；加载器新增 `InvalidateSpriteSetAnchorsCache()` 清精灵集锚点缓存；重装皮肤包与 UiSkin 覆盖（占位皮肤撤掉覆盖）；发出 `SkinChanged`。背包、装备、提示框、拖拽订阅它整体重建（装备面板保持当前预览方向）。旧皮肤包不立即销毁（不订阅的面板，如 HUD，仍持有旧包的精灵，延续 ADR-0082"不回溯重建"的取舍），随 `UiVisuals.Dispose` 释放。实验室衣橱场景新增 `SwitchSkin`。
11. **最小的运行期交互：悬停提示框与拖放穿脱**：皮肤包的提示框三件与拖拽三态此前只被画廊与完整性用例消费，没有任何面板用它们。现在：悬停背包格子/已装备槽位出提示框（底板、分隔线、属性行底条来自皮肤包 `tooltip/*`，内容由 `ItemTooltipBuilder` 从 `item.template` 算出：名称、品质、槽位、物品等级、武器伤害与攻速、固定属性、等级需求，只列数据里有的项；不接收射线、夹在画布内）；从背包格子拖到装备槽位穿上（拖拽影子用 `drag/ghost`，指针下的落点显示 `target_ok`/`target_blocked`，合法 = 物品模板的槽位等于目标槽位，落下的最终结果以装备载体的 `EquipResult` 为准，失败带出原因且装备不变）；把已装备的槽位拖回背包面板卸下。穿脱动作经注入的 `UiEquipActions`（生产宿主接 `UiIntents`，实验室舞台接 `WardrobeStage`）。没有声明皮肤时影子、叠层、提示框取框架占位包的同名文件。**不做**：拖拽排序、槽位间互换、堆叠拆分、触屏长按、技能提示框。

## 后果

### 正面

- 真实美术形态的缺陷在框架里被具名诊断拦下或被样例包 lint 守住，不会第一次出现在游戏接入处；游戏出图可以直接对照参考包的后处理脚本。
- 五处框架缺陷在接入前修复（决策 4）；第二轮再补：逐方向层序、预览锚点对齐、背包面板尺寸与物品名、图标可见度警告、运行期换皮肤缓存失效、最小提示框与拖放（决策 7～11）。静态层对位规则已拍板（决策 8）。

### 代价与限制

- 参考包约 0.5 MB 小图入库；换种子重新出图是人工操作，不进门禁。
- 纸娃娃的身体层与逐层动画剪辑仍用占位美术（静态层是真实美术，装备图标是同一件美术拟合到占位层的几何里）；样例数据只有 2 个槽位、2 档品质，8 槽位 × 5 品质的完整口径靠扩展数据行的单测与清单展开一致性核对，不靠实体物品。
- 锚点只驱动预览区，运行期合成仍居中叠放（决策 8）；背包没有滚动、拖放不做槽位互换（决策 9、11）；`equip_opaque_coverage_low` 只是警告（决策 9）。
- 九宫格令牌大于美术实际边框、边带不恒定等"美术意图类"问题，导入校验不拦（见决策 6）。
