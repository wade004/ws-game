# ADR-0139 非手感已知限制清扫的契约与行为决定

状态：已拍板 2026-10-03（对 [ADR-0125](0125-测试覆盖梳理第三批已知限制与行为语义拍板.md)、[ADR-0128](0128-单位间体积阻挡.md)、[ADR-0138](0138-手感已知限制清扫的数据与契约决定.md) 等的收口；非手感模块的已知限制清扫引入）

## 背景

[ADR-0138](0138-手感已知限制清扫的数据与契约决定.md) 清掉了手感体系自己登记的已知限制。核心层、表现层、适配层、工具链与文档里还有一批同类条目：有的是真能力缺口（套装门槛在数据重载后要等下一次装备变化才对账、滑动终点被拒绝时整个 tick 不位移、货币期望只有线性口径、大词缀池无法精确求解、增长仿真取消检查点太粗、循环音效在实体销毁后不停、音量变更不作用于已在播放的声音、图片解码无完整性校验、地图分层解码占住主线程、同一资源并发请求重复解码、没有单场战斗的命令行入口、没有"此槽位无外观"的声明方式等），有的是合理的边界却被写成"限制"。

收口原则与 ADR-0138 一致：缺口一律实现并带复现用例，不声明新能力时行为与改动前逐位一致；合理边界一律改写成"决定 + 理由"，不再叫限制。本 ADR 登记其中需要拍板的契约与行为取舍；纯实现层面的修复与新增的可选入口见各模块 README 判断记录与变更日志。

## 决策

1. **移动请求（含追击、受控位移、进行中的路径）不参与存档**：读档后由 AI 或玩家输入重新下达。理由：存档只存稳定事实；运行期单位读档后由地图加载重新生成，追击请求引用的目标读档后不一定还存在，恢复一条指向不存在目标的请求没有意义。
2. **追击过冲的上界等于重规划距离**：追击的规划终点是站位点，剩余偏差只来自目标朝追击者移动、尚未触发重规划，上界是移动选项里的重规划距离；要更严就调小它，代价是重规划更频繁。理由：这是停位精度与重规划频率的取舍旋钮，已经存在，不另设机制。
3. **离散模式下，目标丢失只在本单位自己的回合检测**：与路径跟随、受控位移在离散模式下只在行动者自己回合处理的惯例一致。理由：回合制里单位只在自己的回合推进，在别人的回合里改写它的状态会破坏"行动顺序即因果顺序"。
4. **网格实现的对角墙保留阶梯法线；要平滑斜墙，提供带真实法线的导航实现**：网格的阻挡是轴对齐方块的并集，斜墙在其上就是阶梯形，法线逐级交替。理由：核心层不替网格猜一个平滑法线，猜出的法线与实际阻挡几何不一致，会让单位沿一条不存在的墙滑动并穿进格子；需要平滑斜墙的游戏提供带真实法线的导航实现，或在阻挡数据里用凸多边形声明。
5. **滑动终点被可走性判定拒绝时，停在撞击点**：位移退回"撞墙停住"，与没有滑动能力的单位撞墙同口径、速度归零，不再整个 tick 不位移。理由：终点因浮点误差落进阻挡内部是边界上的数值抖动，整 tick 不动让单位在墙边卡顿一拍，停在撞击点是最接近物理含义的退化，且不引入新的数据或开关。这是本批唯一的行为改进，且只在原本就会卡住的情形生效。
6. **旧布局备份计入存档配额**：不按文件名猜测哪些文件是旧备份。理由：槽 id 允许长得像备份文件名，存档目录顶层任何一个槽文件都可能是与备份无关的正式槽，把前者排除出配额必然误伤后者（正式槽被排除即配额被绕过或槽从列表消失）。
7. **货币期望的线性口径与精确取整口径并存**：原有的线性期望语义逐位不变；新增含四舍五入与非正值跳过的精确期望，经嵌套掉落与保底路径同样叠加。理由：运行期对每次结果取整，量级小的货币线性期望会系统性偏离观测均值；改既有字段的含义会破坏依赖它的消费方，所以两个口径各有字段，由调用方按用途选。
8. **词缀大池的精确解为可选开启，受计算量预算约束**：缺省入口行为不变；开启后用抽取次数有界的精确算法，估算超预算、抽取次数过大或池过大时如实降级并建议改用逐次抽样。理由：计算量的边界不是近似，不给"看起来精确、实际有偏"的数；预算由调用方声明，避免分析入口被大池拖死。
9. **套装门槛在数据重载后立即对账**：重载删除或改高的门槛在重载那一刻释放，新增或改低且已满足件数的门槛在那一刻施加，定义没变则不动已施加的句柄。理由：套装表重载是"数据变了"的事实，光环生效与否应立刻与新定义一致，而不是等下一次装备变化才清理。
10. **攻击实例标识向表达式层暴露**：回避结局事件与命中确认事件的攻击实例标识可被表达式读取，为空时查不到。理由：反馈绑定等条件过滤需要按攻击实例关联多个事件，此前只能经强类型属性访问，与同类事件的暴露口径不一致。
11. **槽位定义的"有外观"标志缺省为真**：登记为可选布尔字段，运行期核心不读取，只由资产包校验使用；写假的槽位（不上身可见的槽位）不要求外观行。理由：缺省保持"所有装备类槽位都有外观"的既有行为，显式字段是唯一不靠猜的表达；不按槽位名猜（槽位名是游戏自己的约定），也不让游戏补空外观行（空行没有语义，反被当成真外观去校验）。
12. **持续集成依赖已发布的产物，产物缺失时失败是有意的**：全新仓库或发布产物被清空时，依赖真实产物的守卫用例会被跳过并使步骤失败。理由：把"没有可对照的发布产物"静默放过，等于让依赖真实产物的守卫形同虚设；补救方式是先补传发布产物，不是放宽下限。
13. **引擎适配层包不进 API 手册**：手册只收核心类库与对游戏开放的契约；适配层包的说明由它自己的文档承载。理由：适配层包编译依赖具体引擎，手册生成环境不具备，且它的消费方式是整体引用而不是按类型查阅。
14. **版本控制配置守卫只豁免分支与远端两类登记簿**：测试会话期间别的会话正当修改分支上游或远端，只改共享配置里这两类小节，守卫比较前剔除它们；其余配置小节仍受守卫。理由：误报整个测试会话比放过这两类小节的变化代价大得多，且这两类小节与测试隔离要防的事故（测试里起的子进程把配置写进真实仓库）无关。
15. **在途请求并入只针对同一标识且同一种类**：后到的同标识同种类请求并入在途请求，只读取与解码一次，回调各恰好一次；种类不同、或带不同精灵集提示的请求仍各自独立。理由：标识加种类才是缓存键；提示决定解码结果的枢轴，混并会让不同提示拿到同一份结果。此前各请求各自解码，后完成的覆盖先完成的缓存项，先建的纹理泄漏。
16. **渲染插值系数由适配层按引擎时间计算，核心语义不变**：连续模式下宿主按整步喂入，核心给出的插值系数恒近零；适配层按引擎时间在每个渲染帧重算，核心的契约与测试不动。理由：渲染帧率与逻辑步长无关，系数只有适配层知道真实渲染时刻；改核心语义会影响所有宿主与确定性基线。
17. **分层地图只要有一层不被内置解码器支持，整份资源回退**：整份资源改由引擎解码，不做"部分层后台、部分层主线程"的混合。理由：地图资源是一个不可分的缓存项，读取口不能看到半成品；混合会让缓存写入与回调时序变复杂，而不受支持的变体本就罕见。
18. **完整性校验失败回落到引擎解码并记警告**：校验和不符时整个图片资源判为损坏，不采用已流式写入的缓冲，由引擎给出最终结论。理由：内置解码器只是性能优化，不应比引擎更严也不应更宽；最终的真伪由引擎说了算，同时留下可追查的警告。
19. **开发期热重载改坏一张表时，整个数据集整体阻断**：数据注册表的只读查询是全局阻断语义，在下一次成功的重载或加载之前整个数据集都读不出来。理由：与生产环境不做静默降级的原则一致，开发期让坏数据立刻、整体地暴露，比只冻结那一张表而掩盖依赖它的跨表引用错误更安全；改对后保存即自动恢复。

## 后果

### 正面

- 非手感模块的已知限制清零：真缺口有契约成员、可选字段与复现用例，合理边界都有"决定 + 理由"，读文档的人不再把边界当待办。
- 全部是加法：新增的是重载、默认成员、可选属性与可选字段；不声明时行为与改动前逐位一致，唯一的行为改进是决策 5（只在原本会卡住的情形生效）。
- 期望值与精确算法都由规则算出，测试不写死裸数。

### 负面

- 货币期望有两个字段，调用方要按用途选对；读了旧文档的人可能继续读线性口径。
- 词缀精确解的预算由调用方声明，声明过小会降级，需要读降级标记。
- 并入在途请求后，回调的完成时机取决于首个请求的完成时机，依赖"各请求独立完成"的第三方回调需要注意。

## 备选方案与为什么不选

- **把移动请求写进存档**：目标读档后可能不存在，恢复无意义；否决。
- **给网格实现猜平滑法线**：与实际阻挡几何不一致；否决。
- **按文件名排除旧备份出配额**：与槽 id 可以任意命名的硬约束冲突；否决。
- **改既有线性期望字段为取整口径**：破坏依赖线性语义的消费方；否决，两口径并存。
- **词缀精确解缺省开启**：改变既有入口的耗时与降级行为；否决，声明才开启。
- **槽位外观靠槽位名约定或空外观行表达**：靠猜或无语义；否决，显式字段。
- **持续集成在产物缺失时静默放过**：守卫形同虚设；否决。
- **把适配层包塞进 API 手册**：手册环境不具备引擎依赖；否决。
- **版本控制配置守卫整体放宽**：会放过真正的污染；否决，只豁免两类登记簿。
- **改核心的插值系数语义**：影响所有宿主与确定性基线；否决，适配层按引擎时间重算。
- **热重载失败只冻结出问题的那张表**：掩盖跨表引用错误；否决。

## 魔兽世界的对应做法

无直接对应：魔兽的移动请求、套装对账、货币与词缀分布、渲染插值与资源并发加载都属客户端与服务端各自的内部实现，不向数据层暴露可声明的契约；本 ADR 的取舍面向"数据驱动、缺省行为不变"的框架约束。
