# ADR-0153 M5 收尾遗留：穿脱音效运行期播放、副手与挂点装备夹具、按住冲刺意图解析、异步加载测试驱动

状态：已拍板 2026-10-04（落实 [手感设计/08](../手感设计/08_装备与UI资产契约.md) 第 2、3 节、[01](../手感设计/01_输入与动作.md)、[02](../手感设计/02_移动与运动仲裁.md) 第 3.3 节；承接 [ADR-0148](0148-镜头与音画反馈的合成上限玩家强度脚步材质与动画表现标记.md) 的出声通路、[ADR-0149](0149-装备面板与界面资源契约清单.md) 的装备面板、[ADR-0147](0147-姿势与动画契约落地.md) 的冲刺模式）

## 背景

M5 各切片收口后留下四件小事，彼此独立，但都是"契约已经写了、运行期或验收缺一环"：

1. 装备面板与纸娃娃只有单手剑一套占位装备，副手槽位、副手手感叠加和 `socket_attach` 挂点外观从未被任何夹具和引擎侧用例走过。
2. 物品模板的 `equip_sfx_ref`（穿脱音效）在契约里存在，运行期没有任何一处播放它。
3. 冲刺模式（`MoveMode.Sprint`）在移动层已有语义，但"谁来决定本帧是不是冲刺"没有框架实现：引擎宿主只出轴，冲刺只能靠实验室脚本直接给模式。
4. 一条异步加载相关的方向切换原子性不变量用例偶发失败，且每次重跑都可能绿，无法区分"真问题"与"测试驱动不确定"。

## 决策

1. **副手与挂点装备用独立数据根的夹具覆盖，占位装备集不动。** 新增 `lab/fixtures/data/equip_ext`：副手槽位（武器槽，按槽位 id 序数排在主手之后）、占位副手匕首（paperdoll 层 `hand_off`，`offhand_writes` 只写副手可叠加字段）、饰品槽位、占位提灯（`socket_attach` 外观，挂点由 model 型 `display.map` 行声明），配套换装脚本 `equip_ext_cycle`。理由：副手叠加、挂点附着、装备面板格子与纸娃娃层是三个独立机制，需要真实数据逐项走到；放进 `data/_equip` 会改动既有数据集哈希与全部装备基线。新增条件度量组 `equip_offhand`（只在脚本用到副手或非精灵外观时适用），其余脚本的指纹与基线逐位不变。覆盖面：导入校验（挂点必须被 model 行声明、副手层文件必需、运行期单件事实与静态报告对账）、无头换装场景、引擎侧装备面板与纸娃娃、引擎侧挂点附着与清理。

2. **穿脱音效运行期播放：订阅装备与显式卸装事件，经出声通路播放。** 模板声明了 `equip_sfx_ref`，则 `item.equipped` 与 `item.unequipped` 各在持有者位置播放一次（同一条引用；被替换的旧装备只随新装备的 `item.equipped` 出一次声）。事件只带物品实例 id，模板先查背包与装备槽现状、再退回 `item.added` 累积的实例到模板表，两处都查不到则静默。只有目录里某个模板声明了该字段时，装配方才构造这个订阅；没有声明时总线与行为同此前逐位一致。理由：音效是纯表现，不进逻辑组；装配条件化保证缺省路径零变化；沿用 ADR-0148 的出声通路，不另建出声机制。

3. **按住冲刺由框架的玩家移动意图解析器决定。** 新增 `PlayerMoveIntentResolver`：轴（阈值与现有死区口径一致）加一个可选的、由数据声明的冲刺输入动作，经 `IInputBufferQuery.IsHeld` 读按住状态，产出 `MoveRequest` 与 `MoveMode`（走/跑/冲刺）。冲刺输入动作是 `button` 型且 `class` 为 `move` 的动作，输入层对这一类只记按住、不入缓冲、不写动作事件。三个引擎宿主（框架装配入口、常驻宿主、游戏模板）与实验室试玩宿主都经它出请求。未声明冲刺输入动作时请求与此前逐位相同（用对照用例证明）。实验室新增按住冲刺脚本 `feel_pose_sprint_hold`。理由：避免每个游戏各自在宿主里重写"轴 + 按住 → 模式"；"只记按住"让按住型动作不污染缓冲与动作事件；缺省不声明则等同旧行为。

4. **异步加载用例的不稳定是测试驱动不确定，修驱动，不放松断言、不加重试。** 根因：用例按帧数推进，而异步加载的后台解码按墙钟完成、主线程每帧还有时间预算，于是"某一帧新朝向的资源是否已就绪"取决于机器负载，换向原子性断言偶尔落在资源未就绪的窗口。修法：测试夹具每次推进前先等在途的后台加载全部落定，并取消主线程预算，使"推进一帧 = 当前所有请求的加载完成并上屏"成为确定性规则；生产加载器只新增两个仅供测试读写的钩子（解码停顿注入、在途数）。复现用例用解码停顿注入稳定触发（修复前红、修复后绿）。理由：不稳定用例的价值是暴露真实的时序假设，驱动不确定时断言放松或重试只会掩盖。

## 后果

### 正面

- 副手叠加、挂点附着、装备面板格子、纸娃娃层都有了真实数据的无头与引擎侧验收，期望值全部由数据与规则算出。
- 穿脱音效从契约走到运行期，缺省零变化。
- 冲刺有了框架级实现，三个引擎宿主与实验室同一条路径；按住型动作不再需要游戏自己绕缓冲。
- 异步加载用例从"偶发红"变为确定性，且有一条稳定复现的用例守住。

### 代价与限制

- 副手武器在单件事实里的 `weapon_style` 跟随主手：武器风格来源只跟踪主手（副手只叠加手感字段，不换姿势风格）。
- 占位副手匕首与提灯没有入库的图片资产，引擎侧用例只核对层名、精灵集名与挂点节点，不核对像素。
- 装备或卸装时模板解析不到（背包、装备槽与 `item.added` 表里都没有）则该次穿脱音效静默。
- 冲刺输入动作按住状态只记按住，不产生按下/松开动作事件；需要边沿事件的游戏应另声明一个非 `move` 类动作。

## 备选方案与为什么不选

- **把副手与挂点装备并入 `data/_equip`**：改动既有数据集哈希与装备基线，违反"缺省逐位不变"；否决。
- **为 `unequip` 另设一个卸装音效字段**：契约里没有该字段、没有消费方；否决，穿脱共用同一条引用。
- **每个游戏宿主各自实现按住冲刺**：重复且易漂移；否决，框架出解析器。
- **给不稳定用例加重试或放宽断言**：掩盖真实时序假设；否决。
