# ADR-0013 时间模型可替换：即时与回合制战斗同一套规则层

状态：已拍板 2026-09-04

## 背景

架构原先把"固定步长即时模拟"定为根基（见 ADR-0003），回合制被排除在支持范围之外。用户要求架构级同时支持即时战斗与回合制战斗，且该能力与任何具体游戏无关——某个游戏选即时、某个游戏选回合制，都应该是同一份架构的合法配置，而不是需要另起一套系统。

对规则层（技能、光环、触发、结算、仇恨、目标选择，见 `06_规则层_属性技能战斗AI.md`）逐项分析发现：这些规则全部只依赖"经过了多少时间单位"（读条需要 N 个时间单位、光环持续 M 个时间单位、冷却需要 K 个时间单位……），不依赖"一个时间单位是一秒还是一个回合"。真正与时间模型绑定的只有一处：模拟如何产生"下一步"——连续模式按固定步长产生，离散模式按行动顺序逐个产生。据此，把"时间模型"抽成 L0 主循环的一条可替换策略即可覆盖两类战斗，不需要为回合制另写一套战斗系统。

## 决策

1. **时间模型 TimeModel** 是 L0 `foundation/sim_loop` 的策略：`continuous`（固定步长，时间单位为秒）与 `discrete`（回合，时间单位为回合）。所有与时间相关的数据字段（读条、引导、冷却、充能回充、光环持续与周期、资源回复与衰减、重生计时、脱战判定）一律以"时间单位"计，数据集通过 `found.time_model` 表声明探索与战斗各自的时间模型；校验器按声明检查取值合理性（见 `04_数据与内容管线.md`）。
2. **模拟步 SimStep** 成为 `WorldSim.tick` 的唯一输入：`SimStep = Continuous{dt: Number} | Discrete{actorId: Id, phase: turn_start|act|turn_end|round_end}`。tick 内部固定的八步顺序不变；离散步只处理当前行动者的意图，其余单位不产生意图（见 `03_运行时骨架.md`）。
3. **回合调度器 TurnScheduler**（L0 `foundation/sim_loop` 内的子组件）：按先攻规则维护本回合行动顺序，产生离散步序列；先攻规则是策略：`initiative_stat`（按属性表里声明的先攻属性排序，是否每轮重排或固定由参数决定）、`action_points`（行动点耗尽即结束回合，行动点为可选资源类型）、`fixed_order`（固定顺序）；预留 `atb` 作为后续扩展位，本次不展开。
4. **等待输入**：离散模式下轮到玩家行动时，调度器进入 `awaiting_input`，模拟不推进，主循环照常驱动表现与界面；玩家提交意图（或"结束回合"意图）后继续。回放机制不变：存档与重放只记录意图序列，确定性不受影响。
5. **模式切换**：探索与战斗各自声明时间模型（`exploration_time_model`、`combat_time_model`），三种合法组合：即时/即时（默认）、即时/回合、回合/回合。切换由 `combat.entered`/`combat.left` 事件或遭遇定义的覆盖项触发；切换时刻做一次时间单位换算（进入回合制时，正在生效的光环等以秒计的剩余时长按 `seconds_per_turn` 折算为剩余回合数，反之亦然）。
6. **规则映射（规则层不改代码，只改解释）**：读条 N 在离散模式下解释为"延迟 N 个己方回合生效的动作"；引导解释为"每个己方回合重复一次直到结束"；自动普攻在离散模式下不自动触发，改为一个显式动作；移动在离散模式下按每回合移动预算（距离或行动点）结算，可选格子吸附策略（格子尺寸为参数，范围形状按格子中心采样）；AI 仍用同一张优先级表，在自己回合求值一次并可连续行动直到预算耗尽；仇恨表、目标选择、结算管线、光环叠加规则完全不变。
7. **表现回放**：离散模式下逻辑在一次离散步内可能瞬间产生多条事件，表现层按事件顺序排队回放（动作、飘字、特效），回放完毕发出 `presentation.playback_finished` 事件；L0 的**节奏策略 PacingPolicy**（`immediate` 即时模式默认 / `wait_for_playback` 离散模式默认）决定调度器是否等待该事件再推进下一离散步。表现层仍然只读、只订阅，`presentation.playback_finished` 是它唯一允许发出、且只用于解除节奏门（不携带、不构成任何逻辑判定）的例外。

## 后果

### 正面
- 一套规则层同时覆盖即时与回合制两类战斗，新游戏选哪种战斗节奏是配置问题，不是"要不要换一套系统"的问题。
- 结算管线、仇恨、目标选择、光环叠加等既有规则一字不改，只是被两种不同节奏的模拟步驱动，维护面不因新增时间模型而翻倍。
- 探索与战斗允许分别声明时间模型，也支持"探索即时、进入战斗切换为回合"这类常见形态，覆盖面比单一模式更广。

### 负面
- 时间字段的语义从"确定是秒"变成"单位相关"，内容作者必须知道自己所在数据集声明的是哪种时间模型，校验器要新增一项专门检查（离散模式下时间字段必须为整数）。
- `awaiting_input` 与 `wait_for_playback` 给主循环增加两个必须正确处理的门，实现与测试的分支数比纯连续模式更多。
- 回合制特有的先攻、行动点等概念即使某个具体游戏从不使用离散模式，仍是架构文档与校验规则的常驻内容。

## 备选方案与为什么不选

- **为回合制另写一套战斗系统**：两套数据、两套结算逻辑，直接违反"不写第二套战斗系统"的前提，长期维护成本随内容量线性叠加，不采纳。
- **只支持即时、用极慢时间缩放伪装回合**：无法表达先攻顺序与行动点资源，观感上仍是连续时间的产物，不是真正的回合制，不采纳。
- **用统一的 ATB（主动时间条）形态统一两者**：概念上更连续，但会让"纯回合制"这一常见诉求变得绕（需要用连续时间条模拟离散回合），本次决策把 `atb` 保留为 `initiative_policy` 的预留扩展位，暂不作为统一路线展开。

## 魔兽世界的对应做法

魔兽世界本身只有即时战斗模式，但它的法术数据把持续时间、冷却都表达为"时间量"而非"帧数"或"网络包序号"，这正是"规则层只依赖经过的时间单位、不依赖时间单位的种类"这一前提在真实系统里的体现，是本决策可行的基础。回合制部分不对应魔兽的任何系统，参考的是经典战棋与 CRPG 品类里"先攻决定行动顺序、行动点决定单回合预算"的通行做法。
