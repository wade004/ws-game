# ADR-0118 手感档案分层解析与字段登记

状态：已拍板 2026-10-01

## 背景

手感数值若散在代码常量或各模块自己的配置里，既不能跨游戏迁移，也无法回答"这个数从哪来"。角色、性别、体型、武器、当前动作、临时状态都会改手感，需要一套有明确操作语义与溯源的分层解析；调参面板与测试若各自手写字段清单，字段一多就漂移。

## 决策

1. **新增数据域 `feel`**（04 第 2.2 节域名清单走审批，本 ADR 即审批记录），表：`feel.preset`（类型级基础，全字段）、`feel.archetype`（体型原型：体量/步幅/敏捷/攻击重量）、`feel.weapon`（武器原型，含 `family`、`impact_class`；与 `display.weapon_style` 分表同 id，规则层只读本表）、`feel.character`、`feel.action`、`feel.calibration`、`feel.motion_mode_rules`、`feel.tag_map`。表现侧配套 `feedback.impact_profile`、`camera_profile` 扩展、`display.anim_set` 扩展。
2. **不按性别/角色存数值，按物理原型存**：性别、种族、职业在游戏层 `feel.tag_map` 映射到原型或覆盖；框架不认识性别。
3. **七个分组**：输入、移动、动作、受击、镜头、特效、音频；前四组判定型为主，后三组呈现型。
4. **八层覆盖顺序**：基础预设 → 体型原型 → 标签映射 → 武器 → 角色 → 当前动作 → 临时状态 → 调试覆盖。每层每字段一种操作 `set | multiply | add`（登记声明允许集合，布尔与引用只允许 `set`）；同层重复写为校验错误；顺序为逐层、层内 `set→multiply→add`，最后限幅并记录；列表整体替换、显式 `remove`；`extends` 无环。
5. **合成来源**登记：角色为主（武器层不得写）、武器为主（体型层只可 `multiply`）、攻击期间武器临时覆盖（动作结束自动撤回）；副手只可叠加标记为 `offhand_stackable` 的打击层字段。
6. **字段登记新增元数据**：`half`（判定/呈现）、`group`、`ops`、`composition`、`unit`、`offhand_stackable`。一份登记表驱动校验、解析合成、调参面板生成、测试枚举。校验新增操作/合成/重复/范围/成环/预设完整性/半属越界/标定缺项等检查。
7. **解析器**：纯函数，按实体缓存，由装备/外形/光环/动作/标签/调试覆盖事件失效；输出不可变 `ResolvedFeel`（标定后绝对值 + 标定前相对值 + 被限幅字段 + 版本）与逐字段溯源；按半属生成两套只读视图防越界读取；时间线技能在动作开始时快照手感表，动作中重算不改当前动作。
8. **临时状态**：光环可携带 `feel_modifiers`，以光环实例 id 为键的第 7 层条目，移除即删条目重算，不做反向乘法；字段已是属性的走属性系统，不允许重复表达。
9. **能力声明与降级**：`supportsSweep / supportsRootMotion / supportsFootIK / supportsCameraImpulse`；必需能力缺失报错，可选能力按预设声明降级并诊断，不静默丢失。
10. **版本与成熟度**：预设行携带 schema/profile 版本、依赖版本、单位约定；`maturity: experimental | validated`，`validated` 必须绑定适配组合、姿势集、实验室脚本、设备条件且验收全绿；占位资源上的体验不得标 `validated`。热加载在安全的动作边界应用。
11. **首期原型库**只收录可验证的最小集合：`arpg_responsive`、`rpg_classic` 两预设，三体量原型，单手剑与巨剑两武器原型，四档反馈包，一套镜头档案；其余给结构与试调起点标 `experimental`。

## 后果

### 正面

- 任意角色配任意武器有确定的合成结果，不需要为每个组合单独调。
- 每个字段可回答"从哪来、被谁改、改成了多少"。
- 新增字段只改登记表与消费方。

### 负面

- 登记元数据与校验项显著增多；数据作者需要理解层与操作。
- 与 `display.weapon_style` 同 id 分表要求两表同步维护（校验器检查引用存在性）。

## 备选方案与为什么不选

- **单层平铺的角色档案**：组合爆炸，每个角色×武器一份；否决。
- **隐式"后写覆盖前写"**：来源不可追溯，A/B 与热调参无法解释差异；否决。
- **临时增益用反向乘法撤销**：浮点叠加误差累积；否决。
- **手感字段放 `display.*`**：规则层要读判定型字段，违反分层；否决。

## 魔兽世界的对应做法

魔兽的攻速/急速、移动速度经属性与光环修改，本架构对已是属性的字段沿用属性系统；魔兽没有手感档案概念，武器差异只在攻速与伤害，无直接对应。
