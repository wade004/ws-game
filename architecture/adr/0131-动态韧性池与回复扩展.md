# ADR-0131 动态韧性：韧性池、回复与三项可选扩展

状态：已拍板 2026-10-03（对 [手感设计/03](../手感设计/03_攻击受击与命中.md) 第 4 节"韧性"规则的追加决定；不改静态韧性规则；手感落地 M4-L 引入韧性池与回复，M4-W3 补三项可选扩展）

## 背景

03 第 4 节的韧性只有静态规则：目标声明一个韧性值，攻击的 `stagger_power` 不高于它就只播受击动画（`flinch`），否则按冲击等级映射反应。静态韧性表达不了动作游戏里常见的"连续被打会被打破、破韧之后短暂脆弱、停手或脱战后慢慢回复"：每一击的结果只取决于这一击自己，没有累计。03 原文把"伤害削减韧性、脱战回复"写成"是否启用为游戏级策略"，却没有给机制，结果是每个游戏都得自己写一套带状态的裁决，而裁决入口恰好是手感里最该由框架统一的地方。

要补这块，需要拍板的是：累计状态放在哪里、怎么与静态规则共存而不改既有基线、回复口径由谁决定。

## 决策

1. **可选启用，开关在攻击方档案**：攻击方档案新增可选的判定型数值字段 `poise_damage`（每击削韧量，0..1000，缺省无值）。命中的攻击声明了 `poise_damage > 0` 且目标有韧性属性（容量 > 0）时才走动态韧性；否则走静态规则，裁决与此前逐位一致。霸体（不碰池）与击杀（死亡优先，不碰池）排在韧性之前，口径不变。

2. **韧性池口径**：池的容量 = 目标的韧性属性值，已损失量由受击裁决方自己记录（不回写属性系统）。击前有效韧性 `before = max(0, 容量 − 已损失)`，扣后 `after = max(0, before − poise_damage)`。`after > 0` 且 `stagger_power ≤ before` 才被挡成 `flinch`；否则按冲击等级映射反应，再受 `reaction_cap` 封顶。`before > 0` 且 `after = 0` 是**破韧**；池子已空时后续命中同样不被挡。

3. **回复**：目标侧新增可选字段 `poise_recover_delay_ms`（最近一次动态韧性伤害后等待多久，每次动态命中重新计）与 `poise_recover_per_s`（之后每秒回复多少；缺省不回复）。回满的那个 tick 发 `combat.poise_recovered` 并清除该目标的池记录；单位死亡或销毁同样清除。回复速率与延迟在命中那一刻取目标当时的手感解析值，之后改档案对已建立的池不追溯。

4. **三项可选扩展（M4-W3）**，全部缺省等价上述口径：
   - 回复模式 `poise_recover_mode`（目标侧，`delay` | `out_of_combat`，缺省 `delay`）：`out_of_combat` 时目标处于战斗中的 tick，延迟计时与速率回复都暂停，脱战后才开始计延迟。"战斗中"复用框架已有的战斗状态查询，不另造一套；没有接战斗状态查询时视为一直脱战，口径同 `delay`，不会因为声明了该模式而永不回复。
   - 破韧后定时回满 `poise_break_reset_ms`（目标侧，0..60000，缺省不重置）：声明后，从破韧起算到点一次回满，不看速率与回复模式；已空池子上的后续命中不是新的破韧，不顺延计时。
   - 冲击等级缩放：受击裁决选项里的"冲击等级 → 倍率"表（口径同击退距离的倍率表）。`poise_damage` 乘以攻击方冲击等级的倍率后才扣池，事件里报告乘后的有效值；缺省空表，不缩放。倍率表的数值由游戏填写，框架不预置。

5. **事件**：`combat.poise_changed{targetId, sourceId, before, after, max, damage, broken}`（每次动态命中一条）与 `combat.poise_recovered{targetId, poise}`，登记进事件目录。

6. **契约注释的修订**：受击裁决入口原写"纯函数式"，现改为"仅动态韧性命中会写状态（扣池）"，并要求每次真实命中恰好调用一次（时间线结算路径与瞬时结算适配路径各一处）。

## 后果

### 正面

- 连续削韧、破韧、回复这类动作游戏常见的韧性手感由数据声明，游戏不必自己写带状态的裁决。
- 全部是加法、缺省不启用：不声明 `poise_damage` 的数据与既有基线逐位不变；三项扩展各自缺省等价基础动态口径。
- 回复模式复用既有战斗状态，没有第二套"是否在战斗"的判断。

### 负面

- 裁决入口多了一处状态写入（扣池），"每次真实命中恰好调用一次"从惯例变成必须守住的契约，新增结算路径时要对照。
- 池的已损失量是裁决方内部状态，不对外暴露为属性；想在界面上显示韧性条的游戏通过只读查询与 `combat.poise_changed` 事件取值。
- 冲击等级倍率表没有框架缺省数值，游戏必须自己试调。

## 备选方案与为什么不选

- **把已损失量写进属性系统**：每次命中与每个回复 tick 都会产生属性变化事件并触发依赖它的重算（实验室里单是写入一次静态韧性就多一条属性变化事件），代价与收益不成比例；否决，状态放在裁决方内部。
- **默认对所有攻击启用动态韧性**：既有预设的每一击结果都会变，全部基线重烘；否决，必须由攻击方显式声明 `poise_damage`。
- **用 `stagger_power` 同时承担"打断强度"与"削韧量"**：两个概念不同（一击可以很强但不削韧，反之亦然），合并后无法分别调；否决，独立字段。
- **回复口径写死成"脱战才回复"**：有的游戏要"停手几秒就回"，有的要"脱战才回"；否决，用模式字段并以 `delay` 为缺省以保持既有口径。
- **破韧后让池永远为空直到回复**：无法表达"破韧后有一个固定的脆弱窗口、窗口结束一次回满"；否决，另给定时回满字段。

## 魔兽世界的对应做法

无直接对应：魔兽的打断是法术打断与控制效果，不存在逐击削减的韧性池；本能力对应动作游戏里的"韧性条/架势条"，取其"累计、破韧、回复"三个手感要素。
