# ADR-0130 竖直轴能力包：高度偏移的逻辑语义、命中形状高度窗口与击飞

状态：已拍板 2026-10-02（修订 [05 对象模型与世界](../05_对象模型与世界.md) 第 3.3 节；落实 [ADR-0122](0122-手感实验室场景矩阵与跨场景不变量.md) 决定 3 里预留的 `volume` 与 `side_2d` 两个空间取值中"竖直轴"这一半）

## 背景

05 第 3.3 节把单位的高度偏移（跳跃、被击飞、飘浮的视觉抬升）定为纯表现参数：逻辑层可写，表现层只读，**不参与平面距离与碰撞计算**。这与"世界是 2.5D 平面"的总约定一致，也是所有既有行为与基线的前提。

ADR-0122 为手感实验室预留了体积空间（`volume`）与横版二维（`side_2d`）两个空间取值，并规定启用它们需要独立 ADR。手感落地需要让这两个取值有真实语义：能跳、能被击飞、落地；近战判定要区分"打得到站在地上的目标"与"打不到头顶上的目标"；"最近目标"在体积空间里要把高度差算进去。这些都要求逻辑层真正读取并积分高度，直接与 05 第 3.3 节的"不参与计算"冲突。

不能由实验室自己拼一套：实验室只是宿主，竖直运动、命中高度窗口与击飞是游戏本身也要用的规则能力，必须落在核心层的既有模块里，由实验室按格子的 `space` 取值打开，而不是在实验室里另造一套平行机制。

## 决策

1. **竖直轴是可选能力包，缺省关闭，开关在世界装配**。单位载体的移动选项新增可选的竖直轴配置（缺省为空）。为空时世界没有竖直轴，05 第 3.3 节原口径完全成立，行为与引入本能力之前逐位一致；非空时才装配竖直运动服务。高度偏移在装配后的语义是"逻辑层按重力积分的脚下高度"，命中形状高度窗口与三维距离读取它；表现层仍只读它渲染（影子缩放等），不变。

2. **单位**：重力与跳跃高度用世界单位，不经手感标定换算——空间能力属于世界，不属于某个手感预设（同一张地图换预设，重力不该跟着变）；要按身高比例声明的游戏在装配处自己换算。击飞高度走手感档案，按手感的惯例是"体型倍数、标定后换算为世界单位"（见第 6 条）。

3. **竖直运动模型**：
   - 解析式抛体：脚下高度 `h(t) = h0 + v0·t − g·t²/2`（`t` 为起飞后累计的模拟时间），不做逐步累加，帧长不均匀时没有积分漂移；首次 `h ≤ 0` 的步落地、高度写 0。
   - 地面恒为 0：没有斜坡、台阶、天花板，竖直运动不被地形阻挡。
   - **只积分被抛起的单位**：没被跳跃或击飞过的单位高度保持原值不动——飘浮怪、悬空靶是"静态高度"，不受重力。
   - 每步按单位 Id 序遍历；已销毁的单位静默丢弃其飞行状态；离散模式（ADR-0013）不推进（竖直运动属于连续时间模型）。
   - 跳跃：空中默认拒绝（返回假，由调用方计数，不静默吞掉）；配置允许二段跳时从当前高度重新抛起。再次击飞同理：按"起点为当前高度重新抛起"处理，不叠加速度。
   - 按顶点高度抛起时初速 `sqrt(2·g·H)`，从地面起飞的落地步数为 `⌈2·v0/(g·dt)⌉`。

4. **接口**（中立记法）：

   ```
   interface IVerticalMotion {                     // 竖直运动服务（单位载体层）
     isAirborne(unitId: Id): Bool
     getVerticalSpeed(unitId: Id): Number          // 向上为正；不在空中为 0
     launch(unitId: Id, initialSpeed: Number): Bool
     launchToApex(unitId: Id, apexHeight: Number): Bool   // H 为相对当前脚下高度再升高的量
     jump(unitId: Id): Bool                        // 以配置的跳跃高度起跳；被拒绝返回 false，不改变任何状态
   }
   interface ILaunchSink {                         // 击飞提交口（受击裁决 → 竖直运动服务）
     beginLaunch(unitId: Id, apexHeightWorld: Number)
   }
   IUnitAccess.getHeightOffset(unitId: Id): Number // 脚下高度；默认成员，缺省恒返回 0，真实实现覆盖
   ```

   `getHeightOffset` 做成接口的缺省成员而不是必须实现的抽象成员：既有的自写实现不必跟着改，行为等价于"没人读它"。竖直运动服务同时实现 `ILaunchSink`；没有竖直轴的世界里没有 `ILaunchSink` 的实现方，受击裁决的击飞提交口为空，击飞静默不发生。

5. **形状高度与命中高度窗口**：
   - 目标链的形状（圆、扇形、线、矩形四种通用）新增可选字段 `height`（世界单位，必须为正）：命中判定的**高度窗口半宽**。未声明时竖直方向不设限（无限高的柱体）。
   - 目标选择选项 `VerticalHit` 打开时才生效：候选单位脚下高度与锚点（施法者；地面坐标施法的锚点高度取地面 0）脚下高度之差的绝对值不超过 `height` 才保留。空间查询本身仍是平面的，高度过滤发生在来源收集之后、过滤器之前；施法者自己不受影响。
   - 目标选择选项 `SpatialDistance` 打开时，`sort_by.distance` 与"最近"一律按含高度差的三维欧氏距离；关闭时按平面距离，逐位等于改动之前。
   - 两个选项缺省都关；`height` 在选项关闭时被忽略（平面世界里既有链与既有行为逐位不变）。
   - 施法射程检查仍是平面距离（技能管线判定，竖直方向不参与）。

6. **击飞**：
   - 手感档案新增可选的判定型数值字段 `launch_height`（受击组，体型倍数，范围 0～10，缺省无值 = 不击飞）。
   - 受击反应达到 `knockback` 或 `knockdown` 时，击飞顶点高度（世界单位）= 攻击方 `launch_height`（标定后）×（1 − 目标击退抗性）× 冲击等级倍率（与击退距离同一套倍率）。
   - 与击退**同一触发条件、同一提交时机**（顿帧结束后）；但**互相独立**：只有 `launch_height` 没有击退距离也击飞，反过来亦然。
   - 世界没有竖直轴时档案里的 `launch_height` 被忽略；字段本身可以出现在任何档案里，不因世界不同而校验失败。

7. **`space` 取值的含义**（手感实验室场景表，见 [手感设计/06](../手感设计/06_手感实验室与验收.md) 第 10 节勘误 9）：`plane` = 平面世界、不装配竖直轴；`side_2d` = 装配竖直轴与命中高度窗口；`volume` = 装配竖直轴、命中高度窗口与三维距离。`side_2d` 的"深度轴被控制空间锁死"属于宿主的输入处理（把摇杆的竖直分量当深度丢弃），**不进核心契约**：核心层只提供竖直轴、高度窗口、三维距离与击飞四样能力。

8. **本 ADR 不承诺的范围**：斜坡、台阶、天花板、空中控制、空中攻击与空中受击的专属反应、跳跃动画状态、第三人称自由视角（仍属 ADR-0122 的预留）。击飞中的目标不做空中控制。

9. **05 第 3.3 节的修订**：高度偏移的缺省口径（平面世界、纯表现参数）不变，补充"可选的竖直轴能力包装配后，逻辑层按重力积分该值，命中形状高度窗口与三维距离读取它"，并指向本 ADR；05 文档版本递增并追加变更记录。

## 后果

### 正面

- `volume` 与 `side_2d` 从预留标签变成可运行、可验收的能力，且落在核心层的既有模块里（单位载体、目标选择、受击裁决），游戏与实验室用的是同一套实现。
- 全部是加法、缺省关闭：没有声明竖直轴、没有声明 `height`、没有声明 `launch_height` 的世界与数据，行为与基线逐位不变。
- 解析式积分让落地步数可以由重力与初速直接算出，复现用例的期望值不用写裸数。

### 负面

- 高度偏移不再是纯表现参数：竖直轴装配的世界里，逻辑层读它，表现层以外的模块要考虑它的取值。05 第 3.3 节因此有"缺省口径"与"装配后口径"两种读法。
- 地面恒为 0：没有斜坡与台阶，站在平台上的单位表达不了；平台、台阶类需求需要另一份导航与空间查询契约的扩展与 ADR。
- 命中高度窗口用的是命中判定那一刻施法者的脚下高度，不考虑形状自身的竖直偏移（锚点恒在施法者脚下，没有向上或向下偏置）。
- 击飞期间再次被击飞按重新抛起处理，不叠加速度；击飞中的目标没有空中控制。

## 备选方案与为什么不选

- **把高度做成坐标的第三个分量（三维坐标）**：存档、导航、空间查询、碰撞、数据 schema 全部要改，与 05 的平面世界总约定冲突，且绝大多数游戏不需要；否决，高度仍是单位上的一个附加参数，只在能力包装配后被读取。
- **竖直运动由实验室宿主自建**：游戏要用时还得再写一遍，且实验室验证的就不是游戏用的那份实现；否决，落在核心层，实验室只按格子打开。
- **默认开启**：所有既有基线与既有游戏的命中与距离都会变；否决，缺省关闭。
- **逐步累加（欧拉）积分**：帧长不均匀时有积分漂移，落地步数无法由公式直接算出；否决，用解析式。
- **击飞复用击退距离字段**：击退与击飞是两件独立的事（水平推开与竖直抛起），复用会让"只想击飞不想位移"无法表达；否决，独立字段 `launch_height`。
- **高度窗口做成目标过滤器而非形状字段**：高度范围本来就是命中几何的一部分，与形状同处声明更直观，也复用形状已有的 schema 与校验；否决过滤器方案。
- **把深度锁放进核心**：深度锁只是"哪些输入被丢弃"，属于游戏的控制层，核心没有输入语义；否决，留在宿主。

## 魔兽世界的对应做法

魔兽世界是真三维世界（单位带高度坐标，跳跃与击飞是三维位移）。本架构选择平面世界加可选竖直轴，只取其中"跳跃、击飞、命中区分高度"这几样手感相关的行为；"击飞"对应其"击飞类控制"，本架构把它归入受击裁决的反应（与硬直、击退同源）。
