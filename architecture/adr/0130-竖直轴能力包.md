# ADR-0130 竖直轴能力包：高度偏移的逻辑语义、命中形状高度窗口与击飞

状态：已拍板 2026-10-02（修订 [05 对象模型与世界](../05_对象模型与世界.md) 第 3.3 节；落实 [ADR-0122](0122-手感实验室场景矩阵与跨场景不变量.md) 决定 3 里预留的 `volume` 与 `side_2d` 两个空间取值中"竖直轴"这一半）；2026-10-03 起地形、空中控制与空中战斗等限制由文末"M4 增补"取代

## 背景

05 第 3.3 节把单位的高度偏移（跳跃、被击飞、飘浮的视觉抬升）定为纯表现参数：逻辑层可写，表现层只读，**不参与平面距离与碰撞计算**。这与"世界是 2.5D 平面"的总约定一致，也是所有既有行为与基线的前提。

ADR-0122 为手感实验室预留了体积空间（`volume`）与横版二维（`side_2d`）两个空间取值，并规定启用它们需要独立 ADR。手感落地需要让这两个取值有真实语义：能跳、能被击飞、落地；近战判定要区分"打得到站在地上的目标"与"打不到头顶上的目标"；"最近目标"在体积空间里要把高度差算进去。这些都要求逻辑层真正读取并积分高度，直接与 05 第 3.3 节的"不参与计算"冲突。

不能由实验室自己拼一套：实验室只是宿主，竖直运动、命中高度窗口与击飞是游戏本身也要用的规则能力，必须落在核心层的既有模块里，由实验室按格子的 `space` 取值打开，而不是在实验室里另造一套平行机制。

## 决策

1. **竖直轴是可选能力包，缺省关闭，开关在世界装配**。单位载体的移动选项新增可选的竖直轴配置（缺省为空）。为空时世界没有竖直轴，05 第 3.3 节原口径完全成立，行为与引入本能力之前逐位一致；非空时才装配竖直运动服务。高度偏移在装配后的语义是"逻辑层按重力积分的脚下高度"，命中形状高度窗口与三维距离读取它；表现层仍只读它渲染（影子缩放等），不变。

2. **单位**：重力与跳跃高度用世界单位，不经手感标定换算——空间能力属于世界，不属于某个手感预设（同一张地图换预设，重力不该跟着变）；要按身高比例声明的游戏在装配处自己换算。击飞高度走手感档案，按手感的惯例是"体型倍数、标定后换算为世界单位"（见第 6 条）。

3. **竖直运动模型**：
   - 解析式抛体：脚下高度 `h(t) = h0 + v0·t − g·t²/2`（`t` 为起飞后累计的模拟时间），不做逐步累加，帧长不均匀时没有积分漂移；首次 `h ≤ 0` 的步落地、高度写 0。
   - 地面恒为 0：没有斜坡、台阶、天花板，竖直运动不被地形阻挡。
   - **只积分被抛起的单位**：没被跳跃或击飞过的单位高度保持原值不动——飘浮怪、悬空靶是"静态高度"，不受重力。
   - 每步按单位 Id 序遍历；已销毁的单位静默丢弃其飞行状态；离散模式（ADR-0013）不推进（竖直运动属于连续时间模型）。
   - 跳跃：空中默认拒绝（返回假，由调用方计数，不静默吞掉）；配置允许二段跳时从当前高度重新抛起。再次击飞同理：按"起点为当前高度重新抛起"处理，不叠加速度。
   - 按顶点高度抛起时初速 `sqrt(2·g·H)`，从地面起飞的落地步数为 `⌈2·v0/(g·dt)⌉`。

4. **接口**（中立记法）：

   ```
   interface IVerticalMotion {                     // 竖直运动服务（单位载体层）
     isAirborne(unitId: Id): Bool
     getVerticalSpeed(unitId: Id): Number          // 向上为正；不在空中为 0
     launch(unitId: Id, initialSpeed: Number): Bool
     launchToApex(unitId: Id, apexHeight: Number): Bool   // H 为相对当前脚下高度再升高的量
     jump(unitId: Id): Bool                        // 以配置的跳跃高度起跳；被拒绝返回 false，不改变任何状态
   }
   interface ILaunchSink {                         // 击飞提交口（受击裁决 → 竖直运动服务）
     beginLaunch(unitId: Id, apexHeightWorld: Number)
   }
   IUnitAccess.getHeightOffset(unitId: Id): Number // 脚下高度；默认成员，缺省恒返回 0，真实实现覆盖
   ```

   `getHeightOffset` 做成接口的缺省成员而不是必须实现的抽象成员：既有的自写实现不必跟着改，行为等价于"没人读它"。竖直运动服务同时实现 `ILaunchSink`；没有竖直轴的世界里没有 `ILaunchSink` 的实现方，受击裁决的击飞提交口为空，击飞静默不发生。

5. **形状高度与命中高度窗口**：
   - 目标链的形状（圆、扇形、线、矩形四种通用）新增可选字段 `height`（世界单位，必须为正）：命中判定的**高度窗口半宽**。未声明时竖直方向不设限（无限高的柱体）。
   - 目标选择选项 `VerticalHit` 打开时才生效：候选单位脚下高度与锚点（施法者；地面坐标施法的锚点高度取地面 0）脚下高度之差的绝对值不超过 `height` 才保留。空间查询本身仍是平面的，高度过滤发生在来源收集之后、过滤器之前；施法者自己不受影响。
   - 目标选择选项 `SpatialDistance` 打开时，`sort_by.distance` 与"最近"一律按含高度差的三维欧氏距离；关闭时按平面距离，逐位等于改动之前。
   - 两个选项缺省都关；`height` 在选项关闭时被忽略（平面世界里既有链与既有行为逐位不变）。
   - 施法射程检查仍是平面距离（技能管线判定，竖直方向不参与）。

6. **击飞**：
   - 手感档案新增可选的判定型数值字段 `launch_height`（受击组，体型倍数，范围 0～10，缺省无值 = 不击飞）。
   - 受击反应达到 `knockback` 或 `knockdown` 时，击飞顶点高度（世界单位）= 攻击方 `launch_height`（标定后）×（1 − 目标击退抗性）× 冲击等级倍率（与击退距离同一套倍率）。
   - 与击退**同一触发条件、同一提交时机**（顿帧结束后）；但**互相独立**：只有 `launch_height` 没有击退距离也击飞，反过来亦然。
   - 世界没有竖直轴时档案里的 `launch_height` 被忽略；字段本身可以出现在任何档案里，不因世界不同而校验失败。

7. **`space` 取值的含义**（手感实验室场景表，见 [手感设计/06](../手感设计/06_手感实验室与验收.md) 第 1.2 节）：`plane` = 平面世界、不装配竖直轴；`side_2d` = 装配竖直轴与命中高度窗口；`volume` = 装配竖直轴、命中高度窗口与三维距离。`side_2d` 的"深度轴被控制空间锁死"属于宿主的输入处理（把摇杆的竖直分量当深度丢弃），**不进核心契约**：核心层只提供竖直轴、高度窗口、三维距离与击飞四样能力。

8. **本 ADR 不承诺的范围**：斜坡、台阶、天花板、空中控制、空中攻击与空中受击的专属反应、跳跃动画状态、第三人称自由视角（仍属 ADR-0122 的预留）。击飞中的目标不做空中控制。

9. **05 第 3.3 节的修订**：高度偏移的缺省口径（平面世界、纯表现参数）不变，补充"可选的竖直轴能力包装配后，逻辑层按重力积分该值，命中形状高度窗口与三维距离读取它"，并指向本 ADR；05 文档版本递增并追加变更记录。

## 后果

### 正面

- `volume` 与 `side_2d` 从预留标签变成可运行、可验收的能力，且落在核心层的既有模块里（单位载体、目标选择、受击裁决），游戏与实验室用的是同一套实现。
- 全部是加法、缺省关闭：没有声明竖直轴、没有声明 `height`、没有声明 `launch_height` 的世界与数据，行为与基线逐位不变。
- 解析式积分让落地步数可以由重力与初速直接算出，复现用例的期望值不用写裸数。

### 负面

- 高度偏移不再是纯表现参数：竖直轴装配的世界里，逻辑层读它，表现层以外的模块要考虑它的取值。05 第 3.3 节因此有"缺省口径"与"装配后口径"两种读法。
- 地面恒为 0：没有斜坡与台阶，站在平台上的单位表达不了；平台、台阶类需求需要另一份导航与空间查询契约的扩展与 ADR。
- 命中高度窗口用的是命中判定那一刻施法者的脚下高度，不考虑形状自身的竖直偏移（锚点恒在施法者脚下，没有向上或向下偏置）。
- 击飞期间再次被击飞按重新抛起处理，不叠加速度；击飞中的目标没有空中控制。

## 备选方案与为什么不选

- **把高度做成坐标的第三个分量（三维坐标）**：存档、导航、空间查询、碰撞、数据 schema 全部要改，与 05 的平面世界总约定冲突，且绝大多数游戏不需要；否决，高度仍是单位上的一个附加参数，只在能力包装配后被读取。
- **竖直运动由实验室宿主自建**：游戏要用时还得再写一遍，且实验室验证的就不是游戏用的那份实现；否决，落在核心层，实验室只按格子打开。
- **默认开启**：所有既有基线与既有游戏的命中与距离都会变；否决，缺省关闭。
- **逐步累加（欧拉）积分**：帧长不均匀时有积分漂移，落地步数无法由公式直接算出；否决，用解析式。
- **击飞复用击退距离字段**：击退与击飞是两件独立的事（水平推开与竖直抛起），复用会让"只想击飞不想位移"无法表达；否决，独立字段 `launch_height`。
- **高度窗口做成目标过滤器而非形状字段**：高度范围本来就是命中几何的一部分，与形状同处声明更直观，也复用形状已有的 schema 与校验；否决过滤器方案。
- **把深度锁放进核心**：深度锁只是"哪些输入被丢弃"，属于游戏的控制层，核心没有输入语义；否决，留在宿主。

## 魔兽世界的对应做法

魔兽世界是真三维世界（单位带高度坐标，跳跃与击飞是三维位移）。本架构选择平面世界加可选竖直轴，只取其中"跳跃、击飞、命中区分高度"这几样手感相关的行为；"击飞"对应其"击飞类控制"，本架构把它归入受击裁决的反应（与硬直、击退同源）。

## M4 增补（2026-10-03，手感落地 M4-V、M4-W1b、M4-W1a）

本增补取代上面决策 3 的"地面恒为 0：没有斜坡、台阶、天花板，竖直运动不被地形阻挡"与"击飞期间再次被击飞……不叠加速度"、决策 4 的 `beginLaunch` 单一签名、决策 5 末条"施法射程检查仍是平面距离"、决策 8 的"本 ADR 不承诺的范围"，以及后果"负面"里对应的几条。落点仍在核心层的既有模块里，全部是**可选能力、缺省关闭，缺省行为与增补之前逐位一致**；公开签名只增不改（新增的是默认接口成员、重载、可选字段与枚举追加）。

### V：竖直轴能力包补完（M4-V）

1. **地形高度接口**：新增只读纯查询接口 `ITerrainHeight2D`——`getGroundHeight(mapId, point)` 与 `getCeilingHeight(mapId, point)`（后者默认 +∞），缺省实现是平地（地面 0、没有天花板）；竖直轴选项的地形字段缺省为空。数据版实现读 `world.map` 的可选字段 `terrain`（高度区域清单，后声明覆盖先声明），引擎侧另可用物理射线实现同一接口。声明后：落地高度等于落点的地面高度（不再恒为 0），上升碰到天花板时脚下高度夹到天花板、竖直速度清零，地面上走动的单位贴着地面高度（斜坡贴地）。
2. **台阶阻挡走共享阻挡出口**：竖直轴选项的台阶高度（缺省空 = 不阻挡）声明后，移动路径上地面升高超过台阶高度即视为阻挡。阻挡与导航阻挡、运动仲裁阻挡走**同一个出口**——所有导航射线合并地形阻挡点，方向移动沿法线滑动、受控位移按阻挡策略结束、路径跟随以新增的停止原因"地形阻挡"（枚举只追加）结束。
3. **空中控制与多段跳**：`AirControl`（0..1 的比例，空中的普通移动速度按它缩放，0 = 空中不接受移动输入）与 `MaxAirJumps`（泛化"是否允许二段跳"：空中最多再跳的次数，落地清零）。**`AirControl` 缺省为空 = 不限制，而不是 0**：空中不受限是既有行为，缺省取 0 会改变所有带竖直轴的既有运行。
4. **空中姿势**：竖直轴装配后，姿势请求在空中有固定键与固定回落链——`jump.rise`/`jump.fall` → `jump` → `idle`；`jump.land` → `idle`；`hit.air` → `hit.launch` → `hit`；`attack.air[.<族>]` → `attack[.<族>]` → `attack`。**状态枚举不变**，空中姿势只是同一状态的子键，链的末端恒作兜底。空中阶段（上升、下降、落地保持）由表现层按竖直运动服务的状态派生，**纯表现，不回写判定**。另有可选的空中受击反应字段 `air_hit_reaction`：目标在空中时，把反应替换成声明值，排在韧性与冲击等级映射之后、`reaction_cap` 封顶之前，不改 `Death`。
5. **击飞叠加** `launch_stack`（`restart` 缺省 | `add`）与 `launch_stack_cap`：`add` 时新初速 = 当前竖直速度 + `sqrt(2·g·H)`，有上限时夹到上限；`restart` 仍是从当前高度以新初速重新起算。击飞提交口追加带叠加模式与上限的重载，缺省转调旧签名。
6. **目标链形状竖直偏移** `height_offset`（有限数，可为负，世界单位）：命中高度窗口中心 = 锚点高度 + 偏移，容差仍是 `height`；偏移为 0 时与此前逐位一致。
7. **可选三维施法射程**（技能选项 `SpatialRange`，缺省关）：打开后施法射程检查（含地面坐标施法）按含高度差的三维距离。

### W1b：空中战斗（M4-W1b）

1. **空中受击与击飞的补充字段**（全部可选判定型字段，缺省无值）：`air_reaction_cap`（受击方的空中抗性，反应在 `reaction_cap` 之外再受它封顶，取较低者）、`launch_height_cap`（击飞后脚下高度的**绝对高度上限**，攻击方与受击方都可声明，取较小者；与 `launch_stack_cap` 可同时生效）、`launch_body_scale`（受击方的击飞体型缩放，0..10，0 = 不可被击飞）、`air_stun_until_land`（硬直到点后若仍在空中，保持到落地后的那一个 tick 才结束，缺省关）。`air_hit_reaction` 的**声明来源合成**攻击方与受击方：攻击方声明了就用攻击方的（更具体），否则取受击方的。
2. **落地事件 `unit.landed`**：一次飞行（跳跃、击飞、离开平台下落）结束时由竖直运动服务发出，载荷 `unitId`、`height`（落点地面高度）、`airSeconds`（本次离地以来累计空中时间，再次击飞与空中跳跃不清零）、`impactSpeed`（落地瞬间下落速度，非负）。**缺省不发**（竖直轴选项的开关）：缺省发出会改变所有带竖直轴的既有运行的事件总数，可选开启比让既有基线全部重生成稳妥。
3. **受控位移的深度锁**（移动选项，缺省关）：横版二维没有深度，开启后受控位移也只沿横向——击退保持距离、方向取提交方向横向分量的符号（横向分量为 0 时本次击退不位移），技能位移丢弃目标点的深度分量；单位间重叠分离是穿插修正，不是受控位移，不受它约束。缺省关是因为深度锁一直只是宿主输入层的约定，改成缺省开会改变既有横版基线。
4. **动作式结算的射程门**（技能选项 `SpatialRangeHitWindow`，缺省关）：打开后，带时间线的技能在命中窗口每次结算时对 `range > 0` 的技能额外要求"施法者当时位置到目标的距离不超过射程"（距离口径同 `SpatialRange`），不满足的候选被排除——**不是施法失败**，动作已经出手，只是这一击没选中它。让两种结算方式在"谁被命中"上一致。
5. **地面坐标施法的落点高度读地形**：单位访问接口新增默认成员"某点的地面高度"（缺省恒 0），有地形能力时覆盖；三维射程与命中高度窗口锚点据此取落点的真实地面高度。
6. **空中姿势的变体维度与可配落地保持**：空中键可带姿态、武器族、变体维度（形如 `jump.rise.combat`、`hit.air.wounded`），回落链 = 空中键的维度前缀逐段去尾（先变体、再武器族、再姿态）后接固定尾链，不带维度的请求与此前逐位一致。落地保持由呈现型可选字段 `land_hold_ms`（0..2000 毫秒）决定：缺省无值沿用 8 个 tick，0 = 不播落地姿势。

### W1a：地形与导航（M4-W1a）

1. **台阶规则改为滑窗**：窗口长度 = 台阶采样距离，沿线段按弧长 `s` 记地面高度 `g(s)`，贴地行走者在 `s` 处被挡，当且仅当 `g(s) − g(max(0, s − W)) > 台阶高度`。判定与线段从哪里出发、采样格怎么对齐无关；阻挡点与停点二分到 1e-10 世界单位，不再近似到采样间隔。空中单位的参照是当前脚下高度，前方地面比脚下高出超过台阶高度才挡。
2. **地形感知寻路与"无路"**：导航契约追加两个默认接口成员——带台阶约束的 `findPath` 与 `tryFindNearestReachable`；台阶约束接口 `ITerrainStepConstraint` 回答"贴地行走者沿线段第一个被台阶挡住的点"（**有向**：上台阶被挡不等于下台阶被挡）。声明了台阶阻挡时，直线被台阶挡住就绕行，目标被台阶整个隔开则寻路失败（`NoPath`），不再规划出穿台阶的路再被截断；规划器在导航网格上八邻接搜索，由桩、引擎适配层与核心层的开阔场地导航共用同一份。默认实现（没有网格的第三方导航）对旧结果逐段验证约束，有一段被挡就返回空——不静默忽略地形，也不假装能绕行。路径校验同样看地形；路径分段按本 tick 实际走的折线精确扫掠；AI 取下一路点的转向提示与移动层同一口径。没有台阶阻挡时寻路调用与路点序列逐位不变。
3. **单向平台落地**：声明了地形时，落地条件 = 脚下高度不高于地面**且竖直速度不大于 0**。上升中水平进入更高地面（高出不超过台阶高度）不落地，越过顶点后下落时才落在该地面上，所以上升中的单位可以从平台侧面进入并穿过平台面继续向上；天花板仍然碰撞。没有地形时落地条件不变。
4. **`FallHeight`**：走下台地是否下落由新选项决定（缺省 = 台阶高度，没有台阶高度时取台阶采样距离），与能否走上去的台阶高度无关：贴地单位水平位移里地面在一个窗口长度内下降超过它才从脚下原高度以零速度下落，否则贴地跟随。因此无论是否设置台阶高度，走出台地边缘都会下落。
5. **多边形与高度场地形**：`terrain` 条目新增 `shape`：`rect`（缺省，既有数据逐字兼容）| `polygon`（任意**凸**多边形加地面高度与斜率）| `heightfield`（规则网格、格内双线性插值、结点处恰为结点高度，只回答各处多高、不推断台阶）；同表同序，后声明覆盖先声明；几何非法由校验规则报错。
6. **严格的地图绑定**：引擎侧物理射线实现按地图隔离——每张地图绑到各自的物理场景或根对象，两张地图几何完全重叠也互不串；严格模式下没绑定的地图回答"没有地形"，不回落到全局默认，避免多地图工程漏绑时静默串地图。

## M4 增补的后果

- 正面：斜坡、台阶、平台、天花板、空中控制、空中攻击与空中受击、落地事件、靶子主动跳跃都由核心层的可选能力承担，游戏与实验室用的是同一套实现；缺省关闭，没有声明的世界与数据行为与基线逐位不变。
- 负面：移动与路径规划多了一层可选的地形约束（只在声明了台阶阻挡时才触发）；绕行搜索只在两端点包围盒外扩的有限窗口内进行，超出窗口判无路，数据需要把目标放在可达一侧或拆成途经点；台阶规则的分辨率就是采样窗口长度，比窗口更窄的凸起不是它要表达的特征。
- 05 第 3.3 节的"装配后口径"随之补充：地面高度由地形能力给出（缺省平地 0）。
