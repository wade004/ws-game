# ADR-0143 输入层补全

状态：已拍板 2026-10-04（对 [ADR-0115](0115-输入缓冲与动作时间线.md)、[ADR-0039](0039-内容数据schema破坏性变更政策.md)、[ADR-0130](0130-竖直轴能力包.md) 的补全；手感设计对照评审 M5-S1 引入）

## 背景

对照评审把"输入与动作"设计文档与实现逐条核对后，发现输入这一层有七处"设计写了、实现没有或没有对上"的缺口：

1. 摇杆死区、响应曲线、平滑登记在手感档案输入组里，却没有任何读取点（档案字段是判定型，但消费方是输入映射，输入映射读不到档案）。
2. 蓄力只在抬起时才结算，按住超过上限不会自动释放，下限 `min_ms` 只是"比例夹到 0"，没有"不足则取消"的选择。
3. 点按与按住只能共用一个技能，没有"同一个键点按放 A、按住放 B"的变体。
4. 跳跃只是动画状态，没有输入类别，既无跳跃缓冲、土狼时间，也无可变跳高。
5. 格挡、按住冲刺、持续引导这类"按住期间维持"的动作在时间线上没有表达。
6. 取消窗口与连招窗口只按类别开关，不能表达"打中才能取消 / 挥空才能取消"与"只能取消进入哪些技能"。
7. AI 与自动战斗不经输入缓冲，设计文档却写成"同一套规则"。

## 决策

1. **摇杆处理归设备与玩家设置，消费方是输入映射宿主，写在 `found.input_action` 上**：新增 `dead_zone`、`response_curve`、`smoothing_ms` 三个可选字段，由玩家设置覆盖并随设置文件持久化（`input_axis_settings`）；手感档案输入组里的同名三个字段删除。理由：轴处理是"这个设备、这个玩家的手感偏好"，不是"这套角色/武器的判定手感"，放进可被武器与角色层覆盖的档案是错位的；而输入映射不能读档案（依赖方向）。这是 ADR-0039 授权的破坏性变更：被删字段不再登记，常量保留为过时标记，仍携带旧键的数据表照常加载（容错），CHANGELOG 标注并给出迁移。未声明时输出与原始值逐位一致；死区按向量长度做径向死区并把剩余部分重标度到 0～1；`expo` 是幅值平方，`custom:<id>` 走分段线性曲线；平滑只作用于下降沿（满幅回落到 0 的毫秒数），上升与方向变化即时生效，保证一次按下至少一个 tick 的满幅；只作用于模拟绑定（手柄摇杆与轴），键盘合成轴是数字输入不处理。
2. **跳跃成为输入类别 `jump`**：缺省优先级 35（介于 dodge 与 attack/skill 之间），无按住阈值，接受时不是施法而是对竖直轴能力包的起跳请求，只有装配了竖直轴才生效。**跳跃缓冲**就是输入缓冲本身：起跳不成立（空中、不满足条件）时记录留在缓冲里到过期，落地那一 tick 被消费。**土狼时间**走宽限机制：框架内置宽限条件 `input.grace.builtin_grounded`（读 `event.grounded`），动作的 `grace_conditions` 引用它；空中且是"走出平台边缘的自然下落"（区别于起跳与击飞）且宽限窗口内，按地面起跳处理（`JumpFromLedge`，不占空中跳跃次数）。**可变跳高**用动作的 `jump_cut_ratio`：起跳后松键（或起跳时已松键）若仍在上升，上升速度乘该比例。00 总纲第 7 节"土狼时间不在范围内"据此改写。
3. **按住维持型动作用时间线块 `active_until_release{max_ms}`**：判定相走完时，若触发它的输入键仍按着，动作停在判定相末尾维持，直到松键或到 `max_ms`，再进入后摇；松键早于判定相结束则 `active_ms` 是最短判定时长。维持期间发 `sustain_start` / `sustain_end{reason: release|max}` 标记，动作结束时刻平移量等于两者之差，受击打断与取消窗口照常。本决定只管输入与动作层契约；"格挡"的判定（受击裁决怎么看待维持中的动作）属于受击裁决，不在此定。
4. **点按/按住变体靠两个动作定义**：同一个键按持续时长分成两个技能槽位：`skill_slot`（点按）与新增的 `hold_skill_slot`（按住释放），分界只有一个，就是 `hold_threshold_ms`。理由：不引入"一个动作两个行为"的新概念，复用已有的技能槽位绑定与按住阈值，两个技能各自有自己的时间线。缺省两者同一技能，既有行为不变。
5. **蓄力补全**：按住达到 `max_ms` 时记录在缓冲里自动转为"按住释放"（比例 1）并可被消费，同时发 `input.charge_ready` 事件；这修正了总纲里"`charge_ready` 是时间线标记"与"蓄力期间没有动作实例"的自相矛盾——它是缓冲侧的事件，不是动作标记。`min_ms` 变成真正的阈值：`charge.below_min` 取 `release`（缺省，按最低档释放，既有行为）或 `cancel`（缓冲记录丢弃，`input.buffer_dropped{reason: charge_below_min}`，不进入动作）。抬起时按住时长不足按住阈值则仍是点按，与 `min_ms` 是两条独立的门槛：按住阈值决定"是点按还是蓄力"，`min_ms` 决定"蓄力够不够"。
6. **取消窗口与连招窗口增加 `requires` 与 `into`**：`requires: any|hit|whiff`（缺省 any），依据是 `combat.hit_confirmed` 按动作实例的配对（被回避的接触也算命中确认）；取消窗口另有 `into`（目标技能白名单），不在名单里的记录对该窗口不可接受，且不挡住后面可接受的候选。连招块只有 `requires`（接续目标固定是 `next`，不需要白名单）。缺省与既有行为逐位一致。
7. **AI 提交经缓冲是显式开关，缺省关闭**：AI 的技能施放默认仍直接走施法管线（管线里的动作锁、冷却、全局冷却照常生效，没有绕开规则），装配选项 `AiIntentsThroughBuffer` 打开后，AI 的施放改为向缓冲提交一条合成动作（`input.action.ai_cast`）的意图，由同一套缓冲消费规则接受。理由：经缓冲会让 AI 的出手多出一个 tick 的延迟并受缓冲窗口约束，改变既有 AI 基线，所以只做成可选；自动攻击不经缓冲，仍走直接施放。

## 后果

### 正面

- 输入层的设计文档与实现对上：轴处理有消费方，蓄力有上限与下限的完整语义，点按/按住变体、跳跃、按住维持、条件取消都有数据字段、校验与可由规则算出期望值的测试。
- 全部是加法，除决策 1 外缺省行为逐位不变；实验室新增脚本用独立数据根，既有基线只有 `feel_charge` 因决策 5 的自动释放按设计变化（第三次按住超过上限，动作开始提前到上限）。

### 负面

- 决策 1 是破坏性变更：手感档案的三个输入组字段被删，原来写在档案里的值要迁到 `found.input_action` 或玩家设置（此前这三个字段没有任何读取点，所以不存在"迁移后行为变化"，只有数据行需要删去）。
- 平滑只作用于下降沿，不对上升沿做加速度；维持型动作只对由输入键触发的动作生效；AI 经缓冲带一个 tick 延迟——这些边界写进各模块的判断记录。
