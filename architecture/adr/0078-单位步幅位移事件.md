# ADR-0078 单位步幅位移事件

状态：已拍板 2026-09-23

## 背景

消费方反馈第二十批第 2 条（`<game>` 接入方，基于冻结发布提交核实）指出：与移动相关的事件目前只有 `unit.moved`——每次逻辑位置变化都发一条，频率与移动速度/帧率直接耦合，无法当作一个固定节奏信号使用（接入方原想拿它触发一个"走一步响一下"的呈现效果，实测同样的移动距离在不同帧率/不同速度下收到的事件条数完全不同，做不出稳定节奏）；框架现有的数据登记里也没有任何"这个外形一步迈多远"的概念可用。

约束：

- 步幅距离是外形/体型几何属性，与规则层无关，不得进入规则层，不得影响仿真主循环/仿真基线。
- 新事件由表现层派生，不改动仿真主循环，不进规则层，不写回任何逻辑状态。
- **事件名与字段名一律使用"位移/步幅"这层几何状态语义命名，不使用脚步/footstep 这类呈现语义**：同一个"累计位移达到一个步幅距离"的信号，具体游戏可能用来触发脚步声，也可能用来触发扬尘特效、镜头微幅晃动、地面痕迹——与"脚"本身没有必然关系，框架的事件词汇表不应该把某一种呈现用途（声音、且专属双足行走）写进事件的名字里。
- 不引入任何步态/动画概念（左右脚交替、落地帧、行走/奔跑区分）——这些是具体游戏的表现设计，框架只认"累计位移达到声明的步幅距离"这一条几何规则。
- 框架只负责"什么时候发"，不涉及"发出后播什么"：不登记任何默认音效/特效，样例 `feedback.binding` 数据仅作示范，不暗示推荐配置。

## 决策

1. **`display.map` 新增可选字段 `stride_distance`（数字，未登记或 `<=0` 表示该外形不使用本机制）**：登记在 `display.map` 而不是规则层任何属性表——步幅距离是"这个外形一步迈多远"的几何/体型属性，与战斗数值、移动速度等规则层概念无关（一个游戏完全可以让规则层的移动速度随增益变化，而不影响外形本身的步幅几何设定）。未登记的外形（现有全部样例数据的默认状态）保持零开销：不注册任何状态、不订阅位移累计。
2. **新增事件 `unit.stride_completed { unitId, position }`**（`domain=unit`）：由表现层新组件 `Presentation.ViewBinding.StrideEmitter` 订阅既有 `unit.moved`，按事件携带位置与该单位上一次观测位置的欧氏距离累计位移；单位 → 外形的步幅距离解析复用既有 `entity.TemplateId ?? entity.EntityId` 惯例（同 `WorldSim.AddEntity`/`ViewBinder.OnEntityCreated`），查 `display.map` 拿 `stride_distance`，不新建第二套"实体 → 外形"解析路径。累计值达到步幅距离即发一条本事件并从累计值中扣减一个步幅距离（保留余数，不清零——同框架既有"折算保留余数、不产生漂移"惯例，如 `SimTimers.RescaleAll`/`CooldownTracker`），累计值达到步幅距离的整数倍时对应发出多条。未登记步幅距离（或登记为 `<=0`）的单位完全不发本事件，也不维护任何位移累计状态（真正的零开销 opt-in，不是"注册了但阈值不可达"）。
3. **瞬移/大跨度单帧位移的钳制规则：单次 `unit.moved` 位移超过步幅距离的 8 倍即视为瞬移，只发一条 `unit.stride_completed`，并把该单位的累计位移清零（不保留余数）**——普通按"距离 / 步幅距离"整除连续发多条的语义，前提是这份位移确实是连续行走累积出来的；瞬移落地的这一份位移不是行走产生的，"按步幅距离整除"会在瞬移落地的同一帧内刷出大量事件，语义已经不是"走过了若干步幅"。8 倍是本篇拍板的固定阈值（不做成可配置项——阈值本身是表现层派生规则的一部分，不是需要按游戏调参的内容数据；未来若有具体游戏需要不同阈值，走 12 第 5 节扩展流程另开 ADR 收紧或放宽，不在本篇预留配置面）。清零而不保留余数：大位移的"多余部分"不是行走产生的，没有"下一步该扣多少"的几何意义，清零避免下一次正常行走时被这笔跳变位移污染。
4. **09 表现层第 1 节 P2 铁律措辞收窄修订（与 [ADR-0077](0077-ui交互域事件.md) 决策 4 同一次修订，合并叙述）**：`unit.stride_completed` 纳入 P2 允许表现层发出的事件小集合——本事件由已发布的 `unit.moved` 在表现层派生，不携带、也不允许携带任何会被规则层解释为"逻辑判定"的数据（`unitId`/`position` 均是既有 `unit.moved` 已经公开过的同类信息的复述，不产生新的逻辑事实），不写回仿真、不影响仿真基线，与 P2 原有豁免 `presentation.playback_finished` 的理由同一性质。

## 后果

### 正面

- 框架第一次提供一个与移动速度/帧率解耦、按"走了多远"计算的固定节奏信号，接入方可以在其上挂脚步声、扬尘、镜头微晃、地面痕迹等任意呈现效果，框架不预设、不限定具体用途。
- `stride_distance` 是纯几何可选字段，未登记的现有全部样例数据保持逐字节行为不变、零开销。
- 命名与字段完全落在"位移/步幅"几何语义层，不与任何具体呈现用途（声音、双足行走）绑定，避免事件词汇表被单一呈现用途污染。

### 负面

- `display.map` 的字段表再多一行需要长期维护的公开契约（09/04 均需登记）。
- `StrideEmitter` 是表现层新增的常驻订阅组件，`PresentationAssembly` 装配根多一份需要构造/析构的实例，装配复杂度小幅增加。
- 8 倍钳制阈值是固定值，个别游戏若确有不同瞬移判定需求（如传送门频繁触发、单次位移天然就很大的玩法），需要另开 ADR 才能调整，本篇不预留配置面。

## 备选方案与为什么不选

- **沿用消费方原始提名 `unit.footstep`，字段直接叫 `footstep_index`/`foot`（左右脚交替）**：这是消费方按自己的呈现用途（脚步声）提出的命名，直接采纳会让框架的事件词汇表把"脚"这个呈现概念焊死在一个纯几何信号上；同一个信号未来若被同一个游戏或另一个游戏用来触发扬尘、镜头晃动等与"脚"无关的效果，事件名本身就会造成误导。故改用"位移/步幅"几何语义命名，具体怎么用（含是否配脚步声）完全交给消费方的 `feedback.binding`。
- **步幅距离登记在规则层的移动速度/单位属性表**：步幅是外形/体型的几何属性（同一套外形不因装备了移速增益道具就"腿变长了"），与规则层的移动速度是两个独立维度，混在一起会让规则层多承担一个与战斗数值无关的呈现几何概念，也会让"表现层派生事件不进规则层"这条边界失去意义。故登记在 `display.map`。
- **按"距离 / 步幅距离"整除结果作为事件的一个字段（如 `stepCount`）一次性发一条，不逐个扣减触发多条**：能减少事件条数，但会让消费方在一次移动位移较大时错过"逐步触发"的节奏感（这正是该信号存在的意义——固定节奏，不是"这一帧一共走了几步"的汇总汇报），且与瞬移钳制"只发一条"的区分会变得模糊（两者都是"一次性发一条"，语义却完全不同）。故保留逐个扣减、每次都真实过一遍事件分发的实现。
- **瞬移钳制阈值做成 `display.map` 可选字段，允许按外形配置**：能满足个别游戏的定制需求，但阈值本质是"表现层怎么判断一份位移是不是瞬移"的派生规则本身，不是内容数据（同一个外形不会因为策划改了一个数字就改变"多大位移算瞬移"的物理直觉），过早暴露成内容字段会让本该是实现细节的常量变成需要跨表维护的公开契约。故本篇固定为 8，需要时另开 ADR。
