# ADR-0126 定向门禁四级影响集与切片级只跑下游一层

状态：已拍板 2026-10-01

## 背景

门禁（`check.ps1`）只有"全量"与"-Quick"两档，加上提交前钩子里的文档档。日常切片改的往往只是某个子模块内部，
却要等整套编译、全部测试工程、数据校验、工具链自检跑完；agent 为了省时间自己挑着跑，漏跑的又都是凭记忆挑的——
`AGENTS.md` 里"改到某文件必须再跑某个引擎侧用例"这类交互例外就是靠一行文字登记，没有任何机器能查。
团队 AI 转型方案（`docs/团队AI转型方案-2026-10-01.md` 5.1 与 11）要求把"改了什么 → 影响哪些 → 只跑相关的"
变成机器可读、可自检的规则。

## 决策

1. **模块表**：`toolchain/module_map.json` 登记每个子模块一条：路径前缀、所属层、测试命名空间、引擎侧用例分类、
   责任人（初始 `TBD`）、显式交互例外。表由 `toolchain/gen_module_map.py` 从目录结构生成（保留手填字段），
   `--check` 为只读自检并作为门禁步骤"模块表覆盖所有子模块目录"：新增目录没登记即红。
   `AGENTS.md` 里原有的移动/导航例外迁入此表（模块 `unit` 的移动处理文件、模块 `engine_adapter` 的导航契约
   → 引擎侧移动阻挡用例），文字只保留指向表的一行。
2. **四级影响集，取各文件最高级，未知路径一律 T3**：
   - **T0**：文档（含统计原始数据、流水线配置）。
   - **T1**：子模块内部实现 → 编译 + 该层测试工程 + 该模块已登记的交互例外。
   - **T2**：子模块的契约、登记表 schema、公开类型，以及层级范围（决定 9）与适配层运行时/一致性套件（决定 10）
     → T1 + 向下游多看一层 + 公开面兼容探针 + 引擎侧相关分类的用例。
   - **T3**：真正跨层或跨工具链的共享面（构建配置、解决方案与生产工程文件、全局数据根、桩适配层生产代码、门禁脚本与工具链
     自身代码（工具链测试与用例数下限文件除外，见决定 12）、换行属性）与表里查不到的路径 → 全量。
3. **每个门禁步骤的触发规则登记在表里**（`steps`：基础级别、触发路径、前置依赖、是否依赖引擎）；
   T3 等于全部步骤。门禁脚本按判定出的步骤清单执行，被跳过的步骤标 SKIP 并写明"T? 未触发"。
   步骤可登记最低级别（`min_level`）：低于它时触发路径不生效。数值仿真基线比对据此只在 T2 及以上触发——
   T1 只动模块内部，十几秒的基线比对与其收益不成比例；仿真自己的输入数据与基线文件
   （`core/sim/tests/data`、`core/sim/tests/baseline`）单独登记为不受最低级别限制的触发路径，改了就必须比对。
4. **判定脚本** `toolchain/change_impact.py` 输出 JSON（级别、命中模块、测试工程、步骤、引擎分类、逐文件理由），
   由 `check.ps1` 的 `-Changed <基线>`（默认 main）、`-Staged`、`-Modules a,b`、`-DryRun` 触发，先打印"本次判定"块；
   不带这些参数时行为与此前完全一致。判定脚本自带不变量用例：级别单调、未知路径为 T3、T3 跑全部步骤、
   脚本里的步骤编号与表一一对应。
5. **日志分流**：全文输出落盘到产物目录；控制台只留每步一行、汇总表、首个失败步骤的最后 30 行。
6. **引擎侧分类**：每个引擎侧用例类标 `module:<模块名>` 分类（归属不明的标 `module:shared`，T2 及以上必跑）；
   引擎测试框架的分类过滤与名称过滤是"且"关系，交互例外因此也表达为一个独立分类，而不是追加类名。
   agent 不能开引擎：判定块给出待跑过滤串，由主会话在主检出执行。
7. **提交前钩子**改为调用 `check.ps1 -Staged -SkipUnity` 由判定脚本统一判级；原文档档即 T0。
   T3 沿用此前 Full 档的 `-Quick`，保持提交前秒级把关的口径。发布提交的跳过档位不变。
8. **定向模式下的用例数下限**：全量下限不适用于子集，改为"失败为 0、通过至少 1、跳过数不超过上限"。
9. **层级范围（仍记 T2）**：层内共享面（每层的 `common`、`assembly` 目录）与层根文件（层根目录下的源文件、层标记文件）
   不属于任何子模块，但只被本层与下游通过本层程序集使用，与"切片级只看下游一层"同一取舍——改它们按层级范围处理：
   本层测试工程 + 下游一层测试工程 + 公开面兼容探针 + 引擎侧该层所有模块的分类（加归属不明的共享分类）。
   生产工程文件、解决方案文件、全局构建配置不在此列，仍是 T3（它们改动的是全部工程的编译条件）；测试工程文件见决定 12。
   共享目录里的 `tests` 子树只影响所在层的测试工程，保持 T1。
10. **适配层与其它路径按真实引用关系判级**，登记在模块表的路径规则段（路径类别 -> 级别、额外要跑的测试工程、引擎侧分类、
    额外步骤；同一路径命中多条规则取并集，规则可带排除项使工程文件仍归 T3）。判级依据是工程文件的编译包含/工程引用与
    程序集定义的引用，不是猜测；"所列测试工程必含改动文件自己所在的测试工程"作为不变量用例由脚本对全仓库逐文件核对：
    - 一致性套件：被基础层测试工程直接编译、被引擎侧用例引用 -> T2，基础层测试工程 + 引擎侧一致性相关分类 + 引擎编译与编辑态测试。
    - 桩适配层的专项测试：只被基础层测试工程编译 -> T1；桩的生产代码被所有测试工程引用，仍是 T3。
    - 引擎侧测试：运行态测试只改某文件 -> T1，只跑该文件自己标注的分类（文件里没有分类标注则保守跑全部运行态测试），
      不涉及任何编译与单元测试工程步骤，也不同步核心程序集（前提是程序集已与源码同步）；编辑态测试 -> T1，只跑编辑态测试。
    - 引擎侧运行时与编辑器代码 -> T2：引擎编译 + 相关分类（目录面太宽的整套运行态测试）+ 消费方演练 + 核心程序集同步；
      被诊断转发工程按引用编译的三个源文件另跑该工程的单元测试。
    - 游戏模板 -> T1：模板数据校验 + 消费方演练；资产目录 -> T1：占位资产一致性、样例导入幂等、导入检查；
      流水线配置 -> T0；忽略规则与提交前钩子 -> T1：门禁自检 + 钩子相关测试子集。
    - 引擎侧工作台工程内容（场景、项目设置、第三方资源）与引擎侧包清单、目录元数据仍按未知路径 T3；其中包清单与目录元数据
      在覆盖自检里登记为允许保持 T3 的少数文件。
11. **路径规则的自检**：门禁步骤"模块表覆盖所有子模块目录"同时校验路径规则（id 唯一、引用的测试工程/步骤/分类存在、
    每条规则至少匹配一个受版本管理的文件），并要求登记的覆盖根目录下的文件不得落到"未被任何规则覆盖"——新增适配层/模板/
    资产子目录而忘了登记规则即红。

12. **测试工程文件与工具链测试**：
    - 各层测试工程文件（含表现层测试工程）按它所在层的层级范围记 T2；诊断转发测试工程文件不属于任何核心层，只跑它自己的测试工程，
      同记 T2（没有层就没有公开面兼容探针）。生产工程文件、解决方案文件、全局构建配置仍是 T3。
      不变量用例对全仓库逐个工程文件核对：测试工程文件恒为 T2 且所列测试工程含它自己，其余工程文件恒为 T3。
    - 工具链的测试目录与门禁用例数下限文件记 T1，只跑工具链测试步骤（外加秒级自检步骤，不跑 dotnet、不跑引擎侧）；
      工具链目录下其它路径（脚本、模块表、判定脚本、探针工程）仍是 T3。改了用例数下限文件但没跑工具链测试就不会知道下限是否合理，
      所以它必须带上工具链测试步骤。

## 权衡（明确接受的风险）

**切片级只向下游多看一层；更远处的风险由里程碑全量回归兜底。** T2 改契约时，直接依赖它的下一层会被带上，
再下一层及更远的消费者不在本次切片里跑。理由：全链路下游几乎总是接近全量，等于取消定向；
而里程碑收口、升级依赖、合并到主线前后这三个时刻本来就要跑全量（`AGENTS.md` 回归分级）。
层级范围与适配层规则沿用同一取舍，另有两处明确接受的风险：一是层内共享面（含装配层）与层根文件、测试工程文件的改动只带下游一层，
最终结论是切片级就按此判级、不为装配入口另跑全量，装配入口与多模块共享数据改动的更远处影响由合并到主线前后各一次的全量覆盖
（`AGENTS.md` 回归分级把全量时刻定为里程碑收口、升级依赖、合并前后三种，不再单列"改了装配入口"）；
二是引擎侧运行时目录到分类的对应是登记表里的人工判断（目录面窄的给分类，宽的给整套），漏项由里程碑全量兜底；
引擎侧测试文件的分类取自文件自己的标注，辅助文件没有标注时保守跑整套。
代价是：跨两层以上的隐式依赖若在切片里被打破，要到里程碑才暴露。

## 后果

- 新增子模块目录必须登记模块表，否则门禁自检红；新增引擎侧用例类必须带模块分类，否则自检红。
- 表里没有的路径（引擎侧工作台工程内容、项目设置、包清单、根目录零散文件等）按 T3 全量，宁可多跑不漏跑。
- 引擎侧分类过滤已在路径足够短的工作树里实测：多个分类用分号分隔是并集，同一个类带两个分类时合跑不重复计数；
  深层临时工作树不能跑引擎侧步骤，那类任务的引擎侧交主检出执行。
- 回放（消费方反馈修复期区间与最近 30 次提交，含规则落地前后对比）的分级分布见 `toolchain/README.md`"定向门禁"一节的判断记录。
