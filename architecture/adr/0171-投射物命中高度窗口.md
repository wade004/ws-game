# ADR-0171 投射物命中高度窗口

状态：已拍板 2026-10-08（来源：`docs/消费方反馈/消费方反馈-2026-10-08-样板游戏D-缺口.md`；纯加法，不声明窗口时命中判定逐位不变）

## 背景

投射物的命中判定是平面的：飞行线段对候选单位平面位置的线段/圆相交，单位的高度（竖直轴的离地高度）不参与。横版游戏里"贴着地面推过来的冲击波，起跳就能越过"是核心玩法，样板游戏 D 的首领冲击波要求"玩家跳起来不挨打"。当前没有办法让一发投射物只打脚下贴地的单位：玩家在空中时平面位置照样在飞行线段上，照样命中。

## 决策

1. **投射物参数新增可选对象 `hit_height`**：`{min?, max?}`，数值是相对**发射者发射瞬间脚下高度**的偏移（世界单位），生成时换算成绝对高度存进投射物簿记。声明后，只有脚下高度（`IUnitAccess.GetHeightOffset`）落在 `[min, max]`（含边界，浮点容差 1e-9；缺一端即该端不限）里的单位才会被命中。例：地面冲击波 `{"max": 0.5}`——脚下高度不超过发射者脚下 + 0.5 的单位挨打，起跳超过 0.5 的单位越过。
2. **高度过滤出现在所有单位命中出口**：飞行线段命中（含穿透、命中钩子路径）与 `impact_on_expiry` 的范围判定。不做高度过滤的投射物（缺省）逐位不变；没有竖直轴的世界所有单位高度为 0，窗口含 0 即通过。
3. 技能数据校验：`SkillSchemas` 的投射物参数登记 `hit_height` 对象及 `min`/`max`。

## 后果

- 新增数据字段，纯加法；既有数据与代码路径不变。
- 越过冲击波的判定在高度上是"脚下高度"瞬时值，不是脚底到头顶的体积：一次离地超过窗口上沿的瞬间就不再命中，不做"身体穿过窗口"的体积判定。

## 限制（已知，随各模块判断记录登记）

1. 窗口只比较候选单位的脚下高度，不考虑单位自身的高度（体积）：很高的单位站在窗口外但身体伸进窗口时不会被命中。
2. 窗口相对发射者发射瞬间的脚下高度固定，发射后发射者再升降（或脚下平台移动）不影响已发射的投射物。

## 备选方案与为什么不选

- **按层（图层/过滤标签）命中。** 需要给单位加层属性并在数据里维护，横版"跳过去"本质是高度判断，用高度窗口表达更直接。
- **冲击波由游戏做成每帧检测的区域效果。** 绕开投射物宿主，自建平行机制；命中去重、关系筛选、命中钩子（无敌窗口）都要重做一遍。
