# ADR-0096 运行时解码贴图带多级渐远链

状态：已拍板 2026-09-26

## 背景

消费方反馈第四十二批（`<game>` 接入方，基于 v1.77.0 冻结发布提交核实，阻塞）：源资产密度高于屏幕
实际显示密度时（如高分辨率屏幕下角色按远小于 1 倍缩小显示，常见于俯视角/远景摄像机），贴图欠采样
锯齿明显，相机或物体移动、缩放时贴图闪烁。

落地期核实结论：已落地引擎适配层三条运行时解码贴图的路径——地图分层图、精灵集静态图像、逐帧
动画/特效序列帧图集——构造纹理时统一固定不生成多级渐远链（mip 链），全仓搜索确认没有任何一处
读取纹理采样相关配置。缺 mip 链是欠采样与移动闪烁的直接成因：屏幕像素小于纹理texel 时，没有预先
生成的低分辨率级可采样，只能退化为直接点采样源纹理，产生摩尔纹与像素闪烁。

## 决策

1. **默认对三条解码路径开启 mip 链**：地图分层图、精灵集静态图像、逐帧动画/特效序列帧图集，构造
   纹理时默认生成完整 mip 链；解码后核实生成结果（`mipmapCount > 1`），个别平台/纹理格式组合未能
   生成时记一条诊断，不视为加载失败（画质降级，不是资源不可用）。
2. **过滤模式默认三线性，地图分层图额外声明各向异性等级**：默认三线性过滤（mip 级间插值，缓解
   mip 切换边界的突变观感）；某条路径本次解码未开启 mip 链时，若过滤模式仍是默认三线性，自动降级
   为双线性（三线性没有 mip 级间数据可插值时等价于双线性，直接采用比依赖引擎自身隐式行为更明确），
   显式配置为其它取值时原样保留。地图分层图默认声明各向异性过滤等级为 4——地图按世界矩形整体
   拉伸摆放，观察角度导致的贴图倾斜比角色精灵更常见，各向异性过滤收益更明显；其余两条路径不声明
   各向异性等级，保持引擎默认。
3. **逐帧动画开启 mip 链时按帧切成独立纹理**：mip 链按整张纹理生成，若继续让同一图集内的全部帧
   共享一张纹理，某一帧的低级 mip 会掺入图集内相邻帧的像素（"渗色"），缩小观察时一帧会隐约显现
   邻帧内容。开启该开关时，图集解码后只作为像素来源，按帧矩形切出的像素各自写入一张该帧专属尺寸
   的独立纹理并生成 mip 链，图集本身随即销毁；关闭时保持全部帧共享同一张图集纹理、不生成 mip 链
   的既有行为，逐字节不变。
4. **公开可配置开关，默认全开**：三条路径是否生成 mip 链、过滤模式、地图分层图各向异性等级，
   收拢进一个新增的公开可写选项集合，供极端场景（如内存吃紧的低端设备）按引擎适配层实现整体关闭；
   不新增运行时资源加载提示项——是否生成 mip 链是引擎侧渲染质量策略，不是某个具体资源的属性，
   不需要调用方逐资源声明。只影响此后新解码的资源，不回溯已经解码并缓存的贴图。
5. **范围**：只影响运行时从原始图像字节解码出的贴图（地图分层图、精灵集静态图像、逐帧动画/特效
   序列帧图集）。已经过资产管线预先导入的资源种类（字体、三维模型、动画剪辑）由引擎资产管线自身
   的导入设置管理采样参数，不在本决策范围内。

## 后果

### 正面

- 根治源资产密度高于屏幕显示密度时的欠采样锯齿与移动/缩放闪烁，默认开启，无需游戏内容侧配合。
- 保留公开开关，极端场景可整体关闭，不锁死后续调优空间。

### 负面（行为变更，需在发布说明标注）

- 显存占用上升：mip 链本身在未压缩格式上的固定开销、逐帧动画独立纹理不再共享图集内存，典型逐帧
  动画显存开销上升约三分之一。
- 逐帧动画开启独立纹理后，加载时新增一次 CPU 端像素拷贝（按帧从图集读取像素块），首次加载耗时
  略有上升。
- 已知限制：只影响此后新解码的资源，不回溯运行期已缓存的贴图——需要重新加载资源（卸载后再次
  加载，或重启加载器实例，如重进场景）才能应用变更后的配置。

## 备选方案与为什么不选

- **只对地图分层图开启，逐帧动画/特效序列帧图集维持现状**：地图分层图确实是欠采样最明显的场景
  （整张贴图按世界矩形拉伸，缩放比例最大），但角色远景缩小同样命中消费方反馈描述的场景，遗漏会
  让同一问题在另一条路径上继续复现，不是彻底修复。
- **逐帧动画开启 mip 链但不切成独立纹理，接受帧间渗色**：实现更简单，但渗色在慢速播放或近距离
  观察时肉眼可辨，属于把一个视觉缺陷换成另一个视觉缺陷，不是真正的修复。
- **新增 `ResourceLoadHints` 项逐资源声明是否要 mip 链**：是否生成 mip 链本质是引擎侧渲染质量
  策略（与屏幕分辨率、观察距离相关），不是资源自身固有的属性，按资源声明会让同一份资源在不同
  项目/不同画质档位下需要维护多份加载调用，不如在加载器层面集中配置。
