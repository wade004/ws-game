# ADR-0106 单位级资源下限覆盖

状态：已拍板 2026-09-28

## 背景

消费方第五十五批反馈：需要一个生物模板（训练用假人一类"持续挨打但不死"的单位）能够持续承受伤害
事件——伤害结算、飘字、受击表现照常发生，但该单位的生命值永不归零、永不触发死亡结算；同一数据集
其余单位的死亡结算逐位不变。

现状：资源类型的下限（`min`）登记在资源类型定义本身（`arch.power_type.min`），是该类型下**全部**
单位共用的同一个值；生物模板没有任何按单位覆盖某个资源类型下限的手段。免疫机制会整体吞掉伤害事件
（不落地、不发伤害事件），不满足"伤害事件与受击表现照常"这一要求；在死亡结算处按单位特判"是否为
训练假人"则会让战斗结算逻辑为一种内容用途反复长出特例分支。

## 决策

1. **资源池契约新增单位级下限覆盖**（默认接口成员，纯加法）：为某单位的某资源类型设置/清除一个
   覆盖下限，覆盖值必须落在 `[该资源类型定义的下限, 该单位当前上限]` 区间内，否则报错；未提供覆盖
   的单位/资源类型行为不变（回落到资源类型定义的下限）。
2. **资源池全部夹取出口统一改读"覆盖下限，缺省时回落到定义下限"**（唯一取值来源，不新增第二套
   逻辑）：初始值、修改值下界夹取、上限下降后的再夹取、"跌到下限"判定（决定是否发出"资源耗尽"
   事件）均经这一处。设置覆盖时若当前值已经低于新覆盖值，立即按既有"落值+发事件"出口夹上去。
   单位注销时覆盖随之清除。
3. **生物模板新增可选字段**：单位级资源下限覆盖表（资源类型 → 下限值）。生物生成流程在把该单位
   登记进资源池之后，逐条把这张表写成上面第 1 条的覆盖。键必须是已登记的资源类型，值必须不低于
   该资源类型定义的下限——前者由数据引用完整性校验覆盖，后者是跨记录数值约束，登记层元数据无法
   表达，由内容专属校验规则补一条检查项，给出带具体 id 的诊断，不静默放行。
4. **战斗结算与伤害事件不改**：伤害事件携带的数值仍是结算算出的原始量（夹取前），生命值被夹在
   覆盖下限之上，"降到 0 判死"这条既有判定自然不会触发，不需要在死亡结算再加一条"读取单位专属
   生命下限"的特判分支。选这条而不是后者的理由：本决策对任何资源类型都通用（不止生命值），且不
   在战斗结算路径为一种内容配置反复叠加特判——覆盖只发生在资源池这一层，战斗结算继续只认"资源池
   给出的当前值"。

## 后果

### 正面

- 支持"单一模板持续挨打但不死"这一常见的训练假人/教程类内容需求，且不影响免疫、伤害计算、飘字、
  受击表现等既有链路——伤害是否落地、落地多少完全按既有规则计算，只是落地后的当前值被夹在一个
  按单位配置的下限之上。
- 覆盖机制是资源池的通用能力，不与"生命值/死亡"绑定，未来任何资源类型都可以用同一套字段配置
  单位专属下限。
- 纯新增契约成员与数据字段，公开签名不变；未配置该字段的既有生物模板行为逐位不变。

### 负面（已知限制）

- 若生成流程按数据配置只把该单位注册为一部分资源类型（而不是数据集内全部已登记资源类型），而
  覆盖表引用了未被注册的资源类型，设置覆盖会因"该单位未持有这个资源类型"直接报错终止生成——
  覆盖表只校验"值是否合法"，不校验"这个资源类型是否真的会被这个单位注册"，两者是两个独立的
  配置维度。
- "资源耗尽"事件的判定同样改按覆盖后的下限计算：跌到覆盖下限仍会正常触发一次该事件（语义是
  "跌到这个单位当前生效的下限"），只是战斗结算判死不读这个事件、只读当前值，因此不影响"不死"
  这一效果；若已有消费方把该事件当成死亡的同义信号使用，需要知道语义已经从"跌到全局下限"变为
  "跌到本单位生效的下限"。

## 备选方案与为什么不选

- **免疫**：会整体吞掉伤害事件，不满足"伤害事件、飘字、受击表现照常"这一要求，不选。
- **死亡结算按单位读取专属生命下限（在结算路径特判）**：只对生命值这一种资源类型有效，且把一种
  内容配置需求做成了结算逻辑里的常驻分支；下限覆盖放在资源池层，对全部资源类型通用、结算路径
  不知道也不需要知道"这个单位为什么死不了"，不选。
- **生成流程按覆盖表实际引用的资源类型反推注册集合**：会让"注册哪些资源类型"这一决策依赖"配了
  哪些下限覆盖"这另一个正交维度，两者语义不同（前者决定"有没有这个资源池"，后者决定"这个资源池
  能不能跌到 0"），混在一起会让数据的因果关系变得难以阅读，不选；已知限制里的报错行为按现状
  保留，留给内容作者自己保证两处配置一致。
