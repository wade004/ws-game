# ADR-0082 UI 套件皮肤覆盖注入点

状态：已拍板 2026-09-24

## 背景

消费方反馈第二十七批（阻塞）：消费方想给框架自带的若干参考面板（角色属性、对话框，以及同根因的
技能书、设置、存档槽、暂停菜单、商店）换皮，做不到。这些面板全部是不可再派生的密封面板类型，内部
直接调用同一套控件构建工具集里的"建面板背景""建按钮""建文本标签"三个静态方法，这三个方法内部
统一读取一个静态皮肤类型的只读默认值（字体、基础色板、运行期生成的九宫格占位背景/纯色占位精灵），
该静态皮肤类型没有任何公开写入口。消费方代码从未参与、也无法参与面板内部这几次构建调用，因此不存在
任何注入点。

落地期核实结论：控件构建工具集里实际读取该静态皮肤类型的方法一共四个——"建面板背景""建按钮"
"建文本标签"，以及消费方反馈未点名、但同样读取该静态皮肤类型（经"建面板背景"间接读取九宫格背景，
并直接读取纯色占位精灵）的"建进度条"；消费方点名的两个面板之外，另有若干面板还会绕过控件构建工具
集、直接读取该静态皮肤类型的纯色占位精灵与强调色（设置面板的滑条填充），一并纳入本次范围。

## 决策

1. **注入点开在静态皮肤类型本身，不开在控件构建工具集的方法签名上**：被卡住的面板是密封类型，
   消费方永远没有机会调用控件构建工具集的方法、也就永远传不到任何"可选覆盖参数"。唯一能拦到"面板
   建出来时用什么颜色/精灵/字体"这件事的位置，只有这几个方法（含直接读取该静态皮肤类型的面板内部
   代码）背后统一读取的那个静态皮肤类型自身。消费方反馈原文把"给方法加覆盖参数"与"在皮肤类型上开
   写入口"并列为两个等效方案——核实后只有后者成立，前者对消费方来说到不了。
2. **单一安装点，逐项可空覆盖**：静态皮肤类型新增一个可安装的"当前皮肤覆盖"，覆盖面完整对齐消费方
   点名的全部内容——面板九宫格背景精灵、纯色占位精灵、字体，以及消费方点名的全部颜色（面板背景、
   面板边框、文本、强调、禁用、危险、按钮常态、按钮悬停）。覆盖对象的每一项都可以留空；留空的项，
   皮肤类型继续提供改动前的默认值，行为逐字节不变。
3. **每次构建控件时现场读取覆盖值，不缓存覆盖结果**：九宫格背景精灵/纯色占位精灵/字体的默认值本就
   是运行期现造的对象，改动前就用"首次访问时生成、此后复用"的惰性缓存避免重复生成。这份缓存只服务
   于默认值分支——安装皮肤覆盖之后的每一次读取都先判断覆盖是否存在，命中覆盖直接返回覆盖对象本身
   （覆盖对象由消费方一次性构造好，皮肤类型不对它做二次缓存），不会被默认值那份缓存吃掉。即使消费
   方的代码在安装覆盖之前已经访问过一次皮肤类型（触发默认值缓存生成），之后安装覆盖仍然对随后新建
   的面板生效——这正是消费方反馈原文描述的真实使用顺序，也是本决策要专门验证的边界。
4. **确定性的复位路径**：新增一个卸载覆盖的入口，调用后立即、确定性地恢复改动前的默认值，供验收
   用例与消费方在运行期切换皮肤/恢复默认时使用。
5. **控件构建工具集里全部四个读取该皮肤类型的方法，以及面板内部直接读取该皮肤类型的既有代码，均
   不改动一行**：因为注入点开在皮肤类型自身（决策 1），这些方法与面板代码原样读取皮肤类型暴露的
   同名只读值即可自动感知覆盖，不需要为"覆盖是否生效"专门去改调用方。
6. **不解除面板的密封限定，也不改面板类型的公开构造签名**：本次改动的范围严格限定在"皮肤从哪里
   来"这一件事，面板本身"能不能被继承""构造签名收不收参数"不在消费方反馈第二十七批的诉求范围内，
   也不是解决"换皮做不到"这个问题的必要条件——解除密封/加构造参数只会引入新的兼容面，不额外解决
   任何本次反馈提出的诉求。

## 后果

### 正面

- 消费方现在可以在运行期安装一套完整或部分的皮肤覆盖，全部内部引用该静态皮肤类型的面板（含消费方
  点名的两个与同根因的其余若干个）建出来的背景、按钮、文本、进度条外观立即改用覆盖值，不需要框架
  再为任何具体面板单独开洞。
- 未安装覆盖时行为与改动前逐字节一致（默认值路径的生成方式、缓存时机均未改变）。
- 复位路径确定性，不依赖重启进程或重新构建整个面板树。

### 负面 / 显式取舍

- **已经建好的面板不会因为安装/卸载覆盖而回溯重建**：本次只解决"新建的面板从哪里取皮肤"，不引入
  "皮肤变了，全局已存在的界面元素跟着重新刷一遍"这一层——面板体系目前的绑定方式是"每帧由持有方
  主动调刷新"，不是订阅通知，皮肤覆盖也不打算额外造一条"变更广播"机制。消费方需要新皮肤覆盖到
  已经打开的旧面板时，自行关闭重开（或整体重建面板宿主），这是消费方反馈落地范围内的显式取舍，不是
  遗留缺口。
- **不覆盖到画面上尚未出现过引用的进度条/按钮着色明细**（如控件的悬停/按下过渡色阶）：本次覆盖面
  对齐消费方点名的静态皮肤类型只读值清单本身，凡是这份清单之外、由控件在自己内部再算一层派生色的
  细节（例如按钮悬停态相对常态的固定倍率），不在本次范围，需要覆盖到这一层留待消费方后续有具体诉求
  时再评估。

## 备选方案与为什么不选

- **给控件构建工具集的三个方法加可选覆盖参数**：消费方反馈原文提出的另一个方案。核实后否决——这些
  方法只被密封面板类型内部调用，消费方没有任何机会传参数进去，加了也用不上，见决策 1。
- **解除面板的密封限定，允许消费方继承覆写**：能达成换皮目的，但换皮这一件事不需要打开继承这个更大
  的口子——继承覆写同时把面板的内部布局细节暴露成事实上的公开契约，往后任何一次内部实现调整都可能
  波及消费方的派生类，波及面比"在皮肤类型上开一个写入口"大得多，故不选。
