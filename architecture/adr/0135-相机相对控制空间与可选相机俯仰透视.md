# ADR-0135 相机相对控制空间为输入映射的可选能力，相机俯仰与透视仅在声明时启用

状态：已拍板 2026-10-03（对 [ADR-0012](0012-表现形态双外形类型加固定镜头.md) 固定镜头的追加决定与输入映射的能力补充；手感落地 M4-W4 引入，取代 M4-H 在实验室宿主里的临时换算）

## 背景

第三人称或带俯仰角的游戏里，摇杆"向上"的意思是"朝相机前方走"，而不是"朝世界 +Y 走"。框架缺省的控制空间是世界相对：轴值原样当世界方向。M4-H 的实验室宿主为了在引擎侧验证相机相对移动，在宿主层自己做了一道换算——这是一份只有实验室能用的换算，游戏要用还得再写一遍，且游戏自己的换算与实验室验证的未必同一份。

同时，相机适配器此前只有正交俯视（固定俯角 90 度）这一种姿态；要让第三人称游戏用上框架相机，需要固定俯仰与透视投影，但这两者会改变既有游戏的画面，必须显式声明才生效。

## 决策

1. **控制空间是输入动作的可选字段**：输入动作新增可选字段 `control_space`，取值 `world`（缺省）或 `camera_relative`，只对二维轴动作有意义；取值非法、或对非轴动作声明 `camera_relative` 都在声明期被拒绝。

2. **相机朝向走独立的可选接口，不改必选相机接口**：相机朝向查询接口只有一个属性——偏航角。约定偏航逆时针为正，0 表示屏幕上方是世界 +Y；相机的右轴为 (cos, sin)，上轴为 (−sin, cos)。接口独立成可选能力（探测写法"相机是否同时实现该接口"），不给必选的相机契约加成员，旧相机实现与第三方实现不受影响。桩相机与引擎适配层相机都实现它。

3. **换算在输入映射层，每次更新取样**：声明为 `camera_relative` 的轴动作，每次更新时把轴值 (x, y) 旋转成世界方向 `x·右轴 + y·上轴`，模长不变；偏航每次更新都取样，不在声明时固定。偏航恰为 0 时与不换算逐位相同；不声明控制空间的动作、没有配置朝向查询的宿主，行为与此前逐位一致。

4. **声明了却没有朝向来源是声明期错误**：声明了 `camera_relative` 动作而宿主没有给输入映射配相机朝向查询，声明动作集时直接报错，不静默当成偏航 0——静默恒等会造成"方向全错但看不出来"。表现装配只在相机实现了朝向接口时才给输入映射配朝向查询；无头宿主不提供相机朝向，格子按 `world` 运行。

5. **相机相对只依赖偏航，不需要俯仰**：相机俯仰绕右轴旋转，右轴恒在世界平面上，"屏幕上方"在世界平面上的投影恒为 (−sin, cos)，所以俯仰下换算仍然正确，输入映射不需要知道俯仰。（[ADR-0161](0161-自由第三人称镜头俯仰范围声明焦点高度地面避让与脚本携带控制空间.md) 精化：俯仰范围可由游戏声明越过水平；越过水平后"屏幕上方"的投影翻号，稳定语义是"摇杆向上 = 朝相机水平视线方向走"，它仍只由偏航决定，本条结论与换算公式不变。）

6. **相机俯仰与透视是相机适配器的可选能力，显式声明才生效**：
   - 固定俯仰：0 度为正俯视，增大则相机向 −Y 侧后倾，夹在 [0, 89] 度。
   - 透视投影：视场角缺省 40 度，夹在 [10, 120] 度；缩放含义保持"焦点处地面的可视半高"，相机距离随之按视场角换算，因此按画面高度比例计的镜头冲击幅度在正交与透视下语义一致。
   - 两者都不声明时，相机逐位保持正交俯视；渲染物仍躺在世界平面上，**不做精灵站立（billboard）**——那是渲染层的取舍，不在相机里偷偷做。

## 后果

### 正面

- 第三人称与俯仰角游戏直接声明 `camera_relative` 就得到正确的移动方向，不再各自写换算；实验室验证的就是游戏用的那份实现。
- 全部是加法、显式声明才生效：既有游戏的输入与画面逐位不变，必选相机契约不变。
- 声明期报错把"忘了配朝向"变成立刻可见的错误。

### 负面

- 控制空间是动作级声明，同一游戏里世界相对与相机相对的动作要分别声明。
- 透视下渲染物仍是躺在世界平面上的，想要精灵站立的游戏需要在渲染层自己处理。
- 偏航每次更新取样，相机在同一 tick 内的偏航变化要由相机实现自己保证与模拟步对齐。

## 备选方案与为什么不选

- **继续在宿主层换算（M4-H 的做法）**：每个游戏重写一份，且与真实相机可能不一致；否决，原生进输入映射。
- **给必选相机契约加偏航成员**：自写相机实现全部要改，违反"契约只加不改"；否决，独立可选接口。
- **没有朝向来源时静默按偏航 0**：方向全错却看不出来；否决，声明期报错。
- **输入映射也感知俯仰**：换算只依赖偏航，多一个输入没有收益；否决。
- **默认相对相机**：既有游戏的移动方向全部改变；否决，缺省 `world`。
- **俯仰与透视默认开启**：既有游戏画面全变；否决，显式声明。

## 魔兽世界的对应做法

魔兽的移动是相机相对的：前进键沿相机水平朝向，转动相机即改变前进方向。本架构缺省保持世界相对（固定镜头游戏不需要相机相对），相机相对作为动作级可选声明提供，取其"相机偏航决定摇杆方向"的行为。
