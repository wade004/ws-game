# ADR-0102 追击规划点不可达时采样候选站位点

状态：已拍板 2026-09-27

## 背景

消费方第四十九批反馈 2（阻塞，复现脚本只读复核成立）：追击系统重新规划路径时只算一个"直接回退
点"——目标当前位置沿"追击单位→目标"方向回退停止距离得到的一点，寻路失败即视为"到不了"（
[ADR-0097](0097-以单位为目标的追击移动请求.md) 决策 5）。加了物件静态阻挡后，站在物件旁的目标
从被挡一侧被追击时，这一个点常落在不可走格上，追击单位因此原地不动、直接放弃，即便目标自身所在
格可走、停止距离圆上大多数方向也都可走。消费方统计：地图上多个生物周围的候选站位点里，相当比例
落在不可走格，但每处几乎都能在圆上找到别的可走方向。

## 决策

1. **先直接点，失败再采样**：重新规划路径时仍先尝试原有的直接回退点；寻路成功时行为与此前逐字
   一致，不引入任何额外开销或延迟。
2. **直接点失败后，在目标周围按停止距离采样候选站位点**：以目标当前位置为圆心、停止距离为半径，
   从"正对追击单位的方向"（直接回退点所在角度）起，按左右交替外扩的角度序列（`+δ, -δ, +2δ, -2δ,
   …`，`δ = 2π / N`）依次生成候选点并寻路，取第一个寻路成功的（角度偏移最小即绕路最短）。候选
   点个数 `N` 由新增的可选配置项决定，默认 16；不采样直接回退点本身重复的角度（已经单独试过），
   只补齐圆上其余 `N − 1` 个候选。
3. **候选点个数可配置**：新增配置项，`≤ 1` 时不采样，行为与本决策落地前逐字一致——供不需要本能力
   的既有游戏零成本跳过。未装配寻路能力时同样不采样（直接连线不存在"寻路失败"这一分支）。
4. **全部候选都失败才判定为"到不了"**：仍按 ADR-0097 决策 5 的口径——触发一次寻路失败通知、结束
   本次追击，不重复通知、不静默重试、不引入新的通知原因或事件类型。
5. **追击单位自身站在不可走格：不处理，仍按决策 4 结束**——寻路端点契约保证起点不可走时任何终点
   都会失败，此时直接回退点与全部采样候选会一起失败，表现与"目标真的不可达"完全相同；这是既定的
   放置/生成问题，不是追击系统的职责，本决策不为此单独区分成因。

## 后果

### 正面

- 目标站在物件旁被从被挡一侧追击这类场景不再一律判定为"到不了"，只要停止距离圆上还有一个方向
  可走就能追上。
- 直接点寻路成功时零额外开销；候选点个数可配置，游戏层可按地图密度与手感权衡"多绕一点找到路"和
  "尽快判定放弃"。
- 纯新增可选配置项，默认值下不改变任何既有调用方的行为与既有测试断言。

### 负面（已知限制）

- 追击单位自身站在不可走格时，本决策无法区分"目标真的不可达"与"追击单位卡在阻挡里"，两者都表现
  为全部候选失败、结束追击——见决策 5，是有意为之的范围收敛，不是遗漏。
- 候选点个数越大，单次规划失败判定为"到不了"前的寻路调用次数上限也越高（最坏情形下达到候选点
  个数次）；默认值下未观察到需要额外优化的量级，具体数值仍是口味配置项。

## 备选方案与为什么不选

- **加大直接回退点的容错（如向目标方向微调后再试几次）**：只能处理"贴着边界差一点点"的情形，
  遇到目标被挡一侧整片不可走（本次复现的实际场景）仍会失败，故改为在整个停止距离圆上采样。
- **寻路失败时退化为向目标直线移动直到受阻**：会绕开寻路系统的阻挡判定，可能让单位穿墙或卡进
  阻挡内部，不选。
- **候选点个数固定为不可配置的常量**：更简单，但不同游戏的地图密度、阻挡尺度差异很大，做成可选
  配置项才能不影响未使用本能力的既有游戏，且让需要更强绕障能力的游戏自行加大。
