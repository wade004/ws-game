# ADR-0124 API 参考手册从源码注释生成并随版本快照分发

状态：已拍板 2026-10-01

## 背景

消费方查公开接口只能翻源码或各模块 README；README 讲概念与判断记录，不按命名空间/类型/成员逐条列出，
源码里已写的用途说明（文档注释）没有汇总出口。接口手册若手写，必然与代码漂移。

## 决策

1. **API 参考手册由源码文档注释自动生成**，按命名空间 → 类型 → 成员逐条列出，注释里写的用途、参数、返回值原样呈现。
   不手写、不入库任何生成内容。
2. **模块 README 作为概念文档并入同一站点**，保持各自在仓库里的相对路径，README 之间的相对链接原样可用；
   架构文档集与全部 ADR 并入同一站点的"架构"分区。指向非文档文件（源码、数据、脚本）的链接在站点里不可点，
   以仓库为准。
3. **手册随版本快照分发**：打分发包时生成并放进快照的 `manual/` 子目录，随发布包（含压缩包）一起交付；
   生成失败则打包失败，不静默跳过。内部只想验证打包清单的调用可显式跳过。
4. **范围**：本轮覆盖由解决方案编译的类库；引擎适配层的引擎侧包由引擎自身编译、不在解决方案里，
   暂不纳入 API 参考（已知缺口，登记在落地计划）。
5. **注释完整性不由编译器把关**：公开成员缺注释不报警；注释格式错误（会让整段注释丢失）仍按错误处理。
   指向私有成员/重载组的交叉引用只影响链接是否可点，不作为门禁。
6. 手册相关的具体工具与构建入口写在 `选型/` 与 `落地计划/`，本条只记决定。

## 后果

- 发布包体积增加（手册为静态站点）；换来消费方离线可查的接口手册，且与发布的代码同版本。
- 新增公开类型应当带一句话用途说明——没有注释的类型在手册里只剩签名。
- 不改任何运行时行为与公开签名。
