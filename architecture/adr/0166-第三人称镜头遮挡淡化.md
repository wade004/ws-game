# ADR-0166 第三人称镜头遮挡淡化（遮挡物淡化，不做镜头前推）

状态：已拍板 2026-10-08（来源：样板游戏 C 截图复核——镜头与主角/锁定目标之间的大树把画面完全挡死；纯加法，缺省关闭，不启用时行为逐位不变）

## 背景

第三人称镜头（[ADR-0161](0161-自由第三人称镜头俯仰范围声明焦点高度地面避让与脚本携带控制空间.md)）绕角色头部转，战斗中还要同时看见锁定目标。树、岩石、柱子等布景会落在"镜头 → 主角"或"镜头 → 锁定目标"的连线上，把角色或目标整个挡住。这是所有第三人称游戏的通用问题，框架已有的地面避让只处理地形，不处理布景。

## 决策

1. **二选一：遮挡物淡化，不做镜头前推。** 镜头到观察点连线上的遮挡物降低不透明度，离开连线后恢复；镜头位姿、取景与缩放完全不动。
2. **能力缺省关闭，游戏声明启用。** 相机实现新增"启用遮挡淡化"的声明（带选项，声明期校验，非法立刻报参数错误），返回遮挡淡化器；不声明时相机不创建它，行为与引入前逐位一致。只在第三人称相机（俯仰或透视打开）的每帧推进里被驱动，纯正交俯视没有深度遮挡，不驱动。
3. **观察点 = 相机焦点 + 游戏登记的额外观察点。** 焦点（角色头部）自动成为观察点；游戏可整体设置额外观察点（锁定目标的胸口等）。任一观察点被挡住就算遮挡。
4. **判定几何：** 连线段（镜头位置 → 观察点）按"视线半径"外扩后与遮挡物的世界轴对齐包围盒相交即算挡住。线段终点就是观察点，所以越过观察点、在角色身后的物体不受影响；外扩半径取角色轮廓半宽，擦边而过也算挡住；镜头钻进包围盒内同样算。包围盒在登记时取一次（遮挡物按静态布景处理，移动后显式刷新）；游戏只登记会挡视线的渲染物，地形、天空不登记，地形遮挡仍由地面避让负责。
5. **淡出量的契约：** 每个遮挡物有一个"不透明度"（1 = 完全不透明，被挡时的目标值 `FadedOpacity`，缺省 0.25），按每帧步长 dt 线性推进（淡出与恢复各有秒数选项），不读墙钟，测试用固定 dt 即可逐位确定。引擎侧实现把它写进渲染物的逐渲染物属性覆盖（属性名可选项配置，缺省 `_OcclusionFade`），不改共享材质；恢复到 1 时清掉覆盖，渲染物重新参与合批。框架只规定属性名与取值语义，**怎么画由游戏的着色逻辑决定**（推荐抖动透明：屏幕网点阈值小于淡出量才保留像素，淡出量为 1 时一个像素都不丢，不需要透明排序）。
6. **可观测：** 淡化器公开每个遮挡物的当前不透明度、是否正挡在连线上，以及被淡化/被挡住的数量，用例与游戏的自检都读这些量与渲染物上的属性覆盖，不靠看画面。

## 后果

- 所有新增公开面为纯加法，公开面兼容探针 0 破坏。
- 取景与镜头位姿不受影响，所以不影响相机相对输入的确定性（偏航提交）、脚本录制重放与手感镜头冲击。
- 游戏要让遮挡淡化可见，必须给被登记的渲染物配支持该属性的着色逻辑；不支持时能力只是"无视觉效果"，不会出错。

## 限制（已知，随相机适配层 README 判断记录登记）

1. 包围盒是轴对齐盒，外扩取立方体而不是球：对盒角略偏保守（多淡化一点，不会少淡化）；细长斜放的遮挡物包围盒偏大时会多淡化。
2. 包围盒登记时取一次，运动的遮挡物需要游戏显式刷新。
3. 淡化的是整个渲染物：游戏若把整张地图的布景合并成一个渲染物，遮挡淡化会整体淡化它，所以要按"一棵树/一块岩石一个渲染物"登记。
4. 地形遮挡（山坡挡住镜头）不在本能力内，仍归地面避让。

## 备选方案与为什么不选

- **镜头沿连线前推到遮挡物之前。** 锁定战斗里遮挡常出现在"镜头 → 目标"连线上，前推只能靠近角色而不能清出目标的视线，推到角色身前反而吞掉角色；密林中遮挡物连续出现时前推距离每帧跳变，还要和地面避让、缩放、手感镜头冲击三处距离修正相互协调；前推改变取景，进而改变相机相对输入的偏航以外的画面语义。淡化只改表现、不碰取景，两条连线（主角与目标）都能同时清出来。
- **射线检测并按碰撞体判定。** 要求布景带碰撞体，而框架的布景画面本来不创建碰撞体（碰撞在逻辑层的导航阻挡里）；包围盒登记让画面层独立成立。
- **全屏镂空（固定半径的屏幕空洞）。** 不需要登记渲染物，但会把任意处于空洞里的东西（包括该看见的地面细节）一起镂空，且无法表达"这个物体被淡化、那个没有"的可观测验收。
