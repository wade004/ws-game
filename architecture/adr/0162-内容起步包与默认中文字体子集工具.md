# ADR-0162 内容起步包与默认中文字体子集工具

状态：已拍板 2026-10-07（与 [ADR-0142](0142-默认手感模板.md) 的"出厂可选数据根"口径一致；在 [ADR-0160](0160-框架三层拆分运行时包手感实验室可选包与样板仓库.md) 的样板仓库实践之后）

## 背景

第一个样板游戏（俯视角动作 RPG）的第 3、4 阶段暴露：一个新游戏要从零写出"能跑第一遍"的内容，必须自己重复造一大批与具体游戏无关的通用数据——属性与资源条定义、经验与成长曲线、装备槽位与品质、通用界面文案、技能与敌人的基本结构、任务与对话的写法示例、地图出生点与传送的写法示例。这些东西每个游戏都要，写法也基本相同，却没有出厂版本；样板游戏里约三分之一的数据行是这类通用内容。

用户 2026-10-06 的决定（样板与内容起步包拆分计划）：框架出厂一套**游戏无关的通用内容起步包**，游戏想要就声明加载，样板游戏自己先用它，把重复的通用数据删掉。同时，界面必需一个默认中文字体，且它体积大（整套中文字体 15 MiB 以上），发版需要按游戏实际用字裁剪。

## 决策

1. **起步包是出厂的可选数据根 `data/_starter_kit/`，默认不装载。** 与 `data/_feel_templates` 同款：不并入 `_framework`/`_feel`（既有根的内容哈希不变、不用起步包的游戏逐位不变）；游戏把它作为**额外框架根**声明（装载顺序：框架根 → 手感根 → 额外框架根 → 游戏根）才被装载；引导程序不自动装载。模板配置容器提供根路径常量与注释掉的示例声明。随发布产物进分发目录、框架数据包与内容同步，不进手感实验室根。

2. **起步包只含游戏无关的通用数据，不含任何具体游戏的剧情、角色、美术、音频。** 范围：技能模板（三段连招、重击、蓄力、闪避、远程射击、带预警的范围大招）、敌人原型（近战小兵、远程、重型、首领骨架，带 AI）、装备（槽位、品质、词缀结构、少量示例）、掉落表结构与示例、任务结构（击杀计数、收集、对话交付、多阶段）、对话结构（分支、按任务状态切换）、地图规则（区域、传送、存档点、出生点）、系统文案（框架自带界面用到的全部文案键，简体中文 + 英文）、数值曲线（经验、成长、价格、装备预算）、面板热键声明、基础菜单与界面布局。数值是自拟的试调起点，经框架的数值规则自洽（预算利用率、价格公式偏差都过校验），**不是已验证值**。

3. **命名：基础设施 id 不带前缀，内容模板带 `kit_` 前缀。** 属性、槽位、品质、阵营、货币、时间模型、语言、经验来源这类"所有游戏都直接引用"的 id 取通用名；技能、生物、物品、掉落、任务、对话、地图这类"拿来复制改名"的内容模板用 `kit_` 前缀。游戏自己的内容用游戏前缀，天然不冲突。

4. **冲突规则：同一个 id 不能在起步包与游戏根里各定义一次。** 游戏要么删掉自己那份、直接引用起步包的行，要么在自己那行写 `"override": true`（整行替换，覆盖清单会列出；链式覆盖允许）。起步包对框架默认的生命资源条写一行覆盖（生命上限取自体力属性）。

5. **美术不进起步包，但框架的外形覆盖规则要求每个技能/物品/生物都有外形行**：起步包为自己的内容各给一行外形映射，指向占位精灵 id（没有对应资源）；游戏用 `"override": true` 换成自己的美术。起步包也不带手感数据、特效/音效定义、动画集、场景与导航资源。

6. **默认中文字体：沿用框架已分发的开源中文字体（SIL OFL 1.1，许可证全文与字体同目录随发布产物分发）。** 体积靠**字体子集工具**解决：扫描全部数据根里本地化文本的用字，加"常用字表"（国标一级汉字、可打印字符、中文标点，可关）与额外字符，输出只含这些字的子集字体；源字体缺字时报告（`--strict` 下失败）。不把子集字体随框架分发：子集取决于具体游戏的文案，由游戏在发版流程里生成并替换同名字体资源。

7. **门禁：** 起步包数据根单独校验（叠加框架根，严格模式 0 错误 0 警告）；起步包的内容家族齐全、游戏无关、中英文文案各一份、覆盖框架界面用到的全部文案键，由测试断言；"游戏不声明则不装载"由配置容器的默认值测试断言；字体子集工具有覆盖、体积、缺字报告与确定性测试。

## 后果

- 新游戏有一套能校验通过、能当结构参照的通用内容起点；样板游戏删掉自己重复的通用数据，改为引用或覆盖。
- 不用起步包的游戏行为、既有数据根内容、既有基线逐位不变。
- 代价：一个额外数据根随发布产物分发（约百 KB 级）并多一个校验步骤；基础设施 id 占用了通用名，已有同名定义的游戏要在声明起步包时处理冲突（删除或覆盖）。

## 限制（已知，随数据登记）

1. 数值是自拟的试调起点，未经试玩，不是已验证值。
2. 外形映射与地图的场景/导航引用是占位 id，没有对应资源；直接装载起步包的游戏要为用到的内容补美术或覆盖这些行。
3. 起步包没有手感数据（用 `data/_feel_templates`）、特效/音效定义、动画集。
4. 常用字表是国标一级汉字（3755 字）、可打印字符与中文标点：不含生僻字与繁体；游戏数据里出现的字总是被子集工具收进，所以只影响"运行期出现数据里没有的字"（玩家自定义名称等）。
5. 子集字体由各游戏自行生成与替换；框架不提供某个游戏的子集产物。

## 备选方案与为什么不选

- **把通用数据并进 `data/_framework`。** 改变所有游戏的既有行为与哈希，且与"框架级数据只放被代码硬引用的行"的既有口径冲突。
- **起步包拆成多个小根（技能根、装备根、文案根……）。** 每个根要各自的装载声明与校验，互相引用（技能引用目标链与曲线、装备引用属性）使拆分后无法独立校验，收益不抵成本。
- **随框架分发一份固定的中文子集字体。** 子集取决于游戏文案，固定子集要么缺字要么近似整套；由游戏按自己的数据生成才正确。
- **字体子集在运行期做。** 引擎侧动态字体图集已能按需生成字形，但发版体积（整套字体文件本身）不会变小，不解决问题。
