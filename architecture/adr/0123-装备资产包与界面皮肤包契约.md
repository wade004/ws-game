# ADR-0123 装备资产包与界面皮肤包契约

状态：已拍板 2026-10-01（用户要求：手感设计好后，游戏按框架要求补上装备与界面资产即可直接用）

## 背景

换装涉及的机制都已存在：装备外观映射（`display.equip_visual`）、纸娃娃层随朝向换图与逐层剪辑（ADR-0071/0072/0100）、`model` 型槽位与挂点、武器表现档案、界面布局定义与朴素皮肤的界面套件（ADR-0014）、资源引用路径约定（ADR-0025/0038/0054）。本目录又新增了武器族姿势维度（ADR-0119）与 `feel.weapon`（ADR-0118）。缺的是一份收口的契约：一件装备到底要提供哪些资产与数据行、界面皮肤能换哪些资源、缺项怎么回落、怎么校验。没有它，游戏接入时只能逐条翻各处文档。

## 决策

1. **装备资产包**：每件可装备物品一包，由物品定义、图标、外观映射、纸娃娃层资源集（`sprite`）或槽位网格/挂点模型（`model`）、武器表现档案（武器）、`feel.weapon`（武器）、音效层材质、可选拖尾与穿脱音效组成；全部以同一个物品 id 派生路径与表行键。武器的 `display.weapon_style` 与 `feel.weapon` 同 id 分表，校验器检查互相存在。纸娃娃层覆盖要求以游戏声明的方向档数与必备姿势键为准。
2. **换装链路由框架接线**：装备变化事件 → 外观换装 → 武器表现档案 → 武器族姿势解析 → 手感解析器失效重算 → 反馈包变体 → 界面视图模型刷新；游戏不写代码。
3. **界面皮肤包**：每款游戏一包，替换界面套件引擎侧实现的资源：面板布局行、槽位框三态、品质框（图标不含框）、拖拽态、提示框样式、纸娃娃预览区、主题；每项有框架占位版本，缺项回落占位并进报告，不阻断运行。
4. **可选加法字段**：`feel.weapon.sfx_material`/`trail_ref`、`item.template.equip_sfx_ref`、`display.equip_visual.preview_direction`、`ui_layout_definition.skin_ref`，不提升 schema 版本。
5. **导入校验与装备完整性报告**：图标、外观映射、必备键 × 方向档层资源、槽位/挂点命名、武器双表齐全为错误级；推荐键缺失、武器族无姿势键、音效材质缺行、皮肤缺项为警告级并记录回落目标。报告只留本地；有错误级项的装备不能进 `validated` 数据集。
6. **实验室换装场景**（06 第 3.6 节）与 `equip_cycle` 脚本是本契约的验收场，运行期检查与静态报告零差异；框架占位装备集是参照实现。

## 后果

### 正面

- "设计好手感，补上资产就能用"有了一份可核对的清单与自动检查。
- 武器手感差异变成填两行表加按契约补资源。
- 界面换皮不触碰视图模型。

### 负面

- 占位装备集与占位皮肤是新增的框架资产，随姿势清单与槽位表变化要同步。
- 校验项增多，首次接入时报告可能很长（但都是可回落的警告或明确的错误）。

## 备选方案与为什么不选

- **只写接入指南不做校验**：缺项只会在运行期表现为"没穿上"或"没声音"，定位成本高；否决。
- **图标自带品质框**：品质变化要重出全部图标；否决，品质框独立叠加。
- **皮肤缺项阻断**：会让美术未齐的阶段无法运行实验室；否决，回落占位。

## 魔兽世界的对应做法

魔兽的物品外观经 `ItemDisplayInfo` 关联图标、模型/贴图与各部位纹理，界面由插件系统换皮。本架构的装备资产包对应 `ItemDisplayInfo` 的收口版（多出武器手感与姿势族），界面皮肤包对应可换皮的界面资源层，不做插件脚本。
