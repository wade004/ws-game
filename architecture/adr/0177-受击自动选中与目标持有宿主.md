# ADR-0177 受击自动选中与目标持有宿主

状态：已拍板 2026-10-09（来源：`docs/消费方反馈/消费方反馈-2026-10-09-样板游戏B-受击自动选中施法动作技能详情.md` 第 A 节；纯加法，数据缺省关闭，既有游戏行为逐位不变）

## 背景

目标选择式战斗里，玩家没有选中目标时被敌人打，玩家的第一反应是"回头打它"，游戏应当自动把攻击者选为目标。框架此前没有"单位当前目标"这个概念：目标是游戏层自己的操作状态，"被打自动选中"每个游戏都得自己订阅伤害事件、自己追召唤者归属、自己排除友方和环境伤害，规则细节（要不要抢已有目标、多个攻击者先选谁）各写各的，容易写错也无法统一验收。

## 决策

1. **新增目标持有宿主 `ITargetLockHost`**（载体层 unit 模块，装配根 `TargetLock` 暴露）：持有各单位的当前目标；`GetTarget`（失效目标——不存在、已死亡、与持有者不在同一地图——返回空，不改状态）、`SetTarget`（显式设置/清除；目标须存在且存活，否则拒绝；不检查阵营，能不能选友方是游戏的操作规则）、`GetControlMode`/`SetControlMode`（操控模式标签，纯标签，只影响本规则的判定）。
2. **新增事件 `unit.target_changed`**：`{unitId, targetId, previousTargetId, cause, sourceId}`；`cause` 取值 `manual`（调用方显式设置/清除）、`auto_hit`（受击自动选中）、`target_died`（目标死亡清除）、`target_gone`（目标离开世界清除）。游戏订阅它同步自动攻击、目标框等表现，宿主不替游戏联动任何东西。
3. **受击自动选中规则由数据声明**：`creature.template` 新增可选对象 `target_lock`——`auto_select_on_hit`（布尔，缺省 false = 关闭）、`modes`（可选字符串列表；声明后只在单位的操控模式标签在列表里时生效，未设置标签视为不在；缺省或空 = 任何模式都生效）。玩家单位同样由 `creature.template` 生成，同一字段覆盖玩家与怪物。
4. **规则（订阅 `combat.damage_dealt`，按事件确定性派发顺序逐个处理）**：
   - 受击者存活且规则启用；
   - 受击者当前**没有有效目标**（从未选过 / 目标已死亡 / 不存在 / 不在同一地图）才选中，**已有有效目标一律不抢**；
   - **攻击者** = 伤害来源沿召唤者归属链（`ISummonHost.GetOwner`，最多追 8 层）归到的最终单位——召唤物与投射物伤害归到施放者；
   - 攻击者须存在、存活、与受击者同图、不是受击者自己，且阵营对受击者**敌对**（`IFactionMatrix.IsHostile`）——友方误伤、环境伤害（来源不是单位）、来源已死亡的持续伤害、自伤都不选中；
   - **同一批多个攻击者的确定性裁决（tie-break）**：先派发的伤害事件先选中，之后的因"已有有效目标"不再改变；结果只取决于事件的确定性派发顺序，不依赖字典枚举顺序、距离或随机。
5. **失效清除**：目标死亡（`unit.died`）、目标离开世界（`entity.destroyed`）时清除并发 `unit.target_changed`（同一目标被多个持有者选中时按持有者 id 字符序依次发出）；持有者自己离开世界时直接丢弃其状态（不发事件）。距离过远、换图等"游戏自己的失效口径"由游戏调用 `SetTarget` 清除。
6. **不参与存档**：目标是瞬时操作状态，读档后重新选。
7. **是否在动作模式（无选目标操作）生效由数据决定**，不写进框架：游戏在 `modes` 里列出生效的模式即可。

## 后果

- 新增公开类型 `ITargetLockHost`/`TargetLockHost`/`TargetChangeCause`、事件类 `UnitTargetChangedEvent`、装配根属性 `CarriersAssembly.TargetLock`、事件目录行 `unit.target_changed`、数据字段 `creature.template.target_lock`，均为纯加法；不声明 `target_lock` 的游戏行为逐位不变。
- 触发源只认伤害落地（`combat.damage_dealt`）：未命中/被回避、不带伤害的控制效果不触发自动选中——"被打了"以伤害落地为准，与仇恨表的伤害来源口径一致。

## 限制（已知）

1. 宿主只持有目标，不联动普通攻击与界面；游戏需自己订阅 `unit.target_changed`。
2. 阵营判定沿用阵营矩阵：同阵营一律视为友方，未登记阵营的单位会让阵营矩阵抛异常（与既有阵营口径一致，不在本规则里吞掉）。

## 备选方案与为什么不选

- **游戏层自己订阅伤害事件实现。** 每个游戏重复一遍归属链、阵营、已有目标、顺序裁决，规则细节无法统一验收；且样板游戏实测第一版就漏了"召唤物伤害归到召唤者"。
- **距离最近 / 威胁最高者优先作为多攻击者的裁决。** 引入对位置与威胁表的依赖，结果不再只取决于事件顺序；"先被打先选中"对玩家直观且可复现。
