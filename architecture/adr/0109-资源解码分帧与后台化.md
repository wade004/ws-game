# ADR-0109 资源解码分帧与后台化

状态：已拍板 2026-09-29

## 背景

消费方反馈第五十八批（`<game>` 接入方，基于 v1.87.0 冻结发布提交核实，阻塞）：精灵单位在一局里
第一次转到某个方向档位时，表现层的换向重探测一次发起几十个逐帧动画资源的冷加载（每个方向约 4 个
身体剪辑图集，加上每件已装备物品层各 3 个图集）。引擎适配层的资源加载器只在后台线程读文件字节，
全部解码都排进主线程每帧一次的收尾调用里**一帧排空**：图集位图的解码、开启多级渐远链（ADR-0096）
时对每一帧新建独立纹理并逐像素读写拷贝、再生成多级渐远链。实测该帧耗时 725～866 ms，角色一帧瞬移
1.5 m；一个方向档位只在本局第一次出现时卡，16 档方向意味着一局里最多卡十几次，换装后新装备层的首次
换向同理。

落地期核实：卡顿来源不止逐帧动画——同一次换向里静态层图（纸娃娃层图像）也是首次加载，走的是同一套
"后台读字节、主线程一帧排空解码"，同样是长帧来源；地图分层图是加载期一次性行为，不在换向路径上。

## 决策

1. **图像与逐帧动画两类资源的位图解码、逐帧动画图集按帧切块、帧描述文件解析，全部移到后台线程**。
   覆盖范围写死为这两个资源种类，两条路径都改，不把任何一条写成已知限制。地图分层图、音频、数据表、
   场景、导航、字体、三维模型、动画剪辑不改（地图分层图是加载期行为且单张不可分；其余要么不涉及位图
   解码，要么依赖只能在主线程调用的引擎资产接口）。
2. **后台使用纯托管的位图解码器**（不依赖任何引擎接口，可在任意线程运行）：支持 8 位深、非隔行、
   带/不带透明通道两种颜色类型，输出行序与引擎纹理一致的 RGBA32 字节。其它变体（调色板、灰度、16 位、
   隔行、颜色键透明等）或托管解码抛异常时，**整个资源作为一个不可分的工作单元回退到原主线程解码路径**，
   并按资源 id 写一条警告诊断（该图集无法后台解码、存在长帧风险）；回退后仍失败才回调失败。解码按行
   流式进行，逐帧动画开启多级渐远链时每一行直接分发到各帧的像素块，不在托管堆上保留整张解压缓冲与整张
   图集像素（实测整张缓冲的第一版，大数组分配触发的整堆 GC 停顿会把主线程单个工作单元顶到数十毫秒）。
3. **后台并发与内存约束**：并发解码数上限 `clamp(核心数 - 1, 1, 4)`；已解码、尚未被主线程消费的像素
   字节总量超过 128 MB 时后台暂缓解码新的图集（背压）；主线程灌完一块像素后把数组还给一个上限 64 MB 的
   按长度精确匹配的复用池，后台下一次解码同尺寸帧直接复用。
4. **主线程只做"建纹理 + 灌字节 + 提交 + 建精灵"，按工作单元续作**。工作单元 = 一张最终纹理（开启
   多级渐远链时逐帧动画一帧一张；关闭时整张图集一张；静态图像一张）。灌字节用按像素数据整块写入的接口，
   不再走浮点颜色中转；**多级渐远链仍由引擎在提交时生成，不手写滤波**，像素结果与改动前一致。采样设置、
   枢轴、像素密度、精灵命名、逐帧独立纹理登记与卸载销毁与改动前逐项保持不变。一个资源的全部工作单元
   做完才写入资源缓存、才记为已加载、才触发回调——任何读取口永远看不到半成品；未做完的资源留在队首，
   下一次收尾调用续作；回调仍只在主线程收尾调用内触发，完成顺序保持完成队列先进先出。
5. **收尾调用加主线程时间预算**：新增公开可写属性 `MainThreadBudgetMilliseconds`，默认 `4.0`，
   `<= 0` 表示不限（即改动前的一帧排空）。预算覆盖普通完成队列与地图分层图完成队列（共用一份，先前者
   后者）；字体/三维模型/动画剪辑三个主线程专用队列不动。每做完一个工作单元检查一次，超预算即停；
   **每次收尾调用至少推进一个工作单元**，保证必然前进。不涉及纹理的种类（音频、数据表、场景、导航、
   复用缓存的逐帧动画）每个完成项算一个工作单元；地图分层图每个完成项算一个工作单元。
6. **新增公开只读诊断**（供消费方做运行时验收）：`LastTickDecodeMilliseconds`（上一次收尾调用主线程
   耗时）、`PeakTickDecodeMilliseconds`（自上次重置以来的单次峰值）、`MaxWorkUnitMilliseconds`（自上次
   重置以来的单个工作单元最大耗时，含回调）、`LastTickWorkUnitCount`（上一次做完的工作单元数）、
   `PendingMainThreadCompletionCount`（已就绪等待主线程处理的完成项数），以及重置方法
   `ResetTickDiagnostics()`。单次收尾调用耗时的上界即 预算 + `MaxWorkUnitMilliseconds`。
7. **多级渐远链开关在发起请求时于主线程取快照**，随请求带到后台：同一请求的后台切块与主线程建纹理
   使用同一份取值；过滤模式等其余采样参数仍在建纹理时读取当时取值。
8. **热路径逐字节不变**：已缓存资源命中、以不同精灵集提示重新请求时复用缓存（ADR-0095 决策 5）不经过
   任何解码路径，返回同一个已解码资产。

## 后果

### 正面

- 换向瞬间不再有整帧长卡：主线程每帧只做毫秒级的工作单元，几十个图集的解码分摊到后台线程与多帧。
- 主线程耗时上界可观测、可配置：消费方可用诊断属性做运行时验收，也可按场景调预算。

### 负面（行为变更，需在发布说明标注）

- **同一帧发起的多个冷加载不再保证在下一帧全部完成**：完成时长约等于总主线程工作量除以预算占空比。
  未完成前沿用"加载完成才回调、未完成维持当前显示"的既有语义（上一方向的剪辑或静态层）。需要更快时
  调大预算；加载画面等不在乎帧率的场景可设为 `<= 0` 恢复一帧排空。
- **已知限制（逐条）**：
  1. 预算只能在工作单元之间生效：单张最终纹理（含提交与建精灵）本身耗时超过预算时该次调用仍会完整
     做完它；回退路径整个图集是一个工作单元，长度与改动前相同。
  2. 地图分层图本次不改，仍在主线程一个完成项一次解完（共用同一份预算，计为一个工作单元）。
  3. 托管解码器不校验位图各数据块校验和与压缩流尾部校验和（引擎解码器会校验）：损坏文件可能被"解出"
     错误像素而不是失败；像素数超过 8192×8192 时回退主线程解码；只读取图像头/数据/透明度/结束四类块，
     其余辅助块（色彩管理等）一律忽略。
  4. 后台背压的 128 MB 软上限只约束"已解码未消费"的像素字节，不含引擎侧已建好的纹理；复用池最多
     常驻 64 MB。
  5. 开启多级渐远链的逐帧动画在切块时某帧矩形越界或尺寸非法，整个资源判定加载失败并记一条错误诊断
     （改动前在此处由引擎读像素接口抛异常，异常会逸出收尾调用）。
  6. 主线程单个工作单元仍含 GC 停顿的偶发抖动：大量像素块的托管分配在压力场景下仍会触发整堆回收，
     实测偶发单个工作单元数十毫秒，已用行流式解码与复用池压低到约原先的一半，未能根除。
  7. 一个逐帧动画资源被并发重复请求（尚未完成时再次请求同一资源）时，两次请求各自解码、后写覆盖先写，
     先写者的独立帧纹理不会被销毁（与改动前一致，不是本次新增）。

### 落地期实测（同一台机器，编辑器批处理，仅作量级参考）

- 修复前阶段占比（8 个 2048×2048、16 帧图集，主线程合计 959 ms）：位图解码 30.5%，按帧取块写块
  36.9%，提交含多级渐远链 6.0%，采样设置与建精灵 26.6%。
- 复现用例（24 个 1024×1024、8 帧图集 + 4 张静态图同一帧冷加载）：修复前做了工作的调用仅 1 次、
  单次 1361.5 ms，上界为 132.2 ms；修复后 72～76 次、单次最大 15～17 ms，上界约 27～31 ms。
- 真实量级（一个方向 30 个 2048×2048、16 帧图集，60 Hz 配速）：修复前 1 帧、单帧 4036.5 ms；修复后
  默认预算 4 ms 下约 4.1～8.2 s、247～479 帧完成（随机器同时负载浮动），单帧最大 39～79 ms（含起步抖动与 GC）；预算 8 ms
  约 2.9 s，预算 16 ms 约 1.9 s。

## 备选方案与为什么不选

- **只在主线程分帧、不后台化解码**：单个图集的位图解码仍是一整块几十毫秒，预算无法切开，长帧只是
  变成"每帧一个大块"。
- **由内容方在进图时按命名规则预热全部方向剪辑**：等于在内容侧复制一份换向重探测的候选规则，规则一变
  就静默失效，属于自建平行机制。
- **关闭多级渐远链或降低图集分辨率换解码速度**：用丢失 ADR-0096 已交付的画质换性能，不接受。
- **手写多级渐远链滤波以便后台生成**：与引擎生成结果存在像素差异风险，且增加维护面；本决策保持
  "多级渐远链由引擎生成"，像素结果与改动前一致。
