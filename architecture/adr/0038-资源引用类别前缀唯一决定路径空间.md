# ADR-0038 资源引用类别前缀唯一决定路径空间

状态：已拍板 2026-09-18

## 背景

[ADR-0037](0037-资源引用路径推导契约扩展到vfx-sfx-model-anim_set.md) 背景一节核实并如实记录了一处此前未被文档记录的架构性事实：
`display.anim_set.clips.resource_ref`、`display.weapon_style.auto_attack_anim`、
`display.weapon_style.cast_anim_override`、`display.equip_visual.mesh_ref` 四个字段，运行期
按消费实体的 `display.map.kind`（sprite 型 / model 型）存在两条并存的加载规则——同一个资源引用
字符串，model 型消费时按"引擎侧已导入逻辑资源路径"解释，sprite 型消费时按"资产根相对目录，与
特效资源同一路径空间"解释；`mesh_ref` 的 sprite 型消费更是不经任何路径推导函数中转，直接把值当
纸娃娃层资源 id 使用。ADR-0037 决策 3 已指出这正是校验入口无法安全做存在性检查的根因，决策 2
把"是否收口 sprite 型规则"明确留给设计层裁决，不代为处理。

本次设计层裁决确认：这一"同一类别前缀按消费方不同落在不同路径空间"的现象，违反了
[ADR-0025](0025-资源引用标识到资产相对路径的约定纳入公开契约.md) 已经确立的"资源引用标识 →
相对路径"约定的隐含前提——ADR-0025、ADR-0037 收口的每一类前缀（`sprite`/`icon`/`vfx`/`sfx`/
`anim`/`model`）此前都只对应唯一一条推导规则，唯一一个路径空间。上述四个字段是仅存的例外，不是
新问题、也不是要新建一种机制，而是要把 ADR-0025 已有的"类别前缀"约定贯彻到底，消除这一例外。

进一步核实（勘察见 `architecture/落地计划/` 同批次记录，样例数据集逐行核对）：样例数据中
`display.weapon_style.sample_model_sword` 一行，尽管命名带"model"字样，实际挂在
`kind=sprite` 的 `display.map.sample_model_sword` 行下——其 `auto_attack_anim: "anim.attack"`/
`cast_anim_override.skill.sample_burn: "anim.cast"` 与 `display.anim_set.placeholder_biped`
（被 model 型消费）里同名剪辑的 `resource_ref` 字符串完全相同（`anim.attack`/`anim.cast`），是
"同一字符串被两条路径空间解释"这一风险的活样本——当前并非真正冲突（两者分属不同表、不同消费
路径），但只是巧合未撞车，架构上不排除未来真正撞车。

## 决策

1. **总原则**：资源引用的类别前缀**唯一决定**其路径空间与推导方法。每个类别前缀恰好对应一个
   路径空间、一个推导方法。禁止出现"同一前缀按消费方不同而落在不同路径空间"的字段。这是对
   ADR-0025 已有"类别前缀"约定的贯彻，不是新机制——背景一节所述四个字段是仅存的例外，本 ADR
   消除该例外。

2. **新增类别前缀 `sprite_anim`**：sprite 型动画帧资源改用独立类别前缀，路径为资产根相对目录
   `sprite_anim/<name>`（`<name>` 沿用既有"去掉类别前缀、点号换下划线"规则求得），目录结构与
   `vfx` 类别资源同构（内含图集与帧数据两个文件）。理由：角色动画与特效在语义上是两类完全不同的
   内容（前者服从骨骼/序列帧驱动的动作节拍与状态机，后者服从技能/效果的表现演出），长期共享同一
   目录会让两边各自的产出与消费约定互相绑架，未来任何一边想单独调整目录结构都要连带考虑另一边；
   当前样例数据集里落在这一路径下的 sprite 型剪辑仅 2 行（`display.anim_set.sample_hero`），
   迁移成本接近零，越晚拆分成本只会越高。

3. **`anim` 前缀收归 model 型专用**：`anim` 前缀此后只表示 ADR-0037 收口的
   `AnimClipLogicalPath` 推导结果，即引擎侧已导入的动画剪辑逻辑路径；不再承载 sprite 型资产根
   相对路径语义。sprite 型动画剪辑一律改用决策 2 新增的 `sprite_anim` 前缀。

4. **`equip_visual.mesh_ref` 的 sprite 型取值改用既有 sprite 类别前缀**，走 ADR-0025 已收口的
   `SpriteSetDirectory` 既有推导规则，不再由表现层实现直接把原始值当资源 id 使用。
   **附带条款**：sprite 型 `mesh_ref` 此前实际承载的语义是"纸娃娃层资源 id"，与 ADR-0025
   `sprite_set_id` 承载的"精灵集目录标识"是否为同一概念、取值是否等价，需要在落地期对照两侧
   现行取值逐一核实确认；若确认二者语义不等价（例如纸娃娃层资源 id 还需要额外携带层级/朝向信息，
   精灵集目录标识不携带），按本 ADR 决策 1 的总原则为"纸娃娃层资源 id"新增一个独立类别前缀与
   独立推导方法，而不是让既有 `sprite` 前缀被迫承担两种不同语义——这一核实与后续动作留给落地期
   执行方处理，本 ADR 不预先假定核实结果。

5. **新增公开路由入口**：在 ADR-0025/ADR-0037 收口的"资源引用标识到相对路径"框架契约面上，新增
   一个总入口，输入资源引用标识、输出（路径空间, 相对路径）二元组；内部按类别前缀分派到 ADR-0037
   已收口的四个方法（`VfxResourceDir`/`SfxResourceFile`/`AnimClipLogicalPath`/
   `ModelLogicalPath`）与本 ADR 新增的方法（决策 2 的 `sprite_anim` 推导、决策 4 落地后对应的
   方法）；遇到未知类别前缀，或该前缀缺失（资源引用标识不含合法类别前缀段），均视为错误，不做
   静默兜底。两种运行环境（内容导入工具链侧、已落地引擎适配层侧）各自实现、互相对照，不共享同一
   份源码——沿用 ADR-0037 决策 1 确立的做法。

6. **校验**：新增一条规则，校验资源引用字段的类别前缀合法（属于已登记的类别前缀集合），且与该
   字段 schema 声明允许的类别集合相符（例如 `display.weapon_style.auto_attack_anim` 只允许
   `anim`/`sprite_anim` 两类前缀，不允许 `vfx`/`sfx` 等其它类别误配进来）。资产根路径空间
   （`vfx`/`sfx`/`sprite`/`sprite_anim` 四类前缀）的引用纳入校验入口现有的资源存在性检查覆盖域；
   引擎侧逻辑路径空间（`anim`/`model` 两类前缀）的引用仍在覆盖域外——理由同 ADR-0037 决策 3：
   这两类资源落在引擎适配层内部一个单一、非按数据集分区的资源目录树里，不在校验入口的资产根目录
   检查域内。

7. **部分取代 [ADR-0037](0037-资源引用路径推导契约扩展到vfx-sfx-model-anim_set.md) 决策 2**：
   ADR-0037 决策 2 当时"只收口 model 型规则，sprite 型并存规则本次不纳入"，其中"是否要把 sprite
   型规则也提升为与 model 型平级的公开契约、以及如何在数据层面区分消费路径"这一保留，本 ADR 取消
   ——sprite 型不再是"局部实现细节里默认接线出来的、与 model 型并存的第二条规则"，而是由决策 2/3
   新增的独立类别前缀（`sprite_anim`）与决策 4 的既有 `sprite` 前缀分别承载的、各自独立的路径
   空间，与 model 型的 `anim`/`model` 前缀在契约地位上完全对等。已在 ADR-0037 文件顶部状态行下
   补一行取代说明。

8. **不在本 ADR 范围**：以下两项识别为后续项，不在本次决策范围：
   - sprite 型"按消费实体行 id 末段命名"推断 `display.anim_set` 行的默认接线约定（已落地引擎
     适配层表现层实现里一处默认接线约定的隐式规则），本 ADR 不改动其行为，后续改为显式引用字段（例如
     在消费实体行上新增一个显式的 `anim_set_ref` 等价字段），消除"靠 id 命名猜行"的隐性约定。
   - 已落地引擎适配层实现改为转发决策 5 新增的公开路由入口（需要相应的批处理编译/测试环境验证，
     与 ADR-0037 决策 4 面临的约束相同），本 ADR 不要求本次同步改动引擎适配层代码。

## 后果

### 正面

- 消除了资源引用类别前缀语义分裂的唯一例外，往后每新增一类资源引用，只需确定它的类别前缀，路径
  空间与推导方法即唯一确定，不再需要额外反推"这一行到底谁在消费"。
- 校验入口首次能够对 sprite 型动画/纸娃娃资源做资源存在性检查（决策 6），此前这部分完全在检查
  覆盖域外。
- 消费方工具（内容编辑器的资源预览、日志、报错等）今后可以只凭资源引用字符串本身（类别前缀）确定
  路径空间，不再需要先弄清楚"这一行被哪种类型的实体消费"这一运行期才成立的关系。
- 样例数据中"同一字符串被两条路径空间解释"的活样本（`sample_model_sword`）随本 ADR 落地后不再
  可能出现，因为 sprite 型与 model 型此后使用不同的类别前缀，字符串本身即可区分。

### 负面

- 新增 `sprite_anim` 类别前缀需要迁移样例数据中现有的 2 行 sprite 型动画剪辑记录（把资源引用值
  的类别前缀从 `anim` 改为 `sprite_anim`），属于破坏性变更（见 [ADR-0039](0039-内容数据schema破坏性变更政策.md)
  分级第 2 条），需要按该政策补齐 CHANGELOG 标注、迁移说明等材料，落地期工作量不为零。
- `equip_visual.mesh_ref` 的 sprite 型取值格式变化（决策 4）如果落地期核实为语义不等价、需要
  新增独立类别前缀，则同样构成破坏性变更，且额外多一轮"先核实、再决定是否新前缀"的落地期工作，
  本 ADR 无法预先给出确定的迁移方案。
- 决策 8 列出的两项后续项本次不处理，"按 id 末段命名"的隐式接线约定在本 ADR 落地后依然存在（只是
  它推导出的资源引用改用了新前缀），仍然是一处隐性架构简化，尚未消除。

## 备选方案与为什么不选

- **在 `display.anim_set`、`display.weapon_style`、`display.equip_visual` 三张表上各加一个判别
  字段，各配一条字段组规则**（照搬 `display.map.kind` 的做法，即仓库已有 `DisplayKindFieldGroupRule`
  一类"判别字段 → 条件必填/互斥字段组"模式，repo 内同构先例已有 6 处）：这一方案更贴合仓库现有
  字段组规则先例、改动面也更小（不需要新增类别前缀、不需要迁移已有数据的字符串取值），但它把
  "这一行该按哪条路径空间消费"的判定绑在**行上**而不是绑在**值上**——资源引用的值会脱离它所在的
  行独自旅行（进入消费方工具的预览解析、日志、报错文本、跨表复制粘贴等场景），判别字段不会跟着
  一起旅行，消费方拿到一个孤立的资源引用字符串时仍然无法确定它的路径空间，回到了本 ADR 要解决的
  同一个问题。并且每新增一张持有同类资源引用字段的表，都要重新加一遍判别字段与对应规则，不是
  一次性收口。故不选。
- **不新增类别前缀，让 `anim` 前缀继续同时承载两种路径空间，只在决策 5 的路由入口内部按额外的
  运行期参数（如显式传入 `kind`）分派**：这等于把判定责任从"数据本身"转移到"调用方必须知道自己在
  给谁解析"，路由入口的签名会退化成"我知道答案就不用问你了"的自相矛盾状态——调用方（如资源预览
  工具）往往正是因为不知道某个资源引用属于哪条路径才需要调用路由入口，要求它先自行判断 `kind`
  违背了新增路由入口的初衷。故不选。
