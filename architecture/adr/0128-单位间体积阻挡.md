# ADR-0128 单位间体积阻挡

状态：已拍板 2026-10-02（对 [ADR-0116](0116-运动仲裁器与运动档案.md) 的追加决定：运动仲裁器对"位移遇到别的单位"补写规则；不改 ADR-0116 已有结论）；同日追加决定见文末"追加决定：体积阻挡补完"；2026-10-02～03 的精确化与三期补全见文末"M4 增补"

## 背景

ADR-0116 的运动仲裁器只对地形（墙体、不可走区域）裁决位移，位移撞到别的单位时没有规则：输入位移、动作位移、击退都会穿过木桩与敌人，扑击扑到目标身体里，冲刺落点与敌人重叠。游戏里"单位有体积、走路会被敌人挡住、闪避可以穿过敌人"是常见手感，且和既有的全局单位阻挡开关（只在终点判定、固定半径、不属于手感档案）不是一回事。这个能力必须可选：既有预设与没有声明的单位行为一字不变，否则所有缺省手感基线都要重烘。

设计文档（[手感设计/02](../手感设计/02_移动与运动仲裁.md) 第 3.5 节）已写了行为；本 ADR 把其中的取舍作为架构决定固定下来，供后续改动对照。

## 决策

1. **可选开启，开关在运动档案**：档案新增可选字段 `unit_body_radius`（身高倍数，标定后为世界单位，缺省不声明）；只有**本单位**档案声明且大于 0 才进入任何体积分支。没有声明的单位与既有预设、`LegacyEquivalent` 档案逐位不变。该能力与既有的全局单位阻挡开关独立、互不影响。
2. **成对语义**：体积是二维平面上的圆，半径取自各自的档案；两个单位**都**声明才互相阻挡（中心距不得小于半径之和），只有一方声明则双方互不影响（穿过）。
3. **连续扫掠防隧穿**：本 tick 的位移当作线段，与每个有体积的其他存活同图单位（以其此刻位置为圆心）求首次进入；命中后停在入射点之前一个到达容差处（与墙体阻挡同一约定，下一 tick 不会从圆里起步，撞停后不蠕动）。高速位移（冲刺、击退）因此不会一步跨过单位。
4. **动作位移按 `blocking` 声明处理，穿过只给闪避类**：`stop` 停下、`slide` 沿体积切向滑开（最多一次、不递归，切向那段仍过地形裁决）；`dodge_through_units` 为真且位移种类在档案字段 `pass_through_motion_kinds`（缺省 `dash,step_back`）里时整段穿过别的单位的体积（地形仍阻挡），其余种类（缺省的 `lunge`、`charge` 等）不穿过。理由：闪避的语义是无敌位移穿过敌人，扑击与冲向目标是追击型位移，穿过目标会让"扑到敌人面前"失去意义；用档案字段而不是硬编码，游戏可自己决定哪些位移穿过。
5. **常规移动与追击**：`regular` 来源的输入位移按 `wall_slide` 决定整体停下或沿体积切向滑一段，路径跟随与追击按 `path_avoid_units` 局部绕行（追加决定 2）；追击的停步距离取"声明的停步距离"与"双方半径之和加两个到达容差"的较大者，体积大于停步距离时站在体积边缘而不是撞上去。
6. **强制位移被挡即停，推人可选**：`forced` 来源（击退等受控位移）被体积挡住时以"被阻挡"收场，不滑开；档案字段 `forced_push_units`（缺省假）为真时，被挡住的剩余位移按比例转给挡路的单位（见追加决定 3）。
7. **重叠单位按速率推开**：起点已在别人体积内（出生重叠、穿过式冲刺的落点）时，位移仍只拦"让距离变近"的；另有一步 tick 末的分离（追加决定 1），把重叠的单位按档案速率推到恰好不重叠。
8. **范围边界**：死亡单位不阻挡；离散步（回合制）不受影响；路径跟随与追击撞到体积时局部绕行，绕不过去才停（追加决定 2）；同一 tick 内的体积裁决与单位处理顺序无关（追加决定 4）；体积半径随运动档案走，同一档案下所有单位同半径，不同半径靠体型原型或角色覆盖层给不同档案值。

## 后果

### 正面

- 单位有体积、冲刺穿人、击退被挡等手感可由数据声明，不需要游戏写代码。
- 缺省关闭，既有预设与基线零差异；不同来源的位移在同一个仲裁点上处理，没有新的位置写入点。
- 成对语义让"只让某些单位有体积"（如只对敌人有体积）可以直接用数据表达。

### 负面

- 位移每 tick 多一次对周边单位的扫掠与成对检测（`O(n log n + k)`，k 为接触对数），仅在声明了体积的单位上产生开销。
- 同 tick 的相互阻挡看到的是各单位 tick 起点的位置（见追加决定 4），所以跟在另一个单位后面走的单位最多滞后一个 tick。
- 局部绕行只在撞到的那个体积边上滑过，不是全局避障；多个单位围成的死角里会停下，复杂的群体避让仍需要游戏自己的寻路层承担。

## 备选方案与为什么不选

- **挡人由全局开关统一决定**：粒度太粗，无法让动作位移按种类区分穿过与否，也无法只对部分单位声明；否决。
- **按位移种类硬编码"闪避穿过"**：游戏无法关闭穿过（例如不想让闪避无敌穿人的硬核玩法）；否决，用档案字段。
- **绕行靠重新寻路**：导航契约已冻结，重规划要改它，且每次被挡都重算路径开销大；否决，用局部切向绕行，绕不过去就停。
- **分离直接把单位挪开（瞬移式）**：会穿墙、产生跳变；否决，按速率逐 tick 推，并过地形裁决。
- **推人的位移即时落到被推单位**：被推单位这一 tick 可能已处理完，结果依赖顺序；否决，被推单位下一 tick 起得到一个新的强制位移。

## 追加决定：体积阻挡补完（2026-10-02）

对上面第 6、7、8 条原先的限制逐项补完。全部只在本单位 `unit_body_radius > 0` 时生效；未声明的单位与既有预设逐位不变。新增档案字段（均为可选，位于移动/判定组）：`unit_separation_speed_ratio`（缺省 0.5）、`path_avoid_units`（缺省真）、`forced_push_units`（缺省假）、`forced_push_ratio`（缺省 0.5）、`pass_through_motion_kinds`（缺省 `dash,step_back`）；`dodge_through_units` 保留为总开关。

1. **推开重叠单位**：tick 末对相互重叠的单位做分离。每个单位的分离权重 = `unit_separation_speed_ratio` × 基础移速；中心距小于半径之和时，深度按双方权重比例分摊，每个单位每 tick 的位移不超过权重 × 步长，并且不会推到恰好不重叠以外。被冻结、被定身、死亡或处于受控位移中的单位权重为 0（不被推）；权重为 0 的一方不动，对方独自承担。推开的位移先过地形裁决（不穿墙），再过与别的单位的接触检测（不被推进第三个单位）。理由：分离速率由档案声明，数据可关（比例 0）；逐 tick 小步推不产生跳变，也不与动作位移争位置。
2. **路径跟随与追击局部绕行**：被体积挡住后，沿"目标方向去掉沿被撞单位法向的分量"的切向以本 tick 剩余预算走完，下一 tick 目标方向不再穿过体积时恢复直走。目标方向偏向的一侧被地形或别的体积挡死就停，不换另一侧（换侧在窄道里会来回弹）；只有正对着撞上（没有偏向）时侧由法向逆时针垂线决定，且这时才再试另一侧。目标点本身落在挡路单位的体积里、或两侧都走不动时停在体积前。`path_avoid_units` 为假恢复"撞到即停（开 `wall_slide` 时滑一段）"。理由：导航契约已冻结且重规划开销大；局部绕行确定、便宜，绕不过去就停。
3. **受控位移推人**：`forced_push_units` 为真，且位移被体积（或地形）挡停、挡停策略不是回退时，被撞单位获得一个沿"停下位置 → 被撞单位中心"方向的强制位移，距离 = 剩余距离 × `forced_push_ratio` ×（1 − 被撞单位的击退抗性），曲线或速度沿用推人者的位移。同一 tick 同一目标的多个推力按（目标 id、推人者 id）排序后向量相加；已在受控位移中的目标不再被推。被推单位的位移从下一 tick 开始。缺省关，被挡即停。
4. **同 tick 顺序无关**：每 tick 开头给所有声明体积的单位拍一份快照（id、半径、起点位置），按 id 排序；单位自己的扫掠只看别人**起点**位置，不看本 tick 已经走完的位置。tick 末对"本 tick 都动过的"成对单位用相对运动求接触时刻，取最小比例，迭代到收敛（16 次），不收敛则归零；缩短后的位移必须仍过地形，否则回到起点。分离和强制位移推人也在 tick 末按 id 顺序处理，`unit.moved` 事件延后到 tick 末按 id 顺序、带最终位置发出。理由：单位按什么顺序处理不应改变结果；不变量测试把单位创建顺序与意图提交顺序打乱，要求逐位相同。
5. **穿过的位移种类数据声明**：`pass_through_motion_kinds`（逗号分隔的位移种类名，缺省 `dash,step_back`）；`dodge_through_units` 为真且位移种类在列表中才穿过。名字不认识在读取档案时报错并带上字段名。缺省与此前行为等价。穿过的位移（幽灵）本 tick 不参与成对接触与分离，窗口之后若落在别人体积里，由分离推出。
6. **先撞墙滑动又撞体积用折线精确扫掠**：滑墙后的位移是"到墙前 + 沿墙滑一段"两段折线，体积扫掠逐段进行（拐点 = 起点 + 方向 × (撞墙距离 − 回退量)），不再用起点到终点的直线近似；既不会误拦只和弦相交的体积，也不会漏拦只在第二段上的体积。

## 追加决定的后果

- 限制清单变短，但有两条换了形式：成对阻挡看到的是 tick 起点位置（跟随者最多滞后一个 tick）；缩短位移用起点到终点的弦做接触检测（保守，可能略微多缩短一点，并经地形校验）。
- 到达或位移结束的那个 tick 若恰好与别的单位成对碰撞，停下或到达事件的位置是成对裁决之前的位置，到达状态已经记录。
- 被成对裁决拉回的单位速度清零；路径下标只有在路径对象未变时才恢复。

## M4 增补（2026-10-02～03，手感落地 M4-B 与 M4-W2）

前面"追加决定的后果"列出的限制、第 6 节的"被推单位下一 tick 起得到强制位移"及备选方案里对"推人即时落到被推单位"的否决，都由本增补取代：先精确化（M4-B），再把求解做成可重放的多遍收敛（M4-W2）。全部仍只在本单位 `unit_body_radius > 0` 时生效，没声明体积的世界逐位不变；声明了体积但单位都不动或都是静态障碍（例如没有意图的木桩）时，路径是旧的连续扫掠，基线逐位不变。

### B：精确化（M4-B）

1. **"会动 / 不会动"分类**：每个有体积的单位按本 tick 是否在移动分类。不会动的单位是静态障碍，沿用连续扫掠（停下、滑开、绕行都按它的起点位置）；会动的单位之间**不当静态障碍**，它们之间的接触留到 tick 末按"最终位置"求解。跟随者因此不再滞后一个 tick。
2. **折线时间模型**：每个单位的位移是它本 tick **实际走的折线**（先撞墙滑动的拐点、绕行点、路径逐路点、受控位移与动作位移都计入），成对接触按折线逐段求首次接触：双方沿各自折线匀速走完，每个折线区间解一个二次方程取最早接触，不再用起点到终点的弦。
3. **不对称让路**：接触点上沿连线方向的速度分量决定"谁在靠近"。一方靠近另一方走开时，**只有靠近的一方让路**：它放慢到恰好使它与对方整个 tick 的轨迹都不再接触（阈值为半径之和加一个到达容差），所以快的跟随者追上慢的单位时贴着对方的**最终位置**，前面的单位轨迹与独自行走逐位一致，同速跟随时双方都不用让；相向或擦过时双方按同一比例对称缩短。
4. **事件延后**：位移到达与受阻事件对有体积的单位与"位移已发生"事件一样延后到成对裁决之后，按（单位 id，发生先后）排序、携带最终位置发出；没有体积的单位立即发，既有行为不变。
5. **快照追击**：追击与朝目标的动作位移，有体积的单位读目标的 **tick 起点快照**，不读目标此刻的位置；没有体积的单位仍读此刻位置（既有行为）。单位的创建顺序与意图提交顺序因此不改变位置与事件流。

### W2：可重放求解遍与三期补全（M4-W2）

1. **可重放求解遍**：运动 tick 做成可重放的事务——tick 开始时捕获全部单位的 tick 状态，每遍按当前的"会动"集合跑完整个 tick（扫掠加成对求解），事件与回调先进出口缓冲，只在最后一遍放出。一遍之后取"实际位移超过零长度容差"的单位集合，若会动集合里有实际没动的单位就收缩（只收缩不扩张，所以单调收敛）并从捕获的状态重来，**遍数上限 12**，超出时取最后一遍并保持"不重叠"守卫。规范起点是"本 tick 有尝试位移的单位都当作会动"，最终结果是"只有实际移动的单位被当作会动"这一不动点，与预判从哪里起步无关。第 B-1 条的 tick 起点预判因此降级为**加速提示**：预判全对的 tick 只跑一遍，预判错的代价只是多跑一两遍，不再退化成旧语义。
2. **速度剖面**：成对接触的时刻取运动仲裁给出的真实速度剖面（输入位移的加减速斜坡、动作位移与受控位移的曲线表）。折线给出位置，剖面给出"走到弧长 s 的时刻"；匀速仍走解析式，与旧算式逐位相同；根运动与一个 tick 内多种位移来源叠加时没有可信的 tick 内形状，按匀速处理。
3. **幽灵落点**：穿过式位移（幽灵）窗口内仍不被撞停、不参与重叠分离，但别的单位的成对裁决把它的**最终位置**当作静止的体积，所以别人会避让它的终点；窗口的**最后一个 tick**，幽灵终点不得落在别人体积里，按就近可行位置修正（体积圆的径向投影、圆周上的均匀采样点、两个体积圆的交点，取不落进任何体积、可走且离原终点最近者），修正与别人的裁决迭代到不再变化（轮数封顶）。被中断的窗口（击飞、死亡、击晕打断）没有"最后一个 tick"，落在体积里的由分离推出。
4. **切向速度与路径进度保留**：被成对裁决拉回的单位记下接触法线，保留**沿接触面的切向速度**（法向分量去掉），不再整体清零，贴着对方滑行的单位不会"粘住"；路径跟随的路径进度按实际走过的弧长恢复，本 tick 内路径被新请求替换时仍回到旧路径上的正确点，已记下的到达被撤销、到达事件随之取消。回到起点（地形守卫失败）的单位速度仍清零。
5. **同 tick 推人**：阶段 A 撞停触发的推人在**同一 tick** 生效：被推单位开一段受控位移后立即用真实的受控位移推进走完这一 tick，一轮里所有被推单位互为"会动"、对别的单位按它们裁决完的最终位置扫掠，所以结果与处理顺序无关；被推单位之间在一轮结束后按位移弦做一次成对接触求解；被推单位自己的位移又被挡住并触发推人时进入下一轮，**连锁最多 8 轮**，余下的退回下一 tick 起推进。原决策的备选方案否决"推人即时落到被推单位"是因为结果依赖处理顺序；一轮内互为会动加按最终位置扫掠消除了这一依赖，所以改为同 tick 生效。
6. **宽相网格**：阶段 A 的扫掠与阶段 B 的近邻对收集都用均匀网格缩小候选集，**只缩小候选、不改任何判定式**，结果与暴力两两比较**逐位一致**（有暴力对照的测试钩子证明）；位移包络特别大的少数单位逐个与全部参与者比较；参与者很少时不建网格。每 tick 复杂度由 `O(n log n + k)` 降为 `O(n + k)`。

## M4 增补的后果

- "追加决定的后果"里的三条限制（成对阻挡只看起点位置、缩短位移用弦、到达事件位置是裁决之前的位置）以及"被拉回的单位速度清零、路径下标只在路径对象未变时恢复"都已由本增补取代。
- 代价：运动 tick 在会动集合需要收缩时最多多跑到 12 遍（常见场景一两遍收敛，遍数上限只防病态输入）；成对求解多了速度剖面与轨迹记录的内部状态。
- 不变：可选开启、成对语义、穿过种类由数据声明、死亡单位不阻挡、离散步不受影响、体积半径随运动档案走。
