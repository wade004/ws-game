# ADR-0175 技能提示框内容与描述文本键

状态：已拍板 2026-10-09（来源：`docs/消费方反馈/消费方反馈-2026-10-09-样板游戏B-受击自动选中施法动作技能详情.md` 第 C 节；纯加法）

## 背景

技能栏鼠标悬停应显示技能详情（名称、类型、读条、冷却、消耗、射程、说明）。物品有框架的纯数据提示框内容（`ItemTooltipBuilder`），技能没有：每个游戏都要自己从 `skill.def` 拼文本，数值口径（读条/冷却取当前有效值、伤害含属性缩放）与本地化各写各的，英文界面容易混出中文。技能栏本身的绘制由游戏负责（框架只提供动作条视图模型），所以框架该给的是"内容"，不是控件。

## 决策

1. **`skill.def` 新增可选字段 `desc_key`**（本地化文本键，同 `name_key` 的类型与惯例；缺省时提示框不显示描述段）。
2. **新增纯数据 `SkillTooltipBuilder.Build(registry, skillId, text?, context?)` → `SkillTooltipContent`**（表现层 UI 视图模型，不含任何引擎类型）：名称、类型（读条/瞬发/引导）、读条时长、冷却时长、射程、资源消耗、效果数值（`school_damage`/`heal`）、描述；同时给出数值字段与文案行（`Rows`），两份互相印证。
3. **数值口径**：效果值 = 基础值 + Σ(系数 × 施法者当前属性)，属性读取由调用方通过 `SkillTooltipContext.Stat` 提供（不提供只算基础值）；读条/冷却的当前有效值同样由调用方通过 `SkillTooltipContext` 提供（动作条视图模型已有"有效冷却"），缺省取 `skill.def` 静态值。只列数据里真有的项：冷却为 0、瞬发的读条、没有消耗的技能不出现占位行；射程 0 表示作用于自身，显示"自身"。
4. **文案全部走本地化键**（`l10n.ui.skill_tooltip.*`，框架内容起步包提供中英文两份；技能名、描述、资源名取自各自的 `name_key`/`desc_key`）。键缺失、取不到文案时退回固定中文词与格式，与物品提示框口径一致。
5. 技能栏的悬停与点击施放由游戏自己的界面实现；点击施放应与热键走同一条输入意图通道（同一个动作名），因此冷却/射程/朝向/资源/读条限制与失败提示与热键完全一致。框架不新增点击施放的接口。

## 后果

- 新增数据字段 `skill.def.desc_key`、类型 `SkillTooltipBuilder`/`SkillTooltipContent`/`SkillTooltipContext`/`SkillTooltipRow`/`SkillTooltipCost`、起步包本地化行；不声明 `desc_key`、不使用构建器的游戏零影响。

## 限制（已知）

1. 效果行只覆盖带数值的 `school_damage`/`heal`；其它效果类型（召唤、控制、周期效果）不出数值行，说明靠 `desc_key`。
2. `base_curve_ref` 取代 `base_value` 的曲线型数值不在提示框里展开（只显示可算出的部分）。

## 备选方案与为什么不选

- **框架提供带控件的技能提示框。** 技能栏的绘制与皮肤、布局因游戏而异，且物品提示框同样是"框架给内容、引擎侧控件画"的分工；不重复一套控件。
- **由描述文本里写占位符（`{damage}`）替换数值。** 需要一套新的模板语法与校验；行内数值已由 `Rows` 给出，描述保持纯说明文字。
