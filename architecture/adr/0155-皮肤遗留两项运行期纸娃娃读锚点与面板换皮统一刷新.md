# ADR-0155 皮肤遗留两项：运行期纸娃娃读锚点、换皮肤时所有面板统一刷新

状态：已拍板 2026-10-05（收口 [ADR-0152](0152-参考界面皮肤包与真实素材回归.md) 决策 8 与决策 10 留下的两项已知限制，落实 [手感设计/08](../手感设计/08_装备与UI资产契约.md) 第 3 节；只加不改：未声明锚点的数据集与未换过皮肤的游戏逐位不变）

## 背景

ADR-0152 留了两项"已知限制，未做"：

1. **锚点只驱动预览区**。静态层精灵集的 `anchors.json` 可选声明 `directions.<方向>.grip`，装备面板的预览区会把它对到身体同名挂接点上，运行期合成（适配层 2D 渲染器的 `SetLayers`）却仍按各层画布居中叠放。参考包的层图在制作时已预摆好位置，所以两处恰好一致；换一套"层图不预摆位置"的美术，游戏里武器就会漂在错的地方。
2. **换皮肤只刷新订阅了换肤事件的部件**。`UiVisuals.SwitchSkin` 发出 `SkinChanged`，背包、装备、提示框、拖拽订阅它重建；HUD、动作条、任务日志、技能书、角色属性、设置、存档、暂停、商店、对话与主菜单、实验室控制条经 `UiWidgets` 建控件时一次性取了当时的皮肤精灵与颜色，之后不再更新，换肤后仍是旧皮肤。

另有一处相关的混乱：`UiSkin` 全局覆盖由谁装、谁撤，宿主（`UiPanelHost`）、实验室衣橱场景、`UiVisuals` 各自记着一个"是不是我装的"标志，`SwitchSkin` 与它们互不知情。

## 决策

1. **运行期合成读同一份锚点、用同一条公式**。新增公共的对齐数学 `PaperdollAnchors.AttachOffset(挂接点像素, 身体枢轴像素, 身体比例, grip 像素, 层枢轴像素, 层比例)`：像素坐标先减各自的枢轴、乘各自的"像素到输出单位"比例、把 y 翻成向上，结果 = 身体点 − 层点，即层需要相对"枢轴落在原点"的默认摆位平移的量。预览区传画布中心作枢轴、两边同一个缩放（输出单位是预览框像素）；运行期传各精灵自己的枢轴与 `1 / 像素密度`（输出单位是世界单位）。两边是同一个函数，所以"grip 对到挂接点"在两处是同一条规则，预览区的行为逐位不变（运算次序与改动前一致）。加载器新增 `TryGetSpriteSetAnchor(集, 方向, 锚点名, out 像素)`，读它按精灵集缓存的同一份 `anchors.json` 解析结果（换皮肤时随既有的锚点缓存失效一起清掉），`UiVisuals.TryGetAnchor` 改为转发它，不再自己再缓存一份。
2. **运行期对齐的触发条件与不变量**：`SetLayers` 在以下条件全部成立时对层做平移，任一不成立该层本地位置恒为原点（与改动前逐位一致，精灵对象也是同一个）：存在名为 `body` 的层；该层与身体层不在同一个精灵集（身体集自己的 `hand_main`、`head` 层是它的画布内摆位，不是挂在身体上的装备）；层精灵与身体精灵都已加载（未加载时是占位方块，不对齐）；层所在精灵集声明了该方向的 `grip`，且身体所在精灵集声明了该方向同层名的锚点。层名取资源 id `layer.<集>__<方向>__<层>` 的末段，与预览区同一约定。
3. **镜像**：渲染器的水平镜像（`flipX`）绕精灵枢轴翻，平移量的 x 随之取反，使镜像后 grip 仍落在镜像后的挂接点上；镜像状态改变时（不重新 `SetLayers`）重写层的本地位置。
4. **逐层动画帧不平移**：逐层动画剪辑的帧（`SetLayerSprite`）是另一套美术、自带枢轴摆位，占着的层平移量归零；`RestoreLayerSprite` 写回静态层图时恢复。`SetLayers` 全量重写时清空这一记录。
5. **加载晚到**：层图晚于首次 `SetLayers` 加载完成时，由既有的"加载完成 → `SetLayers` 全量重写"链路重新计算，与热路径是同一个出口，不新增通知机制。
6. **换皮肤时所有界面部件统一刷新**：新增登记表 `UiSkinBindings`。`UiWidgets` 建的每个面板底板、按钮、标签、进度条填充都在登记表里记一笔"它当时从 `UiSkin` 取了什么"；`UiVisuals.SwitchSkin` 在 `SkinChanged` 之前调用 `UiSkinBindings.ReapplyAll()`，把"仍等于登记值"的属性换成 `UiSkin` 现在的取值（底图、按钮图与切换状态、字体、文字色、强调色）；面板自己改过的属性保持原样。这样不订阅 `SkinChanged` 的面板（HUD、动作条、任务日志、技能书、角色属性、设置、存档、暂停、商店、对话、主菜单、实验室控制条）自动在内，不需要逐面板接线。订阅 `SkinChanged` 整体重建的背包、装备、提示框、拖拽保持原做法。不经 `UiWidgets` 自己造图像的面板必须订阅 `SkinChanged` 或调用 `UiSkinBindings.TrackPanel/TrackFlat/TrackAccentFill` 登记（设置面板的音量条填充已补）。登记表是进程级静态的（同 `UiSkin` 本身是全局覆盖）；已销毁的控件在刷新时与登记数超过阈值时清掉。
7. **`SwitchSkin` 接管全局 `UiSkin` 覆盖，覆盖归 `UiVisuals` 持有**：新增 `UiVisuals.InstallSkinOverride(onlyIfFree)`、`ReleaseSkinOverride()`、`OwnsSkinOverride`。`SwitchSkin` 无条件撤掉当前覆盖（包括别人装的）、按新皮肤包重装（占位皮肤不装），装上后覆盖归 `UiVisuals`，`Dispose` 时撤掉。宿主装配用 `onlyIfFree: true`（"调用方自己装过覆盖时以调用方的为准"，行为不变），销毁时只对自己让装的那一次调 `ReleaseSkinOverride`；实验室衣橱场景用无条件安装，换肤时不再整条重建控制条（由统一刷新覆盖）。宿主、场景各自的"是不是我装的"标志删除，归属只有一处。
8. **旧皮肤包仍保留到 `Dispose`**：已换下的包不立即销毁，仍被外部持有的精灵不会悬空；`UiVisuals.IsRetiredSkinSprite` 与 `UiSkinPack.Owns` 供诊断与用例判断"某个精灵是不是旧包的"。

## 验证

- 运行期对齐（引擎内运行用例）：参考武器在五个已制作方向、正常与镜像两种状态下，武器 `grip` 像素的世界坐标 = 身体 `hand_main` 像素的世界坐标（期望值由精灵像素点的世界坐标独立算出，锚点值读自 `anchors.json` 文件，不复用生产公式），且对照"居中叠放"时两点分开；武器集与身体同像素密度时，运行期的武器相对身体位移 = 预览区的相对位移；未声明的四类情形（无 `anchors.json`、身体无同名挂接点、层无 `grip`、与身体同集的层）与无 `body` 层时本地位置恒为原点、精灵为同一个对象；逐层动画帧归零并在写回后恢复；镜像切换的 x 取反。
- 统一刷新：遍历 `UiPanel` 全部枚举值（面板登记表必须覆盖每个取值）加 HUD，占位 → 参考 → 占位 → 参考三次切换后，界面树里的每个图像与按钮状态图都不属于旧皮肤、也不在"上一代 `UiSkin` 精灵而不在这一代"里；登记控件无停在旧值上的；每个面板含一块现行皮肤的底板；换前取皮肤文字色的标签都跟到新皮肤的文字色；一个未登记的对照图像必须被判成漏网（证明判定抓得住）。
- 覆盖归属：别人装的覆盖被 `SwitchSkin` 接管，换回占位皮肤撤掉，`Dispose` 撤掉。

## 代价与限制

- 对齐只作用于静态层图；逐层动画剪辑的帧不对齐（决策 4）。
- 身体基准是名为 `body` 的层；层精灵与身体精灵任一尚未加载时该层暂不对齐，直到下一次 `SetLayers`（加载完成链路会触发）。
- 预览区对身体与层用同一个缩放，运行期各按自己的枢轴与像素密度。参考包的物品精灵集没有声明 `pixels_per_unit`（运行期落在加载器缺省密度，与身体的 32 不同），所以参考武器在游戏里画得比预览小：grip 仍对在挂接点上，但大小比例不同。这是既有的数据缺口，本切片不改参考素材；给物品集声明与身体一致的像素密度即可，对齐规则不需要变。
- 旧皮肤包每换一次肤多留一份到 `Dispose`（内存略增，换肤是低频操作）。
- 统一刷新靠"仍等于登记值才换"区分面板自己改过的属性：面板把某个皮肤属性改成了恰好等于旧登记值的值，会被当成未改动而换掉；当前没有这种用法。
