## 1. 魔兽的经济设计梳理

经济系统的骨架是水龙头和下水道：钱从哪来，钱往哪去，两边的速率在每个等级段对得上。中间是定价规则。

### 1.1 货币与水龙头

一种主货币，金银铜三段显示，本质一个整数。来源按重要性：

| 来源 | 规则 | 备注 |
|---|---|---|
| 灰色物品 | 怪掉的"垃圾"，只能卖商人，售价按怪等级配 | 把击杀变成金币的物理载体 |
| 怪物直接掉钱 | 人形怪按等级掉铜币区间，野兽只掉材料 | 生物模板有最小最大金币两列 |
| 任务金币 | 按任务等级查表，满级后经验按汇率转金币 | 满级后主要收入 |
| 装备卖商人 | 售价是物品等级和品质的函数 | 装备的第二条价值轴 |
| 日常任务、采集制造 | 多人运营与玩家间经济 | 单机不需要 |

经典时代四十级坐骑一百金、六十级史诗坐骑一千金，是升级期最大的储蓄目标。

### 1.2 下水道与定价

| 类 | 例子 | 职责 |
|---|---|---|
| 常规小额 | 修理费、食物水、药水、交通费 | 抵消日常水龙头 |
| 阶梯大额 | 坐骑与骑术、技能学习费 | 给储蓄一个目标 |
| 无上限 | 拍卖行手续费、幻化、收藏坐骑 | 吸收满级后过剩金币 |

修理费是最重要的常规下水道。技能学习费后期取消，理由是它惩罚的是升级本身。**定价规则全部挂在物品等级上**：买价售价由公式从物品等级、品质、类别生成，商人卖价约是收购价的四到五倍。

### 1.3 多货币与玩家间经济

副本徽章是应对掉落随机性的保底机制，后来货币种类膨胀到几十种又一轮轮合并。教训两条：保底货币是好机制，货币种类必须少。拍卖行、交易、邮件、公会银行、代币与每资料片十倍的通胀，单机全部不需要。

六条精髓：每个等级段期望收入对应期望支出；买价售价修理费全是物品等级的函数；灰色物品是击杀变金币的载体；阶梯大目标给储蓄以意义；修理费是常规下水道主力；保底货币对冲随机性且货币要少。

### 1.4 框架现状

08 第 7 节此前只有：货币定义（id、上限），商人（出售清单每件手填绝对价格，收购价规则），四个事件。没有买价售价公式、怪物掉钱、任务金币、任何下水道定义。商人价格手填绝对数和词缀写绝对数是同一个问题。

## 2. 单机方案

### 2.1 货币与定价

- **一种货币，一个整数。** 不做金银铜三段，大数由表现层格式化。不做副货币。
- **价格挂物品等级。** 价值曲线(物品等级) × 品质价格倍率 × 槽位价格倍率 = 基准价值；买价 = 基准价值；售价 = 基准价值 × 售价比例（策略项，建议四分之一）。物品模板加可选价值覆盖，商人价格改可选，不填走公式；手填偏离公式报警告。

### 2.2 水龙头与下水道：框架只做框架层的事

初版方案曾包含每级支出表、收入倒推、限量商人保底、词缀重洗作为无上限下水道。用户逐条划界，最终如下：

| 项 | 结论 | 归属 |
|---|---|---|
| 水龙头与下水道的平衡 | 不做 | 游戏层 |
| 怪物掉钱（金币基数当量）、任务金币当量、装备回收 | 做 | 框架：两条曲线与当量写法 |
| 复活费、快速旅行费 | 做 | 框架：原子扣费契约，扣多少归游戏层 |
| 限量商人当级装备 | 不做 | 游戏层，商人表字段已足够 |
| 坐骑、骑术 | 做 | 框架：坐骑是速度光环加外形层（00 既定），骑术是被动，购买是商人卖物品 |
| 背包扩容、功能解锁 | 不做 | 游戏层；框架背包容量固定，留"引用属性"扩容口子 |
| 词缀重洗 | 不做 | 游戏层，用词缀池与扣费契约可拼出 |
| 灰色物品 | 不做 | 怪直接掉钱自动拾取 |

### 2.3 两处应对措施

**复活费没钱怎么办。** 复活永远不被金钱阻断。费用取"计算值与当前余额的较小者"，余额为零扣零。计算方式为策略项，百分比或固定值二选一，百分比天然不超余额，固定值靠取小者兜底。玩家没钱时的额外惩罚归游戏层。

**掉钱与背包满。** 货币不进背包不占格子，背包满不影响拾取。入账方式为策略项：击杀即入账（默认）或掉在地上靠近自动拾取。唯一边界是货币上限：达到上限时超出部分丢弃并发溢出事件，游戏层订阅处理。

### 2.4 坐骑与骑术、背包容量

- 坐骑是主动技能（施加速度光环并切换外形层）；骑术是被动技能，坐骑技能的使用条件是"已习得骑术"；购买是商人卖一个使用后学会骑术的物品，金币在此消耗；进入战斗时移除坐骑光环为策略项默认开；室内不能骑等限制由使用条件表达。
- 背包容量登记为一个数值，来源为固定值或引用一条属性（与资源上限同一写法），默认固定值。游戏层要扩容就让容量引用属性并用光环或物品修改，框架不做扩容功能。

## 验收标准

1. 任一商人条目与掉落货币条目的金额都能由两条曲线加倍率手算。
2. 余额为零的单位执行复活流程不会被阻断。
3. 背包满时拾取货币成功；货币达到上限时溢出事件被发出。
