## 1. Item（物品与装备）

目录名：`core/carriers/item`（载体层，见 01）。

### 1.1 模板字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | Id | 是 | `item.<name>` |
| `name_key` | Id | 是 | 显示名文本键 |
| `slot` | Id | 是 | 槽位枚举，由数据定义（见下），非架构硬编码 |
| `quality` | Id | 是 | 品质（如 `common/uncommon/rare/epic` 一类分档，具体分档由数据定义） |
| `item_level` | Int | 是 | 物品等级，用于预算公式与掉落/商店的等级匹配 |
| `stats` | List<StatModifier 片段> | 否 | 装备后提供的固定/百分比属性 |
| `grants` | `{skills: List<Id>, auras: List<Id>}` | 否 | 装备后授予的主动技能与被动光环（拍板决策 1 的落地字段） |
| `affixes` | List<Id>（引用 `item.affix`） | 否 | 词缀引用，见 1.6 扩展位 |
| `set_id` | Optional<Id> | 否 | 所属套装 |
| `weapon_profile` | Optional<{damage_min, damage_max, speed, weapon_school}> | 视 slot 而定 | 武器类槽位的伤害与攻速定义，决定普通攻击的数值输入 |
| `display_ref` | Id | 是 | 指向 `display.map`，决定外形与纸娃娃层 |
| `stack_size` | Int | 是 | 最大堆叠数量，非装备类消耗品/材料用 |
| `requirements` | Optional<{level: Optional<Int>}> | 否 | 装备等级需求 |

槽位枚举、品质分档均在专门的数据表中登记（例如 `item.slot_definition`、`item.quality_definition`，字段为 `id` + 显示名文本键 + 排序权重），架构本身不预设"必须有武器/护甲/饰品几个槽位"，具体游戏按需要定义。

### 1.2 物品等级预算公式

预算公式的契约是"给定 `item_level` 与 `quality`，算出该件物品全部 `stats` 条目允许消耗的预算总量上限"，具体系数曲线由数据（`item.budget_curve`，登记在 04 总索引下，字段为 `item_level → budget` 的分段曲线）定义；校验器（04 第 5 节"预算超标"项）在内容提交时核算每件装备的实际属性消耗是否超出该上限。架构固定"存在预算约束"这一机制，不固定具体系数。

### 1.3 背包与装备栏接口

```
interface InventoryHost {
  addItem(unitId: Id, itemTemplateId: Id, count: Int): Bool
  removeItem(unitId: Id, itemInstanceId: Id, count: Int): Bool
  listItems(unitId: Id): List<ItemInstance>
}

interface EquipmentHost {
  equip(unitId: Id, itemInstanceId: Id, slot: Id): EquipResult
  unequip(unitId: Id, slot: Id): Optional<ItemInstanceRef>
  getEquipped(unitId: Id, slot: Id): Optional<ItemInstanceRef>
}
```

### 1.4 穿脱流程对属性与外形的影响

1. `equip` 成功后：按 `stats` 字段对该 `Unit` 的 `StatBlock` 调用 `addModifier`（`sourceId` 为该件物品实例 id，见 06 第 1.2 节）；按 `grants.skills` 加入可用技能集合；按 `grants.auras` 施加对应被动光环（`sourceId` 同为该物品实例）；按 `display_ref` 更新该槽位对应的纸娃娃层（表现层订阅 `item.equipped` 事件后处理，逻辑层不直接碰渲染）。
2. `unequip` 时：调用 `removeModifiersBySource` 撤销该物品带来的全部属性修正；移除对应授予的技能与光环；纸娃娃层订阅 `item.unequipped` 事件后移除该层。
3. 若武器类槽位变化，普通攻击的数值输入（来自 `weapon_profile`）与外形（普攻动作、技能特效变体）随之更新——武器决定表现的具体绑定方式见第 6 节。

### 1.5 与魔兽 `item_template` / `ItemDisplayInfo` / `SpellItemEnchantment` / `ItemSet` 对照

| 魔兽表/字段 | 本架构对应 | 裁剪说明 |
|---|---|---|
| `item_template` 主体字段（槽位、品质、属性、需求等级等） | `item.template` | 保留核心结构；去除需要网络/账号语义的字段（如绑定方式的多人交易含义，见扩展位） |
| `item_template.spellid_*`（装备触发的法术） | `grants.skills` / `grants.auras` | 统一收拢为"授予技能/光环"，不区分"装备时触发"与"使用时触发"两套字段，改由技能定义自身的触发方式区分 |
| `ItemDisplayInfo`（外观模型、粒子附件） | `display.map`（`category: item`） | 收拢进统一外形映射表，不单列 |
| `SpellItemEnchantment`（附魔） | 扩展位（见 1.6），不在初版实现 | 单机初版不做交易行/附魔师等前置系统，附魔留空位待需要时再设计 |
| `ItemSet`（套装效果） | `item.set` | 保留"件数门槛 → 额外效果"的结构，额外效果同样以 `apply_aura` 表达 |

### 1.6 可选扩展点（留位）

以下能力在本版不展开设计，只在字段表预留空位，避免未来加入时破坏既有 schema：

| 扩展点 | 预留方式 |
|---|---|
| 附魔 | `item.template` 预留 `enchant_slot: Optional<Id>` 字段，指向未来的 `item.enchant` 表 |
| 宝石镶嵌 | 预留 `socket_count: Int`（默认 0）与 `socket_ids: List<Optional<Id>>` |
| 耐久 | 预留 `has_durability: Bool`（默认 false）与运行期 `ItemInstance.durability` 字段位 |
| 绑定 | 预留 `bind_type: Optional<none\|on_pickup\|on_equip>`，单机默认不产生实际限制，只作数据兼容位 |
| 随机属性 | 预留 `stat_roll_ref: Optional<Id>`，指向未来的随机属性生成规则表 |

### 2.2 职能标志位清单

| 标志 | 语义 |
|---|---|
| `vendor` | 具备商人交互（挂接 `econ.vendor`） |
| `trainer` | 具备技能训练交互（挂接技能书/天赋学习动作） |

| `ModelId` / `DisplayId` | `display_ref` | 收拢进统一外形映射表 |

## 3. GameObject（游戏对象）

目录名：`core/carriers/gobj`（载体层，见 01）。

### 3.1 类型枚举与类型数据

| 类型 | 类型数据要点 | 语义 |
|---|---|---|
| `door` | `open_state`（经 WorldState 记录）、关联 `lock_id` | 可开关的门 |
| `chest` | `loot_table_ref`、`open_state` | 开箱获取掉落 |
| `quest_object` | `quest_action_ref` | 任务专用交互物（如任务道具、任务触发器） |
| `trap` | `skill_id`（触发时释放的技能）、`trigger_shape` | 踩踏/触碰触发效果 |
| `spell_focus` | `required_skill_tag` | 施放特定类别技能的焦点（如献祭台） |
| `gather_node` | `loot_table_ref`、`respawn_after_use` | 采集点 |
| `teleporter` | `teleport_target_ref` | 传送点 |
| `save_point` | 无额外字段（复用 `npc_flags.save_point` 同等语义，供非生物承载） | 存档点 |
| `lever` | `linked_object_ids: List<Id>`、`on_use` | 机关拉杆，联动其它对象状态 |
| `sign` | `text_key` | 纯文本告示牌，无交互副作用 |

`gobj.template` 顶层另有 `name_key`（Id，必填，显示名文本键）与 `tags`（List<Id>，可选，标签集合，供筛选/查询用）两个字段，不随类型变化。

勘误（拍板 1，见 12 §5、[ADR-0001](adr/0001-万物皆法术.md)）：`door`/`chest`/`gather_node`/`lever`
四种类型各自固定的核心行为（开关门的 `open_state` 切换、开箱与采集按 `loot_table_ref` 掉落、拉杆的
联动切换）由载体层（`GameObjectHost`）直接结算，是 `on_use` → Skill 这一常规路径的合理例外——这类
"kind 内置行为"是该类型本身的定义（一把椅子式的通用行为，不是某个具体物件的定制内容），`on_use`
在这些类型上是可选的叠加内容定制层，而不是行为的唯一入口；`trap` 等类型仍严格经 `on_use`/`skill_id`
走技能管线，不属于这一例外（见 3.3 节）。

`teleporter` 的 `teleport_target_ref` 编码规则：值为 `Id`；恰为两段（即某条 `world.map` 行 `id`，如 `world.town_square`）→ 目标是该地图 `spawn_points[0]`；恰为三段、前两段拼接后等于某条 `world.map` 行 `id`（如 `world.town_square.fountain`）→ 第三段与该地图 `teleport_points[]`（先查）/`spawn_points[]`（再查）逐条按 `id` 的最后一段匹配（见 05 第 4.1 节示例，点位 `id` 各自有独立领域前缀 `spawn.`/`tp.`，不与地图 id 共享前缀）→ 目标是命中点位的 `position`；其余情况解析失败，不产生位移，只记诊断。

### 3.2 锁规则

```
struct LockDef {
  id: Id
  requirement: item_key(itemId: Id)
             | world_flag(flagKey: Id, expected: Value)
             | skill_check(skillTag: Id, minValue: Number)
  consumeKey: Bool  // 默认 false；requirement 为 item_key 时，开锁成功后是否消耗该钥匙物品
}
```

`gobj.template.lock_id` 引用 `gobj.lock`；开锁尝试（经 `open_lock` 效果或直接交互）按 `requirement` 类型分别校验：持有指定钥匙物品、指定世界标志达到期望值、或某项技能相关数值达到门槛（对应魔兽的开锁/急救类技能值判定，单机简化为读一个数值属性比较）。

### 3.3 on_use

`gobj.template.on_use` 指向一个 `skill.def`（复用 06 的 Effect 原语，例如 `open_lock` + `create_item` 组合表达"开箱掉落"）或一个 `dialog.gossip_menu` 动作项（见 08），二者二选一，不并存；对象被交互时按 `on_use` 类型分发到对应系统处理。

### 3.4 状态与 WorldState

`GameObject.state`（见 05）中的可变字段（如 `chest` 的 `open_state`）不是对象私有存储，而是落地为一条 `WorldState` 标志（`flagKey` 按约定拼为 `world.gobj.<实例id>.<字段名>`，实际形态如 `world.gobj.inst_12.open_state`），使得对象状态天然随存档持久化、天然可被 Expr 在其它系统中引用（例如"这个箱子开过了"同时驱动掉落不再刷新与某条对话文案变化）。

### 3.5 与魔兽 `gameobject_template` / `Lock` 对照

| 魔兽字段 | 本架构对应 | 裁剪说明 |
|---|---|---|
| `type` 枚举（Door/Chest/QuestGiver/…） | 第 3.1 节类型枚举 | 收窄到单机 2.5D 场景实际需要的十类，新增类型走审批 |
| `Lock.dbc` 的多种开锁方式（技能、物品、法术） | `LockDef.requirement` 三种变体 | 收窄为钥匙物品/世界标志/技能数值三类，覆盖魔兽锁的常见用法 |
| `data0..data23` 通用槽位字段 | 按类型拆分为具名的类型数据字段（见 3.1 表） | 用具名字段替代泛化槽位，牺牲一点通用性换取可读性与校验能力 |

### 3.6 契约

```
interface GameObjectHost {
  interact(unitId: Id, gobjInstanceId: Id): InteractResult
  tryUnlock(unitId: Id, gobjInstanceId: Id): Bool
}
```

- `interact` 是交互的统一入口，按 `on_use` 类型分发到 3.3 节描述的技能/对话系统；`tryUnlock` 是开锁尝试的独立入口，按 `LockDef.requirement` 三种变体校验，供未直接经 `interact` 触发的开锁场景（如 `open_lock` 效果）复用。

## 4. 召唤与宠物

- 召唤物与宠物复用 `CreatureUnit`（05），额外携带 `ownerId: Id` 字段。
- 跟随规则：拥有 `ownerId` 的 `CreatureUnit` 默认行为外壳状态机加入一条隐式转移——`owner` 移动超出跟随距离时优先转入向 `owner` 靠拢的移动，而非按自身 `patrol`/`chase` 逻辑；具体跟随距离、是否参战、是否共享仇恨表是策略配置项。
- 玩家操控（策略配置项）：是否允许玩家直接操控召唤物——开启时，该召唤物在离散模式下视同玩家行动者（轮到它时等待外部提交意图，不由 AI 自动接管）；未开启时始终按普通 AI 行动者对待。
- 随主人进出战斗：`owner.combatState` 变化时，若策略要求宠物同步进出战斗，则联动置位召唤物的 `combatState`；是否联动、联动方向（单向/双向）为策略配置项。
- 召唤物生命周期：由 `summon` 效果创建，按 `skill.def` 参数决定存在时长（`duration` 到期销毁）或跟随 `owner` 直到主动取消/死亡；不进存档（同 05 对 `CreatureUnit` 的默认结论），读档后由拥有者相关状态（如"当前是否应有宠物"）经 `WorldState` 或 `PlayerUnit` 自身字段驱动重建。

## 5. 职业与天赋数据

- **职业** = 主属性引用 + 资源类型引用 + 技能书（`skill.book`）+ 天赋树引用（`arch.talent_tree`），全部字段登记在 `arch.class`（见 04）。
- **天赋** = 天赋树节点激活后施加的被动光环，光环内容以 `SpellMod`（06 第 3.5 节）或 `override_skill`（06 第 3.3 节）表达，即"天赋只是一种特殊的被动光环来源"，不引入独立于 Skill 系统之外的天赋效果模型。
- **种族** = 直接属性修正（`arch.race.stat_mods`，以固定值写入属性，不经过 Skill 系统）+ 可选被动光环引用（`arch.race.passive_auras`，指向光环定义，复用 Skill 系统），不单独建模成第三套效果系统。

## 6. 外形层

- 纸娃娃层清单由数据定义：`display.map` 的 `paperdoll_layers` 字段（04 已登记）按类别（如"基础形象/头部/上衣/下装/武器/背部"等）列出具体层的资源引用，具体分几层、每层叫什么完全由游戏层的美术管线约定决定，架构不预设固定层数。
- 武器决定普通攻击动作与技能特效变体的实现位置：`item.template.weapon_profile.weapon_school` 与武器的外形分类（经 `display_ref` 关联）共同决定——普通攻击动作的选择属于表现层职责，按"当前装备武器的外形分类"查询对应动作片段（详见 09）；技能特效变体（例如同一个技能因持双手剑/持法杖而播放不同特效）通过 `display.map` 为同一技能 id 按"当前武器分类"登记不同的 `vfx_id`，或在 `skill.def.effects` 中让相关效果引用一个"按武器分类选择变体"的间接 id（具体选择机制留待 09 表现层文档展开，本节只确认"武器分类是该选择的输入维度之一"这一契约）。

## 7. 抛射物

目录名：`core/carriers/projectile`（载体层，第四类载体，见 01）。

### 7.1 定位

抛射物是由技能 `projectile` 效果原语（见 06 第 3.2 节）生成的飞行实体（`Projectile`，见 05 第 1.4 节字段引用），逐 tick 推进飞行、按命中行为判定命中，命中后把命中后效果列表统一回灌规则层的效果入口（06 定义的效果结算管线），不建立与 06 并行的第二套结算路径。

### 7.2 效果参数

`projectile` 效果的 `params` 字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `travel_mode` | `straight\|homing\|arc` | 否，缺省 `straight` | 飞行方式（见 05 第 1.4 节） |
| `hit_behavior` | `impact_on_first\|pierce\|impact_on_expiry` | 否，缺省 `impact_on_first` | 命中行为 |
| `speed` | Number | 否，有策略配置项缺省值 | 飞行速度（单位距离/秒） |
| `max_range` | Number | 否，有策略配置项缺省值 | 最大射程，超出仍未命中/到期视为未命中 |
| `arc_height` | Number | 否，有策略配置项缺省值 | `arc` 飞行方式的抛物线峰值高度（纯表现参数，驱动 `heightOffset`，不参与平面距离与碰撞计算） |
| `impact_radius` | Number | 否，有策略配置项缺省值 | `impact_on_expiry` 到期时的命中判定半径 |
| `max_pierce_count` | Optional<Int> | 否，缺省不限 | `pierce` 命中行为最多穿透命中的单位数 |
| `display_ref` | Optional<Id> | 否 | 指向 `display.map`，决定外形；未提供时按未知种类降级处理 |
| `on_hit_effects` | List<EffectRef> | 否，缺省空列表 | 命中后交回规则层效果管线的效果列表，形状同 `skill.def.effects[]`（见 06 第 3.1 节） |

命中行为语义：`impact_on_first` 命中最近的第一个候选后立即回灌效果并销毁；`pierce` 命中即回灌效果但不销毁，继续飞行直到 `max_pierce_count`（若给出）耗尽或超出 `max_range`；`impact_on_expiry` 飞行途中忽略单位命中，只在到期时按 `impact_radius` 做一次范围判定并回灌。撞墙、超出射程仍未命中、或到期范围内无符合条件目标，均直接销毁、不回灌任何效果。

### 7.3 契约、事件与生命周期

规则层（06）声明的抛射物生成契约由本模块实现（依赖倒置：规则层只依赖一个"生成一个投射物"的最小接口，具体的 `Projectile` 实体与飞行推进逻辑属于载体层，规则层不得反向依赖载体层）。

抛射物没有专属事件：生成与销毁复用既有的通用实体事件（见 05 第 1 节 Entity 生命周期），命中后效果本身产生的事件（如伤害结算事件）经既有效果管线正常发出。

生命周期：随移动与导航阶段推进（紧随移动系统之后、战斗结算之前，保证命中判定用的是本步全部单位完成移动之后的最新位置）；不进存档（同 05 第 1.4 节"进存档：否"）。

### 7.4 策略配置项

飞行速度、最大射程、抛物线峰值高度、命中判定半径、命中判定所需的标签过滤、离散模式下每步的等效秒数（用于飞行距离换算，复用"速度 × 时间"的位移公式，不为离散模式另写一套）均为策略配置项缺省值，具体一发抛射物的取值以效果 `params` 显式指定为准。

## 验收标准

1. 任给一件"装备后获得主动技能或被动效果"的物品，能用 `grants` 字段表达，无需额外的"物品专属效果代码"。
2. 任给一只 NPC 兼具"商人 + 任务发放者"两种职能，能通过在 `npc_flags` 中同时登记 `vendor` 与 `questgiver` 表达，不需要新建生物子类型。
3. 任给一个"需要特定钥匙或达成某剧情节点才能打开"的物件，能分别用 `item_key` 与 `world_flag` 两种 `LockDef.requirement` 表达。
4. 召唤物/宠物的实现完全复用 `CreatureUnit`，文档中未出现与 05 冲突的第二套生物字段定义。
5. 附魔、宝石、耐久、绑定、随机属性五个扩展点均只出现字段预留，没有展开设计细节或提前拍板具体规则。
6. Item/Creature/GameObject/召唤与宠物四个模块均给出目录名、契约、数据表、事件、依赖层、策略配置项、测试方式。
