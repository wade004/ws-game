## 1. 定位

手感（game feel）是玩家的输入与世界的反应之间那条可感知的因果链：按下去多久有反应、角色起步和急停像不像有重量、一刀砍下去有没有打到东西、打到之后世界怎么回应。它不是某一层的功能，而是横跨输入、规则、模拟、表现四层的横切关注点。

本目录把手感做成框架的一等交付物，目标是：新游戏**不再重新开发手感机制**，而是选一套经过实验室验证的预设、做一次标定、在实验室里微调。这里的"直接用"指机制、档案结构、分层解析、调参与验收工具零开发，以及在兼容条件下复用验证过的预设；它不承诺任何模型、动画、镜头与设备组合都不需要试玩微调，也不承诺某个复用百分比。

手感体系不拥有任何玩法权威：技能合法性、伤害、资源、冷却、状态归规则层（06）；手感体系只决定动作何时开始、何时判定、何时能被打断，以及世界怎么把结果表现出来。表现侧的反馈永远不能自行判定伤害、修改生命值或重复结算（09 铁律 P2/P3 不变）。

## 2. 两半拆分（核心原则）

手感按"是否改变模拟结果"切成两半，这是本目录所有设计的第一条约束：

| | 判定型手感 | 呈现型手感 |
|---|---|---|
| 定义 | 改变"动作何时发生、位置怎么变、谁被打到" | 只改变"玩家看到听到什么" |
| 内容 | 输入缓冲、宽限窗口、动作分相与取消窗口、连招接续、加减速与转向、运动仲裁、击退运动、无敌窗口、局部顿帧、硬直裁决 | 动画姿势与步态、打击反馈包（闪白、后仰、震屏、特效、音效分层）、镜头跟随与冲击、飘字、拖尾、残影 |
| 所在层 | L0 输入映射、L2 规则层（技能/战斗）、L1 模拟（移动）| L5 表现层 |
| 时钟 | 模拟时钟与行动者动作时钟（第 5 节） | 表现帧，读真实时钟 |
| 确定性 | 必须：同输入脚本同结果，逐字节一致 | 不要求逐字节；指纹按容差比较 |
| 进存档 | 只有瞬态，不进存档（读档清空） | 不进存档 |
| 离散模式 | 整体不生效（第 7 节） | 生效（回放队列内） |
| 数据存放 | 逻辑层可读的表（单位模板、技能定义、`feel.*`） | 表现层表（`feedback.*`、`camera_profile`、`display.*`） |

一个字段属于哪一半在字段登记时声明（05 第 4 节），不允许一个字段两边都读。判定型字段绝不放在 `display.*`（规则层不读表现域）；呈现型字段绝不被规则层读取。

## 3. 横切结构

不新建"手感层"。手感体系由一个解析器、若干判定型消费者、若干呈现型消费者和一组开发期工具构成，各自落在既有的层与模块内：

| 组件 | 层 / 模块 | 职责 | 详见 |
|---|---|---|---|
| 手感解析器（FeelResolver） | L0 `core/foundation` 新模块 | 纯函数：实体 + 当前状态（武器、体型、姿态、当前动作、临时状态）→ 一张展平的不可变"手感表"（ResolvedFeel），带逐字段溯源；按实体缓存，由失效事件重算 | 05 |
| 输入缓冲与宽限 | L0 `core/foundation/input_map` 扩展 | 动作意图的缓冲槽、过期、优先级、消费；宽限窗口 | 01 |
| 动作时间线 | L2 `core/rules/skill` 扩展 | 前摇/判定/后摇分相、时间标记、取消窗口、连招、速率重映射；与施法管线的对接 | 01、03 |
| 时间线结算模式 | L2 `core/rules/skill` + `core/rules/targeting` | 判定相逐 tick 空间命中、攻击实例去重、多段、命中确认事件 | 03 |
| 运动档案与运动仲裁器 | L1 `core/sim` 移动系统扩展 | 加减速、转向、急停；多来源位移仲裁；运动模式 | 02 |
| 局部动作时钟与顿帧 | L2 `core/rules/combat` | 每行动者的动作时钟；命中确认后冻结攻击方与受击方；群体合并与限幅 | 03 |
| 受击裁决 | L2 `core/rules/combat` | 硬直、击退、倒地由攻击的冲击等级与目标的韧性/霸体/死亡优先级裁决 | 03 |
| 姿势解析 | L5 表现层动画状态机扩展 | 状态 × 步态 × 姿态 × 武器族 × 变体的剪辑解析回落链 | 04 |
| 打击反馈包 | L5 `feedback_binder` 扩展 | 一条记录打包闪白、后仰、震屏、特效、音效层；按命中确认事件的几何与冲击等级播放 | 07 |
| 镜头档案 | L5 `camera` 扩展 | 前瞻、死区、分轴阻尼、战斗缩放、冲击合并限频 | 07 |
| 手感实验室 | 框架交付物：引擎无关内核 + 无头宿主 + 引擎宿主 | 输入脚本、录制、指纹、热调参、溯源、A/B、导出为测试 | 06 |

数据流：

```
输入设备 → InputMap 转译 → [输入缓冲] → tick 步骤 1 意图收集
   → 技能管线（[动作时间线] 推进；timeline 模式在判定相做 [空间命中]）
   → [运动仲裁器] 决定本 tick 位移 → 战斗结算（既有九步）→ 发布 combat.hit_confirmed
   → [局部顿帧] 冻结参与者动作时钟 → 事件派发
   → 表现层：[姿势解析] 选剪辑；[打击反馈包] 按命中几何播放；[镜头档案] 跟随与冲击
```

方括号内是本目录新增的件，其余全是既有机制。tick 八步顺序（03 第 4.2 节）不变：输入缓冲在步骤 1 内消费，动作时间线在步骤 3 内推进，运动仲裁在步骤 4 内裁决，顿帧在步骤 5 结算落地后施加，命中确认事件在步骤 7 派发。

## 4. 字段登记是支点

每个手感字段在数据登记表（04 第 3.2～3.6 节的机器可读登记机制）登记以下元数据，比既有字段多出四项（加粗）：

| 元数据 | 说明 |
|---|---|
| 名称、类型、范围、缺省 | 既有登记项 |
| 单位 | 既有登记项；手感字段的单位取值见第 6 节 |
| **半属** | `judging`（判定型）或 `presenting`（呈现型） |
| **分组** | 输入 / 移动 / 动作 / 受击 / 镜头 / 特效 / 音频（05 第 2 节） |
| **允许的覆盖操作** | `set` / `multiply` / `add` 的子集（布尔与引用只允许 `set`） |
| **合成来源** | 该字段在多层解析里的取值来源：角色为主 / 武器为主 / 攻击期间武器临时覆盖（05 第 3 节） |

一份登记表同时驱动四件事：数据校验（范围、单位、操作合法性）、解析器的合成逻辑、实验室调参面板的自动生成、测试用例的自动枚举（06 第 5 节）。新增一个手感字段只改登记表与消费方，工具与测试不动。

## 5. 时钟与确定性

三个时间基准，各司其职：

| 时钟 | 前进方式 | 用途 |
|---|---|---|
| 真实时钟 | `IClock.now()` | 输入事件的真实时间戳（只用于延迟测量与诊断）、调试界面、实验室录制 |
| 模拟时钟 | 固定步长 tick（03 第 3 节） | 玩法权威：冷却、光环、寻路、缓冲过期、位移积分 |
| 行动者动作时钟 | 每个行动者一个，随模拟 tick 前进，被局部顿帧暂停 | 动作时间线推进、取消窗口、连招窗口、无敌窗口 |

规则：

- 判定型手感全部以 tick 计。档案里的毫秒值在解析时按固定步长换算为 tick（四舍五入，非零值至少 1 tick），换算结果进入溯源。
- 输入缓冲的过期以行动者动作时钟计：顿帧期间缓冲不被吃掉；采样照常进行（缓冲槽仍接受新意图），但被冻结的行动者不消费。
- 冷却是否受顿帧影响是游戏级策略配置项（默认不受：冷却走模拟时钟），一款游戏内统一，不随适配器或单位改变。
- 全局 `setTimeScale` 慢动作仍是模拟时钟的整体缩放（03 第 3.1 节），由玩法层钩子请求，表现层不得触发；局部顿帧与它正交。
- 同一份输入脚本（03 第 4.2 节步骤 1 的 `Intent` 记录，加本目录新增的缓冲状态）在同一平台与运行时二进制下必须产生逐字节一致的事件流（沿用 10 第 8 节口径）。实验室的指纹测试（06）以此为逻辑侧门槛。
- 不做联网预测与纠正。联网项目由权威模拟确认命中后再接反馈纠正，不属于本目录范围。

## 6. 单位与标定

手感预设要跨游戏迁移，所以档案里的数值尽量用相对量，由每款游戏的标定表换算为绝对量：

| 量纲 | 档案里的单位 | 换算依据（标定表 `feel.calibration`） |
|---|---|---|
| 时间 | 毫秒（判定型解析为 tick） | 固定步长 |
| 位移 | 身高倍数（`body_heights`）或"基础移速下的秒数"（`base_speed_seconds`，不推荐，目前没有字段使用） | 参考身高（世界单位）、参考基础移速（世界单位/秒，只用于绝对值视图） |
| 速度 | 单位移动速度属性的倍数 | 无需换算：运动层直接用倍数乘单位的移动速度属性；标定表的参考基础移速只给绝对值视图（实验室与调参面板显示"世界单位/秒"），不参与移动 |
| 角速度 | 度/秒 | 无需换算 |
| 动作分相 | 毫秒，或剪辑长度的比例（0～1，二选一由 `timeline_source` 决定，01 第 3 节） | 剪辑元数据 |
| 镜头幅度 | 画面高度的比例 | 画布分辨率与当前缩放 |
| 世界距离型镜头参数（前瞻、死区） | 身高倍数 | 参考身高 |
| 音频 | 强度档（离散枚举） | 音效表（09 第 5.2 节）按档选资源 |

标定表每款游戏一行：参考身高、参考基础移速（只用于绝对值视图，不改变任何移动结果）、动画帧率、参考镜头高度/缩放、像素密度（沿用 ADR-0036 的像素与世界坐标换算）。解析器的最后一步应用标定；溯源同时保留相对值与绝对值。

顿帧不随动作速率缩放（急速缩短动作时长时，分相按比例重映射，顿帧保持独立的绝对 tick 数），见 01 第 3.5 节。

## 7. 时间模型与范围边界

- **离散模式**（ADR-0013）：判定型手感整体不生效——缓冲槽不消费（直接转为"下一动作"的既有法术队列语义）、动作时间线退化为既有"延迟 N 回合生效"、时间线结算模式解释为"在动作步以当时形状快照一次性判定"、运动仲裁只保留优先级裁决（无加减速）、顿帧不施加。呈现型在回放队列内照常生效。
- **空间约束**：缺省空间模型是 2.5D 平面世界（05 第 3 节），没有竖直运动轴，此时跳跃只是动画状态。竖直轴是可选的能力包（`space: side_2d | volume`，[ADR-0130](../adr/0130-竖直轴能力包.md)，06 第 1.2 节）：装配后有重力下的跳跃、击飞与落地，命中形状带高度窗口；地形（地面与天花板高度、斜坡与台阶、单向平台、多边形与高度场）、空中控制与二段跳、空中战斗都是该能力包的可选能力、缺省关闭；跳跃是一个输入类别（01 第 2.5 节）：跳跃缓冲就是输入缓冲，土狼时间（离开平台边缘后的起跳宽限）走宽限窗口——宽限窗口在本目录中泛化为"前置条件刚失效后的短暂宽限"（01 第 2.4 节），框架内置"在地面"条件，动作引用它即得土狼时间，可变跳高由动作的 `jump_cut_ratio` 声明；这些只在装配了竖直轴时生效，平面世界里跳跃仍只是动画状态。
- **投影**：固定俯角镜头（ADR-0012）。镜头幅度以画面比例计，正是为了不同缩放与画布下可迁移；不承诺跨自由视角引擎复用同一组数值。
- **外形**：`sprite` 与 `model` 两种外形类型（ADR-0012）共用姿势模型与手感档案，只在剪辑资源与标准资产形态上分岔（04 第 5 节）。
- **场景矩阵**：实验室按"2D / 2.5D / 3D 三种空间与呈现组合 × 目标选择式 / 动作式两种结算模式"六个格子验收（06 第 1.1 节）。三种组合都是平面世界上的不同镜头、外形与朝向模式；同一输入脚本在平面空间的各组合之间逻辑指纹必须逐字节一致，这是"呈现不改判定"的机器证据。体积空间（`volume`）与横版二维（`side_2d`）是竖直轴能力包，在无头宿主上可运行（高度维、重力、命中形状高度窗口、击飞，以及可选的地形、空中控制与空中战斗，06 第 1.2 节、第 4 节；第三人称下的相机相对移动是输入映射的原生可选能力，[ADR-0135](../adr/0135-相机相对控制空间与可选相机俯仰透视.md)；相机偏航的驱动仍由游戏自己负责），正式契约见 ADR-0130。
- **装备资产可替换**：装备的图标、纸娃娃层、槽位网格/挂点模型、武器表现档案、`feel.weapon`、音效层引用构成一个按契约命名的"装备资产包"（08）；游戏按契约补齐资产与填表，换装到姿势、手感、反馈、界面的整条链由框架接线。

## 9. 验收标准（本目录整体）

1. 判定型与呈现型的字段登记无交叉：任意判定型字段没有表现层读取点，任意呈现型字段没有规则层读取点（静态检查）。
2. 同一份输入脚本在无头宿主连跑两次，逻辑事件流逐字节一致；改任何呈现型字段不改变逻辑事件流。
3. 框架自带的每套预设（05 第 6 节）在假人姿势集上的指纹与入库基线一致，且预设成熟度标签与实验室记录对得上。
4. 新游戏只填标定表与选预设，不写任何手感机制代码，即可在实验室里用自己的角色跑通移动、连招、受击三条脚本。
5. 离散模式下开启手感体系的数据集与关闭时逐字节同结果。
