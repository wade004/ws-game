## 1. 输入到意图的链路

既有链路是：设备事件 → `InputMap` 转译为动作 → tick 步骤 1 整理为本 tick 的意图列表。本目录在"转译"与"整理"之间插入一个**输入缓冲**，并给动作定义补手感字段。移动轴不经缓冲（连续量每 tick 直接采样）；动作类输入（攻击、技能、闪避、交互、菜单）全部经缓冲。

```
InputMap.actionEvents  ──动作类──▶  InputBuffer(actorId)  ──步骤 1 消费──▶  Intent{kind: cast|interact|...}
InputMap.axis          ──移动轴──▶  直接采样为本 tick 移动意图（经 02 的运动档案处理）
AI 技能施放            ──────────▶  缺省直接进施法管线（动作锁、冷却、全局冷却照常生效）；开关打开后改经同一个 InputBuffer（第 2.3 节）
```

采样与 tick 的对齐：输入按帧轮询（02 第 1.5 节，不得丢事件），每个事件戳上真实时间戳与"到达时的下一个模拟 tick 序号"。一帧内多个 tick 时事件归入该帧的第一个 tick；一个 tick 内多帧时按到达顺序逐个入缓冲，按下与抬起落在同一 tick 内仍算一次完整点按。真实时间戳只用于延迟测量，不参与任何判定。

## 2. 输入手感层

### 2.1 动作定义字段（`found.input_action`）

下列字段都是可选的；全部不写时，动作的行为与没有手感体系时一致（不经输入缓冲，直接映射到既有的输入事件）。

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `class` | `move\|attack\|skill\|dodge\|interact\|item\|menu\|jump` | 无 | 动作类别：取消窗口、优先级、连招都按类别工作。**缺省表示该动作不经输入缓冲**（既有行为）；`move` 为轴类，不入缓冲；`jump` 见第 2.5 节 |
| `buffer_ms` | Number | 取档案输入组 `buffer_ms` | 缓冲窗口；0 表示不缓冲（只在按下当 tick 有效） |
| `priority` | Int | 按类别缺省（dodge 40 > jump 35 > attack = skill 30 > item 20 > interact 10 > menu 0） | 同 tick 多条待消费意图时的排序，也是替换规则的依据 |
| `hold_threshold_ms` | Optional<Number> | 无（`attack`/`skill` 类缺省取档案输入组 `hold_threshold_ms`） | 声明后区分点按与按住：抬起早于阈值为点按，晚于阈值为按住（蓄力类动作，第 2.6 节） |
| `repeat_policy` | `refresh\|ignore` | `refresh` | 同一动作在缓冲未过期时再次按下：刷新过期时刻，或忽略 |
| `face_on_accept` | Bool | 按类别缺省（attack/skill/dodge 为真） | 被接受时是否把行动者朝向对齐到按下瞬间的移动轴方向（无轴输入则保持当前朝向） |
| `grace_conditions` | List<Id> | 空 | 宽限窗口适用的条件名（第 2.4 节） |
| `skill_slot` | String | 无 | 缓冲接受后要施放的技能所在的技能绑定槽位名；缺省表示该动作不映射技能（缓冲出口对它不发施法意图）。`jump` 类不映射技能 |
| `hold_skill_slot` | String | 同 `skill_slot` | 按住释放时施放的技能所在的槽位名（点按/按住变体，第 2.6 节） |
| `jump_cut_ratio` | Number（0～1，不含端点） | 无 | 仅 `jump` 类：可变跳高，见第 2.5 节 |
| `control_space` | `world\|camera_relative` | `world` | 仅轴类：`world` 轴值原样当世界方向；`camera_relative` 按当前相机偏航换算成世界方向，要求宿主给输入映射配相机朝向查询（03 第 7 节） |
| `dead_zone` | Number（0～1，不含 1） | 无 | 仅轴类、仅模拟绑定（手柄摇杆与轴）：向量长度不超过它时输出零，超过部分重标度到 0～1（径向死区） |
| `response_curve` | `linear\|expo\|custom:<curve_id>` | `linear` | 仅轴类：对幅值的响应曲线（`expo` 为幅值平方；`custom` 走 04 第 3.6 节曲线形态登记的分段线性曲线，输入输出为 0～1 幅值） |
| `smoothing_ms` | Number | 无 | 仅轴类：幅值**下降沿**从满幅回落到 0 的毫秒数；上升与方向变化即时生效 |

**摇杆处理归设备与玩家设置**：`dead_zone`、`response_curve`、`smoothing_ms` 登记在动作定义上，是默认值；玩家设置可按动作覆盖（`InputMapHost.SetAxisProcessing`），覆盖值随设置文件持久化（设置键 `input_axis_settings`，只在有覆盖时才写出）。它们不进手感档案：轴处理是"这个设备、这个玩家的手感偏好"，不是"这套角色或武器的判定手感"，并且消费方是输入映射，读不到档案。三者都不写时输出与原始值逐位一致。斜向恒归一化；平滑只作用于下降沿，所以任何平滑都不会吞掉短于一个 tick 的输入：一次按下至少产生一个 tick 的满幅意图；键盘合成轴是数字输入，不经死区、曲线与平滑。

### 2.2 缓冲槽

每个受控行动者一个缓冲，槽位数由档案输入组 `buffer_slots` 决定（缺省 2）。每条记录：

```
struct BufferedIntent {
  actionId: Id
  class: ActionClass
  submittedTick: Int              // 模拟 tick
  expiresAtActionTime: Int        // 行动者动作时钟（顿帧期间不流逝，见 00 第 5 节）
  priority: Int
  directionSnapshot: Optional<Vec2>   // 按下瞬间的移动轴方向
  holdState: tap | hold_pending | hold_released{heldMs}   // 蓄力类动作的 heldMs 夹在蓄力上限
  consumed: Bool
}
```

入槽规则：

1. 同一动作已在槽内且未过期：按 `repeat_policy` 刷新或忽略，不占新槽。
2. 槽满：新意图优先级高于槽内最低者则替换之（被替换者发 `input.buffer_dropped{reason: replaced}`），否则丢弃（`reason: full`）。
3. `hold_threshold_ms` 声明的动作按下时以 `hold_pending` 入槽；抬起时按持续时长改写为 `tap` 或 `hold_released`；`hold_pending` 状态不可被消费，只有抬起后（或按住达到蓄力上限自动转为 `hold_released`，第 2.6 节）才可消费。

清空规则：行动者死亡、场景切换、切到离散模式、读档、被销毁，缓冲整体清空，每条发 `input.buffer_dropped{reason: cleared}`。

### 2.3 消费规则（tick 步骤 1）

对每个行动者，按以下顺序处理它的缓冲：

1. 丢弃过期记录（`reason: expired`）。
2. 行动者动作时钟处于顿帧暂停：本 tick 不消费（记录保留，过期不推进）。
3. 取优先级最高、`submittedTick` 最早的可消费记录，检查接受条件：
   - 行动者无进行中动作：接受。
   - 有进行中动作：只有当该动作对记录的 `class` 的取消窗口此刻打开（第 3.4 节），或该动作对应技能 `respects_gcd` 为假（反应类技能可插入），才接受。
   - 有进行中动作且处于连招窗口、记录为 `attack` 类：接受为连招接续（第 3.6 节）。
4. 接受即生成意图（`kind: cast`、携带 `directionSnapshot` 与 `holdState`），标记 `consumed`，进入既有施法管线；`jump` 类的接受是对竖直轴的起跳请求（第 2.5 节）。管线拒绝时按原因分流：
   - 时间可解原因（`ACTION_LOCKED`、`GCD_ACTIVE`、`ON_COOLDOWN` 且剩余冷却不超过记录剩余缓冲）：撤销 `consumed`，记录保留到过期，下一 tick 重试。
   - 其余原因（资源不足、条件不满足、无目标、死亡等）：记录丢弃，发 `input.buffer_dropped{reason: rejected, reasonCode}`。
5. 一个 tick 内每个行动者至多接受一条动作类意图；移动意图不受此限。

**AI 与自动战斗**：AI 的技能施放缺省**不经缓冲**，直接进施法管线（管线里的动作锁、冷却、全局冷却照常生效，没有绕开规则）；缓冲是玩家输入的手感层，AI 没有"按键"。装配选项 `AiIntentsThroughBuffer` 打开后，AI 在技能就绪判断之后改向缓冲提交一条合成动作（`input.action.ai_cast`）的意图，由同一套消费规则接受；此时只被动作锁或全局冷却挡住的条目也提交（缓冲会在窗口内等它可接受），冷却与充能不足的仍跳过，缓冲不接受时回落到直接施放。经缓冲会让 AI 的出手多一个 tick 的延迟，且 AI 的"提前量"受缓冲窗口约束，所以缺省关闭。自动攻击（普通攻击）不经缓冲。

每条记录从入槽到消费/丢弃的全部状态变化都可经 `IInputBufferQuery`（`snapshot(actorId): List<BufferedIntent>`）只读观察，供实验室时间轴与测试断言。

### 2.4 宽限窗口

平台游戏里的"土狼时间"在本架构泛化为：**某个前置条件刚刚失效后的短暂宽限**。框架提供机制，另内置三条施法瞄点条件与一条"在地面"条件（见下），游戏自己的条件由游戏声明：

- 游戏在 `found.grace_condition` 声明条件名与求值表达式（Expr，宿主为行动者上下文），例如"当前目标在射程内""脚下可行走""有锁定目标"。
- 规则层每 tick 记录每个条件最近一次为真的 tick。
- 动作定义的 `grace_conditions` 列出适用条件；施法管线相应步骤（如步骤 7 距离）在条件当前为假但 `now - lastTrueTick <= grace_ticks`（档案输入组 `grace_ms` 换算）时视为满足。
- 宽限只放宽"接受"判断，不改变随后结算的几何（例如目标已经离开范围，时间线模式的空间命中仍可能打空，这是正确结果）。
- 求值缺省由框架提供：`found.grace_condition` 的表达式在行动者上下文里求值（行动者为 `self`；`target` 为这次求值的目标：游戏的目标解析覆盖 -> 施法请求自己携带的单位目标 -> 自动攻击的当前目标），游戏只写数据；游戏有自己的求值方式时可覆盖。表达式还可读 `event.aim_*` 施法瞄点上下文（目标或落点、射程、距离、视线），框架据此内置三条条件行（`input.grace.builtin_aim_in_range` / `..._line_of_sight` / `..._reachable`），游戏直接在动作的 `grace_conditions` 里引用；不引用则不采样。第四条内置条件 `input.grace.builtin_grounded`（读 `event.grounded`，行动者此刻是否站在地面上；不引用瞄点，历史不按瞄点归属）是土狼时间的前提（第 2.5 节）。
- 与瞄点相关的条件（引用 `target` 或 `event.aim_*`）的历史归属瞄点：施法换了目标或落点，该条件历史从新瞄点重新记起，不拿旧目标"刚才够得着"放行新目标；与瞄点无关的条件历史不受影响。
- 适用范围：对单位施法、地面坐标施法与排队中的施法同一口径。地面坐标施法的条件应表达"落点/目标刚才还够得着"，条件当前仍为真时宽限不参与（射程外的落点仍按落点自己的几何被拒）。排队中的施法在进入队列那一刻记宽限快照，窗口按行动者动作时钟计（顿帧期间暂停），出队执行时快照仍在窗口内即视为满足，过期则按原规则拒绝。
- 非本地行动者（AI 单位等）从登记起就逐 tick 采样，第一次提交动作之前就有历史可查；只有当前数据里确有动作声明宽限条件时才登记（没有声明时不为每个单位建缓冲）。

### 2.5 跳跃

`jump` 是一个输入类别，缺省优先级 35，没有按住阈值。它的接受不是施法，而是对竖直轴能力包（03 第 2 节、ADR-0130）的起跳请求；没有装配竖直轴时该类动作不产生效果（平面世界里跳跃只是动画状态）。

- **跳跃缓冲**就是输入缓冲本身：起跳不成立（在空中，或不满足条件）时记录不丢，留在缓冲里到过期；落地后的第一个可消费 tick 起跳。窗口长度由动作的 `buffer_ms` 决定。
- **土狼时间**走宽限机制：动作的 `grace_conditions` 引用 `input.grace.builtin_grounded`。行动者在空中、且这次下落是**走出平台边缘的自然下落**（区别于起跳与被击飞），并且该条件的宽限窗口（档案输入组 `grace_ms`）未过时，按地面起跳处理：从当前高度以地面起跳速度起跳，**不占空中跳跃次数**；起跳后不再是边缘下落，所以不能连续宽限起跳。不引用该条件的动作没有土狼时间。
- **可变跳高**：动作写 `jump_cut_ratio`，起跳后松键（或起跳时按键已经松开）时若仍在上升，上升速度乘该比例（顶点高度按抛体公式相应降低，当前高度与空中跳跃次数不变）；已过顶点、在地面、比例不在 (0,1) 内都不裁切。
- 跳跃不在取消窗口的类别列表里：取消窗口只管"取消进入下一个动作"，起跳是竖直轴的运动，不打断当前动作。

### 2.6 按住的两个门槛与点按/按住变体

按住类动作有两条相互独立的门槛，名字相近、作用不同：

| 门槛 | 声明处 | 回答的问题 | 低于门槛 |
|---|---|---|---|
| 按住阈值 `hold_threshold_ms` | 动作定义 | 这是"点按"还是"按住" | 点按：走 `skill_slot` 的技能 |
| 蓄力下限 `charge.min_ms` | 被施放技能的时间线 `charge` 块 | 这次蓄力够不够 | 按 `charge.below_min`：`release`（缺省）按最低档释放（蓄力比例 0），`cancel` 取消该次输入 |

- **点按/按住变体**：同一个键按持续时长分成两个技能——点按（抬起早于按住阈值）施放 `skill_slot` 的技能，按住释放（`hold_released`）施放 `hold_skill_slot` 的技能；两者各自有自己的时间线与蓄力声明。`hold_skill_slot` 缺省等于 `skill_slot`，即既有的"一个技能、蓄力比例不同"。按住记录不会被"武器的攻击技能"覆盖，它施放的就是它声明的槽位。
- **蓄力上限**：按住达到 `charge.max_ms` 时，缓冲里的 `hold_pending` 记录自动转为 `hold_released`（蓄力比例 1）并可被消费，同时发 `input.charge_ready`；这一刻不要求抬起。蓄力时长按行动者动作时钟计（顿帧期间不流逝）。抬起时按住时长超过上限也夹在上限。
- **`below_min: cancel`**：按住时长超过按住阈值但不足 `min_ms` 就抬起，记录被丢弃，发 `input.buffer_dropped{reason: charge_below_min}`，不进入动作。

## 3. 动作时间线

### 3.1 适用范围与数据

主动技能在 `skill.def` 上声明可选的 `timeline` 块即进入时间线模式；未声明的技能保持既有行为（`cast_time` 内读条、结束时结算，[ADR-0031](../adr/0031-技能数值契约与预算.md)）。时间线块：

```
struct ActionTimeline {
  source: data | clip                  // 作者态权威来源（第 3.2 节）；运行期永远只读本块
  charge: Optional<{min_ms, max_ms, below_min: release|cancel, value_scale: Optional<{min, max}>, feel_scale: Optional<Map<field, {min, max}>>}>   // 蓄力（仅 hold 类动作，第 2.6 节）；below_min 缺省 release；value_scale 为蓄力比例 0/1 处的效果值倍率；feel_scale 按字段（attacker_hitstop_ms/target_hitstop_ms/knockback_distance/launch_height）给蓄力比例 0/1 处的手感倍率（03 第 2.6 节）
  startup_ms: Number                   // 前摇
  active_ms: Number                    // 判定相
  recovery_ms: Number                  // 后摇
  markers: List<{name: String, at_ms: Number, args: Map}>   // 时间标记（第 3.3 节）；hit/release 标记的 args 可带 segment 与 feel_ref（该段手感覆盖，03 第 2.6 节）
  cancel_windows: List<{class: ActionClass, open_ms: Number, close_ms: Optional<Number>,
                        requires: any|hit|whiff, into: Optional<List<Id>>}>   // requires 缺省 any；into 为目标技能白名单（第 3.4 节）
  combo: Optional<{next: Id, open_ms: Number, close_ms: Number, requires: any|hit|whiff}>
  active_until_release: Optional<{max_ms: Number}>   // 按住维持（第 3.8 节）
  hit_policy: marker | continuous      // 命中解析方式（03 第 2 节）
  hit_mode: auto | spatial | instant   // 命中结算路径，缺省 auto（03 第 2 节）
  sample_step_ms: Optional<Number>     // continuous 命中的采样步长，缺省为一个 tick 的 1/4（03 第 2.2 节）
  rehit_interval_ms: Optional<Number>  // 多段命中的最小再命中间隔（03 第 2 节）
  target_assist: Optional<{chain_ref, max_distance, max_angle_deg, mode}>   // 目标辅助（软锁定，02 第 5 节）
  cost_at: commit | active | first_hit // 资源扣除时刻，缺省 commit（动作开始）；active 为判定相开始时
  cooldown_at: commit | active | finish   // 冷却起算时刻，缺省 commit；active 为判定相开始时
  motion: Optional<ActionMotion>       // 动作位移（02 第 4 节）
  feel_ref: Optional<Id>               // 当前动作层的手感覆盖（05 第 3 节）；与技能行的 feel_ref 等价，同时声明且不同为错误
  hit_anchor: Optional<caster | ground_point>   // 仅对声明了 ground_target 的技能有意义：地面坐标施法请求施放时进入时间线，命中形状以施法者位姿或落点为锚点（03 第 2.2 节）；缺省不进入时间线
  is_attack: Optional<Bool>            // 显式声明动作是否带攻击（第 3.7 节 action.started.isAttack），缺省按技能内容推断
}
```

约束：`startup + active + recovery` 即动作时长，与 `cast_time` 的关系为：声明了 `timeline` 的技能 `cast_time` 由三相之和派生，数据里同时写了且不相等为校验错误。`cast_time` 的"动作时长"语义（节拍锁、技能预算的施放时间当量）不变。两处例外：地面坐标施法请求（`ground_target`）不进入时间线模式，仍按 `cast_time` 读条结算，`timeline` 在该路径上被忽略（校验给警告）；离散模式整体不走时间线（00 第 7 节），技能按 `cast_time` 折算的回合数结算。

### 3.2 权威来源

规则层不能读表现域（00 第 2 节），因此运行期**永远只读 `skill.def.timeline`**。`source` 决定作者态谁说了算：

- `data`：本块的数值是权威；剪辑（04）里的对应标记由校验器比对，偏差超过容差（标定表 `marker_tolerance_ms`）给警告。
- `clip`：剪辑的标记是权威；内容导入工具在数据构建阶段把剪辑标记时间抄写进本块（派生数据步骤，04 第 8 节"新增一个内容"流程增加此步），校验器要求两者一致，不一致为错误（说明忘了重新导入）。

无论哪种来源，同一个事件只由一处触发：判定与取消由规则层按本块触发；拖尾、脚步、特效挂点由表现层按剪辑标记触发。两边不互相替代，也不重复触发。

### 3.3 时间标记

| 标记名 | 归属 | 语义 |
|---|---|---|
| `hit` | 判定 | `hit_policy: marker` 时在此刻解析一次目标并结算（可多个，每个带 `segment` 序号） |
| `combo_open` / `combo_close` | 判定 | 由 `combo` 块派生，不单独写 |
| `cancel_open:<class>` / `cancel_close:<class>` | 判定 | 由 `cancel_windows` 派生 |
| `invuln_start` / `invuln_end` | 判定 | 无敌窗口：期间对该行动者的攻击在结算管线判定步骤前判为回避（03 第 4.3 节） |
| `armor_start` / `armor_end` | 判定 | 霸体窗口：期间受击裁决视目标为霸体，不进硬直、仍扣血（03 第 4 节）；与无敌窗口同样成对，动作结束或被取消时复位 |
| `motion_start` / `motion_end` | 判定 | 动作位移的起止（02 第 4 节） |
| `release` | 判定 | 投射物发射时刻（走既有投射物机制） |
| `cost` | 判定 | `cost_at: first_hit` 时的扣费点，由首个命中派生 |
| `sustain_start` / `sustain_end` | 判定 | 按住维持的起止（第 3.8 节）；`sustain_end` 带 `reason: release\|max`；由 `active_until_release` 块在运行期派生，不单独写 |
| `trail_start` / `trail_end`、`footstep`、`fx` | 表现 | 只存在于剪辑元数据，规则层不读 |

蓄力：蓄力相是动作开始之前的按住阶段，由输入缓冲里的 `hold_pending` 记录表示（第 2 节：`hold_pending` 不可被消费，表现层经输入缓冲的只读快照读到按住时长即可画蓄力）；动作在抬起或达到 `max_ms` 时才开始，因此蓄力期间没有动作实例、`action.phase_changed` 不发 `charge`。按住达到 `max_ms` 时缓冲记录自动转为 `hold_released` 并发 `input.charge_ready`（缓冲侧的事件，不是时间线标记，第 3.7 节）。蓄力比例 `(held − min) / (max − min)`（夹到 0～1）随 `action.started.chargeRatio` 给出；声明了 `charge.value_scale{min, max}` 时，伤害/治疗类效果值乘倍率 `min + (max − min) × 蓄力比例`（含 `release` 标记发射的投射物命中后效果），不声明不缩放，效果值契约不变。按住阈值与 `min_ms` 的分工、不足 `min_ms` 的两种处理见第 2.6 节。

### 3.4 取消窗口

- 每个取消窗口按目标类别独立声明：移动取消、闪避取消、下一段攻击、其他技能、物品。`close_ms` 缺省为动作结束。
- 窗口可带两个可选条件，缺省都等于无条件（既有行为）：`requires` 取 `any`（缺省）、`hit`（本动作实例已有命中确认才开，"命中取消"）、`whiff`（本动作实例尚无命中确认才开，"挥空取消"）；判定依据是 `combat.hit_confirmed` 按动作实例的配对，被回避的接触也算命中确认；动作结束之后才落地的投射物命中不计入。`into` 是目标技能白名单：只有输入动作映射到的技能在名单里才可取消进入；不在名单里的缓冲记录对这个窗口永远接不了，因此不会挡住缓冲里后面可接受的候选（与第 2.3 节"永远接不了"的剔除同一口径）。
- 一条缓冲记录在其类别的窗口打开时被接受，即触发**取消进入**：当前动作立即结束，依次：关闭已开启的命中集合（不再产生新命中）、停止动作位移、撤销尚未到达的标记、发 `action.cancelled{reason: cancel_into, next}` 与 `skill.cast_interrupted{reason: CANCELLED}`（满足 06 第 3.6 节施法终结事件保证），然后开始新动作。
- 已扣的资源不退（`refund_on_cancel` 为游戏级策略，缺省不退）；已起算的冷却不回滚。
- 移动输入不是打断：动作进行中收到移动轴只在 `move` 类取消窗口打开时生效，否则忽略并保留（移动轴不入缓冲，窗口一开当 tick 即生效）。`interrupt_flags: movement` 对时间线技能的解释就是"存在 `move` 类取消窗口且被使用"。
- 受击打断：由 03 第 4 节受击裁决决定（硬直打断动作），不是取消窗口的事。

### 3.5 速率重映射

急速缩短动作时长（策略见 ADR-0031，含下限）时：三相与全部判定标记按同一系数等比重映射；表现层动画播放速率取同一系数（04 第 6 节）；顿帧的 tick 数**不**缩放；缓冲窗口与取消窗口的绝对长度不缩放（窗口的起止点跟随重映射，长度以档案值为准，超出动作末尾则截到末尾）。跨帧的标记按区间遍历处理：一次推进 `dt` 内经过的全部标记按时间顺序依次触发，低帧率不漏。

### 3.6 连招

- `combo.next` 指向下一段技能（自己有独立的 `timeline`），`open/close` 为接续窗口；可选 `requires`（`any|hit|whiff`，口径同第 3.4 节）限定接续条件，典型用法是"打中才能接下一段"。接续的目标固定是 `next`，所以连招块没有 `into`。窗口内接受的 `attack` 类记录启动 `next` 而不是重新开始本技能，并携带 `comboIndex + 1`。
- 连招链在以下情况重置：任何非连招动作被接受、进入待机超过档案动作组 `combo_reset_ms`、受击硬直、死亡。
- 缺省只保留一条后续攻击在缓冲里（`attack` 类的 `repeat_policy: refresh` 天然保证）。闪避是否替换已缓冲的攻击由优先级决定（缺省 dodge 更高，替换）。

### 3.7 事件与查询

新增事件（登记进 06 第 8 节词汇表与 `found.event_catalog`）：

| 事件 | 字段 | 时机 |
|---|---|---|
| `action.started` | actorId, skillId, castInstanceId, comboIndex, durationTicks, chargeRatio, isAttack, startupRate, activeRate, recoveryRate | 时间线开始推进（与 `skill.cast_start` 同批发出）；`startupRate`/`activeRate`/`recoveryRate` 为三相的动画播放速率（作者毫秒 ÷ 重映射后实际毫秒；没有重映射为 1），表现层按它缩放各相位的剪辑播放（02 第 7 节）；`isAttack` 为动作是否带攻击（含伤害类/投射物效果，或声明了 `hit`/`release` 标记），反馈侧据此决定是否开挥空窗口 |
| `action.projectile_launched` | actorId, castInstanceId, segment | 时间线动作发射了一发投射物（03 第 2.5 节） |
| `action.projectile_ended` | actorId, castInstanceId, segment, reason(`Hit\|Blocked\|Expired\|Cleared`) | 该发投射物有了结局，与发射一一配对（03 第 2.5 节） |
| `action.phase_changed` | actorId, castInstanceId, phase(`startup\|active\|recovery`) | 相位切换 |
| `action.marker` | actorId, castInstanceId, name, args | 判定类标记到达 |
| `action.cancelled` | actorId, castInstanceId, reason(`cancel_into\|stagger\|death\|cleared`), nextSkillId | 动作未自然结束即终止 |
| `action.finished` | actorId, castInstanceId | 后摇自然结束（与 `skill.cast_success` 同批） |
| `input.buffer_dropped` | actorId, actionId, reason(`replaced\|full\|expired\|cleared\|rejected\|charge_below_min`), reasonCode | 记录未被执行即离开缓冲 |
| `input.charge_ready` | actorId, actionId, heldTicks | 按住达到蓄力上限，`hold_pending` 记录自动转为 `hold_released`（第 2.6 节） |

只读查询 `IActionStateQuery`：`current(unitId): Optional<{skillId, castInstanceId, phase, elapsedTicks, comboIndex}>`、`isCancelOpen(unitId, class)`、`isInvulnerable(unitId)`、`isActionClockPaused(unitId)`、`isSustained(unitId)`（第 3.8 节）。表现层与实验室只经它读状态。

### 3.8 按住维持

格挡、按住冲刺、持续引导这类"按住期间维持"的动作用 `active_until_release{max_ms}` 表达。本节只定输入与动作层契约；"格挡"的判定（受击裁决怎么看待维持中的动作）属于受击裁决（03 第 4 节），不在这里。

- 判定相走完（冻结点是判定相的最后一个 tick）时，若触发该动作的输入键仍按着，动作停在判定相末尾**维持**：动作内的已走时间冻结，发 `sustain_start`；直到松键或维持满 `max_ms`，发 `sustain_end{reason: release|max}`，然后正常推进进入后摇。维持时长按行动者动作时钟计（顿帧期间不流逝）。动作的结束时刻因此后移"`sustain_end` 与 `sustain_start` 之间的 tick 数"。
- 判定相走完时键已经松开：不维持，`active_ms` 就是最短判定时长。
- 只对由输入键触发的动作生效：施放请求不带触发键（例如 AI 的施放、没有输入动作的技能）时没有维持。
- 维持期间受击打断、取消窗口照常；维持期间不重复采样连续命中、不发新的命中标记。
- 与 `charge` 同时声明给警告（蓄力在动作开始之前，维持在动作判定相之后，两个按住阶段叠在同一个键上没有清晰语义）。

## 5. 测试与验收

全部在无头宿主用输入脚本驱动，期望值由档案换算：

1. 缓冲边界：窗口内最后一个 tick 提交的攻击在动作结束的下一 tick 被接受；窗口外第一个 tick 提交的被丢弃并发 `expired`。
2. 顿帧不吃缓冲：顿帧 N tick 期间提交的记录，在解冻后第一个可接受 tick 被接受。
3. 优先级替换：槽满时高优先级替换最低者，`buffer_dropped{replaced}` 恰好一次。
4. 取消窗口：`dodge` 类记录在窗口打开前一 tick 提交不生效、打开当 tick 生效；取消后本次攻击实例不再产生命中，`action.cancelled` 与 `skill.cast_interrupted` 各恰好一次。
5. 连招：窗口内攻击启动 `next` 且 `comboIndex` 递增；窗口外重新开始第一段。
6. 速率重映射：急速系数 k 下三相 tick 数等于 `round(ms × k / 步长)`，顿帧 tick 数不变；一次大 `dt` 推进跨过的多个标记按序全部触发。
7. 按住/点按：抬起早于阈值走点按变体，晚于阈值 `chargeRatio` 等于公式值。
8. 宽限：目标离开射程后 `grace_ms` 内提交的攻击被接受，之后被拒绝为 `OUT_OF_RANGE`。
9. 确定性：以上脚本连跑两次事件流逐字节一致。
10. 蓄力上限与下限：按住超过 `max_ms` 的那次，动作在按下后第 `ceil(max_ms / 步长)` 个 tick 开始、早于抬起、发 `input.charge_ready` 恰好一次；`below_min: cancel` 下不足 `min_ms` 的抬起丢弃记录且不开始动作。
11. 点按/按住变体：同一个键点按与按住分别启动两个槽位的技能。
12. 跳跃：落地前按下的起跳在落地当 tick 起跳（缓冲）；走出边缘后宽限窗口内起跳成立且不占空中跳跃次数、窗口外不成立；松键裁切上升速度恰为 `ratio × v`。
13. 条件取消：`requires: hit` 的窗口在命中确认前不开、确认后开，`whiff` 相反；`into` 白名单外的记录不取消且不挡住白名单内的候选。
14. 按住维持：键按住到 `max_ms` 时动作结束时刻后移 `max_ms` 对应的 tick 数、松键时后移按住的 tick 数；判定相走完时已松键则不后移。
15. 摇杆处理：未声明时输出与原始值逐位一致；死区内为零、死区外为 `(len − dz) / (1 − dz)`；平滑的下降沿每 tick 回落 `步长 / 平滑时间`；玩家覆盖往返设置文件一致。
16. AI 经缓冲（开关打开）：同一技能经缓冲施放比直接施放晚一个 tick，且受缓冲窗口约束。
