## 1. 换装链路（框架接线，游戏不写代码）

```
装备变化事件（既有）
  ├─ 表现：纸娃娃层 / 槽位网格 / 挂点模型 换装（display.equip_visual，ADR-0071/0072/0100）
  ├─ 表现：主手武器 → 武器表现档案（攻击/施法覆盖剪辑、特效变体，09 §4.4）
  ├─ 表现：武器族 → 姿势解析回落链（04 §2），待机/跑步/受击随武器变化
  ├─ 判定：主手武器 → feel.weapon（05 §2）→ 手感解析器失效重算 → 分相、取消窗口、顿帧、击退、impact_class
  ├─ 表现：feel.weapon 的音效层材质 / 拖尾引用 → 打击反馈包变体（07）
  └─ 界面：装备面板与纸娃娃预览视图模型刷新（09 §7，既有 UI 布局定义）
```

这条链每一段都已存在或由本目录其它文档定义；本文的贡献是把"一件装备需要提供哪些资产与数据行"收成一份契约，并给导入校验与实验室换装场景一个共同的检查清单。

## 2. 装备资产包（每件可装备物品一包）

| 组成 | 数据行 / 资源 | `sprite` 型 | `model` 型 | 必填 |
|---|---|---|---|---|
| 物品定义 | `item.template`（既有，含装备槽、`weapon_profile`） | — | — | 是 |
| 图标 | `item.template.icon_ref`（既有）；图标资源按 14 第 7 节规格（尺寸、透明边距、**不含品质框**） | 同 | 同 | 是 |
| 外观映射 | `display.equip_visual`（04 第 7.1.2 节） | `slot_mesh`：`slot_id` = 纸娃娃层名，`mesh_ref` = 层资源集引用 | `slot_mesh` 或 `socket_attach` | 是（有外观的装备） |
| 纸娃娃层资源集 | 按 ADR-0025/0038/0054 的路径推导：`<层资源集>/<方向档>/<姿势键>/…` | 每个方向档 × 必备姿势键至少一套；推荐键按 04 第 3 节；缺项按 ADR-0072 两级探测回落到静态图 | — | 是（`sprite`） |
| 槽位网格 / 挂点模型 | `mesh_ref` / `model_ref` 资源 | — | 网格按标准骨骼槽位命名（14 第 4.3 节） | 是（`model`） |
| 武器表现档案 | `display.weapon_style`（09 第 4.4 节）：攻击/施法覆盖剪辑、特效变体 | 同 | 同 | 武器必填 |
| 武器手感 | `feel.weapon`（05）：`family`、节奏、承诺、打击、`impact_class`、`auto_attack_timeline_ref` | 同 | 同 | 武器必填 |
| 音效层材质 | `feel.weapon.sfx_material`（`swing`/`impact` 层的材质标签，映射到 `sfx` 表行） | 同 | 同 | 武器必填（缺省材质 `generic`） |
| 拖尾 / 残影 | `feel.weapon.trail_ref`（可选，07） | 同 | 同 | 否 |
| 装备音效 | `item.template.equip_sfx_ref`（穿脱音效，可选） | 同 | 同 | 否 |

规则：

- 一件装备的全部资产用**同一个物品 id** 派生路径与表行键（既有前缀契约），不得靠命名巧合关联。
- 武器的 `display.weapon_style` 与 `feel.weapon` **同 id 分表**（05 第 2 节）：前者表现层读，后者规则层读；校验器检查二者互相存在。
- `family` 决定姿势维度与手感合成；没有对应武器族姿势键的姿势集按 04 回落链兜底，不报错，进完整性报告。
- 纸娃娃层的"每个方向档 × 姿势键"覆盖要求以**该游戏声明的方向档数与必备姿势键**为准（14 第 2 节游戏填写项 + 04 第 3 节），不是框架写死的数量。
- 槽位有无外观由 `item.slot_definition.has_appearance`（可选布尔，缺省 `true`）决定：缺省或 `true` 的装备槽位，物品必须有 `display.equip_visual` 行；显式 `false`（戒指、项链等不上身可见的槽位）不要求外观行，其余检查（图标、武器配对、音效与拖尾引用）照常。槽位声明无外观而物品仍写了外观行，外观行照常校验。
- 纸娃娃图层的像素与帧规则（静态层图必须有透明像素、逐层剪辑与同姿势同方向的身体剪辑逐帧对齐）见第 5.1 节契约清单，由导入校验按规则给具名诊断。

## 3. 界面皮肤包（每款游戏一包，可换）

皮肤包是资产目录 `assets/<数据集>/ui/skin/<名>/`，`ui_layout_definition.skin_ref = skin.<名>` 指向它（名里的点换下划线），缺省框架占位皮肤 `skin.default`。引擎侧界面实现**运行期读它**：游戏选定默认手感模板之后，界面上的换装全靠换资源文件，不写界面代码。包里有哪些文件、哪些必备、什么尺寸与比例、九宫格边框多少、有哪些状态变体、透明度怎么要求、主题有哪些令牌，全部在第 5.1 节的机器可读契约清单里，下表只列语义：

| 元素 | 文件（包内相对路径） | 要求 | 说明 |
|---|---|---|---|
| 槽位框 | `slot_frame/<槽位名>.png`（每个装备槽一张） | 必备 | 空槽底图，按槽位名命名；缺则回落占位同名、再回落占位 `_default` |
| 槽位框状态 | `slot_frame/_highlight.png`（悬停）、`_disabled.png`、`_drag_hover.png`；可选 `_pressed.png`、`_selected.png` | 前三张必备，后两张可选 | 槽位格随交互切换；按下/选中缺省用悬停图 |
| 品质框 | `quality_frame/<品质名>.png`（每个品质一张） | 必备 | 叠在图标之上，**中心区域必须透明**（图标本身不含框） |
| 拖拽态 | `drag/ghost.png`、`target_ok.png`、`target_blocked.png` | 必备 | 拖拽影子与可放置/不可放置两种目标反馈 |
| 提示框 | `tooltip/background.png`（九宫格）、`divider.png`、`row.png` | 必备 | 文本由本地化键提供 |
| 纸娃娃预览区 | `paperdoll_preview/background.png` | 必备 | 装备面板内的角色预览背景；预览尺寸取它的原生尺寸乘布局的 `preview_scale` |
| 面板底图 | `panel/background.png`（九宫格，边框取主题 `panel_border`，缺省 5） | 可选 | 全部面板的底板；缺省沿用框架面板底图 |
| 按钮 | `button/normal.png`、`hover.png`、`pressed.png`、`disabled.png`、`selected.png`（九宫格，边框取 `button_border`，缺省 4） | 可选 | 提供任一状态图必须同时提供 `normal`；其它状态缺省用 `normal`；整组缺省沿用框架纯色按钮 |
| 主题 | `theme.json`：`colors`（面板、边框、正文、次要文字、高亮、禁用、可放置、不可放置八个令牌）、`font`、可选的 `panel_border` / `tooltip_border` / `button_border` | 必备 | 配色与字体；缺某个颜色令牌回落框架默认色 |
| 面板布局 | `ui_layout_definition` 行 | 三个必需面板必备 | 见下 |

**面板与布局。** `ui_layout_definition.panel` 的枚举为 `hud`、`action_bar`、`inventory`、`quest_log`、`dialog`、`skill_book`、`character_stats`、`settings`、`save_slots`、`pause_menu`、`shop`、`equipment` 十二个；装备面板是独立的 `equipment` 面板（视图模型取装备槽位、已装备物品与纸娃娃图层，数量全部由数据与真实装备状态算出）。布局字段放在行的 `fields` 里：`anchor`（九个锚点名之一）、`columns`（槽位网格列数）、`cell_size`（格子边长，0 取槽位框原生尺寸）、`preview_scale`、`preview_body_set`（预览区身体层的精灵集）、`preview_direction`（初始方向档）；背包行同样读 `anchor` 与 `cell_size`。`equipment` 行可选，没有时取内置缺省布局；必需面板只有 `character_stats`、`inventory`、`action_bar`。

**运行期消费（缺省逐位不变）。** 背包面板每行有物品格：槽位框、图标、品质框与右下角数量，图标按物品模板解析、尺寸取自资源本身；装备面板有槽位网格（每格槽位框 + 图标 + 品质框，点击已装备的槽位卸下，悬停/按下/选中/禁用换状态图）和纸娃娃预览区（预览身体层与各装备层逐层叠放，可切换五个已制作方向档；图层数 = 已装备槽位里 `sprite` 型外观的件数）。`skin.default` **不安装任何覆盖**：面板底图、按钮、字体、配色保持框架原有默认，占位包里的主题只是占位配色的文档；非缺省皮肤才把主题颜色、`panel/background.png`、`button/*.png`、字体映射成界面皮肤覆盖。回落链：本包 → 占位皮肤同名 → 占位 `_default` → 程序生成的框，每一次回落都留记录，与导入校验的"缺项 + 回落目标"是同一批项；可选元素缺失不算回落，沿用框架默认外观。

**换皮肤要换哪些文件。** 游戏做完这一包，界面就整套换完：上表"必备"的全部文件 + 想换观感的可选文件 + 主题；图标放 `icons/<类别>/<名>.png`，纸娃娃层资源见第 2 节。其余一概不动。

## 4. 数据字段增补

| 表 | 字段 | 说明 |
|---|---|---|
| `feel.weapon` | `sfx_material: Id`、`trail_ref: Optional<Id>` | 音效材质标签与拖尾引用 |
| `item.template` | `equip_sfx_ref: Optional<Id>` | 穿脱音效 |
| `display.equip_visual` | `preview_direction: Optional<Id>` | 预览区使用的方向档（缺省取姿势集的正面档） |
| `ui_layout_definition` | `skin_ref: Optional<Id>` | 指向皮肤包，缺省占位 |

均为可选加法字段，不提升 schema 版本（ADR-0039 加法政策）。

## 5. 导入校验与完整性报告

导入工具对每件可装备物品检查，输出装备完整性报告（与 06 第 3.6 节换装场景的运行期检查一一对应）：

| 检查 | 级别 |
|---|---|
| 图标：资源缺失、`display_ref` 解析不出图标 | 错误 |
| 图标：尺寸/比例不合规（须正方形、边长为 2 的幂且在清单范围内）、全透明或主体贴边（图标不含品质框） | 错误 |
| 有外观的装备缺 `display.equip_visual`（槽位 `has_appearance` 为 `false` 的除外） | 错误 |
| 外观模式取值不认识；`preview_direction` 不是该游戏声明的方向档；姿势集缺失 | 错误 |
| `sprite` 型：任一方向档的静态层图缺失 | 错误 |
| `sprite` 型：静态层图读不出、全透明或没有任何透明像素（实心满铺会盖住身体） | 错误 |
| `sprite` 型：必备姿势键 × 全部方向档的逐层剪辑缺失 | 错误（必备键）/ 警告（推荐键，记录回落到静态层图） |
| `sprite` 型：逐层剪辑与同姿势同方向的身体剪辑帧数不同、帧宽高不同、帧矩形超出图集 | 错误 |
| 武器的攻击/施法覆盖剪辑没有该装备的逐层剪辑 | 警告（回落整身剪辑） |
| `model` 型：网格槽位名不在标准骨骼槽位表 / 挂点不存在 | 错误 |
| 武器缺 `display.weapon_style` 或 `feel.weapon` 之一，或二者 id 不同 | 错误 |
| `feel.weapon.family` 在姿势集里没有任何对应键 | 警告（全部回落到基础键） |
| `sfx_material` 在 `sfx` 表无对应行；穿脱音效/拖尾引用无对应行 | 警告（回落 `generic` / 不播放） |
| 皮肤包：目录不存在、必备文件缺失、必备状态变体缺失、主题缺颜色令牌或颜色格式不对、必备面板布局行缺失 | 警告（回落占位，写明回落目标） |
| 皮肤包：图片读不出、尺寸/比例不合规、同尺寸组内边长不一致、九宫格边框过大没有可拉伸的中心、全透明或缺要求的透明像素 | 错误（文件会被原样使用，不会回落） |
| 框架占位皮肤自身缺必备文件或有以上内容缺陷 | 错误（没有可回落的下一级） |
| `skin_ref` 不是 `skin.<名>` 形式 | 错误 |

每一条都有一个具名诊断（稳定的检查名，`--json` 消费方按名过滤），每个诊断有一个反例用例守住。报告只留本地。缺错误级项的装备资产包不能进入 `validated` 数据集；皮肤包问题不阻断物品，但内容缺陷让导入命令失败。

### 5.1 界面资源契约清单

皮肤包、图标、纸娃娃图层的全部规则收在**一份机器可读的清单**（`toolchain/asset_import/skin_manifest.json`），出图工具、导入校验、占位皮肤生成器、引擎侧完整性用例读的是同一份，不各抄一份。清单包含：

- 皮肤元素模板：路径模板（`{slot}` / `{quality}` 由数据展开）、必备 / 可选 / 仅占位皮肤必备、尺寸与比例规则（范围、正方形、同尺寸组）、透明度规则（非全透明 / 须有透明像素 / 须有透明中心）、九宫格边框令牌与缺省、状态变体（常态、悬停、按下、禁用、选中、拖拽悬停）及其依赖与回落状态；
- 主题令牌：必备颜色键、字体、可选数值令牌（边框像素）；
- 图标类别（物品必备，其余可选）与图标规格；
- 纸娃娃：静态层图、逐层剪辑（带方向与不带方向两级）、身体剪辑路径模板，方向档与姿势键的来源，帧对齐规则；
- 导入校验会给出的具名诊断全集。

人读的逐文件清单由同一份清单生成（`import_assets.py skin-checklist`，按数据展开槽位与品质，给出每个文件的路径、要求、尺寸、九宫格、状态、透明度与用途），交给出图与美术；元素数由数据算出（模板条数与展开后的文件数两个口径），不写死。

## 6. 与手感的关系

- 手感设计完成后，一款游戏"让某把武器有自己的手感"的全部工作是：填一行 `feel.weapon`（或引用框架武器原型再覆盖差异）、一行 `display.weapon_style`、按契约补剪辑与层资源。分相、取消、顿帧、击退、反馈包、姿势切换随之生效。
- 装备属性（伤害、攻速）仍走既有物品与属性系统；`feel.weapon` 不写数值属性。
- 实验室换装场景（06 第 3.6 节）与 `equip_cycle` 脚本是这份契约的验收场；占位装备集是参照实现。

## 7. 测试与验收

1. 逐件穿戴：对数据根内每件可装备物品，穿戴后视图模型槽位、纸娃娃层/槽位网格、武器表现档案、`feel.weapon` 解析结果与静态报告一致（运行期检查与导入检查零差异）。装备面板的数量（已装备槽位数、纸娃娃图层数、非 2D 外观数、无外观数）由数据与真实装备状态算出，每一步满足"图层 + 非 2D 外观 + 无外观 = 已装备槽位数"。
2. 武器族切换：换主手武器后 `IActionStateQuery` 无动作时，下一次 `idle`/`move` 解析出的姿势键随 `family` 变化；手感解析器版本号递增且 `impact_class`、分相倍率来自新武器（溯源第 4 层）。
3. 回落：删除一件装备的某方向档层资源，运行期按两级探测回落到静态图且报告记录一致；删除必备键层资源导入报错。
4. 皮肤包：移除任一必备皮肤资源，面板仍可打开并使用占位，运行期回落记录与导入报告一致；移除可选资源沿用框架默认外观。
5. 皮肤替换完整性：遍历清单的**每一个**展开元素，换到另一套皮肤包后每个元素都解析到新包的文件（逐元素读回像素核对，没有默认皮肤残留），且面板实际使用的取用路径与清单路径逐元素一致；真实面板（槽位框、品质框、状态精灵、预览区背景、面板底图、按钮）换皮肤后只引用新资源；九宫格元素在多种尺寸下精灵的边框数据等于主题令牌、像素密度不缩放（四角不变形）；槽位格与按钮的悬停/按下/选中/禁用随交互切换状态图；可选元素缺失走框架默认；缺省皮肤不安装任何覆盖。
6. 换装场景（06 第 3.6 节，引擎宿主）：屏幕上有装备面板、预览区与"方向 × 姿势键"轮播，"逐件穿戴"按数据清单逐件穿上、穿完卸空再来一遍，穿脱走真实背包与装备载体；"跑完整报告"在引擎宿主上跑同一份数据生成的衣橱脚本，核对每件装备的图标与每个方向档的静态层图、每个方向档 × 姿势键的层剪辑与身体剪辑（帧数与尺寸），写出本地报告与本地拼图（只留本地，与导入校验的静态检查一一对应）。衣橱的件数、步数、图层数、轮播格数（装备 × 方向档 ×（静态层 + 姿势键数））全部由数据算出。
