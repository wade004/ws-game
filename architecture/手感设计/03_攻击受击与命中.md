## 1. 两种结算模式并存

| | `instant`（目标选择式，既有） | `timeline`（时间线式，新增） |
|---|---|---|
| 适用 | 法术、增益、治疗、召唤、锁定目标的追踪类 | 近战、投射物、闪避、突进、蓄力 |
| 目标 | 施法管线步骤 6 一次解析 | `hit_policy: marker` 在每个 `hit` 标记解析一次；`continuous` 在判定相逐 tick 解析 |
| 时机 | `cast_time` 结束一次结算 | 判定相内逐次结算，动作收尾不再结算 |
| 挥空 | 不存在（无目标即拒绝） | 存在：没有目标也开始动作，判定相打空就是打空 |
| 走位 | 与命中无关 | 站位与朝向直接决定命中 |
| 打断 | 读条打断 | 受击硬直打断、取消窗口取消 |
| 数据 | 既有字段 | 既有字段 + `timeline` 块（01 第 3.1 节） |

两种模式共用：施法管线步骤 1～5（存活/条件/学派锁/冷却/节拍锁/资源）、结算管线九步、事件词汇表、光环与 Proc、技能预算。技能声明了 `timeline` 块即为时间线模式，`resolution` 是派生的只读属性，不单独填。普通攻击（ADR-0059）可按武器声明 `timeline`（`feel.weapon` 的 `auto_attack_timeline_ref`），未声明时保持既有挥击计时。

现代单机动作游戏内部也是两种并存：近战与投射物走空间判定，追踪法术、增益、治疗走目标选择。本架构的规则层是魔兽血统，光环、属性、效果原语不动，只把近战与投射物的"命中判定"这一环换成空间判定。

## 2. 时间线模式的施法与命中

### 2.1 施法管线的解释

| 步骤 | `timeline` 模式下的解释 |
|---|---|
| 1～5 | 不变 |
| 6 目标合法性 | **不拒绝**：`hit_policy` 决定何时解析目标；本步只对声明了 `target_assist` 的动作做辅助目标解析（02 第 5 节），没有目标不是失败 |
| 7 距离与视线 | 不适用（`range` 只用于 AI 与目标辅助的候选筛选，不作为拒绝条件） |
| 8 读条/引导 | 改为**动作时间线推进**：按行动者动作时钟推进 `charge → startup → active → recovery`，触发标记；判定相内按 2.2 节命中 |
| 9 结算触发 | 拆为两处：每次命中各自结算（2.3 节）；动作自然结束时收尾（`action.finished` + `skill.cast_success`，不再结算） |

资源在 `cost_at` 时刻扣除（缺省动作开始），冷却在 `cooldown_at` 时刻起算（缺省动作开始）。法术队列语义由输入缓冲取代（01）；时间线技能不使用既有法术队列。

### 2.2 命中解析

- **命中路径**（`timeline.hit_mode`）：缺省 `auto`——目标选择链声明了 `shape` 走本节的空间命中，没声明保持 `instant` 结算（链的既有目标选择，不看位姿）；`spatial` 强制空间命中（链必须有 `shape`）；`instant` 强制 `instant` 结算（不能与 `continuous` 同用）。
- **锚点**：命中形状的锚点是**攻击方当时的位置与朝向**。声明了 `ground_target` 的技能经地面坐标施法请求（06 第 3.6 节）施放时，缺省不进入时间线（读条结算，`timeline` 被忽略，加载期给警告）；`timeline.hit_anchor` 声明后进入时间线并改变锚点：`caster` = 仍以攻击方当时的位姿为锚点；`ground_point` = 以请求里的落点为锚点，朝向取施放时刻"攻击方指向落点"的方向（两点重合取攻击方朝向），落点与朝向在整个动作期间固定不动。射程门（`range`）、视线与可行走校验仍在施放请求时按落点做一次，动作期间不再校验。`skill.cast_success` 携带落点（既有字段 `groundPoint`）。该字段只对声明了 `ground_target` 的技能有意义；没声明 `ground_target` 却写了 `hit_anchor` 给警告并忽略。
- `hit_policy: marker`：每个 `hit` 标记到达时，用 `target_shape_ref` 的目标选择链以上述锚点解析一次（06 第 5 节 `resolve`），得到本段命中集合。
- `hit_policy: continuous`：判定相内每 tick 用同一条链解析一次；链的 `shape` 随锚点移动。高速形状可能在两个 tick 之间跳过目标，处理方式**一律是子采样**：按 `timeline.sample_step_ms`（缺省一个 tick 的 1/4）在两 tick 位姿之间线性插值多次采样，并按形状最窄尺寸加密（相邻采样间位移不超过它的一半，单个区间上限 256 个采样）；判定相落在两 tick 之间的部分同样处理，低帧率不漏。**不设 `supportsSweep` 扫掠接口**：采样密度已保证不漏，上限只在单 tick 位移超过形状尺寸 128 倍（已是瞬移）时才咬合，为这种极端情形让所有适配层实现一个解析扫掠查询得不偿失。
- **目标是圆，不是点**：目标的**受击半径** = `unit_body_radius`（05 第 3 节受击组，身高倍数，经标定成世界单位）× `hurt_radius_scale`（可选字段，缺省 1，范围 0～4）。命中形状与该圆**相交**即命中（形状到目标中心的最短距离不超过受击半径；半径为 0 时退化为"中心在形状内"）。没有声明 `unit_body_radius` 的单位受击半径恒为 0，仍按点判定。装配层把半径来源接给目标选择宿主的 `TargetingOptions.TargetRadius`，广相位上界由 `MaxTargetRadiusProvider` 每次查询重新读取（半径来自档案、可被换装与光环改变，静态上界不够用）；该装配**默认关闭**（`CarriersFeelOptions.HitRadiusFromFeel = false`）——打开会改变既有命中结果（擦边的目标从没打中变成打中），由游戏在装配根显式打开，缺省与此前逐位一致。投射物的碰撞由空间查询登记的碰撞半径决定，不读 `hurt_radius_scale`（本节只管近战形状命中；需要二者一致时由游戏把碰撞半径与受击半径配成同一个值）。
- **攻击实例去重**：每次动作激活分配一个攻击实例 id（沿用 06 第 3.6 节"攻击实例 id"语义，一次激活一个；`comboIndex` 不同的连招段各自一个）。同一攻击实例对同一目标缺省只命中一次；多段技能在标记或时间线上显式声明 `segment` 序号与 `rehit_interval_ms`，同一目标在不同段、且距上次命中不少于该间隔时可再次命中。命中集合随攻击实例存在，动作结束、取消、硬直时清空。
- 过滤：目标选择链的既有过滤（阵营、存活、免疫）照常。**处于无敌窗口的目标不被排除**：它们留在命中集合里（同样记入去重账本），由 2.3 节的第 0 步判为 `Invulnerable` 回避——"没被打到"与"被打到但无敌"是两件事，后者要发回避事件与确认事件供反馈侧表现。
- `max_targets` 与超出策略（06 第 3.7 节）按每次解析生效。

### 2.3 每次命中的结算

每个新命中的目标构造一份 `EffectContext`（携带攻击实例 id、`segment`、技能 id、接触几何）执行既有 `effects` 列表，走结算管线九步。九步之前是**第 0 步**，所有命中路径共享（时间线标记与判定相、时间线投射物、目标选择式、范围效果、非时间线投射物——凡是进入结算管线做伤害类结算的都经过它）：

```
第 0 步 无敌窗口（目标 IActionStateQuery.isInvulnerable 为真）→ 直接判为回避，hitResult = Invulnerable，
   发布 combat.attack_avoided（ADR-0098 的既有出口，hitResult 取值扩一项），不进入命中表、不落地、不进战。
```

- **只拦伤害类结算**：治疗类不经第 0 步（无敌不拦治疗，同既有口径）；周期性结算（光环跳伤）、光环来源的结算、目标就是来源自己（自伤）也不拦。不经命中表的效果（光环施加、位移、召唤等）不属于"一次命中的结算"，不受第 0 步约束，沿用各自既有的免疫判定；时间线路径在构造批次时另有一道前置过滤（见下），所以时间线命中的整批效果对无敌目标都不执行，这一点与此前一致。
- **豁免**：技能行可声明 `ignores_invulnerability: true`（环境伤害、斩杀、必中机制等），第 0 步与时间线路径的前置过滤都不拦它；缺省 false。
- **时间线路径的前置过滤保留**：时间线批次在执行效果之前就把无敌目标从批次里摘掉并为它们发 `combat.attack_avoided` 与 `combat.hit_confirmed`（`hitResult = Invulnerable`，几何字段照常），这是为了让"整批对该目标都不执行"并让确认事件与同批其它目标同一时刻到达；第 0 步对这条路径是第二道门（命中表之前再拦一次，对已被摘掉的目标不会再到达），其它路径只有第 0 步一道。
- 目标选择式（instant）路径被第 0 步拦下时，受击裁决的 instant 适配层据 `combat.attack_avoided` 合成 `combat.hit_confirmed`（结局 `Invulnerable`，无顿帧无反应），与其它回避结局同口径。
- 对既有结果的影响：只有时间线动作的 `invuln_start`～`invuln_end` 才会让目标进入无敌窗口，没有这类动作的数据里第 0 步恒为假，结算逐位不变（实验室全部既有脚本基线在接入后逐字不变，见实验室 README 判断记录 61）。

命中表（06 第 4.2 节）各项在时间线模式下仍可启用：站位打到了不等于一定命中，`miss/dodge/parry` 由属性决定，这是"数值层"与"空间层"的分工。游戏可以按口味关掉它们只留空间判定。

### 2.4 命中确认事件

结算落地后（九步的"后置"步骤内）发布新事件，两种模式统一发出，使反馈绑定不必区分模式：

| 事件 | 字段 | 说明 |
|---|---|---|
| `combat.hit_confirmed` | attackInstanceId, segment, sourceId, targetId, skillId, hitResult, amount, amountRatio, isCrit, isKill, contactPoint, contactNormal, worldDirection, impactClass, attackerHitStopTicks, targetHitStopTicks, reaction, castInstanceId | 一次命中的完整结论；紧随同一批次的 `combat.damage_dealt`/`combat.attack_avoided` 之后 |

- `contactPoint`：目标有受击半径（2.2 节）时，取**目标受击圆面上朝向命中形状的点**——形状上离目标中心最近的点所在的方向，目标中心已在形状内时取朝向攻击方的点；因此接触点不再落在目标体内，`contactNormal` 就是从目标中心指向该点的单位向量（指向攻击方一侧）。目标没有受击半径时（缺省）保持此前口径：`continuous` 取形状上离目标中心最近的点；`marker`/`instant` 模式取目标登记位置；投射物取碰撞点。`worldDirection` 为攻击方到目标的单位向量（击退方向）。无接触几何时三者由适配层给出明确替代（目标中心与攻击方朝向），不为空。
- `impactClass`：来自解析后手感表的受击组（缺省武器层 `impact_class`：`light|medium|heavy|massive`，可扩），是反馈包与受击裁决的公共输入。
- `castInstanceId`：发起本次命中的动作实例 id（与 `action.started`/`action.marker`/`action.phase_changed` 的 `castInstanceId` 是同一个值；时间线命中——包括投射物命中——填入，目标选择式 instant 命中没有动作实例为空）。反馈侧的挥空窗口按它与动作配对。`attackInstanceId` 仍是一批效果结算的攻击实例 id，二者不是同一个概念。
- `amountRatio`：`amount / 目标最大生命`，供反馈强度缩放。
- `reaction`：受击裁决结果（第 4 节）。
- 回避类结局也发本事件（`amount = 0`，`reaction = none`），使"打空/被闪避"有独立的表现（挥空音效、格挡火花），但**命中失败不播放成功命中的完整反馈**由反馈包按 `hitResult` 分流（07）。

### 2.5 投射物

投射物（既有机制，ADR-0028）在 `release` 标记发射；到达/碰撞时的结算复用 2.3 节，`contactPoint` 取碰撞点，攻击实例 id 沿用发射它的动作（多发投射物各自 `segment`）。飞行期间攻击方已进入后摇或被打断不影响已发射的投射物。

投射物的生命周期对外有两条事件（均带发射它的动作实例 id 与段序号）：`action.projectile_launched`（生成时）、`action.projectile_ended`（结局确定时，每发恰好一条，与发射一一配对）。结局原因 `reason` 取：`Hit`（命中后销毁或穿透次数耗尽；穿透中的命中不算结局）、`Blocked`（被地形挡住）、`Expired`（射程耗尽或到期）、`Cleared`（被清场、离开地图）。命中确认（`combat.hit_confirmed`）总是先于该发投射物的结局事件到达。反馈侧凭这两条事件判定投射物动作"是否打空"（07 第 6 节）。

### 2.6 命中的手感来源（技能、分段、蓄力）

一次命中交给受击裁决（第 4 节）的"攻击方手感"由下面三类可选声明决定；**都不声明时与此前逐位一致**（时间线动作取动作开始快照，instant 命中取攻击方当前的解析结果）。它们落在 05 第 3.2 节的同一个位置——第 6 层"当前动作"，所以"技能 > 武器 > 角色"的优先级不是新增规则，而是第 6 层高于第 4 层（武器）与第 5 层（角色），按字段逐个覆盖：技能声明的字段盖过武器与角色，没声明的字段仍按武器/角色。

| 声明 | 位置 | 语义 |
|---|---|---|
| 技能行手感引用 | `skill.def.feel_ref`（`feel.action` 行 id） | **时间线技能**：与 `timeline.feel_ref` 等价，进入动作开始快照的第 6 层（同时声明且不同是加载期错误 `skill_feel_ref_conflict`）。**非时间线技能**（法术、增益、治疗等 `instant` 技能）：命中时受击裁决以该行为动作层重算攻击方视图，法术的 `impact_class` 因此不再只能取武器（本文原第 5 节的缺口）；该视图按命中时刻的单位状态解析，不是快照 |
| 分段手感覆盖 | `timeline.markers[].args.feel_ref`（只在 `hit`/`release` 标记上读取；`release` 默认段 0） | 该段命中的攻击方视图 = 动作层（技能行或 `timeline.feel_ref`）之上再叠这一行（同在第 6 层，行内与行间都是 `set`→`multiply`→`add`，同一操作按"动作层先、分段行后"的列表顺序，后者胜），于**命中那一刻**重算，不是动作开始快照；该段命中落地时的击退距离、击飞高度、击飞叠加也读这份视图（受击裁决宿主按攻击实例 + 目标暂存它，同一 tick 内取走）。多段技能因此能让最后一击更重而不必拆成两个技能。非 `hit`/`release` 标记写了它给警告并忽略 |
| 蓄力手感缩放 | `timeline.charge.feel_scale`：四个可选字段 `attacker_hitstop_ms`、`target_hitstop_ms`、`knockback_distance`、`launch_height`，各为 `{min, max}`（蓄力比例 0/1 处的倍率，之间线性插值，≥ 0） | 乘在对应判定型字段**解析后**的取值上（顿帧仍受 `*_hitstop_cap_ms` 限幅；击退/击飞在落地阶段乘）；没列出的字段倍率为 1；缺省不缩放。蓄力比例与 `charge.value_scale` 是同一个值（01 第 3.3 节） |

- 调试覆盖（05 第 3.2 节第 8 层）高于第 6 层：实验室里对某字段写了全局调试覆盖，技能行与分段行对该字段的写入同样会被盖住（符合"调试覆盖最高"的既有规则，调参时留意）。
- 技能行 `feel_ref` 对 `instant` 命中经受击裁决宿主的 `HitFeelOptions.SkillFeelRef` 取得，生产装配根默认接上技能模块的读口；解析来源若不支持"指定动作层"（`IFeelJudgingSource.ResolveJudgingWithAction` 的缺省实现退回单位视图），声明被静默忽略——框架内的全部生产来源都已实现它。
- `hit_confirmed` 的 `impactClass` 随这份攻击方视图变化，所以反馈包（07）按 `impactClass` 分流时，分段重击与蓄力满的那一击自然落到更重的档。

### 2.7 击飞与空战字段索引

击飞、空中受击与落地由竖直轴能力包（[ADR-0130](../adr/0130-竖直轴能力包.md)）引入的一组可选字段承载，缺省全部"无值"即不启用；平面世界忽略。字段语义的权威来源是字段登记表（05 第 4 节）与运动层说明（02），此处只列索引，使本文第 4 节的 `knockback`/`knockdown` 条目能查到它们：

| 字段 | 半属/侧 | 作用 |
|---|---|---|
| `launch_height` | 判定，攻击方 | 击飞顶点高度（身高倍数），第 4 节 `knockback`/`knockdown` 反应据此把目标抛起 |
| `launch_stack` / `launch_stack_cap` | 判定，攻击方 | 已腾空的目标再次被击飞：`restart`（缺省）重新抛起，`add` 把本次初速叠加到当前竖直速度；`launch_stack_cap` 封叠加后的初速（折成顶点高度） |

## 3. 局部顿帧（行动者动作时钟）

### 3.1 定义

顿帧（hit stop）是命中瞬间攻击方与受击方短暂冻结的效果，本架构把它做成**判定型**：冻结的是参与者的**行动者动作时钟**（00 第 5 节），不是模拟时钟，不是表现帧。

- 冻结期间：该行动者的动作时间线不推进、取消/连招/无敌窗口不流逝、缓冲过期不推进、运动仲裁给 `frozen` 叠加态（位移为零，02 第 3.1 节）、`velocity` 保留；模拟时钟照常，其它单位照常，冷却按游戏级策略（缺省照常），光环照常。
- 表现层收到 `feel.hitstop_started{unitIds, ticks}` / `feel.hitstop_ended{unitIds}`，冻结对应实体的动画与程序动画时间轴；哪些层冻结（粒子、拖尾是否随冻）由打击反馈包声明（07）；界面、调参面板、其它实体不冻。
- 既有 `Freeze(durationMs)` 反馈动作（09 第 6.1 节）保留为纯呈现型的全局演出（过场、终结演出），与本节机制正交；缺省打击反馈包不再使用它。

### 3.2 时长与施加

- 攻击方时长 `attacker_hitstop_ms`、受击方时长 `target_hitstop_ms` 来自解析后手感表（受击组，武器为主、体型倍率），按 `impactClass` 与 `hitResult` 分档；回避类结局缺省不顿帧；击杀可用 `kill_hitstop_scale` 放大。
- 施加时机：tick 步骤 5 战斗结算落地之后、步骤 7 派发之前，与 `combat.hit_confirmed` 同批。
- **群体命中合并**：同一 tick 同一攻击方的一批命中，攻击方顿帧取批次最大值并按 `attacker_hitstop_cap_ms` 限幅，不逐个累加；每个受击方各自独立。
- **嵌套**：冻结中再被命中/再命中，新时长与剩余时长取大，不相加；`hitstop_cap_ms` 同样限幅。
- **释放保证**：死亡、销毁、场景卸载、离散模式切换时无条件解除并清零；测试断言"顿帧结束后所有冻结句柄为零"。
- 不随动作速率缩放（01 第 3.5 节）。

## 4. 受击裁决

一次命中对目标的反应由固定顺序裁决，输出 `reaction` 写入 `combat.hit_confirmed`：

```
死亡优先：目标本次落地后生命为零 → reaction = death（既有死亡流程）
免疫/回避：hitResult 为回避类 → reaction = none
霸体：目标处于 super_armor（时间线标记 armor_start/armor_end 或光环标志） → reaction = none（仍扣血、仍顿帧受击方，视 super_armor_hitstop 策略）
韧性：攻击的 stagger_power(impactClass) ≤ 目标 poise（属性，可选；未声明视为 0） → reaction = flinch（只播受击动画不打断）
      动态韧性（攻击声明了 poise_damage 且目标有韧性属性时，替换上一行）：目标有韧性池（容量 = poise 属性，已损失量由裁决方记录），
      命中先从池里扣 poise_damage：扣后仍 > 0 且 stagger_power ≤ 扣前有效韧性 → flinch；否则按下一行映射（扣后恰为 0 的那一击是"破韧"）
否则按 impactClass 映射：light → stagger_light；medium → stagger；heavy → knockback；massive → knockdown
Boss/精英规则：目标声明 reaction_cap（如最高到 stagger_light）→ 截到上限
被格挡（hitResult = Block，4.3 节）：目标声明 block_reaction_cap → 再截到该上限
硬直保护期：目标正处于硬直、或硬直结束后 stagger_grace_ms 未走完（4.1 节）→ 硬直类反应截到 stagger_grace_cap（缺省 flinch）；击杀不受影响
```

每一行只会把反应压低，不会抬高；声明了的才生效，没声明的行等于不存在。

- `stagger*` 是**硬直**（hit stun）：一段控制效果，打断当前动作（发 `action.cancelled{reason: stagger}` 与 `skill.cast_interrupted`），进入 `staggered` 运动模式（02），时长见 4.1 节公式，走模拟时钟；**与顿帧分别计时**，互不包含。硬直是受击裁决宿主自己登记的一段"硬直窗口"（时长、剩余、是否已开始），不是光环，也不受控制类光环的免疫与递减约束；防止"被高频攻击无限硬直锁"的是 4.1 节的硬直保护期，不是递减。
- `knockback`：硬直 + 击退运动（02 第 6 节，距离与时长见 4.2 节）；档案声明了 `launch_height` 且世界装配了竖直轴（`side_2d`/`volume`）时，同时按顶点高度 = `launch_height` ×(1 − 击退抗性)× 冲击等级倍率把目标抛起（06 第 1.2 节，击飞与击退互相独立；平面世界忽略）。`knockdown`：硬直 + 击退 + 倒地段 + 可选的起身段（4.5 节）。
- 韧性 `poise` 可由属性系统承载（是否启用为游戏级策略）；不声明时全部命中按 `impactClass` 映射，这是响应型缺省。**动态韧性**（M4-L）：攻击声明可选 `poise_damage` 即走韧性池——池的容量是 `poise` 属性值，每次动态命中扣 `poise_damage`（有效韧性 = max(0, 容量 − 已损失量)，扣后 > 0 且 `stagger_power` ≤ 扣前有效韧性才被挡成 `flinch`，把正数打到 0 是破韧，池子已空的命中同样不被挡）；目标侧可选 `poise_recover_delay_ms`（最近一次动态韧性伤害后等待多久，每次动态命中重新计）与 `poise_recover_per_s`（之后每秒回复多少，回满发 `combat.poise_recovered`；缺省不回复）。**三项可选扩展**（M4-W3，缺省全部等价上述口径）：目标侧 `poise_recover_mode = out_of_combat` 时处于战斗中的 tick 延迟与回复都暂停、脱战后才开始计延迟（战斗状态复用战斗模块的进出战状态）；目标侧 `poise_break_reset_ms` 声明后，破韧起算到点池子一次回满（已空池子上的命中不顺延计时）；`poise_damage` 可按攻击方冲击等级乘以倍率表（游戏填表，缺省空表不缩放，`combat.poise_changed` 的 `damage` 报告乘后的有效值）。命中不声明 `poise_damage`、或目标没有韧性属性，沿用上面的静态规则，逐位不变；霸体与击杀（死亡优先）不碰池。每次动态命中发 `combat.poise_changed`（`before`/`after`/`max`/`damage`/`broken`）。裁决入口因此多了一处状态写入（扣池），仍要求每次真实命中恰好调用一次。
- 玩家角色与怪物走同一裁决；玩家的 `reaction_cap` 与 `poise` 由角色手感层声明。
- 反馈永远不能让 Boss 无限硬直：`reaction_cap` 与硬直保护期是权威，反馈包只按 `reaction` 播。

### 4.1 硬直时长与硬直保护期

**硬直时长**（反应为 `stagger_light`/`stagger`/`knockback`/`knockdown` 时的"硬直段"）：

```
硬直段 tick = ms→tick( 受击方 hit_stun_ms × 攻击方 hit_stun_scale × 反应类型倍率 )
```

- `hit_stun_ms`：受击方基础硬直（受击组，受击方体型为主，沿用既有口径）。`hit_stun_scale`：攻击方（武器 / 技能，判定半的武器层）可选倍率，缺省 1——**武器对硬直时长的贡献在这里**：重武器声明大于 1，快刀小于 1。反应类型倍率是游戏级选项表（`stagger_light`/`stagger`/`knockback`/`knockdown` 各一个倍率，缺省空表即全部为 1），游戏要"轻击短硬直、重击长硬直"时自己填；乘 1 不改变数值，所以不声明任何一项时与此前逐位一致。
- 倒地段 `downed_ms` 与起身段 `getup_ms` **不乘**上述倍率（它们描述的是躺在地上与爬起来的动作长度，不是被打的力度）。
- 05 第 9 节试调起点里的"硬直 150/230 ms"是**受击方基础 `hit_stun_ms` 的参考取值**（单手剑 / 巨剑两档攻击对应的受击方硬直），落在目标一侧；想让同一个受击方对轻重两种武器有不同硬直，用攻击方的 `hit_stun_scale` 表达，而不是给受击方写两个值。
- 反应落地时算定（含攻击方倍率的快照），随 `combat.hit_confirmed` 的 `reactionDetail` 带到落地处，所以顿帧期间攻击方换武器不改变这一击的硬直。

**硬直保护期 `stagger_grace_ms`**（受击方可选字段，缺省无）：从硬直登记起，直到硬直（含倒地段与起身段）结束后再过这么久，期间新的硬直类反应一律截到 `stagger_grace_cap`（缺省 `flinch`，只播受击动画、不打断、不刷新硬直）；击杀（死亡优先）不受影响。

- 这是堵"每隔不到一次硬直时长就打一下 = 永远硬直"的唯一机制：没有它，硬直窗口每次被更长的新反应刷新、被连击锁死；有了它，一段硬直只能被完整地受一次，保护期过后才能再次硬直。
- 保护期从"硬直结束"那个 tick 起算，共 `stagger_grace_ms` 折算的 tick 数；起算前（硬直进行中）同样受保护，所以不存在"硬直结束与保护期开始之间的空窗"。
- 声明保护期的单位，硬直进行中被打到的那一击也截到 `stagger_grace_cap`：这是有意的——想允许"硬直中被更重的攻击升级成击倒"（对打游戏的追击），把 `stagger_grace_cap` 设为 `knockdown` 即可，此时保护期只起记账作用。
- 已知限制：同一 tick 内裁决的两次命中在任一方登记硬直之前各自读到"无保护"，两击都会得到完整反应；同 tick 双击不是"连击锁"，不额外处理。

### 4.2 击退距离与时长

击退距离 = 攻击方 `knockback_distance` ×(1 − 目标击退抗性)× 冲击等级倍率（02 第 6 节）。**击退时长**由攻击方可选字段 `knockback_duration_ms` 声明（武器 / 技能，缺省无）：声明了就按它（重击拖得更久、轻击瞬间弹开）；缺省取游戏级选项，选项也缺省则取运动层缺省击退时长，与此前逐位一致。时长与距离一样在裁决时算定、随命中确认带到落地处。

### 4.3 命中类别：暴击、格挡、偏斜、弹反

结算管线的 `hitResult`（06 第 4.2 节命中表）里，`Crit`、`Block`、`GlancingBlow`、`Parry` 此前与普通命中走完全相同的顿帧与反应。现在每一类可以**独立声明**冲击等级与顿帧倍率，不声明的类别逐位等价普通命中：

| 类别 | 字段来源 | 可声明项 |
|---|---|---|
| 暴击 `Crit` | 攻击方（武器 / 技能） | `crit_impact_class`（替换本次的冲击等级，同时决定反应映射、击退倍率与反馈包变体）、`crit_hitstop_scale`（攻击方与受击方顿帧时长都乘该倍率，再过各自上限） |
| 格挡 `Block` | 受击方（防御方） | `block_impact_class`、`block_hitstop_scale`、`block_reaction_cap`（被格挡的反应再截到该上限）、`block_attacker_reaction`（攻击方被弹开成什么反应） |
| 偏斜 `GlancingBlow` | 受击方 | `glancing_impact_class`、`glancing_hitstop_scale` |
| 弹反 `Parry` | 受击方 | `parry_impact_class`、`parry_hitstop_scale`、`parry_attacker_reaction` |

- 弹反时受击方不受伤、不起反应（沿用回避类结局），但声明了 `parry_hitstop_scale` 则**两侧**按基础顿帧时长乘该倍率顿帧，声明了 `parry_attacker_reaction` 则攻击方被弹开；两者都没声明与此前一致（什么都不发生）。
- 攻击方被弹开（`block_attacker_reaction`/`parry_attacker_reaction`，取值同 `reaction_cap` 的枚举，`none` 或缺省不弹）：按"攻击方作为受击者"落地——先过攻击方自己的霸体、`reaction_cap` 与硬直保护期，硬直段 = 攻击方自己的 `hit_stun_ms`（乘反应类型倍率）；击退方向是攻击方背离防御方，距离取自防御方的 `knockback_distance`，不击飞。`combat.reaction_applied` 此时 `targetId` 是攻击方、`sourceId` 是防御方。击杀不弹。
- 命中类别只改"这一击如何被感受"，不改命中表本身；暴击是否发生、格挡是否发生仍由结算管线决定。

### 4.4 格挡状态与弹反窗口

命中表的 `Block`/`Parry` 来自属性随机；动作游戏的格挡是"举盾期间正面的攻击被挡下"。裁决为此提供一个**防御状态查询**（契约接口，防御方的动作层或输入层实现；缺省没有实现）：

```
interface IGuardStateQuery { tryGetGuard(unitId) → (是否格挡中, 格挡开始后经过的 tick 数) }
```

- 没有实现（缺省）时回退到动作实例的格挡窗口标记：时间线标记 `guard_start`/`guard_end`（与 `armor_start`/`armor_end` 同形：成对、`guard_start` 先于 `guard_end`、缺 `guard_end` 持续到动作结束），格挡经过的 tick 数以动作时钟计、顿帧期间不增长。
- 防御裁决在**命中表之前**问一次（只对会掷命中表的伤害效果、非周期伤害）：
  1. 防御方处于起身无敌窗口（4.5 节）→ `Invulnerable`，不进命中表、不消耗随机数；
  2. 防御方在格挡中且攻击来向落在正面 `guard_arc_deg`（缺省 180 = 朝向前方的半平面；360 = 全向）内：格挡开始后 `guard_parry_window_ms` 之内 → `Parry`（弹反窗口，缺省 0 即无）；否则 → `Block`，伤害乘 `guard_damage_scale`（缺省 1 = 不减伤，0 = 完全挡住）；
  3. 其余按命中表。
- 格挡 / 弹反的反应与顿帧按 4.3 节的类别规则；`guard_*` 与 `block_*`/`parry_*` 字段都是受击方可选字段，没有声明时格挡状态不存在、也没有任何开销。
- 格挡状态不是"无敌"：被格挡的命中仍扣血（乘倍率）、仍计入命中确认，只是反应被压低、攻击方可被弹开。

### 4.5 倒地与起身

`knockdown` 反应的完整生命周期是三段，由受击裁决宿主依次推进，每段只在受击方动作时钟之外按模拟时钟走（与硬直同口径，顿帧期间不推进）：

```
硬直段（hit_stun 公式） → 倒地段（downed_ms） → 起身段（getup_ms，缺省 0 即没有） → 恢复
```

| 事件 | 时机 | 字段 |
|---|---|---|
| `unit.knocked_down` | 硬直段走完、倒地段开始（每次登记最多一次；硬直段为零时与反应落地同 tick） | unitId, downedTicks, getupTicks |
| `unit.getup_started` | 倒地段走完、起身段开始（只有声明了 `getup_ms` 才发） | unitId, getupTicks, invulnerableTicks |
| `unit.getup_finished` | 起身段走完、硬直解除（只有发过 `getup_started` 才发） | unitId |

- 查询：`isDowned`（仅倒地段）、`isGettingUp`（仅起身段）、`isStaggered`（三段合计，沿用既有语义）、`isGetupInvulnerable`（见下）。倒地期间被刷新（新的更长反应）则三段重新计、事件重新发。
- **起身无敌**：受击方可选字段 `getup_invuln_ms`（缺省 0 = 起身不无敌），从起身段开头起算（不超过起身段长度）；窗口内的命中判为 `Invulnerable`（不扣血、不顿帧、不硬直、不起反应），走 4.4 节的防御裁决，对非周期伤害全部生效、不要求效果会掷命中表。起身无敌只在起身段内，倒地段本身仍可被命中（追打倒地是对打游戏的常见设计，要不要由游戏用 `reaction_cap`/保护期自己限制）。
- 事件只描述阶段；**姿势由表现层按事件驱动**（04），框架不在规则层选姿势。

**反应 → 姿势键映射**（契约：姿势键与回落链的定义在 04 第 3、10 节，这里规定"哪个反应、哪个阶段请求哪个键"）：

| 反应 / 阶段 | 驱动事件 | 姿势键 | 备注 |
|---|---|---|---|
| `flinch` | `combat.reaction_applied`（`durationTicks = 0`） | `hit.light` | 单次受击动画，不进 `staggered` 运动模式、不打断动作 |
| `stagger_light` | `combat.reaction_applied` | `hit.light` | 持续到硬直结束 |
| `stagger` | `combat.reaction_applied` | `hit.heavy` | 持续到硬直结束 |
| `knockback` | `combat.reaction_applied` | `hit.knockback` | 持续到硬直结束；空中受击改请求 `hit.air`（04 第 10 节回落链） |
| `knockdown` 硬直段 | `combat.reaction_applied` | `hit.knockback` | 被打飞 / 后仰的过程 |
| `knockdown` 倒地段 | `unit.knocked_down` | `hit.knockdown` | 躺姿保持到倒地段结束 |
| `knockdown` 起身段 | `unit.getup_started` | `hit.getup` | 没有起身段（缺省）时倒地段结束直接回 `idle` |
| 起身结束 | `unit.getup_finished` | 回到运动 / 待机解析 | 同时硬直解除 |
| 被格挡（受击方，`Block`） | `combat.hit_confirmed`（`hitResult = Block`） | `hit.block` | 单次抖动，不进硬直 |
| 攻击方被弹开 | `combat.reaction_applied`（`targetId` 为攻击方） | 同上按反应类型 | 与受击方同一张表 |

- `stunned`（眩晕摇晃）**不属于**受击反应：它由控制类光环（眩晕、定身等，数值设计）驱动，与硬直是两回事；硬直不会请求 `stunned`。
- 键缺失时按 04 的回落链退到 `hit`；本表只规定请求，不要求资源齐全。

## 5. 反馈层次（与 07 的分工）

| 冲击等级 | 判定型（本文） | 呈现型（07 打击反馈包） |
|---|---|---|
| light | 短顿帧、`stagger_light` | 局部闪白、小粒子、轻音效层 |
| medium | 中顿帧、`stagger` | 后仰、中粒子、中音效层、轻镜头冲击 |
| heavy | 长顿帧、击退 | 大后仰、重低频音效层、镜头冲击、拖尾 |
| massive | 长顿帧、倒地 | 全套 + 慢动作请求（玩法层钩子，00 第 5 节） |

法术与远程强调飞行、落点爆炸与群体反应，`impactClass` 由技能行的 `feel_ref` 覆盖，不取武器；落点与优先级见第 2.6 节（技能行 `feel_ref` 进入 05 第 3.2 节第 6 层，高于武器与角色层，按字段覆盖）。

## 6. 离散模式

`timeline` 技能在离散模式下解释为：动作步内以当时位姿做一次 `marker` 式解析（全部 `hit` 标记折叠为一次），结算一次，不推进时间线、不顿帧、不硬直（受击裁决整体不运行，不登记硬直窗口；需要回合制的控制效果用既有控制光环，那是技能效果的事，不是受击反应）。呈现型在回放队列内照常。 声明了 `hit_anchor` 的落点技能在离散模式下同样折叠为一次瞬发结算（走既有地面落点路径），不进入时间线。

## 7. 事件词汇表增补

| 事件 | 字段 | 时机 |
|---|---|---|
| `combat.hit_confirmed` | 见 2.4 节 | 结算后置步骤 |
| `feel.hitstop_started` | unitIds, ticks, attackInstanceId | 顿帧施加 |
| `feel.hitstop_ended` | unitIds | 解冻或强制释放 |
| `combat.reaction_applied` | targetId, reaction, sourceId, attackInstanceId, durationTicks, stunTicks, downedTicks, getupTicks | 受击裁决落地（`none` 不发）；`durationTicks` = 三段之和（硬直 + 倒地 + 起身），后三项给出分段，非倒地反应的倒地/起身段为 0；被弹开的攻击方同样发（`targetId` 为攻击方） |
| `combat.hit_confirmed`（追加字段） | reactionDetail, attackerReaction | 受击反应的分段时长、击退时长与攻击方被弹开的反应（4.1～4.3 节）；不经受击裁决的发出方可以不填 |
| `unit.knocked_down` | unitId, downedTicks, getupTicks | 硬直段走完、倒地段开始（4.5 节） |
| `unit.getup_started` | unitId, getupTicks, invulnerableTicks | 倒地段走完、起身段开始（4.5 节） |
| `unit.getup_finished` | unitId | 起身段走完、硬直解除（4.5 节） |
| `action.target_assisted` | 见 02 第 5 节 | 目标辅助生效 |

`combat.attack_avoided.hitResult` 增加 `Invulnerable` 取值。

## 8. 测试与验收

无头宿主、输入脚本、假人靶；期望值由数据算出：

1. 每攻击实例对同一目标恰好命中一次；多段技能按 `segment` 与 `rehit_interval_ms` 命中期望次数。
2. `continuous` 高速形状在 30 tick/s 步长下不漏目标（与 120 tick/s 结果一致）；不同步长（30 与 120 tick/s）下命中集合相同。
3. 取消后无残留命中：取消当 tick 之后本攻击实例不再产生任何结算事件。
4. 无敌窗口内的攻击判为 `Invulnerable`，不扣血、不顿帧、不硬直；所有命中路径（时间线标记/判定相/投射物、目标选择式、范围效果）一致；治疗、周期结算、自伤与 `ignores_invulnerability` 技能不受影响；门恒为假时既有结算逐位不变（实验室既有基线零差异）。
5. 顿帧：攻击方与受击方各自冻结期望 tick 数；第三方单位位置与动作不受影响；群体命中攻击方取最大并限幅；嵌套取大；死亡/卸载后冻结句柄为零。
6. 受击裁决：`poise` 高于 `stagger_power` 时 `flinch` 不打断；`reaction_cap` 生效；死亡优先于一切。
7. `combat.hit_confirmed` 在两种模式下字段齐全，几何字段永不为空。
8. 投射物到达时结算沿用发射动作的攻击实例 id；攻击方被打断不影响已发射投射物。
9. 离散模式下开关 `timeline` 块结果逐字节一致。
10. 确定性：全部脚本连跑两次事件流逐字节一致。
11. 受击半径：每个靶子被命中当且仅当其中心到命中形状的最短距离不超过 `unit_body_radius × hurt_radius_scale`（由数据与几何规则在用例里算出）；接触点到目标中心的距离恰为受击半径、法线为单位向量；半径为 0 或装配选项关闭时与此前逐位一致。
12. 手感来源：技能行 `feel_ref`、分段 `args.feel_ref` 与 `charge.feel_scale` 各有一条复现（具体顿帧/击退数值由档案毫秒、标定与缩放规则算出）与一条不变量（未声明时受击裁决收到的缩放为恒等、不标记覆盖；同一段顿帧随蓄力比例单调不减）。
13. 落点技能：`hit_anchor: ground_point` 时只有落点前方的目标被命中、`caster` 时只有攻击方身边的目标被命中；未声明 `hit_anchor` 时地面落点施放不进入时间线（无 `action.started`）。
14. 加载期校验：`timeline_ground_target_unsupported`（警告，声明了 `hit_anchor` 后不再给）、`timeline_hit_anchor_without_ground_target`（警告）、`skill_feel_ref_conflict`（错误）、`timeline_marker_feel_ref_ignored`（警告）。
15. 硬直时长（4.1）：硬直段 tick = 受击方 `hit_stun_ms` × 攻击方 `hit_stun_scale` × 反应类型倍率换算（对若干倍率取值逐一断言）；不声明任何一项时与此前逐位一致；倒地段不乘倍率。
16. 硬直保护期（4.1）：复现"每隔不到一次硬直时长打一下"——不声明保护期时硬直被连击锁住、声明后连续硬直 tick 数恰为一次反应时长；保护期共 `stagger_grace_ms` 折算的 tick 数（窗口内最后一个 tick 仍是 flinch、之后第一击是完整反应）；击杀不受影响；`stagger_grace_cap` 可配。
17. 击退时长（4.2）：声明 `knockback_duration_ms` 的击退以该时长提交，未声明取游戏级选项。
18. 命中类别（4.3）：各类别声明的冲击等级、顿帧倍率、`block_reaction_cap`、攻击方被弹开逐项生效，攻击方霸体时不被弹开；未声明的类别与普通命中的裁决结果逐字段相同。
19. 格挡裁决（4.4，真实结算管线）：正面格挡伤害 = 普通伤害 × `guard_damage_scale`（对多个倍率取值断言），背后与不在格挡中不减伤，弹反窗口边界（窗口内最后一个 tick 弹反、之后格挡），`guard_arc_deg` 窄弧拒绝侧面、360 全向，不会掷命中表的效果（`canMiss = false`）忽略格挡；时间线 `guard_start`/`guard_end` 标记成对校验与窗口内外判定。
20. 倒地与起身（4.5）：`unit.knocked_down`/`unit.getup_started`/`unit.getup_finished` 的 tick 间隔恰为硬直段 / 倒地段 / 起身段；`isDowned`/`isGettingUp` 各覆盖对应段的 tick 数；未声明 `getup_ms` 时不发起身事件；非 knockdown 反应从不发阶段事件；起身无敌窗口内恰 `getup_invuln_ms` 折算的 tick 数被判 `Invulnerable`、窗口外伤害照常。
21. 实验室脚本（06）：`feel_react_knockdown`（阶段时长、击退距离、起身无敌）、`feel_react_grace`（保护期对照）、`feel_react_guard`（弹反 / 格挡 / 普通命中、攻击方被弹开）；度量在独立条件组 `reactionext`，既有脚本基线不变。
