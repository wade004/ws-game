## 1. 两种结算模式并存

| | `instant`（目标选择式，既有） | `timeline`（时间线式，新增） |
|---|---|---|
| 适用 | 法术、增益、治疗、召唤、锁定目标的追踪类 | 近战、投射物、闪避、突进、蓄力 |
| 目标 | 施法管线步骤 6 一次解析 | `hit_policy: marker` 在每个 `hit` 标记解析一次；`continuous` 在判定相逐 tick 解析 |
| 时机 | `cast_time` 结束一次结算 | 判定相内逐次结算，动作收尾不再结算 |
| 挥空 | 不存在（无目标即拒绝） | 存在：没有目标也开始动作，判定相打空就是打空 |
| 走位 | 与命中无关 | 站位与朝向直接决定命中 |
| 打断 | 读条打断 | 受击硬直打断、取消窗口取消 |
| 数据 | 既有字段 | 既有字段 + `timeline` 块（01 第 3.1 节） |

两种模式共用：施法管线步骤 1～5（存活/条件/学派锁/冷却/节拍锁/资源）、结算管线九步、事件词汇表、光环与 Proc、技能预算。技能声明了 `timeline` 块即为时间线模式，`resolution` 是派生的只读属性，不单独填。普通攻击（ADR-0059）可按武器声明 `timeline`（`feel.weapon` 的 `auto_attack_timeline_ref`），未声明时保持既有挥击计时。

现代单机动作游戏内部也是两种并存：近战与投射物走空间判定，追踪法术、增益、治疗走目标选择。本架构的规则层是魔兽血统，光环、属性、效果原语不动，只把近战与投射物的"命中判定"这一环换成空间判定。

## 2. 时间线模式的施法与命中

### 2.1 施法管线的解释

| 步骤 | `timeline` 模式下的解释 |
|---|---|
| 1～5 | 不变 |
| 6 目标合法性 | **不拒绝**：`hit_policy` 决定何时解析目标；本步只对声明了 `target_assist` 的动作做辅助目标解析（02 第 5 节），没有目标不是失败 |
| 7 距离与视线 | 不适用（`range` 只用于 AI 与目标辅助的候选筛选，不作为拒绝条件） |
| 8 读条/引导 | 改为**动作时间线推进**：按行动者动作时钟推进 `charge → startup → active → recovery`，触发标记；判定相内按 2.2 节命中 |
| 9 结算触发 | 拆为两处：每次命中各自结算（2.3 节）；动作自然结束时收尾（`action.finished` + `skill.cast_success`，不再结算） |

资源在 `cost_at` 时刻扣除（缺省动作开始），冷却在 `cooldown_at` 时刻起算（缺省动作开始）。法术队列语义由输入缓冲取代（01）；时间线技能不使用既有法术队列。

### 2.2 命中解析

- `hit_policy: marker`：每个 `hit` 标记到达时，用 `target_shape_ref` 的目标选择链以**攻击方当时的位置与朝向**为锚点解析一次（06 第 5 节 `resolve`），得到本段命中集合。
- `hit_policy: continuous`：判定相内每 tick 用同一条链解析一次；链的 `shape` 随攻击方当前位置与朝向移动。高速形状可能在两个 tick 之间跳过目标，处理方式二选一：适配层声明 `supportsSweep` 时用扫掠查询（形状从上一 tick 位姿到当前位姿的扫掠体）；否则按 `timeline.sample_step`（缺省一个 tick 的 1/4）在两 tick 位姿之间线性插值多次采样。判定相落在两 tick 之间的部分同样处理，低帧率不漏。
- **攻击实例去重**：每次动作激活分配一个攻击实例 id（沿用 06 第 3.6 节"攻击实例 id"语义，一次激活一个；`comboIndex` 不同的连招段各自一个）。同一攻击实例对同一目标缺省只命中一次；多段技能在标记或时间线上显式声明 `segment` 序号与 `rehit_interval_ms`，同一目标在不同段、且距上次命中不少于该间隔时可再次命中。命中集合随攻击实例存在，动作结束、取消、硬直时清空。
- 过滤：目标选择链的既有过滤（阵营、存活、免疫）照常；额外排除处于无敌窗口的目标（2.3 节判定前置）。
- `max_targets` 与超出策略（06 第 3.7 节）按每次解析生效。

### 2.3 每次命中的结算

每个新命中的目标构造一份 `EffectContext`（携带攻击实例 id、`segment`、技能 id、接触几何）执行既有 `effects` 列表，走结算管线九步。九步之前前置一项检查：

```
无敌窗口（目标 IActionStateQuery.isInvulnerable 为真）→ 直接判为回避，hitResult = Invulnerable，
   发布 combat.attack_avoided（ADR-0098 的既有出口，hitResult 取值扩一项），不进入命中表。
```

命中表（06 第 4.2 节）各项在时间线模式下仍可启用：站位打到了不等于一定命中，`miss/dodge/parry` 由属性决定，这是"数值层"与"空间层"的分工。游戏可以按口味关掉它们只留空间判定。

### 2.4 命中确认事件

结算落地后（九步的"后置"步骤内）发布新事件，两种模式统一发出，使反馈绑定不必区分模式：

| 事件 | 字段 | 说明 |
|---|---|---|
| `combat.hit_confirmed` | attackInstanceId, segment, sourceId, targetId, skillId, hitResult, amount, amountRatio, isCrit, isKill, contactPoint, contactNormal, worldDirection, impactClass, attackerHitStopTicks, targetHitStopTicks, reaction, castInstanceId | 一次命中的完整结论；紧随同一批次的 `combat.damage_dealt`/`combat.attack_avoided` 之后 |

- `contactPoint`：`continuous` 取形状与目标碰撞半径的最近交点；`marker`/`instant` 模式取目标登记位置；投射物取碰撞点。`contactNormal` 从目标中心指向接触点；`worldDirection` 为攻击方到目标的单位向量（击退方向）。无接触几何时三者由适配层给出明确替代（目标中心与攻击方朝向），不为空。
- `impactClass`：来自解析后手感表的受击组（缺省武器层 `impact_class`：`light|medium|heavy|massive`，可扩），是反馈包与受击裁决的公共输入。
- `castInstanceId`：发起本次命中的动作实例 id（与 `action.started`/`action.marker`/`action.phase_changed` 的 `castInstanceId` 是同一个值；时间线命中——包括投射物命中——填入，目标选择式 instant 命中没有动作实例为空）。反馈侧的挥空窗口按它与动作配对。`attackInstanceId` 仍是一批效果结算的攻击实例 id，二者不是同一个概念。
- `amountRatio`：`amount / 目标最大生命`，供反馈强度缩放。
- `reaction`：受击裁决结果（第 4 节）。
- 回避类结局也发本事件（`amount = 0`，`reaction = none`），使"打空/被闪避"有独立的表现（挥空音效、格挡火花），但**命中失败不播放成功命中的完整反馈**由反馈包按 `hitResult` 分流（07）。

### 2.5 投射物

投射物（既有机制，ADR-0028）在 `release` 标记发射；到达/碰撞时的结算复用 2.3 节，`contactPoint` 取碰撞点，攻击实例 id 沿用发射它的动作（多发投射物各自 `segment`）。飞行期间攻击方已进入后摇或被打断不影响已发射的投射物。

投射物的生命周期对外有两条事件（均带发射它的动作实例 id 与段序号）：`action.projectile_launched`（生成时）、`action.projectile_ended`（结局确定时，每发恰好一条，与发射一一配对）。结局原因 `reason` 取：`Hit`（命中后销毁或穿透次数耗尽；穿透中的命中不算结局）、`Blocked`（被地形挡住）、`Expired`（射程耗尽或到期）、`Cleared`（被清场、离开地图）。命中确认（`combat.hit_confirmed`）总是先于该发投射物的结局事件到达。反馈侧凭这两条事件判定投射物动作"是否打空"（07 第 6 节）。

## 3. 局部顿帧（行动者动作时钟）

### 3.1 定义

顿帧（hit stop）是命中瞬间攻击方与受击方短暂冻结的效果，本架构把它做成**判定型**：冻结的是参与者的**行动者动作时钟**（00 第 5 节），不是模拟时钟，不是表现帧。

- 冻结期间：该行动者的动作时间线不推进、取消/连招/无敌窗口不流逝、缓冲过期不推进、运动仲裁给 `frozen` 叠加态（位移为零，02 第 3.1 节）、`velocity` 保留；模拟时钟照常，其它单位照常，冷却按游戏级策略（缺省照常），光环照常。
- 表现层收到 `feel.hitstop_started{unitIds, ticks}` / `feel.hitstop_ended{unitIds}`，冻结对应实体的动画与程序动画时间轴；哪些层冻结（粒子、拖尾是否随冻）由打击反馈包声明（07）；界面、调参面板、其它实体不冻。
- 既有 `Freeze(durationMs)` 反馈动作（09 第 6.1 节）保留为纯呈现型的全局演出（过场、终结演出），与本节机制正交；缺省打击反馈包不再使用它。

### 3.2 时长与施加

- 攻击方时长 `attacker_hitstop_ms`、受击方时长 `target_hitstop_ms` 来自解析后手感表（受击组，武器为主、体型倍率），按 `impactClass` 与 `hitResult` 分档；回避类结局缺省不顿帧；击杀可用 `kill_hitstop_scale` 放大。
- 施加时机：tick 步骤 5 战斗结算落地之后、步骤 7 派发之前，与 `combat.hit_confirmed` 同批。
- **群体命中合并**：同一 tick 同一攻击方的一批命中，攻击方顿帧取批次最大值并按 `attacker_hitstop_cap_ms` 限幅，不逐个累加；每个受击方各自独立。
- **嵌套**：冻结中再被命中/再命中，新时长与剩余时长取大，不相加；`hitstop_cap_ms` 同样限幅。
- **释放保证**：死亡、销毁、场景卸载、离散模式切换时无条件解除并清零；测试断言"顿帧结束后所有冻结句柄为零"。
- 不随动作速率缩放（01 第 3.5 节）。

## 4. 受击裁决

一次命中对目标的反应由固定顺序裁决，输出 `reaction` 写入 `combat.hit_confirmed`：

```
死亡优先：目标本次落地后生命为零 → reaction = death（既有死亡流程）
免疫/回避：hitResult 为回避类 → reaction = none
霸体：目标处于 super_armor（时间线标记 armor_start/armor_end 或光环标志） → reaction = none（仍扣血、仍顿帧受击方，视 super_armor_hitstop 策略）
韧性：攻击的 stagger_power(impactClass) ≤ 目标 poise（属性，可选；未声明视为 0） → reaction = flinch（只播受击动画不打断）
否则按 impactClass 映射：light → stagger_light；medium → stagger；heavy → knockback；massive → knockdown
Boss/精英规则：目标声明 reaction_cap（如最高到 stagger_light）→ 截到上限
```

- `stagger*` 是**硬直**（hit stun）：一段控制效果，打断当前动作（发 `action.cancelled{reason: stagger}` 与 `skill.cast_interrupted`），进入 `staggered` 运动模式（02），时长 `hit_stun_ms` 来自受击组（受击方体型为主），走模拟时钟；**与顿帧分别计时**，互不包含。硬直落地为一个内部控制光环（复用光环机制与控制递减，06 第 3.9 节），不需要游戏自己写。
- `knockback`：硬直 + 击退运动（02 第 6 节）；档案声明了 `launch_height` 且世界装配了竖直轴（`side_2d`/`volume`）时，同时按顶点高度 = `launch_height` ×(1 − 击退抗性)× 冲击等级倍率把目标抛起（06 第 10 节勘误 9，击飞与击退互相独立；平面世界忽略）。`knockdown`：硬直 + 击退 + 倒地状态（`downed_ms`，起身动作，起身期间可选无敌）。
- 韧性 `poise` 可由属性系统承载（伤害削减韧性、脱战回复，是否启用为游戏级策略）；不声明时全部命中按 `impactClass` 映射，这是响应型缺省。
- 玩家角色与怪物走同一裁决；玩家的 `reaction_cap` 与 `poise` 由角色手感层声明。
- 反馈永远不能让 Boss 无限硬直：`reaction_cap` 与控制递减是权威，反馈包只按 `reaction` 播。

## 5. 反馈层次（与 07 的分工）

| 冲击等级 | 判定型（本文） | 呈现型（07 打击反馈包） |
|---|---|---|
| light | 短顿帧、`stagger_light` | 局部闪白、小粒子、轻音效层 |
| medium | 中顿帧、`stagger` | 后仰、中粒子、中音效层、轻镜头冲击 |
| heavy | 长顿帧、击退 | 大后仰、重低频音效层、镜头冲击、拖尾 |
| massive | 长顿帧、倒地 | 全套 + 慢动作请求（玩法层钩子，00 第 5 节） |

法术与远程强调飞行、落点爆炸与群体反应，`impactClass` 由技能的 `feel_ref` 覆盖，不取武器。

## 6. 离散模式

`timeline` 技能在离散模式下解释为：动作步内以当时位姿做一次 `marker` 式解析（全部 `hit` 标记折叠为一次），结算一次，不推进时间线、不顿帧、不硬直（硬直折叠为既有控制光环按回合计）。呈现型在回放队列内照常。

## 7. 事件词汇表增补

| 事件 | 字段 | 时机 |
|---|---|---|
| `combat.hit_confirmed` | 见 2.4 节 | 结算后置步骤 |
| `feel.hitstop_started` | unitIds, ticks, attackInstanceId | 顿帧施加 |
| `feel.hitstop_ended` | unitIds | 解冻或强制释放 |
| `combat.reaction_applied` | targetId, reaction, sourceId, attackInstanceId, durationTicks | 受击裁决落地（`none` 不发） |
| `action.target_assisted` | 见 02 第 5 节 | 目标辅助生效 |

`combat.attack_avoided.hitResult` 增加 `Invulnerable` 取值。

## 8. 测试与验收

无头宿主、输入脚本、假人靶；期望值由数据算出：

1. 每攻击实例对同一目标恰好命中一次；多段技能按 `segment` 与 `rehit_interval_ms` 命中期望次数。
2. `continuous` 高速形状在 30 tick/s 步长下不漏目标（与 120 tick/s 结果一致）；开 `supportsSweep` 与不开结果一致（命中集合相同）。
3. 取消后无残留命中：取消当 tick 之后本攻击实例不再产生任何结算事件。
4. 无敌窗口内的攻击判为 `Invulnerable`，不扣血、不顿帧、不硬直。
5. 顿帧：攻击方与受击方各自冻结期望 tick 数；第三方单位位置与动作不受影响；群体命中攻击方取最大并限幅；嵌套取大；死亡/卸载后冻结句柄为零。
6. 受击裁决：`poise` 高于 `stagger_power` 时 `flinch` 不打断；`reaction_cap` 生效；死亡优先于一切。
7. `combat.hit_confirmed` 在两种模式下字段齐全，几何字段永不为空。
8. 投射物到达时结算沿用发射动作的攻击实例 id；攻击方被打断不影响已发射投射物。
9. 离散模式下开关 `timeline` 块结果逐字节一致。
10. 确定性：全部脚本连跑两次事件流逐字节一致。
