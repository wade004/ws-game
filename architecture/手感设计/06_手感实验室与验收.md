## 1. 结构：一个内核、两个宿主、一份数据集

| 部件 | 位置 | 内容 |
|---|---|---|
| 实验室数据集 | 框架级数据目录 `_lab`（与框架级数据同级，占位命名，不含任何游戏内容） | 一张竞技场地图、玩家模板、四类靶子、首期武器、假人姿势集、`experimental`/`validated` 预设 |
| 实验室内核 | 框架内独立模块，引擎无关，依赖无头装配根（ADR-0035）与表现层公共部分 | 场景控制、输入脚本驱动、录制器、指标提取、覆盖存储、溯源查询、A/B 槽位、导出为测试 |
| 面板视图模型 | 表现层，与 HUD 视图模型同一模式（引擎侧只绘制） | 调参、帧数据时间轴、轨迹、指标、场景控制、评分 |
| 无头宿主 | 无头运行器 + 桩适配层（ADR-0018 无头适配层） | 命令行：数据根 + 预设 + 脚本 → 指纹文件；日常回归 |
| 引擎宿主 | 与模板游戏并列的独立包，基于长驻运行入口（ADR-0040） | 实验室场景 + 面板绘制；人玩、调参、里程碑冒烟 |

两个宿主吃同一份输入脚本、出同一种指纹。**数据根可替换**：实验室场景固定，数据根可指向任何游戏自己的数据集（长驻入口既有的数据根参数），新游戏用自己的角色、武器、美术进同一个实验室，面板与脚本原样可用。

### 1.1 场景矩阵

实验室不是一个场景，是一张 **空间与呈现组合 × 结算模式** 的矩阵，每个格子一行 `lab.scenario`，各自有脚本子集、靶子集、默认预设与指纹基线。用户拍板的六个格子：

| | 目标选择式（`rpg_classic` 预设，技能无 `timeline`） | 动作式（`arpg_responsive` 预设，近战/投射物有 `timeline`） |
|---|---|---|
| **2D** | `2d_targeted` | `2d_action` |
| **2.5D** | `2_5d_targeted` | `2_5d_action` |
| **3D** | `3d_targeted` | `3d_action` |

三种空间与呈现组合的定义（都建立在既有契约上，见 ADR-0012 与 05 第 3 节）：

| 组合 | 空间模型 | 外形 | 镜头 | 朝向 | 控制空间 | 命中形状 | 高度与影子 |
|---|---|---|---|---|---|---|---|
| 2D | 平面世界 | `sprite` | 正交俯视（俯角 90，无透视） | 翻转或 4/8 向量化 | 世界相对 | 二维 `Shape` | 无高度偏移，贴地影 |
| 2.5D | 平面世界 | `sprite` 或 `model` | 固定俯角透视（ADR-0012 缺省） | `sprite` 量化 / `model` 连续 | 世界相对 | 二维 `Shape` + 高度偏移只作显示 | 有 |
| 3D | 平面世界（当前） | `model` | 固定俯角透视；第三人称跟随为可选镜头模式（需适配层能力 `supportsFreeYaw`） | 连续 | 世界相对；第三人称下镜头相对 | 二维 `Shape`（当前）；体积扫掠为可选能力 `supportsVolumeSweep` | 有 |

**边界声明**：本架构的空间模型目前只有平面世界（05 第 3 节，无竖直运动轴）。"3D"格子在当前契约下指 `model` 外形 + 固定俯角，与 ADR-0012 的"三维角色加固定镜头"一致；斜坡、台阶、重力、空中控制、第三人称自由视角属于**体积空间能力包**（`space: volume`），需要导航与空间查询契约扩展和独立 ADR，本目录只在 `lab.scenario` 上预留 `space` 字段取值 `volume` 并标 `reserved`。横版二维（侧视 + 重力轴）同理预留为 `2d_side`，不在六格之内。

```
struct LabScenario {
  id: Id                                   // lab.scenario.<组合>_<模式>
  space: plane | volume(reserved)
  form: sprite | model
  camera_mode: ortho_top | fixed_pitch | third_person(需能力)
  control_space: world | camera_relative
  facing: flip | quantized | continuous
  hit_shape: shape_2d | volume(需能力)
  default_preset: Id                       // feel.preset
  default_weapons: List<Id>
  dummy_set: Id
  script_subset: List<Id>                  // 标准脚本集里适用的脚本
  required_capabilities: List<String>      // 缺失则该格子在此适配层上标"不可运行"，不静默跳过
}
```

**格子之间的不变量**（第 5 层与第 4 层各跑一次）：

1. 同一份输入脚本、同一预设，在 2D 与 2.5D、2.5D 与 3D（同为平面空间）之间，**逻辑组指纹逐字节一致**——镜头、外形、朝向量化只改呈现，不改判定；这是"手感核心真正可复用"的机器证据。
2. 同一组合内目标选择式与动作式的差异只来自 `timeline` 块与预设：把动作式数据集的 `timeline` 块全部移除并换预设，指纹应等于目标选择式格子。
3. 表现组指纹按格子各自有基线；跨格子只比较声明为"投影无关"的指标（响应帧数、反馈动作数、音效峰值），画面比例类指标不跨格子比较。
4. 三种组合对应三套脚本子集：2D 增加方向量化档位边界脚本；3D 第三人称格子增加镜头相对输入脚本；控制空间为 `camera_relative` 时轴到世界方向的换算是被测对象。

每个格子在每个适配层组合上有"可运行 / 不可运行（缺能力 X）"的显式状态，写进实验室的能力报告；预设的 `validated` 标签按格子记录（05 第 8 节），一个预设可以在 `2_5d_action` 已验证而在 `3d_action` 仍是 `experimental`。

## 2. 实验室数据集

**地形**：空地、一段直墙、一条走廊、若干柱子；覆盖贴墙、斜向、反转、绕柱。2.5D 无斜坡。

**靶子四类**：

| 靶子 | 特征 | 验证什么 |
|---|---|---|
| 不死木桩 | 吃伤害、有受击反应、不死、可选韧性值 | 打击反馈、受击裁决、顿帧 |
| 普通怪 | 会死，AI 可开关 | 击杀反馈、慢动作请求、掉落不干扰 |
| 精英 | 霸体、`reaction_cap`、抗硬直 | "反馈不等于硬直"、Boss 规则 |
| 群体 | 一键刷一簇 N 个 | 合并、限幅、限流、性能 |

外加一个巡逻靶（验证突进、目标辅助、追踪）与一个可破坏障碍（动态阻挡）。

**玩家模板**：三体量原型各一个，假人姿势集；首期武器单手剑与巨剑，各配 `feel.weapon` 与武器表现档案。

**占位装备集**：每个装备槽至少一件占位装备（占位图标 + 假人纸娃娃层全方向档全姿势 + `model` 型占位槽位网格/挂点模型），武器另配武器表现档案与 `feel.weapon`；这是 08 装备资产包契约的参照实现，也是换装场景（第 3.6 节）的夹具。

**场景模板**：按第 1.1 节矩阵，三种空间与呈现组合各一份场景（同一张竞技场地图，只换镜头档案、外形类型与朝向模式），结算模式由数据集与预设切换，六个格子共用地图与靶子。

## 3. 内核的五个机制

### 3.1 输入脚本

```
InputScript {
  meta: {datasetRoot, presetId, calibrationVersion, tickRate, frameRateCap, scriptVersion, description}
  events: List<{tick: Int, action: Id, kind: press|release|axis, value: Optional<Vec2>, realTs: Optional<Number>}>
  expectations: Optional<List<Expectation>>     // 由导出为测试时写入（3.5 节）
}
```

- 逐 tick 的动作事件序列，既可手写也可在引擎宿主录制。`realTs` 只用于延迟测量。
- 脚本回放经桩输入接口按 tick 注入（与 03 第 4.2 节步骤 1 的 `Intent` 记录同源），是实验室的通用货币：验收场景每个一份脚本入库当夹具。
- 标准脚本集（随框架发布）：短按移动、连续小幅轴、180 度反转、斜向、贴墙、绕柱、移动中攻击、攻击后急停、三段连招、闪避取消、蓄力、群体命中、被精英打断、击杀。

### 3.2 录制器

三条时间线同步记录，全部只读订阅：

| 时间线 | 内容 | 来源 |
|---|---|---|
| 逻辑 | 每 tick：位置、速度、运动模式与来源、动作相位、缓冲槽快照、命中事件、顿帧状态、受击裁决 | `MovementState`、`IActionStateQuery`、`IInputBufferQuery`、事件总线 |
| 表现 | 动画状态与剪辑键切换、反馈动作提交、镜头位置与冲击、音效层发声数 | 表现层事件与视图模型 |
| 真实时间 | 每帧真实时间戳、帧时间、分配量 | 真实时钟与宿主统计 |

引擎宿主录制时同时产出输入脚本，人玩的一局可在无头宿主逐 tick 重放。录制文件只留本地。

### 3.3 指标与指纹

从录制里算出指纹（每组指标的定义与容差写死在内核，不由游戏改）：

| 组 | 指标 | 逻辑/表现 |
|---|---|---|
| 响应 | 输入 tick → 动作接受 tick；输入真实时间 → 首次可见响应真实时间（ms 与帧）；命中确认 → 首个反馈动作提交（ms 与帧） | 逻辑 / 表现 |
| 移动 | 起步达速 tick 数、急停距离、反转耗时、斜向速度模长偏差、贴墙法向抖动量、绕柱路径长度 | 逻辑 |
| 攻击 | 每攻击实例命中次数、去重违例数、取消后残留命中数、各相实际 tick 数、连招接续成功率 | 逻辑 |
| 顿帧 | 作用实体集合、实际 tick 数、嵌套后的实际值、结束时未释放句柄数 | 逻辑 |
| 受击 | 裁决分布、硬直实际 tick 数、击退距离、倒地时长 | 逻辑 |
| 群体 | 合并后的攻击方顿帧、镜头冲击次数、同时发声峰值、反馈动作总数 | 逻辑 / 表现 |
| 性能 | 帧时间分布（p50/p95）、每帧分配、事件规模 | 表现 |

- 指纹 = `(脚本, 数据根版本, 预设, 标定, 姿势集版本, 适配组合) → 指标集合`。基线作为夹具入库。
- 逻辑组要求**逐字节一致**（固定步长确定性）；表现组按容差（内核给缺省，标定表可收紧不可放宽）。
- 真实屏幕延迟引擎测不了：实验室只提供"输入瞬间角落闪块"开关，供外接相机测量；引擎日志里的首次可见响应指的是提交到渲染的时刻。
- 30/60/120 帧率上限各跑一遍是标准脚本集的一部分（`meta.frameRateCap`），逻辑组三者必须一致。

### 3.4 覆盖存储与溯源

- 调参面板改的值进内存覆盖层（解析器第 8 层，05 第 3.2 节），与正式配置走同一套校验；在安全的动作边界生效（05 第 8 节）。
- 任意字段可查完整来源链（解析器 `provenance`）。
- 两个 A/B 槽位，热键瞬间切换；切换本身写进录制，指纹按槽位分开。
- "写回数据表"生成对表文件的差异并走正常提交；"恢复基准"清空覆盖层。
- 面板关闭后不产生正式版本开销：覆盖层为空时解析器路径与正式运行完全一致。

### 3.5 导出为测试

- 当前录制的脚本 + 当前指纹一键写成夹具（脚本文件 + 基线文件），落到测试夹具目录；`expectations` 由指纹生成，逻辑组精确、表现组带容差。
- 反向：回归失败的用例在引擎宿主加载脚本重放，慢放到四分之一速对照。

### 3.6 换装场景

装备资产包契约（08）的验收场：

- 场景内一个装备面板（既有 UI 布局定义）+ 纸娃娃/模型预览区 + 全部方向档与姿势键的轮播；一键"逐件穿戴"遍历数据根里每件可装备物品。
- 每件装备记录：图标是否解析、每个方向档 × 必备姿势键的纸娃娃层是否命中或按声明回落、`model` 型槽位网格/挂点模型是否加载、武器的武器表现档案与 `feel.weapon` 是否解析、武器族切换后姿势键与手感表是否随之变化、装备面板视图模型是否反映槽位变化。汇总为**装备完整性报告**（只留本地），与导入工具的静态检查（08 第 5 节）一一对应。
- 每件装备出一张换装拼图（全方向档 × 待机/跑/攻击三键）供人眼审，只留本地。
- 脚本：`equip_cycle`（逐件穿戴 + 每件一次攻击 + 一次移动），进标准脚本集；指纹里增加"装备解析"组（图标缺失数、层回落数、武器族切换后的姿势键与手感版本变化次数）。

## 4. 面板

全部从视图模型绘制，引擎侧不含逻辑：

| 面板 | 内容 |
|---|---|
| 调参 | 按七个分组（05）从字段登记自动生成；每字段显示来源层、单位、范围；A/B 槽位、重置、保存为预设、写回差异 |
| 帧数据时间轴 | 每个实体一条：蓄力/前摇/判定/后摇色条、输入标记、缓冲槽状态、取消窗口开闭、连招窗口、无敌窗口、顿帧、命中点、裁决结果；暂停后可逐 tick 或逐表现帧步进并拖动 |
| 轨迹 | 移动路径、速度矢量、判定形状与扫掠体、接触点与法线、目标辅助的转角，叠在场景上 |
| 指标 | 响应三项实时滚动；性能三项 |
| 场景控制 | 刷靶、换武器、换体型原型、切假人/正式美术、帧率上限、时间尺度、暂停/步进、单项关闭震屏/闪白/顿帧/音效/镜头冲击、角落闪块开关 |
| 评分 | 移动、转向、命中重量、连招衔接各 1～5 分；"慢/飘/软/黏/粘滞/拖沓/空挥"标签；连同预设版本、指纹哈希、设备条件存本地 |

暂停与单步：既有暂停机制上加"推进一个 tick"与"推进一个表现帧"两个入口（03 第 3.1 节主循环）。

## 5. 五层测试体系

前四层无引擎、无渲染，进日常回归；第五层只在里程碑与升级引擎时跑。

| 层 | 内容 | 跑在 | 频率 |
|---|---|---|---|
| 1 解析器单元 | 05 第 10 节：字段登记自动枚举组合、操作语义、合成来源、限幅、溯源 | 单元测试 | 每次提交 |
| 2 判定型模拟 | 01/02/03 各文档末节的用例：输入脚本喂无头 WorldSim，逐 tick 断言，期望由档案公式算出；确定性双跑 | 无头宿主 | 每次提交 |
| 3 呈现型模拟 | 假适配层记录调用时间线：顿帧冻结帧数、震屏曲线与叠加截断、闪白时间线、镜头轨迹、姿势解析回落链、剪辑播放速率 | 表现层测试（既有假适配层模式） | 每次提交 |
| 4 端到端指纹 | 标准脚本集全链路（模拟 + 表现 + 假适配层）→ 指纹 → 与基线比较；姿势与手感对齐（04 第 9 节） | 无头宿主 | 每次提交 |
| 5 引擎内实验室 | 同一脚本由脚本驱动器在引擎宿主回放，采指纹与无头指纹比差（差值 = 适配层引入的延迟），容差内为过；主观评分 | 引擎宿主 | 里程碑、升级引擎 |

指纹基线全部在假人姿势集上采集，与美术无关；游戏换上自己的美术后再跑一次，差异就是美术偏离规格的量。

## 6. 验收表与退出条件

| 验收项 | 客观检查（第 2～4 层） | 试玩检查（第 5 层评分表） |
|---|---|---|
| 移动 | 斜向速度、反转、滑墙、各帧率轨迹一致 | 启动、急停、转向是否跟手 |
| 攻击 | 标记跨帧、去重、取消清理、资源与冷却时刻 | 是否空挥、拖沓或粘滞 |
| 顿帧 | 作用域、时钟、嵌套恢复、输入采样 | 重量与节奏是否合适 |
| 受击 | 裁决分布、硬直与顿帧分离、韧性与上限 | 打击是否有分量、Boss 是否"站得住" |
| 群体命中 | 反馈合并、音效限流、镜头限幅 | 大量怪物是否遮挡与吵闹 |
| 姿势 | 完整性、对齐测试、回落链 | 走跑战斗各武器姿势是否可辨识 |
| 预设复用 | 新角色仅配置接入、版本与能力校验 | 两个角色/两把武器风格是否可辨识 |
| 性能 | 目标设备帧时间、分配、事件规模 | 操作中是否明显卡顿 |

**必须通过**（第 2～4 层硬门槛）：每个攻击实例按规则命中；取消后无残留伤害；顿帧结束所有句柄释放；死亡与场景卸载无冻结泄漏；低帧率不漏跨越事件；不支持能力可明确诊断；输入脚本双跑逐字节一致；离散模式开关手感体系结果一致。

**成熟度升级**：`experimental → validated` 需要：客观检查全绿 + 评分表一次不低于阈值（缺省各项 ≥ 4）的记录 + 绑定的数据根版本、姿势集版本、设备条件。连续试玩 10 分钟是体验环节，不能代替正确性验收。

## 7. 生成物规则

录制、指纹输出、评分、截图、缩略拼图全部本地，忽略规则覆盖；只有输入脚本与指纹基线作为夹具入库；每轮回归在回归记录里追加一行（沿全局规则）。基线更新必须显式：改动画、改标定、改合成规则导致指纹变化时，更新基线是一次有意的提交，不允许静默通过。

## 8. 新游戏怎么用（13 接入指南"手感接入"一节的落点）

1. 选基础预设与体型/武器原型，填 `feel.calibration`。
2. 用假人姿势集在实验室跑标准脚本集，得到自己数据根上的指纹（应与框架基线在容差内，否则是标定或数据问题）。
3. 逐键替换美术，跑对齐测试与完整性报告。
4. 试玩评分，热调参，写回数据表，导出自己的脚本为夹具。
5. 把自己的预设标 `validated` 时绑定版本与设备。

不写任何手感机制代码。

实验室内核与实验室数据集目前只在框架源码仓库提供，不随发布产物分发；只消费发布产物的游戏暂时跑不了第 2 步，接入正文与当前限制见 [13_新游戏接入指南.md](../13_新游戏接入指南.md) 第 9 节。

## 9. 建造顺序（依赖排序，不是切片计划）

内核 + 无头宿主 + 脚本与指纹（第 2/4 层即可跑）→ 引擎场景 + 指标面板 + 脚本重放（第 5 层）→ 调参面板 + 时间轴 + 溯源 → A/B、评分、导出为测试。

## 10. 首版落地勘误（2026-10-02）

内核与无头宿主首版落地后，实现与本文前述结构的差异如下；结论不变，以下为勘误：

1. **勘误：位置**。第 1 节"框架内独立模块"落在仓库顶层的独立目录（模块表里单独的一层，依赖装配根、桩适配层与表现层公共部分，任何运行时核心程序集都不引用它）；命令行与核心库分开，命令行放在工具链目录。数据集目录 `_lab` 与框架级数据同级，校验规则单独一步，不并入合并根。
2. **勘误：场景表字段**。第 1.1 节 `LabScenario` 之外，场景表增加三个字段：地形引用、结算模式显式取值（目标选择式 / 动作式）、输入动作到技能的绑定。`default_preset`、`default_weapons` 指向手感数据域（预设表、武器表）的行，但场景表对它们只作为自由标识携带、不校验存在性；脚本实际用的预设与武器由脚本元信息与数据根决定。`space` 的取值在 `plane`、`volume` 之外增加 `side_2d`（横版二维），两个预留取值的格子在宿主上显式标"不可运行"。另外新增两张表：地形表（阻挡矩形清单）与靶子集表（靶子条目：类别、生物模板、位置、分组、群体个数与间距）。
3. **勘误：动作式格子现状**。第 1.1 节"动作式 = 技能带 `timeline`"：不带手感装配的旧标准脚本没有 `timeline` 数据，三个动作式格子对它们的行为与对应的目标选择式格子一致（测试锁住，旧脚本的六格基线不变）；手感场景脚本里两类格子的差别正是 `timeline` 加预设，第 1.1 节不变量 2（移除 `timeline` 并换预设后指纹等于目标选择式格子）由跨格子不变量检查在运行期证明。
4. **勘误：靶子表达**。第 2 节"可破坏障碍（动态阻挡）"在数据表里只能近似为无 AI 的敌对低血量单位（没有运行期增删阻挡的表达）；精英的 `reaction_cap`、霸体、抗硬直已由手感场景自己的靶子集表达（带手感引用的精英、霸体窗口内与窗口后按反应上限封顶两种脚本），可破坏障碍在该靶子集里出场时追加占位阻挡、被打死后经导航接口的动态阻挡替换去掉；基础靶子集里的可破坏障碍仍是上述近似。数据表仍不能表达的是不死木桩的可选韧性值（木桩没有声明韧性）。
5. **勘误：基线布局与指纹**。第 3.3 节"基线作为夹具入库"落为每个脚本一份基线文件，内含六个格子各自的 `{键, 各度量组}`；真实时间类度量（帧耗时、分配）不按逐字节或绝对允差比较，按量级分桶入基线、只做上限检查，逻辑组逐字节、表现组按绝对允差。数据集哈希变化只给警告，以度量差异为准。
6. **勘误：脚本与导出**。第 3.1 节 `expectations` 首版未实现，"导出为测试"（第 3.5 节）产出脚本加基线，不产出期望清单；脚本带 `formatVersion` 与 `scriptVersion`，高于内核支持版本的格式被拒绝，脚本版本变化使旧基线失效。标准脚本集现有旧脚本十个（短按移动、连续小幅轴、180 度反转、斜向、贴墙、绕柱、移动中攻击、攻击后急停、群体命中、换装循环）加手感场景脚本二十个（近战与目标辅助、扑击与冲刺位移、投射物命中与挥空、三段连招、闪避取消、输入提前量、蓄力、普通靶被打断、精英霸体与反应上限封顶、击杀、可破坏障碍、巡逻靶、群体命中、运动加减速与转向与贴墙等）；"被精英打断"拆为霸体窗口内、窗口后封顶与普通靶被打断三种。
7. **勘误：指标组**。第 3.3 节现实现响应、移动、攻击、性能四组标准度量，加输入缓冲、动作时间线、顿帧、受击反应、运动、空间命中、表现七组手感度量，以及只在记录带换装记录时才出现的装备解析条件组；注册表按组扩展，不改运行器与比较器。响应组的"首次可见响应"在无头宿主上由假适配器视图的可见位移给出，视图插值因子在整步推进下恒为 0，故可见响应比逻辑响应晚一个 tick，这是现状的如实度量。
