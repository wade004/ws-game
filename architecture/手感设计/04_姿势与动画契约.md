## 1. 边界

- 框架不出任何具体游戏画风的最终美术（硬性规则）。框架出的是：姿势模型与解析规则、标准姿势清单与动作规格、标准人形骨骼上的姿势剪辑库（`model` 型）、中性假人姿势集（`sprite` 型）、导入校验与完整性报告。
- 姿势属于呈现型。姿势解析只读逻辑层的只读状态（动作相位、速度、姿态、武器族），永远不反向影响判定。判定型需要的剪辑时间信息（分相、命中标记）在作者态经导入工具抄写进 `skill.def.timeline`（01 第 3.2 节），运行期规则层不读表现域。
- 资源许可与来源由游戏层负责，导入不假定任意动画可互换。

## 2. 姿势维度模型

现状是七个状态键加两个补丁（`combat_` 前缀表示战斗姿态，武器表现档案覆盖攻击/施法剪辑），走路与跑步没有区分。本节把补丁收成正交维度：

| 维度 | 取值 | 决定者 |
|---|---|---|
| 状态 | `idle / move / attack / cast / hit / death / jump`（既有 `AnimState`，不增不减） | 动画状态机（09 第 4.2 节） |
| 步态 | `walk / run / sprint`（仅 `move` 状态） | 表现层按速度比例派生（02 第 7 节） |
| 姿态 | `peace / combat` | `combat.entered/left`（ADR-0111） |
| 武器族 | `unarmed / 1h / 2h / polearm / bow / staff / dual / shield …`（自由集合，`feel.weapon.family` 声明） | 主手武器解析（既有"实体 → 武器风格引用"链路） |
| 变体 | `wounded / carrying / mounted …`（游戏层自由扩展） | 游戏层声明的只读探针 |

性别与体型**不是维度**，是整套姿势集的选择（第 7 节）：一套姿势集就是一个身体原型的全部姿势，解析只在一套集内进行。

### 2.1 剪辑键语法

```
<state>[.<gait>][.<stance>][.<family>][.<variant>]      维度按此固定顺序拼接，缺省维度省略
例：move.run.combat.2h    idle.combat    hit.heavy    attack.2h    move.walk.wounded
```

既有键的兼容：`combat_<state>` 恒等于 `<state>.combat`（单处定义的别名，`AnimSetDef` 内），旧数据不改；无维度的 `<state>` 是基础键。

### 2.2 回落链

请求键找不到时按固定顺序逐个去掉维度，直到基础键：

```
去变体 → 去武器族 → 去姿态 → 去步态 → 基础键
move.run.combat.2h.wounded → move.run.combat.2h → move.run.combat → move.run → move
```

理由：跑步时缺武器族剪辑，播一条没拿武器的跑步比播一条拿武器的走路更不违和（后者脚会打滑）；变体最次要。武器表现档案的攻击/施法覆盖剪辑与技能覆盖剪辑优先级仍最高（既有规则），因此武器族维度主要服务运动态、待机与受击。

`hit` 状态按裁决结果加后缀：`hit.light / hit.heavy / hit.knockback / hit.knockdown / hit.getup / hit.block`，回落到 `hit`。后缀（状态子键）紧跟状态段、先于姿态与武器族：`hit.heavy.combat.2h`；带子键的请求先走完带子键的全部候选（去变体、去武器族、去姿态），再以不带子键的请求走一遍，最后是基础键——反应信息比站姿细分更重要。哪个反应、哪个阶段请求哪个后缀见第 2.4 节与 03 第 4.5 节。`attack` 的连招段由技能覆盖剪辑指定（`attack.2h.02`），不占维度。

步态回落补一条：请求 `move.sprint…` 找不到时，先以 `run` 代替 `sprint` 把同一串候选走一遍，再去步态——`move.sprint` 是可选键（第 3 节），没有冲刺剪辑的姿势集在冲刺时播跑步，而不是解析不到任何剪辑。

### 2.3 解析时机与就绪

与 ADR-0111 同一出口：运动态（`idle/move`）维度变化即时切换并从头播，解析结果与正在播的相同则不动；瞬态（`attack/cast/hit/jump`）不被维度变化打断，回落时按当时维度解析；`death` 不受影响。变体剪辑未加载完成时维持当前显示，就绪后经同一出口补切；换向重探测、换装重探测走既有键表机制，键表由回落链展开（外形实际声明的全部键）。

### 2.4 受击反应驱动与剪辑播放速率

**受击反应驱动**：世界装配了手感受击裁决（动作式，03 第 4 节）时，动画状态机进入反应驱动模式——`hit` 状态由裁决事件驱动而不是由"伤害落地"驱动，并带反应子键（第 2.2 节），映射表在 03 第 4.5 节：

- `combat.reaction_applied` 按反应请求 `hit.light`（`flinch`、`stagger_light`）、`hit.heavy`（`stagger`）、`hit.knockback`（`knockback`、`knockdown` 的硬直段）；`unit.knocked_down` 请求 `hit.knockdown`；`unit.getup_started` 请求 `hit.getup`；`combat.hit_confirmed` 的 `Block` 请求 `hit.block`；`unit.getup_finished` 与硬直结束回到运动态或待机解析。空中受击（`light/heavy/knockback`）请求空中键 `hit.air`（第 10 节第 9 条）；躺姿与格挡抖动不随空中改键。
- **反应为 `none`（霸体）不播任何受击动画**：没有 `combat.reaction_applied`，也就没有请求。此前"伤害落地就播受击"让霸体也播受击，已不成立。
- **保持**：有硬直的反应进入"保持"——剪辑播完停在末帧，直到硬直（含倒地、起身，空中硬直直到落地）结束的那个 tick 才回落到运动态。判据是受击裁决宿主的硬直时钟（只读查询 `IHitReactionQuery.RemainingStaggerTicks`，每个 `sim.tick_finished` 查一次），与逻辑层同源，顿帧期间自然不走，表现层不自己数 tick。
- **没有装配手感受击裁决的世界**（含离散模式、没有手感系统的游戏）：不进入反应驱动模式，受击仍由 `combat.damage_dealt` 驱动、不带子键，行为与此前逐位一致。

反应驱动模式的限制（原样记录）：①离散模式的世界裁决宿主不活动，状态机不进入反应驱动；②`flinch`（单次轻抖动）不打断动作——处于 `attack`/`cast` 时忽略，处于硬直保持中也忽略（不把倒地姿势换成轻抖动）；③格挡抖动同样不进入动作与保持，被格挡命中随后的 `flinch` 反应不再重播一次轻抖动；④有硬直的反应只在它刷新了硬直记录时生效（`RemainingStaggerTicks` 不大于事件的 `durationTicks`），较弱的反应打在更长的硬直上不换姿势，即"更轻的反应落在更长的硬直上"被忽略；⑤`stunned`（眩晕摇晃）不属于受击反应，由控制类光环驱动，不在本模式内。

**剪辑播放速率**：表现层对每个实体当前状态的剪辑给出播放速率（`ClipPlaybackRates`）：动作各相位取 `action.started` 带出的三相速率（作者毫秒 ÷ 重映射后实际毫秒）、移动取步幅速率（`stride_scale` × 速度比 ÷ 参考速度比），其余状态为 1；速率或状态变化时交给播放器（序列帧与骨骼剪辑都支持，播放器接口 `SetSpeed`，默认成员，不支持的实现忽略）。取值规则与限制见 02 第 7 节。速率是播放参数，不改变事件的百分比位置，也不影响判定。

## 3. 标准姿势清单

键数随维度组合与武器族增长（本文不写死总数，以 `display.anim_set` 数据为准）；框架预置的每套姿势集（标准骨骼剪辑库与假人姿势集）按下表覆盖全部必备、推荐与可选键：

| 层级 | 键 | 说明 |
|---|---|---|
| 必备 | `idle`、`move.walk`、`move.run`、`attack`（每个武器族一段）、`hit`、`death` | 缺任一项数据校验为错误，姿势集不能发布 |
| 推荐 | `idle.combat`、`move.run.combat`、`attack` 二三段、`hit.heavy`、`hit.knockback`、`hit.knockdown`、`hit.getup`、`cast`、`dodge`（作为 `attack` 的技能覆盖剪辑）、`jump`、空中键 `jump.rise`/`jump.fall`/`jump.land`/`hit.air`/`attack.air[.<族>]`（见第 10 节第 9 条） | 缺项为警告并进完整性报告；运行期按回落链兜底 |
| 可选 | `move.sprint`、`move.walk.combat`、启停过渡（`move.start`/`move.stop`/`move.pivot`，作为过渡剪辑）、`hit.launch`、`stunned`、`block`、`wounded` 变体 | 缺项静默回落 |

启停过渡剪辑（`move.start`/`move.stop`/`move.pivot`）不是状态，是可选键，留给美术提供；运行期当前只做混合：待机与移动之间切换时用 `start_blend_ms`/`stop_blend_ms` 作交叉淡入时长（02 第 7 节），**尚未选用这三个过渡剪辑**——已知限制，它们在标准姿势集里存在但运行期不请求。

## 4. 动作规格

每个姿势键一份规格，随 14 资产规格书模板发布，是美术交付验收标准，也是手感相对量（分相比例、步幅）的依据：

| 规格项 | 内容 |
|---|---|
| 循环 | 是否循环；循环剪辑首尾帧姿势连续 |
| 关键姿势 | 走/跑：接触、下沉、经过、抬起各一次（每条腿）；攻击：预备、接触、收势；受击：冲击、恢复 |
| 参考时长与帧数 | 以标定帧率给出参考值（如走 1000 ms、跑 600 ms、轻攻击 450 ms） |
| 每循环位移 | 走/跑剪辑每个循环对应的身高倍数位移；它与时长一起决定剪辑"是按多快的移动制作的"（速度比 = 每循环位移 ÷ 时长 ÷ 基础移速），是 02 第 7 节参考速度比的制作依据与导入校验的对照项，运行期不读 |
| 时间标记 | 第 5 节要求的标记与其参考位置 |
| 方向档 | `sprite` 型需覆盖的方向档位（09 第 3.2 节） |
| 锚点 | 角色中心、地面点、武器/施法点、命中点、脚点（挂点语义沿 09 第 3.3 节） |
| 元数据 | 时长、朝向、适用运动模式、资源比例（像素密度或骨骼比例） |

## 5. 时间标记

| 标记 | 剪辑内 | 归属 | 说明 |
|---|---|---|---|
| `active_start` / `active_end` | 攻击类 | 判定（经导入抄入 timeline） | 判定相 |
| `hit` | 攻击类 | 判定 | 命中点，可多个带 `segment` |
| `combo_open` / `combo_close` | 攻击类 | 判定 | 连招窗口 |
| `cancel_open:<class>` | 攻击/施法类 | 判定 | 取消窗口 |
| `invuln_start` / `invuln_end` | 闪避类 | 判定 | 无敌窗口 |
| `motion_start` / `motion_end` | 突进/闪避类 | 判定 | 动作位移 |
| `release` | 远程/施法类 | 判定 | 投射物发射 |
| `footstep` | 走/跑 | 表现 | 脚触地（音效、扬尘） |
| `trail_start` / `trail_end` | 攻击类 | 表现 | 拖尾 |
| `fx:<id>` | 任意 | 表现 | 特效挂点触发 |
| `impact` | 受击类 | 表现 | 受击冲击帧（闪白对齐） |

**唯一权威**：`skill.def.timeline.source` 决定判定类标记的作者态权威（01 第 3.2 节）；运行期规则层只读 `timeline`，表现层只读剪辑。同一事件不由两处触发。动画加速或减速时表现层的播放速率与判定时间线用同一系数（01 第 3.5 节），跨帧标记按区间遍历，不重复触发回调，不因重复播放音效或回调造成多次伤害。

**表现类标记的对外发布**：序列帧外形与骨骼外形的角色外壳都实现可选接口 `IClipMarkerEmitter`（`ClipMarkerReached(entityId, 标记名)`）：剪辑播放跨过标记时发布一次，标记名原样转发（不过滤、不改写），不进事件总线的 `action.marker`（那条只承载判定类标记，01 第 3.3 节）；纯呈现，不得反向影响判定。框架只保证"发出去"；`footstep`、`trail_start`/`trail_end`、`fx:<id>`、`impact` 触发什么（脚步音与扬尘、拖尾、特效挂点、闪白）由反馈绑定与音画消费方订阅它接线（07），不各自读剪辑。

**脚步声单一来源**：剪辑含 `footstep` 标记时，标记是该单位脚步的唯一来源；`display.map.stride_distance` 经 `unit.stride_completed`（ADR-0078，几何累计）只服务没有 `footstep` 标记的外形（静态图、未标注的美术）。两者并存会让同一步发两次声音与扬尘，消费方据此在有标记的外形上抑制 `stride_completed`。本条是契约，消费端的接线随表现类标记的消费方落地（07）。

顿帧冻结哪些层（骨骼/序列帧必冻，粒子与拖尾按反馈包声明）见 07。

## 6. 标准资产

### 6.1 标准人形骨骼与剪辑库（`model` 型）

- 框架定义一套标准人形骨骼（骨名、层级、单位比例、前向轴、根骨约定——根骨原地、不携带位移轨迹，位移权威在逻辑层），随版本发布。
- 标准姿势清单的每个键在该骨骼上各有一版剪辑，按身体原型出若干组（轻/中/重三档体量，第 7 节与第 10 节第 7 条），每组即一套姿势集。步幅不是资产维度：它是运行期参数，由播放速率表达（02 第 7 节），不为步幅出独立剪辑。
- 使用标准骨骼的游戏换蒙皮即拥有全部姿势；自有骨骼做一次重定向，重定向结果仍按第 8 节校验。
- 剪辑库自带全部时间标记，且经手感实验室验证（06），随成熟度标签发布。

### 6.2 假人姿势集（`sprite` 型）

- 序列帧美术无法重定向，框架提供中性像素密度的假人（剪影或块状人偶）序列帧，覆盖标准姿势清单全部必备与推荐键、全部方向档，时间标记齐全。
- 用途：新游戏第一天就用假人跑手感、跑测试；美术后来按规格逐键替换；手感实验室的指纹基线全部在假人集上采集，因此与美术无关（06 第 5 节）。
- 已实现（[ADR-0140](../adr/0140-标准骨骼蒙皮预渲染为序列帧.md)）：把标准骨骼加蒙皮预渲染成序列帧，让 `sprite` 型游戏做一套蒙皮自动得到全部姿势与方向档。这是离线工具链能力，运行期契约不变：产物是普通的序列帧型姿势集（序列帧资源 + `display.anim_set` 数据行），与假人姿势集同形；帧数、帧时长、事件时刻与假人姿势集取自同一套函数，逐键逐位一致。入口与用法见 `toolchain/prerender_skin/README.md`。

### 6.3 交付形态

姿势集是 `display.anim_set` 的一行加对应资源；框架级姿势集放在框架级数据目录，id 以 `display.anim_set.std_` 开头，随版本发布并受不可变发布规则约束。

## 7. 姿势集的继承、覆盖与角色差异

- `display.anim_set` 新增可选字段 `extends: Id`：只声明要覆盖的键，未声明的键沿用模板；链无环，深度不限；解析时先合并再走回落链。
- 角色定义引用：单位模板 `display.map.anim_set_ref`（既有）指向自己的姿势集；`feel_ref`（05）指向手感角色层。性别与种族在游戏层的数据里映射为"选哪套姿势集 + 选哪个体型原型"，框架不认识性别。
- 同一性别可以有不同重量与敏捷（选不同体型原型），不同性别可以选同一套姿势集。怪物复用同一语义系统；巨型、四足、飞行角色需要自己的姿势集与运动能力声明（骨骼不同，标准清单里的键名照用）。
- 武器表现档案（09 第 4.4 节）继续决定攻击/施法覆盖剪辑与特效变体；本节的武器族维度补齐运动态与待机的武器差异。

## 8. 导入校验与完整性报告

导入工具（框架交付物，ADR-0014）的 `import_assets check` 对 `display.anim_set` 与技能时间线做下列检查；落点列写明每项由谁执行，不在 `import_assets check` 里的项由生成器侧或引擎侧工具执行，游戏自有美术的这几项由游戏侧工具负责：

| 检查 | 级别 | 落点 |
|---|---|---|
| 继承合法（`extends` 存在、无环）、键语法合法 | 错误 | `import_assets check`（`anim_set_extends_invalid`、`anim_set_key_syntax`） |
| 必备键齐全（按清单发布的姿势集：声明 `pose_standard: true` 或框架级 `display.anim_set.std_*`；既有的自由姿势集不受影响） | 错误 | `import_assets check`（`anim_set_pose_required_missing`） |
| 推荐键缺项 | 警告，写入完整性报告并指出回落到哪个键 | `import_assets check`（`anim_set_pose_recommended_missing`） |
| 攻击类剪辑有 `active_start/active_end` 与至少一个 `hit`；走/跑/冲刺剪辑有 `footstep`；闪避类有 `invuln_start/invuln_end`（同样只对按清单发布的姿势集） | 错误 | `import_assets check`（`anim_set_clip_markers_missing`） |
| 声明的剪辑总时长 `duration_ms` 与资源一致（序列帧资源从 `frames.json` 量出，缺省声明时以量出值为准；骨骼剪辑没有磁盘资源可量，只检查声明值有效） | 错误 | `import_assets check`（`anim_set_clip_duration_mismatch`） |
| `skill.def.timeline` 与剪辑标记一致：`source: clip` 时任一偏差超过抄写取整误差为错误，`source: data` 时偏差超过标定表 `marker_tolerance_ms`（取不到按 50 毫秒）为警告；技能到剪辑的对应见下 | 错误 / 警告 | `import_assets check`（`timeline_clip_*`），生产加载期同口径（`SkillClipConsistencyRule`，规则组装层，读 `duration_ms`） |
| 序列帧资源完整：图集、帧文件、方向档数、锚点、镜像对等 | 错误 | `import_assets check`（`sprite_*`、`display_anim_*`） |
| `sprite` 型：原点、帧时长、碰撞轮廓、层级排序；循环标志与规格一致、循环剪辑首尾连续；每循环位移与时长在规格参考值的容差内 | 错误 / 警告 | 框架假人姿势集的生成器自检；游戏自有美术由游戏侧工具 |
| `model` 型：单位、比例、前向轴、骨架兼容、根骨原地、武器锚点、关节角限 | 错误 | 骨骼剪辑库的只读一致性检查（第 10 节第 6 条）；自有骨骼的重定向结果由游戏侧工具 |

**技能 → 剪辑的唯一映射**（`source: clip` 与一致性检查所依赖）：来自施法者武器表现数据，两处——①`display.weapon_style.cast_anim_override`（技能 id → 剪辑资源引用）；②普攻：物品 `feel_weapon_ref` 指向的 `feel.weapon.auto_attack_timeline_ref`（普攻技能）与物品 `display_ref` → `display.map.weapon_style_ref` → `display.weapon_style.auto_attack_anim`（普攻剪辑）。两处都指到同一技能时 `cast_anim_override` 优先（作者的显式指定）。资源引用再经姿势集（已合并 `extends`）找到剪辑条目，取其 `events` 与 `duration_ms`。没有声明 `duration_ms` 的剪辑取不到标记（事件是百分比，没有总时长无法换算毫秒）：`source: data` 的技能静默跳过，`source: clip` 的技能报错（权威来源缺失，不静默放过）。同一资源被多个剪辑键引用时取键名序最前者，确定性，不依赖加载顺序。

缺必备键拒绝发布；可选启停过渡缺失回退为混合并在报告中显示。报告是校验输出，不入库。

## 9. 姿势与手感的对齐（测试）

这一层保证"改了动画帧数手感就变了"在提交前暴露：

1. 剪辑长度 × `timeline` 分相比例得到的三相时长与 `feel.weapon.timeline_reference` 声明的参考值偏差不超过一帧（标定帧率；武器没有声明参考值时不检查）。
2. `hit` 标记落在判定相内；`invuln` 窗口不超出剪辑。
3. 走/跑剪辑 `footstep` 间隔换算的位移等于规格的每循环位移除以步数，且与 `display.map.stride_distance`（ADR-0078）一致（两者只在没有 `footstep` 标记时才同时出现声音，第 5 节脚步声单一来源）。
4. 回落链：枚举全部维度组合，解析出的键与预期链一致；只要基础键存在任何组合都能解析。
5. 姿势集继承：`extends` 合并后完整性报告与手写等价集一致。
6. 引擎宿主：每套姿势集出一张缩略拼图（每键一格）供人眼审，只留本地。

第 1、2、3 条对框架假人姿势集由其生成器自检执行；对游戏自己的"技能 + 姿势集"组合，第 8 节的剪辑标记与时间线一致性检查覆盖第 1、2 条的同类问题（时间线抄自剪辑或与剪辑偏差在容差内，则 hit 落在判定相内、三相时长与剪辑同源），第 3 条没有通用门槛。

## 10. 标准资产的落地判定

第 6 节标准资产（`model` 型标准骨骼与骨骼剪辑库、`sprite` 型假人姿势集）落地时的具体判定如下，是正文的组成部分：

1. **落地范围**。框架级骨骼剪辑库提供一套标准人形骨骼的占位模型资源（`model.std_dummy_biped`：骨盆、躯干、头、双臂、双腿共十七根骨骼，主手与副手挂点 `socket.main_hand`、`socket.off_hand`，头部块体名 `slot.head`，方块可视件，不带蒙皮）与一套姿势集 `display.anim_set.std_dummy_biped_model`，覆盖第 3 节全部必备、推荐与可选键：八个武器族（徒手、`1h`、`2h`、`polearm`、`bow`、`staff`、`dual`、`shield`）的待机、移动、冲刺、攻击与格挡，以及 `move.sprint`、启停过渡 `move.start`／`move.stop`／`move.pivot`、`hit.launch`、`stunned`、`block`、`wounded` 变体与受击后缀键（键数以数据为准，本文不写死；部分键是指向同一剪辑的别名，例如战斗站姿的冲刺别名到无站姿的冲刺；因为键回落链是先去变体、再去武器族、再去站姿、最后去步态，冲刺键找不到才先退回奔跑再去步态，所以每个族的冲刺键都应登记）。序列帧版与骨骼版同一份键清单、同一组姿势函数。第 6.1 节"轻/中/重体量 × 短/中/长步幅"的判定见本节第 7 条；标准骨骼的比例、前向轴、骨骼局部旋转约定写在生成规格的参数里，不随引擎资产分散。
2. **与序列帧版同源**。键清单、时长、三相毫秒数、帧数规则、命名事件（第 5 节）与每步位移全部取自序列帧版同一份配置，姿势取自同一组姿势函数，逐键逐帧同源；骨骼剪辑的关键帧取在序列帧版的帧边界上（含终点，关键帧数为帧数加一），相边界与三相毫秒数精确对齐。试调起点（05 第 9 节单手 110/80/190 毫秒、双手 170/100/290 毫秒）因此两版一致。
3. **动作质量与关节角限**。占位级动作：待机呼吸、走与跑的左右交替摆臂迈步、攻击前摇—命中—收招三相、受击后仰。肘与膝是单轴铰链，取样时夹在 0 到 150 度之间，不出现反向过伸（序列帧版的受击与倒地姿势在二维剪影上允许的负肘角，骨骼上会成为手臂反折，故只在骨骼版夹紧）；肩、髋、躯干、头的上下限按全部姿势的包络再留余量，自检对每个关键帧检查每根骨骼的局部旋转角不超限。躺姿（M4-W5）：`hit.launch`、`hit.knockdown`、`hit.getup`、`death` 与 `hit.launch.land`（末姿势与 `hit.getup` 起姿势相同，所以同一躺姿一并重绘）改用骨盆整体俯仰表达躺平（仰卧约 -88 度、俯卧约 +88 度），肩、髋、躯干回到人体范围：肩前屈 -65 到 185 度、髋前屈 -46 到 100 度、躯干俯仰 -50 到 60 度，上臂、大腿、躯干、头的骨骼旋转角上限同步收紧；整体俯仰只对这些躺姿键与击飞翻滚两键开放（髋的旋转上限分别放到 100 度与 180 度），其余键恒为 0，自检会报错。键名、时长、事件（名与时刻）、帧数不变，其余键的规格条目与图像字节不变（M4-W6 重绘的重受击与击退除外），两版与体量组、装备集同步。重受击与击退（M4-W6）：`hit.heavy`、`hit.knockback` 的极值帧此前靠外推表达强后仰，肩后伸到约 -125 度，靠按键登记的角限例外保留；现在放开这两个键的字节锁、重绘到人体范围——限肢外推倍率降低，后仰由骨盆整身俯仰补足（重受击约 -12 度、击退约 -24 度，乘体量反应倍率，只后仰，整体俯仰上限 35 度），整体俯仰开放的键因此扩为躺姿、翻滚与这两个键，其余键仍恒为 0。键名、时长、事件、帧数不变，由结构摘要逐字节锁定；角限例外表与相关机制一并删除，任何键的肩、髋、躯干角限都是同一张全局表，没有例外。翻滚时整个身体绕骨盆翻转、落地缓冲贴地。
4. **命中事件别名**。第 5 节的命中标记名是 `hit`，而 `model` 型角色外壳识别的命中帧事件名是 `hit_frame`（ADR-0017）。数据行只写第 5 节的名字（与序列帧版同源），骨骼剪辑内部在每个 `hit` 旁同时刻再放一条 `hit_frame` 别名事件，使命中帧同步在 `model` 型单位上落在第 5 节规定的时刻（判定相中点）；序列帧版也识别 `hit_frame`：两版的数据行都在每个攻击剪辑的事件表末尾追加一条与 `hit` 同时刻的 `hit_frame` 事件（既有事件的内容与顺序不变，只在末尾追加），序列帧播放器按事件时间百分比换算出关键帧下标并在播到该帧时触发一次；骨骼版烘进剪辑时，数据行已带同名同时刻事件则不再重复烘。弓的放箭点 `release` 同样与 `hit` 同时刻。施法 `cast` 的释放点 `release`（M4-W5）同样烘出同刻 `hit_frame` 别名（一个剪辑最多一条），使 `model` 型单位的命中帧同步能数到施法的释放点；序列帧版识别 `release` 或 `hit_frame`，两版等价。
5. **带参标记的事件名换算**。带参标记（`cancel_open:dodge`、`fx:<id>`）的冒号后缀在引擎事件标识里换成点分段（`cancel_open.dodge`），因为标识格式不允许冒号；写错的、仍不合法的事件名静默丢弃，不打断动画播放。
6. **交付与校验**。生成物为一份规格文件（骨架、可视块体、逐剪辑关键帧与事件）、数据行，以及由规格经引擎侧生成脚本产出的模型资源、动画控制器与逐键剪辑资源；第 8 节"model 型"校验在工具链里落为只读一致性检查（规格与当前代码逐字节对账、缺键、缺事件、帧数与关键帧数、骨骼路径与模型资源骨骼层级、关节角限、用写出的旋转把关节摆回去与序列帧版关节位置对账、数据行与引擎资产一致），接入门禁。
7. **体量与步幅轴的判定（第 6.1 节）**。步幅是运行期参数——第 6.1 节的播放速率就是步幅的运行期表达（02 第 7 节），不为步幅出独立资产；体量差异只在站姿（躯干前倾、重心高低、四肢开合）与受击／腾空幅度上，不改时长、帧数、事件与每步位移。体量三档（轻、中、重）由数据声明：配置里一张体量表给出每档的关节角偏移与两个幅度系数（受击反应幅度、腾空高度，反应幅度有上限），中档就是主集，不叠加偏移；两版（骨骼版与序列帧版）都读同一张表。数据行：主集 `display.anim_set.std_dummy_biped_model`（序列帧版 `display.anim_set.std_dummy_biped`）加三个体量行 `…_medium`（空 `extends` 行，不声明任何键）、`…_light`、`…_heavy`，后两者用 `extends` 继承主集且**覆盖主集的全部键**（含别名），每个键指向体量组自己的剪辑，键清单永远与主集一致，不会出现某个键只有主集版本。受击反应幅度系数的上限防止轻体量把受击后仰放大到穿帮；腾空高度系数只作用于跳跃与击飞的离地量。装备集占位剪辑只跟主集走（装备美术覆盖是按主集键对位的占位，见 ADR-0100）。资产体量：序列帧版每个体量组同样写整身方向变体（M4-W5，取代此前只写正面合成图的取舍）：先估算全部键的增量，实测新增 2340 个文件、约 8.2 MB（轻约 4.0 MB、重约 4.2 MB），低于 20 MB 的上限，所以全部键都出、不退化为只出移动与待机键；用整身剪辑（没有纸娃娃层）的外形在体量组下因此也随朝向换图。M4-D 追加的序列帧资源新增文件合计约 16.6 MB（轻体量组约 6.6 MB、重体量组约 6.9 MB、新键约 1.8 MB、装备集派生约 1.2 MB），既有五个族的武器层与合成图原地改写体积变化约 0.2 MB，未超过 20 MB 的上限。
8. **确定性生成与门禁**。骨骼版的动画控制器由生成脚本直接按固定格式写出：状态与过渡的标识由状态名按固定散列公式给出，控制器的元数据标识沿用既有值；因此重复生成两次逐字节一致，且既有剪辑资源与模型资源字节不变（新键只追加；唯一的例外是五个新武器族的武器层与合成图，见第 9 条）。序列帧版的一致性检查同样接入门禁（与骨骼版检查并列，缺图像库时按快速档跳过）。装备集由全部假人剪辑派生，新增键与族自动级联，`block` 并入装备集需要派生的族状态。
9. **空中姿势键（手感落地 M4-V，[ADR-0130](../adr/0130-竖直轴能力包.md) 追加决定）**。竖直轴能力包装配后，姿势请求在空中有固定键与固定回落链：`jump.rise`/`jump.fall` → `jump` → `idle`；`jump.land` → `idle`；`hit.air` → `hit.launch` → `hit`；`attack.air.<族>` → `attack.air` → `attack.<族>` → `attack`（无武器族时 `attack.air` → `attack`）。空中键之后可按地面键同样的顺序追加 `[.<姿态>][.<武器族>][.<变体>]`（姿态只有 `combat` 生成段、`peace` 省略，武器族与变体是自由集合；例如 `jump.rise.combat`、`hit.air.wounded`），回落链是这些维度前缀先逐段去尾（先变体、再武器族、再姿态），然后接上面的固定尾链；尾链本身不再带维度，通用键自己的姿态与变体细分由地面解析负责。不带任何维度的请求链与此前逐位一致。状态枚举不变（`jump`/`hit`/`attack` 不增不减），空中姿势只是同一状态的子键；链的末端恒作为兜底。空中阶段由呈现层按竖直运动服务的状态派生（上升/下降/落地保持，落地保持是呈现常量、不进手感档案），纯呈现、不回写判定；没有竖直轴时阶段恒为空，请求与此前逐位一致。键存在则直接取到、键缺失则沿链回落，两类都有运行期用例。
10. **M4-D 三期——空中键、细节键、带伤全覆盖、武器形体、不做根运动、过渡混合**。
   - **新键**。空中：`jump.rise`、`jump.fall`、`jump.land`、`hit.air`、`attack.air`（别名到 `attack.air.unarmed`）、`attack.air.<武器族>`（八族）；带伤：`move.sprint.wounded`、`move.sprint.combat.wounded`（别名）、`move.walk.combat.wounded`、`move.run.combat.wounded`、`move.start.wounded`、`move.stop.wounded`、`move.pivot.wounded`，使带伤变体覆盖全部移动与战斗移动键；细节：`hit.block`、`hit.block.shield`（格挡受击抖动）、`stunned.sway`（眩晕摇晃，循环）、`hit.launch.tumble`（击飞翻滚）、`hit.launch.land`（落地缓冲，末姿势与 `hit.getup` 起姿势相同）。空中攻击不带离地量，也不带连招窗口与闪避取消窗口（空中不连段）。
   - **回落链（契约）**。`jump.rise`、`jump.fall` 回落到 `jump`，再回落到 `idle`；`jump.land` 回落到 `idle`；`hit.air` 回落到 `hit.launch`，再回落到 `hit`；`attack.air[.<族>]` 回落到 `attack.air`，再到 `attack[.<族>]`。现状（M4-W5 核对）：核心的通用键回落（`PoseRequest.Chain`，逐段去末段）只用于地面请求与清单检查；空中请求由 `AirPoseRequest` 的固定尾链构造（第 9 条的链，`hit.air` 经 `hit.launch` 再到 `hit`，`jump` 之后落到 `idle`），呈现层的姿势选择器、动画剪辑解析器与引擎适配层的剪辑解析器对全部空中键都走这条链；运行期用例（核心的姿势维度测试）对 `std_dummy_biped` 与 `std_dummy_biped_model` 两套姿势集枚举全部空中请求，键存在则深度 0 直接取到、逐个移除键则按链回落，并断言通用去末段链与固定尾链确有差异（`hit.air` 的通用链直接得到 `hit`，固定尾链得到 `hit.launch`），证明没有路径误用通用链。
   - **不做布娃娃**。位移由逻辑驱动（ADR-0116），击飞翻滚与落地缓冲都是关键帧动画，骨骼不参与物理模拟；翻滚时整个身体绕骨盆翻转、全程不穿过地面。
   - **没有根运动**。单位的位移只由逻辑层给出（每步位移是姿势集的运行期参数，ADR-0116），动画不携带根骨位移曲线、不反向驱动单位位置；标准骨骼的根骨与骨盆除步幅与击飞需要的高度起伏外保持原地。理由：位移权威在逻辑，根运动让模拟结果依赖表现帧率与引擎动画求值，无头回放、指纹基线与重放都无法覆盖，也会让同一姿势集在不同地形、不同速度下行为不一致。曾设想的 `root_motion` 驱动与适配层能力 `supportsRootMotion` 已删除（ADR-0147）；美术带位移的动画走导入期烘焙：把剪辑根位移曲线抄写成 `skill.motion_curve` 行，动作位移引用它（02 第 4 节）。
   - **武器形体**。五个新武器族（`polearm`、`bow`、`staff`、`dual`、`shield`）由程序化低多边形凸块拼成（长柄带枪头、弓带弓身与弓弦、法杖带杖头宝珠、双持两把短刃、盾为多边形盾面带盾边），序列帧版的武器层与合成图同步；它们仍是占位，装备美术可按 ADR-0100 覆盖。因此这五个族既有键的武器层与合成图字节有变，身体层、元数据与全部骨骼剪辑字节不变。骨骼版没有武器几何（武器是挂在挂点上的装备），所以没有骨骼版的武器形体工作。
   - **施法释放点与实验室命中标记（M4-W5 判定）**。引擎宿主实测动画命中点比逻辑命中标记晚 150 毫秒，根因在数据：`cast` 剪辑的 `release` 在 250 毫秒，而实验室技能的命中标记多在 150 毫秒（少数 100 毫秒、精英重击 300 毫秒）。判定改 `cast` 剪辑而不改技能时间线：总时长 600 毫秒与帧数 12 不变，windup/release/recovery 由 250/100/250 改为 150/100/350（`release` 落在 150 毫秒），因为技能时间线是手感基线的输入、改动要连带重写基线，而 `cast` 剪辑只被表现层读。结果：起手 150 毫秒的技能动画命中点与逻辑命中标记逐毫秒相等；起手 100 毫秒与 300 毫秒的技能（M4-W6）由施放点变体对齐：可选键 `cast.quick`（`release` 100 毫秒）与 `cast.heavy`（`release` 300 毫秒），总时长与帧数同 `cast`，两版与体量组同键同事件；游戏用武器风格的施法动画覆盖（技能 id 到剪辑资源引用）把技能指到变体，回退链为 `cast.<变体>` 到 `cast`，没有声明覆盖的游戏不变。结果：每个实验室技能的命中标记都等于它所播放施放剪辑的 `release` 时刻，不再有残余偏差。宿主侧的命中配对逻辑不在本条范围；模型位面的事件在下一次动画求值时派发，命中时刻施放者已被顿帧冻结，所以模型位面滞后 = 一帧量化 + 施放者这次命中的顿帧时长，这是引擎侧冻结语义而不是数据偏差。
   - **过渡混合**。`display.anim_set` 加法字段：每个剪辑条目可选 `blend_ms`（切入本剪辑的交叉淡入毫秒，0 到 2000，缺省 = 调用方默认 0.15 秒，显式 0 = 硬切），行级可选 `blends`（`[{from, to, blend_ms}]`，键为本行剪辑键，每对键声明）。优先级：每对键 > 目标剪辑逐键 > 默认。有 `extends` 时沿链合并：子集覆盖同名键而没有写 `blend_ms` 则沿用被覆盖键的值，子集同一对键的 `blends` 覆盖父集；体量组不重复声明。只对 `model` 型骨骼剪辑生效（序列帧播放器不做交叉淡入）；角色外壳在切换剪辑时按它取值，不挂数据时与此前一致。假人姿势集按状态给出逐键值（待机 120、移动 100、受击 30、格挡 80 等）与 22 对每对键值（如 `jump.land` 到 `idle` 160、`hit.getup` 到 `idle` 180）。控制器仍由生成脚本确定性写出，重复生成逐字节一致、元数据标识不变，过渡时长不进控制器，由运行期取值。**判定：控制器的状态之间不连线**——过渡时长是可数据声明、按每对键覆写、沿 `extends` 继承的运行期参数，写进控制器就成了第二份会漂移的真源；连线数量随状态数平方增长（128 键乘体量组），确定性生成与字节稳定的成本远高于收益；完成事件靠每个状态预置的中继行为，不依赖过渡。
