## 1. 边界

- 框架不出任何具体游戏画风的最终美术（硬性规则）。框架出的是：姿势模型与解析规则、标准姿势清单与动作规格、标准人形骨骼上的姿势剪辑库（`model` 型）、中性假人姿势集（`sprite` 型）、导入校验与完整性报告。
- 姿势属于呈现型。姿势解析只读逻辑层的只读状态（动作相位、速度、姿态、武器族），永远不反向影响判定。判定型需要的剪辑时间信息（分相、命中标记）在作者态经导入工具抄写进 `skill.def.timeline`（01 第 3.2 节），运行期规则层不读表现域。
- 资源许可与来源由游戏层负责，导入不假定任意动画可互换。

## 2. 姿势维度模型

现状是七个状态键加两个补丁（`combat_` 前缀表示战斗姿态，武器表现档案覆盖攻击/施法剪辑），走路与跑步没有区分。本节把补丁收成正交维度：

| 维度 | 取值 | 决定者 |
|---|---|---|
| 状态 | `idle / move / attack / cast / hit / death / jump`（既有 `AnimState`，不增不减） | 动画状态机（09 第 4.2 节） |
| 步态 | `walk / run / sprint`（仅 `move` 状态） | 表现层按速度比例派生（02 第 7 节） |
| 姿态 | `peace / combat` | `combat.entered/left`（ADR-0111） |
| 武器族 | `unarmed / 1h / 2h / polearm / bow / staff / dual / shield …`（自由集合，`feel.weapon.family` 声明） | 主手武器解析（既有"实体 → 武器风格引用"链路） |
| 变体 | `wounded / carrying / mounted …`（游戏层自由扩展） | 游戏层声明的只读探针 |

性别与体型**不是维度**，是整套姿势集的选择（第 7 节）：一套姿势集就是一个身体原型的全部姿势，解析只在一套集内进行。

### 2.1 剪辑键语法

```
<state>[.<gait>][.<stance>][.<family>][.<variant>]      维度按此固定顺序拼接，缺省维度省略
例：move.run.combat.2h    idle.combat    hit.heavy    attack.2h    move.walk.wounded
```

既有键的兼容：`combat_<state>` 恒等于 `<state>.combat`（单处定义的别名，`AnimSetDef` 内），旧数据不改；无维度的 `<state>` 是基础键。

### 2.2 回落链

请求键找不到时按固定顺序逐个去掉维度，直到基础键：

```
去变体 → 去武器族 → 去姿态 → 去步态 → 基础键
move.run.combat.2h.wounded → move.run.combat.2h → move.run.combat → move.run → move
```

理由：跑步时缺武器族剪辑，播一条没拿武器的跑步比播一条拿武器的走路更不违和（后者脚会打滑）；变体最次要。武器表现档案的攻击/施法覆盖剪辑与技能覆盖剪辑优先级仍最高（既有规则），因此武器族维度主要服务运动态、待机与受击。

`hit` 状态按裁决结果加后缀：`hit.light / hit.heavy / hit.knockback / hit.knockdown / hit.getup`，回落到 `hit`。`attack` 的连招段由技能覆盖剪辑指定（`attack.2h.02`），不占维度。

### 2.3 解析时机与就绪

与 ADR-0111 同一出口：运动态（`idle/move`）维度变化即时切换并从头播，解析结果与正在播的相同则不动；瞬态（`attack/cast/hit/jump`）不被维度变化打断，回落时按当时维度解析；`death` 不受影响。变体剪辑未加载完成时维持当前显示，就绪后经同一出口补切；换向重探测、换装重探测走既有键表机制，键表由回落链展开（外形实际声明的全部键）。

## 3. 标准姿势清单

按维度组合展开后约五十个键；框架预置的每套姿势集按下表覆盖：

| 层级 | 键 | 说明 |
|---|---|---|
| 必备 | `idle`、`move.walk`、`move.run`、`attack`（每个武器族一段）、`hit`、`death` | 缺任一项数据校验为错误，姿势集不能发布 |
| 推荐 | `idle.combat`、`move.run.combat`、`attack` 二三段、`hit.heavy`、`hit.knockback`、`hit.knockdown`、`hit.getup`、`cast`、`dodge`（作为 `attack` 的技能覆盖剪辑）、`jump`、空中键 `jump.rise`/`jump.fall`/`jump.land`/`hit.air`/`attack.air[.<族>]`（见第 10 节第 9 条） | 缺项为警告并进完整性报告；运行期按回落链兜底 |
| 可选 | `move.sprint`、`move.walk.combat`、启停过渡（`move.start`/`move.stop`/`move.pivot`，作为过渡剪辑）、`hit.launch`、`stunned`、`block`、`wounded` 变体 | 缺项静默回落 |

启停过渡剪辑不是状态：表现层在步态从 `idle` 到 `run`、`run` 到 `idle`、方向反转时若存在过渡剪辑则先播过渡再进循环，不存在则用 `start_blend_ms`/`stop_blend_ms` 混合。

## 4. 动作规格

每个姿势键一份规格，随 14 资产规格书模板发布，是美术交付验收标准，也是手感相对量（分相比例、步幅）的依据：

| 规格项 | 内容 |
|---|---|
| 循环 | 是否循环；循环剪辑首尾帧姿势连续 |
| 关键姿势 | 走/跑：接触、下沉、经过、抬起各一次（每条腿）；攻击：预备、接触、收势；受击：冲击、恢复 |
| 参考时长与帧数 | 以标定帧率给出参考值（如走 1000 ms、跑 600 ms、轻攻击 450 ms） |
| 每循环位移 | 走/跑剪辑每个循环对应的身高倍数位移（决定播放速率匹配与脚步节奏，02 第 7 节） |
| 时间标记 | 第 5 节要求的标记与其参考位置 |
| 方向档 | `sprite` 型需覆盖的方向档位（09 第 3.2 节） |
| 锚点 | 角色中心、地面点、武器/施法点、命中点、脚点（挂点语义沿 09 第 3.3 节） |
| 元数据 | 时长、朝向、适用运动模式、资源比例（像素密度或骨骼比例） |

## 5. 时间标记

| 标记 | 剪辑内 | 归属 | 说明 |
|---|---|---|---|
| `active_start` / `active_end` | 攻击类 | 判定（经导入抄入 timeline） | 判定相 |
| `hit` | 攻击类 | 判定 | 命中点，可多个带 `segment` |
| `combo_open` / `combo_close` | 攻击类 | 判定 | 连招窗口 |
| `cancel_open:<class>` | 攻击/施法类 | 判定 | 取消窗口 |
| `invuln_start` / `invuln_end` | 闪避类 | 判定 | 无敌窗口 |
| `motion_start` / `motion_end` | 突进/闪避类 | 判定 | 动作位移 |
| `release` | 远程/施法类 | 判定 | 投射物发射 |
| `footstep` | 走/跑 | 表现 | 脚触地（音效、扬尘） |
| `trail_start` / `trail_end` | 攻击类 | 表现 | 拖尾 |
| `fx:<id>` | 任意 | 表现 | 特效挂点触发 |
| `impact` | 受击类 | 表现 | 受击冲击帧（闪白对齐） |

**唯一权威**：`skill.def.timeline.source` 决定判定类标记的作者态权威（01 第 3.2 节）；运行期规则层只读 `timeline`，表现层只读剪辑。同一事件不由两处触发。动画加速或减速时表现层的播放速率与判定时间线用同一系数（01 第 3.5 节），跨帧标记按区间遍历，不重复触发回调，不因重复播放音效或回调造成多次伤害。

顿帧冻结哪些层（骨骼/序列帧必冻，粒子与拖尾按反馈包声明）见 07。

## 6. 标准资产

### 6.1 标准人形骨骼与剪辑库（`model` 型）

- 框架定义一套标准人形骨骼（骨名、层级、单位比例、前向轴、根骨约定、根运动轨迹约定），随版本发布。
- 标准姿势清单的每个键在该骨骼上各有一版剪辑，按身体原型出若干组（轻/中/重体量 × 短/中/长步幅，第 7 节），每组即一套姿势集。
- 使用标准骨骼的游戏换蒙皮即拥有全部姿势；自有骨骼做一次重定向，重定向结果仍按第 8 节校验。
- 剪辑库自带全部时间标记，且经手感实验室验证（06），随成熟度标签发布。

### 6.2 假人姿势集（`sprite` 型）

- 序列帧美术无法重定向，框架提供中性像素密度的假人（剪影或块状人偶）序列帧，覆盖标准姿势清单全部必备与推荐键、全部方向档，时间标记齐全。
- 用途：新游戏第一天就用假人跑手感、跑测试；美术后来按规格逐键替换；手感实验室的指纹基线全部在假人集上采集，因此与美术无关（06 第 5 节）。
- 后续项（不进第一版）：把标准骨骼加蒙皮预渲染成序列帧，让 `sprite` 型游戏做一套蒙皮自动得到全部姿势与方向档。

### 6.3 交付形态

姿势集是 `display.anim_set` 的一行加对应资源；框架级姿势集放在框架级数据目录，id 以 `display.anim_set.std_` 开头，随版本发布并受不可变发布规则约束。

## 7. 姿势集的继承、覆盖与角色差异

- `display.anim_set` 新增可选字段 `extends: Id`：只声明要覆盖的键，未声明的键沿用模板；链无环，深度不限；解析时先合并再走回落链。
- 角色定义引用：单位模板 `display.map.anim_set_ref`（既有）指向自己的姿势集；`feel_ref`（05）指向手感角色层。性别与种族在游戏层的数据里映射为"选哪套姿势集 + 选哪个体型原型"，框架不认识性别。
- 同一性别可以有不同重量与敏捷（选不同体型原型），不同性别可以选同一套姿势集。怪物复用同一语义系统；巨型、四足、飞行角色需要自己的姿势集与运动能力声明（骨骼不同，标准清单里的键名照用）。
- 武器表现档案（09 第 4.4 节）继续决定攻击/施法覆盖剪辑与特效变体；本节的武器族维度补齐运动态与待机的武器差异。

## 8. 导入校验与完整性报告

导入工具（框架交付物，ADR-0014）对每套姿势集检查：

| 检查 | 级别 |
|---|---|
| 必备键齐全 | 错误 |
| 攻击类剪辑有 `active_start/active_end` 与至少一个 `hit`；走/跑剪辑有 `footstep`；闪避类有无敌窗口标记 | 错误 |
| 循环标志与规格一致；循环剪辑首尾连续 | 错误 |
| 剪辑标记与 `skill.def.timeline`（`source: clip` 时）一致 / （`source: data` 时）偏差在容差内 | 错误 / 警告 |
| 每循环位移、时长在规格参考值的容差内 | 警告 |
| `model` 型：单位、比例、前向轴、骨架兼容、根运动轨迹、武器锚点 | 错误 |
| `sprite` 型：原点、方向档数、帧时长、碰撞轮廓、层级排序 | 错误 |
| 推荐键缺项 | 警告，写入完整性报告并指出回落到哪个键 |

缺必备键拒绝发布；可选启停过渡缺失回退为混合并在报告中显示。报告是校验输出，不入库。

## 9. 姿势与手感的对齐（测试）

这一层保证"改了动画帧数手感就变了"在提交前暴露：

1. 剪辑长度 × `timeline` 分相比例得到的三相时长落在手感原型声明的范围内（05 第 6 节预设自带范围）。
2. `hit` 标记落在判定相内；`invuln` 窗口不超出剪辑。
3. 走/跑剪辑 `footstep` 间隔换算的位移等于规格的每循环位移除以步数，且与 `display.map.stride_distance`（ADR-0078）一致。
4. 回落链：枚举全部维度组合，解析出的键与预期链一致；只要基础键存在任何组合都能解析。
5. 姿势集继承：`extends` 合并后完整性报告与手写等价集一致。
6. 引擎宿主：每套姿势集出一张缩略拼图（每键一格）供人眼审，只留本地。

## 10. 首版落地勘误（2026-10-02）

第 6.1 节 `model` 型标准骨骼与骨骼剪辑库首版落地后，实现与前述结构的差异如下；结论不变，以下为勘误：

1. **勘误：落地范围**。框架级骨骼剪辑库提供一套标准人形骨骼的占位模型资源（`model.std_dummy_biped`：骨盆、躯干、头、双臂、双腿共十七根骨骼，主手与副手挂点 `socket.main_hand`、`socket.off_hand`，头部块体名 `slot.head`，方块可视件，不带蒙皮）与一套姿势集 `display.anim_set.std_dummy_biped_model`，覆盖第 3 节全部必备、推荐与可选键：八个武器族（徒手、`1h`、`2h`、`polearm`、`bow`、`staff`、`dual`、`shield`）的待机、移动、冲刺、攻击与格挡，以及 `move.sprint`、启停过渡 `move.start`／`move.stop`／`move.pivot`、`hit.launch`、`stunned`、`block`、`wounded` 变体与受击后缀键（手感落地 M3-D 时共 103 个键；M4-D 追加 25 个键后共 128 个键、117 份独立剪辑，其余 11 个键是指向同一剪辑的别名，例如战斗站姿的冲刺别名到无站姿的冲刺；因为键回落链是先去变体、再去武器族、再去站姿、最后去步态，冲刺键找不到才退回奔跑，所以每个族的冲刺键都必须登记）。序列帧版与骨骼版同一份键清单、同一组姿势函数。第 6.1 节"轻/中/重体量 × 短/中/长步幅"的判定见本节第 7 条；标准骨骼的比例、前向轴、骨骼局部旋转约定写在生成规格的参数里，不随引擎资产分散。
2. **勘误：与序列帧版同源**。键清单、时长、三相毫秒数、帧数规则、命名事件（第 5 节）与每步位移全部取自序列帧版同一份配置，姿势取自同一组姿势函数，逐键逐帧同源；骨骼剪辑的关键帧取在序列帧版的帧边界上（含终点，关键帧数为帧数加一），相边界与三相毫秒数精确对齐。试调起点（05 第 9 节单手 110/80/190 毫秒、双手 170/100/290 毫秒）因此两版一致。
3. **勘误：动作质量与关节角限**。占位级动作：待机呼吸、走与跑的左右交替摆臂迈步、攻击前摇—命中—收招三相、受击后仰。肘与膝是单轴铰链，取样时夹在 0 到 150 度之间，不出现反向过伸（序列帧版的受击与倒地姿势在二维剪影上允许的负肘角，骨骼上会成为手臂反折，故只在骨骼版夹紧）；肩、髋、躯干、头的上下限按全部姿势的包络再留余量，自检对每个关键帧检查每根骨骼的局部旋转角不超限。已知限制：既有键 `hit.launch`、`hit.knockdown`、`hit.getup` 的后飞与倒地姿势仍用"腿绕髋整体后摆"表达躺平（骨盆没有俯仰自由度），肩、髋后伸下限因此比人体范围宽；原因是这些键已被下游引用、第 10 节第 8 条规定既有剪辑字节不变，只追加新键。新增的 `hit.launch.tumble`、`hit.launch.land` 给骨盆加了整体俯仰（只对这两个键放开髋的旋转上限，其余键髋的旋转仍夹在小范围内），翻滚时整个身体绕骨盆翻转、落地缓冲贴地。
4. **勘误：命中事件别名**。第 5 节的命中标记名是 `hit`，而 `model` 型角色外壳识别的命中帧事件名是 `hit_frame`（ADR-0017）。数据行只写第 5 节的名字（与序列帧版同源），骨骼剪辑内部在每个 `hit` 旁同时刻再放一条 `hit_frame` 别名事件，使命中帧同步在 `model` 型单位上落在第 5 节规定的时刻（判定相中点）；序列帧版也识别 `hit_frame`：两版的数据行都在每个攻击剪辑的事件表末尾追加一条与 `hit` 同时刻的 `hit_frame` 事件（既有事件的内容与顺序不变，只在末尾追加），序列帧播放器按事件时间百分比换算出关键帧下标并在播到该帧时触发一次；骨骼版烘进剪辑时，数据行已带同名同时刻事件则不再重复烘。弓的放箭点 `release` 同样与 `hit` 同时刻。
5. **勘误：带参标记的事件名换算**。带参标记（`cancel_open:dodge`、`fx:<id>`）的冒号后缀在引擎事件标识里换成点分段（`cancel_open.dodge`），因为标识格式不允许冒号；写错的、仍不合法的事件名静默丢弃，不打断动画播放。
6. **勘误：交付与校验**。生成物为一份规格文件（骨架、可视块体、逐剪辑关键帧与事件）、数据行，以及由规格经引擎侧生成脚本产出的模型资源、动画控制器与逐键剪辑资源；第 8 节"model 型"校验在工具链里落为只读一致性检查（规格与当前代码逐字节对账、缺键、缺事件、帧数与关键帧数、骨骼路径与模型资源骨骼层级、关节角限、用写出的旋转把关节摆回去与序列帧版关节位置对账、数据行与引擎资产一致），接入门禁。
7. **勘误：体量与步幅轴的判定（第 6.1 节）**。步幅是运行期参数——第 6.1 节的播放速率就是步幅的运行期表达（02 第 7 节），不为步幅出独立资产；体量差异只在站姿（躯干前倾、重心高低、四肢开合）与受击／腾空幅度上，不改时长、帧数、事件与每步位移。体量三档（轻、中、重）由数据声明：配置里一张体量表给出每档的关节角偏移与两个幅度系数（受击反应幅度、腾空高度，反应幅度有上限），中档就是主集，不叠加偏移；两版（骨骼版与序列帧版）都读同一张表。数据行：主集 `display.anim_set.std_dummy_biped_model`（序列帧版 `display.anim_set.std_dummy_biped`）加三个体量行 `…_medium`（空 `extends` 行，不声明任何键）、`…_light`、`…_heavy`，后两者用 `extends` 继承主集且**覆盖主集的全部键**（含别名），每个键指向体量组自己的剪辑，键清单永远与主集一致，不会出现某个键只有主集版本。受击反应幅度系数的上限防止轻体量把受击后仰放大到穿帮；腾空高度系数只作用于跳跃与击飞的离地量。装备集占位剪辑只跟主集走（装备美术覆盖是按主集键对位的占位，见 ADR-0100）。资产体量：序列帧版每个体量组只写正面合成图与全部槽位的身体层、武器层剪辑，不写按方向拆分的整身方向变体（ADR-0093），这是显式的体积取舍：声明了纸娃娃层的外形用分层剪辑，不受影响；用整身剪辑的外形在体量组下不随朝向换图（只有正面一张），要按方向换图须回到主集或用分层外形；M4-D 追加的序列帧资源新增文件合计约 16.6 MB（轻体量组约 6.6 MB、重体量组约 6.9 MB、新键约 1.8 MB、装备集派生约 1.2 MB），既有五个族的武器层与合成图原地改写体积变化约 0.2 MB，未超过 20 MB 的上限。
8. **勘误：确定性生成与门禁**。骨骼版的动画控制器由生成脚本直接按固定格式写出：状态与过渡的标识由状态名按固定散列公式给出，控制器的元数据标识沿用既有值；因此重复生成两次逐字节一致，且既有剪辑资源与模型资源字节不变（新键只追加；唯一的例外是五个新武器族的武器层与合成图，见第 9 条）。序列帧版的一致性检查同样接入门禁（与骨骼版检查并列，缺图像库时按快速档跳过）。装备集由全部假人剪辑派生，新增键与族自动级联，`block` 并入装备集需要派生的族状态。
9. **勘误：空中姿势键（手感落地 M4-V，[ADR-0130](../adr/0130-竖直轴能力包.md) 追加决定）**。竖直轴能力包装配后，姿势请求在空中有固定键与固定回落链：`jump.rise`/`jump.fall` → `jump` → `idle`；`jump.land` → `idle`；`hit.air` → `hit.launch` → `hit`；`attack.air.<族>` → `attack.air` → `attack.<族>` → `attack`（无武器族时 `attack.air` → `attack`）。状态枚举不变（`jump`/`hit`/`attack` 不增不减），空中姿势只是同一状态的子键；空中键不带姿态、步态与变体维度；链的末端恒作为兜底。空中阶段由呈现层按竖直运动服务的状态派生（上升/下降/落地保持，落地保持是呈现常量、不进手感档案），纯呈现、不回写判定；没有竖直轴时阶段恒为空，请求与此前逐位一致。键存在则直接取到、键缺失则沿链回落，两类都有运行期用例。
10. **勘误：M4-D 三期——空中键、细节键、带伤全覆盖、武器形体、不做根运动、过渡混合**。
   - **新键（25 个，总数 128）**。空中：`jump.rise`、`jump.fall`、`jump.land`、`hit.air`、`attack.air`（别名到 `attack.air.unarmed`）、`attack.air.<武器族>`（八族）；带伤：`move.sprint.wounded`、`move.sprint.combat.wounded`（别名）、`move.walk.combat.wounded`、`move.run.combat.wounded`、`move.start.wounded`、`move.stop.wounded`、`move.pivot.wounded`，使带伤变体覆盖全部移动与战斗移动键；细节：`hit.block`、`hit.block.shield`（格挡受击抖动）、`stunned.sway`（眩晕摇晃，循环）、`hit.launch.tumble`（击飞翻滚）、`hit.launch.land`（落地缓冲，末姿势与 `hit.getup` 起姿势相同）。空中攻击不带离地量，也不带连招窗口与闪避取消窗口（空中不连段）。
   - **回落链（契约）**。`jump.rise`、`jump.fall` 回落到 `jump`，再回落到 `idle`；`jump.land` 回落到 `idle`；`hit.air` 回落到 `hit.launch`，再回落到 `hit`；`attack.air[.<族>]` 回落到 `attack[.<族>]`。已知限制：核心的键回落链实现（`PoseRequest.Chain`）是通用的"逐段去末段"，因此 `hit.air` 目前回落到 `hit` 而不经 `hit.launch`，`jump` 之后没有再落到 `idle` 的一步；本切片只交付资产与数据行，请求构造与回落链接线归垂直轴（M4-V）切片，故未改核心。
   - **不做布娃娃**。位移由逻辑驱动（ADR-0116），击飞翻滚与落地缓冲都是关键帧动画，骨骼不参与物理模拟；翻滚时整个身体绕骨盆翻转、全程不穿过地面。
   - **不做根运动（判定）**。单位的位移只由逻辑层给出（每步位移是姿势集的运行期参数，ADR-0116），动画不携带根骨位移曲线、不反向驱动单位位置；标准骨骼的根骨与骨盆除步幅与击飞需要的高度起伏外保持原地。理由：位移权威在逻辑，根运动会让表现层与逻辑层各有一份位移而漂移，也会让同一姿势集在不同地形、不同速度下行为不一致。第 6.1 节与第 8 节提到的"根运动轨迹约定"就是这条判定：标准骨骼不携带根运动轨迹。此前登记的已知限制"无根运动"随之删除。
   - **武器形体**。五个新武器族（`polearm`、`bow`、`staff`、`dual`、`shield`）由程序化低多边形凸块拼成（长柄带枪头、弓带弓身与弓弦、法杖带杖头宝珠、双持两把短刃、盾为多边形盾面带盾边），序列帧版的武器层与合成图同步；它们仍是占位，装备美术可按 ADR-0100 覆盖。因此这五个族既有键的武器层与合成图字节有变，身体层、元数据与全部骨骼剪辑字节不变。骨骼版没有武器几何（武器是挂在挂点上的装备），所以没有骨骼版的武器形体工作。
   - **过渡混合**。`display.anim_set` 加法字段：每个剪辑条目可选 `blend_ms`（切入本剪辑的交叉淡入毫秒，0 到 2000，缺省 = 调用方默认 0.15 秒，显式 0 = 硬切），行级可选 `blends`（`[{from, to, blend_ms}]`，键为本行剪辑键，每对键声明）。优先级：每对键 > 目标剪辑逐键 > 默认。有 `extends` 时沿链合并：子集覆盖同名键而没有写 `blend_ms` 则沿用被覆盖键的值，子集同一对键的 `blends` 覆盖父集；体量组不重复声明。只对 `model` 型骨骼剪辑生效（序列帧播放器不做交叉淡入）；角色外壳在切换剪辑时按它取值，不挂数据时与此前一致。假人姿势集按状态给出逐键值（待机 120、移动 100、受击 30、格挡 80 等）与 22 对每对键值（如 `jump.land` 到 `idle` 160、`hit.getup` 到 `idle` 180）。控制器仍由生成脚本确定性写出，重复生成逐字节一致、元数据标识不变，过渡时长不进控制器，由运行期取值。
