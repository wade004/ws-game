## 1. 原则

- 档案是配置，不执行逻辑。运行期消费的是解析后的不可变手感表（ResolvedFeel），每个字段可查来源。
- 不按"男/女/某角色"存数值，按物理原型存；标签（性别、种族、职业）在游戏层映射到原型。
- 数值尽量用相对量（00 第 6 节），由标定表换算，使原型库跨游戏迁移。
- 判定型字段只放在逻辑层可读的表，呈现型字段只放表现层表；一张 `feel.*` 表内两类字段可以并存，但读取方按半属过滤，规则层拿不到呈现型字段。

## 2. 数据域 `feel` 与表清单

新增数据域 `feel`（04 第 2.2 节域名清单走审批，本目录 ADR-0118 即审批记录）。

| 表 | 一行是什么 | 引用方 |
|---|---|---|
| `feel.preset` | 类型级基础档案（`rpg_classic`、`arpg_light`、`arpg_heavy` …），全字段齐全 | 标定表指定一款游戏的基础预设 |
| `feel.archetype` | 体型原型：体量（轻/中/重）、步幅（短/中/长）、敏捷（低/中/高）、攻击重量（轻/中/重）四个轴的组合，只写与基础预设的差异 | 单位模板 `feel_archetype_ref` |
| `feel.weapon` | 武器原型（轻近战、中近战、重近战、长柄、投射、法器 …）：`family`（04 武器族维度）、节奏、承诺、移动耦合、打击、`impact_class`、`auto_attack_timeline_ref` | 物品模板 `feel_weapon_ref`（与 `display.weapon_style` 分表同 id，规则层只读本表） |
| `feel.character` | 角色/怪物层覆盖，只写差异 | 单位模板 `feel_ref` |
| `feel.action` | 当前动作层覆盖，只写差异 | `skill.def.timeline.feel_ref` |
| `feel.calibration` | 标定：参考身高、基础移速、动画帧率、参考镜头高度/缩放、像素密度、标记容差 | 每款游戏一行，装配根指定 |
| `feel.motion_mode_rules` | 运动模式规则（02 第 3.1 节） | 移动系统 |
| `feel.tag_map` | 标签到原型/覆盖的映射（`gender:female → archetype.light_long`；游戏层内容，框架给结构） | 解析器第三层 |

表现侧配套表（不在 `feel` 域）：`feedback.impact_profile`（打击反馈包，07）、`camera_profile`（既有表扩展跟随字段，07）、`display.anim_set`（姿势集，04）。

## 3. 七个分组与覆盖顺序

### 3.1 分组

| 分组 | 半属 | 典型字段 | 详见 |
|---|---|---|---|
| 输入 | 判定 | `buffer_ms`、`buffer_slots`、`grace_ms`、轴处理 | 01 第 4 节 |
| 移动 | 判定为主 | `accel_ms`、`decel_ms`、`turn_rate_deg_s`、`walk_speed_ratio`、`action_move_speed_ratio`；步态阈值、`stride_scale`、启停混合为呈现 | 02 第 2/7 节 |
| 动作 | 判定 | `phase_scale.*`、`cancel_window_scale`、`combo_window_scale`、`turn_assist_deg`、`stop_distance` | 01 第 4 节 |
| 受击 | 判定 | `impact_class`、`attacker_hitstop_ms`、`target_hitstop_ms`、`hitstop_cap_ms`、`hit_stun_ms`、`stagger_power`、`knockback_distance`、`launch_height`（可选，体型倍数，缺省不击飞；只在竖直轴世界生效）、`poise_damage`（可选，缺省不走动态韧性）、`poise_recover_per_s`（可选，缺省不回复）、`poise_recover_delay_ms`（可选，缺省 0）、`poise_recover_mode`（可选，`delay`｜`out_of_combat`，缺省 `delay`）、`poise_break_reset_ms`（可选，缺省不重置）、`downed_ms`、`reaction_cap`、`kill_hitstop_scale` | 03 第 3/4 节 |
| 镜头 | 呈现 | 跟随、前瞻、死区、阻尼、战斗缩放、冲击增益与限频 | 07 第 2 节 |
| 特效 | 呈现 | `impact_profile_ref`（按 `impact_class` 与 `hitResult` 索引的反馈包引用表）、拖尾/残影开关 | 07 第 1 节 |
| 音频 | 呈现 | 挥空层、命中层、增味层强度档；脚步材质层；同时发声上限 | 07 第 3 节 |

### 3.2 覆盖顺序

固定八层，从粗到细：

```
1 基础预设 feel.preset（标定表指定）
2 体型原型 feel.archetype（单位模板）
3 标签映射 feel.tag_map（游戏层：性别/种族/职业 → 原型或覆盖）
4 武器 feel.weapon（主手；副手只叠加打击层，见 3.4 节）
5 角色 feel.character（单位模板 feel_ref）
6 当前动作 feel.action（进行中动作的 feel_ref；动作结束即撤）
7 临时状态（光环携带的手感修饰，第 5 节）
8 调试覆盖（实验室热调参，仅开发期，06）
```

### 3.3 操作语义

每层对每个字段只能做一种操作：`set`（替换）、`multiply`（乘）、`add`（加）。规则：

- 字段登记声明允许的操作集合；布尔与引用只允许 `set`。
- 同一层内同一字段被写两次为校验错误（不允许"后写覆盖前写"的隐式规则）。
- 计算顺序：按层号从低到高逐层应用，同层内先 `set`、再 `multiply`、再 `add`；全部应用后按登记的范围限幅并记录被限幅的事实。
- 列表字段缺省整体替换；删除元素用显式 `remove`，不用空值暗示删除。
- 预设依赖（`extends`）必须无环；`feel.preset` 不允许 `extends` 以外的引用。

### 3.4 合成来源

字段登记的"合成来源"决定第 2 层（角色侧）与第 4 层（武器）谁是主：

| 合成来源 | 规则 | 典型字段 |
|---|---|---|
| 角色为主 | 武器层不写该字段（写了为错误） | 加减速、转向、步幅、`hit_stun_ms`（受击方）、脚步音效层 |
| 武器为主 | 体型层只允许 `multiply` | 分相倍率、取消窗口、`impact_class`、顿帧、击退、命中/挥空音效层 |
| 攻击期间武器临时覆盖 | 武器层的值只在 `action` 模式下生效，动作结束自动撤回 | `action_move_speed_ratio`、`action_turn_lock` |

副手武器：只允许写"武器为主"分组里标记为 `offhand_stackable` 的字段（打击层的音效增味、特效），以 `add`/`multiply` 叠加；节奏与承诺永远取主手。双持作为一个武器族（`dual`）由主手武器原型声明。

## 4. 字段登记元数据

沿用 04 第 3.2～3.6 节的机器可读登记，手感字段新增四项元数据（00 第 4 节）：`half`（`judging|presenting`）、`group`、`ops`（允许操作）、`composition`（合成来源），外加 `unit`（00 第 6 节单位枚举）与 `offhand_stackable`。校验器新增检查：

| 检查 | 级别 |
|---|---|
| 操作不在 `ops` 内 | 错误 |
| 违反合成来源（武器层写了角色为主字段等） | 错误 |
| 同层重复写 | 错误 |
| 相对量字段的值超出登记范围（标定前） | 错误 |
| `extends` 成环 | 错误 |
| 预设缺字段（`feel.preset` 必须全字段） | 错误 |
| 判定型字段出现在 `display.*`/`feedback.*` 表 | 错误 |
| 标定表缺项 | 错误（阻断装配） |

## 5. 解析器

```
interface FeelResolver {
  resolve(unitId: Id): ResolvedFeel                  // 缓存命中直接返回
  invalidate(unitId: Id, reason: String): void        // 装备/变身/光环/动作开始结束/标签变化事件驱动
  provenance(unitId: Id, field: String): List<{layer: Int, sourceId: Id, op: String, valueBefore, valueAfter}>
  version(unitId: Id): Int                            // 每次重算递增，供消费者判断是否需要重读
}

struct ResolvedFeel {
  fields: Map<String, Value>      // 标定后的绝对值；判定型时间字段同时给 ticks
  raw: Map<String, Value>         // 标定前的相对值
  clampedFields: List<String>
  version: Int
}
```

- 纯函数：输入只有数据表与实体的只读状态（体型引用、标签、主/副手武器、当前动作、临时状态列表、调试覆盖），不读时钟、不读随机。
- 失效事件：装备变化（既有事件）、外形变化、`aura.applied/removed`（仅携带手感修饰的光环）、`action.started/finished/cancelled`（仅当动作有 `feel_ref` 或武器有攻击期间临时覆盖）、标签变化（游戏层事件）、调试覆盖变化。失效后下一次 `resolve` 重算。
- 时间线技能在 `action.started` 时快照一份手感表挂在施法实例上：动作进行中重算不改变正在进行的动作（热加载在安全的动作边界应用，第 8 节）。
- 判定型消费者只经 `resolve` 读判定型字段；呈现型消费者只读呈现型字段；登记表驱动的访问器按半属生成两套只读视图，防止越界读取。

## 6. 临时状态

- 光环定义新增可选 `feel_modifiers: List<{field, op, value}>`，作为第 7 层条目，以光环实例 id 为键。光环移除即删除该条目并失效重算，**不是**做反向乘法恢复（避免叠加误差）。
- 规则：字段若已是属性（移动速度、急速），走属性系统，不允许用 `feel_modifiers` 重复表达（校验错误）；`feel_modifiers` 只用于没有对应属性的手感字段。
- 控制效果（定身、硬直）不经本机制，它们改变运动模式（02）。

## 7. 标定、能力声明与降级

- 标定表缺失时装配失败，不用隐式缺省。标定值进入指纹元数据（06）。
- 适配层能力声明（02 引擎适配层的契约风格）：`supportsSweep`、`supportsRootMotion`、`supportsFootIK`、`supportsCameraImpulse`。加载预设或姿势集时校验：**必需能力**缺失直接报错（如预设里有 `root_motion` 驱动的动作而适配层不支持）；**可选能力**缺失按预设声明的降级项退化（无扫掠用子步采样、无足部 IK 用标准步态、无镜头冲击用震屏），并写进诊断；不能静默丢失关键命中或移动能力。
- 预设跨维度：相同"重"风格可以跨 `sprite`/`model` 表达同一意图，不保证复制相同数值得到相同感知；每个成熟预设都绑定它验证过的外形类型与适配组合。

## 8. 版本、成熟度与热加载

- 每个预设/原型行携带 `schema_version`、`profile_version`、`requires`（依赖的姿势集版本、反馈包版本、适配能力）、`units`（单位约定版本）。发布的游戏固定依赖版本；迁移旧字段必须有显式转换与变更说明（沿 ADR-0029/0039）。
- 成熟度标签 `maturity: experimental | validated`：`validated` 的条件是绑定了适配器组合、姿势集、实验室脚本与设备条件，且 06 第 6 节的客观检查全绿、评分表有达标记录。未经试玩的配置一律 `experimental`；占位资源上的体验不得标 `validated`。
- 热加载（开发期 `reload`）：解析器失效重算，但正在进行的动作沿用其开始时的快照（第 5 节）；`hit_policy` 与形状引用在一次挥击内不会前后不一致。运动档案的变化在下一 tick 生效（速度状态保留）。
- 标定行同样热换：新数据里标定行取值变化时，档案与新标定一并换入（结果标注标定已变，但不要求重启）；此后每次解析与下一个动作的开始快照按新标定换算（相对量 → 绝对量、基础预设选择），进行中的动作沿用其开始时的快照。毫秒到 tick 只取决于模拟步长，不随标定变化；新标定指定的基础预设不存在时整次热加载拒绝，保持当前档案与标定。使用标定的表现侧消费方（镜头冲击、命中反馈的参考高度）读实时标定，不在装配时固化。

## 9. 框架预置原型库（首期范围）

首期只收录能在实验室被验证的最小集合，不预先堆满：

| 类别 | 首期内容 |
|---|---|
| 基础预设 | `arpg_responsive`（响应型动作，缺省）、`rpg_classic`（目标选择式、无缓冲取消，等价既有行为） |
| 体型原型 | 轻/中/重体量 × 中步幅 × 中敏捷 三组，其余轴留字段与范围 |
| 武器原型 | 轻近战（单手剑）、重近战（巨剑）两套；长柄、投射、法器给结构与试调起点、标 `experimental` |
| 姿势集 | 标准骨骼三组（对应三体量）、假人集一组 |
| 反馈包 | `light/medium/heavy/massive` 四档 × 命中/回避 |
| 镜头档案 | 响应型跟随一套 |

试调起点（单手剑 / 巨剑，俯视近战原型，不是已验证值）：三相 110/80/190 与 170/100/290 ms；缓冲 120 ms；攻击方顿帧 35/65 ms；受击方顿帧 45/75 ms；硬直 150/230 ms；突进 0.2/0.3 身高；击退 0.15/0.3 身高；闪避取消从动作进度 0.65/0.75 开始。这些数进入 `experimental` 预设行，由实验室试玩后决定是否升为 `validated`。

## 10. 测试与验收

1. 解析器性质测试（字段登记自动枚举）：任意原型 × 武器 × 标签组合解析成功；所有字段落在登记范围内；重复解析结果不变；溯源链每字段至少一条且最后一条的 `valueAfter` 等于结果。
2. 操作语义：同层重复写被校验拒绝；`set→multiply→add` 顺序结果等于手算；限幅事实被记录。
3. 合成来源：武器层写角色为主字段被拒绝；攻击期间临时覆盖在 `action.finished` 后撤回。
4. 临时状态：光环施加/移除后字段值恢复到施加前的精确值（非反向乘法）。
5. 快照：动作进行中热加载不改变该动作的分相与形状，下一次动作生效。
6. 能力校验：必需能力缺失装配报错；可选能力缺失诊断里出现降级记录。
7. 标定：同一相对值在两组标定下换算出的绝对值等于公式值；判定型时间字段的 tick 换算四舍五入且非零至少 1。
8. 半属隔离：静态检查规则层程序集没有任何呈现型字段的读取点，表现层程序集没有判定型字段的读取点。
