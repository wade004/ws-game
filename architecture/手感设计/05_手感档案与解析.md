## 1. 原则

- 档案是配置，不执行逻辑。运行期消费的是解析后的不可变手感表（ResolvedFeel），每个字段可查来源。
- 不按"男/女/某角色"存数值，按物理原型存；标签（性别、种族、职业）在游戏层映射到原型。
- 数值尽量用相对量（00 第 6 节），由标定表换算，使原型库跨游戏迁移。
- 判定型字段只放在逻辑层可读的表，呈现型字段只放表现层表；一张 `feel.*` 表内两类字段可以并存，但读取方按半属过滤，规则层拿不到呈现型字段。

## 2. 数据域 `feel` 与表清单

新增数据域 `feel`（04 第 2.2 节域名清单走审批，本目录 ADR-0118 即审批记录）。

| 表 | 一行是什么 | 引用方 |
|---|---|---|
| `feel.preset` | 类型级基础档案（首期 `arpg_responsive`、`rpg_classic`，第 9 节），全字段齐全 | 标定表指定一款游戏的基础预设 |
| `feel.archetype` | 体型原型：体量（轻/中/重）、步幅（短/中/长）、敏捷（低/中/高）、攻击重量（轻/中/重）四个轴的组合，只写与基础预设的差异 | 单位模板的 `feel_archetype_ref`；玩家读职业行（`arch.class`）上的同名字段 |
| `feel.weapon` | 武器原型（轻近战、中近战、重近战、长柄、投射、法器 …）：`family`（04 武器族维度）、节奏、承诺、移动耦合、打击、`impact_class`、`auto_attack_timeline_ref` | 物品模板 `feel_weapon_ref`（与 `display.weapon_style` 分表同 id，规则层只读本表） |
| `feel.character` | 角色/怪物层覆盖，只写差异 | 单位模板的 `feel_ref`；玩家读职业行上的同名字段 |
| `feel.action` | 当前动作层覆盖，只写差异 | `skill.def.timeline.feel_ref` |
| `feel.calibration` | 标定：参考身高、参考基础移速（只用于绝对值视图，不参与移动）、动画帧率、参考镜头高度/缩放、像素密度、标记容差 | 每款游戏一行，装配根指定 |
| `feel.motion_mode_rules` | 运动模式规则（02 第 3.1 节） | 移动系统 |
| `feel.tag_map` | 标签到原型/覆盖的映射（`gender:female → <原型行 id>`；游戏层内容，框架给结构） | 解析器第三层 |
| `feel.validation` | 成熟度验证记录：哪一行、哪个版本、哪个格子、在什么数据根/姿势集/设备条件下、评分摘要如何（第 8 节）；游戏自己的数据，框架不提供任何行 | 加载期成熟度校验 |

表现侧配套表（不在 `feel` 域）：`feedback.impact_profile`（打击反馈包，07）、`camera_profile`（既有表扩展跟随字段，07）、`display.anim_set`（姿势集，04）。

## 3. 七个分组与覆盖顺序

### 3.1 分组

字段的完整清单、取值范围、允许操作、合成来源、单位与落地状态由字段登记生成，见 [05a_字段登记表.md](05a_字段登记表.md)（自动生成、不手改，登记变了而片段没重新生成时测试失败）。本文只写分组语义：

| 分组 | 半属 | 内容 | 详见 |
|---|---|---|---|
| 输入 | 判定 | 缓冲窗口与槽位、宽限窗口、按住阈值、轴处理 | 01 第 4 节 |
| 移动 | 判定为主 | 加减速与曲线、转向、各模式的速度倍率、动作中的移动与转向锁、动量保持与到达减速、滑墙、单位间体积阻挡与分离、受控位移推人；步态阈值、步幅、落地保持、启停混合、倾斜为呈现 | 02 第 2/7 节 |
| 动作 | 判定 | 分相倍率、取消窗口与连招窗口倍率、转向辅助、停步距离 | 01 第 4 节 |
| 受击 | 判定 | 冲击等级、双方顿帧与上限、硬直、击退、击飞与空中受击、韧性与动态韧性、倒地、反应上限、击杀顿帧 | 03 第 3/4 节 |
| 镜头 | 呈现 | 跟随、前瞻、死区、阻尼、战斗缩放、冲击增益与限频 | 07 第 2 节 |
| 特效 | 呈现 | 打击反馈包引用（按冲击等级与命中结果索引）、拖尾/残影 | 07 第 1 节 |
| 音频 | 呈现 | 挥空层、命中层、增味层强度档、脚步材质层、同时发声上限 | 07 第 3 节 |

字段有落地状态：`active`（已有消费方，写了就生效）与 `planned`（已登记、数据里可以写，但目前没有任何消费方，写了不改变行为）。状态由测试守住，见第 4 节。

### 3.2 覆盖顺序

固定八层，从粗到细：

```
1 基础预设 feel.preset（标定表指定）
2 体型原型 feel.archetype（单位模板；玩家取职业行）
3 标签映射 feel.tag_map（游戏层：性别/种族/职业 → 原型或覆盖）
4 武器 feel.weapon（主手；副手只叠加打击层，见 3.4 节）
5 角色 feel.character（单位模板；玩家取职业行；两者的 feel_ref）
6 当前动作 feel.action（进行中动作的 feel_ref；动作结束即撤）
7 临时状态（光环携带的手感修饰，第 5 节）
8 调试覆盖（实验室热调参，仅开发期，06）
```

### 3.3 操作语义

每个写入对一个字段做一种操作：`set`（替换）、`multiply`（乘）、`add`（加）。规则：

- 字段登记声明允许的操作集合；布尔、枚举、文本与引用只允许 `set`。
- 同一行的 `writes` 对同一字段写两次是校验错误（不论操作），不允许"后写覆盖前写"的隐式规则。同一层内**不同来源**写同一字段是叠加场景，不算错：主手与副手武器同在第 4 层，副手只允许 `add`/`multiply` 叠加，多个标签映射同在第 3 层，多个光环同在第 7 层。
- 计算顺序：按层号从低到高逐层应用；同层内先 `set`、再 `multiply`、再 `add`，操作相同的按来源顺序确定性应用；全部应用后按登记的范围限幅并记录被限幅的事实。
- 值的范围口径：`set` 的值落在登记范围内；`multiply` 的倍数在 0～10；`add` 的增量绝对值不超过范围跨度。登记范围是限幅依据，不是唯一合法取值，多层叠加后越界不是数据错误，由解析器限幅并记录。
- 列表字段缺省整体替换；删除元素用显式 `remove`，不用空值暗示删除。
- 预设依赖（`extends`）必须无环；`feel.preset` 不允许 `extends` 以外的引用。

### 3.4 合成来源

字段登记的"合成来源"决定角色侧（第 2 层体型原型与第 5 层角色）与第 4 层（武器）谁是主：

| 合成来源 | 规则 | 典型字段 |
|---|---|---|
| 角色为主 | 武器层不写该字段（写了为错误） | 加减速、转向、步幅、`hit_stun_ms`（受击方）、脚步音效层 |
| 武器为主 | 体型层只允许 `multiply` | 分相倍率、取消窗口、`impact_class`、顿帧、击退、命中/挥空音效层 |
| 攻击期间武器临时覆盖 | 武器层的值只在 `action` 模式下生效，动作结束自动撤回 | `action_move_speed_ratio`、`action_turn_lock` |

副手武器：只允许写"武器为主"分组里标记为 `offhand_stackable` 的字段（打击层的音效增味、特效），以 `add`/`multiply` 叠加；节奏与承诺永远取主手。双持作为一个武器族（`dual`）由主手武器原型声明。

## 4. 字段登记元数据

沿用 04 第 3.2～3.6 节的机器可读登记，手感字段新增四项元数据（00 第 4 节）：`half`（`judging|presenting`）、`group`、`ops`（允许操作）、`composition`（合成来源），外加 `unit`（00 第 6 节单位枚举）、`offhand_stackable` 与落地状态 `status`（`active|planned`，`planned` 须写明原因）。校验器新增检查：

| 检查 | 级别 |
|---|---|
| 操作不在 `ops` 内 | 错误 |
| 违反合成来源（武器层写了角色为主字段等） | 错误 |
| 同一行重复写同一字段 | 错误 |
| 相对量字段的值超出登记范围（标定前） | 错误 |
| `extends` 成环 | 错误 |
| 预设缺字段（`feel.preset` 必须全字段；标可选的字段除外） | 错误 |
| 判定型字段出现在 `display.*`/`feedback.*` 表 | 错误 |
| 标定表缺项 | 错误（阻断装配） |
| 档案行标 `validated` 而 `feel.validation` 没有覆盖它的记录（第 8 节） | 错误 |
| 验证记录指向不存在的档案行，或日期不是 yyyy-mm-dd | 错误 |

**落地状态由测试守住**：每个 `active` 字段至少有一处生产代码引用，没有任何引用的字段必须标 `planned`；字段被实现后由实现者摘掉 `planned`，没摘或没引用却标 `active` 都使测试失败。这样"登记了但没生效"是显式、可查的事实，调参面板可以据此对 `planned` 字段注明"尚未生效"。

**目录由登记生成**：字段清单是登记的派生物，工具链把登记渲染成 [05a_字段登记表.md](05a_字段登记表.md)，测试把渲染结果与入库的片段逐字节比较；新增、改范围、改说明都只改登记再重新生成，不在文档里手抄字段名。

**游戏自有字段**：游戏层自己的手感字段（如招架窗口、冲刺次数）在框架默认登记之上追加，名字必须带 `game.` 前缀（与框架字段永不重名）。游戏把扩展后的登记同时交给数据校验（预设与五张分层表的 `writes` 因此接受它）与装配选项，它就参与八层解析、溯源与调参面板；框架的判定与表现消费方不读取它，读取方是游戏自己的代码，经解析结果按名取值。建议声明为可选字段（预设可缺省），否则框架预设与每个游戏预设都要给它取值。校验规则按"这份数据注册表登记的字段集"取字段，框架目录与游戏扩展的注册先后不影响结果。光环携带的手感修饰（第 6 节）读的是规则层的光环定义表，该表按框架默认登记生成，游戏自有字段不能写在光环的修饰里。

## 5. 解析器

```
interface FeelResolver {
  resolve(unitId: Id): ResolvedFeel                  // 缓存命中直接返回
  invalidate(unitId: Id, reason: String): void        // 装备/变身/光环/动作开始结束/标签变化事件驱动
  provenance(unitId: Id, field: String): List<{layer: Int, sourceId: Id, op: String, valueBefore, valueAfter}>
  version(unitId: Id): Int                            // 每次重算递增，供消费者判断是否需要重读
}

struct ResolvedFeel {
  fields: Map<String, Value>      // 标定后的绝对值；判定型时间字段同时给 ticks
  raw: Map<String, Value>         // 标定前的相对值
  clampedFields: List<String>
  version: Int
}
```

- 纯函数：输入只有数据表与实体的只读状态（体型与角色引用——生物读单位模板、玩家读职业行，标签、主/副手武器、当前动作、临时状态列表、调试覆盖），不读时钟、不读随机。
- 失效事件：装备变化（既有事件）、外形变化、`aura.applied/removed`（仅携带手感修饰的光环）、`action.started/finished/cancelled`（仅当动作有 `feel_ref` 或武器有攻击期间临时覆盖）、标签变化（游戏层事件）、读档（玩家的职业可能被存档改写，仅在有职业行声明了手感引用时）、调试覆盖变化。失效后下一次 `resolve` 重算。
- 时间线技能在 `action.started` 时快照一份手感表挂在施法实例上：动作进行中重算不改变正在进行的动作（热加载在安全的动作边界应用，第 8 节）。
- 判定型消费者只经 `resolve` 读判定型字段；呈现型消费者只读呈现型字段；登记表驱动的访问器按半属生成两套只读视图，防止越界读取。

## 6. 临时状态

- 光环定义新增可选 `feel_modifiers: List<{field, op, value}>`，作为第 7 层条目，以光环实例 id 为键。光环移除即删除该条目并失效重算，**不是**做反向乘法恢复（避免叠加误差）。
- 规则：字段若已是属性（移动速度、急速），走属性系统，不允许用 `feel_modifiers` 重复表达（校验错误）；`feel_modifiers` 只用于没有对应属性的手感字段。
- 控制效果（定身、硬直）不经本机制，它们改变运动模式（02）。

## 7. 标定、能力声明与降级

- 标定表缺失时装配失败，不用隐式缺省。标定值进入指纹元数据（06）。
- 适配层能力声明（02 引擎适配层的契约风格）：目前只有一项可选能力 `supportsCameraImpulse`（`ICameraImpulse`，07 第 2 节）：缺失时退化为震屏并写进诊断，不静默丢失反馈。曾设想的 `supportsSweep`（高速形状扫掠：改为一律子步采样）、`supportsRootMotion`（根运动：已删除，位移权威只在逻辑层，02 第 4 节）、`supportsFootIK`（没有任何键与消费者依赖足部 IK）不再存在。数据里写了框架不再支持的能力或字段时在**加载期**报错并给迁移说明（例如 `timeline.motion.driver: root_motion`，校验检查名 `timeline_motion_driver_removed`），不在运行中途才抛错；新增一项适配层能力时，先在适配层契约里登记并写明缺失时的降级或报错，再在加载期校验依赖它的数据。
- 预设跨维度：相同"重"风格可以跨 `sprite`/`model` 表达同一意图，不保证复制相同数值得到相同感知；每个成熟预设都绑定它验证过的外形类型与适配组合。

## 8. 版本、成熟度与热加载

- 表有 `schema_version`，每个档案行有 `profile_version`（缺省 1）。发布的游戏固定依赖版本；迁移旧字段必须有显式转换与变更说明（沿 ADR-0029/0039）。单位约定已固定在字段登记里，不单设版本字段。
- 成熟度标签 `maturity: experimental | validated`。未经试玩的配置一律 `experimental`，**框架自带的预设、原型、武器行永远是 `experimental`**（占位资源上的体验不得标 `validated`，框架也不提供任何验证记录）。`validated` 只属于游戏，并且必须有证据：游戏自己的数据里 `feel.validation` 至少有一条记录覆盖该行——记录指向该行、记录的 `profile_version` 等于该行当前版本（档案改版即过期）、评分摘要各项不低于升级门槛 4、格子非空；一条记录写明格子（06 第 1.1 节矩阵）、数据根版本、姿势集版本、设备条件与日期。行上的 `validated` 表示"至少一个格子已验证"，哪些格子已验证以记录为准（一个预设可以在 `2_5d_action` 已验证而在 `3d_action` 仍是 `experimental`）。标了 `validated` 而没有覆盖它的记录，数据加载时报错。升级的完整条件、门槛 4 与真机手测及格线 3 的区别见 06 第 6 节。
- 热加载（开发期 `reload`）：解析器失效重算，但正在进行的动作沿用其开始时的快照（第 5 节）；`hit_policy` 与形状引用在一次挥击内不会前后不一致。运动档案的变化在下一 tick 生效（速度状态保留）。
- 标定行同样热换：新数据里标定行取值变化时，档案与新标定一并换入（结果标注标定已变，但不要求重启）；此后每次解析与下一个动作的开始快照按新标定换算（相对量 → 绝对量、基础预设选择），进行中的动作沿用其开始时的快照。毫秒到 tick 只取决于模拟步长，不随标定变化；新标定指定的基础预设不存在时整次热加载拒绝，保持当前档案与标定。使用标定的表现侧消费方（镜头冲击、命中反馈的参考高度）读实时标定，不在装配时固化。

## 9. 框架预置原型库（首期范围）

首期只收录能在实验室被验证的最小集合，不预先堆满：

| 类别 | 首期内容 |
|---|---|
| 基础预设 | `arpg_responsive`（响应型动作，缺省）、`rpg_classic`（目标选择式、无缓冲取消，等价既有行为）；全部 `experimental` |
| 体型原型 | 轻/中/重体量 × 中步幅 × 中敏捷 三组，其余轴留字段与范围 |
| 武器原型 | 轻近战（单手剑）、重近战（巨剑）两套；长柄、投射、法器给结构与试调起点、标 `experimental` |
| 姿势集 | 标准骨骼三组（对应三体量）、假人集一组 |
| 反馈包 | `light/medium/heavy/massive` 四档 × 命中/回避 |
| 镜头档案 | 响应型跟随一套 |

试调起点（单手剑 / 巨剑，俯视近战原型，不是已验证值）：三相 110/80/190 与 170/100/290 ms；缓冲 120 ms；攻击方顿帧 35/65 ms；受击方顿帧 45/75 ms；硬直 150/230 ms（这是**受击方基础 `hit_stun_ms` 的参考取值**，落点在受击一侧、记在武器行的 `timeline_reference.inflicted_hit_stun_ms` 供对照，不分层、不参与解析；武器对硬直时长的实际贡献用武器为主的可选字段 `hit_stun_scale`——以受击方 150 ms 为基准，巨剑相当于 230/150 ≈ 1.53 倍，公式见 03 第 4.1 节）；突进 0.2/0.3 身高；击退 0.15/0.3 身高；闪避取消从动作进度 0.65/0.75 开始。这些数进入 `experimental` 预设行；框架行不会升为 `validated`，游戏在自己的数据根上试玩后，以 `feel.validation` 记录支撑自己的行升级（第 8 节）。

## 10. 测试与验收

1. 解析器性质测试（字段登记自动枚举）：任意原型 × 武器 × 标签组合解析成功；所有字段落在登记范围内；重复解析结果不变；溯源链每字段至少一条且最后一条的 `valueAfter` 等于结果。
2. 操作语义：同层重复写被校验拒绝；`set→multiply→add` 顺序结果等于手算；限幅事实被记录。
3. 合成来源：武器层写角色为主字段被拒绝；攻击期间临时覆盖在 `action.finished` 后撤回。
4. 临时状态：光环施加/移除后字段值恢复到施加前的精确值（非反向乘法）。
5. 快照：动作进行中热加载不改变该动作的分相与形状，下一次动作生效。
6. 能力校验：必需能力缺失装配报错；可选能力缺失诊断里出现降级记录。
7. 标定：同一相对值在两组标定下换算出的绝对值等于公式值；判定型时间字段的 tick 换算四舍五入且非零至少 1。
8. 半属隔离：静态检查规则层程序集没有任何呈现型字段的读取点，表现层程序集没有判定型字段的读取点。
9. 落地状态：每个 `active` 字段至少有一处生产代码引用，没有引用的字段都标 `planned` 并带原因；字段登记表片段与登记逐字节一致。
10. 成熟度：无验证记录的 `validated` 行报错；档案改版使旧记录过期；评分取门槛值时覆盖、略低于门槛时不覆盖，四个维度各自判定；按格子记录已验证状态；框架数据根不含任何 `validated` 行与验证记录。
11. 玩家入口：职业行声明体型原型与角色引用后，玩家的解析结果在第 2、5 层出现对应来源，数值等于预设值经该行写入的结果；未声明的职业行解析结果与此前逐位一致。
12. 标定的基础移速：只差基础移速的两组标定，解析出的相对值逐位相同，只有绝对值视图不同。
13. 游戏自有字段：未登记时写 `game.` 字段被校验拒绝，登记后（不论与框架目录的注册先后）被接受并参与解析。
