引擎适配层（L-1）是运行时唯一允许直接接触引擎能力的层。它把引擎能力封装成本文档定义的一组中立接口；其余各层只调用这些接口，不知道背后是哪种引擎实现。接口签名统一使用中立伪代码记法（见 `00_架构总则.md` 引用的记法约定），类型只用 `Bool`、`Int`、`Number`、`String`、`Id`、`Handle`（不透明句柄，供跨接口传递资源引用而不泄漏引擎类型）、`Vec2`、`Rect`（`{min: Vec2, max: Vec2}` 结构体，见第 1.8 节）、`List<T>`、`Map<K,V>`、`Optional<T>` 与枚举 `a|b|c`。除 `ICamera.configure` 的 `pitchDegrees`/`yawDegrees`（命名本身已表明按角度制）外，本文档全部角度类参数——包括 `IRenderer2D.setTransform` 的 `rotation`、`IRenderer3D.setPlacement` 的 `facing`、`ISpatialQuery.queryCone` 的 `direction`/`angle` 等旋转、朝向、锥形方向与张角参数——一律以弧度（radian）为单位。

## 1. 接口清单

### 1.1 IWindow — 窗口生命周期、分辨率、全屏

```
interface IWindow {
  create(title: String, width: Int, height: Int): void
  destroy(): void
  setResolution(width: Int, height: Int): void
  setFullscreen(enabled: Bool): void
  isFocused(): Bool
  onCloseRequested(callback: Callback): void
}
```

- **语义**：管理游戏窗口的创建、销毁、分辨率与全屏切换；`onCloseRequested` 在用户请求关闭窗口（点击关闭按钮、Alt+F4 等）时回调，由上层决定是否弹出"未保存进度"确认后再真正调用 `destroy`。
- **性能约定**：`setResolution` 与 `setFullscreen` 允许有一帧以上的延迟生效，但必须在调用后的下一次 `IClock.onFrame` 之前完成状态切换；不得阻塞主线程超过一帧。
- **可选性**：必需。

### 1.2 IClock — 帧回调、固定步长驱动、真实时间

```
interface IClock {
  now(): Number
  getDeltaSeconds(): Number
  onFrame(callback: FrameCallback): SubscriptionHandle
  requestFixedStep(stepSeconds: Number, callback: FixedStepCallback): SubscriptionHandle
}
```

- **语义**：`now()` 返回单调递增的真实时间（秒），供 UI 动画等不受模拟暂停/慢动作影响的场景使用；`onFrame` 每个引擎渲染帧回调一次，供表现层与主循环的插值/累积逻辑使用；`requestFixedStep` 是主循环用来驱动固定步长模拟的唯一入口，引擎适配层负责按 `stepSeconds` 的粒度触发回调并处理帧率抖动的补偿。`onFrame`/`requestFixedStep` 均返回 `SubscriptionHandle`，调用方可据此退订该回调；主循环在场景/世界重建（见 03 第 6 节场景路由卸载旧场景）前必须退订旧世界注册的全部固定步回调，避免旧回调残留导致重复推进（见 [ADR-0016](adr/0016-引擎适配层契约阶段4联调补齐.md)）。
- **性能约定**：`now()` 调用开销必须是常数级，可在每帧多次调用；固定步长回调的触发误差应控制在步长的 5% 以内。
- **可选性**：必需。

### 1.3 IRenderer2D — 精灵实例句柄、分层与 Y 排序、纸娃娃层合成、粒子发射、着色器参数

```
interface IRenderer2D {
  createSpriteInstance(spriteSetId: Id): Handle
  setLayers(handle: Handle, layers: List<Id>): void
  setTransform(handle: Handle, position: Vec2, height: Number, sortY: Number, layer: Int, rotation: Number, scale: Number, flipX: Bool): void
  setShaderParam(handle: Handle, paramName: String, value: Number): void
  destroySpriteInstance(handle: Handle): void
  emitParticle(effectId: Id, position: Vec2, params: Map<String, Number>): Handle
  stopParticle(handle: Handle): void
}
```

- **语义**：本接口采用保留句柄模式（设计层拍板，与场景图型引擎天然对应）：`createSpriteInstance` 依据精灵集 id 创建一个持久化的精灵实例并返回不透明句柄 `Handle`；`setLayers` 设置/更新该实例当前应绘制的层集合（例如角色的身体、装备、武器等纸娃娃分层，按固定锚点合成为一个视觉整体，具体锚点见 `05_对象模型与世界.md`）；`setTransform` 更新该实例的位置、`height`（跳跃/击飞/悬浮类效果的纵向绘制偏移，只平移绘制位置，不参与 `sortY` 排序、不平移影子，语义见 09 第 3.4 节，与 `IRenderer3D.setPlacement` 的 `height` 参数对齐）、`sortY`（同层内按纵坐标排序，用于 2.5D 的前后遮挡，且与 `IRenderer3D` 模型实例的 `sortY` 共享同一排序空间，由适配层保证二者合成顺序一致，见第 2 节）、`layer`（离散图层）、旋转、缩放与水平翻转；`setShaderParam` 设置该实例的着色器参数（例如受击闪白强度、溶解进度），参数含义由 `DisplayInfo` 映射决定，接口本身不理解参数语义，不承载高度这类已有正式参数通路的量（见 [ADR-0016](adr/0016-引擎适配层契约阶段4联调补齐.md)）；`destroySpriteInstance` 释放该实例持有的表现资源；`emitParticle`/`stopParticle` 管理粒子特效的生命周期，`emitParticle` 返回的 `Handle` 是该粒子实例的运行期句柄，供 `stopParticle` 引用。镜头变换与震屏迁移到 `ICamera`（见第 1.13 节）；本接口保留精灵实例、粒子、着色器参数职责，专注地面层、装饰层、前景遮挡层、2D 粒子与飘字等 2D 表现。保留句柄模式使纸娃娃合成结果可以持久保持而非每帧重建。精灵与粒子实例都是运行期分配的句柄，不是内容 id。
- **性能约定**：单帧可承受的 `setTransform` 调用量、并发存活的精灵实例数量、`emitParticle` 并发数量作为引擎选型评估的性能基线之一（见第 3 节），本文档不预设具体数值上限，由目标引擎的评估结果给出。
- **可选性**：必需。

### 1.4 IAudio — 音效、音乐、分层叠放、对象池

```
interface IAudio {
  playSfx(soundId: Id, volume: Number, pitch: Number, position: Optional<Vec2>): Handle
  stopSfx(handle: Handle): void
  playMusic(trackId: Id, fadeInSeconds: Number, loop: Bool): void
  stopMusic(fadeOutSeconds: Number): void
  setBusVolume(bus: music|sfx|ui|ambient, volume: Number): void
}
```

- **语义**：音效播放返回句柄以便按需提前停止；`position` 为空时按无空间衰减方式播放，非空时允许实现按二维位置做空间衰减/声像（对应 09 第 5.3 节 `SfxPlayer.play` 的 `at` 参数）；不支持空间音频的实现可以忽略该参数按无空间方式播放，但不得因该参数报错或拒绝播放（见 [ADR-0016](adr/0016-引擎适配层契约阶段4联调补齐.md)）；音乐播放支持淡入淡出与循环；音频总线分组（音乐/音效/界面/环境）分别控制音量，供设置界面调节。
- **性能约定**：音效对象池由实现方内部管理，接口调用方不感知池的存在；高频短音效（如连续命中音）不应造成播放延迟累积。
- **可选性**：必需。

### 1.5 IInput — 设备事件、键鼠手柄、文本输入

```
interface IInput {
  pollEvents(): List<InputEvent>
  isKeyDown(key: String): Bool
  getMousePosition(): Vec2
  getGamepadAxis(gamepadIndex: Int, axis: String): Number
  beginTextInput(placeholder: String): void
  endTextInput(): String
}
```

- **语义**：`pollEvents` 返回自上次调用以来的离散输入事件（按下/抬起/设备接入断开）供 `InputMap` 转译为游戏动作；`isKeyDown`/`getMousePosition`/`getGamepadAxis` 提供连续状态查询；文本输入用于存档命名等少量场景，`beginTextInput` 开启一个平台原生或引擎内置的文本输入会话，`endTextInput` 结束并返回最终文本。
- **性能约定**：`pollEvents` 每帧调用一次，不得丢事件（多次按下需全部保留在返回列表中）。
- **可选性**：必需。

### 1.6 IFileSystem — 用户目录、读写、原子写入

```
interface IFileSystem {
  getUserDataDir(): String
  getContentRootDir(): String
  readText(path: String): Optional<String>
  writeTextAtomic(path: String, content: String): Bool
  exists(path: String): Bool
  listFiles(dirPath: String): List<String>
  deleteFile(path: String): Bool
}
```

- **语义**：`getUserDataDir` 返回平台约定的用户数据目录（存档、设置的落盘位置）；`getContentRootDir` 返回只读内容根目录（数据表、静态资产的落盘位置），与用户数据目录分离；对内容根目录下的路径调用 `writeTextAtomic`/`deleteFile` 一律返回 `false`，不真正执行写入/删除，也不抛异常（见 [ADR-0016](adr/0016-引擎适配层契约阶段4联调补齐.md)）。`writeTextAtomic` 保证写入过程要么完全成功要么保持旧文件不变，杜绝存档写到一半崩溃导致存档损坏。`listFiles(dirPath)` 返回 `dirPath` 下（含子目录，递归）全部文件的路径，相对 `dirPath`、以 `/` 分隔、按字典序排序；调用方据此枚举按目录组织的数据表与存档槽。内容根只读的具体落地拓扑（例如同一实例按路径前缀路由到只读区，或另起一个专职只读的独立实例分工）由实现自选，调用方不得假设具体拓扑，只能依赖本节接口本身的行为约定。
- **性能约定**：`writeTextAtomic` 必须真正具备原子性（典型做法是先写临时文件再原子替换），不得只是"看起来原子"的顺序写。
- **可选性**：必需。

### 1.7 IResourceLoader — 图片、音频、字体、数据表、模型、异步加载

```
interface IResourceLoader {
  loadAsync(resourceId: Id, kind: image|audio|font|data_table|scene|nav_mesh|effect|model, callback: LoadCallback): void
  isLoaded(resourceId: Id): Bool
  getLoadProgress(resourceId: Id): Number
  unload(resourceId: Id): void
}
```

- **语义**：统一的异步资源加载入口，`kind` 声明资源种类，`callback` 在加载完成或失败时触发一次；数据表资源经此加载后交给 L0 的 `DataRegistry` 解析，图片/音频/字体资源加载后交给 `IRenderer2D`/`IAudio`/`IUISurface` 使用；`scene` 对应 `world.map` 的 `scene_ref` 字段（见 05 第 4.1 节），加载后交给场景路由使用；`nav_mesh` 对应 `world.map` 的 `nav_ref` 字段（同节），加载后交给 `INavigation2D` 使用；`effect` 对应 `vfx.def` 的 `resource_ref` 字段（见 09 第 5.1 节），加载后交给 `IRenderer2D`/`IRenderer3D` 使用，使 `emitParticle` 的 `effectId` 能解析到具体特效资产而非实现内建的通用效果（见 [ADR-0016](adr/0016-引擎适配层契约阶段4联调补齐.md)）；`model` 对应 `display.map`（`kind: model`）的 `model_ref` 字段与 `display.equip_visual` 的 `model_ref` 字段（见 04 第 7.1、7.1.2 节），加载后交给 `IRenderer3D` 使用（见 [ADR-0017](adr/0017-模型型外形默认路线补齐与命中帧同步.md) 决策 1）。
- **语义（资源首次加载的责任归属）**：谁首次引用一个资源 id（某个 View、某个播放器、某个界面面板），谁负责调用 `loadAsync`；`IRenderer2D`、`IRenderer3D`、`IAudio`、`IUISurface` 的实现只消费已加载完成的资源，遇到未加载的资源 id 时使用实现内建的可见/可听占位（例如洋红色方块、静音、内置最简占位模型）并记录一条诊断信息，不得隐式触发该资源的加载，也不得抛出异常或使调用方的调用崩溃（见 [ADR-0016](adr/0016-引擎适配层契约阶段4联调补齐.md)；`model` 资源种类另见 [ADR-0017](adr/0017-模型型外形默认路线补齐与命中帧同步.md) 决策 1，勘误，2026-09-08）。
- **性能约定**：加载过程不得阻塞主线程；`getLoadProgress` 取值范围为 `[0,1]`（0 表示未开始，1 表示已完成），用于加载画面展示百分比，允许粗粒度估算（例如只区分未开始/进行中/已完成几个离散点，不要求连续精确进度）。
- **可选性**：必需。

### 1.8 INavigation2D — 导航网格、路径查询、可行走判定

```
interface INavigation2D {
  buildNavMesh(mapId: Id): void
  isWalkable(mapId: Id, point: Vec2): Bool
  findPath(mapId: Id, from: Vec2, to: Vec2): Optional<List<Vec2>>
  raycast(mapId: Id, from: Vec2, to: Vec2): Optional<Vec2>
  setBlocking(mapId: Id, rects: List<Rect>): void
  clear(mapId: Id): void
}
```

- **语义**：`buildNavMesh` 在场景加载时根据地图数据构建二维可行走区域；`isWalkable` 做单点判定；`findPath` 返回一串路径点供移动系统跟随，找不到可行路径时返回空（`Optional` 为空，而非空列表，供调用方明确区分"无路径"与"路径长度为零"）；`raycast` 返回从起点到终点连线上第一个阻挡点（若无阻挡则返回空），供视线判定与移动前的直线可达性判断复用——视线是否受阻即"`raycast` 返回值是否非空"；`setBlocking` 登记一批运行时动态阻挡矩形（`Rect = {min: Vec2, max: Vec2}`，如临时关闭的门、被摧毁的可破坏物），语义为整批替换而非追加——每次调用即以本次给出的列表整体替换该地图先前登记的动态阻挡集合，调用方需自行维护完整的当前阻挡集合并整体传入；供 `isWalkable`/`findPath`/`raycast` 在原有静态导航数据之上叠加判定，不需要重新 `buildNavMesh` 整图；`clear` 清空某地图的全部动态阻挡登记，供场景卸载时重置（见 [ADR-0016](adr/0016-引擎适配层契约阶段4联调补齐.md)）。
- **性能约定**：`findPath` 是可能较重的调用，运行时应支持跨帧分摊计算（例如限定每帧最多完成若干条路径请求），不得要求引擎实现在单帧内同步返回。
- **可选性**：可选——不依赖寻路的游戏（例如 AI 只做原地/直线追击）可以不实现完整寻路，退化为 `isWalkable` 与直线移动。

### 1.9 ISpatialQuery — 半径/锥形/线段/矩形查询、视线遮挡

```
interface ISpatialQuery {
  queryRadius(center: Vec2, radius: Number, filter: QueryFilter): List<Id>
  queryCone(origin: Vec2, direction: Number, angle: Number, range: Number, filter: QueryFilter): List<Id>
  queryLine(from: Vec2, to: Vec2, filter: QueryFilter): List<Id>
  queryRect(min: Vec2, max: Vec2, filter: QueryFilter): List<Id>
  queryShape(shape: Shape, filter: QueryFilter): List<Id>
  nearest(point: Vec2, filter: QueryFilter): Optional<Id>
  hasLineOfSight(from: Vec2, to: Vec2): Bool
  register(id: Id, position: Vec2, radius: Number, tags: List<String>): void
  updatePosition(id: Id, position: Vec2): void
  unregister(id: Id): void
  clear(): void
}
```

- **语义**：为技能范围判定、AI 感知、目标选择提供统一的空间查询能力，`filter` 只承载中立的字符串标签匹配（包含/排除），标签语义由上层与登记方约定，接口本身不解释；`Shape` 是 `05_对象模型与世界.md` 第 3.5 节定义的联合类型（`circle`/`cone`/`line`/`rect`），`queryShape` 按该联合类型统一查询，供技能目标解析等按同一形状描述复用；`nearest` 返回满足过滤条件的最近一个对象；`hasLineOfSight` 判断两点间是否存在视线遮挡物。以上全部查询默认作用于调用方当前已加载的场景，`mapId` 由该场景隐含，不作为显式参数传入。`register`/`updatePosition`/`unregister`/`clear` 是空间索引的登记接口：`WorldSim` 在对象创建时调用 `register` 把该对象的位置、半径与过滤用标签登记进空间索引，位置变化时调用 `updatePosition` 同步，对象销毁时调用 `unregister` 移除登记，场景卸载时调用 `clear` 清空整个索引；以上查询方法只查询已登记的对象，登记时机与登记内容由调用方负责，接口本身不主动扫描场景（见 [ADR-0016](adr/0016-引擎适配层契约阶段4联调补齐.md)）。
- **性能约定**：查询应基于空间索引而非线性扫描全部对象，具体索引结构由实现方决定，接口不关心内部实现。
- **可选性**：必需——战斗范围判定与 AI 感知都依赖它。

### 1.12 IRenderer3D — 三维模型实例句柄、骨骼动画、槽位换装、挂点、材质参数、阴影模式

```
interface IRenderer3D {
  createModelInstance(modelId: Id): Handle
  destroyModelInstance(handle: Handle): void
  setPlacement(handle: Handle, planePos: Vec2, height: Number, facing: Number, scale: Number, sortY: Number): void
  playAnim(handle: Handle, clipId: Id, loop: Bool, speed: Number, blendSeconds: Number): void
  setAnimSpeed(handle: Handle, speed: Number): void
  onAnimEvent(handle: Handle, callback: AnimEventCallback): SubscriptionHandle
  setSlotMesh(handle: Handle, slotId: Id, meshId: Optional<Id>): void
  attachToSocket(handle: Handle, socketId: Id, child: Handle): void
  detach(child: Handle): void
  setMaterialParam(handle: Handle, paramName: String, value: Number): void
  setShadow(handle: Handle, mode: none|blob|projected): void
}
```

- **语义**：`createModelInstance`/`destroyModelInstance` 管理三维模型实例的生命周期；`setPlacement` 用世界平面坐标 `planePos` 加高度 `height`、朝向、缩放与 `sortY` 定位模型（`sortY` 与 `IRenderer2D` 共享同一排序空间，见 1.3 节与第 2 节）；`playAnim`/`setAnimSpeed` 播放/调速一条动画剪辑，`blendSeconds` 控制与上一动作的过渡混合时长；`onAnimEvent` 订阅动画剪辑内标记的关键帧事件（命中、收招、脚步声等，事件清单见 `04_数据与内容管线.md` 的 `display.anim_set`），返回可用于取消订阅的句柄；**引擎适配层必须在 `playAnim` 播放的非循环剪辑（`loop=false`）自然播放完成时，经同一条 `onAnimEvent` 通道额外发出一次约定的"播放完成"事件（循环剪辑不发）——09 第 4.2 节动画状态机靠这条信号解除瞬态状态（受击/攻击/施法等）的优先级锁，不实现这条义务会让上层瞬态状态永久卡死，具体事件 id 由消费方约定，本文档不规定**（勘误，2026-09-08）；`setSlotMesh` 做槽位换装，`slotId` 对应模型上一个可替换部位，`meshId` 为空表示卸下该部位网格；`attachToSocket`/`detach` 把一个子模型实例挂接到/解除自父模型的命名挂点（武器、特效等）；`setMaterialParam` 设置材质参数（闪白、溶解等），语义由 `DisplayInfo` 映射决定，接口本身不解释参数含义；`setShadow` 设置阴影呈现模式（无/贴地简化影子/投影阴影）。
- **性能约定**：单帧可承受的 `setPlacement`/`playAnim` 调用量、并发存活的模型实例数量、槽位换装与挂点挂接的开销作为引擎选型评估的性能基线之一（见第 3 节），本文档不预设具体数值上限，由目标引擎的评估结果给出。
- **可选性**：条件必需——仅当游戏层为至少一类外形选择 `model` 型时必需；只使用 `sprite` 型外形的游戏可以不实现本接口。

### 1.13 ICamera — 固定俯角镜头配置、跟随、缩放、世界平面与屏幕坐标互投影、震屏

```
interface ICamera {
  configure(pitchDegrees: Number, yawDegrees: Number, zoomRange: {min: Number, max: Number}): void
  follow(planePos: Vec2, smoothing: Number): void
  setZoom(zoom: Number): void
  worldToScreen(planePos: Vec2, height: Number): Vec2
  screenToWorld(screen: Vec2): Optional<Vec2>
  shake(intensity: Number, durationSeconds: Number, frequency: Number): void
}
```

- **语义**：`configure` 设定固定俯角 `pitchDegrees`、水平朝向 `yawDegrees` 与允许的缩放范围 `zoomRange`，镜头姿态在此之后只能通过再次 `configure` 整体调整，不支持自由旋转；`follow` 让镜头以给定平滑系数持续跟随一个世界平面坐标（通常是玩家单位的位置）；`setZoom` 在 `zoomRange` 内设置当前缩放；`worldToScreen` 把世界平面坐标加高度投影为屏幕坐标，供血条、飘字、UI 挂点等定位使用；`screenToWorld` 把屏幕坐标与地面平面求交反投影为世界平面坐标，找不到交点（如指向天空方向）时返回空，供点选、技能指示器等使用；`shake` 提供震屏效果，`frequency` 与 09 第 6.1 节震屏反馈动作引用的震屏预设的频率字段一一对应，强度、时长、频率三项经这一个方法完整传递（见 [ADR-0016](adr/0016-引擎适配层契约阶段4联调补齐.md)）。`configure`/`follow`/`setZoom` 与 `shake` 合起来取代了 v1 版 `IRenderer2D` 里的 `setCameraTransform`/`shakeScreen` 两个方法（见第 1.3 节与变更记录），现由镜头统一承担这类全局表现操作。
- **性能约定**：`worldToScreen`/`screenToWorld` 单帧可能被多次调用（每个可见单位的血条定位、每次点击判定），开销应为常数级，不得对场景做整体遍历。
- **可选性**：必需。

## 2. 适配层实现规范

1. **不得泄漏引擎类型到接口外**：接口的参数与返回值只能使用本文档约定的中立类型；任何引擎特有的对象、句柄、类实例都不得穿透接口边界暴露给 L0 及以上的层。凡是需要跨接口传递的资源引用，一律用 `Id` 或不透明句柄表示。
2. **线程约定**：`IResourceLoader.loadAsync` 的回调可能在非主线程触发，调用方必须自行处理回到主线程的切换（或由适配层保证回调总是在主线程的下一次 `IClock.onFrame` 之前排队执行，具体约定由实现方声明并在其实现文档中注明）；固定步长模拟与渲染帧回调的时序关系由 `IClock` 统一协调，其余接口的方法调用默认发生在主线程，不承诺线程安全。
3. **错误约定**：接口一律用 `Bool` 返回值或 `Optional<T>` 表达失败，不使用引擎特有的异常类型穿透边界；不可恢复的严重错误统一经 `IPlatform.reportCrash` 上报，可恢复的错误经调用方约定的错误回调或事件通知，不在接口内部吞掉错误。
4. **每种引擎一套实现**：每个目标引擎对应一套完整实现全部必需接口（可选接口可声明为"未实现，调用即返回空/降级值"）；实现内部可以自由使用引擎原生能力，但对外只暴露本文档定义的接口。
5. **接口稳定性**：接口方法签名的变更视为架构级变更，需按 `12_扩展与变更流程.md` 的流程处理，不得因单个引擎实现的方便而随意改动签名。
6. **2D/3D 混合排序**：2D 层（`IRenderer2D`）与三维模型（`IRenderer3D`）的深度合成规则由适配层内部实现并保证一致，上层（L0~L5）只需要为每个可见对象提供一个 `sortY` 数值，不关心具体合成算法。
7. **契约一致性验证**：每个接口至少提供一组与具体测试框架无关的契约一致性场景，场景本身只依赖本文档定义的中立接口与断言抽象，不绑定任何测试框架的类型；同一份场景源码可分别驱动桩实现与任意目标引擎的真实实现，用以验证二者对同一接口的行为是否一致。因平台限制导致某场景在特定实现下无法确定性验证时，允许声明跳过该场景并记录跳过原因，但不得因此放宽其余场景的断言强度。这套场景库的具体存放位置、组织方式属实现范畴，不在本文档规定。

## 4. 迁移引擎的步骤清单

1. 依据第 3 节评估框架完成候选引擎打分，确认目标引擎（此步骤在本文档范围之外单独进行）。
2. 为目标引擎实现本文档全部必需接口，可选接口按需实现或明确声明降级行为。
3. 复用已有的契约一致性场景（见第 2 节"契约一致性验证"）为新实现包一层薄壳并全部跑通，逐条核对每个接口的语义与性能约定是否满足，而非从零编写针对性测试。
4. 只替换应用启动流程中 L-1 具体实现的绑定点，不改动 L0 及以上任何一行代码。
5. 运行不依赖引擎的核心模拟测试集（脱离引擎的模块单测与数据校验），预期无需修改即可全部通过。
6. 用新引擎实现跑一遍人工表现校验：Y 排序是否正确、纸娃娃合成是否对齐、粒子与音效分层是否正常、UI 布局是否还原。
7. 若新引擎的资源导入格式与旧引擎不同，转换或重新生成表现资源，但不改动 `DisplayInfo` 映射表的逻辑 id。
8. 记录迁移过程中发现的接口缺口或语义歧义，如需新增接口方法，走 `12_扩展与变更流程.md` 的变更流程评估影响范围。
9. 先在开发环境跑通全部关卡验收，再切换发布管线到新引擎实现。
10. 核对 `IRenderer3D` 的换装（`setSlotMesh`/`attachToSocket`）与关键帧事件（`onAnimEvent`）语义是否与旧引擎实现一致，避免换装表现或命中反馈时机偏差。
