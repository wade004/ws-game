## 1. 七层定义

依赖只允许从内容相关的高层流向基础性的低层（即 L5 可以依赖 L4…L-1，L0 只能依赖 L-1，反之不成立）；同一层内的模块之间只经契约接口与事件总线交互，不得互相持有对方内部状态；除 L-1 外任何层都不得直接调用引擎能力，只能调用 L-1 暴露的接口；L5 表现层对 L-1 之外的所有层都只读、只订阅事件。

| 层 | 名称 | 内容概述 |
|---|---|---|
| L-1 | 引擎适配层 Engine Adapter | 把引擎能力封装为中立接口：窗口与生命周期、帧回调与时间、二维渲染（精灵、分层、Y 排序、粒子、着色器参数）、三维模型渲染与固定镜头（骨骼动画、槽位换装、挂点、世界平面与屏幕坐标互投影，仅 model 型外形需要，见 ADR-0012）、音频、输入设备、文件系统、资源加载、二维导航与空间查询、UI 承载面、平台服务。每种引擎各有一套实现，运行时其余层只依赖接口。 |
| L0 | 基础层 Foundation | 应用生命周期与游戏状态机、固定步长主循环、数据注册表 DataRegistry、条件表达式求值器 Expr、事件总线 EventBus、分流随机源 Rng、存档系统 SaveSystem、输入映射 InputMap、本地化 L10n、外形注册表 DisplayInfo、场景路由 SceneRouter、脚本钩子注册表 HookRegistry。 |
| L1 | 数值层 Numbers | 等级与经验 Progression、属性表 StatBlock（三段式聚合）、资源池 PowerSet、职业与种族模板 Archetype、阵营矩阵 Faction。 |
| L2 | 规则层 Rules | 技能系统 Skill（效果/光环/触发/法术修饰/施法管线/冷却充能/目标解析）、战斗系统 Combat（结算管线、命中表、护甲抗性、吸收免疫、仇恨、进出战斗、死亡）、AI（行为外壳状态机 + 优先级表）、目标选择 Targeting（可配置链）。 |
| L3 | 载体层 Carriers | 物品与装备 Item、生物 Creature、游戏对象 GameObject、召唤与宠物。 |
| L4 | 玩法层 Gameplay | 掉落 Loot、任务 Quest、对话与剧情 Dialog、遭遇与关卡 Encounter/Level、难度 Difficulty、成就 Achievement、货币与商人 Economy、世界状态 WorldState、区域与触发 Area/AreaTrigger、刷新 Spawn。 |
| L5 | 表现层 Presentation | 2.5D 渲染约定与混合渲染（sprite 型与 model 型外形按统一 sortY 合成，默认 2D 精灵，可选 3D 模型）、纸娃娃/骨骼与程序动画、VFX/SFX 播放、反馈绑定 FeedbackBinder、UI 框架、镜头、视图绑定 View、游戏外壳 Shell。 |

## 2. 每层职责与不负责什么

| 层 | 负责 | 不负责 |
|---|---|---|
| L-1 引擎适配层 | 把具体引擎的窗口、时钟、渲染、音频、输入、文件、资源加载、导航、空间查询、UI 承载、平台服务封装成中立接口 | 不了解任何游戏规则、不持有任何游戏对象、不做任何战斗/任务/剧情判断 |
| L0 基础层 | 提供跑起来的骨架能力：生命周期、主循环、数据加载与校验、条件求值、事件分发、随机数、存档、输入映射、本地化、外形映射、场景切换、钩子挂载 | 不定义任何具体游戏系统（不知道什么是技能、什么是物品），不做数值计算 |
| L1 数值层 | 定义单位的数值骨架：等级经验曲线、属性聚合规则、资源池模型、职业种族模板、阵营关系 | 不定义技能怎么释放、不做战斗结算、不涉及具体物品与生物 |
| L2 规则层 | 定义技能如何生效、战斗如何结算、AI 如何决策、目标如何选择这几套通用规则引擎 | 不定义某个具体技能长什么样、不持有物品/生物的模板数据、不做界面呈现 |
| L3 载体层 | 定义物品、生物、物件、召唤物这些"内容的容器"模板结构，把 L1/L2 的能力组装到具体载体上 | 不定义掉落规则、任务、对话这些玩法编排，不做战斗结算本身 |
| L4 玩法层 | 定义内容如何被组织与推进：掉落规则、任务流程、对话剧情、遭遇关卡、难度、成就、经济、世界状态、区域触发、刷新策略 | 不做底层数值计算、不做技能释放细节、不涉及任何画面表现 |
| L5 表现层 | 把逻辑事件与只读状态转译为画面、音效、动效、界面 | 不做任何会改变逻辑状态的判断，不持有游戏规则，不能替代逻辑层做决策 |

## 3. 依赖规则矩阵

行 = 调用方所在层，列 = 被调用方所在层。取值含义：**允许**＝可直接调用其契约接口；**仅事件**＝只能通过事件总线订阅，不能直接调用契约方法；**仅只读契约**＝只能调用不改变状态的查询类接口；**禁止**＝不允许任何形式的依赖。

| 调用方 \ 被调用方 | L-1 | L0 | L1 | L2 | L3 | L4 | L5 |
|---|---|---|---|---|---|---|---|
| L-1 引擎适配层 | — | 禁止 | 禁止 | 禁止 | 禁止 | 禁止 | 禁止 |
| L0 基础层 | 允许 | 同层仅契约/仅事件 | 禁止 | 禁止 | 禁止 | 禁止 | 禁止 |
| L1 数值层 | 允许 | 允许 | 同层仅契约/仅事件 | 禁止 | 禁止 | 禁止 | 禁止 |
| L2 规则层 | 允许 | 允许 | 允许 | 同层仅契约/仅事件 | 禁止 | 禁止 | 禁止 |
| L3 载体层 | 允许 | 允许 | 允许 | 允许 | 同层仅契约/仅事件 | 禁止 | 禁止 |
| L4 玩法层 | 允许 | 允许 | 允许 | 允许 | 允许 | 同层仅契约/仅事件 | 禁止 |
| L5 表现层 | 允许（调用渲染/音频/输入等表现操作） | 仅只读契约/仅事件 | 仅只读契约/仅事件 | 仅只读契约/仅事件 | 仅只读契约/仅事件 | 仅只读契约/仅事件 | 同层仅契约/仅事件 |

要点：

- L-1 是唯一允许被所有层调用、也是唯一实际接触引擎能力的层；其余层调用引擎必须经过 L-1 的接口，不得绕过。
- L5 调用 L-1 是为了执行绘制、播放音效、读取输入等表现操作，这不违反"L5 只读"原则，因为这些调用不改变 L0~L4 的逻辑状态。
- L5 对 L0~L4 一律只读、只订阅事件；任何"表现层需要改变逻辑"的需求都必须改写成"逻辑层先做判断、再发出事件或提供只读查询"，不能反向开洞。
- 同层模块之间（例如 L2 内 Skill 与 Combat）只能通过契约接口或事件总线交互，禁止相互持有对方的内部对象引用。

## 5. 游戏层 Game Layer 的边界

游戏层贯穿全部七层，但只做三件事：组装、少量注册、数据与资源。它不是第八层，不参与依赖矩阵的层间调用规则，而是通过下表列出的三种合法方式接入架构。

| 必须提供 | 允许做 | 禁止做 |
|---|---|---|
| 全部内容数据表的实际数据行 | 选择启用哪些模块与哪些可选扩展点 | 直接持有或修改 L0~L4 模块的内部状态 |
| 全部表现资源（精灵、音效、特效等）及其在 `display.map` 中的映射行 | 注入策略配置（命中表启用项、目标链组合、资源池类型数量等） | 绕过引擎适配层直接调用引擎能力 |
| 输入动作集的具体定义 | 实现并注册自定义策略（自定义 Targeting 策略、自定义优先级表生成规则等） | 在表现层代码中做任何会改变逻辑状态的判断 |
| 主菜单/存档槽/设置等外壳界面的具体内容 | 在 HookRegistry 声明的挂载点上注册回调 | 新增效果类型、光环类型、事件类型等原语（须走 ADR 审批流程，不能在游戏层"绕过"实现） |
| 難度档位、任务、对话、遭遇等玩法内容数据 | 扩展 Shell 的菜单结构、扩展 UI 框架的具体界面 | 在架构核心目录内直接修改契约接口签名 |

## 6. 禁止事项清单

1. 禁止任何层直接调用引擎能力，L-1 之外一律经 L-1 接口。
2. 禁止 L5 调用会改变 L0~L4 状态的方法，只能只读查询或订阅事件。
3. 禁止跨层"跳跃式"直接持有对象引用（例如 L4 直接持有 L1 的内部属性对象），一律经契约接口访问。
4. 禁止同层模块互相持有对方内部状态，只能经契约接口或事件总线。
5. 禁止游戏层修改架构核心目录内的契约接口签名或新增原语而不走 ADR 流程。
6. 禁止为单个内容写专用代码分支（违反"万物皆法术"与"数据即内容"原则）。
7. 禁止绕开数据注册表的引用完整性校验直接读取原始数据。
8. 禁止在表现层持久化任何逻辑状态（表现层重建后必须能从逻辑状态完全恢复）。

## 8. 跨层调用的三种合法方式

1. **直接契约调用（自上而下）**：L2 规则层的战斗结算管线需要读取单位护甲值时，直接调用 L1 数值层 `StatBlock` 契约暴露的 `getStat(unitId, StatKey.Armor)` 接口，属于上层对下层的直接契约调用。
2. **事件总线发布订阅（跨层，通常流向表现层）**：L2 规则层在完成一次伤害结算后发布 `combat.damage_dealt` 事件；L5 表现层的 `FeedbackBinder` 订阅该事件，据此播放飘字、特效与音效，全过程不发生直接契约调用。
3. **策略注入回调（游戏层向下插入实现，运行时向上回调）**：游戏层实现一个自定义的目标选择策略并注册到 L2 规则层的 `TargetHost` 策略表中；运行时 `TargetHost` 在需要解析目标时通过契约接口回调这个游戏层提供的实现，属于"架构定义挂载点、游戏层提供实现"的合法反向依赖。

## 9. 基础架构提供 / 游戏层提供

| 基础架构提供 | 游戏层提供 |
|---|---|
| 七层结构、依赖规则矩阵、禁止事项清单 | 遵守规则的具体游戏层代码与数据 |
| 每层的模块契约接口与数据表结构 | 契约接口对应的数据行与资源 |
| 事件总线与统一事件命名规范 | 具体订阅哪些事件、如何响应 |
| 策略挂载点（目标选择、优先级表、命中表等） | 具体策略配置或自定义策略实现 |
| HookRegistry 挂载点清单 | 挂载点上的具体回调实现 |

## 10. 验收标准

- 七层编号、名称、内容口径统一，未出现改名或合并层。
- 依赖规则矩阵覆盖全部 7×7 组合，且与"依赖只允许从高层到低层""L5 只读""除 L-1 外不得直接调用引擎"三条约束一致。
- 模块清单覆盖第 1 节列出的全部模块，每个模块都给出目录名、职责、契约接口名、数据表、事件、策略配置项六项内容。
- 游戏层边界给出"必须提供/允许做/禁止做"三张清单，且与 00 篇的目标一致。
- ASCII 图包含引擎适配层、事件总线、契约连线与游戏层贯穿四个要素。
- 跨层调用三种合法方式各给出一个具体、可追溯到模块清单的例子。
- 全文没有出现与本文档集其它章节冲突的层名、目录名或 id 规范。
