## 1. 总则

### 1.1 规格书与 `display.map` 的关系

本规格书每一节规格最终都要落到 [04_数据与内容管线.md](04_数据与内容管线.md) 第 7.1 节 `display.map`（或其展开表）的具体字段上；资产导入工具（见第 11 节）读取按本规格书产出的资源与标注，自动生成下表右列字段的数据行：

| 规格类别（本文档章节） | 对应字段 / 表 |
|---|---|
| 精灵集与方向（第 2 节） | `display.map`（`kind: sprite`）的 `sprite_set_id`、`direction_count`、`mirror_pairs` |
| 纸娃娃层（第 3 节） | `display.map`（`kind: sprite`）的 `paperdoll_layers` |
| 锚点（第 4 节） | `display.map`（`kind: sprite`）的 `anchor_points` |
| 影子（第 5 节） | `display.map`（公共字段）的 `shadow` |
| 场景排序偏移 | `display.map`（公共字段）的 `sort_offset` |
| 图标（第 7 节） | `display.map`（公共字段）的 `icon_id` |
| 特效（第 6 节） | `display.map` 的 `vfx_id`，展开定义见 `vfx.def`（09 第 5.1 节） |
| 音效与音乐（第 8 节） | `display.map` 的 `sfx_id`，展开定义见 `sfx.def`（09 第 5.2 节） |
| 武器表现（挥舞/命中特效等） | `display.map` 的 `weapon_style_ref`，展开定义见 `display.weapon_style`（09 第 4.4 节） |
| model 型槽位/挂点/换装（若该游戏选用 `model` 型外形，见 13 口味配置清单） | `display.map`（`kind: model`）的 `sockets`、`slots`、`default_slot_meshes`；`display.anim_set`（04 第 7.1.1 节）；`display.equip_visual`（04 第 7.1.2 节） |

本框架默认表现路线是 `sprite` 型外形（见 13 口味配置清单"外形类型"一项），本规格书第 2～4 节按此默认路线展开；游戏若选用 `model` 型外形，槽位/挂点/换装的结构规则已在 09 第 3.3.2 节与 04 第 7.1.1、7.1.2 节定义，本规格书不重复展开，仅在上表登记对应关系。

勘误（[ADR-0017](adr/0017-模型型外形默认路线补齐与命中帧同步.md) 决策 b）："默认表现路线"仅指本规格书的默认展开路线（第 2～4 节按 `sprite` 型展开），不代表 `model` 型外形是次等选项：表现层的 `model` 型 `CharacterRig`（槽位/挂点管理、程序动画原语映射）已是框架提供的真实实现，与 `sprite` 型对等；游戏选用 `model` 型外形后，需要投入的是该表选用 `model` 型行对应的具体美术资源（模型、骨骼动画、槽位网格等）与引擎适配层对 `IRenderer3D` 的真实实现，不是表现层胶水代码。

### 1.2 命名规则

**资源引用 id**（`sprite_set_id`、`icon_id`、`model_ref`、`vfx.def`/`sfx.def` 的 `resource_ref` 等，均为"由引擎适配层解析的不透明字符串"，见 04 第 7.1 节字段说明）不属于 04 第 2.2 节的固定内容域名清单——那份清单约束的是技能/物品/生物等逻辑记录的 id 归属域，走新增域名审批；资源引用 id 是另一套命名空间。本规格书建议其书写沿用 04 第 2.1 节的点分格式，并使用资源类别前缀保持可读性（例如 `sprite.`、`icon.`、`model.`、`anim.`、`mesh.` 等，`vfx.`/`sfx.` 本身已是 04 登记的内容域，二者语义统一），具体前缀集合与命名细节由每款游戏在其接入记录中定义，不需要走 04 第 2.2 节的域名审批流程。勘误（2026-09-08，见 02 第 1.7 节"`mesh_ref` 资源合同"）：`mesh.` 前缀只是本节建议的可读性写法，不代表一个独立的引擎适配层资源种类——`display.equip_visual.mesh_ref`（04 第 7.1.2 节）实际与 `model_ref` 共用同一条资源种类与磁盘路径约定（见下"model 型外形专属"小节"槽位网格资源合同"）。



**磁盘布局（导入工具实际产出，权威）**：资产导入工具落地资源时，方向档位与层名各自展开为一级
目录，不拼进文件名——`<sprite_set 输出目录>/<direction_slot>/<layer_id>.<扩展名>`（多层/纸娃娃）
或 `<sprite_set 输出目录>/<direction_slot>.<扩展名>`（单层，无 `paperdoll_layers`）；序列帧动画
（特效等）同理按 `<name>/frame_<三位帧序号>.<扩展名>` 逐帧落盘，并额外打包出一张 `atlas.png` +
索引 `atlas.json`。目录模板与命名细节以 [`toolchain/README.md`](../toolchain/README.md)"资产
导入工具"一节、`toolchain/asset_import/` 各子命令实现为准，本节不重复维护实现级路径规则。

**资源引用 id → 扁平文件名（打包后可选形态）**：引擎适配层把某些资源种类的资源引用 id
解析为磁盘路径时，可以选择把方向档位/层名/帧序号拼进单个扁平文件名而不是嵌套目录（例如
纸娃娃层运行期资源 id 形如 `layer.<sprite_set 裸名>__<direction_slot>__<layer_id>`，见
`adapters/` 引擎适配层"资源 id → 路径规则"对该类别的处理），这是资源引用 id 自身的编码形态、
供不便按目录嵌套组织资源的打包/引擎侧管线选用，不是导入工具在磁盘上产出的默认布局。扁平命名
模板（按"去掉类别前缀的剩余部分（点号换下划线） + 方向档位（若适用） + 层名（若适用） + 帧
序号（若适用）"顺序拼接）：

```
<资源引用id去掉类别前缀，点号换下划线>[__<方向档位id>][__<层id>][__<三位帧序号>].<扩展名，具体格式见选型 02>
```

示例（沿用 09 第 7.1 节 `display.map` 示例记录 `sprite_set_id: sprite.creature.wolf_grey`）：该
精灵集在方向档位 `front` 下、纸娃娃层 `body` 对应的扁平资源引用名为
`creature_wolf_grey__front__body`（磁盘上导入工具产出的实际路径是
`.../wolf_grey/front/body.<位图扩展名>`，二者按同一份"去掉类别前缀、点号换下划线"规则一一对应，
只是嵌套层级从目录换成了双下划线）；若该层还是一段序列帧动画的第 3 帧，扁平形态追加帧序号段
`creature_wolf_grey__front__body__002`（帧序号从 0 起）。

## 2. 精灵与方向

### 2.1 框架固定项

- 方向档位数量默认 **8**，允许 4 或 16（对应 04 `display.map.direction_count` 枚举 `4|8|16`，见 09 第 3.2 节、13 口味配置清单）。
- 方向档位命名沿用 09 第 3.2 节镜像规则表的档位族：`front`、`front_side`、`side`、`back_side`、`back`。8 方向默认下，`front`、`back` 各为独立档位（左右对称，无需镜像），其余三个档位族各拆出 `_r`（原创绘制）与 `_l`（镜像得到）两个具体档位，共 8 个：

  | 档位族 | 具体档位 id | 是否原创绘制 | `mirror_of` |
  |---|---|---|---|
  | front | `front` | 是 | — |
  | front_side | `front_side_r` | 是 | — |
  | front_side | `front_side_l` | 否（镜像） | `front_side_r` |
  | side | `side_r` | 是 | — |
  | side | `side_l` | 否（镜像） | `side_r` |
  | back_side | `back_side_r` | 是 | — |
  | back_side | `back_side_l` | 否（镜像） | `back_side_r` |
  | back | `back` | 是 | — |

  4 方向下只保留 `front`、`side_r`、`side_l`（镜像 `side_r`）、`back`；16 方向在每两个相邻档位族之间插入过渡档位，命名与镜像方式按同一模式延伸，具体新增档位 id 由游戏侧登记。
- 镜像规则字段结构与 09 第 3.2 节镜像规则表一致（`direction_slot`/`mirror_of`/`flip_x`），对应 `display.map.mirror_pairs`。
- 序列帧的帧序号从 0 起按播放顺序编号，写入文件名帧序号段（见第 1.2 节命名模板）；`clipId` 与图集切图的对应关系见 09 第 4.5 节 `FrameAnimPlayer`。
- 方向档位在数据表与运行期以 `dir.<档位名>` 形式作为标识（满足 00 第 4.1 节标识格式），文件名、标注文件与导入工具中使用不带前缀的档位名，两者一一对应，前缀在档位名进入标识字段时补上。

## 3. 纸娃娃

### 3.1 框架固定项

- **层清单**：`body`、`head`、`hair`、`chest`、`legs`、`hand_main`、`hand_off`、`back`、`effect_overlay` 是框架给出的**建议默认层集合**，对应 `display.map.paperdoll_layers`；由游戏按实际换装深度裁剪增减，不强制全部启用。
- **叠放顺序的互换规则**：`hand_main`、`hand_off`、`back` 三层的层内 z 序在"面向镜头"方向族（`front`/`front_side`）与"背对镜头"方向族（`back`/`back_side`）之间必须互换——武器/背部物件在角色面向镜头时应画在身体前方，在角色背对镜头时应画在身体后方；本规格书固定这条互换规则本身，具体每层数值由下表填写。
- **画布对齐要求**：同一逻辑对象的全部纸娃娃层必须使用相同画布尺寸、相同原点，任意层组合叠放时无需额外位移即可对齐；这是 09 第 3.3.1 节"每层声明一个锚点、跨层复用同一套锚点偏移"的前提。
- **透明与描边一致性**：各层边缘的透明通道处理方式与描边风格必须跨层统一，避免组合后出现视觉接缝。

## 4. 锚点

### 4.1 框架固定项

- **锚点清单**：`root`、`hand_main`、`hand_off`、`head`、`chest`、`feet`、`overhead` 是框架建议的默认集合，对应 `display.map.anchor_points` 的 key 集合，供特效挂点、头顶信息（伤害飘字/姓名牌）、装备挂接使用；游戏按需裁剪增减。
- **标注方式（机制）**：锚点坐标由资产导入工具从原始出图产物的标注图层或独立标注文件中读取，自动写入 `anchor_points`/`offset_by_direction` 字段，不由内容作者手填坐标数值（呼应 11 第 2.1 节导入工具职责与 [ADR-0014](adr/0014-资产契约导入工具与UI套件是框架交付物.md)"外形表行由工具生成而非手填"）；标注图层/标注文件的具体格式由资产导入工具实现决定，本规格书只约束"标注驱动、非手填"这条机制，不约束具体标注载体格式。

### 4.3 model 型外形专属：挂点/槽位/动画事件命名约定（W6-B 新增，见 [ADR-0017](adr/0017-模型型外形默认路线补齐与命中帧同步.md)）

#### 4.3.1 框架固定项

- **命名一致性（机制）**：三维模型美术资产内部的挂点/槽位对象命名，必须与 `display.map.sockets`/
  `display.map.slots` 登记的 id **逐字相等**（含类别前缀 `socket.`/`slot.`，不做任何"去前缀/转换"
  处理）——引擎适配层按这个精确名字在美术资产内部查找对应挂点/槽位，命名不一致会导致该挂点/槽位
  在运行期查不到（表现层"缺表现资源不阻断游戏"的一贯宽容策略下静默跳过，不阻断，但也不会生效）。
- **命中帧标记名（机制）**：`display.anim_set.clips[*].events[*].name` 取值 `"hit_frame"` 是框架
  固定识别的命中帧标记（与 sprite 型序列帧剪辑的命中帧标记同一个名字，09 第 4.3 节），其余事件名
  由游戏自定义，具体触发的表现效果由该游戏自己的反馈绑定规则决定；`time_pct` 取值范围
  `[0, 1]`（0＝剪辑开始，1＝剪辑结束）。
- **动画集剪辑名清单**：与 sprite 型序列帧默认动画状态同一套建议集合——`idle`/`move`/`attack`/
  `cast`/`hit`/`death`（09 第 4.2 节 `AnimState` 七态，`jump` 未在建议集合中默认要求，按需追加），
  对应 `display.anim_set.clips` 的键。
- **槽位网格资源合同（勘误，2026-09-08，第九方审核 `architecture/落地计划/audit-85f1f4f-20260908/`
  AUD-05 根治，见 02 第 1.7 节）**：`display.equip_visual.mesh_ref`（04 第 7.1.2 节，`mode: slot_mesh`
  时必填）与 `model_ref` 共用同一条资源种类与磁盘路径约定——填写时既可以直接复用某个模型资源引用
  id（引擎适配层从该模型预制体上与槽位 id 同名的子对象提取网格），也可以是一个独立的网格资源引用
  id（无对应预制体、只有网格本身）；不需要也不应该给它单独发明一套资源种类或目录约定。
- **关键帧事件合并与按 anim_set 隔离（勘误，2026-09-08，同上审核"动画剪辑事件登记契约差异"根治）**：
  多个 `display.anim_set` 引用同一份剪辑资源（同一"剪辑资源引用"列取值）时，允许各自声明不同的
  "关键帧事件"——引擎适配层负责把每个 `display.anim_set` 各自登记的事件与该剪辑资产原有（美术
  自带）的事件合并、并按 anim_set 隔离生效范围，不需要游戏内容层为了规避"共享剪辑事件互相覆盖"
  而被迫给每个 anim_set 各自复制一份剪辑文件；游戏填写项按每个 anim_set 各自真实需要的事件配置
  填写即可。

## 5. 影子与高度

### 5.1 框架固定项

`shadow` 字段三种模式（`display.map.shadow`，见 04 第 7.1 节、09 第 3.4 节）：`none`（不渲染）、`blob`（贴地简化影子）、`projected`（投影阴影）。影子锚定逻辑平面坐标，不随高度位移；高度偏移（跳跃、击飞等）只平移精灵纵向绘制位置，不平移影子（09 第 3.4 节）。

`shadow` 字段不属于第 11 节"导入工具契约"里"标注驱动、自动生成"的那部分——它不经出图产物或
标注文件推导，而是由资产导入工具的命令行参数直接指定（如 `sprite` 子命令的 `--shadow` 选项）
写入 `display.map`，本质是游戏层显式填写的一项配置，只是恰好也经同一个导入工具落地。

| 字段 | 说明 | 值 |
|---|---|---|

| 影子尺寸比例 | 相对第 2 节"角色基准尺寸"的宽高比例 | `<待填>` |
| 基础透明度 | `<待填>` |
| 高度联动规则 | 高度偏移增大时影子是否同步缩小/降低透明度以增强离地感，及具体曲线 | `<待填>`（框架建议：随高度增大适度缩小并降低透明度，具体数值由游戏定） |

  - 缺锚点：声明需要的锚点（`display.map.anchor_points`）在标注中缺失；
  - 尺寸不符：产出尺寸与本规格书登记的规格（第 2、6、7、9 节各表）不一致，含同一精灵集同一层跨方向档位尺寸必须一致这条附加约束；
  - 引用不存在：生成的资源引用 id 在对应数据表中找不到落点，或反向指向的逻辑 id 不存在（涵盖 `sprite_set_id`/`icon_id`/`vfx.def`/`sfx.def` 的 `resource_ref`/`variants` 对应文件是否存在）；
  - 方向档位缺失且无镜像回退：某方向档位既未提供原创美术，也未在 `mirror_pairs` 中声明镜像来源，导致该方向无法渲染；已声明的镜像来源本身也必须已落地，不能指向一个同样缺失的方向档位（对应 09 第 3.2 节镜像规则表）；
  - 地图引用不存在：`world.map` 引用的地图分层图（第 9 节必需分层）在交付目录下缺失。

## 基础架构提供 / 游戏层提供

| 能力 | 基础架构提供 | 游戏层提供 |
|---|---|---|
| 本规格书的章节结构与字段清单 | 是 | 否，不得自行增删架构级规格类别 |
| 命名规则与目录模板的机制 | 是 | 具体前缀集合、子目录内文件组织细节 |
| 各类资产"游戏填写项"的字段位 | 是（字段位固定） | 具体数值（尺寸、像素比、响度基准、配色映射等） |
| 与 `display.map`/`display.anim_set`/`vfx.def`/`sfx.def` 等表字段的对应关系 | 是 | 具体数据行 |
| 导入工具的输入输出契约与校验项定义 | 是 | 导入工具的具体实现、具体校验阈值 |
| 具体美术/音频资源本身 | 否 | 是 |

## 验收标准

1. 任取本规格书第 2～9 节中的一条"游戏填写项"，能在该游戏的接入记录中找到对应的具体取值，不存在"规格书要求填但实际未填"的空缺。
2. 给定一份符合本规格书目录模板（第 10 节）与命名规则（第 1.2 节）的原始出图产物，资产导入工具能够无需人工改名/挪位置直接读取并生成对应的 `display.map` 数据行。
3. 任取一个启用了方向精灵集的逻辑对象，其 `direction_count` 对应的全部方向档位（含镜像）在渲染时都有画面，不存在"某方向空白"的情况（对应第 11 节镜像回退校验项）。
4. 任取一个纸娃娃层集合的换装组合，各层在同一画布同一原点对齐，肉眼核查无接缝错位（对应第 3 节画布对齐要求）。
5. 任取一条 `vfx` 记录，其 `attach_mode` 与实际交付的特效素材形态（贴图序列/独立模型/屏幕空间贴图）一致，不存在世界坐标特效却按屏幕空间尺度制作一类的错配（对应第 6 节）。
6. 全部音效/音乐素材经响度检测落在本规格书登记的响度基准容差范围内（对应第 8 节）。
7. 用规格书流程从出图到资产导入工具生成外形表数据行全程可计时，且不需要任何人工手填 `display.map` 字段（对应第 11 节输出定义）。
