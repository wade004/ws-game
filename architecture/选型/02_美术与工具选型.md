- 本地已装：git、Python 3.13、Pillow、.NET 运行时；勘误 2026-09-06——落地阶段已补齐 Unity Hub + Unity 6 LTS（实际 6000.3.23f1）与 .NET SDK（`Core.sln` 六个核心类库工程与 `adapters/unity` 引擎适配层工程均已跑通构建与测试，见 `architecture/落地计划/落地方案与分阶段计划.md` 进度记录）。
- 待装：抠图模型（`rembg` 已拆到 `toolchain/requirements-optional.txt`，本地是否已装权重未在本次审计范围内核实）。
- 备用（默认不用）：会话内第三方云端生成工具，成本未核实，仅在本地管线明确无法满足时才评估启用。

## 3. 重新评估触发条件

出现以下任一情况时，应重新评估对应资产类别的工具选型：

- 抠图效果经批量验证仍达不到资产规格书要求的边缘精度，需要更换抠图模型或引入人工修图环节；
- 程序动画在实际内容量下表现力不足，序列帧试验证明 Wan 2.2 图生视频抽帧路线可行且成本可接受，需要正式引入并纳入本地已装清单；
- 音效/音乐占位方案撑到框架验收后，正式内容制作启动前需要落实本地开源音频/音乐生成模型或授权曲库的具体选型；
- 本地硬件升级或更换，导致原有工具的显存/算力假设失效，需要重新验证首选工具是否仍然可用。

## 4. 验收标准

1. 表中每一类资产都能对应到 [`01_引擎与语言选型评估.md`](01_引擎与语言选型评估.md) 或 ADR-0014 描述的某个资产管线环节，不存在游离于资产管线之外的工具条目。
2. 本地状态列如实反映 2026-09-04 当天的软硬件就绪情况，"待装"与"缺"两类条目在第 2 节的待装清单中均有对应项。
3. 第 3 节的重新评估触发条件具体、可判断，不是模糊的"如有需要"。
