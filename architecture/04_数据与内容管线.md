## 1. 数据表体系总览

"数据即内容"（第 4 节拍板决策 4）：游戏世界的一切具体内容——技能、光环、物品、生物、物件、掉落、任务、对话、成就……——都是结构化文本表里的行，运行时代码只认 id 与字段，不认具体内容。本节按所属层、所属模块列出全部数据表；每份下游文档（05～08）在讲对应模块时会重复给出该模块表的详细字段，本节只做总账与去重索引。

存储格式统一表述为"结构化文本表，格式待选型"，不预设具体序列化方式；每张表逻辑上是一组同构记录（行），每条记录以字段名到值的映射表示。

## 2. id 规范

### 2.1 格式

```
<domain>.<segment>(.<segment>)*
```

- `domain`：固定域名，小写字母与下划线，取自下方域名清单。
- `segment`：小写字母、数字、下划线组成的名字；可以是一段，也可以多级点分（用于表达子表种类与层级，如子分类、子键），同一 domain 下整体唯一。
- 整体不含大写字母、空格、连字符；点号只用于分隔 domain 与各级 `segment`。

### 2.3 合法与非法示例

合法：`skill.fireball`、`item.iron_sword_01`、`creature.grey_wolf_elite`、`quest.deliver_letter`、`skill.aura.burning`（多级 `segment`）、`world.bridge.repaired`（多级 `segment`）。

非法（反例与原因）：
- `Skill.Fireball`（含大写）
- `skill-fireball`（用连字符而非点号分隔 domain）
- `fireball`（缺 domain 前缀）
- `skill.法球`（含非 ASCII 字符；显示名走本地化文本键，id 本身必须是 ASCII）

### 2.4 文本键与世界标志键：多级命名的典型用法

本地化文本键（`l10n.<来源域>.<来源id去掉domain部分>.<字段名>`，详见第 7 节）与世界状态标志键（`world.<路径>`，可多级，详见 05）是 2.1 节多级 `segment` 命名的典型用法：前者需要唯一定位"某条内容记录的某个文本字段"，后者需要按剧情结构组织标志的层级路径。二者与其它多级 id 一样遵循 2.1 节的统一格式，不是单独的例外规则。

## 3. schema 版本与迁移

- 每张表携带 `schema_version`（Int），随表定义一起登记，随内容变化单调递增。
- 每次 `schema_version` 提升，同时登记一个迁移函数（逻辑上是"旧字段结构 → 新字段结构"的纯函数），迁移函数按版本号顺序串成迁移链。
- `DataRegistry` 加载一张表时，读取每条记录携带的（或表级统一的）版本号，若低于当前代码期望版本，依次应用迁移链，直至补齐到当前版本，再进入内存态。
- 迁移函数只做结构转换（补默认值、改字段名、拆分/合并字段），不做业务判断；业务含义变化必须新增字段而非复用旧字段语义。
- 迁移链只增不减：任何历史版本永远可迁移到最新版本，保证旧存档引用的旧内容 id 不因表结构升级而失效（存档细节见 10）。

字段表：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schema_version` | Int | 是 | 当前记录遵循的表结构版本号，从 1 起 |
| `migrated_from` | Optional<Int> | 否 | 若经过迁移，记录原始版本号，便于排查 |

记录主键约定（勘误补充）：内容表主键为 `id`（domain 前缀等于表名第一段，见第 2 节 id 规范）；跨 domain 的登记表（`found.event_catalog`、`found.input_action`、`l10n.text`）主键为 `key`，`l10n.text` 为 `key` + `locale` 复合键。

### 3.1 时间字段语义

时间模型（`continuous`/`discrete`，见 03、ADR-0013）是 L0 的可替换策略，探索与战斗各自声明。`found.time_model` 字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | Id | 是 | `found.time_model.<name>`，探索与战斗各自登记一条（对应 `exploration_time_model`、`combat_time_model`） |
| `scope` | `exploration\|combat` | 是 | 声明本条作用于探索还是战斗 |
| `mode` | `continuous\|discrete` | 是 | 时间模型：连续（固定步长，时间单位为秒）或离散（回合，时间单位为回合） |
| `seconds_per_turn` | Number | `mode: discrete` 时必填 | 连续/离散切换时刻的时间单位换算系数，默认 6 |
| `initiative_policy` | `initiative_stat\|action_points\|fixed_order\|atb` | `mode: discrete` 时必填 | 先攻策略；`atb` 为预留扩展位，本版不展开 |
| `initiative_stat` | Optional<Id> | `initiative_policy: initiative_stat` 时必填 | 指向 `stat.definition` 的先攻属性 id |
| `movement_budget_rule` | `distance\|action_points` | `mode: discrete` 时必填 | 离散模式下每回合移动预算的计算方式 |
| `grid_snap` | Optional<{cell_size: Number}> | 否 | 若启用格子吸附，声明格子尺寸；范围形状按格子中心采样 |

全部与时间相关的数据字段一律"以数据集声明的时间单位计"，不区分秒或回合两种表述方式，只按所属作用域当前声明的 `mode` 解释取值：`cast_time`、`channel_time`、`cooldown_duration`、`charges.recharge_time`、光环 `duration` 与周期 `interval`、资源 `regen`/`decay`、`respawn_timer`、脱战判定时长、`internal_cooldown`（字段定义均见 05、06）。作用域声明为 `discrete` 时，以上字段取值必须是整数（以回合计）；声明为 `continuous` 时按秒计，允许小数。

校验器新增一项（见第 5 节）："时间字段与时间模型一致"：某条记录所属作用域（探索/战斗）声明为 `discrete` 时，该记录引用到的全部时间字段必须是整数；声明为 `continuous` 时不做整数限制。

`stat.definition` 补充说明：先攻属性是一条普通属性，不是独立的字段类型，由 `found.time_model.initiative_stat` 引用；未被引用时该属性仍可正常参与三段式聚合（见 06）。

## 4. DataRegistry 接口

`DataRegistry` 是 L0 基础层暴露给全架构的唯一数据入口；除表现层的资源加载（经引擎适配层）外，任何模块读取内容一律经它。

```
interface DataRegistry {
  loadAll(): ValidationReport
  get<T>(domain: String, id: Id): Optional<T>
  getAll<T>(domain: String): List<T>
  query<T>(domain: String, predicate: Expr): List<T>
  validate(): ValidationReport
  declareReference(fromField: String, toDomain: String): void
  reload(domain: String): ValidationReport   // 可选：热重载，仅限开发期使用
}
```

- `loadAll()`：启动时一次性加载全部表、跑全部迁移、跑全部校验，返回报告；报告含错误项即视为不可进入游戏状态机的 `gameplay` 状态（见 03）。
- `get` / `getAll` / `query`：只读访问；`query` 的 `predicate` 用第 6 节的 Expr 语言表达，宿主上下文只暴露该记录自身字段（用于按字段筛选内容表，不同于运行时判定用的 Expr 求值）。
- `declareReference`：模块在注册期声明"我的哪个字段是指向哪个域的外键"，供校验器做引用完整性检查；例如 `skill.def.granted_by` 声明为指向 `item` 域。
- `reload`：（建议）仅用于开发期内容热更新，正式运行可关闭；不属于第 6 节校验的强制项。

## 5. 校验器检查项清单

校验器是内容提交门槛（拍板决策 4）：任何一项失败即视为本次内容变更不可合入。

| 检查项 | 说明 |
|---|---|
| 引用完整性 | 每个通过 `declareReference` 声明的外键字段，其值必须能在目标域找到记录，或显式声明为 `Optional` 且为空 |
| id 格式合法 | 每条记录的 id 符合第 2 节格式与所属域名 |
| 枚举合法 | 枚举字段的取值必须在该字段登记的合法枚举集合内 |
| 表达式可解析 | 所有 Expr 字段必须能被解析为合法语法树（不要求运行时求值为真，只要求语法合法且引用的 key 在对应宿主分组中存在登记）；点分标识符按第 6.3 节归类规则以引用登记表消歧为引用或 id 字面量，域名与分组同名但未登记的 id 字面量报"疑似引用拼写错误"警告（不阻断） |
| 效果数上限 | 单条 `skill.def` / `skill.aura_def` 的效果列表长度不超过配置的上限（策略配置项，默认建议值见 06） |
| 预算超标 | 具备数值预算公式的表（如物品等级预算，见 07）算出的预算值不超过对应等级/品质允许的上限 |
| 叠加类别冲突 | 同一叠加类别（见 06 光环叠加规则）下不得有两条效果同时要求互斥的叠加语义 |
| 外形映射存在 | 每个出现在 `display` 域引用集合中的逻辑 id（技能、光环、物品、生物、物件）必须在 `display.map` 中有对应行 |
| 外形类型字段组完整 | `display.map` 记录的 `kind` 字段决定的专属字段组（sprite 型或 model 型）必填项必须齐全，另一组字段必须留空（见 7.1） |
| 文本键存在 | 每个记录中标记为"文本键"类型的字段，其值必须能在 `l10n.text` 的默认语言下查到 |
| schema 版本已知 | 记录的 `schema_version` 必须落在该表已登记的迁移链范围内 |
| 循环引用检测 | 声明为树/链结构的字段（如天赋前置、对话节点分支）不得成环 |
| 孤儿记录检测 | （建议）不被任何已知入口引用的记录（如没有任何技能书引用的技能）报告为警告而非错误，便于清理 |
| 时间字段与时间模型一致 | 记录所属作用域的 `found.time_model.mode` 为 `discrete` 时，该记录的全部时间字段（见第 3.1 节）取值必须为整数 |

## 6. Expr 条件表达式语言

Expr 是全架构唯一的条件与表达式语言（拍板决策 5），触发条件、优先级表候选条件、掉落条件、任务前置、对话显隐、遭遇阶段切换、成就 criteria、刷新条件全部用它书写，任何宿主只需实现一个 `query(key, args)` 出口即可接入。

### 6.1 语法（BNF）

```
<expr>        ::= <or_expr>
<or_expr>     ::= <and_expr> ( "or" <and_expr> )*
<and_expr>    ::= <unary_expr> ( "and" <unary_expr> )*
<unary_expr>  ::= "not" <unary_expr> | <compare_expr>
<compare_expr>::= <term> ( <cmp_op> <term> )?
<cmp_op>      ::= "==" | "!=" | ">" | ">=" | "<" | "<="
<term>        ::= <literal> | <reference> | "(" <expr> ")"
<literal>     ::= <number> | <string> | "true" | "false" | <id_literal>
<reference>   ::= <group> "." <key> ( "(" <arg_list> ")" )?
<group>       ::= "self" | "target" | "event" | "world" | "quest" | "player" | "combat" | "enemies" | "time"
<arg_list>    ::= <term> ( "," <term> )*
```

- 无变量赋值、无循环、无自定义函数；表达式永远求值为 `Bool` 或可比较的标量，用于"是否满足条件"或"取某个数值再比较"两类场景。
- 括号仅用于改变优先级，不支持函数定义。
- `<reference>` 与 `<id_literal>`（内容 id 字面量，见第 2 节 id 格式）在语法形式上完全相同；一个点分标识符具体归类为哪一种，由宿主引用登记表在解析时消歧，不由 BNF 本身区分，详见第 6.3 节（[ADR-0015](adr/0015-Expr点分标识符以引用登记表消歧.md)）。

### 6.2 宿主引用分组（按用途）

| 分组 | 含义 | 示例引用 | 典型使用场景 |
|---|---|---|---|
| `self` | 表达式所属主体自身状态 | `self.hp_pct`、`self.has_aura(skill.aura.burning)` | 优先级表候选条件、光环叠加判断 |
| `target` | 当前目标状态 | `target.hp_pct < 0.3`、`target.faction == fac.wildlife` | 目标选择链筛选、任务前置 |
| `event` | 触发此次求值的事件携带的数据 | `event.damage_amount`、`event.school` | Proc 触发条件、成就 criteria |
| `world` | 世界状态标志 | `world.get(world.bridge.repaired)` | 刷新条件、对话显隐、区域触发 |
| `quest` | 玩家任务状态 | `quest.is_active(quest.deliver_letter)`、`quest.objective_progress(...)` | 任务前置、对话选项显隐 |
| `player` | 玩家角色数据 | `player.level >= 10`、`player.has_item(item.town_key)` | 任务前置、锁的开锁条件 |
| `combat` | 当前战斗/施法上下文 | `combat.in_combat`、`combat.cast_school` | 施法管线检查、公共冷却判断 |
| `enemies` | 周边敌对单位聚合信息 | `enemies.count_in_range(8)` | AI 行为外壳状态切换、遭遇阶段 |
| `time` | 时间与计时器 | `time.since_combat_start`、`time.day_cycle`、`time.turn_index`、`time.round_index`、`time.is_my_turn` | 遭遇阶段计时、刷新计时策略；`turn_index`/`round_index`/`is_my_turn` 仅离散模式下有意义（见 03、06） |

每个宿主实现只需要提供 `query(group, key, args) -> Value`，Expr 求值器不关心宿主内部实现，只负责把语法树按分组分发出去。

### 6.3 类型与求值规则

- 类型集合与接口记法一致：`Bool`、`Int`、`Number`、`String`、`Id`。
- 比较运算符两侧类型必须一致（`Id` 只支持 `==`/`!=`）；类型不一致视为解析期错误，校验器阶段即拒绝。
- `and`/`or` 短路求值；短路时被跳过的子表达式不触发对应 `query` 调用（避免访问不存在的目标等空引用）。
- 未登记的 `group.key` 组合在校验期报"未知引用"错误；运行期若引用的具体对象缺失（如 `target` 分组但当前无目标），`query` 返回该分组约定的默认值（`Bool` 默认 `false`，数值默认 `0`），并记录一条运行期警告，不中断调用方流程。
- 点分标识符的归类以宿主引用登记表为准：`<第一段>.<其余段>` 若在当前宿主的引用登记表中登记为 `group.key` 组合，解析为 `<reference>`；否则整体解析为 `<id_literal>`，须满足第 2 节 id 格式。内容校验期与运行期使用同一份引用登记表，保证同一段表达式文本在两处解析结果一致（[ADR-0015](adr/0015-Expr点分标识符以引用登记表消歧.md)）。校验器对此新增一条警告：当某个 `<id_literal>` 的域名段与九个分组之一同名、但对应的 `group.key` 组合未登记时，报"疑似引用拼写错误"（警告，不阻断合入）。

### 6.4 错误处理

| 阶段 | 错误情形 | 处理方式 |
|---|---|---|
| 解析期（内容提交时） | 语法错误、未知分组、未知 key、类型不匹配 | 校验器报错，内容不可合入 |
| 求值期（运行时） | 引用对象暂缺（如无目标） | 按分组默认值返回，记录警告，不抛异常 |
| 求值期（运行时） | 宿主 `query` 内部异常 | 视为该表达式求值为 `false`，记录错误日志，不影响其余系统 tick |

## 7. DisplayInfo 表字段与本地化

### 7.1 `display.map` 字段

公共字段（`sprite`/`model` 两种 `kind` 均适用）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | Id | 是 | `display.<逻辑id去掉domain前缀>` |
| `category` | `skill\|aura\|item\|creature\|gobj\|projectile` | 是 | 逻辑对象类别 |
| `logical_id` | Id | 是 | 指向的逻辑记录 id（技能/光环/物品/生物/物件） |
| `kind` | `sprite\|model` | 是 | 外形类型，决定下方哪组类型专属字段生效 |
| `icon_id` | String | 否 | UI 图标资源引用 |
| `vfx_id` | Optional<Id> | 否 | 指向 `vfx.def` |
| `sfx_id` | Optional<Id> | 否 | 指向 `sfx.def` |
| `scale` | Number | 否 | 默认缩放，默认 1.0 |
| `shadow` | `none\|blob\|projected` | 否 | 阴影呈现模式，默认 `blob`（详见 05、09；`model` 型经 `IRenderer3D.setShadow` 应用） |
| `sort_offset` | Number | 否 | 同一 `sortY` 下的排序微调偏移，用于区分前后景装饰物（详见 09 第 3.1 节），默认 0 |
| `weapon_style_ref` | Optional<Id> | 否 | 指向 `display.weapon_style`，供武器类物品经此行关联武器表现档案（详见 09 第 4.4 节） |

`kind: sprite` 型专属字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sprite_set_id` | String | 是（sprite 型） | 精灵集资源引用（不含路径，由引擎适配层解析） |
| `direction_count` | `4\|8\|16` | 是（sprite 型） | 方向量化档位（详见 05） |
| `mirror_pairs` | Optional<List<{direction_slot: Id, mirror_of: Id, flip_x: Bool}>> | 否 | 方向镜像规则：元素结构与 09 第 3.2 节镜像规则表一致 |
| `paperdoll_layers` | List<String> | 否 | 纸娃娃分层引用列表，仅 `item`/`creature` 使用（详见 09） |
| `anchor_points` | Map<String, Vec2> | 否 | 挂点定义，供特效/武器/头顶信息等对齐 |

`kind: model` 型专属字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `model_ref` | Id | 是（model 型） | 三维模型资源引用（不含路径，由引擎适配层解析） |
| `anim_set_ref` | Id | 是（model 型） | 指向 `display.anim_set`（详见 7.1.1） |
| `sockets` | List<Id> | 否 | 该模型声明的挂点 id 列表，供 `IRenderer3D.attachToSocket` 使用 |
| `slots` | List<Id> | 否 | 该模型声明的可换装槽位 id 列表，供 `IRenderer3D.setSlotMesh` 使用 |
| `default_slot_meshes` | Map<Id, Id> | 否 | 槽位 id 到默认网格资源引用的映射，未被 `display.equip_visual` 覆盖时使用 |
| `material_params` | Map<String, Number> | 否 | 材质参数默认值（闪白、溶解等），经 `IRenderer3D.setMaterialParam` 应用 |

校验规则：`kind` 决定哪组类型专属字段必填——`kind: sprite` 时 sprite 型字段组的必填项必须齐全，model 型专属字段一律留空；`kind: model` 时相反（详见第 5 节"外形类型字段组完整"检查项）。

示例记录（`kind: sprite`）：

```
id: display.grey_wolf
category: creature
logical_id: creature.grey_wolf
kind: sprite
sprite_set_id: sprite.creature.wolf_grey
direction_count: 8
icon_id: icon.creature.wolf_grey
sfx_id: sfx.wolf_growl
scale: 1.0
shadow: blob
sort_offset: 0
```

示例记录（`kind: model`）：

```
id: display.stone_golem
category: creature
logical_id: creature.stone_golem
kind: model
model_ref: model.creature.stone_golem
anim_set_ref: display.anim_set.stone_golem
icon_id: icon.creature.stone_golem
sfx_id: sfx.stone_golem_step
scale: 1.2
shadow: projected
sort_offset: 0
sockets: [socket.hand_main, socket.hand_off]
slots: [slot.weapon_main]
default_slot_meshes: {slot.weapon_main: mesh.golem_fist}
```

逻辑表（`skill.def`、`item.template` 等）只存 id，不存任何资源路径；新增一个外形只需在 `display.map` 加一行，运行时逻辑代码零改动。

### 7.1.1 `display.anim_set` 字段

动画集把一组动画剪辑 id 映射到资源引用与关键帧事件列表，供 `kind: model` 的外形驱动骨骼动画（详见 09 第 4 节）。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | Id | 是 | `display.anim_set.<名字>` |
| `clips` | Map<Id, {resource_ref: Id, events: List<{name: String, time_pct: Number}>}> | 是 | 剪辑 id 到资源引用与关键帧事件列表的映射；`time_pct` 是关键帧在剪辑内的时间百分比（0~1），`name` 为事件名（如 `hit`、`release`、`footstep`），经 `IRenderer3D.onAnimEvent` 回调 |

示例记录：

```
id: display.anim_set.stone_golem
clips:
  attack: { resource_ref: anim.stone_golem.attack, events: [{name: hit, time_pct: 0.6}] }
  move: { resource_ref: anim.stone_golem.move, events: [] }
```

### 7.1.2 `display.equip_visual` 字段

装备外观把一件装备映射到它在 `model` 型外形上的呈现方式：替换槽位网格，或作为独立模型挂接到挂点（详见 09 第 4.4 节）。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | Id | 是 | `display.equip_visual.<名字>` |
| `item_id` | Id | 是 | 指向 `item.template` |
| `mode` | `slot_mesh\|socket_attach` | 是 | 呈现方式：替换槽位网格，或挂接独立模型到挂点 |
| `slot_id` | Optional<Id> | `mode: slot_mesh` 时必填 | 目标槽位 id，对应 `display.map` 的 `slots` |
| `mesh_ref` | Optional<Id> | `mode: slot_mesh` 时必填 | 替换用网格资源引用 |
| `socket_id` | Optional<Id> | `mode: socket_attach` 时必填 | 目标挂点 id，对应 `display.map` 的 `sockets` |
| `model_ref` | Optional<Id> | `mode: socket_attach` 时必填 | 挂接的独立模型资源引用 |

### 7.2 本地化

- 文本键规范：`l10n.<来源域>.<来源记录name>.<字段名>`，例如任务标题 `l10n.quest.deliver_letter.title`。
- 语言表 `l10n.locale` 定义支持的语言 id 与回退链（例如某语言缺文本时回退到默认语言）。
- `l10n.text` 字段表：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `key` | String | 是 | 文本键，见上 |
| `locale` | Id | 是 | 语言 id |
| `text` | String | 是 | 正文，支持变量占位 |
| `schema_version` | Int | 是 | 见第 3 节 |

- 变量代入语法：正文中以 `{变量名}` 占位，运行时由调用方提供 `Map<String, String>` 做替换；变量名来自事件或表达式求值结果（如 `{target_name}`、`{amount}`），不支持嵌套表达式，替换失败（变量缺失）时原样保留占位符并记录警告。

## 8. "新增一个内容"标准流程

| 新增类型 | 改哪些表 | 加哪些资源 | 跑哪些校验 |
|---|---|---|---|
| 新技能 | `skill.def`；如带光环则加 `skill.aura_def`；如有触发则加 `skill.proc_def`；如需被学习加入 `skill.book` | `display.map` 加一行；如需文本则加 `l10n.text` 的技能名/描述键 | 引用完整性、效果数上限、外形映射存在、文本键存在、表达式可解析（若效果含条件） |
| 新光环 | `skill.aura_def`；若涉及叠加类别复用需检查既有类别 | `display.map`（若光环有独立图标/持续特效）、`l10n.text` | 叠加类别冲突、外形映射存在、文本键存在 |
| 新装备 | `item.template`；若属于套装则更新 `item.set` | `display.map`（外形与纸娃娃层）、`display.equip_visual`（model 型外形的槽位网格或挂点模型）、`l10n.text` | 引用完整性（授予的技能/光环存在）、预算超标、外形映射存在、外形类型字段组完整、文本键存在 |
| 新怪 | `creature.template`；如需专属掉落加 `loot.table`；如需专属 AI 加 `ai.rotation`/`ai.behavior_profile` | `display.map`、`l10n.text` | 引用完整性（AI/掉落/外形引用）、外形映射存在、文本键存在 |
| 新物件 | `gobj.template`；如需上锁加 `gobj.lock` | `display.map`（若有独立外观）、`l10n.text` | 引用完整性（on_use 指向的技能/对话存在）、外形映射存在、文本键存在 |
| 新地图 | `world.map`（详见 05）、按需加 `spawn.table` | 场景资源引用（由游戏层提供，架构只登记引用 id）、`l10n.text`（地图名） | 引用完整性（场景资源引用、出生点/传送点合法）、文本键存在 |
| 新任务 | `quest.def` | `dialog.gossip_menu` 中挂接接取/交付动作、`l10n.text`（标题、目标描述、对话文本） | 引用完整性（前置任务、奖励物品/技能存在）、表达式可解析（前置条件）、文本键存在、循环引用检测（前置链） |
| 新对话 | `dialog.gossip_menu` 或 `dialog.story_tree` | `l10n.text`（对话文本）、如涉及演出钩子则登记 `found.hook` 引用 | 引用完整性（动作指向的技能/任务/传送点存在）、表达式可解析（显隐条件）、文本键存在、循环引用检测（对话树分支） |
| 新成就 | `achv.def` | `display.map`（成就图标）、`l10n.text` | 引用完整性（观察事件已登记）、文本键存在 |

## 基础架构提供 / 游戏层提供

| 能力 | 基础架构提供 | 游戏层提供 |
|---|---|---|
| 表结构与字段定义 | 是（本文档登记的字段表） | 否，不得自行增删架构级字段 |
| DataRegistry 加载/校验/查询实现 | 是 | 否 |
| Expr 语法与求值器 | 是 | 提供宿主 `query` 实现的具体数据来源（如世界状态的具体标志集合） |
| id 域名清单 | 是（固定，新增域名走审批） | 域内具体 name 由游戏层内容作者填写 |

| 表现资源本身（精灵、音频等文件） | 否，只提供 `display.map` 结构 | 是 |
| 本地化文本正文 | 提供文本键规范与求值/回退机制 | 提供各语言正文 |

## 验收标准

1. 全部表在第 1 节总索引中有登记，且下游文档（05～09）中出现的表名与此表一一对应，无遗漏无冲突。
2. 任取架构文档中出现的任意一个内容 id，能唯一定位其 domain 并在第 2.2 节域名清单中找到归属。
3. `DataRegistry` 接口签名可被任一模块契约引用而不需要额外说明。
4. 校验器清单中的每一项都能用一句话说清"检查什么、什么情况下判定失败"。
5. Expr 的 BNF 可以推导出本文档及 05～08 中出现的所有示例表达式。
6. "新增一个内容"表中的九类改动，任一类都不涉及修改运行时代码，只涉及加表行与加资源引用。
