## 1. 数据表体系总览

"数据即内容"（第 4 节拍板决策 4）：游戏世界的一切具体内容——技能、光环、物品、生物、物件、掉落、任务、对话、成就……——都是结构化文本表里的行，运行时代码只认 id 与字段，不认具体内容。本节按所属层、所属模块列出全部数据表；每份下游文档（05～08）在讲对应模块时会重复给出该模块表的详细字段，本节只做总账与去重索引。

存储格式统一表述为"结构化文本表，格式待选型"，不预设具体序列化方式；每张表逻辑上是一组同构记录（行），每条记录以字段名到值的映射表示。

## 2. id 规范

### 2.1 格式

```
<domain>.<segment>(.<segment>)*
```

- `domain`：固定域名，小写字母与下划线，取自下方域名清单。
- `segment`：小写字母、数字、下划线组成的名字；可以是一段，也可以多级点分（用于表达子表种类与层级，如子分类、子键），同一 domain 下整体唯一。
- 整体不含大写字母、空格、连字符；点号只用于分隔 domain 与各级 `segment`。

### 2.3 合法与非法示例

- `Skill.Fireball`（含大写）
- `skill-fireball`（用连字符而非点号分隔 domain）

- `skill.法球`（含非 ASCII 字符；显示名走本地化文本键，id 本身必须是 ASCII）

### 2.4 文本键与世界标志键：多级命名的典型用法

## 3. schema 版本与迁移

- 每张表携带 `schema_version`（Int），随表定义一起登记，随内容变化单调递增。
- 每次 `schema_version` 提升，同时登记一个迁移函数（逻辑上是"旧字段结构 → 新字段结构"的纯函数），迁移函数按版本号顺序串成迁移链。
- `DataRegistry` 加载一张表时，读取每条记录携带的（或表级统一的）版本号，若低于当前代码期望版本，依次应用迁移链，直至补齐到当前版本，再进入内存态。
- 迁移函数只做结构转换（补默认值、改字段名、拆分/合并字段），不做业务判断；业务含义变化必须新增字段而非复用旧字段语义。
- 迁移链只增不减：任何历史版本永远可迁移到最新版本，保证旧存档引用的旧内容 id 不因表结构升级而失效（存档细节见 10）。

字段表：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schema_version` | Int | 是 | 当前记录遵循的表结构版本号，从 1 起 |
| `migrated_from` | Optional<Int> | 否 | 若经过迁移，记录原始版本号，便于排查 |

记录主键约定（勘误补充）：内容表主键为 `id`（domain 前缀等于表名第一段，见第 2 节 id 规范）；跨 domain 的登记表（`found.event_catalog`、`found.input_action`、`l10n.text`）主键为 `key`，`l10n.text` 为 `key` + `locale` 复合键。

### 3.1 时间字段语义

时间模型（`continuous`/`discrete`，见 03、ADR-0013）是 L0 的可替换策略，探索与战斗各自声明。`found.time_model` 字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | Id | 是 | `found.time_model.<name>`，探索与战斗各自登记一条（对应 `exploration_time_model`、`combat_time_model`） |
| `scope` | `exploration\|combat` | 是 | 声明本条作用于探索还是战斗 |
| `mode` | `continuous\|discrete` | 是 | 时间模型：连续（固定步长，时间单位为秒）或离散（回合，时间单位为回合） |
| `seconds_per_turn` | Number | `mode: discrete` 时必填 | 连续/离散切换时刻的时间单位换算系数，默认 6 |
| `initiative_policy` | `initiative_stat\|action_points\|fixed_order\|atb` | `mode: discrete` 时必填 | 先攻策略；`atb` 为预留扩展位，本版不展开 |
| `initiative_stat` | Optional<Id> | `initiative_policy: initiative_stat` 时必填 | 指向 `stat.definition` 的先攻属性 id |
| `movement_budget_rule` | `distance\|action_points` | `mode: discrete` 时必填 | 离散模式下每回合移动预算的计算方式 |
| `grid_snap` | Optional<{cell_size: Number}> | 否 | 若启用格子吸附，声明格子尺寸；范围形状按格子中心采样 |
| `action_points_per_turn` | Number | 否 | `initiative_policy` 或 `movement_budget_rule` 任一为 `action_points` 时，两者共享同一份每回合行动点总额度，默认 1 |
| `movement_action_cost_per_unit` | Number | `movement_budget_rule: action_points` 时必填 | 移动 1 单位距离消耗的行动点数 |

全部与时间相关的数据字段一律"以数据集声明的时间单位计"，不区分秒或回合两种表述方式，只按所属作用域当前声明的 `mode` 解释取值：`cast_time`、`channel_time`、`cooldown_duration`、`charges.recharge_time`、光环 `duration` 与周期 `interval`、资源 `regen`/`decay`、`respawn_timer`、脱战判定时长、`internal_cooldown`（字段定义均见 05、06）。作用域声明为 `discrete` 时，以上字段取值必须是整数（以回合计）；声明为 `continuous` 时按秒计，允许小数。

勘误（2026-09-10，ADR-0022，消费方反馈第二批第 15 条）：以上这份"时间字段名清单"是面向人的说明，不再是唯一权威来源——权威来源是第 3.4 节 `FieldSchema.Unit`/`TableSchema.TimeScope` 登记表本身；本清单与登记表不一致时以登记表为准，且门禁会检查两者不发生单边漂移（见第 5 节"时间字段清单防遗漏"）。

校验器新增一项（见第 5 节）："时间字段与时间模型一致"：某条记录所属作用域（探索/战斗）声明为 `discrete` 时，该记录引用到的全部时间字段必须是整数；声明为 `continuous` 时不做整数限制。

`stat.definition` 补充说明：先攻属性是一条普通属性，不是独立的字段类型，由 `found.time_model.initiative_stat` 引用；未被引用时该属性仍可正常参与三段式聚合（见 06）。

### 3.2 复合字段子结构登记

第 1 节表清单登记的复合字段（`Object`/`Array` 两种字段种类）此前只做"存在且类型匹配"检查，具体结构留给使用方自行解释。本节补充一种可选的机器可读子结构登记，使已登记的复合字段获得与标量字段同等强度的结构校验；未登记的复合字段行为保持不变。

**登记记法**

字段登记（第 1 节字段表的每一行）新增三个互斥的可选属性，仅对 `Object`/`Array` 两种字段种类生效，不新增字段种类：

- `fields: List<字段登记>` —— 仅 `Object` 字段可用：列出该对象的子字段清单，每个子字段本身又是一条完整的字段登记（含类型、必填、枚举、引用、表达式等既有语义），可递归嵌套 `Object`/`Array`。
- `item: 字段登记` —— 仅 `Array` 字段可用：给出数组元素的结构，元素可以是标量、引用，也可以是 `Object`/`Array`。
- `variants: { discriminator: 字段名, cases: Map<取值, List<字段登记>> }` —— 用于同一处 `Object` 需要按某个判别字段的取值分派到不同子字段结构的场景（如一个效果条目按其类型字段决定还有哪些参数）：`discriminator` 是同一层级内某个判别字段的名字，`cases` 的每个键是该判别字段的一个合法取值、值是该取值下生效的子字段清单；`cases` 的键集合即判别字段的合法枚举取值集合，登记 `variants` 等价于同时登记了对判别字段的一次枚举校验。`variants` 与 `fields` 互斥（一个 `Object` 字段要么是固定子字段清单，要么是按判别字段分派的变体，不同时登记两者）。

三者均为可选：不登记时，该字段的校验行为与登记前完全一致（只检查"存在且类型是 Object/Array"），属向后兼容的补充登记。

**登记与校验同源**

已登记子结构的复合字段，其结构检查由登记递归展开：子字段/元素/变体分支各自的必填、类型、枚举、引用完整性、表达式可解析，全部按第 5 节既有校验项对递归到的每一层字段登记生效，不需要为每种复合结构另写一条手工校验规则。各模块原有的手写结构校验规则只保留登记表达不了的业务判断（如数值预算超标、叠加类别冲突、循环引用一类跨记录/跨字段的语义检查），结构本身的检查以登记为唯一权威。

**变体与原语注册的一致性**

某些复合字段的判别字段取值集合，本身就是某种"原语"的注册表（如一种效果类型、一种光环类型，见 12 第 2 节"新增原语审批流程"）。新增一种这样的原语时，登记其对应变体分支是"再改注册表"这一步的必做项（见 12 第 2 节）；`variants.cases` 的键集合必须与运行时实际注册的该类原语集合保持一致，第 5 节新增校验项"变体表与原语注册集合一致"检查这一点，避免登记表与运行时注册表出现单边漂移。

**示例：`skill.def.effects` 的三个变体**

`skill.def.effects`（技能效果列表，字段种类 `Array`）的元素登记为按判别字段 `kind` 分派的 `variants`，以下给出其中三种取值作为记法示例（其余取值同一模式登记，见本节末尾"首批登记范围"）。

勘误（2026-09-09，F1a 落地对齐）：本节初版示例把变体每个取值下的字段清单直接当成元素本身的子字段，遗漏了元素的真实形状 `{kind, params: {...}}` 里 `params` 这一层——变体分派命中的字段清单登记在 `params` 内部，不是元素顶层；下例已改正，并把 `display_ref`/`speed`/`max_range` 等按落地时对照运行时解析代码核对后的必填/类型改正（原始 04 号文档定稿时未逐参数对照实现，`speed`/`max_range` 实际有引擎侧缺省值、`display_ref` 因跨层引用限制退回 `Id`，见下）：

```
skill.def.effects: Array
  item: Object
    variants:
      discriminator: kind
      cases:
        school_damage:              // 按加成系数结算的伤害/治疗类效果
          - params: Object
              - base_value: Number, 必填=否
              - coefficient: Number, 必填=否
              - school: Id, 必填=否           // 缺省取技能自身 school
              - scaling_stat: Reference, 必填=否
        apply_aura:                 // 施加一个光环
          - params: Object
              - aura_def: Reference, 必填=是
              - duration_override: Number, 必填=否
        projectile:                 // 发射一枚弹道，并按弹道结果触发后续效果
          - params: Object
              - travel_mode: Enum(straight|arc|homing), 必填=否   // 缺省 straight
              - hit_behavior: Enum(impact_on_first|pierce|impact_on_expiry), 必填=否   // 缺省 impact_on_first
              - speed: Number, 必填=否   // 缺省取引擎侧配置项
              - max_range: Number, 必填=否   // 缺省取引擎侧配置项
              - impact_radius: Number, 必填=否
              - max_pierce_count: Int, 必填=否
              - display_ref: Id, 必填=否   // 跨层引用限制：display.map 属更上层，本层不可 Reference，见下"分层边界"
              - on_hit_effects: Array, 必填=否   // 元素结构递归引用本 variants（弹道命中后触发的后续效果，同样按 kind 分派）
```

上例中 `on_hit_effects` 的元素结构与 `skill.def.effects` 本身共用同一份 `variants` 登记（同一种效果原语注册表在两处复用），体现"登记一次、多处复用"的记法意图，不需要为嵌套场景另建一份变体表；实现级登记用 `Func<字段登记>` 一类惰性求值的中立记法表达（首次被访问时才求值并缓存），避免"登记 A 需要先构造出登记 A 自身"的构造期死锁，递归深度设一个有限上限，超过判定为一条独立的校验错误（见第 5 节新增行）。`CommonFields`（全部取值共有的子字段，判别字段本身不必重复登记）与某个具体取值的字段清单在校验期合并成该取值下生效的完整子字段清单一起递归检查，不是各自独立校验。

**分层边界**：某个变体分支的字段若要登记为 `Reference`，目标表必须属于本字段所在层或更下层（依赖方向单向，见 01）；`create_item`/`summon` 分别想引用的物品/生物模板表、`projectile` 想引用的外形映射表都属于更上层，本层不可 `Reference`，一律退回 `Id`（只做格式校验，不做跨表存在性检查，同本节"变体与原语注册的一致性"上一段"04 §5.1 校验覆盖矩阵"口径）；待目标表后续下沉或改用其它消歧方式时再升级。

**首批登记范围**

按对内容作者与工具（编辑器、文档生成、差异比对）的价值排序，分批登记，首批覆盖：`skill.def.effects`（技能效果，多种变体）、`skill.aura_def.effects`（光环效果，多种变体）、`skill.proc_def`/`skill.spell_mod_def` 的复合字段、`loot.table.groups`（掉落分组）、`quest.def` 的目标与奖励、`dialog.*` 的节点与动作、`encounter.def` 的单位/波次/阶段、`spawn.table` 条目、`area.trigger_def.params`、`gobj.lock.requirement`、`display.map`/`display.anim_set` 的复合字段。未在首批范围内的复合字段维持现状（只做存在性与类型检查），后续按需追加登记，追加本身不改变已登记字段的行为，属细节补充。

### 3.3 数值范围约束

勘误（2026-09-10，消费方反馈"技能效果参数数值范围校验改进建议"）：`Number`/`Int` 两种标量字段种类此前只检查"存在且类型匹配"，取值本身不受任何约束——内容里出现语义上不可能成立的取值（如周期效果的间隔填 0 或负数）能顺利通过校验器，问题只在运行期才以"该效果悄悄不生效"一类不易察觉的方式暴露，比类型错误（能被第 5 节"复合字段子结构合法"/`field_type` 拦下）更容易被忽视。

**登记记法**：`Number`/`Int` 字段登记新增可选的范围约束（下界/上界各自独立，含/不含端点各自独立），仅对这两种字段种类生效，不新增字段种类；不登记范围时行为与登记前完全一致（只检查"存在且类型匹配"，向后兼容）。范围本身要求下界/上界至少给一个，且下界不能大于上界。

**登记与校验同源**：已登记范围的字段，第 5 节校验项按登记的范围检查实际取值，复用同一套"字段级校验先于业务规则运行"的既有时序（类型错误优先于范围错误——一个字段的取值若类型都不对，不会再额外报范围问题）；子结构（3.2 节）内部的 `Number`/`Int` 字段同样可以登记范围，按子结构的完整字段路径定位问题。范围只能约束单个字段自身的取值，两个字段之间的关系（如"下限不能大于上限"）仍属登记表达不了的业务判断，继续留给各模块既有的手写校验规则。

**自洽检查**：范围只能登记在 `Number`/`Int` 字段上，登记在其它字段种类上判定为一条独立的登记自洽问题（不属于第 5 节数据校验，属登记本身是否自洽，见"元数据门禁"惯例）；范围声明本身（下界/上界至少给一个、下界不大于上界、端点选择不产生空区间）在登记时即校验，不合法的声明本身无法完成登记。

**导出给内容工具**：已登记的范围与其它字段元信息一样，可从登记表批量导出（字段路径、种类、下界/上界及端点选择），供内容编辑器在作者输入时就地校验，不必等到一次完整的加载校验才发现越界。

### 3.4 表级归属与编辑元数据

勘误（2026-09-10，ADR-0022，消费方反馈第二批第 12～16 条）：第 1、2 节登记的表结构信息此前只承载"数据合法性校验"所需的部分，本节补充内容工具（编辑器等）做导航、表单分组、引用自动补全所需的元数据；不改变第 5 节任何一条既有校验项的判定结论，只新增登记与新增自洽检查。

**表级归属**：`TableSchema` 登记 `Layer`（架构分层，取值对应 01 文档 L-1～L5）、`Module`（所属模块名，与 01 第 1.1 节"模块"列一致）、`Domain`（04 第 2.2 节域名；默认取表名首段，三张命名例外表见 2.2 节）。`Layer`/`Module` 由各层 schema catalog 注册时逐表显式登记，无可推导的默认值。

**字段分组**：`FieldSchema` 登记 `Group`（基础/引用/数值/表现/高级五值，对应 05_4.1/5.4.1 节编辑器表单分组）。未显式登记时按字段种类与命名规则计算默认值（主键与名称/描述类文本键→基础；`Reference`/`IdList`/`Id`→引用；`Number`/`Int`→数值；表现类命名关键词→表现；其余→高级），可显式覆盖默认值。

**时间字段单位与作用域**：`FieldSchema` 登记 `Unit`（含"时间模型单位"取值，标记 3.1 节列举的时间字段），`TableSchema` 登记 `TimeScope`（无/探索/战斗/两者皆有，声明该表的时间字段对照哪个作用域）。框架"时间字段与时间模型一致"校验规则的判定逻辑经公开只读入口（`TimeModelRules.GetTimeScope`/`TimeModelRules.IsTimeField`）对外暴露，供内容工具复用同一份判定。

**IdList 引用目标**：`FieldSchema` 对 `IdList` 种类沿用 `Reference` 种类已有的 `ReferenceTable`/`ReferenceDomain` 记法；`reference_integrity` 校验（见第 5 节）扩展为逐元素覆盖 `IdList`。确属不指向任何表的自由 id 列表（标签、局部声明的名字），或因分层边界/装配约束当前无法静态声明引用目标的，用显式标记（`WithFreeIds`，须写明理由）声明，不是默认行为。

**导出**：`toolchain/validator --list-tables --json` 每张表条目新增 `layer`/`module`/`domain`/`time_scope`；每个顶层字段新增 `group`/`unit`/`reference_table`/`reference_domain`/`free_ids`（随 `field_meta` 数组给出），与既有 `fields`/`field_ranges` 并列，不改动既有字段。

详见 [ADR-0022](adr/0022-登记表补充导航与编辑元数据.md)。

## 4. DataRegistry 接口

`DataRegistry` 是 L0 基础层暴露给全架构的唯一数据入口；除表现层的资源加载（经引擎适配层）外，任何模块读取内容一律经它。

```
interface DataRegistry {
  loadAll(): ValidationReport
  get<T>(domain: String, id: Id): Optional<T>
  getAll<T>(domain: String): List<T>
  query<T>(domain: String, predicate: Expr): List<T>
  validate(): ValidationReport
  declareReference(fromField: String, toDomain: String): void
  reload(domain: String): ValidationReport   // 可选：热重载，仅限开发期使用
}
```

- `loadAll()`：启动时一次性加载全部表、跑全部迁移、跑全部校验，返回报告；报告含错误项即视为不可进入游戏状态机的 `gameplay` 状态（见 03）；`loadAll` 允许一次传入多个数据根（例如框架级数据表与具体游戏内容分属不同目录），按传入顺序分"层"（先传入的是前层，后传入的是后层），同一张表出现在多个根时按主键合并为一份记录集；同一表跨根 schema 版本不一致，无条件判定为阻断错误。主键跨根重复默认仍判定为阻断错误（防止无意撞键）；记录可用行级布尔字段显式改写这一默认行为——后层记录声明 `override: true` 时整行替换前层同主键记录（不做字段级合并），前层记录声明 `final: true` 时拒绝被覆盖（仍判定为阻断错误）；两个字段仅在确实发生跨根同主键重复时才生效，单根场景（该表本次未经历合并）出现值为真的这两个字段判定为警告并忽略。
- `get` / `getAll` / `query`：只读访问；`query` 的 `predicate` 用第 6 节的 Expr 语言表达，宿主上下文只暴露该记录自身字段（用于按字段筛选内容表，不同于运行时判定用的 Expr 求值）。
- `recordCount`（勘误，2026-09-10，消费方反馈第二批第 17 条，12 第 5 节）：只读记录总数，取全部已成功加载表的合并记录数；与 `get`/`getAll`/`query` 不同，阻断态（`loadAll`/`reload` 报告含阻断错误）下仍可读，不因数据未通过校验而拒绝——两者的限制目的不同：`get`/`getAll`/`query` 防止把未经校验的数据当权威数据在业务逻辑里使用，`recordCount` 只是诊断信息，不代表数据本身可信。不确定当前是否处于阻断态、需要容错读取时改用配套的"尝试获取"变体：成功返回真与计数，阻断态返回假而不抛异常。
- `declareReference`：模块在注册期声明"我的哪个字段是指向哪个域的外键"，供校验器做引用完整性检查；例如 `skill.def.granted_by` 声明为指向 `item` 域。

勘误（消费方反馈第三批第 20 条，2026-09-10，12 第 5 节，不改变本节接口签名与既有 `get`/`getAll`/`query` 阻断结论）：`getAll`/`query` 各自配套一个"尝试获取"变体，仅供内容工具使用——阻断态下也返回当前已合并的记录视图（与 `recordCount` 同一份数据源），供内容工具在数据未通过校验时仍能读取、定位/修复问题；运行期宿主必须继续用 `get`/`getAll`/`query` 本身，阻断态即禁止读取这一条结论不变。


- `reload`：（建议）仅用于开发期内容热更新，正式运行可关闭；不属于第 6 节校验的强制项。

`reload` 对已在运行的消费方（已按旧定义构造索引/缓存、持有运行期状态的模块）的可验收边界（2026-09-10 补充，第十五轮外部审核跟进）：`reload` 只承诺"下一次访问经 `get`/`getAll`/`query` 能看到新定义"，不单独承诺"任何消费方在任意实现下都自动正确处理"——但下列条件是不分具体实现都必须满足的验收线，任何模块自称支持 `reload` 却不满足其一即视为该模块自身的缺陷，不是本接口留白：

1. 定义发生可兼容变化（不改变已被消费方依赖的结构，如只改数值/文案类字段）时，消费方已持有的运行期状态必须保留，不因 `reload` 被清空或重置。
2. 定义发生消费方依赖的结构性变化（如某个模块把"按索引访问的定长集合"当作契约的一部分，而 `reload` 后该集合的数量/顺序变化）时，必须把消费方已持有的运行期进度迁移到新结构，或原子拒绝这次不兼容的 `reload`（整体不生效，报告拒绝原因）——两者选一，但不允许"部分接受"，即不允许让后续本应合法的操作因为索引越界等原因失败。
3. 定义在取值集合内发生"策略类型切换"（例如某种可配置策略从一种取值变为另一种取值，新策略依赖某种以前不需要的运行期状态，如计时器/累计量）时，`reload` 必须为新策略初始化其运行所需的运行期状态，并且延续（守恒）切换前已经消耗/累计的部分，不得把已消耗量丢弃重置。
4. 由定义派生、可从定义与运行期状态重新计算得出的缓存值（派生值缓存）不属于"运行期状态"本身，`reload` 后必须失效并按新定义重新计算，不能因为消费方多次访问的顺序不同而对同一份新定义给出不同的历史遗留值。
5. 内容校验入口对任何不满足预期形状的输入（含非法/畸形的字段值），必须产出可定位的校验报告项，不能任由内部实现抛出未被捕获的异常向上冒泡——校验入口对"形状不对"的容错边界与"数据完全为空/尚未加载"这类阻断状态是两回事，前者必须走本节校验器的报告路径。

## 5. 校验器检查项清单

校验器是内容提交门槛（拍板决策 4）：任何一项失败即视为本次内容变更不可合入。

| 检查项 | 说明 |
|---|---|
| 引用完整性 | 每个通过 `declareReference` 声明的外键字段，其值必须能在目标域找到记录，或显式声明为 `Optional` 且为空；已登记 `ReferenceTable`/`ReferenceDomain` 的 `IdList` 字段（见 3.4 节）同样受本项检查，逐元素核对，问题定位到具体元素下标（勘误，2026-09-10，ADR-0022） |
| id 格式合法 | 每条记录的 id 符合第 2 节格式与所属域名 |
| 枚举合法 | 枚举字段的取值必须在该字段登记的合法枚举集合内 |
| 表达式可解析 | 所有 Expr 字段必须能被解析为合法语法树（不要求运行时求值为真，只要求语法合法且引用的 key 在对应宿主分组中存在登记）；点分标识符按第 6.3 节归类规则以引用登记表消歧为引用或 id 字面量，域名与分组同名但未登记的 id 字面量报"疑似引用拼写错误"警告（不阻断）；表达式文本中的整数字面量超出可表示的整数范围、或数字字面量的解析结果不是有限数值，二者均视为解析期错误（与语法错误同一检查名 `expr_parsable`，报错定位到该字面量在原始文本中的位置），不以未分类的运行期异常形式逃逸出校验流程（勘误，2026-09-10，消费方反馈"schema/expr 边界审计"） |
| 效果数上限 | 单条 `skill.def` / `skill.aura_def` 的效果列表长度不超过配置的上限（策略配置项，默认建议值见 06） |
| 预算超标 | 具备数值预算公式的表（如物品等级预算，见 07）算出的预算值不超过对应等级/品质允许的上限；预算上限 = 预算曲线按物品等级插值 × 品质预算倍率 |
| 叠加类别冲突 | 同一 `stack_category` 静态分组（见 06 第 3.3/3.8 节）下不得同时登记可叠加（`max_stacks>1`）与不可叠加（`max_stacks==1`）两种叠加形态的定义；本项是加载期静态内容校验，不改变运行时按 `(target, aura_def, sourceKey)` 分槽的叠加行为——不同 `aura_def` 即使类别相同也各自独立叠加、互不影响（勘误，2026-09-10，[ADR-0023](adr/0023-光环叠加类别为静态校验分组.md)） |
| 外形映射存在 | 每个出现在 `display` 域引用集合中的逻辑 id（技能、光环、物品、生物、物件）必须在 `display.map` 中有对应行；该规则默认不随其余项一并自动登记——实现需要调用方显式声明"哪些内容表参与外形域覆盖检查"才能构造，游戏接入时若需要启用需自行显式登记（见 09 表现层装配根判断记录） |
| 外形类型字段组完整 | `display.map` 记录的 `kind` 字段决定的专属字段组（sprite 型或 model 型）必填项必须齐全，另一组字段必须留空（见 7.1） |
| 文本键存在 | 每个记录中标记为"文本键"类型的字段，其值必须能在 `l10n.text` 的默认语言下查到 |
| schema 版本已知 | 记录的 `schema_version` 必须落在该表已登记的迁移链范围内 |
| 循环引用检测 | 声明为树/链结构的字段（如天赋前置、对话节点分支）不得成环 |
| 孤儿记录检测 | （建议）不被任何已知入口引用的记录（如没有任何技能书引用的技能）报告为警告而非错误，便于清理；当前无对应校验规则实现，仍停留在"建议"阶段 |
| 时间字段与时间模型一致 | 记录所属作用域的 `found.time_model.mode` 为 `discrete` 时，该记录的全部时间字段（见第 3.1 节）取值必须为整数 |
| 复合字段子结构合法 | 已登记子结构（见第 3.2 节 `fields`/`item`/`variants`）的复合字段，按登记递归检查必填、类型、枚举、引用、表达式可解析，复用既有检查项（不新增平行检查名）；`variants` 判别字段缺失或取值不在 `cases` 键集合内报"判别字段非法"（检查名 `variant_discriminator`）；递归深度超过实现设定的上限报"子结构递归深度超限"（检查名 `substructure_depth`，防御登记错误导致的无限递归）；已登记 `fields`/`variants` 之外出现的多余子字段默认不报（向前兼容游戏层扩展字段），可选开启后报警告（检查名 `unknown_subfield`）；未登记子结构的复合字段不受本项影响，仍只做存在性与类型检查 |
| 变体表与原语注册集合一致 | 按判别字段分派的变体登记（第 3.2 节 `variants`）中 `cases` 的键集合，必须等于运行时实际登记的对应原语集合；新增原语未同步登记变体、或登记了运行时未注册的取值，均报错。当前以测试锁死这条一致性（变体键集合与运行时原语注册表都在实现代码里，两者一致性属"改一处、另一处编译期/测试期即发现"的静态可核对关系，不需要额外的运行期校验规则） |
| 数值范围合法 | 已登记范围（见第 3.3 节）的 `Number`/`Int` 字段，取值超出登记的下界/上界（含端点选择）报错（检查名 `field_range`）；类型错误优先于范围错误，同一字段至多命中其中一种；子结构内部登记了范围的 `Number`/`Int` 字段同样受本项检查，按完整字段路径定位；未登记范围的字段不受本项影响 |
| 数值有限 | `Number`/`Int` 字段的取值必须是有限数值，不允许"无穷大"或"非数字"这类特殊取值；命中报阻断错误（检查名 `field_finite`）；与该字段是否登记第 3.3 节的数值范围无关——未登记范围的字段同样受本项检查；判定顺序为类型错误优先，其次本项，最后才是数值范围检查，同一字段至多命中其中一种（勘误，2026-09-10，消费方反馈"schema/expr 边界审计"） |

以下五项（勘误，2026-09-10，ADR-0022）不是"每次内容加载都跑一遍"的运行期校验，而是"元数据门禁"（ADR-0018 决策 3 的静态审计工具，命令行入口 `toolchain/validator --schema-audit`）在登记表本身上跑的自洽检查——检查的是"登记有没有填齐"，不是"某条具体内容数据是否合法"，与上面各行的运行时校验属两条正交的检查通道（惯例同已有的 `composite_without_substructure`/`field_range_kind` 等既有元数据门禁检查项）：

| 检查项 | 说明 |
|---|---|
| 表级归属 | 每张已登记表的 `Layer`/`Module`（见 3.4 节）非空，`Domain` 与表名首段一致或属 2.2 节命名例外（检查名 `table_ownership`） |
| 字段分组 | 每个字段的 `Group`（见 3.4 节）可解析为已定义的分组取值（检查名 `field_group`；`Group` 有计算默认值，本项主要防御默认规则实现遗漏，见 ADR-0022） |
| 时间作用域已声明 | 登记为 `Unit=时间模型单位` 的字段，所属表的 `TimeScope`（见 3.4 节）必须非"无"（检查名 `time_scope_declared`） |
| 时间字段清单防遗漏 | 3.1 节清单里已落地并接入"时间字段与时间模型一致"校验的具体字段，登记表里必须已标记 `Unit=时间模型单位`，防止清单与登记表单边漂移（检查名 `time_unit_missing`） |
| IdList 引用目标 | `IdList` 字段必须在 `ReferenceTable`/`ReferenceDomain`/显式自由列表标记三者中登记其一（检查名 `idlist_reference_target`，见 3.4 节） |

## 6. Expr 条件表达式语言

Expr 是全架构唯一的条件与表达式语言（拍板决策 5），触发条件、优先级表候选条件、掉落条件、任务前置、对话显隐、遭遇阶段切换、成就 criteria、刷新条件全部用它书写，任何宿主只需实现一个 `query(key, args)` 出口即可接入。

### 6.1 语法（BNF）

```
<expr>        ::= <or_expr>
<or_expr>     ::= <and_expr> ( "or" <and_expr> )*
<and_expr>    ::= <unary_expr> ( "and" <unary_expr> )*
<unary_expr>  ::= "not" <unary_expr> | <compare_expr>
<compare_expr>::= <term> ( <cmp_op> <term> )?
<cmp_op>      ::= "==" | "!=" | ">" | ">=" | "<" | "<="
<term>        ::= <literal> | <reference> | "(" <expr> ")"
<literal>     ::= <number> | <string> | "true" | "false" | <id_literal>
<reference>   ::= <group> "." <key> ( "(" <arg_list> ")" )?
<group>       ::= "self" | "target" | "event" | "world" | "quest" | "player" | "combat" | "enemies" | "time"
<arg_list>    ::= <term> ( "," <term> )*
```

- 无变量赋值、无循环、无自定义函数；表达式永远求值为 `Bool` 或可比较的标量，用于"是否满足条件"或"取某个数值再比较"两类场景。
- 括号仅用于改变优先级，不支持函数定义。
- `<reference>` 与 `<id_literal>`（内容 id 字面量，见第 2 节 id 格式）在语法形式上完全相同；一个点分标识符具体归类为哪一种，由宿主引用登记表在解析时消歧，不由 BNF 本身区分，详见第 6.3 节（[ADR-0015](adr/0015-Expr点分标识符以引用登记表消歧.md)）。

勘误（12 第 5 节，消费方反馈 E5，不改变本节 BNF 与结论，仅补充契约面说明）：表达式解析器契约面新增一个词法切分入口，返回 token 种类与源文本位置区间，与解析器共用同一套词法规则；编辑器等工具做语法高亮/token 级诊断须调用该入口，不得另写词法（[ADR-0020](adr/0020-表达式词法器纳入公开契约.md)）。

勘误（消费方反馈第三批第 19 条，2026-09-10，12 第 5 节，不改变本节 BNF 与结论，仅补充契约面说明）：语法树节点与静态校验产出的问题项同样携带源文本位置区间（起始偏移 + 长度，与上一条词法切分入口的坐标系一致）——`ExprParser.Parse` 解析源文本产出的节点带精确区间，手写构造的节点默认区间未知；编辑器等工具据此把某条校验问题（如"未登记的引用"、"参数类型不匹配"）精确定位、高亮到源文本对应片段，不需要自己重新做一遍字符串匹配去猜测问题出在哪一段。

### 6.2 宿主引用分组（按用途）

| 分组 | 含义 | 示例引用 | 典型使用场景 |
|---|---|---|---|
| `self` | 表达式所属主体自身状态 | `self.hp_pct`、`self.has_aura(skill.aura.burning)` | 优先级表候选条件、光环叠加判断 |
| `target` | 当前目标状态 | `target.hp_pct < 0.3`、`target.faction == fac.wildlife` | 目标选择链筛选、任务前置 |
| `event` | 触发此次求值的事件携带的数据 | `event.damage_amount`、`event.school` | Proc 触发条件、成就 criteria |
| `world` | 世界状态标志 | `world.get(world.bridge.repaired)` | 刷新条件、对话显隐、区域触发 |
| `quest` | 玩家任务状态 | `quest.is_active(quest.deliver_letter)`、`quest.objective_progress(...)` | 任务前置、对话选项显隐 |
| `player` | 玩家角色数据 | `player.level >= 10`、`player.has_item(item.town_key)` | 任务前置、锁的开锁条件 |
| `combat` | 当前战斗/施法上下文 | `combat.in_combat`、`combat.cast_school` | 施法管线检查、公共冷却判断 |
| `enemies` | 周边敌对单位聚合信息 | `enemies.count_in_range(8)` | AI 行为外壳状态切换、遭遇阶段 |
| `time` | 时间与计时器 | `time.since_combat_start`、`time.day_cycle`、`time.turn_index`、`time.round_index`、`time.is_my_turn`、`time.sim_time` | 遭遇阶段计时、刷新计时策略；`turn_index`/`round_index`/`is_my_turn` 仅离散模式下有意义（见 03、06）；`sim_time` 为经构造注入的仿真时钟读数，连续/离散模式均可用 |

每个宿主实现只需要提供 `query(group, key, args) -> Value`，Expr 求值器不关心宿主内部实现，只负责把语法树按分组分发出去。

勘误（消费方反馈第三批第 18 条，2026-09-10，12 第 5 节，不改变本节分组清单与结论，仅补充契约面说明）：宿主引用登记表额外支持"按分组枚举本分组下全部已登记 key"与"枚举全部已出现过登记的分组"两种只读查询（有序、确定性）——编辑器等工具据此做字段自动补全/清单展示，不需要先穷举全部 `group.key` 组合再自行按分组过滤。

### 6.3 类型与求值规则

- 类型集合与接口记法一致：`Bool`、`Int`、`Number`、`String`、`Id`。
- 比较运算符两侧类型必须一致（`Id` 只支持 `==`/`!=`）；类型不一致视为解析期错误，校验器阶段即拒绝。
- `and`/`or` 短路求值；短路时被跳过的子表达式不触发对应 `query` 调用（避免访问不存在的目标等空引用）。
- 未登记的 `group.key` 组合本身不直接产生阻断性的"未知引用"错误：具体归类取决于下一条 ADR-0015 规则——普通分组（`self`/`target`/`world`/`quest`/`player`/`combat`/`enemies`/`time`）未登记的组合回退为 `<id_literal>`（至多触发下一条的"疑似引用拼写错误"警告，不阻断合入），`event` 分组按本节"`event` 分组例外"单独处理（同样不报错）。`ExprValidator` 里仍保留的 `UnknownGroup`/`UnknownKey` 两类真正的阻断性"未知分组/未知 key"检查，只在校验器独立防御手工构造、不经 `ExprParser.Parse` 产出的 `ExprNode` 时才可能触发——内容作者正常撰写的表达式文本经 `ExprParser.Parse` 不会走到这两个分支（`core/foundation/expr/README.md`"语法细节"第 4 条判断记录）。运行期若引用的具体对象缺失（如 `target` 分组但当前无目标），`query` 返回该分组约定的默认值（`Bool` 默认 `false`，数值默认 `0`），并记录一条运行期警告，不中断调用方流程。
- 点分标识符的归类以宿主引用登记表为准：`<第一段>.<其余段>` 若在当前宿主的引用登记表中登记为 `group.key` 组合，解析为 `<reference>`；否则整体解析为 `<id_literal>`，须满足第 2 节 id 格式。内容校验期与运行期使用同一份引用登记表，保证同一段表达式文本在两处解析结果一致（[ADR-0015](adr/0015-Expr点分标识符以引用登记表消歧.md)）。校验器对此新增一条警告：当某个 `<id_literal>` 的域名段与九个分组之一同名、但对应的 `group.key` 组合未登记时，报"疑似引用拼写错误"（警告，不阻断合入）。
- `event` 分组例外：具体触发事件携带的字段随事件类型变化，任何一份引用登记表都不可能穷举登记全部 `event.<key>`；`event` 本身又不是第 2 节的内容域名（不可能是合法的 `<id_literal>`）。因此未登记的 `event.<key>` 组合不落入上一条"未登记则归为 `<id_literal>`"的默认路径，仍整体归类为 `<reference>`（签名未知时解析器放行、跳过静态类型检查，运行期照常按分组求值规则处理），不报"疑似引用拼写错误"。

### 6.4 错误处理

| 阶段 | 错误情形 | 处理方式 |
|---|---|---|
| 解析期（内容提交时） | 语法错误、类型不匹配 | 校验器报错，内容不可合入 |
| 解析期（内容提交时） | 未登记的 `group.key`（普通分组回退为 id 字面量、`event` 分组回退为签名未知的引用，见 6.3 节） | 不阻断合入；普通分组至多触发"疑似引用拼写错误"警告（ADR-0015）。`ExprValidator` 保留的 `UnknownGroup`/`UnknownKey` 阻断错误只防御手工构造的 AST，正常撰写的表达式文本不会触发 |
| 求值期（运行时） | 引用对象暂缺（如无目标） | 按分组默认值返回，记录警告，不抛异常 |
| 求值期（运行时） | 宿主 `query` 内部异常 | 视为该表达式求值为 `false`，记录错误日志，不影响其余系统 tick |

| `vfx_id` | Optional<Id> | 否 | 指向 `vfx.def` |
| `sfx_id` | Optional<Id> | 否 | 指向 `sfx.def` |
| `scale` | Number | 否 | 默认缩放，默认 1.0 |
| `shadow` | `none\|blob\|projected` | 否 | 阴影呈现模式，默认 `blob`（详见 05、09；`model` 型经 `IRenderer3D.setShadow` 应用） |
| `sort_offset` | Number | 否 | 同一 `sortY` 下的排序微调偏移，用于区分前后景装饰物（详见 09 第 3.1 节），默认 0 |
| `weapon_style_ref` | Optional<Id> | 否 | 指向 `display.weapon_style`，供武器类物品经此行关联武器表现档案（详见 09 第 4.4 节） |

`kind: sprite` 型专属字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sprite_set_id` | String | 是（sprite 型） | 精灵集资源引用（不含路径，由引擎适配层解析） |
| `direction_count` | `4\|8\|16` | 是（sprite 型） | 方向量化档位（详见 05） |
| `mirror_pairs` | Optional<List<{direction_slot: Id, mirror_of: Id, flip_x: Bool}>> | 否 | 方向镜像规则：元素结构与 09 第 3.2 节镜像规则表一致 |
| `paperdoll_layers` | List<String> | 否 | 纸娃娃分层引用列表，仅 `item`/`creature` 使用（详见 09） |
| `anchor_points` | Map<String, Vec2> | 否 | 挂点定义，供特效/武器/头顶信息等对齐 |

`kind: model` 型专属字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `model_ref` | Id | 是（model 型） | 三维模型资源引用（不含路径，由引擎适配层解析） |
| `anim_set_ref` | Id | 是（model 型） | 指向 `display.anim_set`（详见 7.1.1） |
| `sockets` | List<Id> | 否 | 该模型声明的挂点 id 列表，供 `IRenderer3D.attachToSocket` 使用 |
| `slots` | List<Id> | 否 | 该模型声明的可换装槽位 id 列表，供 `IRenderer3D.setSlotMesh` 使用 |
| `default_slot_meshes` | Map<Id, Id> | 否 | 槽位 id 到默认网格资源引用的映射，未被 `display.equip_visual` 覆盖时使用 |
| `material_params` | Map<String, Number> | 否 | 材质参数默认值（闪白、溶解等），经 `IRenderer3D.setMaterialParam` 应用 |

校验规则：`kind` 决定哪组类型专属字段必填——`kind: sprite` 时 sprite 型字段组的必填项必须齐全，model 型专属字段一律留空；`kind: model` 时相反（详见第 5 节"外形类型字段组完整"检查项）。

示例记录（`kind: sprite`）：

```
id: display.grey_wolf
category: creature
logical_id: creature.grey_wolf
kind: sprite
sprite_set_id: sprite.creature.wolf_grey
direction_count: 8
icon_id: icon.creature.wolf_grey
sfx_id: sfx.wolf_growl
scale: 1.0
shadow: blob
sort_offset: 0
```

示例记录（`kind: model`）：

```
id: display.stone_golem
category: creature
logical_id: creature.stone_golem
kind: model
model_ref: model.creature.stone_golem
anim_set_ref: display.anim_set.stone_golem
icon_id: icon.creature.stone_golem
sfx_id: sfx.stone_golem_step
scale: 1.2
shadow: projected
sort_offset: 0
sockets: [socket.hand_main, socket.hand_off]
slots: [slot.weapon_main]
default_slot_meshes: {slot.weapon_main: mesh.golem_fist}
```

逻辑表（`skill.def`、`item.template` 等）只存 id，不存任何资源路径；新增一个外形只需在 `display.map` 加一行，运行时逻辑代码零改动。

### 7.1.1 `display.anim_set` 字段

动画集把一组动画剪辑 id 映射到资源引用与关键帧事件列表，供 `kind: model` 的外形驱动骨骼动画（详见 09 第 4 节）。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | Id | 是 | `display.anim_set.<名字>` |
| `clips` | Map<Id, {resource_ref: Id, events: List<{name: String, time_pct: Number}>}> | 是 | 剪辑 id 到资源引用与关键帧事件列表的映射；`time_pct` 是关键帧在剪辑内的时间百分比（0~1），`name` 为事件名（如 `hit`、`release`、`footstep`），经 `IRenderer3D.onAnimEvent` 回调 |

示例记录：

```
id: display.anim_set.stone_golem
clips:
  attack: { resource_ref: anim.stone_golem.attack, events: [{name: hit, time_pct: 0.6}] }
  move: { resource_ref: anim.stone_golem.move, events: [] }
```

### 7.1.2 `display.equip_visual` 字段

装备外观把一件装备映射到它在 `model` 型外形上的呈现方式：替换槽位网格，或作为独立模型挂接到挂点（详见 09 第 4.4 节）。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | Id | 是 | `display.equip_visual.<名字>` |
| `item_id` | Id | 是 | 指向 `item.template` |
| `mode` | `slot_mesh\|socket_attach` | 是 | 呈现方式：替换槽位网格，或挂接独立模型到挂点 |
| `slot_id` | Optional<Id> | `mode: slot_mesh` 时必填 | 目标槽位 id，对应 `display.map` 的 `slots` |
| `mesh_ref` | Optional<Id> | `mode: slot_mesh` 时必填 | 替换用网格资源引用 |
| `socket_id` | Optional<Id> | `mode: socket_attach` 时必填 | 目标挂点 id，对应 `display.map` 的 `sockets` |
| `model_ref` | Optional<Id> | `mode: socket_attach` 时必填 | 挂接的独立模型资源引用 |

### 7.2 本地化

- 文本键规范：`l10n.<来源域>.<来源记录name>.<字段名>`，例如任务标题 `l10n.quest.deliver_letter.title`。
- 语言表 `l10n.locale` 定义支持的语言 id 与回退链（例如某语言缺文本时回退到默认语言）。
- `l10n.text` 字段表：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `key` | String | 是 | 文本键，见上 |
| `locale` | Id | 是 | 语言 id |
| `text` | String | 是 | 正文，支持变量占位 |
| `schema_version` | Int | 是 | 见第 3 节 |

- 变量代入语法：正文中以 `{变量名}` 占位，运行时由调用方提供 `Map<String, String>` 做替换；变量名来自事件或表达式求值结果（如 `{target_name}`、`{amount}`），不支持嵌套表达式，替换失败（变量缺失）时原样保留占位符并记录警告。

## 8. "新增一个内容"标准流程

| 新增类型 | 改哪些表 | 加哪些资源 | 跑哪些校验 |
|---|---|---|---|
| 新技能 | `skill.def`；如带光环则加 `skill.aura_def`；如有触发则加 `skill.proc_def`；如需被学习加入 `skill.book` | `display.map` 加一行；如需文本则加 `l10n.text` 的技能名/描述键 | 引用完整性、效果数上限、外形映射存在、文本键存在、表达式可解析（若效果含条件） |
| 新光环 | `skill.aura_def`；若涉及叠加类别复用需检查既有类别 | `display.map`（若光环有独立图标/持续特效）、`l10n.text` | 叠加类别冲突、外形映射存在、文本键存在 |
| 新装备 | `item.template`；若属于套装则更新 `item.set` | `display.map`（外形与纸娃娃层）、`display.equip_visual`（model 型外形的槽位网格或挂点模型）、`l10n.text` | 引用完整性（授予的技能/光环存在）、预算超标、外形映射存在、外形类型字段组完整、文本键存在 |
| 新怪 | `creature.template`；如需专属掉落加 `loot.table`；如需专属 AI 加 `ai.rotation`/`ai.behavior_profile` | `display.map`、`l10n.text` | 引用完整性（AI/掉落/外形引用）、外形映射存在、文本键存在 |
| 新物件 | `gobj.template`；如需上锁加 `gobj.lock` | `display.map`（若有独立外观）、`l10n.text` | 引用完整性（on_use 指向的技能/对话存在）、外形映射存在、文本键存在 |
| 新地图 | `world.map`（详见 05）、按需加 `spawn.table` | 场景资源引用（由游戏层提供，架构只登记引用 id）、`l10n.text`（地图名） | 引用完整性（场景资源引用、出生点/传送点合法）、文本键存在 |
| 新任务 | `quest.def` | `dialog.gossip_menu` 中挂接接取/交付动作、`l10n.text`（标题、目标描述、对话文本） | 引用完整性（前置任务、奖励物品/技能存在）、表达式可解析（前置条件）、文本键存在、循环引用检测（前置链） |
| 新对话 | `dialog.gossip_menu` 或 `dialog.story_tree` | `l10n.text`（对话文本）、如涉及演出钩子则登记 `found.hook` 引用 | 引用完整性（动作指向的技能/任务/传送点存在）、表达式可解析（显隐条件）、文本键存在、循环引用检测（对话树分支） |
| 新成就 | `achv.def` | `display.map`（成就图标）、`l10n.text` | 引用完整性（观察事件已登记）、文本键存在 |

## 基础架构提供 / 游戏层提供

| 能力 | 基础架构提供 | 游戏层提供 |
|---|---|---|
| 表结构与字段定义 | 是（本文档登记的字段表） | 否，不得自行增删架构级字段 |
| DataRegistry 加载/校验/查询实现 | 是 | 否 |
| Expr 语法与求值器 | 是 | 提供宿主 `query` 实现的具体数据来源（如世界状态的具体标志集合） |
| id 域名清单 | 是（固定，新增域名走审批） | 域内具体 name 由游戏层内容作者填写 |
| 具体内容记录（技能、物品、生物……的每一行数据） | 否 | 是 |
| 表现资源本身（精灵、音频等文件） | 否，只提供 `display.map` 结构 | 是 |
| 本地化文本正文 | 提供文本键规范与求值/回退机制 | 提供各语言正文 |

## 验收标准

1. 全部表在第 1 节总索引中有登记，且下游文档（05～09）中出现的表名与此表一一对应，无遗漏无冲突。
2. 任取架构文档中出现的任意一个内容 id，能唯一定位其 domain 并在第 2.2 节域名清单中找到归属。
3. `DataRegistry` 接口签名可被任一模块契约引用而不需要额外说明。
4. 校验器清单中的每一项都能用一句话说清"检查什么、什么情况下判定失败"。
5. Expr 的 BNF 可以推导出本文档及 05～08 中出现的所有示例表达式。
6. "新增一个内容"表中的九类改动，任一类都不涉及修改运行时代码，只涉及加表行与加资源引用。
