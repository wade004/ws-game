## 2. 疑似真缺陷（代码行为问题，需设计层拍板）

这些不是单纯的测试缺口。按 AGENTS.md 第 0 节，代码注释里写下的“已知限制”须逐条汇报，2.2 组即为此类。各条“建议”取自原报告的表述；原报告未给出预期语义的，一律写“待设计层确认预期语义”。

### 2.1 原报告明确标为疑似缺陷 / P0 / 待设计层确认

#### D1 VFX 冷加载中无法 Stop（冷/热不一致）
- 位置：`presentation/vfx_sfx/core/VfxPlayer.cs`（`Spawn`→`QueuePendingSpawn` 冷加载返回 null 句柄，`Stop(handle)` 无取消排队路径）；`presentation/feedback_binder/core/CompositeFeedbackSink.cs`（`PlayVfx` 仅在拿到句柄时登记 `_activeVfxByKey`）
- 现象：`stop_vfx` 在资源加载完成前到达是空操作，随后粒子被补发且无人停止。SFX 已有对称修复与用例（`presentation/vfx_sfx/tests/SfxPlayerTests.cs` 的 `PlayAttached_ColdLoad_StopAttachedBeforeLoadCompletes_*`），VFX 没有。
- 影响：无寿命的循环特效会永久残留；违反 AGENTS 第 0 节“冷加载路径必须与热路径一致并作为不变量用例”。
- 建议：待设计层确认预期语义；补 `presentation/vfx_sfx/tests/VfxPlayerTests.cs`、`presentation/feedback_binder/tests/CompositeFeedbackSinkTests.cs` 复现用例。

#### D2 SfxPlayer 冷加载超时用墙钟 `DateTime.UtcNow`
- 位置：`presentation/vfx_sfx/core/SfxPlayer.cs:260,363`（VfxPlayer 用 dt 累计）
- 现象：用例靠 `FirstLoadTimeoutSeconds=0.0` 规避（`presentation/vfx_sfx/tests/SfxPlayerTests.cs:236,303,414`、`presentation/feedback_binder/tests/FeedbackBinderTests.cs:503-540`）；没有“timeout>0 且未到期不应丢弃”的 SFX 用例（VFX 有）；`FeedbackBinderTests.cs` 注释写 `FirstLoadTimeoutSeconds=0.05` 与代码 0.0 不符。
- 影响：违反 AGENTS 第 3 节确定性（不依赖系统时间）。
- 建议：设计层决定 SFX 超时改注入时钟或用 dt 累计，并补正/反两向用例。

#### D3 SfxPlayer 层满时抢占不比较新来者优先级
- 位置：`presentation/vfx_sfx/core/SfxPlayer.cs` `MakeRoomIfNeeded`（约 :575-610）
- 现象：层满时无条件淘汰“最低优先级+最老”的在播实例，即便新来者优先级更低（低优先级新音会顶掉高优先级旧音）。现有用例只测“高抢低”和同优先级取最老（`presentation/vfx_sfx/tests/SfxPlayerTests.cs:89`、`SfxLayerSlotHoldTests.cs`）。
- 影响：无用例固定“低到达、层满且全部更高”的预期。
- 建议：待设计层确认这是刻意语义还是缺陷，再补用例。

#### D4 shake_camera 用 profile_id 当 preset id，feedback→camera/freeze 链路无端到端用例
- 位置：`presentation/assembly/PresentationAssembly.cs:493`（`onShakeCamera: profileId => Camera.Shake(profileId)`）；`data/_sample/feedback/feedback.binding.json:46`
- 现象：`CameraHost.Shake(shakePresetId)` 要求该 id 是当前 profile 的 shake_presets 条目 id，样例数据的 `profile_id` 实际是 preset id，命名易误导；相位切档后新 profile 无该 preset 时 `Shake` 抛 `ArgumentException`，被 `SafeDispatch` 吞成诊断；`OnFreeze` 默认 no-op 未测（`presentation/assembly/tests/PresentationAssemblyTests.cs` 中 `OnFreeze` 0 次出现）。
- 影响：无任何 dotnet 用例验证“事件→规则→ShakeCamera→CameraHost→`StubCamera.LastShake*`”。
- 建议：先确认 `profile_id` 语义，再补端到端用例。

#### D5 ViewBinder 异常隔离缺口（11 章 §4）
- 位置：`presentation/view_binding/core/ViewBinder.cs`：`SyncAll`、`OnForwardableEvent`、`OnEntityDestroyed`、`OnSaveLoaded` 第一循环
- 现象：单个 `view.SyncPose` 抛异常会中断整帧同步；`view.OnEvent` 抛异常无隔离；`view.Destroy` 抛异常后 `_views` 残留；`OnSaveLoaded` 内第一循环 `Destroy` 失败的 try/catch 无用例，代码注释承认“绑定表可能残留该实体，需人工核查”（注释中的已知限制）。仅“创建期”与“OnSaveLoaded 对账循环”有隔离并有用例（`presentation/view_binding/tests/ViewBinderTests.cs:138,178`）。

阶段一（`check.ps1`）：门禁自检（Test-NativeExitCode 探针）→ 禁用词（游戏代号，git grep）→ architecture 正文技术名 → 版本一致性 → `validate_data.py --strict`（合并根 `_framework+_sample`）→ `validate_data.py --data-root data/_framework`（**不带 strict**，有意）→ `validator --schema-audit` → `gen_event_constants.py --check` → `format_data.py --schema-order --check` → `import_assets.py check --dataset _sample` → `validate_data.py --strict --data-root core/sim/tests/data` → 工作树无 CR → `check_unity_meta.py` → pytest 单文件 `test_registry_stop_pidfile_rewrite_timestamp.py`（-Quick 跳过）。

阶段二重线（`toolchain/_gate_line_heavy.ps1`）：`dotnet build Core.sln` → `dotnet test Core.sln --no-build`（全部 8 个测试工程，含 `Perf` 类别；步骤名仍写“六工程”，已过时）→ ABI 探针（无基线 zip 且未传 -AbiStrict 时 SKIP；退出码 3=SKIP）→ `gen_placeholder_assets.py --check` → 样例导入幂等性（有未提交改动则 SKIP）→ `pytest toolchain/tests -q --ignore=<registry 文件>` → simrunner 基线比对（含 `added>0` 拦截）。`-Quick` 只保留 build/test 两步。

阶段二 Unity 线（`toolchain/_gate_line_unity.ps1`）：`build.ps1 -SkipTests`（同步 DLL）→ 包清单一致性（`-SyncOnly -Dist <ver>-dryrun` + 4 个包 `npm pack --dry-run`）→ Unity 编译检查 → EditMode（**无 filter，跑全部 testables**）→ PlayMode（同）→ 独立版构建 + `-gf-smoke` → `-gf-smoke-discrete` → IL2CPP 三步（仅 `-Il2cpp`）→ 消费方演练 `consumer_smoke.ps1`。

模式：`-Quick`（pre-commit Full 档）、`-DocsOnly`（pre-commit 只改 md）、`-SkipUnity`（GitHub CI 固定用）、`ReleaseSkip`（发布提交本身不重复跑）。CI（`.github/workflows/ci.yml`）= `check.ps1 -SkipUnity`，因此 Unity 测试、独立版冒烟、消费方演练只在本机全量门禁里存在。

##### 4.2 “存在但没被门禁跑到”的核对（用 grep 逐项核）
- `Core.sln` 与 `git ls-files '*.csproj'`（排除 dist/）对比：所有 8 个 `Tests.*.csproj` 都在 sln 里。不在 sln 的只有 `toolchain/abi_probe`、`abi_surface`、`asset_root_probe`、`map_ref_probe` 四个工具工程，它们都是被 pytest/abi_probe.ps1 单独构建的（有意设计），不是测试工程。
- 所有 `*Tests.cs` 与 `tests/` 下的 .cs 都落在各测试工程的 `Compile Include="../*/tests/**/*.cs"`（或 Tests.Sim 默认 glob、Tests.Foundation 另含 `adapters/conformance/**`）范围内，没有游离的测试文件。
- Unity：`Packages/manifest.json` testables 覆盖 adapter.unity 与 game-template 两个包，两个包的 Editor/Runtime 测试 asmdef 都被跑到。
- **未被任何门禁跑到的**：
  1. `games/_template/data/game` 的 `validate_data.py --strict`（AGENTS §4 G1 明文要求“默认数据根与 `games/_template/data/game` 必须 warnings 为 0”）：`check.ps1` 三个数据校验步骤是合并根、`data/_framework`、`core/sim/tests/data`，没有模板根；`games/_template/validate.ps1` 全仓没有任何门禁脚本调用（只有文档提到）。模板数据仅在 PlayMode `GameTemplateSmokeTests.GameBootstrap_DefaultGameOptions_LoadsWithZeroBlockingErrors`（`games/_template/Tests/Runtime/GameTemplateSmokeTests.cs:144-153`）里断言 `ErrorCount==0`，**不断言 warnings**，且 `-SkipUnity`（CI、pre-commit）下完全不跑。
  2. IL2CPP 三步：只有 `-Il2cpp` 才跑，发布门禁也不传。
  3. `test_abi_surface_compare.py` 真实基线端到端例：本机无 `dist/ws-game-<baseline>.zip` 时 skip。
  4. `-ReleaseSkipUnity` 允许发布时整段跳过 Unity（设计如此，但是一个可被用掉的口子）。

##### 4.3 门禁判据的弱点
- Unity EditMode/PlayMode 步骤只判 `xml.DocumentElement.result -eq "Passed"`（`toolchain/_gate_line_unity.ps1:281-291`、`:310-320`），没有 `total`/`passed` 下限，没有检查 skipped/inconclusive 数；测试被误排除（asmdef 平台设置、编译条件）或全 Ignore 时依然 PASS。契约场景在 Unity 里用 `Assert.Ignore`，其数量也不在门禁输出里出现。
- `dotnet test` 与 `pytest` 步骤同样没有用例数量下限；Perf 诊断行缺失只 `Write-Host` 黄色警告，不失败（`_gate_line_heavy.ps1:103-105`）。
- ABI 探针步骤在本地无基线时 SKIP，是否计入“32/32”取决于 Results 里 SKIP 是否算入总数，日志只写 32/32 看不出。
- 6 个 `PlaceholderTests.cs`（`core/{carriers,foundation,gameplay,numbers,rules}/tests/`、`presentation/tests/`）内容是 `Assert.True(true)`，纯占位，会虚增用例数。
