# 升级指南：1.100.0 → 2.0.0（框架三层拆分）

对应 [ADR-0160](../../architecture/adr/0160-框架三层拆分运行时包手感实验室可选包与样板仓库.md)；`CHANGELOG.md` `[2.0.0]` 的"变更（破坏性）"条目是它的单版摘要，本指南给出游戏侧要做的事。

## 1. 适用范围与读者

- 读者：已经按版本号（私服或发布 zip）消费框架的游戏仓库维护者。
- **只有用到下面任一项的游戏需要动手**：①引用了适配层包里的实验室宿主类型（`Adapter.Unity.LabHost` 程序集、`EngineLabHost`、`LabPlayground`、编辑器菜单"手感实验室/手感试玩"）；②用了工具链包或发布 zip 里的实验室命令行（`toolchain/feellab`、`Tools~/feellab`）或实验室数据集（`data/_lab*`、`data/_equip`、`lab/fixtures`）；③引用了三个演示场景或其资产。
- **没有用到以上三项的游戏**：只需把四个包的版本号改到 2.0.0，其余不变。

## 2. 一页总览

| 变化 | 之前（≤ 1.100.0） | 之后（2.0.0） |
|---|---|---|
| 适配层包 `com.gamefoundation.adapter.unity` | 含实验室引擎宿主、F1 面板、占位试玩场景构建器与三个实验室插件 DLL | **只剩运行时**；包边界判定保证没有实验室或演示文件 |
| 手感实验室引擎宿主 | 适配层包里的 `Adapter.Unity.LabHost` | 新的可选包 `com.gamefoundation.feel-lab.unity`（程序集 `FeelLab.Unity`/`FeelLab.Unity.Editor`，只在编辑器编译） |
| 实验室命令行与数据集 | 工具链包 `Tools~/feellab` 与主 zip 的 `toolchain/feellab`、`data/_lab*`、`lab/fixtures` | 新的可选包 `com.gamefoundation.feel-lab.headless`（`Tools~/feellab/{bin,lib,labroot}`），不进主 zip 与工具链包 |
| 三个演示场景（2D、2.5D、3D）与其美术 | 框架仓库 | 本地样板仓库 `ws-game-samples`（按版本号消费框架），框架不再带 |
| 发布流程 | 门禁 → 打标签 → 发布 | 门禁 → **候选阶段（`X-rc.N`，样板仓库跑全量门禁）** → 打标签 → 发布 |
| 包与附件数量 | 四个包、九件附件 | 六个包、十一件附件 |

## 3. 推荐升级路径

直接升到 2.0.0：先改版本号，再按第 4 节处理你用到的那几项，最后跑第 5 节检查表。不需要中间版本。

## 4. 逐项迁移

### 4.1 必做

1. **版本号**：`ws-game.lock`、`Packages/manifest.json` 里 `com.gamefoundation.adapter.unity`/`com.gamefoundation.framework-data`/`com.gamefoundation.toolchain` 三个依赖版本都改到 2.0.0；重新跑 `toolchain/get_framework.ps1 -Version 2.0.0 [-FromRegistry]`，并重跑 `toolchain/sync_package_content.ps1 -UnityProjectPath <工程>`。
2. **用到实验室引擎宿主的游戏**：在工程 `Packages/manifest.json` 的 `dependencies` 里加 `"com.gamefoundation.feel-lab.unity": "2.0.0"`（作用域注册表的 `scopes` 已含 `com.gamefoundation`，无需改）。把你自己代码里对程序集 `Adapter.Unity.LabHost` 的引用改成 `FeelLab.Unity`（编辑器代码改 `FeelLab.Unity.Editor`），命名空间同样由 `Adapter.Unity.LabHost` 改为 `FeelLab.Unity`；`using Adapter.Unity;` 仍需要保留。该包的程序集只在编辑器编译，**在运行期（玩家构建）代码里引用它会编译失败，这是有意的**：实验室不得进游戏独立版。
3. **用到实验室命令行或数据集的游戏**：改装 `com.gamefoundation.feel-lab.headless`（`npm install com.gamefoundation.feel-lab.headless@2.0.0 --registry <私服地址>`，或从发布 Release 取 `com.gamefoundation.feel-lab.headless-2.0.0.tgz`）。命令行改为 `dotnet <包>/Tools~/feellab/bin/FeelLab.dll <子命令>`，工作目录用 `<包>/Tools~/feellab/labroot/`，叠加自己的数据根用 `--data-root`（用法不变）。之前用 `dist/<版本>/toolchain/feellab/...` 或工具链包 `Tools~/feellab/...` 的脚本与 CI 需要改路径。
4. **用到三个演示场景的游戏**：它们不再随框架分发。需要参考样板时，使用样板仓库 `ws-game-samples`（本地仓库，在框架同级目录）。

### 4.2 行为变更

- 适配层包里 `UnityAudio.Tick(double)`、`UnityCamera.Tick(double)`、`UnityResourceLoader.Tick()` 现在是公开方法（原先 `internal`，靠友元程序集给实验室宿主）；游戏侧一般不需要调用。
- `EngineLabOptions.Showcase` 布尔选项已删除，改由 `EngineLabOptions.StageExtension`（舞台扩展）与 `LabPlayground.Extension`（试玩宿主扩展）表达，见第 4.3 节。
- 不装任何扩展时，试玩宿主就是占位试玩场景（面板缺省展开、没有面板提示、舞台建缺省地面），逻辑指纹与之前一致。

### 4.3 可选采用：在实验室公开扩展点上搭自己的演示

`com.gamefoundation.feel-lab.unity` 提供两个公开扩展点，供游戏或样板自建演示场景而不依赖任何友元程序集：

- `LabPlaygroundExtension`：额外数据根、舞台扩展工厂、环绕镜头开关、面板缺省可见性与提示、角落提示、会话起止通知；
- `EngineStageExtension`（配合 `StageSceneContext`、`IStageProjection`）：外形登记替换、场景搭建（返回真则舞台不建缺省地面）、投影（广告牌朝向与深度排序）、显示绑定、逻辑事件、出手、每帧推进、朝向换算、释放。

范式见样板仓库 `ws-game-samples` 的 `Samples.Showcase` 包；框架里的 `ExtensionPointsPlayModeTests` 是它们的契约用例。

### 4.4 发布侧（仅框架维护者）

`build.ps1 -Release X` 新增候选阶段：本机必须有样板仓库（`-SamplesRepo`，或环境变量 `WS_GAME_SAMPLES`，或同级 `ws-game-samples`）；没有时发布被拒绝，显式 `-SkipSamplesCandidate` 才放行并记 `OPT-OUT`。候选版本 `X-rc.N` 只发本地私服，不打标签、不推送。

### 4.5 验证

- 独立版构建里不得有实验室或演示内容：消费方演练（`toolchain/consumer_smoke.ps1`）在装了 `com.gamefoundation.feel-lab.unity` 的工程里构建独立版，并断言产物里没有实验室或演示的程序集、数据与资源。游戏自己也可以在构建产物目录里搜 `FeelLab`、`LabHost`、`Showcase` 做同样的检查。
- 实验室命令行：`dotnet <包>/Tools~/feellab/bin/FeelLab.dll suite` 在包里的 `labroot/` 下应与框架基线一致（`RESULT total=<n> pass=<n> diff=0 missing=0`）。

## 5. 总检查表

- [ ] 三个 Unity 依赖与 `ws-game.lock` 都指向 2.0.0，已重跑 `sync_package_content.ps1`
- [ ] 用实验室引擎宿主：已装 `com.gamefoundation.feel-lab.unity`，自己代码的程序集引用与命名空间已改为 `FeelLab.Unity`/`FeelLab.Unity.Editor`，且只在编辑器代码里引用
- [ ] 用实验室命令行或数据集：已装 `com.gamefoundation.feel-lab.headless`，脚本与 CI 路径已改
- [ ] 独立版构建产物里搜不到 `FeelLab`、`LabHost`、`Showcase`
- [ ] 游戏自己的门禁（编译、EditMode、PlayMode、独立版冒烟）全绿
