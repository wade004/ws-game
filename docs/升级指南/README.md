# 升级指南索引

本目录存放"面向游戏侧的跨版本升级指南"——一份指南覆盖多个连续发布版本，给出从某个起点版本升到某
个终点版本需要做的全部事情（数据表升版、代码适配、行为确认、编辑器契约面变化、验证方法），并附
一张可逐项打勾的检查表。

与仓库根 `CHANGELOG.md` 的关系：`CHANGELOG.md` 每个版本区间的"迁移说明"小节记录**单版增量**——
只回答"从上一个 PATCH/MINOR 升到这一个版本，我需要注意什么"；本目录的每份指南记录**跨版本升级
路径**——回答"从版本 A 跨若干个 MINOR 升到版本 B，把中间每一版的迁移说明合并去重、按主题重新组织
后，我总共需要做哪些事"。两者不是互相替代关系：升级单个 MINOR 版本时查 `CHANGELOG.md` 就够；一次
跨多个版本升级时，先查本目录是否已有覆盖该区间的指南，没有则仍需逐版查 `CHANGELOG.md`"迁移说明"。

新增一份跨版本指南的时机：某个专项（如一次数值设计、一次表现层改版）连续跨越多个 MINOR 版本落地
完毕后，为该专项区间补一份指南；不要求每一对相邻版本都有对应指南。

## 编写规范（供后续新增指南参照）

- 每条结论标注来源版本号，来源是 `CHANGELOG.md` 对应版本的"新增/变更/迁移说明"小节、
  `architecture/落地计划/` 对应落地计划的"落地进度记录"、相关 ADR 的"决策"节；不确定的事实去
  代码核实，核实不了就不写，不凭印象编造。
- 不整段复制 `CHANGELOG.md` 原文，提炼成"游戏要做什么"；每条建议具体到文件/表/字段/命令名字，
  可执行。
- 结构固定：适用范围与读者、一页总览、推荐升级路径、逐版本升级说明（必做/行为变更/可选采用/
  编辑器/验证五个固定小标题）、总检查表、附录（数据表版本变化、新增表、废弃与替代 API、新增
  校验检查名、分发布局变化）。
