# 消费方反馈处理记录（样板游戏 B「2.5D 目标选择式 RPG」：五项缺口与若干备忘，2026-10-08）

> 本文档允许出现具体技术名（引擎/语言/框架/工具名），不受 `architecture/00～14` 与
> `architecture/adr/` 正文的禁用词约束。反馈来自样板仓库 `ws-game-samples` 里的"样板游戏 B"
> （`tab_target_rpg`：斜透视相机 + 公告牌精灵的 2.5D 目标选择式 RPG，只按版本号消费框架，并声明内容起步包
> `GameOptions.StarterKitDatasetRoot`）开发中撞到的缺口。按"上游缺口不绕行"规则，阻塞项没有在游戏侧绕过，
> 而是在框架分支 `feature/p5b-gaps_20261008` 上先写红的复现用例、再根治。契约决定见 ADR-0164。

**结论先行**：五项缺口，均已修并带"红绿对照"用例，均为纯加法或行为只在原先必然出错的场景下变化：
G1 生产渲染链路不支持相机偏航后的 2.5D 呈现（排序/朝向/公告牌）；G2 技能没有朝向弧检查；
G3 内容起步包稀有/史诗品质的装备预算规则互相矛盾；G4 召唤物击杀不给召唤者的任务计数；
G5 反馈绑定取不到召唤事件的实体 id。另有三项经查证后登记为"已知限制"（不绕行、不阻塞，见 C 节）。

## A. 阻塞缺口（已修）

| 编号 | 症状（消费方可观测） | 根因 | 修法 | 复现与不变量用例（先红后绿） |
|---|---|---|---|---|
| G1 | 相机绕竖轴转动后：角色遮挡关系错（该在前面的被后面的盖住）、朝向与相机不跟随；相机俯仰倾斜后精灵"躺"在地面上、特效序列帧同理 | 排序键与朝向换算没有把相机偏航算进去；引擎适配层精灵实例把"高度"直接写成本地 Y（平放在世界平面），此前只有实验室场景里有一份私有实现 | `RenderOptions.CameraYawRadiansProvider`；精灵渲染器 `BillboardCamera` + `ApplyBillboards()`；`vfx.def.upright`；导入器 `--upright` | `RenderConventionHostTests.CameraYawProvider_*`（3 条）；`UnityRenderer2DTests.Billboard_NoCamera_*` / `Billboard_WithCamera_*`；`test_import_assets.py::test_vfx_upright_flag_writes_field_and_survives_reimport` |
| G2 | 目标选择式游戏的"目标在身后不能施放"只能由游戏在施法前自己算，拿不到统一的失败原因 | 显式目标施法只走目标链过滤，不检查施法者面向 | 技能新增可选 `facing_arc`（度），起手检查一次，失败原因 `CastFailureReason.NotFacing`（枚举末尾追加）；校验规则 `facing_arc_range` / `facing_arc_timeline_conflict` | `CastFacingArcTests`（9 条：身后失败/身前成功、未声明从不失败、边界、绕过 ±π、目标重合、校验规则） |
| G3 | 内容起步包的稀有/史诗装备（带可抽词缀，预留份额 0.3）：模板自身消耗至多占 70%，而预算利用率警告要求至少 70%，窗口宽度为零，任何不带词缀的稀有装备要么报错要么报警 | 利用率分母用预算上限，没有扣除词缀预留份额 | 利用率分母 = 预算上限 ×（1 − 可抽词缀最大预留份额），警告消息写明已扣除；不带词缀的品质不变 | `ItemValidationRulesTests.BudgetRule_UtilizationWithAffixReserve_FullyUsedAvailableBudget_NoWarning` / `..._BelowAvailableBudget_StillWarnsAgainstAvailable` |

G1 边界：公告牌只处理旋转与高度抬升，不做"随相机距离缩放"的补偿；贴地的光环类特效应保持 `upright` 为假。
G2 边界：只在起手检查（读条途中目标绕到身后不打断）；只对显式解析出的目标生效，无目标施法（地面点、自身）不检查。
G3 边界：词缀预留份额口径按品质池、模板词缀白名单与 `affix_count` 计算，不含按等级过滤等其它抽取规则。
G4 边界：只改缺省；游戏自己的归属规则（队伍、宠物主人等）仍经 `questOwnerResolver` 注入。
G5 边界：升级事件在数值层、不是表达式可读事件，取不到单位 id，见 C 节第 1 条。

## B. 内容起步包被样板驱动的修正与观察

- 起步包漏了 `stat.healing_done_pct`（治疗加成）的属性定义：战斗结算默认读它，带治疗技能的游戏每次结算都告警"属性缺失，按 0 处理"。已补进起步包（属性定义 + 中英文名），不变量用例 `toolchain/tests/test_starter_kit_data.py::test_kit_defines_every_percent_stat_the_combat_resolver_reads_by_default`（先红后绿：补之前缺该属性）。
- 起步包的稀有/史诗装备预算矛盾已由 G3 根治，样板游戏 B 的装备不压任何预算告警。
- 起步包的动作条布局固定 4 槽（`ui_layout_definition.kit_action_bar`）：样板需要 6 个技能，只能用同 id 的 `override` 行改成 6 槽；
  同理 `kit_hud` / `kit_pause_menu` / `kit_save_slots` 引用本游戏皮肤也是覆盖行。已登记为备忘：建议起步包的动作条槽数可由游戏数据声明而不是整行覆盖。
- 起步包的抗性曲线只含物理一条：非物理学派（火焰/冰霜/奥术/暗影）的结算按学派读 `stat.resist_<学派>` 与 `combat.resist.<id>`，
  样板游戏 B 自己登记了四个学派的属性定义与饱和曲线；不登记属性时每次结算告警"属性缺失，按 0 处理"。建议起步包补齐常见学派的属性定义。
- 数据校验器出现 7 条 `sim_growth_opponent_ambiguous` 警告：起步包的敌人原型（`kit_melee_grunt`、`kit_heavy_brute`、`kit_boss`）与游戏自己的敌人在同档位同等级同时存在，
  `GrowthSimulation.ResolveCreatureFamily` 只取登记顺序第一条。这是"声明起步包 + 自己做敌人"的常态，已接受而不压制；
  建议后续让该规则只对游戏自己的根报警，或让起步包的样例敌人带可识别的"样例"标记。

## C. 已知限制与备忘（未改框架，游戏侧已有等价接法）

1. **升级事件挂接实体的特效无法声明**：`LevelUpEvent` 位于数值层，不是 `IExprReadableEvent`（数值层不依赖规则层），反馈绑定取不到单位 id。
   样板游戏 B 的升级只放音效，升级提示由 HUD 自己订阅事件显示（ADR-0164 限制 5）。
2. **遭遇的阶段/波次条件在"结算"期间求值**：以"战斗开始后若干秒"这类时间条件做阶段切换时，条件必须同时要求处于战斗中（`self.in_combat`），
   否则战斗尚未开始的结算帧就会误触发。这是有意设计，样板游戏 B 的首领阶段条件已按此书写（ADR-0164 限制 6）。
3. **区域触发对每个移动过的单位求值**（包括敌人与场景道具），触发条件必须带阵营条件（`self.faction == fac.player`），否则敌人走过触发区也会触发；遭遇起始的"遭遇单位"同理。
4. **引擎适配层的宿主（`UnityEngineHost`）跨场景常驻，它的空间索引不随组合根销毁**：游戏模板的 `GameBootstrap.OnDestroy` 没有清空空间索引时，
   后一局会读到前一局的过期实体（顺序相关的测试失败）。样板游戏 B 在 `OnDestroy` 清空；建议模板同样处理（2.5.0 的 G3 只保证查询时丢弃不存在的单位，不负责清理）。
5. **`stat.resist_*` 需要游戏登记定义**：见 B 节。
6. **场景立牌（装饰生物）没有"装饰"通道**：树、帐篷、篝火等立牌在样板里是 `creature.template`（不可选中、不攻击），框架的视图工厂对每个显示行的每个状态都要找动画剪辑，没有 `display.anim_set` 行会逐状态逐立牌告警；样板给每个立牌一行全部状态键都指向同一张单帧待机剪辑（视觉静止、日志干净）。建议框架提供不需要动画集的静态装饰通道。
