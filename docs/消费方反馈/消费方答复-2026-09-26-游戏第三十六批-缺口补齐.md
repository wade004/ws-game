# 消费方答复：第三十六批顺带发现的区域卸载缺口已补（2026-09-26）

## 结论

落在 **1.73.0**（标签 `v1.73.0`，发布提交 `cc1d41be`，修复提交 `4d8f4331`）。ADR-0090。这是第三十六批答复里"顺带发现（未修）"那条的补齐；第三十六批本身的结论不变（框架无缺陷，你方两条规则加单位过滤）。

## 修法

- **卸载即离开**：`IAreaTriggerHost.Unregister(triggerId)` / `UnloadMap(mapId)` 时，对该触发器内每个仍处于"已进入"状态的单位各补发一条 `area.trigger_left`，然后再清状态。已正常走出的单位不重复发；空区域卸载不发。**行为变更**：切图/读档时你方所有订阅 `area.trigger_left` 的规则（含 `stop_sfx`）都会收到这批事件。
- **事件新增 `reason` 字段**：`AreaTriggerLeftEvent.Reason`，枚举 `moved | unloaded | despawned`；`feedback.binding` 条件里可用 `event.reason == "moved"` 只响应真实走出。旧二参构造保留（默认 `moved`），ABI 只加法。`area.trigger_entered` 不变。
- 事件目录 `area.trigger_left` 已登记 `reason`。

## 凭据

- 复现：单位在区域内 → `UnloadMap` → 收到 `area.trigger_left(reason=unloaded)`；修复前 `Assert.Single() Failure: The collection was empty`。生产装配级：进入起播 → `UnloadMap` → 循环实例 1→0（修复前 `Assert.Contains() Failure`）。
- 不变量：正常走出 `reason=moved`；卸载空区域 0 事件；已走出单位不重复发。
- `Tests.Gameplay` 952/952、`Tests.PresentationCommon` 828/828；`abi_probe`（基线 1.72.0）breaks=0；发布门禁 32/32。

## 未覆盖（写在 ADR-0090 已知限制）

**单位消失（死亡/销毁）不补发 `left`**：区域触发宿主不持有单位存在性查询，没有现成检测点，本次不新建机制；`despawned` 枚举值保留但暂不触发。该单位会一直被 `GetActiveTriggerIds` 报告，直到其触发体被卸载（届时按 `unloaded` 一并清理）。你方若有"单位在区域内死亡/销毁后循环音效残留"的真实场景，标阻塞项反馈。

## 你方要做的

1. 升级 1.73.0；两条矿道规则按第三十六批答复加单位过滤后，切图/读档场景无需再额外接线。
2. 检查你方其它订阅 `area.trigger_left` 的规则/任务逻辑是否需要用 `event.reason == "moved"` 排除卸载来源。
