# 消费方反馈处理记录（样板游戏 C「3D 动作」：三项阻塞缺口，2026-10-08）

> 本文档允许出现具体技术名（引擎/语言/框架/工具名），不受 `architecture/00～14` 与
> `architecture/adr/` 正文的禁用词约束。反馈来自样板仓库 `ws-game-samples` 里的"样板游戏 C"
> （`action_3d`：第三人称 3D 动作样板，只按版本号消费框架，并声明内容起步包 `GameOptions.StarterKitDatasetRoot`）
> 开发中撞到的缺口：自由第三人称镜头（ADR-0161）、动作模式锁定战、选目标模式、首领大招预警与闪避、带高度差与坡道的室外区域。
> 按"上游缺口不绕行"规则，阻塞项没有在游戏侧绕过，而是在框架分支 `feature/p5c-gaps_20261008` 上先写红的复现用例、再根治。
> 契约决定见 ADR-0165。

**结论先行**：三项阻塞缺口，均已修并带"红绿对照"用例，均为纯加法或行为只在原先会崩溃/穿地的场景下变化：
G1 相机地面避让只认 `z = 0` 的平地，真实地形（斜坡、台地）上向上看时相机会钻进地里（新增 `UnityCamera.GroundHeightProvider`）；
G2 `IInput` 没有滚轮通道，游戏只能绕过输入接口直接读硬件（新增默认接口成员 `IInput.ConsumeScrollNotches()`）；
G3 空间索引里残留"已销毁、销毁事件尚未派发"的单位时，`nearest_in_shape` 等目标查询直接抛 `KeyNotFoundException`
（`BuiltinTargetStrategies.QueryShape` 过滤不存在的单位）。内容起步包本身没有发现需要改的数据或曲线问题（见 C 节）。

## A. 阻塞缺口（已修）

| 编号 | 症状（消费方可观测） | 根因 | 修法 | 复现与不变量用例 |
|---|---|---|---|---|
| G1 | 在有高度差的区域（台地、坡道）里，把镜头俯仰推过水平向上看（天空盒入画）时，相机落到地形以下：实测台地边缘相机离地 -0.4 ～ -1.98，画面里是地面内侧 | `UnityCamera` 的地面避让（`AvoidGround`）只知道平面 `z = 0`，不知道游戏的真实地形；焦点在高处、相机在低处的斜坡背后时判定恒为"在地面之上" | 新增可选属性 `UnityCamera.GroundHeightProvider`（`Func<double,double,double>?`，入参世界 XY，返回该处地表高度；缺省 `null` = 原行为逐位不变）。设置后避让沿焦点→相机连线做 32 等分采样找第一处穿地，再二分 24 次收敛到余量之上，最小距离 0.01；`GroundAvoidanceMargin` 仍是净空，焦点自己离地低于余量时按焦点净空收缩 | 适配层 PlayMode `UnityCameraTests.GroundHeightProvider_SlopeBehindTheFocus_LookUpCameraStaysAboveTheTerrain_FlatGroundAvoidanceDoesNot`（偏航 0/90/180/270 × 俯仰 20～150，修复前平地避让版红、provider 版绿）；样板侧 `A3dCameraTests` 台地仰视用例断言相机离地恒大于余量 |
| G2 | 镜头缩放要读鼠标滚轮，但 `IInput` 只有按钮/轴/指针，没有滚轮；游戏侧只好绕过输入接口直接读 `Mouse.current.scroll`，于是脚本化输入（机器人、回放、测试）驱动不了缩放，缩放也进不了确定性输入序列 | 契约缺口：输入接口没有"滚轮刻度"通道 | 新增默认接口成员 `double IInput.ConsumeScrollNotches()`（缺省返回 0，旧实现不用改）：返回自上次调用以来累积的滚轮刻度（向前滚为正），读后清零。`StubInput` 加 `ScrollWheel(double)` 供测试注入；`UnityInput` 绑定 `<Mouse>/scroll`，像素量（\|y\|≥20）按 120 一格折算 | `StubInputTests.ScrollWheel_AccumulatesNotches_ConsumeReturnsTheSumOnceThenZero`、`StubInputTests.ScrollWheel_AnInputWithoutWheelSupport_ReportsZeroThroughTheDefaultMember`；适配层 PlayMode `UnityInputTests.ConsumeScrollNotches_ReturnsAccumulatedNotchesOnceThenZero`；样板侧机器人经 `ScriptedInput.ScrollWheel` 驱动缩放并断言钳制范围 |
| G3 | 战斗中偶发崩溃：`nearest_in_shape`（选目标模式的自动辅助、AI 找候选）抛 `KeyNotFoundException`（`creature.inst_6` 不在世界里） | 单位被销毁的那个固定步里，空间索引还留着它的条目（销毁事件在稍后才派发、索引随事件更新），目标查询拿索引结果直接去 `WorldUnitAccess.Require` 取单位，取不到就抛 | `BuiltinTargetStrategies.QueryShape` 对索引结果用 `IUnitAccess.Exists` 过滤；格点吸附路径与"体半径额外候选"路径同样跳过不存在的单位；活单位的结果与顺序逐位不变 | `core/rules/targeting/tests/TargetHostStaleSpatialTests.cs`：`NearestInShape_SkipsStaleSpatialEntry_AndPicksNearestLiveUnit`、`AllInShape_SkipsStaleSpatialEntry_KeepsLiveOnesInDistanceOrder`、`BodyRadiusExtraCandidates_SkipStaleSpatialEntry`（修复前三条均红，KeyNotFound）、`WithoutStaleEntries_ResultsAreUnchanged`（不变量，前后皆绿）；样板侧整局通关与选目标机器人用例 |

G1 边界：只改相机位置的"够不着地面"一侧——相机仍然看向焦点；地形高度由游戏通过 provider 提供，框架不假设地形来源。
G2 边界：滚轮刻度的方向与折算由适配层决定，契约只规定"累积、读后清零、缺省 0"。
G3 边界：只丢弃不存在的单位；不尝试在索引里补删（索引的更新时机仍由事件派发决定）。

## B. 非阻塞备忘（游戏侧已有等价接法，未改框架）

1. **内容起步包的物品模板没有图标**：起步包 `item.template` 的 `display.map` 行都落到占位精灵，背包里是一排空格子。游戏侧用
   `display.map` 覆盖行补 `icon_id`（文件约定 `icons/item/<name>.png`），覆盖行是整行替换，必须自带 `direction_count`（kind 为 sprite 时必填），
   漏写会让数据校验阻断启动。建议起步包随包提供一套通用图标，或在文档里写明覆盖行要带哪些字段。
2. **任务自动开始/自动交付要游戏每个固定步调用 `Gameplay.Quest.Update(PlayerId)`**：框架不替游戏驱动；不调用时任务永远停在未接取。
   这是现有契约，只是容易漏，建议在任务系统 README 的接入清单里置顶。
3. **手感前摇缩放与顿帧会让"预警圈 = 数据前摇"对不上**：`ActionStartedEvent.StartupRate` 缩放时间线，命中顿帧冻结动作时钟。
   游戏侧的预警圈必须用"动作时钟（`ActionStateQuery.Current(...).ElapsedTicks` × 固定步长）"并除以 `StartupRate`，而不是墙钟和数据前摇；
   同一单位别的技能的施放失败/打断事件也会到达，预警只能按技能 id 匹配移除。建议在手感层 README 里写一段"预警类视觉如何对齐"的接法。

## C. 说明

- 内容起步包：样板游戏 C 的敌人（近战、远程、重型、首领）、技能（轻击连段、重击、蓄力、闪避带无敌帧、远程射击、大招）、
  装备、掉落、任务与曲线全部来自起步包，数据校验器 0 错 0 警告（无警告压制、无覆盖修补）。装备需求等级等于物品等级（起步包曲线恒等映射），
  样板里先升到 2 级再穿 `kit_sword_fine` / `kit_armor_mail`，这是设计而非缺陷。
- 闪避无敌帧窗口由起步包技能数据给出（接受后约 50～200 ms），无敌期间被命中的攻击发 `CombatAttackAvoidedEvent`，样板用该事件的逻辑时间断言
  "预警窗口内闪避、无伤"，不写死裸数。
- 验证：样板游戏 C 的 PlayMode 22 条（含相机偏航 360°、移动方向由偏航算出、仰视不穿地、坡道可达、锁定切换顺序、选目标机器人击杀、
  首领预警与闪避、整局通关、存读档一致与确定性）、EditMode 5 条、Python 17 条在框架候选版本上通过；通关机器人经真实输入通道
  （右键拖动转镜头 + 相机相对移动 + 键位）完成。
