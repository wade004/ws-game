# 消费方答复：游戏接入方第三十四批已交付（2026-09-25）

## 结论

阻塞解除，落在 **1.71.0**（标签 `v1.71.0`，发布提交 `924eaf56`，修复提交 `fda16b53`）。ADR-0089。按你方第一个"二选一"做，且 `play_sfx` 顺带加了 `attach`。

## 修法

- **`sfx.def` 新增可选字段 `loop: bool`**，缺省 `false`。循环标志经引擎适配契约一路落到播放单元的循环开关上（`IAudio.PlaySfx` 新增带 `loop` 的重载）。
- **`play_sfx` 新增可选 `attach: source|target|world`**，缺省 `world`（缺省时行为与以前逐字一致，不跟踪）。循环音效要想被停掉，必须写 `attach: source` 或 `target`——键是 `(sfx_id, 附着实体)`。
- **`feedback.binding` 新增 `stop_sfx` 动作**，形状与 `stop_vfx` 完全对齐：`sfx_id?|from_display` 二选一 + `attach: source|target`（`world` 构造期拒绝）。按 `(sfx_id, 附着实体)` 找到在播的循环实例就停；找不到静默、不记诊断（正常时序）。
- 同键重复 `play_sfx` **幂等不叠播**；一次性音效（`loop=false`）不跟踪、不建键。
- 契约全部 ABI 只加法：`ISfxPlayer` 新增默认成员 `PlayAttached/StopAttached`，`IFeedbackSink` 新增默认成员 `PlaySfx(sfxId, at, attach)/StopSfx(sfxId, attach)`；旧签名一律保留，你方现有代码不用改。

## 凭据

- 复现用例：经 `FeedbackBinder` 把 `play_sfx{loop def, attach: source}` 与 `stop_sfx{attach: source}` 绑到进入/离开两个事件——修复前红（无 `stop_sfx` 动作、无循环实例），修复后进入事件起播且不随剪辑时长结束、离开事件停止。
- 不变量：无 `attach`/无 `loop` 的 `play_sfx` 行为不变；`stop_sfx` 无匹配实例不抛、无诊断。
- 引擎适配层 PlayMode 用例 3 条：循环 def 播放后播放单元循环开关为真（14/14）。
- `abi_probe` `breaks=0`；`validate_data.py --strict` 0 错 0 警；发布门禁 32/32。

## 已知限制（写在 ADR 里）

**实体销毁不会自动停循环音效**——必须靠内容侧显式 `stop_sfx`。你方两个场景都有天然的离开事件（`area.trigger_left`、光环移除），各配一条 `stop_sfx` 即可；DoT 目标在光环移除前就死亡的场景，请把 `stop_sfx` 同时绑到死亡事件上。真需要框架兜底再反馈，另开 ADR。

## 你方要做的

1. 矿洞环境音：`sfx.def` 加 `loop: true`；`area.trigger_entered` → `play_sfx{attach: source}`，`area.trigger_left` → `stop_sfx{attach: source}`（同一 `sfx_id`、同一 attach 侧）。
2. 燃烧循环音：`aura.applied`（或命中事件）→ `play_sfx{attach: target}`，`aura.removed` + 目标死亡 → `stop_sfx{attach: target}`。
3. 升级后跑一遍 S01 音效批，反馈"离开区域后是否仍有残留循环"。
