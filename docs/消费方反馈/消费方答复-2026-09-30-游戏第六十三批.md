# 消费方答复：游戏接入方第六十三批已交付（2026-09-30）

## 结论

两条都成立，已落在 **1.91.0**（标签 `v1.91.0`，发布提交 `2ee88626`，修复提交 `6ed0f6bf` + `73642d91`，[ADR-0112](../../architecture/adr/0112-方向切换原子化与按实体预热全部方向.md)）。A（冷转向混搭 / 闪占位图）按缺陷修，B（按实体预热全部方向）按新增能力做。默认开启原子提交，预热默认关。

## A：方向切换原子化

- 视图区分**期望方向**与**已显示方向**。转向时先为新方向准备"当前显示所需"的资源：当前合成层每一层的静态图 + 运动态剪辑（`idle`、`move`，含声明了的 `combat_*` 变体）+ 实体此刻所处状态的剪辑 + 正在播放的覆盖剪辑。全部有结论（缺美术也算结论，不会无限等）后**当帧整体提交**，其余状态键提交后在后台补加载。准备期间整个实体保持旧方向，不出现新旧混搭、不出现占位图。
- 整身兜底渲染器可见时其内容方向必须等于已显示方向（不变量，有用例守着）。
- 仅镜像变化与热转向（缓存已有）当帧提交，0 帧保持。
- **行为变化**：`UnitySpriteView.DirectionSlotChanged` / `SpriteViewBase.OnDirectionSlotChanged` 改在**提交时**触发（此前是期望方向变化的当帧）。若你方有订阅者按它同步别的东西，语义变为"显示已切换"。
- 新增只读查询 `DesiredDirection` / `DisplayedDirection` / `HasPendingDirectionSwitch`；受保护虚方法 `PrepareDirection` / `OnDirectionCommitted`。纯新增 ABI。

## B：按实体预热

- `UnityViewFactory.PrewarmDirections(entityId, onCompleted)`：镜像对去重后逐档位顺序加载全部状态键与覆盖剪辑，填满缓存不改显示；实体真实转向的准备优先，档位之间让路；换装后自动补预热新增层；销毁时取消并以 `false` 回调。只读进度 `TryGetDirectionPrewarmProgress`。
- 选项 `UnityViewFactory.DirectionPrewarm`：`DirectionPrewarmPolicy.None`（默认）/ `OnAttach`（挂接即预热）。走加载器既有分帧预算，不额外抢主线程。

## 凭据（你方真实外形：16 方向、5 个声明键、身体 + 一件装备）

冷转向保持窗口 = 转向后旧方向多停的时间（保持帧数 / ms）：

| 目标档位 | 1.90.0 混搭窗口 | 1.91.0，4 ms 预算 | 1.91.0，8 ms 预算 |
|---|---|---|---|
| back | 80～263 ms（混搭 + 占位） | 14 / 238 | 14 / 237 |
| front | 同上 | 21 / 354 | 11 / 193 |
| front_side_r_a | 同上 | 20 / 338 | 9 / 155 |

- 保持期间占位帧 0、混搭帧 0；热转向 0 帧。
- 预热后首次转向任一方向 0 帧。预热耗时 4 ms 预算约 3.6 s / 8 ms 预算约 2.3 s；**代价约 1.4 GB 纹理内存**（该外形全部 9 个档位常驻）。
- 提交后立刻进入尚未就绪的状态（例如冷转向后马上攻击）：该状态各层先显示新方向静态图，剪辑就绪后接上；用例实测 4 帧无进展期间无占位、无混搭，恢复后 40 帧内接上。
- 定向回归：引擎侧 PlayMode 362/362（含第六十二批 103 例）、EditMode 91/91、表现层核心 849/849、ABI 探针 OK。
- 发布门禁 32/32，PlayMode 362/362。

## 已知限制

1. 冷转向保持时间等于"当前显示所需"资源里最慢一项的加载时间；4 ms 预算下 front 类档位仍约 340～350 ms。要更短只能提高 `MainThreadBudgetMilliseconds` 或预热。
2. 首次显示与换装冷加载仍有 1～3 帧占位（约 17～100 ms，磁盘缓存冷热浮动），本批不改。
3. 预热是全部方向贴图常驻，按 1.4 GB / 外形计，不要对所有单位开 `OnAttach`。
