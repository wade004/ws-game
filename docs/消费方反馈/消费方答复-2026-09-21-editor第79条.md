### 对编辑器有影响的条目（逐条核对 1.52.0/1.53.0 全部 CHANGELOG 条目后的结果）

`1.52.0`、`1.53.0` 各自包含若干条目，其中绝大多数是 C# 侧运行时/表现层契约新增（`ISkillHost`

**不改动任何数据 schema 字段**，与内容编辑器编辑数据表无关，逐条核对后确认无影响，不再展开。

以下两条改动了数据 schema，会直接体现为编辑器表格里的新增可编辑列，需要提醒：

1. **`skill.aura_def` 新增可选字段 `name_key`（1.52.0，ADR-0056 决策 1）**：`FieldKind.TextKey`，
   命名/类型沿用 `skill.def.name_key`（ADR-0048）同一惯例，缺省未声明。
2. **`skill.aura_def` 新增可选字段 `polarity`/`icon_ref`（1.53.0，ADR-0060）**：
   - `polarity`：`FieldKind.Enum`，取值集合 `beneficial`/`harmful`，缺省未声明；
   - `icon_ref`：`FieldKind.Id`，类别前缀限定为 `icon`（受 ADR-0038/0039 资源引用前缀约束，
     即该字段只接受以 `icon.` 为前缀命名空间的资源引用标识，不是任意字符串）。

   三个字段合计给编辑器的 `skill.aura_def` 表格编辑界面新增三列可编辑字段：`name_key` 是纯文本，
   `polarity` 需要渲染为受限枚举选择控件（非任意文本），`icon_ref` 需要接入既有的资源引用选择/
   校验控件（同已支持的其它 `FieldKind.Id` 字段一致处理，校验前缀必须是 `icon`）。均为可选字段，
   未声明的既有行零改动仍合法，不需要为存量数据补值。

   另有一条**不要求编辑器改动、仅供留意**：`creature.template` 新增可选字段 `attack_interval`
   （1.52.0，ADR-0059 决策相关，`FieldKind.Number`，非必填，`min` 严格大于 0，未装备武器时的固定
   挥击间隔回退）。如果编辑器的表格编辑覆盖 `creature.template` 数据集，这里也会多一列；如果编辑器
   当前范围不含该数据集，可忽略本条。

## 第 79 条交付内容

### 新方法签名

- C#（`core/foundation/engine_adapter/contracts/AssetRootConventions.cs`）：

  ```csharp
  public static bool TryGetDatasetName(string dataRoot, string datasetDataDirectory, out string dataset);
  ```

- Python（`toolchain/asset_import/ref_conventions.py`）：

  ```python
  def try_get_dataset_name(data_root: Path, dataset_data_directory: Path) -> str | None:
  ```

  两侧各自独立实现、不互相调用，与既有 `ResolveAssetsRoot`/`ResolveDataRoot`/
  `DatasetAssetsDirectory`/`DatasetDataDirectory` 四组方法同一手法。

### 与转发稿里期望签名的差异

**无差异。** 转发稿建议的签名
`public static bool TryGetDatasetName(string dataRoot, string datasetDataDirectory, out string dataset)`
与实际交付逐字符一致；转发稿未给出具体的 Python 期望签名（只要求"两侧同形"），实际交付的
`try_get_dataset_name(data_root, dataset_data_directory) -> str | None` 与 C# 侧同一套输入/输出
形状对应（`bool + out` 在 Python 侧用"成功返回值 / 失败返回 `None`"表达，与本模块既有
`try_parse_sprite_set_id`/`try_parse_icon_id` 的既有惯例一致，不是本次新引入的表达方式）。

### 边界口径（逐条列清楚）

以下口径以 `AssetRootConventions.cs` 该方法 XML 注释与 `toolchain/README.md` 对应判断记录为准，
C#/Python 两侧逐条对应：

- **不是 `dataRoot` 的直接子目录**：更深一层（如 `<dataRoot>/a/b`）、根本身（就是 `dataRoot`）、
  或根之外（不在 `dataRoot` 之下），三种情况一律返回“不成功”（C# 侧 `TryGetDatasetName` 返回
  `false`；Python 侧 `try_get_dataset_name` 返回 `None`），不猜测、不编造数据集名。
- **分隔符与结尾分隔符**：比较前把 `/` 归一化为当前平台的目录分隔符（Windows 下 `\`），并去掉
  末尾多余的分隔符（长度为 1 的字符串，如裸盘符分隔符，不再继续裁剪）；两侧输入混用分隔符或结尾
  带斜杠不影响判定结果。不使用 `Path.GetFullPath`/`Path.resolve()` 做归一化——这类方法依赖当前
  工作目录，与仓库"运行时路径不依赖运行环境状态"的确定性要求冲突。
- **`.`/`..` 路径段不做语义解析**：与 `DatasetDataDirectory`/`dataset_data_directory` 本身"只是
  纯字符串拼接、不校验、不规整 `.`/`..` 段"的既有行为一致——正向方法都没有为这类输入定义行为，
  逆运算不借机新增正向没有的语义。含这类段的输入按字面字符比较，真实来源（对目录做遍历取得的
  已存在路径）不会产生这类段，不影响验收口径覆盖的实际场景。
- **相对路径不做绝对化，只按字面比较**：调用方须保证 `dataRoot`/`data_root` 与
  `datasetDataDirectory`/`dataset_data_directory` 处于同一相对/绝对表示下（典型来源都经同一次
  `ResolveDataRoot`/`resolve_data_root` 调用得到，天然满足）；混用两种表示属于调用方用法错误，
  返回“不成功”，不视为框架缺陷。
- **大小写**：父目录段按 Windows 文件系统语义做大小写不敏感比较（C# 侧
  `StringComparison.OrdinalIgnoreCase`，Python 侧 `str.lower()`，均不受当前文化/区域设置影响）；
  但**还原出的数据集名取自输入路径最后一段的原样字符**（调用方在磁盘上实际观测到的目录名字面量），
  不对大小写做任何变换，也不取自 `dataRoot` 或任何“标准”大小写——数据集名是内容标识，以调用方
  实际观测到的为准。
- **空参数**：C# 侧 `dataRoot` 为 `null` 时抛 `ArgumentNullException`（根目录是调用方必须持有的
  配置值，缺失属于调用方编程错误，与本类型其余方法既有约定一致）；`datasetDataDirectory` 为
  `null`/空字符串时返回 `false`（不抛异常——该参数来自调用方对磁盘的探测结果，缺失/未知本身就是
  一种合法输入）。Python 侧同一口径：`data_root` 为必需参数，`dataset_data_directory` 为空时返回
  `None`。

### 互逆保证

明确保证：`TryGetDatasetName`/`try_get_dataset_name` 与正向 `DatasetDataDirectory`/
`dataset_data_directory` 严格互逆——对任意不含路径分隔符的合法数据集名 `x`：

```
TryGetDatasetName(dataRoot, DatasetDataDirectory(dataRoot, x), out var y) && y == x
```

C# 与 Python 两侧各自独立实现、不互相调用，跨语言一致性由 `toolchain/asset_root_probe` 扩充的
第 5 个可选参数 `inverseProbeDirectory` 驱动：经子进程取得 C# 侧真实运行期结果后，与 Python 侧
`try_get_dataset_name` 的输出逐字节对照，对 `_sample` 数据集及本条反馈列出的边界场景均覆盖。

## 绕行代码可以拆除

消费方自行拆分路径字符串末段来推导数据集名的那段绕行代码，现在可以拆掉了：请改为直接调用
`AssetRootConventions.TryGetDatasetName`（C# 侧）或 `ref_conventions.try_get_dataset_name`
（Python 侧），按上面的边界口径处理“不成功”分支即可，不需要再自己判断路径层级、分隔符或大小写。
