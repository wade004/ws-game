# 消费方反馈处理记录（样板游戏 C「3D 动作」：镜头被布景遮挡，2026-10-08）

> 本文档允许出现具体技术名（引擎/语言/框架/工具名），不受 `architecture/00～14` 与
> `architecture/adr/` 正文的禁用词约束。反馈来自样板仓库 `ws-game-samples` 里的"样板游戏 C"（`action_3d`）截图复核：
> 第三人称镜头与主角/锁定目标之间的大树把画面挡死（`03_lock_on_combat`、`09_target_select_combat` 里主角或目标几乎看不见）。
> 按"上游缺口不绕行"规则，没有在游戏侧自建镜头逻辑，而是在框架分支 `feature/polish-gaps_20261008` 上补通用能力。
> 契约决定见 ADR-0166。

**结论先行**：一项缺口，已修，纯加法、缺省关闭：

| 编号 | 症状（消费方可观测） | 根因 | 修法 | 用例 |
|---|---|---|---|---|
| H1 | 树、岩石落在"镜头 → 主角"或"镜头 → 锁定目标"连线上时，把角色/目标整个遮住；战斗截图里看不到谁在打谁 | 框架相机只有地面避让（ADR-0161/0165，只管地形），没有布景遮挡的处理手段；游戏侧要么放任、要么自建一套"逐帧找遮挡物并改材质"的平行机制 | `UnityCamera.EnableOcclusionFade(CameraOcclusionOptions?)` 返回 `CameraOcclusionFader`：游戏登记会挡视线的渲染物，淡化器每个相机帧按"镜头 → 焦点（及游戏登记的额外观察点）"线段 + 视线半径与渲染物包围盒相交判定，被挡的渲染物按步长线性淡到 `FadedOpacity`，离开后恢复；淡出量写逐渲染物属性块（缺省 `_OcclusionFade`），恢复到 1 清掉覆盖。不启用时相机不创建淡化器，行为逐位不变 | `UnityCameraTests.OcclusionFade_*` 七条（先红：未实现时编译即失败；再绿） |

**二选一的结论：淡化，不做镜头前推。** 前推清不出"镜头 → 锁定目标"的连线（只能靠近主角），会吞掉主角，密林里连续遮挡物让距离逐帧跳变，
还要与地面避让、缩放、手感镜头冲击三处距离修正互相协调；淡化只改表现、不碰取景，主角与目标两条连线能同时清出来。

边界：判定是包围盒近似（外扩取立方体，对盒角略偏保守）；包围盒登记时取一次，运动的遮挡物要显式 `Refresh`；淡化的是整个渲染物，
游戏若把整张地图的布景合并成一个渲染物会整体淡化，所以要一物一渲染物登记；框架只规定属性名与取值语义，怎么画由游戏的着色器决定
（样板 C 用屏幕网点抖动透明，`_OcclusionFade` 放在逐材质常量缓冲里，不破坏 SRP 合批）。

## 样板侧接法（给后续游戏参考）

1. 创建相机后 `EnableOcclusionFade(new CameraOcclusionOptions { SightRadius = <角色轮廓半宽> })`；
2. 世界画面按"一棵树/一块岩石一个渲染物"建网格并 `Add` 给淡化器；
3. 锁定目标时每帧 `SetWatchPoints(目标胸口)`，解除锁定 `ClearWatchPoints()`；
4. 着色器声明 `_OcclusionFade`（缺省 1，放进逐材质常量缓冲）并按网点阈值丢弃像素。
