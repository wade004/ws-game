# 消费方反馈处理记录（样板游戏 A：切图后上一张地图的分层图残留，2026-10-07）

> 本文档允许出现具体技术名（引擎/语言/框架/工具名），不受 `architecture/00～14` 与
> `architecture/adr/` 正文的禁用词约束。反馈来自样板仓库 `ws-game-samples` 里的"样板游戏 A"
> （俯视角动作 RPG 样板，只按版本号消费框架）P3 验收截图：HUD 写着"地牢二层"，画面却是小镇（石板广场、木屋、喷泉、长椅、路灯）；
> 首领战画面左侧也混着小镇的木屋与干草堆。按"上游缺口不绕行"规则，没有在游戏侧去找并销毁框架建出来的地图层物体，
> 而是在框架分支 `feature/map-switch-fix_20261007` 上先写红的复现用例、再根治，随补丁版 `2.3.1` 发布。

**结论先行**：缺陷在框架 `Presentation.Render.MapLayerHost`——地图分层图的异步加载回调无条件建层，回调晚于切图到达时建出无人销毁的孤儿层。
单个缺陷、纯行为修正（公开签名与数据不变），带"红绿对照"用例与随机交错不变量用例。样板游戏 A 侧新增 PlayMode 不变量用例按 bot 路线逐次校验。

## A. 现象与根因

| 项 | 内容 |
|---|---|
| 现象（消费方可观测） | 场景里同时存在两张地图的分层图 `SpriteRenderer`：物体名 `MapLayer_<句柄>_<地图 id>_<层>` 里出现不属于当前地图的 id。孤儿层与当前地图的地面层同一排序序号（`ground` → 0）、世界矩形相互重叠（小镇 32x24 落在地牢 48x32 的左下角），画面上两张地图的美术叠在一起 |
| 复现 | 样板游戏 A 的不变量用例沿 bot 路线（小镇 → 一层 → 二层 → 回一层 → 回小镇、死亡回城后再进地牢、读档后再进地牢）逐次换图，换图稳定后枚举场景里全部 `MapLayer_*` 物体：修复前在"读档回小镇"一步红——场景里同时有两套小镇层与一套一层层（`MapLayer_25..33`），而当前地图只应有 3 个层物体；`MapLayerHost.ActiveMapCount` 只记得其中一套 |
| 根因 | `MapLayerHost.OnPostLoad` 发起 `ResourceKind.MapLayers` 的 `LoadAsync`（真实加载器经后台线程读盘、主线程 `Tick` 才回调），回调里无条件 `BuildLayers`；而 `SceneRouter` 的切图不等这次加载。回调晚于切图时：（a）地图已被卸载，`pre_unload` 先于回调跑过、当时 `_activeLayers` 里没有这张图，建出来的层没人销毁；（b）同一张地图在加载完成前被再次请求（真实加载器 `UnityResourceLoader` 把两次请求并入同一次在途加载，两个回调都到达），后一次 `_activeLayers[mapId] = handles` 覆盖前一次记账，前一套层再也找不到。冷缓存/慢盘（加载窗口更长）更容易撞上，所以 P3 验收的第一轮截图出现、复跑时不出现——属于时序缺陷，不是数据缺陷 |
| 影响范围 | 所有使用 `PresentationAssembly.MapLayers` 的游戏；切图快于分层图加载完成、或同一张地图连续请求（开局默认地图后立即读档回同一张图）时发生；孤儿层持续到进程结束 |

## B. 修法

`presentation/render/core/MapLayerHost.cs`：每次载入领一个令牌（`_pendingLoadTokens`），`post_load` 先作废该图旧状态再领新令牌，
`pre_unload` 与 `Dispose` 清掉令牌；回调只在"令牌仍是该地图最新令牌"时建层，且建层或判定失败即消费令牌（同一令牌至多一次）。
不去读路由器的当前场景（宿主只订阅 `pre_unload`/`post_load` 两个挂载点，保持原有依赖面）。`Dispose` 之后迟到的回调也不再建层。
判断记录见 `presentation/render/README.md` 第 33 条。

## C. 复现与不变量用例

- `presentation/render/tests/MapLayerHostTests.cs`（用 `ManualMapLayersLoader` 手动放行地图分层图加载，`StubRenderer2D` 的建层/销毁记录推出存活层，不看宿主自己的记账）：
  - `LeavingMapBeforeLayerLoadCompletes_LateCompletion_BuildsNothingForTheOldMap`（修复前红）
  - `SameMapRequestedTwiceBeforeLayerLoadCompletes_BuildsExactlyOneSet`（修复前红：存活 6 层）
  - `LayerLoadCompletionAfterDispose_BuildsNothing`（修复前红）
  - `RandomSwitchAndReleaseOrders_AliveLayersAlwaysBelongToCurrentMapOnly`（固定种子，200 轮 x 12 步切图/放行交错；每步断言存活层只属于当前地图、层数 0 或恰好一整套，全部放行后恰好当前地图一整套；修复前红）
- 样板游戏 A：`ArpgMapLayerInvariantTests.Bot_RouteThroughEveryMapSwitch_OnlyCurrentMapLayersAlive`（真实加载器、真实输入通道；期望由当前地图 `image_transform` 与素材目录算出，不写死）。

## D. 说明

- 未增加适配层 PlayMode 用例：真实加载器的并入在途加载语义由 `UnityResourceLoaderInFlightCoalesceTests` 钉住，宿主侧的行为由上面的单元用例钉住，两端拼起来的整条链路由样板游戏 A 的 PlayMode 不变量用例覆盖。
- 回调晚于卸载到达时，该次加载解码出的资源缓存不由 `MapLayerHost` 回收（`IResourceLoader.Unload` 的调用时机属于加载器与场景路由）；这是修复前就存在的行为，本次不改。
