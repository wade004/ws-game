# 消费方答复：游戏接入方第三十六批排查结论（2026-09-26）

## 结论

**框架链路没有缺陷，不发新版本；你方改两条规则的 `condition` 即可。** 排查提交 `226e0bf5`（只新增生产装配级复现/对照用例与文档），1.72.0 可继续使用。

## 根因

- `area.trigger_entered` / `area.trigger_left` **对区域内的每个单位各发一次**；出生即在区域内的单位在地图加载后第一次评估时就收到"进入"。`attach: source` 取的是事件的 `unitId`。
- 你方的两条规则条件只写了 `event.trigger_id == <触发器>`，没按单位过滤。于是矿道圆内原本站着的单位（只读核对你方出生点表：4 个在圆内，1 个恰在边界上，含等号判定也算在内）在 t0 各起了一个循环实例；玩家进入后是第 N+1 个；玩家离开只停掉玩家自己那个。
- 你方采样函数统计的是"场景里任意一个剪辑名匹配且正在播放的音源"，不区分挂在哪个单位上，所以看到"停不掉"。
- `aura` 那条之所以好：`attach: target` 只挂在被施加光环的那一个单位上。

## 凭据（生产装配级：真 `AreaTriggerHost` + 真事件总线 + binder + `SfxPlayer`，玩家逐 tick 真实移动，音频异步解码）

| 场景 | 玩家进入前 | 区内停留 10s | 走进相邻区域后 |
|---|---|---|---|
| 只有玩家 | 0 | 1 | 0 |
| 区内有 NPC，条件只按区域 id | **1**（NPC t0 已起播） | 2 | **1**（剩 NPC 的） |
| 同现场，两条规则都追加 `self.faction == <玩家阵营>` | 0 | 1 | 0 |

第二行按你方口径断言"离开后 0"实测红（`t0 entered unit=npc … t143 left unit=player, entered <相邻> unit=player ‖ playing=1`）；第三行绿。你怀疑的四条（条件求值、离开/再进入同 tick 重入、长时循环键被摘、队列吞掉停止动作）都逐一排除：离开与进入相邻区域同 tick、先离开后进入、无重进入；停留 100 tick 后仍可停。

## 你方要做的

1. 把移除的两条规则加回来，**两条**的 `condition` 都追加 `and self.faction == <玩家阵营>`（`self` 即事件 `unitId`；你方另一个区域定义里已经用过这种写法）。若随从与玩家同阵营且可能留在区内，换一个只命中玩家的条件。
2. 自查办法：玩家走进区域**之前**先采样一次——按上面的结论，那时就已经在播。

## 顺带发现（未修，等你方反馈是否会踩到）

单位仍在区域内时该区域被整体卸载（`UnloadMap`/`Unregister`，如切图/读档），**不会补发 `area.trigger_left`**，靠"离开"规则停止的循环音效会一直播。与 ADR-0089 已知限制"实体销毁不自动停循环音效"同一类生命周期缺口。你方切图/读档流程若在区域内发生，请标为阻塞项反馈，届时按 ADR 处理（候选方案：卸载时对区内单位补发 `left`，或新增独立的卸载事件——需要拍板对任务/其它订阅方的影响）。
