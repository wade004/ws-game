## 语义（写死）

比较器序 = 绘制序：比较结果靠前 = 先绘制 = 位于画面后方。同层且 sortY 相等时，`Id` 小者在后、`Id` 大者在前（`SortYThenIdComparer` 升序）。

## 修法

- **契约**：`IRenderer2D.SetSortIdentity(handle, id)` 登记参与平局比较的稳定 id；`IRenderer2D.CompareDrawOrder(a, b)` 读回渲染器实际落到引擎的最终键（层、sortingOrder、排序轴上的最终位置含平局偏移），<0 表示 a 先绘制（在 b 后方），0 表示无法区分或同一句柄。`SpriteViewBase.Bind` 统一登记（冷热路径同一调用点）。
- **引擎实现**：`sortingOrder` 公式不变。同层且 sortY 逐位相等的实例组按 `TieBreakComparer` 排序，组内第 k 个成员沿透明排序轴加 `k × SortingConvention.TieBreakEpsilon`（1e-4 世界单位量级，肉眼不可见）的位置偏移，方向经实测使比较器靠前者被引擎先绘制；离组归零并重排。生产装配把 `IRenderConventionHost.TieBreakComparer` 接进 `UnityRenderer2D.TieBreakComparer`，未接线时退化为按 `Id` 升序的同一规则。
- 已知限制：平局偏移是对根物体位置的真实微小位移（你方诊断读 SortingGroup 根 Y 时会看到 1e-4 级差异）；`CompareDrawOrder` 只承诺两个存活句柄的当前相对顺序。

## 凭据（PlayMode，真实 `UnityRenderer2D` + 相机渲染到 RenderTexture 读像素）

- 复现：两精灵同层、sortY 逐位相同、重叠，5 帧每帧打乱 `SetTransform` 顺序，重叠区像素恒为 `Id` 大者颜色，`CompareDrawOrder` 符号与比较器一致。修前三次探针在受控窗口内未观测到互换（引擎兜底碰巧稳定），修前无 `CompareDrawOrder`，红绿分界以该 API 存在与否为准。
