# 消费方反馈处理记录（样板游戏 B「2.5D 目标选择式 RPG」：受击自动选中、施法动作、技能栏详情，2026-10-09）

> 本文档允许出现具体技术名（引擎/语言/框架/工具名），不受 `architecture/00～14` 与
> `architecture/adr/` 正文的禁用词约束。反馈来自样板仓库 `ws-game-samples` 里的"样板游戏 B"
> （`tab_target_rpg`）试玩的三条意见。按"上游缺口不绕行"规则，缺口没有在游戏侧绕过，
> 而是在框架分支上先写红的复现用例、再根治；契约决定见 ADR-0177、ADR-0174、ADR-0175。

**结论先行**：三条反馈各查到一处框架缺口，均为纯加法（唯一的行为修正见 B2、B4，只在原先必然出错的场景下变化），均带红绿对照用例：

| 反馈 | 框架原有能力 | 缺口 | 处理 |
|---|---|---|---|
| A「玩家受到攻击时，如果玩家没有目标，应该自动把玩家目标锁定为攻击者」 | 没有"单位当前目标"的概念：目标选择由游戏自己持有，框架只有仇恨表与自动攻击目标 | 缺受击自动选中 | ADR-0177：载体层目标持有宿主 + `creature.template.target_lock` 数据开关（缺省关闭） |
| B「施法时没有施法动作」 | 武器风格 `cast_anim_override` 按技能选读条剪辑 | 读条剪辑只播一遍、读完无释放动作、瞬发一律用普攻剪辑、受击顶掉后读条剩余时间无姿势、武器风格剪辑首次使用显示白色占位帧 | ADR-0174：`release_anim_override`、状态机回到施法姿势、武器风格剪辑预热 |
| C「鼠标放到技能上应显示技能详情，鼠标左键点击技能应可以使用技能」 | 动作条视图模型 `Presentation.ActionBar`（技能格、冷却、可用性）；技能栏本身由游戏自己画 | 缺提示框的内容（数值含属性缩放、本地化说明）；点击施放属于游戏自己的界面，无框架缺口 | ADR-0175：纯数据 `SkillTooltipBuilder` + `skill.def.desc_key`；点击在样板里走同一条输入意图通道 |

## A. 受击自动选中（ADR-0177）

| 项 | 内容 |
|---|---|
| 症状 | 没有目标时被怪打，玩家要自己 Tab 选中攻击者才能还手 |
| 根因 | 框架没有"单位当前目标"的持有者，伤害事件落地后无处写入"选中攻击者" |
| 修法 | `ITargetLockHost`/`TargetLockHost`（`CarriersAssembly.TargetLock`），事件 `unit.target_changed`，数据 `creature.template.target_lock { auto_select_on_hit, modes[] }` |
| 规则 | 仅当没有目标或目标已死亡/无效时选中；已有有效目标不抢；攻击者沿归属链归到召唤者/投射物施放者；只认敌对（友方误伤、环境伤害、来源已死的持续伤害不选）；同批多个攻击者取先派发的伤害事件；`modes` 声明在哪些控制模式下生效（控制模式标签由游戏设置，动作模式游戏不声明即不生效） |
| 用例（先红后绿 + 不变量） | `ADR0177_TargetLockTests`（12 条：无目标被打选中、已有目标不抢、目标死亡后重选、召唤物归属者、投射物归施放者、友方误伤不选、环境伤害不选、死亡来源 DoT 不选、同批取先派发、模式不匹配不选、缺省关闭、目标变更事件原因/来源） |

## B. 施法动作（ADR-0174）

运行时观察到的根因（样板游戏 B 玩家法师，真实装配）：

1. 读条剪辑只播一遍：比读条时间短时，读条后半段站回待机。
2. 读条完成立刻回落运动态，没有"释放"动作；瞬发技能一律播普攻剪辑。
3. 读条中被受击姿势（优先级更高）顶掉，受击结束回到运动态，读条剩余时间无施法姿势。
4. 读条期间别的施法请求被拒（敌人 AI 每个决策间隔再请求一次的 `Busy`，玩家读条时按别的技能键同理），`skill.cast_failed` 被当作读条收尾，姿势提前收回待机（咒术师读条 1.8 秒，约 0.3 秒后站回待机）。
5. 武器风格里不在动画集默认状态的剪辑，第一次使用时先显示 1x1 白色占位帧（实测约 2 秒），第一次施法看到的是白点。

| 编号 | 修法 | 用例（先红后绿） |
|---|---|---|
| B1 | `display.weapon_style.release_anim_override`；读条期间循环读条剪辑、完成播释放、被打断直接回落；瞬发直接播释放 | `ADR0174_CastReleaseAnimTests`（7 条） |
| B2 | 状态机：受击结束时读条仍在继续则回到 Cast（对所有游戏生效，原先是缺陷） | 同上 |
| B3 | 工具链资源存在性检查覆盖 `release_anim_override` | `test_import_assets.py::test_weapon_style_release_anim_override_missing_resource_is_reported_then_present` |
| B5 | 状态机按读条实例 id 区分：别的请求被拒不收读条姿势（对所有游戏生效，原先是缺陷） | `ADR0174_CastReleaseAnimTests`（追加 2 条） |
| B4 | `UnityViewFactory.PrewarmWeaponStyleClips`：挂接动画播放器与换主手武器后预热该实体武器风格的动作剪辑 | `WeaponClipRegistrationTests.WeaponStyleCastClip_IsPrewarmedAfterAttach_BeforeAnyCastHappens`（引擎 PlayMode） |

**已知限制**：

- 读条剪辑循环对美术有要求：应是可首尾相接的蓄力片段，释放剪辑是出手到收招片段；一份既含蓄力又含出手的整段剪辑不适合直接循环。样板游戏 B 用确定性脚本把已有的整段施法帧重切成两段，没有新增美术。
- 没有声明释放动作的技能（含敌人施法者）仍是"读条剪辑播一遍"，剪辑比读条时间短时后半段会回待机；样板里敌人的施法剪辑时长不短于读条时间，所以不受影响。
- 受击姿势顶掉后回到 Cast 是从读条剪辑第一帧重播，不记录进度。

## C. 技能栏悬停详情与点击施放（ADR-0175）

归属判断：技能栏是游戏自己画的（框架只提供动作条视图模型），所以悬停与点击的交互属于游戏；提示框的内容（名称、类型、读条、冷却、消耗、射程、效果数值含属性缩放、说明）需要读技能数据与当前属性，每个游戏重写一遍必然不一致，属于框架该提供的纯数据能力。

| 项 | 内容 |
|---|---|
| 框架新增 | `Presentation.Ui.SkillTooltipBuilder.Build(registry, skillId, localize, context)` → `SkillTooltipContent`（名称、行列表、说明）；`skill.def.desc_key`（说明文本键，说明里不写数值，数值由行给出）；起步包 `l10n.ui.skill_tooltip.*` 中英文行 |
| 点击 = 热键 | 样板里点击只入队同一个 `InputActionTriggeredEvent`，之后走同一个待办队列，冷却、法力、没有目标等限制与提示和按键完全一致 |
| 不穿透世界 | 样板 HUD 画布原先没有射线检测器，鼠标永远"不在界面上"；给技能栏嵌套画布加射线检测，点技能栏不会同时点选背后的敌人 |
| 用例 | `SkillTooltipBuilderTests`（8 条：读条技能各字段与数据一致、英文无中文泄漏、效果值 = 基础 + Σ系数×属性且冷却/读条取有效值、瞬发无读条/冷却/消耗行、自身技能射程行、引导技能类型、无文本函数时的回退与未知技能返回空、行仅在数据存在时出现且构建确定） |
