## 反馈 3（阻塞项）：`event.<key>` 与字符串/Id 字面量比较不再被误报类型不一致（ADR-0076）

**根因**：解析用 schema 内部对 `event` 分组下**任意未登记 key** 恒注入一份固定签名——参数未知、
**返回类型恒为 Bool**。表达式校验器的比较检查据此认定该引用是 Bool，与运行期实际返回的 String/Id
比较即判定类型不一致、报 Error，整份表加载失败。

**改法**：对 `event` 分组**不再做任何特殊处理**，如实返回"未登记"，交给校验器既有的
"类型未知则跳过比较类型检查"分支处理。解析期/运行期求值路径**未改动**——`event.<key>` 的取值行为
与改动前逐字一致，改的只是静态期不再谎称它是 Bool。

**代价与边界（如实说明）**：`event.<key>` 现在对静态校验器是"未知类型"，因此
**比较两侧的类型检查对它不再生效**——写 `event.hit_result == 3` 也不会在加载期报错，只会在运行期
按实际值求值为假。这是有意的取舍：谎称一个类型会把真实可用的写法拦死（你方就是被这个拦住的），
而如实说未知只是少一层静态保护。语法错误、参数个数不对、未知分组**仍照常报错**。

**实测**：新增 `presentation/assembly/tests/ADR0076_EventGroupExprSchemaTests.cs`——经真实
`DataRegistry.LoadAll` + 完整表达式 schema 验证 `event.hit_result == "Hit"` 一类条件不再报错；
`presentation/assembly/tests/PresentationAssemblyTests.cs` 新增三例，经真实反馈绑定器 /
规则表达式宿主管线验证条件按事件真实字段值正确求值为真/假。

## 反馈 1：UI 交互域事件（ADR-0077）

你方核实正确：`presentation/ui/**` 此前**只订阅、从不发出**任何事件，反馈绑定挂不到任何 UI 交互上。

**新增三个事件**（`domain=ui`），由**引擎无关的 UI 核心层**发出：

| 事件 key | 字段 | 何时发 |
| --- | --- | --- |
| `ui.panel_opened` | `panelId` | 面板注册表的打开调用**使状态真正变化**时 |
| `ui.panel_closed` | `panelId` | 同上，关闭 |
| `ui.action_invoked` | `panelId`, `actionName` | UI 意图方法被调用时 |

- `UiPanelRegistry` 新增 3 参构造重载（携带 `IEventBus?`）；`UiIntents` 新增 13 参构造重载，
  并新增一批**带前导 `panelId` 参数**的方法重载（`CastSkill`/`UseItem`/`Equip`/`Unequip`/
  `Buy`/`Sell` 等）。既有无 `panelId` 的重载原样保留，调用它们不发事件。
- `actionName` 取**框架自持的 UI 意图方法名语义**，不引入 `buttonId` 概念——框架不知道你方有哪些
  按钮，也不该知道。哪个按钮对应哪个意图是游戏侧的事。
- 三个事件**只陈述"哪个面板发生了什么交互"，不携带任何呈现意图字段**；框架**不为任何 UI 交互
  预设默认音效/特效绑定**。要点击音效，你方在 `feedback.binding` 里自己声明。

**随本次改动顺带接线**：`UiPanelRegistry` 此前从未接入任何生产装配根（只在测试里被构造过），
现已接入 `PresentationAssembly.Panels`，新增 `PresentationAssemblyOptions.MenuOverlayPanelIds` 选项。

## 反馈 2：单位步幅位移事件（ADR-0078）

你方核实正确：唯一的移动事件 `unit.moved` 与移动速度/帧率耦合，当不了固定节奏信号。

**新增**：`display.map` 新增可选字段 `stride_distance`（**该外形的步幅几何距离**）。
未登记或 `<=0` 时该外形**完全不使用**本机制，不发任何新事件、无任何开销。

新增表现层组件订阅 `unit.moved`，按单位累计位移，达到一个步幅距离即发
**`unit.stride_completed { unitId, position }`** 并**保留余数**（不清零，长期不漂移）；
单次位移超过步幅距离 8 倍视为瞬移，只发一条并清零累计（地图切换/传送不会补发一串）。

**命名口径（有意的）**：事件名与字段名一律用**"位移/步幅"几何语义**，不用脚步/footstep 呈现语义，
不引入任何步态/动画概念。框架只负责**"什么时候发"**；这一拍是脚步声、是扬尘、还是别的什么，
是游戏侧在 `feedback.binding` 里自己决定的，框架**不登记任何默认音效/特效绑定**。

**边界**：由表现层派生，**不进入规则层、不写回任何逻辑状态、不影响仿真基线**（回放/存档不受影响）。

## 升级影响

1. **无破坏性变更**，ABI 破坏 0 处。UI 两处是新增构造重载与新增方法重载；步幅是新增可选字段 +
   新增装配属性；第 3 条只改静态校验行为，不改任何签名与求值路径。
2. **第 3 条会放宽既有校验**：若你方现有 `condition` 里写了 `event.<key>` 与字面量比较的**笔误**
   （类型确实对不上），升级后加载期不再报错，改为运行期恒为假。建议升级后过一遍自己的
   `feedback.binding` 条件。
3. UI 事件要发出来，需要用**新的带 `panelId` 的重载**；沿用旧重载则行为与升级前逐字一致。

   （由 1 条扩至 4 条：`presentation.playback_finished`、`ui.panel_opened`/`ui.panel_closed`/
   `ui.action_invoked`、`unit.stride_completed`）。表现层仍然不是事件源头，这 4 条是白名单。
