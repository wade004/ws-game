# 消费方答复：游戏接入方第五十五批已交付（2026-09-28）

## 结论

缺口成立，已补，落在 **1.86.0**（标签 `v1.86.0`，发布提交 `94ac3764`，功能提交 `defc4ad5`，ADR-0106）。你方五条排除逐条核实无误；选的是你方方向 1 的收窄版（只覆盖下限，不覆盖 `max_source`/`regen_*`），不选方向 2（结算路径特判）。

## 设计

- **资源池契约新增单位级下限覆盖**：`IPowerHost` 新增默认接口成员 `SetMinOverride(unitId, powerType, double? min)`（null 清除）。覆盖值必须落在 `[该资源类型定义的 min, 该单位当前 max]`，否则报错。未设覆盖的单位/资源类型行为逐位不变。
- **`PowerHost` 全部夹取出口统一改读"覆盖 ?? 定义 min"**：初始值、`ApplyDelta`/`SetCurrentClamped` 下界、上限下降再夹取、`power.depleted` 判定都走这一处。设置覆盖时当前值已低于覆盖值则立即夹上并按既有出口发事件；`UnregisterUnit` 随之清除。
- **`creature.template` 新增可选字段 `power_floors`**（`Map<资源类型 id, Number>`）。`CreatureFactory` 在 `RegisterUnit` 之后逐条落地为覆盖。键必须是已登记资源类型（引用完整性校验）；值不得低于该资源类型定义 `min`，由 `CreatureContentValidationRule` 新检查项 `creature_power_floor_min` 给出带 id 的诊断。
- **战斗结算与伤害事件不改**：`combat.damage_dealt.Amount` 仍是结算算出的原始量，生命值落地后被夹在覆盖下限之上，`Resolver` 那条"≤ 0 判死"自然不触发。不在结算路径加"读单位专属下限"的特判，理由：覆盖对全部资源类型通用，且结算路径不为一种内容配置长出常驻分支。免疫方向不选（吞伤害事件）。

## 已知限制

- `power.depleted` 语义从"跌到全局 min"变为"跌到本单位生效的下限"：假人打到 floor 仍会发一次该事件。战斗判死不读这个事件，不影响"不死"；若你方把它当死亡同义信号用，需知悉。
- 若你方把 `CreatureOptions.DefaultPowerTypes` 收窄为子集而 `power_floors` 引用了未注册的资源类型，生成时报错终止（两处配置由内容作者自行保证一致，不反推注册集合）。
