## 反馈 1：`MoveRequest.ToUnit`（ADR-0097）

- 新增 `MoveRequest.ToUnit(unitId, targetUnitId, stopRange, mode = Run)`（`stopRange` 必须 > 0）。每 tick 读目标当前位置：距离 ≤ `stopRange` 静止并朝向目标（不清请求）；距离 > `stopRange + MovementOptions.FollowResumeSlack`（默认 0.25）恢复追击（滞回防抖）；路径只在目标自上次规划位移 > `MovementOptions.FollowRepathDistance`（默认 0.5）时重算，终点为目标位置沿追击方向回退 `stopRange` 的一点。
- 自动结束：目标不存在 / 已死亡 / 不在同一地图 → 清请求、就地静止，走既有 `OnMoveStopped`，新原因 `MoveStopReason.ChaseTargetLost`；寻路失败（目标不可达）→ 走既有 `OnMoveFailed`/`OnMoveFailedDetailed`（`MoveFailReason.NoPath`）并结束追击，不无声重试。任何新的 `MoveRequest`（含 `ToTarget`）或显式停止都替换/清空它。发起时已在 `stopRange` 内：只转向、不移动、不结束（目标走开会追）。
- 未动 `AutoAttackHost` 与 AI。已知限制：移动请求本就不入存档，读档后追击请求需你方重新下达；离散模式下目标消失只在本单位自己的回合被探测。
- 凭据：`ToUnit_ApproachesThenStopsWithinStopRange_ThenResumesWhenTargetMovesAway`（4 单位外追到 ≤1.5 停下并朝向，目标挪到 5 单位外再追再停）；`ToUnit_TargetDriftsBelowRepathThreshold_DoesNotReplan_UnreachableTargetFailsOnceAndEndsChase`（累计位移 <0.5 不重规划；不可达 → 恰好一次失败通知、请求清空、此后不再寻路）；滞回/目标死亡/换图/被 `ToTarget` 替换/`stopRange<=0` 各一支。`Tests.Carriers` 657/657；`abi_probe` breaks=0 additions=15。
- 你方要做的：右键可攻击单位时改下 `MoveRequest.ToUnit(playerId, targetId, AutoAttackHost.Options.Range × 0.75, Run)` 一次即可，撤掉"取目标当时位置退 0.75 射程"的落点计算；订阅 `OnMoveFailed`（`NoPath`）给"无法到达"提示。
