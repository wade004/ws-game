# 消费方答复：游戏接入方第六十一批已交付（2026-09-30）

## 结论

缺口成立，已补，落在 **1.90.0**（标签 `v1.90.0`，发布提交 `a72073ed`，功能提交 `c524347f`，ADR-0111）。你方链路核对无误。形态上**没有**采用"给 `AnimState` 加战斗待机成员"，改为与动画状态正交的"战斗姿态"维度 + 剪辑键变体。

## 为什么不加枚举成员

新增成员会波及所有按 `Idle`/`Move` 判断运动态的代码和你方自己的穷举分支；正交维度对七个状态一视同仁，将来要"战斗中移动/受击"另一套剪辑只需加数据键，不用再改契约。

## 交付内容

- **剪辑键约定**：单位处于战斗姿态时，状态 `<键>` 的默认剪辑先查 `display.anim_set.clips` 里的 `combat_<键>`，没有就回落到 `<键>`。七个状态键都支持（`combat_idle`、`combat_move`、`combat_attack`、`combat_cast`、`combat_hit`、`combat_death`、`combat_jump`）。
- **驱动**：状态机订阅 `combat.entered` / `combat.left`。
- **装备层**：逐层剪辑按既有命名规则随身体剪辑推导，`combat_idle` 的逐层资源命名与 `idle` 同一套规则，只是剪辑引用换成 `combat_idle` 那条的 `resource_ref`。
- **查询与事件**：`AnimStateMachine.IsInCombatStance(entityId)`、`CombatStanceChanged`。
- 优先级：技能/武器风格覆盖剪辑 > 战斗姿态变体键 > 普通键。

## 切换规则

| 场景 | 行为 |
|---|---|
| 站着进战 / 脱战 | 立即切换，从头播 |
| 攻击、受击、施法中进战或脱战 | 不打断，结束后回落到当时姿态对应的待机 |
| 战斗中移动但没有 `combat_move` | 播普通 `move`，停下回到 `combat_idle` |
| 战斗待机中转向 / 换装 | 新方向、新装备层用 `combat_idle` 那一套，时间轴按既有规则保持 |
| 变体资源还没加载完 | 维持当前显示，加载完成后切；期间已脱战则不切 |
| 视图创建时单位已在战中 | 初始即 `combat_idle`（需接探针，见下） |
| 外形没有任何 `combat_*` 键 | 与 1.89.0 一致，进出战不重播 |

## 已知限制

- 声明了 `combat_<键>` 但对应美术缺失时，一直维持当前显示，没有超时回落，也不写诊断。
- 武器风格/技能覆盖剪辑不感知战斗姿态，原样播放。要战斗/非战斗两套攻击，请不用覆盖、改用 `combat_attack`。
- `jump` 不在默认登记的状态键里（既有行为），默认装配下 `combat_jump` 不会被播。
- `combat.entered` / `combat.left` 读档后不补发，所以读档、重生、进入视野时已在战中的单位靠探针确定初始姿态。

## 凭据

- 复现用例（生产装配级，外形声明 `idle` + `combat_idle` 并带一个装备层）：修前进战后身体层应用的仍是 idle 逐层资源（红）；修后进战切到 combat_idle 那一套、脱战切回，身体层与装备层都对。
- 不变量：无变体键外形零重播（带阳性对照）、攻击中进战、冷加载两种先后顺序、视图创建时已在战中、战斗待机中换向与换装、覆盖剪辑优先级。
- 定向回归：引擎侧 PlayMode 101/101；表现层核心 849/849；ABI 无破坏。
- 发布门禁 32/32，PlayMode 356/356。

## 你方要做的

1. 升级 1.90.0（含 1.88.0、1.89.0 的修复）。
2. **在你方自己的装配入口加一行**，把探针接到规则层：`viewFactory.CombatProbe = <规则层战斗宿主>.IsInCombat;`（框架自带的三个装配入口已接；不接的后果是读档、重生、进入视野时已在战中的单位初始为普通待机，直到下一次进出战事件）。
3. 在 `display.anim_set` 给需要的外形加 `combat_idle` 剪辑，并按既有逐层命名规则制作身体层与各装备层的资源。
4. 若你方有代码按"当前正在播的剪辑 id == idle 剪辑"判断站立，请改用 `GetState` + `IsInCombatStance`。
